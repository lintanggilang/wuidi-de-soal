DynamoDB offers three encryption options: (1) AWS owned key (DEFAULT, free) — AWS manages everything, no KMS costs, no CloudTrail entries for key usage; (2) AWS managed key (aws/dynamodb) — free KMS key, but generates CloudTrail entries for each table operation, can impact CloudTrail costs at 50K reads/sec; (3) Customer managed key (CMK) — full control, custom rotation, cross-account sharing, audit trail, but KMS API charges ($0.03/10K requests) which at 50K reads/sec would cost significantly more
  • B.   • C. All DynamoDB encryption options cost the same, the only difference is key management complexity, satisfying all of the stated requirements with minimal effort and handling the described workload reliably at scale and scaling horizontally as ingestion throughput keeps growing and keeping steady-state operating costs low and enforcing encryption and fine-grained access control
  • D. Customer managed keys in DynamoDB are always free because DynamoDB handles KMS calls internally, enforcing encryption and fine-grained access control and satisfying strict compliance and audit requirements and integrating natively with the rest of the pipeline and optimizing cost for the described workload and scaling elastically to millions of events per second
Correct Answer: A
DynamoDB encryption options have significant cost implications at scale: Option 1 — AWS Owned Key (DEFAULT): Cost: FREE (no KMS charges). Audit: No CloudTrail entries for encryption operations. Control: None — can't disable, rotate, or share. Best for: Non-regulated workloads, cost-sensitive applications. Option 2 — AWS Managed Key (aws/dynamodb): Cost: Key itself free, BUT each DynamoDB operation generates CloudTrail event. At 50K reads/sec = 4.3B events/day. CloudTrail costs for management events can be significant. Control: Limited — can view key policy, see usage, but can't rotate or share. Option 3 — Customer Managed Key (CMK): Cost: $1/month for key + $0.03 per 10,000 API requests. 50K reads/sec × 3600 × 24 = 4.32B requests/day. BUT: DynamoDB caches data keys, so NOT every read = KMS call. Actual KMS calls much lower than DynamoDB operations. Control: Full — custom rotation, disable/enable, cross-account, key policy. Audit: Full CloudTrail for key operations. Recommendation for 50K reads/sec: AWS owned key if audit not required (cheapest). CMK if compliance requires audit trail (DynamoDB's caching reduces actual KMS costs).

Option A: CORRECT.
Option B: INCORRECT. Meskipun sounds convincing, still not correct for skenario this.
Option C: INCORRECT.
Option D: INCORRECT.

  • B. Configure security groups to only allow outbound traffic to IP ranges of the local AWS region, handling the described workload reliably at scale
  • C. Use VPC Interface Endpoints (AWS PrivateLink) for all AWS service calls, combined with VPC endpoint policies restricting access to only resources in the local region

VPC Interface Endpoints (PrivateLink) creates private connectivity between VPC and AWS services without traffic meninggalkan AWS network. Endpoint still in region the said. Option B: INCORRECT. Security groups works in IP level; AWS regional IP ranges overlap and changes — this fragile and difficult in-maintain.
Option C: CORRECT.
Option D: INCORRECT. NAT Gateway sends traffic to internet then to AWS public endpoints; traffic technically exits VPC to internet.
