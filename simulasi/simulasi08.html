Recipient: downloads encrypted object, calls KMS Decrypt on data key, decrypts locally. CSE-C (Client-managed key): Application uses its own master key (not in KMS). Generates data key locally, encrypts data. Uploads encrypted data + wrapped data key. Complete independence from AWS for key management. Defense-in-depth layers: Layer 1: Client-side encryption (data encrypted before leaving app). Layer 2: TLS (HTTPS) encrypts the already-encrypted data in transit. Layer 3: S3 SSE (can ALSO enable) encrypts the already-encrypted object at rest. Result: Triple encryption — even if one layer compromised, data remains protected. AWS Encryption SDK: Multi-language SDK (Java, Python, JavaScript, C). Handles envelope encryption, key caching, algorithm selection. Supports data key caching for performance. Message format includes authentication (prevents tampering). Opsi A — SSE happens at S3 (server-side) AFTER data arrives. Opsi C — VPN to S3 is not standard architecture. Opsi D — Transfer Acceleration is performance optimization, not security — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
