Background: The Dashboard Gap

Traditional dashboards have limitations

  • Dashboards only display pre-designed KPIs and charts
  • Deep drill-downs require filter changes or new visualizations
  • Business users cannot "ask" questions to data directly
  • Hidden insights are hard to discover without SQL/analytics skills

The Problem

For Business Users

"I see revenue dropped in the chart, but why? Which pizza? What hour is slow?"

For Data Teams

"Every ad-hoc question means we write SQL manually and build new reports."

Gap: Dashboards show "what happened" but cannot answer "why" or "what should we do".

Solution: Contextual AI Analytics

Keep the dashboard simple. Let AI be the analyst.

  • User views dashboard KPIs (QuickSight)
  • User asks questions in natural language
  • AI generates SQL automatically (Text-to-SQL)
  • AI queries data directly from Athena
  • AI provides insight + business recommendation

Key principle: AI answers from DATA, not from pretrained knowledge.

1 Athena: Data Preparation

Console: Amazon Athena > Query Editor

  • Create database: wuidi-pizza-db
  • Create tables via Glue: orders, order_details, pizzas, pizza_types
  • Create unified view joining all tables
  • Set output location: s3://wuidi-pizza/athena-results/
CREATE VIEW wuidi_vw_pizza_sales AS SELECT o.order_id, o.date as order_date, od.quantity, p.size, p.price, pt.name as pizza_name, pt.category, od.quantity * p.price as total_sales FROM orders o JOIN order_details od ON o.order_id = od.order_id JOIN pizzas p ON od.pizza_id = p.pizza_id JOIN pizza_types pt ON p.pizza_type_id = pt.pizza_type_id

1 Athena: Verify Data

Console: Run test queries to verify

-- Test: Top 5 pizzas by revenue SELECT pizza_name, SUM(total_sales) as revenue, SUM(quantity) as units_sold FROM wuidi_vw_pizza_sales GROUP BY pizza_name ORDER BY revenue DESC LIMIT 5; -- Test: Revenue by category SELECT category, SUM(total_sales) as revenue FROM wuidi_vw_pizza_sales GROUP BY category ORDER BY revenue DESC;

If queries work here, they will work when AI generates them.

2 QuickSight: Create Dataset

Console: QuickSight > Datasets > New Dataset

  • Data source: Amazon Athena
  • Database: wuidi-pizza-db

3 Bedrock: Enable Model Access

Console: Amazon Bedrock > Model Access

  • Request access to Amazon Nova Pro
  • Region: ap-southeast-1 (Singapore)
  • Model ID: amazon.nova-pro-v1:0
  • Use case: Text-to-SQL generation + business insight generation

Nova Pro chosen for strong SQL generation and reasoning capabilities at competitive cost.

3 Bedrock: Create Flow

Console: Bedrock > Builder tools > Flows

  • Flow name: wuidi-pizza-flow
  • Drag & drop nodes in visual canvas:
  • Input > CheckRelevance (Prompt) > Condition > GenerateSQL (Prompt)
  • GenerateSQL > ValidateAndQuery (Lambda) > GenerateInsight (Prompt) > Output
  • Condition (default) > SorryResponse (Prompt) > Output

Visual pipeline — each node is a step. Click any node to see input/output.

3 Bedrock Flow: Prompt Design

Each prompt node has a specific role

CheckRelevance Prompt

"Is this question about pizza sales data? Answer RELEVANT or NOT_RELEVANT"

GenerateSQL Prompt

"Given this schema [view + tables], generate Athena SQL for the user question. SELECT only."

GenerateInsight Prompt

"Given question + query results, provide: direct answer, business insight, recommendation."

SorryResponse Prompt

"Politely decline — only pizza sales questions are supported."

4 Lambda: Create Functions

Console: AWS Lambda > Create Function

wuidi-context-builder

API Gateway handler. Receives question, invokes Bedrock Flow, returns response.

Runtime: Python 3.12 | Memory: 512MB | Timeout: 90s

wuidi-flow-athena

Called BY Bedrock Flow. Validates SQL safety + executes Athena query + returns results.

Runtime: Python 3.12 | Memory: 256MB | Timeout: 60s

4 Lambda: SQL Safety Check

AI generates SQL, but Lambda always validates

def validate_sql(sql): forbidden = ["INSERT", "UPDATE", "DELETE", "DROP", "ALTER", "CREATE", "TRUNCATE"] for keyword in forbidden: if keyword in sql.upper().split(): raise Exception(f"Forbidden: {keyword}") if not sql.strip().upper().startswith("SELECT"): raise Exception("Only SELECT allowed")

AI can only read data. Never modify. Defence in depth.

Lessons Learned

  • Text-to-SQL is more flexible than hardcoded queries — AI adapts to any question
  • Bedrock Flows makes orchestration visual & modular — easy to debug in console
  • Condition nodes as guardrails — prevent AI from answering out of scope
  • Serverless = cost efficient — pay per request, great for demos & MVPs
  • Prompt engineering is crucial — schema in prompt = AI understands data
  • CDK optional — can set up via console first, then codify later with CDK

Key Takeaways

1. Dashboard ≠ Analytics

Dashboards display data. AI analyzes and answers questions.

2. AI + Data = Powerful

Bedrock + Athena: AI answers from real data, not hallucination.

3. Flows = Visual Orchestration

Build, debug, and demo AI pipelines visually in the console.

4. Serverless = Scale

From 0 to thousands of requests — no servers to manage.
