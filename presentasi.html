Latar Belakang Masalah

Dashboard tradisional punya keterbatasan

  • Dashboard hanya menampilkan KPI dan chart yang sudah di-design
  • Untuk deep drill-down → perlu ubah filter, buat chart baru
  • Bisnis user tidak bisa "bertanya" ke data secara langsung
  • Insight tersembunyi sulit ditemukan tanpa skill SQL/analytics

Masalah Spesifik

Untuk Business User

"Saya lihat revenue turun di chart, tapi kenapa? Pizza mana yang turun? Jam berapa yang sepi?"

Untuk Data Team

"Setiap pertanyaan ad-hoc dari bisnis → kami harus tulis SQL manual, buat report baru."

Gap: Dashboard bisa menampilkan "apa", tapi tidak bisa menjawab "kenapa" dan "apa yang harus dilakukan".

Solusi: AI Analitik Kontekstual

Dashboard tetap simpel. AI jadi analis.

  • User melihat dashboard KPI (QuickSight)
  • User bertanya dalam bahasa natural ke AI
  • AI generate SQL otomatis (Text-to-SQL)
  • AI query data langsung dari Athena
  • AI berikan insight + rekomendasi bisnis

Kunci: AI menjawab dari DATA, bukan dari pengetahuan umum.

Technology Stack

Data & Visualization

  • AWS Glue (data catalog)
  • Amazon Athena (query engine)
  • Amazon QuickSight (dashboard)

AI & Orchestration

  • Amazon Bedrock (Nova Pro)
  • Bedrock Flows (orchestration)
  • AWS Lambda (serverless compute)
  • API Gateway (REST API)

Semua serverless — bayar per request, tidak ada server yang dikelola.

Arsitektur dari Sisi User

User buka Dashboard (QuickSight + AI Chat) ↓ User lihat chart & KPI → lalu bertanya ke AI ↓ "Pizza apa yang paling laku bulan Januari?" ↓ AI generate SQL → validate → query Athena → generate insight ↓ "The Thai Chicken Pizza adalah yang paling laku di Januari dengan 120 orders. Rekomendasi: tingkatkan stok bahan..."

Arsitektur Teknis

Frontend (GitHub Pages) ↓ API Gateway (POST /ask) ↓ Lambda (invoke Bedrock Flow) ↓ ┌─────────────── Bedrock Flow ───────────────┐ │ │ │ [Input] → [CheckRelevance] → [Condition] │ │ ↓ relevant ↓ not │ │ [GenerateSQL] [SorryResponse] │ │ ↓ ↓ │ │ [Lambda: Athena] [Output] │ │ ↓ │ │ [GenerateInsight] │ │ ↓ │ │ [Output] │ └────────────────────────────────────────────┘

Kenapa Bedrock Flows?

Sebelum (Monolith Lambda)

  • Semua logic di 1 file Python
  • Sulit debug step by step
  • Prompt hardcoded di code

Sesudah (Bedrock Flows)

  • Visual node-based pipeline
  • Tiap step terpisah & observable
  • Modular — tambah node tanpa ubah code

Bonus: bisa di-demo langsung di console! 🎯

Step 1: Persiapan Data

MySQL → S3 → Glue → Athena

  • Dataset: Pizza Sales (orders, order_details, pizzas, pizza_types)
  • Upload CSV ke S3 bucket wuidi-pizza
  • Buat Glue Tables (schema definition)
  • Buat Athena View: wuidi_vw_pizza_sales (join semua tabel)
CREATE VIEW wuidi_vw_pizza_sales AS SELECT o.order_id, o.date as order_date, od.quantity, p.size, p.price, pt.name as pizza_name, pt.category, od.quantity * p.price as total_sales FROM orders o JOIN order_details od ON o.order_id = od.order_id JOIN pizzas p ON od.pizza_id = p.pizza_id JOIN pizza_types pt ON p.pizza_type_id = pt.pizza_type_id

Step 2: Dashboard di QuickSight

Visualisasi KPI untuk user

  • Dataset mode: SPICE (in-memory, fast)
  • Revenue Trend, Orders Trend (by month)
  • Revenue by Hour, by Category, by Size
  • Detail table dengan calculated fields
  • Filters: month, category, pizza_name, size

Step 3: AI Engine (Lambda + Bedrock)

Text-to-SQL Pipeline

User: "Pizza apa yang paling laku?" ↓ Bedrock (Nova Pro): Generate SQL → SELECT pizza_name, SUM(quantity) ... ↓ Lambda: Validate (SELECT only!) + Run Athena → [{pizza_name: "Thai Chicken", total: 2371}, ...] ↓ Bedrock (Nova Pro): Generate Business Insight → "Thai Chicken Pizza adalah yang paling laku dengan 2,371 pizza terjual. Ini 15% lebih tinggi dari rata-rata. Rekomendasi: ..."

Step 4: Bedrock Flow (Orchestration)

7 Nodes dalam 1 Flow

  • FlowInput — Terima pertanyaan user
  • CheckRelevance — Apakah pertanyaan terkait data pizza?
  • IsRelevant — Condition: RELEVANT → lanjut, NOT → maaf
  • GenerateSQL — AI buat SQL dari pertanyaan
  • ValidateAndQuery — Lambda validate + jalankan Athena
  • GenerateInsight — AI analisa hasil + buat insight
  • FlowOutput — Return jawaban ke user

Fitur: Relevance Check

AI sebagai gatekeeper

✅ Pertanyaan Relevan

"Revenue kategori Classic berapa?"
"Jam berapa paling ramai?"
"Pizza mana yang paling mahal?"

→ Lanjut ke SQL + Athena

❌ Pertanyaan Tidak Relevan

"Cuaca hari ini?"
"Siapa presiden Indonesia?"
"Buatkan code Python"

→ "Maaf, saya hanya bisa menjawab tentang data pizza..."

Step 5: Infrastructure as Code (CDK)

Semua di-deploy via AWS CDK (Python)

cdk deploy # Creates: # ✅ Lambda (wuidi-context-builder) — API wrapper # ✅ Lambda (wuidi-flow-athena) — Athena node # ✅ Bedrock Flow (wuidi-pizza-flow) — 7 nodes # ✅ Flow Version + Alias # ✅ IAM Role (wuidi-flow-role) # ✅ API Gateway (POST /ask, GET /embed-url) # ✅ CORS enabled

1 command = seluruh infrastruktur terbuat. Reproducible, version-controlled.

Security: SQL Validation

AI generate SQL, tapi kita tetap validasi

def validate_sql(sql): forbidden = ["INSERT", "UPDATE", "DELETE", "DROP", "ALTER", "CREATE", "TRUNCATE"] for keyword in forbidden: if keyword in sql.upper().split(): raise Exception(f"Forbidden: {keyword}") if not sql.strip().upper().startswith("SELECT"): raise Exception("Only SELECT allowed")

AI hanya boleh membaca data. Tidak pernah memodifikasi.

Pelajaran yang Dipetik

  • Text-to-SQL lebih fleksibel dari hardcoded query — AI adaptasi ke pertanyaan apapun
  • Bedrock Flows bikin orchestration visual & modular — gampang debug
  • Condition node sebagai guardrail — cegah AI jawab di luar scope
  • Serverless = cost efficient — bayar per request, cocok untuk demo & MVP
  • CDK memastikan reproducibility — 1 command deploy semua
  • Prompt engineering sangat krusial — schema di prompt = AI paham data

Key Takeaways

1. Dashboard ≠ Analytics

Dashboard menampilkan data. AI yang menganalisa dan menjawab pertanyaan.

2. AI + Data = Powerful

Bedrock + Athena: AI yang menjawab dari data real, bukan hallucination.

3. Flows = Orchestration

Bedrock Flows membuat pipeline AI visual, modular, dan maintainable.

4. Serverless = Scale

Dari 0 request sampai ribuan — tanpa manage server.
