Background: The Dashboard Gap

Traditional dashboards have limitations

  • Dashboards only display pre-designed KPIs and charts
  • Deep drill-downs require filter changes or new visualizations
  • Business users cannot "ask" questions to data directly
  • Hidden insights are hard to discover without SQL/analytics skills

The Problem

For Business Users

"I see revenue dropped in the chart, but why? Which pizza? What hour is slow?"

For Data Teams

"Every ad-hoc question from business means we write SQL manually and build new reports."

Gap: Dashboards show "what happened" but cannot answer "why" or "what should we do".

Solution: Contextual AI Analytics

Keep the dashboard simple. Let AI be the analyst.

  • User views dashboard KPIs (QuickSight)
  • User asks questions in natural language
  • AI generates SQL automatically (Text-to-SQL)
  • AI queries data directly from Athena
  • AI provides insight + business recommendation

Key principle: AI answers from DATA, not from pretrained knowledge.

Technology Stack

Data & Visualization

  • AWS Glue (data catalog)
  • Amazon Athena (query engine)
  • Amazon QuickSight (dashboard)

AI & Orchestration

  • Amazon Bedrock (Nova Pro)
  • Bedrock Flows (orchestration)
  • AWS Lambda (serverless compute)
  • API Gateway (REST API)

100% serverless — pay per request, no servers to manage.

Architecture: User Perspective

User opens Dashboard (QuickSight + AI Chat panel) | User views charts & KPIs, then asks AI: | "What is the best selling pizza in January?" | AI generates SQL -> validates -> queries Athena -> generates insight | "The Thai Chicken Pizza is the top seller in January with 120 orders. Recommendation: increase ingredient stock..."

Technical Architecture

Frontend (GitHub Pages) | API Gateway (POST /ask) | Lambda (invoke Bedrock Flow) | +-------------- Bedrock Flow ----------------+ | | | [Input] -> [CheckRelevance] -> [Condition]| | | relevant | default | | [GenerateSQL] [SorryResponse] | | | | | | [Lambda: Athena] [Output] | | | | | [GenerateInsight] | | | | | [Output] | +--------------------------------------------+

Why Bedrock Flows?

Before (Monolith Lambda)

  • All logic in 1 Python file
  • Hard to debug step by step
  • Prompts hardcoded in code

After (Bedrock Flows)

  • Visual node-based pipeline
  • Each step isolated & observable
  • Modular — add nodes without changing code

Bonus: can be demoed live in the AWS Console!

Step 1: Data Preparation

CSV -> S3 -> Glue -> Athena

  • Dataset: Pizza Sales (orders, order_details, pizzas, pizza_types)
  • Upload CSV to S3 bucket wuidi-pizza
  • Create Glue Tables (schema definitions)
  • Create Athena View: wuidi_vw_pizza_sales (joins all tables)
CREATE VIEW wuidi_vw_pizza_sales AS SELECT o.order_id, o.date as order_date, od.quantity, p.size, p.price, pt.name as pizza_name, pt.category, od.quantity * p.price as total_sales FROM orders o JOIN order_details od ON o.order_id = od.order_id JOIN pizzas p ON od.pizza_id = p.pizza_id JOIN pizza_types pt ON p.pizza_type_id = pt.pizza_type_id

Step 3: AI Engine (Text-to-SQL)

The core pipeline

User: "What is the best selling pizza?" | Bedrock (Nova Pro): Generate SQL -> SELECT pizza_name, SUM(quantity) ... | Lambda: Validate (SELECT only!) + Run Athena -> [{pizza_name: "Thai Chicken", total: 2371}, ...] | Bedrock (Nova Pro): Generate Business Insight -> "Thai Chicken Pizza is the best seller with 2,371 units sold. This is 15% above average. Recommendation: ..."

Step 4: Bedrock Flow (Orchestration)

7 Nodes in 1 Flow

  • FlowInput — Receives user question
  • CheckRelevance — Is the question about pizza data?
  • IsRelevant — Condition: RELEVANT -> proceed, NOT -> sorry
  • GenerateSQL — AI creates SQL from question
  • ValidateAndQuery — Lambda validates + runs Athena
  • GenerateInsight — AI analyzes results + creates insight
  • FlowOutput — Returns answer to user

Feature: Relevance Guardrail

AI as gatekeeper

Relevant Questions

"Revenue for Classic category?"
"What hour is busiest?"
"Most expensive pizza?"

-> Proceeds to SQL + Athena

Irrelevant Questions

"What's the weather today?"
"Who is the president?"
"Write Python code"

-> "Sorry, I can only answer pizza sales questions..."

Step 5: Infrastructure as Code (CDK)

Everything deployed via AWS CDK (Python)

cdk deploy # Creates: # - Lambda (wuidi-context-builder) — API wrapper # - Lambda (wuidi-flow-athena) — Athena node # - Bedrock Flow (wuidi-pizza-flow) — 7 nodes # - Flow Version + Alias # - IAM Role (wuidi-flow-role) # - API Gateway (POST /ask, GET /embed-url) # - CORS enabled

1 command = entire infrastructure created. Reproducible & version-controlled.

Security: SQL Validation

AI generates SQL, but we always validate

def validate_sql(sql): forbidden = ["INSERT", "UPDATE", "DELETE", "DROP", "ALTER", "CREATE", "TRUNCATE"] for keyword in forbidden: if keyword in sql.upper().split(): raise Exception(f"Forbidden: {keyword}") if not sql.strip().upper().startswith("SELECT"): raise Exception("Only SELECT allowed")

AI can only read data. Never modify.

Lessons Learned

  • Text-to-SQL is more flexible than hardcoded queries — AI adapts to any question
  • Bedrock Flows makes orchestration visual & modular — easy to debug
  • Condition nodes as guardrails — prevent AI from answering out of scope
  • Serverless = cost efficient — pay per request, great for demos & MVPs
  • CDK ensures reproducibility — 1 command deploys everything
  • Prompt engineering is crucial — schema in prompt = AI understands data

Key Takeaways

1. Dashboard ≠ Analytics

Dashboards display data. AI analyzes and answers questions.

2. AI + Data = Powerful

Bedrock + Athena: AI answers from real data, not hallucination.

3. Flows = Orchestration

Bedrock Flows makes AI pipelines visual, modular, and maintainable.

4. Serverless = Scale

From 0 requests to thousands — without managing servers.
