A pharmaceutical company uses AWS Glue jobs to process research datasets stored in an Amazon S3 bucket. The company organizes the datasets by S3 prefixes that represent sensitivity levels such as public, internal, confidential, and regulated. The security team must allow each AWS Glue job role to access only the prefixes that match the job's approved data classification. The team must also restrict access to an approved business-hours window from 8 AM to 6 PM.

Which elements must the company include in a custom IAM policy to meet these requirements?

Jawaban benar

Use a Resource element with S3 object ARN patterns that include wildcards for each approved prefix and use a Condition element with aws:CurrentTime and DateGreaterThan and DateLessThan operators

Karena

Opsi yang benar:

Use a Resource element with S3 object ARN patterns that include wildcards for each approved prefix and use a Condition element with aws:CurrentTime and DateGreaterThan and DateLessThan operators

Sebuah IAM policy dapat membatasi izin pada level objek Amazon S3 dengan mencantumkan ARN objek S3 tertentu di dalam Resource element. Untuk memberikan akses hanya ke prefix yang disetujui, policy tersebut dapat memakai pola object ARN seperti arn:aws:s3:::example-bucket/confidential/* atau arn:aws:s3:::example-bucket/regulated/*.

Policy dapat membatasi rentang waktu dengan memakai AWS global condition key aws:CurrentTime beserta date condition operator seperti DateGreaterThan dan DateLessThan. Hal ini memungkinkan tim keamanan untuk membatasi kapan request dari AWS Glue job role boleh diotorisasi.

Solusi ini memenuhi kedua kebutuhan. Resource element membatasi akses S3 pada classification prefix yang relevan, sementara Condition element menegakkan akses berbasis waktu dengan mengevaluasi waktu request saat proses otorisasi IAM.

Opsi yang salah:

Use a Condition element with the s3:ResourceAccount condition key to restrict bucket ownership and add an explicit Deny statement outside the approved business-hours window - condition key s3:ResourceAccount membantu membatasi akses berdasarkan AWS account yang memiliki resource S3 tersebut. Ini bisa berguna pada sebagian skenario cross-account access control.

Namun, condition key ini tidak membatasi akses ke classification prefix tertentu di dalam sebuah bucket. Perusahaan membutuhkan object ARN yang spesifik per prefix atau list condition yang mengenali prefix, bukan sekadar pemeriksaan kepemilikan account.

Use a Condition element with the s3:prefix condition key to restrict all object access and use aws:CurrentTime with DateGreaterThanEquals and DateLessThanEquals operators to restrict the access window - condition key s3:prefix dapat membatasi prefix untuk operasi listing bucket seperti s3:ListBucket. Ini berguna ketika sebuah policy harus mengontrol key mana yang boleh di-list oleh suatu principal pada S3 bucket.

Namun, s3:prefix dengan sendirinya tidak membatasi action pada level objek seperti s3:GetObject atau s3:PutObject. Policy tetap membutuhkan pola S3 object ARN di dalam Resource element untuk membatasi akses objek yang sebenarnya hanya ke prefix yang disetujui.

Use a Resource element with S3 bucket ARN patterns for each classification prefix and use a Condition element with aws:RequestTag to restrict access during the approved business-hours window - Resource element harus memakai format S3 ARN yang benar. ARN pada level bucket seperti arn:aws:s3:::example-bucket berlaku untuk action pada level bucket, sedangkan action pada level objek membutuhkan object ARN seperti arn:aws:s3:::example-bucket/prefix/*.

condition key aws:RequestTag mengevaluasi tag yang dilewatkan sebuah request ke action service yang didukung. Ini tidak menyediakan mekanisme umum untuk membatasi akses objek S3 ke jam kerja.

💡 Tips

Jika IAM policy harus batasi akses S3 per prefix + jam kerja 8–18 maka pakai Resource (ARN + wildcard prefix) & Condition (aws:CurrentTime, DateGreaterThan/LessThan) karena Resource batasi objek, Condition batasi waktu.Ingat elemen IAM: Effect, Action, Resource, Condition; batas waktu pakai aws:CurrentTime + DateGreater/LessThan.

An Amazon Redshift cluster is used to store sensitive information of a business-critical application. The regulatory guidelines mandate tracking audit logs of the Redshift cluster. The business needs to store the audit logs securely by encrypting the logs at rest. The logs are to be stored for a year at least and audits need to be conducted on the audit logs on a monthly basis.

Which of the following is a cost-effective solution that fulfills the requirement of storing the logs securely while having access to the logs for monthly audits?

Jawaban benar

Enable default encryption on the Amazon S3 bucket that uses Amazon S3-managed keys (SSE-S3) encryption (AES-256) for audit logging. Use Amazon Redshift Spectrum to query the data for monthly audits

Karena

Opsi yang benar:

Enable default encryption on the Amazon S3 bucket that uses Amazon S3-managed keys (SSE-S3) encryption (AES-256) for audit logging. Use Amazon Redshift Spectrum to query the data for monthly audits

Audit logging tidak diaktifkan secara default pada Amazon Redshift. Ketika Anda mengaktifkan logging pada cluster, Amazon Redshift membuat dan mengunggah log ke Amazon S3 yang merekam data mulai dari saat audit logging diaktifkan hingga waktu sekarang. Setiap pembaruan log merupakan kelanjutan dari informasi yang sudah dicatat sebelumnya.

Audit logging ke Amazon S3 bersifat opsional dan merupakan proses manual. Ketika Anda mengaktifkan logging pada cluster, Anda hanya mengaktifkan logging ke Amazon S3. Saat ini, Anda hanya dapat memakai Amazon S3-managed keys (SSE-S3) encryption (AES-256) untuk audit logging.

Amazon Redshift Spectrum adalah fitur Amazon Redshift yang memungkinkan Anda menjalankan query terhadap data lake di Amazon S3, tanpa perlu memuat data atau ETL. Ketika Anda mengirimkan sebuah SQL query, query itu menuju endpoint Amazon Redshift, yang menghasilkan dan mengoptimalkan query plan. Amazon Redshift menentukan data mana yang bersifat lokal dan mana yang ada di Amazon S3, menyusun rencana untuk meminimalkan jumlah data S3 yang perlu dibaca, dan meminta Amazon Redshift Spectrum worker dari shared resource pool untuk membaca dan memproses data dari S3.

via - https://aws.amazon.com/blogs/big-data/amazon-redshift-spectrum-extends-data-warehousing-out-to-exabytes-no-loading-required/

Opsi yang salah:

Enable default encryption on the Amazon S3 bucket that uses Amazon S3-managed keys (SSE-S3) encryption (AES-256) for audit logging. Copy the data into the Amazon Redshift cluster from Amazon S3 when data needs to be queried for monthly audits - Menyalin data ke dalam Redshift cluster untuk mengaktifkan audit bulanan akan menjadi solusi yang mahal. Memakai Redshift Spectrum adalah pilihan yang tepat untuk skenario ini.

Enable encryption on the Amazon S3 bucket that uses Amazon Server-Side Encryption with KMS keys Stored in AWS Key Management Service (SSE-KMS) for audit logging. Use Amazon QuickSight to query the data for monthly audits

Enable encryption on the Amazon S3 bucket that uses Amazon Server-Side Encryption with KMS keys Stored in AWS Key Management Service (SSE-KMS) for audit logging. Use Amazon Redshift Spectrum to query the data for monthly audits

Saat ini, Anda hanya dapat memakai Amazon S3-managed keys (SSE-S3) encryption (AES-256) untuk audit logging. Oleh karena itu, kedua opsi ini salah.

💡 Tips

Jika simpan audit log Redshift terenkripsi ≥1 tahun, hemat, bisa di-query bulanan maka S3 (SSE-S3/AES-256) + Redshift Spectrum karena S3 murah untuk arsip & Spectrum query langsung tanpa load.Ingat: audit log Redshift bisa dikirim ke S3; SSE-S3 = enkripsi gratis dikelola S3.

A data engineer is tasked with managing the real-time ingestion of streaming data into AWS. The solution must have the capability to perform real-time analytics, including time-based aggregations over periods of up to 45 minutes with high fault tolerance.

Which of the following options fulfills these criteria while minimizing the operational overhead?

Jawaban benar

Leverage Amazon Managed Service for Apache Flink to conduct real-time data analysis including time-based aggregations over periods of up to 45 minutes

Karena

Opsi yang benar:

Leverage Amazon Managed Service for Apache Flink to conduct real-time data analysis including time-based aggregations over periods of up to 45 minutes

Dengan Amazon Managed Service for Apache Flink, Anda dapat mentransformasi dan menganalisis streaming data secara real time menggunakan Apache Flink. Amazon Managed Service for Apache Flink menangani semua hal yang diperlukan untuk menjalankan aplikasi streaming secara terus-menerus dan melakukan scaling otomatis agar sesuai dengan volume serta throughput data yang masuk. Amazon Managed Service for Apache Flink mendukung semua operator dari Apache Flink yang dapat dipakai untuk menyelesaikan beragam use case, termasuk map, KeyBy, aggregations, windows, joins, dan lainnya. Aggregations melakukan pemrosesan lintas banyak key seperti sum, min, dan max. Window Join menggabungkan dua data stream pada key dan window tertentu.

via - https://aws.amazon.com/managed-service-apache-flink/faqs/

Untuk use case ini, Amazon Managed Service for Apache Flink paling cocok untuk melakukan analitik real-time termasuk time-based aggregations pada periode hingga 45 menit dengan fault tolerance yang tinggi, karena solusi ini melibatkan operational overhead yang minimal.

Opsi yang salah:

Leverage Amazon Kinesis Streams having a consumer Lambda function to conduct real-time data analysis including time-based aggregations over periods of up to 45 minutes - Sebuah Kinesis data stream adalah sekumpulan shard. Setiap shard berisi urutan data record. Consumer adalah aplikasi yang memproses data dari sebuah Kinesis data stream. Anda dapat memetakan sebuah Lambda function ke shared-throughput consumer (standard iterator), atau ke dedicated-throughput consumer dengan enhanced fan-out. Untuk opsi ini, Anda perlu mengintegrasikan Lambda function sebagai consumer dan mengembangkan custom code untuk melakukan time-based aggregations pada periode hingga 45 menit. Ini menimbulkan operational overhead tambahan, sehingga opsi ini salah.

Leverage Amazon Kinesis Streams having a consumer app running on an EC2 instance to conduct real-time data analysis including time-based aggregations over periods of up to 45 minutes - Sebuah Kinesis data stream adalah sekumpulan shard. Setiap shard berisi urutan data record. Consumer adalah aplikasi yang memproses data dari sebuah Kinesis data stream. Anda dapat menyiapkan consumer app pada sebuah EC2 instance. Namun, Anda perlu mengembangkan custom code untuk melakukan time-based aggregations pada periode hingga 45 menit. Selain itu, Anda perlu memantau dan memelihara EC2 instance tersebut. Jadi, opsi ini menimbulkan operational overhead tambahan sehingga salah.

Leverage Amazon Kinesis Firehose with a data transformation Lambda function to conduct real-time data analysis including time-based aggregations over periods of up to 45 minutes - Amazon Kinesis Firehose hanya dapat dipakai untuk analisis near real-time dan BUKAN analisis real-time, sehingga opsi ini salah.

💡 Tips

Jika analitik real-time dengan agregasi berbasis waktu (window s.d. 45 menit) fault-tolerant, overhead minim maka pakai Managed Service for Apache Flink karena Flink mendukung windowing & state terkelola.Ingat: time-window aggregation stream → Flink (tumbling/sliding/session window).

A data engineer is tasked with using AWS services to ingest a dataset into an Amazon S3 data lake. Upon profiling the dataset manually, the engineer finds that it contains personally identifiable information (PII). The engineer needs to devise a method to both profile the dataset and mask the PII effectively.

Which of the following options can be independently used to fulfill this requirement with the least amount of operational effort? (Select two)

Jawaban benar

Utilize the Detect PII transform in AWS Glue Studio to identify and mask the PII. Use an AWS Step Functions state machine to orchestrate a data pipeline to ingest the data into the S3 data lake

Run an AWS Glue DataBrew data profile job to identify and suggest potential PII columns present in the dataset. Execute a DataBrew job to apply the transformations to handle the sensitive columns in the entire dataset and store the masked data securely in Amazon S3

Karena

Opsi yang benar:

Utilize the Detect PII transform in AWS Glue Studio to identify and mask the PII. Use an AWS Step Functions state machine to orchestrate a data pipeline to ingest the data into the S3 data lake

Transform Detect PII mengidentifikasi Personal Identifiable Information (PII) pada sumber data Anda. Anda memilih entitas PII yang akan diidentifikasi, cara data dipindai, dan tindakan apa yang dilakukan terhadap entitas PII yang telah diidentifikasi oleh transform Detect PII.

Transform Detect PII menyediakan kemampuan untuk mendeteksi, me-mask, atau menghapus entitas yang Anda definisikan, atau yang sudah didefinisikan sebelumnya oleh AWS. Ini memungkinkan Anda meningkatkan kepatuhan dan mengurangi liabilitas. Misalnya, Anda mungkin ingin memastikan tidak ada personally identifiable information yang dapat terbaca pada data Anda dan ingin me-mask social security number dengan string tetap (seperti xxx-xx-xxxx), nomor telepon, atau alamat. Anda kemudian dapat memakai AWS Step Functions state machine untuk mengorkestrasi data pipeline guna meng-ingest data ke dalam S3 data lake.

via - https://docs.aws.amazon.com/glue/latest/dg/detect-PII.html

Run an AWS Glue DataBrew data profile job to identify and suggest potential PII columns present in the dataset. Execute a DataBrew job to apply the transformations to handle the sensitive columns in the entire dataset and store the masked data securely in Amazon S3

AWS Glue DataBrew, sebuah visual data preparation tool, memungkinkan pengguna mengidentifikasi dan menangani data sensitif dengan menerapkan transformasi lanjutan seperti redaction, replacement, encryption, dan decryption pada data personally identifiable information (PII) mereka, serta jenis data lain yang mereka anggap sensitif. DataBrew memiliki transformasi penanganan data PII yang memungkinkan Anda menerapkan data masking, encryption, decryption, dan operasi lain pada data sensitif Anda.

Anda dapat menjalankan data profile job untuk mengidentifikasi dan menyarankan kolom PII potensial yang ada dalam sebuah dataset. Kemudian, Anda dapat menargetkan kolom PII dalam sebuah DataBrew project dan menerapkan berbagai transformasi untuk menangani kolom sensitif yang ada dalam dataset. Terakhir, jalankan DataBrew job untuk menerapkan transformasi pada seluruh dataset dan menyimpan data yang telah diproses, di-mask, dan dienkripsi secara aman di Amazon S3.

via - https://docs.aws.amazon.com/glue/latest/dg/detect-PII.html

Opsi yang salah:

Ingest the dataset into Amazon Kinesis Data Firehose. Leverage a data transformation Lambda function to mask the PII data in the delivery stream and write the transformed output in Amazon S3

Ingest the dataset into Amazon Kinesis Data Streams. Process the stream data using a Lambda function that masks the PII data before writing the output in Amazon S3

Anda perlu menulis custom code pada Lambda function untuk me-mask data PII, yang merupakan upaya operasional yang tidak perlu untuk use case ini, sehingga kedua opsi ini salah.

Utilize the Detect PII transform in AWS Glue Studio to identify the PII. Set up a rule in AWS Glue Data Quality to mask the PII. Use an AWS Step Functions state machine to orchestrate a data pipeline to ingest the data into the S3 data lake - AWS Glue Data Quality adalah fitur AWS Glue yang mengurangi upaya manual terkait kualitas data dengan mengukur dan memantau kualitas data pada data lake dan pipeline secara otomatis. Pada data lake, fitur ini kemudian secara otomatis merekomendasikan data quality rule. Anda dapat memodifikasi rule tersebut, menambahkan rule lain dari built-in rule type, dan mengonfigurasi tindakan untuk memberi tahu tim ketika terjadi masalah kualitas.

AWS Glue Data Quality saat ini mendukung 18 built-in rule type di bawah empat kategori:

Consistency rule memeriksa apakah data lintas kolom berbeda saling sesuai dengan melihat korelasi antar-kolom. Accuracy rule memeriksa apakah jumlah record memenuhi ambang tertentu dan apakah kolom tidak kosong, cocok dengan pola tertentu, memiliki tipe data yang valid, serta memiliki nilai yang valid. Integrity rule memeriksa apakah terdapat duplikat dalam sebuah dataset. Completeness rule memeriksa apakah data dalam dataset Anda tidak memiliki nilai yang hilang.

AWS Glue Data Quality tidak memiliki rule bawaan untuk me-mask PII. Anda dapat membuat custom rule untuk me-mask PII, tetapi hal itu melibatkan upaya operasional tambahan, sehingga opsi ini salah.

💡 Tips

Jika profiling + masking PII dengan effort minim maka Glue Studio Detect PII transform atau Glue DataBrew profile + mask karena keduanya mengidentifikasi & menyamarkan PII tanpa banyak kode.Ingat: deteksi+mask PII → Glue Studio Detect PII / DataBrew; deteksi di S3 → Macie.

A travel booking company needs to store semi-structured reservation session data for a customer-facing application. The application writes session records only when customers create or modify itineraries, but it reads the records frequently during search, checkout, and support workflows. The database layer must be serverless, require minimal administration, and return frequently accessed records within milliseconds.

Which solution will meet these requirements with the LEAST operational overhead?

Jawaban benar

Store the reservation session data in an Amazon DynamoDB table and configure DynamoDB Accelerator to cache frequently accessed items

Karena

Opsi yang benar:

Store the reservation session data in an Amazon DynamoDB table and configure DynamoDB Accelerator to cache frequently accessed items

Amazon DynamoDB adalah NoSQL database yang serverless dan fully managed yang mendukung model data key-value dan dokumen. Hal ini membuatnya cocok untuk data transaksional semi-terstruktur seperti objek reservation session, pilihan pelanggan, dan metadata itinerary.

DynamoDB memberikan performa milidetik satu digit pada skala besar tanpa mengharuskan perusahaan mengelola database server, alokasi storage, patching, atau kapasitas cluster seperti pada database tradisional. Aplikasi ini jarang melakukan write tetapi sering melakukan read, yang selaras dengan pola akses DynamoDB ketika desain tabel memakai partition key dan pola akses yang tepat.

DynamoDB Accelerator (DAX) meningkatkan performa read untuk workload yang didominasi read dengan menambahkan in-memory cache yang fully managed di depan DynamoDB. Karena aplikasi sering mengambil data session yang sama dan membutuhkan pengambilan dalam milidetik, DAX dapat mengurangi read latency dan mengurangi beban read berulang pada tabel DynamoDB.

Opsi yang salah:

Store the reservation session data in an Amazon ElastiCache for Redis cluster, configure the application to write all transactional records directly to the cache, and create daily snapshots for durability - Amazon ElastiCache for Redis dapat memberikan akses dengan latensi sangat rendah untuk data yang di-cache. Namun, memakai Redis sebagai primary transactional data store untuk semua record session meningkatkan risiko terkait durability, recovery, dan pemodelan data dibandingkan DynamoDB.

Opsi ini juga mengharuskan perusahaan mengelola pertimbangan desain spesifik cache seperti sizing memori, perilaku eviction, konfigurasi cluster, dan recovery snapshot. DynamoDB dengan DAX menyediakan pola primary database plus cache yang lebih tepat dengan operational overhead yang lebih rendah.

Store the reservation session data in an Amazon RDS for MySQL cluster and configure RDS Optimized Reads for the database instances - Amazon RDS for MySQL dapat menyimpan data transaksional dalam relational database. Namun, sebuah RDS cluster membutuhkan administrasi database yang lebih banyak dibandingkan serverless NoSQL database untuk use case ini.

RDS Optimized Reads dapat meningkatkan pemrosesan query yang memakai objek sementara pada instance class yang didukung. Fitur ini tidak menyediakan model serverless document database atau lapisan akselerasi in-memory untuk record semi-terstruktur yang sering diakses.

Store the reservation session data in an Amazon S3 Apache Iceberg table and enable S3 Transfer Acceleration for low-latency object access - Tabel Apache Iceberg di Amazon S3 dirancang untuk workload tabel analitik, terutama query data lake, schema evolution, dan analitik skala besar. Tabel ini tidak dirancang untuk read transaksional dalam milidetik dari aplikasi yang menghadap ke pelanggan.

S3 Transfer Acceleration tidak menyelesaikan pola akses database. Fitur ini meningkatkan transfer data masuk atau keluar S3 pada jarak jauh, tetapi tidak menyediakan pengambilan item dengan latensi rendah, key-value lookup transaksional, atau caching untuk read aplikasi yang sering.

💡 Tips

Jika session data semi-terstruktur, write jarang baca sering ms, serverless, overhead minim maka DynamoDB + DAX karena DynamoDB serverless NoSQL & DAX cache baca mikrodetik.Ingat: key/value serverless + cache baca → DynamoDB + DAX.

A data engineer is configuring an AWS Step Function for a banking system workflow. The workflow must process large amounts of data files in parallel and it should simultaneously apply transformations for each file.

Which Step Functions state is the right fit for this requirement?

Jawaban benar

Map state

Karena

Opsi yang benar:

Map state

Anda dapat memakai Map state untuk menjalankan serangkaian langkah workflow bagi setiap item dalam sebuah dataset. Iterasi pada Map state's berjalan secara paralel, sehingga memungkinkan pemrosesan dataset dengan cepat. Map state dapat memakai berbagai tipe input, termasuk JSON array, daftar objek Amazon S3, atau file CSV.

Step Functions menyediakan dua tipe mode pemrosesan untuk memakai Map state dalam workflow Anda: inline mode dan distributed mode.

Secara default, Map state berjalan dalam inline mode. Dalam inline mode, Map state hanya menerima JSON array sebagai input. Dalam mode ini, Map state mendukung hingga 40 iterasi bersamaan.

Dalam distributed mode, Map state memungkinkan pemrosesan dengan konkurensi tinggi. Dalam distributed mode, Map state memproses item dalam dataset melalui iterasi yang disebut child workflow execution. Anda dapat menentukan jumlah child workflow execution yang dapat berjalan secara paralel. Setiap child workflow execution memiliki riwayat eksekusinya sendiri yang terpisah dari parent workflow. Jika Anda tidak menentukannya, Step Functions menjalankan 10.000 child workflow execution secara paralel.

Opsi yang salah:

Parallel state - Parallel state ("Type": "Parallel") dapat dipakai untuk menambahkan cabang eksekusi terpisah dalam state machine Anda. Parallel state menyebabkan AWS Step Functions mengeksekusi setiap cabang, dimulai dari state yang disebut pada field StartAt cabang tersebut, sesecara bersamaan mungkin, dan menunggu hingga semua cabang berhenti (mencapai terminal state) sebelum memproses field Next milik Parallel state.

Choice state - Choice state ("Type": "Choice") menambahkan logika kondisional ke state machine. State ini berisi array Choice Rule yang menentukan ke state mana state machine beralih berikutnya. Anda memakai comparison operator dalam sebuah Choice Rule untuk membandingkan input variable dengan nilai tertentu. Misalnya, dengan Choice Rule Anda dapat membandingkan apakah sebuah input variable lebih besar atau lebih kecil dari 100.

Concurrent state - State ini tidak ada. Ini adalah opsi fiktif yang berfungsi sebagai pengecoh.

💡 Tips

Jika Step Functions proses banyak file paralel dengan transform sama maka pakai Map state karena Map menjalankan iterasi paralel per item.Ingat: paralel per item → Map (Distributed Map untuk skala besar/ribuan item).

A video production company uploads large raw footage files to an Amazon S3 bucket in the us-west-2 Region for transcoding and quality checks. After the transcoding workflow finishes, the company must retain the original raw files for 75 days in case editors need to reprocess any footage. After 75 days, the company no longer needs the originals and wants to delete them to reduce storage costs. The processed videos are stored in a separate S3 bucket.

Which S3 Lifecycle configuration will meet these requirements for the original files MOST cost-effectively?

Jawaban benar

Store the original files in S3 Standard for 75 days and configure an S3 Lifecycle rule to expire the current versions of the files after the retention period

Karena

Opsi yang benar:

Store the original files in S3 Standard for 75 days and configure an S3 Lifecycle rule to expire the current versions of the files after the retention period

Amazon S3 Lifecycle dapat meng-expire versi objek saat ini setelah sejumlah hari tertentu sejak objek dibuat. Perusahaan dapat membuat Lifecycle rule untuk bucket raw footage atau untuk prefix tertentu yang menyimpan file asli dan menetapkan expiration action ke 75 hari.

Solusi ini menjaga file asli tetap tersedia di S3 Standard selama jendela reprocessing. S3 Standard sesuai ketika perusahaan mungkin membutuhkan akses langsung ke file asli selama 75 hari pertama setelah upload.

Opsi ini paling hemat biaya karena perusahaan tidak membutuhkan file asli setelah masa retensi. Meng-expire file secara langsung menghindari transition request yang tidak perlu, biaya durasi penyimpanan minimum, penyimpanan versi, konfigurasi Object Lock, atau penyimpanan arsip jangka panjang untuk file yang rencananya akan dihapus perusahaan.

Opsi yang salah:

Store the original files in S3 Intelligent-Tiering for 75 days, enable bucket versioning, and configure an S3 Lifecycle rule to expire the files after the retention period - S3 Intelligent-Tiering dapat mengoptimalkan biaya penyimpanan ketika pola akses tidak diketahui atau berubah seiring waktu. Namun, ia juga memiliki pertimbangan monitoring dan automasi, sedangkan perusahaan memiliki masa retensi tetap yang jelas untuk file asli.

Mengaktifkan versioning juga dapat meningkatkan konsumsi penyimpanan karena versi noncurrent dapat tetap ada setelah update atau delete kecuali konfigurasi Lifecycle juga mengelola versi noncurrent. Kebutuhan ini tidak memerlukan riwayat versi untuk file asli raw.

Store the original files in S3 Standard-Infrequent Access immediately after upload, keep the files for 75 days, and configure an S3 Lifecycle rule to expire the files when the retention period ends - S3 Standard-Infrequent Access dapat mengurangi biaya penyimpanan untuk objek yang jarang diakses, tetapi memiliki durasi penyimpanan minimum 30 hari dan biaya retrieval. Ia paling baik ketika objek tersimpan cukup lama dan jarang diakses.

Opsi ini langsung mentransisikan file meskipun editor mungkin perlu memprosesnya ulang selama masa retensi. Untuk jendela retensi tetap yang singkat dengan kemungkinan kebutuhan reprocessing langsung, expiration langsung dari S3 Standard adalah pilihan yang lebih sederhana dan lebih aman.

Store the original files in S3 Standard for 75 days, transition the files to S3 Glacier Flexible Retrieval, and then configure expiration after archival storage - S3 Glacier Flexible Retrieval dirancang untuk data arsip yang tidak membutuhkan akses langsung. Ia juga memiliki durasi penyimpanan minimum 90 hari, sehingga mentransisikan objek di sekitar akhir jendela retensi 75 hari dapat menimbulkan biaya durasi minimum yang tidak perlu.
