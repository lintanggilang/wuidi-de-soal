An analytics engineering team is migrating two existing ingestion workflows to AWS. The first workflow is an Apache Spark application written in Scala that will run on Amazon EMR and must read data from a PostgreSQL database. The second workflow is a legacy Windows-based data integration tool that can connect to databases only through an ODBC data source name (DSN). The team wants to keep changes to each workflow minimal by using the most appropriate connectivity method for each. Which TWO statements are correct? (Select TWO.)

Jawaban benar

The Spark application on Amazon EMR should connect to PostgreSQL by using a JDBC driver, because JDBC is commonly used by Java/Scala applications and is platform-independent.

The Windows-based integration tool should use an ODBC driver and DSN to connect to PostgreSQL, because ODBC is generally language-independent but requires platform-specific drivers.

Karena

Skenario ini menguji kemampuan Anda memilih antarmuka konektivitas database yang tepat saat melakukan ingestion dari sumber relasional. Workload berbasis JVM (seperti job Scala Spark yang berjalan di Amazon EMR) secara alami cocok dengan JDBC. JDBC adalah antarmuka umum yang digunakan oleh Java dan bahasa JVM untuk terhubung ke database relasional, dan dirancang agar platform-independent selama JDBC driver spesifik untuk database tersebut tersedia. Sebuah tool Windows lama yang secara eksplisit membutuhkan ODBC DSN harus menggunakan ODBC. ODBC umum dipakai oleh berbagai macam tool tanpa memandang bahasa pemrograman, tetapi bergantung pada instalasi driver yang spesifik untuk sistem operasi (misalnya, memasang ODBC driver di Windows dan mengonfigurasi DSN). Opsi yang salah justru menukar properti JDBC dan ODBC, mengklaim bahwa driver tidak diperlukan, atau mengusulkan mengarahkan kedua alur kerja melalui layanan yang bukan merupakan metode konektivitas database yang langsung dan minim perubahan untuk kebutuhan yang disebutkan. Further reading (AWS): - Deploying an EMR cluster on AWS Outposts to process data from an on-premises database | AWS Compute Blog (AWS Blog) - Use the Hive JDBC driver - Amazon EMR (AWS Documentation) - Windows - Amazon Athena (AWS Documentation)

💡 Tips

Jika app Spark/Scala di EMR konek PostgreSQL dan tool Windows lama konek via DSN maka Spark pakai JDBC, tool Windows pakai ODBC/DSN karena JDBC untuk Java/Scala (platform-independent), ODBC butuh driver per-platform.Ingat: JDBC = Java; ODBC = language-independent tapi driver OS-spesifik (DSN).

An e-commerce retailer stores curated datasets in Amazon S3 and Amazon Redshift. Data engineers use AWS Glue Data Catalog tables so that Amazon Athena can query the data in the data lake. Business analysts report that they still struggle to discover the correct datasets and interpret business meaning for fields such as “net_revenue” and “active_customer.” The analysts want a business-facing catalog where they can search for datasets, maintain business terminology, and manage access through projects and approval workflows. Which solution will meet these requirements with the LEAST operational overhead?

Jawaban benar

Use Amazon SageMaker Catalog to create a business data catalog. Define a business taxonomy/glossary, organize datasets into projects, and manage governed access requests and approvals through the catalog.

Karena

Kebutuhan utamanya adalah kemampuan business data catalog, bukan sekadar penemuan schema teknis. Pada setup bergaya lakehouse AWS yang umum, AWS Glue Data Catalog menyediakan metadata teknis (database, table, partition, dan schema) yang dapat digunakan query engine seperti Athena untuk menginterpretasikan file di Amazon S3. Hal itu menjawab “bagaimana cara meng-query data,” tetapi sering kali tidak menjawab “bagaimana pengguna bisnis menemukan dan memahami makna data” atau “bagaimana kita mengelola permintaan akses secara tertata dan ramah bisnis.” Amazon SageMaker Catalog dirancang khusus untuk membuat dan mengelola business data catalog. Katalog bisnis berfokus pada discoverability, konteks bisnis (taxonomy/glossary), dan konstruksi kolaborasi seperti project, beserta alur governance untuk meminta dan menyetujui akses. Karena merupakan managed service untuk tujuan ini, ia meminimalkan pengembangan kustom dan beban operasional yang berkelanjutan. Opsi lain hanya berfokus pada cataloging teknis (Glue Data Catalog), berfokus terutama pada penegakan izin untuk akses data lake (Lake Formation), atau mengharuskan membangun dan mengoperasikan aplikasi kustom (Aurora plus EC2) yang meningkatkan beban operasional. A data engineering team stores daily extracts in an Amazon S3 bucket under the prefix s3://company-data-lake/staging/. The team enabled S3 versioning on the bucket to protect against accidental overwrites. To control storage growth, the team needs the current objects in the staging/ prefix to be deleted 7 days after they are created. The team also needs older versions of those same objects to be permanently removed 30 days after they become noncurrent. Which solutions will meet these requirements with the LEAST operational overhead? (Select TWO.)

Jawaban benar

Create an S3 Lifecycle rule with a filter for the staging/ prefix and configure a NoncurrentVersionExpiration action to permanently delete noncurrent versions 30 days after they become noncurrent.

Create an S3 Lifecycle rule with a filter for the staging/ prefix and configure an Expiration action to delete current objects 7 days after object creation.

Karena

S3 Lifecycle policies adalah mekanisme yang memang dirancang untuk meng-expire (menghapus) data setelah mencapai usia tertentu. Dengan membatasi rule pada prefix seperti staging/, lifecycle policy hanya berlaku untuk dataset sementara yang perlu dibersihkan. Dengan versioning aktif, menghapus sebuah objek akan membuat delete marker, dan versi lama bisa tetap tersimpan sebagai noncurrent version. Oleh karena itu, memenuhi tujuan retention pada bucket yang ber-versioning umumnya membutuhkan dua perilaku lifecycle: satu rule action yang meng-expire objek current setelah sejumlah hari tertentu, dan rule action lain yang menghapus noncurrent version setelah menjadi noncurrent selama durasi yang dibutuhkan. Pendekatan ini sepenuhnya dikelola oleh S3 dan menghindari pembangunan serta pengoperasian alur penghapusan kustom. 💡 Tips

Jika objek current hapus 7 hari & versi noncurrent hapus 30 hari maka buat Lifecycle Expiration (current, 7 hari) + NoncurrentVersionExpiration (30 hari) karena keduanya aksi lifecycle terpisah.Ingat: Expiration = versi current; NoncurrentVersionExpiration = versi lama (butuh versioning aktif).

A retail analytics team publishes checkout events to an Amazon Kinesis Data Streams stream. Each record must be processed within seconds to validate required fields and enrich the payload before the transformed result is stored in an Amazon DynamoDB table for downstream reporting. Which solution will meet these requirements with the LEAST operational overhead?

Jawaban benar

Configure an AWS Lambda function as a consumer of the Kinesis data stream by creating an event source mapping, and write the transformed records from the Lambda function to DynamoDB.

Karena

Untuk memanggil Lambda function dari Kinesis Data Streams dengan upaya operasional minimal, pola paling langsung adalah mengonfigurasi Lambda sebagai stream consumer menggunakan event source mapping. Dengan integrasi ini, Lambda terus-menerus melakukan polling pada Kinesis data stream dan mengirimkan batch stream record ke function. Lambda memproses record dari setiap shard secara berurutan, dan Anda dapat mengatur perilaku batching (misalnya, batch size) untuk menyeimbangkan throughput dan waktu eksekusi. Jika sebuah batch gagal, Lambda melakukan retry, yang penting dipahami karena error yang tidak ditangani dapat menunda pemrosesan pada shard terkait hingga batch berhasil atau data expired. Alternatif seperti menjalankan consumer berbasis KCL di ECS (atau compute lain) menambah tanggung jawab infrastruktur dan operasional tanpa memberi manfaat untuk langkah validasi/enrichment sederhana. Firehose bisa mentransformasi record dengan Lambda tetapi tidak dapat mengirim langsung ke DynamoDB, dan EventBridge rule bukan pengganti untuk mengonsumsi payload record dari Kinesis Data Streams. 💡 Tips

Jika proses tiap record Kinesis dalam hitungan detik lalu simpan ke DynamoDB, overhead minim maka pakai Lambda sebagai consumer (event source mapping) karena Lambda otomatis poll shard tanpa kelola server.Ingat: Kinesis/DynamoDB Streams → Lambda via event source mapping (ESM).

A retail analytics team needs to ingest shipment tracking events from a third-party logistics provider. The provider exposes a REST API that returns the last hour of events in JSON format when called with an API token. The team wants to store the raw JSON responses in an Amazon S3 data lake every hour with the LEAST operational overhead. Which solution will meet these requirements?

Jawaban benar

Create an Amazon EventBridge scheduled rule that invokes an AWS Lambda function every hour. In the Lambda function, call the provider’s REST API and write the JSON payload to Amazon S3. Store the API token in AWS Secrets Manager and allow the Lambda execution role to retrieve the secret and put objects in the target S3 bucket.

Karena

Untuk mengonsumsi data API dalam sebuah pipeline ingestion, kebutuhan utamanya adalah menjalankan kode yang dapat melakukan autentikasi ke endpoint eksternal (biasanya melalui HTTPS), meminta data (sering kali JSON), dan menyimpan hasilnya ke landing zone AWS seperti Amazon S3. Pola serverless adalah cara paling efisien secara operasional untuk melakukan ini di AWS pada polling terjadwal yang sederhana: - Amazon EventBridge dapat menjalankan scheduled rule (gaya cron) untuk memicu pekerjaan pada irama tetap tanpa manajemen server apa pun. - AWS Lambda dapat mengeksekusi logika pemanggilan API (misalnya, menggunakan HTTP client) lalu menyimpan response mentah sebagai objek di Amazon S3, yang umum digunakan sebagai raw zone sebuah data lake. - Menggunakan AWS Secrets Manager untuk API token menjaga credential tetap di luar kode dan file konfigurasi. Lambda execution role dapat diberi hanya izin yang dibutuhkannya (membaca secret dan menulis ke lokasi S3 tertentu). Opsi lain kurang cocok karena memperkenalkan manajemen infrastruktur yang tidak perlu (Amazon EC2), menggunakan layanan pemrosesan data yang lebih berat hanya untuk memanggil API (AWS Glue Spark job), atau membutuhkan gaya webhook berbasis push yang tidak disebutkan dan mengubah masalah dari mengonsumsi API menjadi meng-host API (API Gateway). Further reading (AWS): - Tutorial: Create an EventBridge scheduled rule for AWS Lambda functions - Amazon EventBridge (AWS Documentation) - Use Secrets Manager secrets in Lambda functions - AWS Lambda (AWS Documentation) - Uploading objects - Amazon Simple Storage Service (AWS Documentation)

💡 Tips

Jika panggil REST API tiap jam & simpan JSON mentah ke S3, overhead minim maka EventBridge Scheduler → Lambda (token di Secrets Manager) karena jadwal + fungsi serverless paling ringan.Ingat jadwal: EventBridge scheduled rule/Scheduler = cron serverless; token/rahasia → Secrets Manager.

A retail analytics team is building an event ingestion endpoint for a clickstream pipeline. Mobile clients send HTTPS requests to an Amazon API Gateway REST API. The API uses an AWS service integration to write each request payload directly into an Amazon Kinesis Data Streams stream. The team must configure authentication so that API Gateway can write to the stream without storing long-term access keys anywhere. The solution must follow least-privilege permissions and require the LEAST operational overhead. Which solution meets these requirements?

Jawaban benar

Create an IAM role that API Gateway can assume. Attach a policy that allows kinesis:PutRecord and kinesis:PutRecords on the specific stream ARN. Configure the API Gateway integration to use this role as its credentials.

Karena

API Gateway tidak dapat memanggil Kinesis Data Streams secara anonim. Bahkan ketika menggunakan AWS service integration (tanpa Lambda), API Gateway tetap harus melakukan autentikasi ke Kinesis dengan menandatangani request menggunakan AWS credential. Cara yang direkomendasikan untuk menyediakan credential tersebut—tanpa menyematkan atau mendistribusikan access key—adalah mengonfigurasi IAM role untuk API Gateway. Dengan pola ini, dua konsep IAM bekerja bersama: • Trust policy (siapa yang boleh assume role): Role harus mempercayai layanan API Gateway sehingga API Gateway diizinkan meng-assume-nya. • Permissions policy (apa yang boleh dilakukan role): Role hanya boleh mengizinkan operasi tulis Kinesis yang dibutuhkan integrasi (umumnya PutRecord/PutRecords) dan membatasi Resource pada ARN stream tertentu demi least privilege. Pendekatan ini sepenuhnya menghindari access key jangka panjang, menjaga izin tetap terpusat di IAM, dan membutuhkan operasi berkelanjutan yang minimal karena AWS menangani penerbitan dan rotasi credential secara otomatis ketika layanan meng-assume role tersebut. Further reading (AWS): - Tutorial: Create a REST API as an Amazon Kinesis proxy - Amazon API Gateway (AWS Documentation) - Tutorial: Create a REST API with an AWS integration - Amazon API Gateway (AWS Documentation) - Controlling access to Amazon Kinesis Data Streams resources using IAM - Amazon Kinesis Data Streams (AWS Documentation)

💡 Tips

Jika API Gateway harus tulis ke Kinesis tanpa access key jangka panjang, least-privilege maka pakai IAM role yang di-assume API Gateway (izin kinesis:PutRecord pada ARN stream) karena role memberi kredensial sementara.Ingat: integrasi layanan AWS tanpa kredensial statis = IAM role (bukan access key).

An HR analytics team runs a scheduled AWS Lambda function that processes daily time-tracking files in an Amazon S3 bucket named corp-data-lake. The function uses the ListObjectsV2 API operation to enumerate input objects under the prefix hr/ingest/, downloads each file, and then writes transformed output objects under the prefix hr/curated/. The same bucket also contains a finance/raw/ prefix with sensitive data that the Lambda function must not be able to read. The Lambda execution role currently uses AWS managed policies, but the security team requires least-privilege permissions and has determined that no single managed policy provides the required combination of restricted read access to hr/ingest/ and write access to hr/curated/. Which solution will meet these requirements with the LEAST privilege?

Jawaban benar

Create and attach a customer-managed IAM policy to the Lambda execution role that allows only the required S3 actions on only the required bucket locations, such as: { "Version": "2012-10-17", "Statement": [ { "Sid": "ListOnlyHrIngestPrefix", "Effect": "Allow", "Action": "s3:ListBucket", "Resource": "arn:aws:s3:::corp-data-lake", "Condition": { "StringLike": { "s3:prefix": "hr/ingest/*" } } }, { "Sid": "ReadOnlyHrIngestObjects", "Effect": "Allow", "Action": "s3:GetObject", "Resource": "arn:aws:s3:::corp-data-lake/hr/ingest/*" }, { "Sid": "WriteOnlyHrCuratedObjects", "Effect": "Allow", "Action": "s3:PutObject", "Resource": "arn:aws:s3:::corp-data-lake/hr/curated/*" } ] }

Karena

Skenario ini membutuhkan izin yang spesifik untuk sekumpulan operasi S3 yang sempit sekaligus terbatas pada key prefix tertentu dalam satu bucket. AWS managed policy sengaja dibuat generik untuk kasus penggunaan yang luas, sehingga sering memberi akses yang lebih lebar daripada yang seharusnya dimiliki sebuah pipeline data yang terkontrol ketat. Pendekatan least-privilege adalah menulis customer-managed IAM policy yang persis sesuai dengan apa yang dilakukan Lambda function: • Gunakan s3:ListBucket pada ARN bucket (bukan ARN objek) dan batasi operasi list hanya pada prefix yang dibutuhkan dengan menggunakan condition pada s3:prefix. Hal ini sejalan dengan cara S3 mengevaluasi operasi List: action berlaku pada resource bucket, sementara filter dinyatakan sebagai condition. • Gunakan s3:GetObject hanya pada ARN objek di bawah input prefix. Action tingkat objek harus merujuk pola ARN objek (ARN bucket ditambah key path dan wildcard). • Gunakan s3:PutObject hanya pada ARN objek di bawah output prefix. Ini mengizinkan penulisan hasil tanpa memberi akses baca ke lokasi bucket lain. Dengan hanya memberikan action yang dibatasi ini, execution role tidak akan memiliki izin membaca dari finance/raw/ (atau prefix lain yang tidak terkait), yang memenuhi kebutuhan melindungi data sensitif sekaligus tetap memungkinkan alur ETL berfungsi dengan benar. Further reading (AWS): - Bucket policy examples using condition keys - Amazon Simple Storage Service (AWS Documentation) - Required permissions for Amazon S3 API operations - Amazon Simple Storage Service (AWS Documentation) - Defining Lambda function permissions with an execution role - AWS Lambda (AWS Documentation)

💡 Tips

Jika butuh least-privilege S3 (baca hr/ingest/, tulis hr/curated/, tolak finance/raw/) maka buat customer-managed IAM policy spesifik prefix karena managed policy tak bisa membatasi ke prefix tertentu.Ingat: s3:ListBucket pakai Condition s3:prefix; GetObject/PutObject pakai ARN objek (bucket/prefix/*).

A retail data platform team uses Amazon Managed Workflows for Apache Airflow (Amazon MWAA) to orchestrate a nightly pipeline. One task connects to an Amazon Redshift cluster in the same VPC by using a JDBC connection over TCP port 5439 to run SQL statements. After a security hardening change, the Airflow task begins to fail with a connection timeout to the Redshift cluster endpoint. The team confirms that the Redshift cluster is healthy and that an Amazon EC2 instance in the same VPC can still connect to the cluster endpoint successfully. Which action will most likely restore the Amazon MWAA workflow with the LEAST operational overhead?

Jawaban benar

Modify the Amazon Redshift security group inbound rules to allow TCP port 5439 from the security group that is associated with the Amazon MWAA environment.

Karena

Amazon MWAA adalah managed Apache Airflow service, tetapi task yang dijalankannya tetap dieksekusi di dalam VPC Anda. Dalam praktiknya, itu berarti Airflow worker tunduk pada kontrol jaringan yang sama seperti workload lain: VPC routing, network ACL, dan—yang paling umum—security group. Koneksi JDBC dari sebuah Airflow task ke cluster Amazon Redshift adalah koneksi TCP langsung ke endpoint cluster (biasanya port 5439). Jika task tersebut mulai mengalami timeout tepat setelah sebuah “perubahan security hardening,” akar masalah yang paling mungkin adalah bahwa inbound rule pada security group Redshift tidak lagi mengizinkan trafik dari sumber koneksi tersebut. Fakta bahwa instance EC2 di VPC yang sama masih bisa terhubung sangat mengindikasikan cluster dapat dijangkau dan sehat, serta bahwa masalahnya spesifik pada apa yang diizinkan (dan tidak diizinkan) sebagai source di security group Redshift. Memperbarui security group Redshift agar mengizinkan inbound TCP 5439 dari security group yang terpasang pada environment MWAA adalah remediasi tercepat dan paling ringan. Hal ini memperbaiki jalur jaringan untuk alur kerja yang ada tanpa perlu mengubah kode DAG, menambah komponen baru seperti NAT gateway, atau memperkenalkan metode akses alternatif. NAT gateway menangani egress internet untuk subnet privat dan tidak membantu konektivitas database privat di dalam VPC. Demikian pula, menambah izin IAM mungkin memperbaiki error access denied saat mengambil credential, tetapi tidak dapat menyelesaikan TCP connection timeout karena IAM tidak mengontrol keterjangkauan jaringan. Further reading (AWS): - Security in your VPC on Amazon MWAA - Amazon Managed Workflows for Apache Airflow (AWS Documentation) - About networking on Amazon MWAA - Amazon Managed Workflows for Apache Airflow (AWS Documentation) - Configuring security group communication settings for an Amazon Redshift cluster or an Amazon Redshift Serverless workgroup - Amazon Redshift (AWS Documentation)

💡 Tips

Jika MWAA timeout ke Redshift (5439) padahal EC2 di VPC sama bisa maka izinkan inbound 5439 dari SG MWAA di SG Redshift karena penyebabnya aturan security group, bukan Redshift.Ingat: connection timeout di VPC biasanya Security Group/NACL; Redshift port = 5439.

The team needs to run ad hoc SQL queries directly on the S3 data to investigate a spike in checkout failures, without provisioning or managing servers. Which solution will meet these requirements with the LEAST operational overhead?

Create an Amazon Athena table for the S3 dataset (for example, by using the AWS Glue Data Catalog). Run SQL queries in Athena to analyze the Parquet partitions in place.

A healthcare analytics team receives nightly exports of appointment and billing events as large CSV files (multiple terabytes) in an Amazon S3 data lake. Before analysts can use the data in an Amazon Redshift data warehouse, the team must standardize column formats, remove duplicate records, and store the curated data in a columnar format to reduce downstream query costs. Which combination of steps will meet these requirements with the LEAST operational overhead? (Select TWO.)

Jawaban benar

Create an AWS Glue ETL job to cleanse and deduplicate the CSV data, convert the output to Apache Parquet, and write the curated dataset back to Amazon S3 in a separate prefix.

Use the Amazon Redshift COPY command to load the curated Parquet data from Amazon S3 into Amazon Redshift by using an IAM role for S3 access.

Karena

Workload ini adalah pola batch transform-and-load klasik: file CSV besar mendarat di Amazon S3, harus dibersihkan dan di-deduplikasi, dikonversi ke format kolumnar yang ramah analitik, lalu dimuat ke data warehouse untuk reporting. A healthcare analytics team stores appointment events as Apache Parquet files in an Amazon S3 data lake. Data analysts query the data with Amazon Athena, and data engineers run Apache Spark jobs on Amazon EMR. The team must support GDPR requests that require deleting individual records and must be able to query prior versions of the dataset for audits and rollback purposes. Which TWO actions will meet these requirements with the LEAST operational overhead?

Jawaban benar

Store and manage the table metadata in the AWS Glue Data Catalog so Athena and EMR Spark can share the same table definitions and track schema and snapshot metadata consistently.

Create new Athena tables that use the Apache Iceberg open table format (for example, use table properties such as table_type='ICEBERG') so updates and deletes are managed transactionally.

Karena

Kebutuhan utamanya adalah mendukung perubahan tingkat baris (seperti penghapusan GDPR) sekaligus memungkinkan akses ke versi historis untuk audit/rollback, dan melakukannya dengan cara yang dapat digunakan oleh Athena maupun Spark di EMR tanpa membangun logika locking dan manajemen versi kustom. Apache Iceberg adalah open table format yang dirancang untuk data lake. Ia menyimpan dataset di object storage (biasanya Amazon S3) sambil memelihara metadata table yang memungkinkan konsistensi transaksional bergaya ACID untuk operasi tulis (termasuk update dan delete), schema evolution, dan time travel (meng-query snapshot historis). A retail analytics team receives a daily CSV extract in an Amazon S3 data lake. The extract frequently contains duplicate rows and occasional missing values that cause downstream reporting inconsistencies. Before the team publishes the data for wider use, they want a managed, interactive way to visually inspect the dataset, apply cleaning transformations, and run a quick validation model to confirm the cleaned dataset is usable. The cleaned output must be written back to Amazon S3. Which solution will meet these requirements with the LEAST operational overhead?

Jawaban benar

Use Amazon SageMaker Data Wrangler in Amazon SageMaker Studio to import the CSV data from Amazon S3, visually inspect and transform the data to remove duplicates and address missing values, run a Quick Model for validation, and export the cleaned dataset to Amazon S3.

Karena

Skenario ini menuntut pendekatan interaktif dan terkelola untuk memverifikasi dan membersihkan data (penghapusan duplikat dan penanganan nilai yang hilang) lalu memvalidasi bahwa dataset yang telah dibersihkan dapat digunakan dengan menjalankan sebuah quick model, dengan output ditulis kembali ke Amazon S3. Amazon SageMaker Data Wrangler dirancang khusus untuk alur kerja ini. Ia menyediakan pengalaman visual yang terintegrasi di SageMaker Studio untuk mengimpor data dari Amazon S3, mengeksplorasi dan memvisualisasikan masalah seperti nilai yang hilang dan field yang tidak konsisten, serta menerapkan transformasi tanpa menyiapkan dan mengoperasikan cluster pemrosesan data Anda sendiri. Ia juga menyertakan fitur Quick Model yang dapat dengan cepat melatih dan mengevaluasi sebuah model sederhana terhadap data yang telah disiapkan, yang merupakan cara praktis untuk memvalidasi bahwa dataset yang telah dibersihkan sudah wajar sebelum dipublikasikan.
