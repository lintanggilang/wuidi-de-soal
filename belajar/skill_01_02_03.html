Key Points

  • AWS Glue ETL job can reads from multiple heterogeneous sources (JDBC for RDS, DynamoDB connector, S3 for files) in one job. DynamicFrames/DataFrames enables joins and transformation before writes result akhir to Redshift. This most efficient because one job handles all.
  • Glue Streaming ETL supports stream-to-batch joins. Streaming source (Kinesis) in-join with static/slowly changing data from S3 uses broadcast join or lookup. Glue handles micro-batching and writes to data lake automatically.
  • Glue crawlers detects schema berbagai database. Data Catalog becomes metadata registry pusat. Glue ETL jobs with schema mapping (ApplyMapping transform) menstandarkan heterogeneous schemas to format canonical that consistent. This most maintainable because schema changes is detected automatic.
  • Each source requires connector that different: AppFlow has native Salesforce connector, Lambda can consume REST APIs, and Glue JDBC connects to data warehouse on-premises. Landing data to S3 as common layer, then one consolidation job integrates semuanya.
  • Lake Formation cross-account sharing enables sharing Data Catalog tables and underlying S3 data without copying. Central account can query all data through Athena with unified view. Lake Formation manages fine-grained permissions.
  • Broadcast join very efficient when one table small (fits in memory per worker). Dimension table 10,000 rows in-broadcast to all executors, so that join is performed locally without expensive data shuffling. This avoids shuffle from 2 billion row fact table.
  • Medallion architecture separates ingestion (bronze) from integration (silver). Each source in-ingest on jadwalnya each. Integration job reads "latest available" partition from each source, so that view always ter-update although data arrives asynchronously.
  • Standardisasi data before join is best practice. Uses lower() function on column email in second sources before join ensures matching that akurat. This simpel, efficient, and deterministic.
  • Redshift provides unified SQL interface: Streaming Ingestion for real-time data from Kinesis, internal tables for historical data, and Redshift Spectrum external tables for S3 files. All can in-join in single SQL query.
  • Apache Iceberg (and Delta Lake, Hudi) supports MERGE INTO (upsert) that handles insert, update, and delete in one operation atomic. Iceberg performs row-level operations on Parquet files without rewriting entire partitions. This most efficient for CDC (Change Data Capture) integration.
