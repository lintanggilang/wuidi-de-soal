Key Services & Concepts

AWS IAM
Identity and Access Management: user, group, role, and policy for access least-privilege.
IAM Access Analyzer
Mengidentifikasi access berlebih/external and membantu menyusun policy least-privilege.

Key Points

  • Policy this applies least privilege with correct: Statement 1 (Allow GetObject on */raw/*): Mengizinkan read from ANY bucket but ONLY prefix "raw/" — memenuhi requirement #1. Statement 2 (Allow PutObject on specific bucket/prefix): Write only to data-lake-prod/processed/* — memenuhi requirement #2. Statement 3 (Explicit Deny DeleteObject): Explicit Deny on DeleteObject for all S3 resources ensures TIDAK EXIST policy other that can override (explicit Deny always wins) — memenuhi requirement #3.
  • For enforce regional restrictions, gunakan explicit Deny with condition StringNotEquals on aws:RequestedRegion. Policy: {"Effect": "Deny", "Action": "glue:*", "Resource": "*", "Condition": {"StringNotEquals": {"aws:RequestedRegion": "eu-west-1"}}}. This artinya: DENY all Glue actions if region that requested NOT eu-west-1. Explicit Deny always override Allow policies manapun, so that even if there is Allow policy for Glue in region other, Deny will applies. aws:RequestedRegion is global condition key that contains region tempat API call ditujukan.
  • IAM policy variables enables dynamic resource resolution based on request context. Contoh: if databases dinamai appropriate team tag (team-analytics-db, team-ml-db), Resource ARN can is written as "arn:aws:glue:*:*:database/${aws:PrincipalTag/team}-*". Satu statement this replace 50+ explicit ARN entries. Strategi other for size management: (1) Group resources by common prefix patterns, (2) Use multiple managed policies (max 10 per role), (3) Combine conditions efficiently.
  • IAM Policy Simulator (https://policysim.aws.amazon.com) enables testing policies without deployment: (1) Input policy JSON, (2) Select specific actions (redshift:GetClusterCredentials, s3:GetObject, etc.), (3) Specify resource ARNs, (4) Simulator evaluates policy and shows Allow/Deny/Implicit Deny result. Best practice workflow: Step 1 — Simulate policy with Policy Simulator for all expected actions. Step 2 — Attach policy to test role in non-prod environment. Step 3 — Run test workloads and verify CloudTrail for access patterns. Step 4 — Setelah validated, attach to production role.
  • Fastest mitigation: Tambahkan explicit Deny statement that limits overly-broad permissions. Approach: (1) Add Deny statement for dangerous actions (s3:DeleteBucket, s3:PutBucketPolicy, etc.) and resources that should not diakses, ATAU (2) Attach a Permissions Boundary that defines maximum allowed permissions — boundary acts as ceiling regardless of identity policies. Permissions Boundary particularly useful because: can in-apply without modifying existing policy, immediately restricts effective permissions, doesn't break other needed statements. Contoh Deny: {"Effect": "Deny", "Action": ["s3:Delete*", "s3:PutBucket*"], "Resource": "*"} plus {"Effect": "Deny", "Action": "s3:*", "NotResource": ["arn:aws:s3:::allowed-bucket/*"]}.
  • For time-based access control, gunakan aws:CurrentTime condition key with DateGreaterThanEquals and DateLessThanEquals operators. Format time-only (08:00:00Z) creates condition berulang each days (without fixed date). Policy structure: {"Effect": "Allow", "Action": "sts:AssumeRole", "Resource": "arn:aws:iam::333333333333:role/CrossAccountRedshiftRole", "Condition": {"DateGreaterThanEquals": {"aws:CurrentTime": "08:00:00Z"}, "DateLessThanEquals": {"aws:CurrentTime": "18:00:00Z"}}}. Catatan: aws:CurrentTime with time-only format enables daily recurring windows. For day-of-week restriction, requires additional custom logic (Lambda authorizer) because IAM not natively support day-of-week conditions.
  • ABAC (Attribute-Based Access Control) uses tags for dynamic authorization. Condition key aws:ResourceTag/team gets value tag "team" on resource that diakses. Policy variable ${aws:PrincipalTag/team} gets value tag "team" from calling principal (IAM user/role). By StringEquals comparison: access only is allowed if tag "team" on resource SAME with tag "team" on principal. If engineer has tag team=analytics, mereka only can manage Glue jobs that also tagged team=analytics. Benefit: does not need update policy when team members changes — quite manage tags.
  • Least privilege means granting ONLY the exact permissions needed, on the exact resources needed: S3: s3:GetObject (read only, no list/write) on "arn:aws:s3:::source-bucket/source-path/*" — crawler reads objects from specific path. Glue Catalog: glue:CreateTable, glue:UpdateTable, glue:BatchCreatePartition, glue:GetDatabase on "arn:aws:glue:region:account:database/specific-db" and "arn:aws:glue:region:account:table/specific-db/*" — only the target database. CloudWatch Logs: logs:CreateLogGroup, logs:CreateLogStream, logs:PutLogEvents on "arn:aws:logs:region:account:log-group:/aws-glue/crawlers*" — specific log group.
  • Policy this uses Deny + StringNotEquals for forces usage SPECIFIC KMS key: If request PutObject not uses KMS key ID that is determined → DENY. Condition key s3:x-amz-server-side-encryption-aws-kms-key-id contains ARN KMS key that is used for server-side encryption. StringNotEquals ensures that ONLY key specific said that is received — not key other, not encryption type other.
  • IAM policy evaluation with multiple policy types: glue:StartJobRun evaluation: (1) Identity policy: Allow ✓, (2) Permissions boundary: allows glue:* ✓, (3) SCP: does not deny glue:StartJobRun ✓. Result: ALLOWED — all three layers permit it. glue:DeleteJob evaluation: (1) Identity policy: no explicit Allow for DeleteJob (implicit deny), but even if it were allowed: (2) SCP: explicit Deny on glue:DeleteJob ✗. Result: DENIED. SCP Deny overrides everything — even if identity policy AND permissions boundary both allowed it. Evaluation order: Explicit Deny (any layer) → SCP evaluation → Permissions Boundary → Identity policies → Resource policies. Key rule: for action to be allowed, it must be permitted by ALL applicable policy types (identity, boundary, SCP) with NO explicit deny from ANY layer.

Common Misconceptions & Pitfalls

  • Memenuhi requirements #1 and #2 but without explicit Deny, policy other can provides DeleteObject permission.
  • Provides too many permissions (s3:PutObject to all buckets).
  • Too restrictive (only one bucket) and enables write to all prefixes.
  • Aws:SourceIp contains IP address, not region name.
  • Aws:SourceRegion not condition key that valid for scenario this.
  • Has logic that correct but its description membingungkan — this sebenarnya same with C if is applied with correct.
  • Sacrifices fine-grained control — provides access to ALL databases.
  • Incorrect — inline policies has limit 2,048 characters (smaller from managed policy).
  • Removes security controls and doesn't solve root cause if resources dominate the policy size.
  • IAM policies are global, region separation not membantu testing.
  • Langsung to production — risky if policy too restrictive (break production) or too permissive (security gap).
  • DateGreaterThan condition can works but not proper testing approach.
  • Breaks ALL services attached to it.
  • Disruptive if policy has other needed statements.
  • Too slow for security incident.
  • Uses fixed date — only applies on one days.
  • Aws:TokenIssueTime tracks when token is created, not current time.
  • Uses ${aws:username} that not team identifier.
  • Only checks whether tag key "team" there is, not value comparison.
  • Hardcodes one team value — not dynamic.
  • Incorrect — Glue NEEDS explicit permissions for catalog and logging.
  • Is complex and AWSGlueServiceRole grants access to ALL databases/S3 paths.
  • Violates least privilege completely.
  • Is about HTTPS vs HTTP transport, not encryption at rest.
  • Only ensures SOME encryption header there is, but not forces specific key — too broad (s3:* on all resources).
  • Only ensures KMS encryption is used but not forces KEY SPESIFIK — any KMS key would be allowed.
  • Incorrect — boundary allows glue:*.
  • Incorrect — boundary allows glue:StartJobRun.
