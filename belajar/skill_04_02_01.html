Domain 4: Security & Governance — Task 4.2: Apply authorization mechanisms

Skill 4.2.1: Custom IAM policies

customIAMpoliciesleastprivilege

Ringkasan

Skill ini termasuk dalam Domain 4: Security & Governance (Task 4.2: Apply authorization mechanisms), dengan fokus pada custom iam policies. Materi berikut merangkum layanan AWS yang relevan beserta konsep penting yang perlu kamu kuasai untuk topik ini.

Layanan & Konsep Utama

AWS IAM
Identity and Access Management: user, group, role, dan policy untuk akses least-privilege.
IAM Access Analyzer
Mengidentifikasi akses berlebih/eksternal dan membantu menyusun policy least-privilege.

Poin-Poin Kunci

  • Policy ini menerapkan least privilege dengan tepat: Statement 1 (Allow GetObject on */raw/*): Mengizinkan read dari ANY bucket tapi HANYA prefix "raw/" — memenuhi requirement #1. Statement 2 (Allow PutObject on specific bucket/prefix): Write hanya ke data-lake-prod/processed/* — memenuhi requirement #2. Statement 3 (Explicit Deny DeleteObject): Explicit Deny pada DeleteObject untuk semua S3 resources memastikan TIDAK ADA policy lain yang bisa override (explicit Deny always wins) — memenuhi requirement #3.
  • Untuk enforce regional restrictions, gunakan explicit Deny dengan condition StringNotEquals pada aws:RequestedRegion. Policy: {"Effect": "Deny", "Action": "glue:*", "Resource": "*", "Condition": {"StringNotEquals": {"aws:RequestedRegion": "eu-west-1"}}}. Ini artinya: DENY semua Glue actions jika region yang diminta BUKAN eu-west-1. Explicit Deny selalu override Allow policies manapun, sehingga bahkan jika ada Allow policy untuk Glue di region lain, Deny akan berlaku. aws:RequestedRegion adalah global condition key yang berisi region tempat API call ditujukan.
  • IAM policy variables memungkinkan dynamic resource resolution berdasarkan request context. Contoh: jika databases dinamai sesuai team tag (team-analytics-db, team-ml-db), Resource ARN bisa ditulis sebagai "arn:aws:glue:*:*:database/${aws:PrincipalTag/team}-*". Satu statement ini replace 50+ explicit ARN entries. Strategi lain untuk size management: (1) Group resources by common prefix patterns, (2) Use multiple managed policies (max 10 per role), (3) Combine conditions efficiently.
  • IAM Policy Simulator (https://policysim.aws.amazon.com) memungkinkan testing policies tanpa deployment: (1) Input policy JSON, (2) Select specific actions (redshift:GetClusterCredentials, s3:GetObject, etc.), (3) Specify resource ARNs, (4) Simulator evaluates policy dan shows Allow/Deny/Implicit Deny result. Best practice workflow: Step 1 — Simulate policy dengan Policy Simulator untuk semua expected actions. Step 2 — Attach policy ke test role di non-prod environment. Step 3 — Run test workloads dan verify CloudTrail untuk access patterns. Step 4 — Setelah validated, attach ke production role.
  • Fastest mitigation: Tambahkan explicit Deny statement yang membatasi overly-broad permissions. Approach: (1) Add Deny statement untuk dangerous actions (s3:DeleteBucket, s3:PutBucketPolicy, etc.) dan resources yang seharusnya tidak diakses, ATAU (2) Attach a Permissions Boundary yang defines maximum allowed permissions — boundary acts as ceiling regardless of identity policies. Permissions Boundary particularly useful karena: dapat di-apply tanpa modifying existing policy, immediately restricts effective permissions, doesn't break other needed statements. Contoh Deny: {"Effect": "Deny", "Action": ["s3:Delete*", "s3:PutBucket*"], "Resource": "*"} plus {"Effect": "Deny", "Action": "s3:*", "NotResource": ["arn:aws:s3:::allowed-bucket/*"]}.
  • Untuk time-based access control, gunakan aws:CurrentTime condition key dengan DateGreaterThanEquals dan DateLessThanEquals operators. Format time-only (08:00:00Z) membuat condition berulang setiap hari (tanpa fixed date). Policy structure: {"Effect": "Allow", "Action": "sts:AssumeRole", "Resource": "arn:aws:iam::333333333333:role/CrossAccountRedshiftRole", "Condition": {"DateGreaterThanEquals": {"aws:CurrentTime": "08:00:00Z"}, "DateLessThanEquals": {"aws:CurrentTime": "18:00:00Z"}}}. Catatan: aws:CurrentTime dengan time-only format memungkinkan daily recurring windows. Untuk day-of-week restriction, memerlukan tambahan custom logic (Lambda authorizer) karena IAM tidak natively support day-of-week conditions.
  • ABAC (Attribute-Based Access Control) menggunakan tags untuk dynamic authorization. Condition key aws:ResourceTag/team mendapatkan value tag "team" pada resource yang diakses. Policy variable ${aws:PrincipalTag/team} mendapatkan value tag "team" dari calling principal (IAM user/role). Dengan StringEquals comparison: akses hanya diizinkan jika tag "team" pada resource SAMA dengan tag "team" pada principal. Jika engineer memiliki tag team=analytics, mereka hanya bisa manage Glue jobs yang juga tagged team=analytics. Benefit: tidak perlu update policy saat team members berubah — cukup manage tags.
  • Least privilege means granting ONLY the exact permissions needed, on the exact resources needed: S3: s3:GetObject (read only, no list/write) on "arn:aws:s3:::source-bucket/source-path/*" — crawler reads objects from specific path. Glue Catalog: glue:CreateTable, glue:UpdateTable, glue:BatchCreatePartition, glue:GetDatabase on "arn:aws:glue:region:account:database/specific-db" dan "arn:aws:glue:region:account:table/specific-db/*" — only the target database. CloudWatch Logs: logs:CreateLogGroup, logs:CreateLogStream, logs:PutLogEvents on "arn:aws:logs:region:account:log-group:/aws-glue/crawlers*" — specific log group.
  • Policy ini menggunakan Deny + StringNotEquals untuk memaksa penggunaan SPECIFIC KMS key: Jika request PutObject tidak menggunakan KMS key ID yang ditentukan → DENY. Condition key s3:x-amz-server-side-encryption-aws-kms-key-id berisi ARN KMS key yang digunakan untuk server-side encryption. StringNotEquals ensures bahwa HANYA key spesifik tersebut yang diterima — bukan key lain, bukan encryption type lain.
  • IAM policy evaluation dengan multiple policy types: glue:StartJobRun evaluation: (1) Identity policy: Allow ✓, (2) Permissions boundary: allows glue:* ✓, (3) SCP: does not deny glue:StartJobRun ✓. Result: ALLOWED — all three layers permit it. glue:DeleteJob evaluation: (1) Identity policy: no explicit Allow for DeleteJob (implicit deny), tapi even if it were allowed: (2) SCP: explicit Deny on glue:DeleteJob ✗. Result: DENIED. SCP Deny overrides everything — even if identity policy AND permissions boundary both allowed it. Evaluation order: Explicit Deny (any layer) → SCP evaluation → Permissions Boundary → Identity policies → Resource policies. Key rule: untuk action to be allowed, it must be permitted by ALL applicable policy types (identity, boundary, SCP) with NO explicit deny from ANY layer.

Miskonsepsi & Jebakan Umum

  • Memenuhi requirements #1 dan #2 tapi tanpa explicit Deny, policy lain bisa memberikan DeleteObject permission.
  • Memberikan terlalu banyak permissions (s3:PutObject ke semua buckets).
  • Terlalu restrictive (hanya satu bucket) dan memungkinkan write ke semua prefixes.
  • Aws:SourceIp berisi IP address, bukan region name.
  • Aws:SourceRegion bukan condition key yang valid untuk scenario ini.
  • Memiliki logic yang benar tapi deskripsinya membingungkan — ini sebenarnya sama dengan C jika diterapkan dengan benar.
  • Sacrifices fine-grained control — memberikan akses ke SEMUA databases.
  • Salah — inline policies memiliki limit 2,048 characters (lebih kecil dari managed policy).
  • Removes security controls dan doesn't solve root cause jika resources dominate the policy size.
  • IAM policies are global, region separation tidak membantu testing.
  • Langsung ke production — risky jika policy terlalu restrictive (break production) atau terlalu permissive (security gap).
  • DateGreaterThan condition bisa bekerja tapi bukan proper testing approach.
  • Breaks ALL services attached to it.
  • Disruptive jika policy has other needed statements.
  • Terlalu lambat untuk security incident.
  • Menggunakan fixed date — hanya berlaku pada satu hari.
  • Aws:TokenIssueTime tracks kapan token dibuat, bukan current time.
  • Menggunakan ${aws:username} yang bukan team identifier.
  • Hanya checks apakah tag key "team" ada, bukan value comparison.
  • Hardcodes satu team value — tidak dynamic.
  • Incorrect — Glue NEEDS explicit permissions for catalog and logging.
  • Is complex dan AWSGlueServiceRole grants access ke ALL databases/S3 paths.
  • Violates least privilege completely.
  • Adalah tentang HTTPS vs HTTP transport, bukan encryption at rest.
  • Hanya memastikan SOME encryption header ada, tapi tidak memaksa specific key — terlalu broad (s3:* on all resources).
  • Hanya memastikan KMS encryption digunakan tapi tidak memaksa KEY SPESIFIK — any KMS key would be allowed.
  • Salah — boundary allows glue:*.
  • Salah — boundary allows glue:StartJobRun.
