Skill 3.1.7: Query data (Athena)

AthenaSQLserverlessquery

Summary

Skill this including in Domain 3: Operations & Support (Task 3.1: Automate data processing), with fokus on query data (athena). Materi berikut merangkum service AWS that relevan along with concept important that needs kamu kuasai for topik this.

Key Services & Concepts

Amazon Athena
Query SQL serverless against data in S3 (Presto/Trino); bayar per data that is scanned.

Key Points

  • Kombinasi konversi to Parquet (columnar format — only column that queried in-scan), Snappy compression (reduces size data that in-scan), and partitioning by event_date and event_type (Athena only reads partition that relevan) provides reduction drastically on data scanned. Parquet itself can reduces scan 90%+ for query that only requires several column. Partitioning avoids full table scan.
  • Athena workgroups provides: (1) per-query data usage control — limits maximum data that boleh in-scan per query (100 GB limit), (2) workgroup-level data scan limits that can is configured per periode (equivalent spending control), (3) CloudWatch metrics per workgroup for tracking usage per team. This single feature that memenuhi all requirements.
  • CTAS (CREATE TABLE AS SELECT) in Athena enables transformation data and creation table new in one operation SQL. Properties that can is configured including: format (PARQUET, ORC, JSON, etc.), compression, partitioned_by columns, external_location for S3 path, and bucketing. This is ideal for ETL operations.
  • Athena prepared statements enables parameterized queries where user-supplied values in-bind as parameter (uses ?) and not diinterpretasi as SQL code. This is best practice security standard for prevents SQL injection.
  • Athena Federated Query enables eksekusi SQL queries against berbagai data sources uses Lambda-based data source connectors. Connectors available for RDS (PostgreSQL, MySQL), DynamoDB, Redshift, CloudWatch Logs, and others. This enables JOIN lintas source in one query without moves data.
  • Athena query result reuse enables identical queries (same SQL) returns result that already in-cache without re-scanning data. By max-age setting (for example 6 hours appropriate update frequency), queries berulang not dikenakan cost scan additional. This transparent for dashboards — does not need modifikasi.
  • Athena views with built-in WHERE clause on partition column ensures that queries through view only scan 30 days data in a default. Workgroup per-query data scan limits provides safety net — if query exceeds threshold (for example 1 TB), query will dibatalkan. Kombinasi this prevents accidental full scans.
  • Small file problem is problem umum in data lakes. Each file requires overhead: S3 LIST operations for menemukan file, GET requests for membuka file, and Parquet footer reading per file. By millions of file small, overhead this mendominasi query time. The solution is compaction — combines file small becomes file berukuran 128-512 MB that optimal for Athena/Presto. CTAS or Glue job can performs compaction this.
  • Athena views provides abstraction layer that ideal: column aliases provides business-friendly names, pre-built JOINs menyederhanakan access pattern, and column selection menyembunyikan technical fields. Views not stores data duplikat and always reflect data terbaru.
  • Parquet row group statistics (min/max values) and page-level column indexes enables predicate pushdown — Athena (Presto/Trino) can skip row groups where filter condition (customer_segment = 'enterprise') cannot dipenuhi based on statistics, without reads actual data. This significant reduces I/O for non-partition column filters.
