Skill 3.2.4: Athena Spark notebooks

AthenaSparknotebooks

Ringkasan

Skill ini termasuk dalam Domain 3: Operations & Support (Task 3.2: Analyze data by using AWS services), dengan fokus pada athena spark notebooks. Materi berikut merangkum layanan AWS yang relevan beserta konsep penting yang perlu kamu kuasai untuk topik ini.

Layanan & Konsep Utama

Amazon Athena
Query SQL serverless terhadap data di S3 (Presto/Trino); bayar per data yang dipindai.
Apache Spark
Engine komputasi terdistribusi in-memory; inti Glue ETL dan EMR.

Poin-Poin Kunci

  • Amazon Athena Spark notebooks menyediakan sesi Spark yang fully serverless tanpa perlu provisioning atau manajemen infrastruktur. Notebooks ini terintegrasi secara native dengan AWS Glue Data Catalog, memungkinkan pembacaan tabel langsung menggunakan spark.sql() atau spark.table(). Sesi dimulai dalam hitungan detik.
  • Dalam Athena Spark notebooks, menggunakan df.write.saveAsTable() akan otomatis menulis data ke S3 dan mendaftarkan tabel di AWS Glue Data Catalog. Tabel yang terdaftar ini langsung queryable dari Athena SQL. Ini adalah pendekatan paling seamless yang memanfaatkan integrasi Spark-Glue Catalog.
  • Athena Spark notebook sessions memiliki konfigurasi untuk DPU count dan idle timeout. Mengurangi DPU allocation (minimum bisa serendah yang diperlukan) dan memperpendek idle timeout (dari default 45 menit ke misalnya 10-15 menit) secara langsung mengurangi biaya. Session otomatis terminated setelah idle timeout.
  • Athena Spark notebooks unggul untuk analisis iteratif dimana hasil satu langkah menentukan langkah berikutnya, karena state (DataFrames) dipertahankan antar cell executions. Ditambah kemampuan menggunakan library Python (pandas, scipy, matplotlib) membuat Spark notebooks ideal untuk statistical exploration.
  • Dalam Athena Spark notebooks, spark.sql() langsung mengakses Glue Data Catalog dan mendukung SQL standard. Query dengan database.table notation membaca dari catalog, dan predicate pada partition column (event_date) mendapatkan partition pruning sehingga hanya data relevan yang di-scan.
  • Athena Spark notebook sessions dapat dikonfigurasi dengan jumlah DPU (Data Processing Units) yang lebih besar. Meningkatkan DPU memberikan lebih banyak memory dan compute resources untuk operasi intensif seperti window functions pada data besar. Konfigurasi ini dilakukan saat memulai atau memodifikasi session.
  • Athena Spark sessions mendukung parameter --additional-python-modules yang memungkinkan loading custom Python packages dari S3. Tim bisa mengemas utility functions sebagai Python package (.whl atau .zip), upload ke S3, dan semua notebook bisa mengimport module tersebut. Ini memberikan version control dan single source of truth.
  • Spark DataFrame df.filter() dengan multiple conditions menggunakan & (logical AND) memungkinkan identifikasi records dengan correlated anomalies secara efisien. Kemudian df.describe() memberikan statistik summary dan df.count() menunjukkan volume anomalies. Ini memanfaatkan distributed processing Spark.
  • Athena Spark sessions memiliki cold start time untuk inisialisasi Spark runtime (driver, executors, JVM). Ini inherent pada serverless Spark. Untuk mengurangi dampak, engineer bisa mengonfigurasi idle timeout lebih panjang sehingga session tetap aktif selama working hours, menghindari repeated cold starts.
  • Best practice adalah memindahkan logic dari notebook explorasi ke production-grade service. AWS Glue ETL jobs mendukung PySpark dan memiliki scheduling triggers, error handling, job bookmarks, dan monitoring bawaan yang diperlukan untuk production. Notebook dimaksudkan untuk exploration, bukan scheduled production workloads.

Miskonsepsi & Jebakan Umum

  • Memerlukan provisioning cluster dan management.
  • Memerlukan pengelolaan Kubernetes cluster.
  • Memerlukan setup tambahan dan tidak se-seamless Athena notebooks.
  • Memerlukan langkah manual untuk registrasi tabel.
  • Kehilangan benefit Parquet dan metadata registration.
  • Salah karena spark.sql() BISA menjalankan DDL statements dalam Spark mode di Athena.
  • Menghilangkan capability PySpark yang diperlukan.
  • Terlalu kasar dan bisa mengganggu work-in-progress.
  • Tidak didukung, setiap user memiliki session terpisah.
  • Lebih efisien dengan Athena SQL.
  • Tidak memerlukan interaktivitas notebook.
  • Adalah API AWS Glue ETL, bukan Athena Spark notebooks.
  • Melewatkan catalog metadata dan partitioning.
  • Menggunakan format "glue" yang bukan API standar Spark.
  • Bisa membantu tapi menambah I/O overhead dan tidak menyelesaikan masalah memory untuk window function itu sendiri.
  • Menambah kompleksitas dan kehilangan keuntungan pipeline Spark terintegrasi.
  • Salah karena Athena Spark adalah serverless, tidak ada EC2 yang dikelola user.
  • Terbatas pada SQL context dan tidak mendukung arbitrary Python logic.
  • Bukan mekanisme yang tepat untuk code sharing.
  • Tidak maintainable dan prone to divergence.
  • Akan gagal pada large datasets karena memory constraints.
  • Kurang readable untuk complex multi-column conditions.
  • Berfungsi tapi kurang interaktif dibanding DataFrame operations untuk exploratory analysis.
  • Tidak terjadi saat session start.
  • Memakan milliseconds, bukan puluhan detik.
  • Hanya relevan jika ada additional packages, bukan penyebab utama 60 detik.
  • Sangat fragile dan anti-pattern.
  • Mungkin kehilangan custom Python logic yang tidak bisa direplikasi di SQL.
  • Tidak robust untuk production (tidak ada retry logic, monitoring terbatas).
