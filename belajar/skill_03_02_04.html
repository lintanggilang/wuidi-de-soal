Skill 3.2.4: Athena Spark notebooks

AthenaSparknotebooks

Summary

Skill this including in Domain 3: Operations & Support (Task 3.2: Analyze data by using AWS services), with fokus on athena spark notebooks. Materi berikut merangkum service AWS that relevan along with concept important that needs kamu kuasai for topik this.

Key Services & Concepts

Amazon Athena
Query SQL serverless against data in S3 (Presto/Trino); bayar per data that is scanned.
Apache Spark
Engine komputasi terdistribusi in-memory; inti Glue ETL and EMR.

Key Points

  • Amazon Athena Spark notebooks provides session Spark that fully serverless without needing provisioning or manajemen infrastructure. Notebooks this terintegrasi in a native with AWS Glue Data Catalog, enables pembacaan table directly uses spark.sql() or spark.table(). Sesi started in hitungan seconds.
  • In Athena Spark notebooks, uses df.write.saveAsTable() will automatic writes data to S3 and mendaftarkan table in AWS Glue Data Catalog. Tabel that terdaftar this directly queryable from Athena SQL. This is approach most seamless that utilizes integration Spark-Glue Catalog.
  • Athena Spark notebook sessions has configuration for DPU count and idle timeout. Reduces DPU allocation (minimum can serendah that is required) and memperpendek idle timeout (from default 45 minutes to for example 10-15 minutes) directly reduces cost. Session automatic terminated after idle timeout.
  • Athena Spark notebooks unggul for analisis iteratif where result one step determines step berikutnya, because state (DataFrames) dipertahankan between cell executions. Ditambah capabilities uses library Python (pandas, scipy, matplotlib) creates Spark notebooks ideal for statistical exploration.
  • In Athena Spark notebooks, spark.sql() directly accesses Glue Data Catalog and supports SQL standard. Query with database.table notation reads from catalog, and predicate on partition column (event_date) gets partition pruning so that only data relevan that in-scan.
  • Athena Spark notebook sessions can is configured with number DPU (Data Processing Units) that larger. Increases DPU provides more memory and compute resources for operation intensif such as window functions on data large. Konfigurasi this is performed when memulai or memodifikasi session.
  • Athena Spark sessions supports parameter --additional-python-modules that enables loading custom Python packages from S3. Tim can mengemas utility functions as Python package (.whl or .zip), upload to S3, and all notebook can mengimport module said. This provides version control and single source of truth.
  • Spark DataFrame df.filter() with multiple conditions uses & (logical AND) enables identifikasi records with correlated anomalies in a efficient. Then df.describe() provides statistics summary and df.count() indicates volume anomalies. This utilizes distributed processing Spark.
  • Athena Spark sessions has cold start time for inisialisasi Spark runtime (driver, executors, JVM). This inherent on serverless Spark. For reduces dampak, engineer can configures idle timeout more panjang so that session still active during working hours, avoids repeated cold starts.
  • Best practice is moves logic from notebook explorasi to production-grade service. AWS Glue ETL jobs supports PySpark and has scheduling triggers, error handling, job bookmarks, and monitoring bawaan that is required for production. Notebook dimaksudkan for exploration, not scheduled production workloads.
