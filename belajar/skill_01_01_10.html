Key Points

  • Without Enhanced Fan-Out, all consumers shares 2 MB/s read throughput per shard uses GetRecords API (polling). By 3 consumers, each in a effective mendapat ~666 KB/s. Besides that, GetRecords is limited 5 calls/second per shard that also is divided. This increases read latency.
  • SNS + SQS fan-out pattern is that most scalable. SNS can handle millions of messages/second and delivers to all subscribers (SQS queues) in a independent. Each SQS queue buffers messages for consumer each, provides decoupling sempurna.
  • Kinesis with gateway ID as partition key guarantees ordering per gateway (all records from gateway that same enters to shard that same). By 50 MB/s, needed minimal 50 shards (1 MB/s per shard). 500 gateways will terdistribusi in between 50 shards (~10 gateways per shard). This scalable and real-time.
  • Amazon EventBridge Pipes supports source (Kinesis), filtering (content-based), optional enrichment, and target (another Kinesis stream). By multiple pipes from source that same with different filters, records can in-route to target streams different. This serverless and minimal code.
  • Amazon MSK (Kafka) consumer groups enables each group reads all messages from topic in a independent. Kafka designed for high-throughput (100K+ events/sec) with multiple consumer groups without performance degradation because messages is stored in log.
  • EventBridge Pipes can consume from Kinesis source, apply transformation (including schema normalization via enrichment or input transformer), and write to target Kinesis stream. Three pipes (one per source) fan-in to one target stream. This serverless, no-code, and maintainable.
  • Enhanced Fan-Out provides dedicated 2MB/s and ~70ms latency via HTTP/2 push — ideal for pricing engine that butuh sub-second. Standard shared consumer (GetRecords) quite for data lake writer that toleran latency. Kinesis Analytics (Flink) performs preprocessing for ML. This optimizes cost appropriate requirement each.
  • Kinesis resource policy (since 2023) enables cross-account access directly. Producer accounts uses IAM roles (AssumeRole) for mendapat temporary credentials and writes to stream in central account. This mengikuti least privilege and not requires static credentials.
  • Kafka Streams KStream.branch() (or split() in newer versions) enables routing messages to multiple output topics based on predicates (conditions). This runs as stream processing application that reads from source topic and writes to destination topics. This MSK-native and scalable.
  • ReadProvisionedThroughputExceeded indicates that consumers exceeds read capacity (2 MB/s shared or 5 GetRecords calls/s per shard). By 5 consumers shares, each consumer only can GetRecords 1x/second per shard. Enhanced Fan-Out provides dedicated 2 MB/s per consumer per shard via HTTP/2 push, eliminates sharing.
