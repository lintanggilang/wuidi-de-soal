Domain 1: Ingestion & Transformation — Task 1.1: Perform data ingestion

Skill 1.1.8: Create IP allowlists

IPallowlistsVPCsecuritygroups

Ringkasan

Skill ini termasuk dalam Domain 1: Ingestion & Transformation (Task 1.1: Perform data ingestion), dengan fokus pada create ip allowlists. Materi berikut merangkum layanan AWS yang relevan beserta konsep penting yang perlu kamu kuasai untuk topik ini.

Layanan & Konsep Utama

Amazon VPC
Jaringan terisolasi; security group & endpoint mengontrol konektivitas sumber daya.

Poin-Poin Kunci

  • AWS Glue connections menggunakan ENI (Elastic Network Interface) di VPC dengan security group yang ditetapkan. Glue membutuhkan self-referencing rule (inbound dari security group sendiri) untuk komunikasi antar worker nodes. RDS security group harus mengizinkan inbound dari Glue security group.
  • Untuk koneksi dari DMS ke sumber on-premises melalui internet, DMS replication instance harus berada di public subnet dengan Elastic IP. EIP ini statis dan dapat di-allowlist di firewall on-premises.
  • Security group pada Redshift cluster adalah mekanisme yang tepat untuk membatasi akses network ke IP tertentu. Dengan menambahkan inbound rule untuk TCP 5439 (Redshift port) dari CIDR partner's IP, hanya partner yang bisa connect.
  • VPC Gateway Endpoint untuk S3 memungkinkan akses ke S3 tanpa internet, menjaga traffic di dalam AWS network. Route table di-update untuk mengarahkan traffic S3 melalui endpoint. Ini paling secure karena traffic tidak pernah meninggalkan AWS network.
  • AWS Network Firewall mendukung domain name filtering (stateful rule groups) yang secara otomatis resolve domain ke IP saat evaluasi. Ini ideal ketika IPs berubah sering karena rules berdasarkan domain name, bukan static IPs.
  • NAT Gateway memiliki Elastic IP yang statis. Semua outbound traffic dari private subnet ke internet melewati NAT Gateway, sehingga partner akan selalu melihat koneksi dari NAT Gateway's EIP. Ini memberikan satu static IP untuk allowlisting.
  • Redshift publicly accessible + security group IP restriction adalah cara standar untuk memberikan akses dari corporate network. Security group membatasi akses ke CIDR yang ditentukan. Redshift audit logging mencatat semua connection attempts dan queries.
  • Lambda functions di VPC menggunakan Hyperplane ENIs dengan IPs dari subnet CIDR. Karena Lambda bisa membuat banyak ENIs dengan IPs berbeda (tergantung concurrency), solusi paling praktis adalah mengizinkan seluruh VPC CIDR range (yang biasanya adalah private IP range tertentu) di firewall on-premises.
  • IAM policy dengan aws:SourceIp condition membatasi akses API ke Kinesis berdasarkan source IP address. Ini bisa diterapkan pada IAM role/user yang digunakan consumer application. Untuk cross-region access, ini adalah mekanisme yang efektif karena Kinesis adalah service managed yang tidak memiliki security group sendiri.
  • Security group references (SG-to-SG rules) adalah best practice karena rules tetap valid bahkan ketika IP addresses berubah. Setiap resource yang menggunakan SG yang di-reference secara otomatis mendapat akses. Ini paling maintainable karena tidak perlu update ketika instances berubah.

Miskonsepsi & Jebakan Umum

  • Untuk akses ke Glue API, bukan untuk Glue mengakses resources di VPC.
  • Melanggar security best practices.
  • Salah karena Glue menggunakan ENI di VPC, bukan IP range service.
  • Tidak routable melalui internet ke on-premises.
  • Bisa bekerja jika replication instance di private subnet tapi EIP di replication instance lebih direct.
  • Terlalu broad dan bisa mempengaruhi resources lain di subnet.
  • Tidak relevan untuk Redshift connection.
  • Tidak applicable untuk Redshift — WAF untuk HTTP/HTTPS di ALB, CloudFront, atau API Gateway.
  • Security groups are stateful dan allow all outbound by default; masalahnya routing bukan security group.
  • Memungkinkan internet access yang lebih luas dari yang diperlukan.
  • Tidak supported - security groups hanya menerima IP/CIDR, bukan domain names.
  • Tidak resolve DNS - hanya berisi static CIDR blocks.
  • Bisa bekerja tapi sangat custom dan fragile.
  • Over-engineering untuk SFTP access.
  • Tidak feasible karena EMR nodes bisa auto-scale dan private subnet nodes tidak bisa punya public IP.
  • Membutuhkan partner juga di AWS dan mengekspos NLB.
  • Tidak applicable karena Redshift menggunakan PostgreSQL protocol, bukan HTTP.
  • Kurang granular dan Flow Logs tidak capture application-level info.
  • Mengubah requirement (harus publicly accessible untuk BI tool).
  • Tidak mungkin — Lambda tidak mendukung static IP assignment.
  • Untuk Direct Connect traffic, NAT Gateway tidak digunakan karena traffic sudah private-to-private.
  • Salah — Kinesis tidak memiliki security group.
  • Fitur ini tidak ada di Kinesis.
  • Valid untuk same-region VPC endpoint tapi cross-region endpoint membutuhkan setup tambahan.
  • Tidak maintainable karena ENI IPs berubah.
  • Untuk static CIDR ranges, bukan dynamic service IPs.
  • Terlalu luas dan melanggar least privilege.
