Skill 3.2.3: SQL in Redshift and Athena

Summary

Skill this including in Domain 3: Operations & Support (Task 3.2: Analyze data by using AWS services), with fokus on sql in redshift and athena. Materi berikut merangkum service AWS that relevan beserta concept important that needs kamu kuasai for topik this.

Key Services & Concepts

Amazon Redshift
Data warehouse scale petabyte; supports COPY/UNLOAD, materialized view, and streaming ingestion.
Redshift Streaming Ingestion
Konsumsi directly from Kinesis/MSK to materialized view Redshift, latensi seconds, without staging S3.
Amazon Athena
Query SQL serverless against data in S3 (Presto/Trino); bayar per data that is scanned.

Key Points

  • Materialized views in Redshift stores result query in a fisik, so that query berikutnya reads from pre-computed results (sub-second). AUTO REFRESH will automatic updates materialized view when data underlying changes (setelah nightly load). This is ideal for query berat that data-nya rarely changes.
  • Partition projection enables Athena calculates partition in a in-memory based on pattern that didefinisikan (for example date range), without needing performs GetPartitions call to Glue Data Catalog. Ini in a drastis reduces query planning time for table with many partition.
  • CTAS in Athena enables creation table new from result query SELECT. Anda can determines format output (Parquet), location S3 destination, and strategi partitioning. Data in a fisik is written to S3 in format that is determined. This is ideal for creates layer data that ditransformasi.
  • Late-binding views (WITH NO SCHEMA BINDING) in Redshift not memverifikasi schema underlying table saat view is created. Schema divalidasi only saat query time. Ini very useful for external/Spectrum tables that schema-nya can changes. Regular views validates schema saat CREATE and will error if kolom changes.
  • Window functions with PARTITION BY month limits kalkulasi in each months. SUM() OVER with ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW provides running total that correct in months. RANK() OVER with ORDER BY daily_sales DESC provides ranking based on value sales in months.
  • Redshift supports PartiQL syntax for querying SUPER type columns. PartiQL enables unnesting arrays menjadi baris individual uses syntax FROM table t, t.reviews r where each element array menjadi row separate. Ini native and efficient for semi-structured data.
  • SVV_TABLE_INFO menampilkan metadata table including sort key configuration. If table not has sort key on kolom date, Redshift cannot performs zone map filtering (range-restricted scan) and must performs full sequential scan. Sort key enables Redshift melewati blocks that not relevan based on min/max metadata.
  • Athena views stores definisi query without mematerialisasi data. Analysts can SELECT from view with additional WHERE clauses for filtering. Views provides abstraction layer that reusable and maintainable.
  • Recursive CTEs (WITH RECURSIVE) enables traversal hierarki with kedalaman that not diketahui or variabel. CTE consists from anchor member (root level) and recursive member (UNION ALL) that meng-join returns to CTE for level berikutnya. Redshift supports recursive CTEs.
  • AWS Glue Data Catalog berfungsi sebagai metastore terpusat that can diakses by KEDUA Athena and Redshift Spectrum. Tabel that didefinisikan in Glue Data Catalog with Parquet SerDe and partition information will automatic queryable from Athena (native integration) and Redshift Spectrum (via external schema that mereferensikan Glue catalog). Satu definisi table, dua query engine.
