Skill 3.2.2: Verify and clean data

verifycleanqualityWrangler

Ringkasan

Skill ini termasuk dalam Domain 3: Operations & Support (Task 3.2: Analyze data by using AWS services), dengan fokus pada verify and clean data. Materi berikut merangkum layanan AWS yang relevan beserta konsep penting yang perlu kamu kuasai untuk topik ini.

Layanan & Konsep Utama

AWS Glue DataBrew
Persiapan data visual (no-code) untuk membersihkan dan menormalkan data.

Poin-Poin Kunci

  • AWS Glue Data Quality memungkinkan definisi rules secara deklaratif menggunakan Data Quality Definition Language (DQDL). Rules dapat dievaluasi secara otomatis selama ETL job execution dan terintegrasi langsung dengan Glue Data Catalog. Rules seperti Completeness, ColumnValues range check bisa didefinisikan tanpa coding.
  • Amazon Athena adalah solusi serverless yang bisa langsung query data di S3 tanpa loading atau provisioning. Query GROUP BY dengan HAVING COUNT > 1 akan segera menunjukkan skala duplikasi dan record spesifik. Ini paling cepat karena zero setup.
  • Amazon Data Firehose dengan transformation Lambda adalah solusi paling terintegrasi untuk validasi real-time sebelum data masuk ke data lake (S3). Lambda melakukan validasi JSON dan range check, mengembalikan status Ok untuk valid records dan ProcessingFailed untuk invalid records. Firehose secara otomatis memisahkan failed records ke error prefix.
  • Jupyter Notebooks pada EMR memberikan fleksibilitas penuh untuk eksplorasi interaktif menggunakan PySpark dan pandas. Data scientist bisa mencoba berbagai strategi cleaning secara iteratif, menulis custom parsing logic, dan langsung melihat hasilnya. Ini paling cocok untuk kompleksitas format yang memerlukan logic custom.
  • AWS Glue Data Quality dengan EvaluateDataQuality transform memungkinkan definisi rules deklaratif untuk referential integrity (ReferentialIntegrity), freshness (DataFreshness), dan uniqueness (Uniqueness). Rules dievaluasi inline dalam Glue workflow dan bisa dikonfigurasi untuk menghentikan job jika gagal. Integrasi dengan CloudWatch memungkinkan alerting otomatis.
  • Athena CTAS (CREATE TABLE AS SELECT) adalah pendekatan paling cost-effective karena serverless dan Anda hanya membayar per data yang di-scan. Dengan fungsi date_parse dan CASE statements, Anda bisa mendeteksi format dan mengkonversi ke standar. Hasilnya langsung tersedia sebagai tabel baru di Glue Data Catalog.
  • SageMaker Data Wrangler menyediakan built-in transforms untuk Handle Outliers (termasuk Winsorization yang caps values pada percentile tertentu) dan Handle Missing Values (termasuk imputation dengan median, mean, atau custom value). Kedua operasi ini tersedia sebagai visual transforms tanpa coding.
  • AWS Glue Data Quality evaluation results dapat di-export ke S3 dalam format yang bisa di-catalog oleh Glue Crawler. Dengan data historis di S3, QuickSight bisa membuat dashboard interaktif yang menampilkan tren quality scores per source, trend degradation, dan drill-down ke specific rules. Ini memberikan visualisasi paling kaya dan interaktif.
  • Menggunakan Glue ETL dengan konfigurasi mapping di DynamoDB adalah pendekatan paling maintainable. Ketika supplier baru ditambahkan, cukup menambahkan entry di tabel konfigurasi tanpa mengubah kode ETL. DynamicFrame dengan ApplyMapping mendukung schema yang fleksibel.
  • AWS DMS memiliki fitur data validation bawaan yang secara otomatis membandingkan data antara source dan target selama migration task. Fitur ini melakukan row-by-row comparison, memeriksa row count, dan melaporkan mismatches. Ini paling efisien karena terintegrasi langsung dengan proses migrasi.

Miskonsepsi & Jebakan Umum

  • Lebih cocok untuk transformasi visual daripada automated quality gates.
  • Dirancang untuk ML data preparation, bukan pipeline data quality automation.
  • Memerlukan kode custom dan orchestration terpisah.
  • Untuk fuzzy matching, bukan exact duplicate yang sudah bisa dideteksi dengan GROUP BY sederhana.
  • Memerlukan loading data ke Redshift (waktu dan biaya).
  • Tidak memberikan detail granular per record yang diperlukan untuk investigasi.
  • Memiliki startup time lebih lama dan kurang cocok untuk simple filtering.
  • Terlalu kompleks untuk simple validation.
  • Memerlukan manajemen consumer dan DLQ terpisah.
  • Bagus untuk visual transformation tapi terbatas untuk complex custom logic.
  • Memiliki built-in transforms tapi kurang fleksibel untuk format internasional yang sangat bervariasi.
  • Kurang interaktif dan regex di SQL terbatas untuk multi-step cleaning.
  • Tidak dirancang untuk referential integrity checks lintas tabel.
  • Memerlukan maintenance kode custom.
  • Memerlukan orchestration custom yang kompleks.
  • Berfungsi tapi lebih mahal dengan DPU costs untuk job sederhana ini.
  • Dirancang untuk ML workflows dan overkill.
  • Memiliki biaya per-node yang lebih tinggi dibanding Athena untuk transformasi sederhana pada 200M records.
  • Kehilangan integrasi dengan Data Wrangler pipeline.
  • Untuk feature engineering seperti one-hot encoding, bukan outlier handling.
  • Tidak perlu karena built-in transforms sudah tersedia.
  • Hanya memberikan snapshot profiling, bukan time-series quality monitoring.
  • Memerlukan custom development.
  • Memiliki keterbatasan visualization dan retention.
  • Menjadi sangat kompleks dengan 50+ supplier dan tidak bisa menangani transformasi format yang berbeda.
  • Memiliki keterbatasan parameterisasi dibanding Glue ETL.
  • Tidak scalable dan maintenance nightmare.
  • Memerlukan pengembangan dan tidak scalable untuk volume ini.
  • Sangat resource-intensive untuk 500M rows.
  • Menambah load ke RDS production dan network transfer besar.
