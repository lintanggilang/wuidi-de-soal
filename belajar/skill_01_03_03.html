Summary

Skill this including in Domain 1: Ingestion & Transformation (Task 1.3: Orchestrate data pipelines), with fokus on serverless workflows. Materi berikut merangkum service AWS that relevan beserta concept important that needs kamu kuasai for topik this.

Key Services & Concepts

AWS Lambda
Komputasi serverless event-driven; limit timeout 15 minutes and memory up to 10 GB.
AWS Step Functions
Orkestrasi flow kerja serverless (state machine) with retry, parallel, and error handling.

Key Points

  • MaxConcurrency on Map state limits berapa many iterations that runs simultaneously. By MaxConcurrency=100, only 100 Lambda invocations runs concurrent, jauh in bawah account limit. Files other waits in queue and is processed saat slots available.
  • Step Functions can orchestrate multiple Lambda calls, each within the 15-minute limit. Pattern: first Lambda reads data and creates chunk list → Map state processes each chunk in separate Lambda invocations → final Lambda aggregates results. This remains fully serverless while removing the timeout constraint.
  • Glue Auto Scaling enables job adjusts number workers based on actual utilization. If utilization low, Auto Scaling reduces workers = fewer DPU-hours billed. Also review NumberOfWorkers setting — may over-provisioned from awal.
  • Step Functions has built-in state management. Each state receives input JSON, produces output JSON, and passes it to the next state. InputPath selects which part of input to send to the task, ResultPath determines where task output is placed, OutputPath selects what passes to next state. Map state automatically collects results from all iterations. No external storage needed for workflow state.
  • S3 Event Notifications → Lambda is most cost-effective because Lambda only is called saat ada file new (event-driven), not each 5 minutes (polling). If there is no files, there is no cost. Processing under 1 minute easily fits Lambda limits.
  • Provisioned Concurrency keeps specified number of Lambda execution environments initialized and ready. Invocations go to pre-warmed environments with no cold start. Since the function runs every 30 seconds, Provisioned Concurrency of 1 ensures always-warm state.
  • SAM deploys via CloudFormation. CloudFormation supports stack rollback — reverting all resources to previous state atomically. This rolls back Lambda code, Step Functions definition, and DynamoDB config together. Fastest because it's one command and handles all resources.
  • Express Workflows pricing = (number of requests) + (duration × memory). Duration is calculated per state transition multiplied by execution memory (64MB increments). For 100K executions/day × multiple state transitions each, costs accumulate. If each execution has 10 states × 10 seconds, that's billed differently than expected. Understanding the pricing model (transitions × duration × memory) is critical.
  • EventBridge Pipes filter criteria evaluates messages BEFORE enrichment and target. Messages that don't match are discarded at the pipe level — no Lambda invocation, no Step Functions execution. This is the earliest and cheapest filtering point.
  • Comprehensive observability: X-Ray provides end-to-end distributed traces showing timing and errors across all services. CloudWatch Logs at ALL level captures every state transition with input/output. Structured logging with correlation IDs (execution ID) links Lambda logs to specific Step Functions execution. This gives full picture.
