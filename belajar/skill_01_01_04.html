Domain 1: Ingestion & Transformation — Task 1.1: Perform data ingestion

Skill 1.1.4: Consume data APIs

RESTGraphQLAPIGatewayAppFlow

Ringkasan

Skill ini termasuk dalam Domain 1: Ingestion & Transformation (Task 1.1: Perform data ingestion), dengan fokus pada consume data apis. Materi berikut merangkum layanan AWS yang relevan beserta konsep penting yang perlu kamu kuasai untuk topik ini.

Layanan & Konsep Utama

Amazon AppFlow
Integrasi data SaaS (mis. Salesforce) ke AWS dengan flow terjadwal & transfer inkremental, tanpa kode.
Amazon API Gateway
Mengelola REST/HTTP/WebSocket API: throttling, otorisasi, caching, dan integrasi backend.

Poin-Poin Kunci

  • Step Functions dengan Lambda ideal untuk workflow yang membutuhkan pagination (Map state) dan rate limiting (Wait state). Lambda menangani setiap API call, Step Functions mengorkestrasikan loop pagination dan mengatur jeda antar batch. Ini serverless dan cost-effective.
  • API Gateway caching menangani burst traffic tanpa membebani backend. Dengan TTL 5 menit, data tetap fresh sesuai requirement. Redshift Data API menghindari masalah connection pooling.
  • AWS Secrets Manager dirancang khusus untuk mengelola credentials dengan fitur automatic rotation. Lambda rotation function dapat secara otomatis merefresh OAuth token sebelum expired.
  • Lambda /tmp storage mendukung hingga 10 GB (jauh lebih besar dari 50 MB response). Lambda bisa streaming API response ke /tmp lalu upload ke S3. Ini adalah solusi serverless yang paling sederhana.
  • Amazon AppFlow memiliki pre-built connectors untuk Salesforce, ServiceNow, Zendesk, dan banyak SaaS lainnya. Ini memberikan unified interface untuk mengonfigurasi flows dari semua sources ke S3, dengan features seperti scheduling, data transformation, dan error handling built-in.
  • Redshift Data API adalah asynchronous. ExecuteStatement mengembalikan query ID segera. EventBridge menangkap event ketika statement berubah status ke FINISHED, lalu memicu Lambda kedua yang mengambil hasil. Ini event-driven dan efisien.
  • GraphQL dengan cursor-based pagination memungkinkan pengambilan data dalam batch (1,000 items per page). Pemilihan field (query projection) mengurangi ukuran response. Ini adalah pola standar untuk batch consumption dari GraphQL API.
  • Exponential backoff with jitter adalah best practice untuk handling rate limiting (429 errors). Jitter mencegah thundering herd problem dimana semua retry terjadi bersamaan. Maximum retry count mencegah infinite loops. Dead letter queue menangkap requests yang gagal setelah semua retry untuk investigasi.
  • DynamoDB Export to S3 membaca dari point-in-time recovery (PITR) backup dan tidak mengonsumsi read capacity units pada tabel. Ini ideal untuk batch export tanpa impacting production.
  • AWS Secrets Manager adalah tempat aman untuk menyimpan client certificates dan private keys. Lambda mengambil secret saat runtime dan mengonfigurasi HTTPS client (misalnya requests library di Python) dengan mTLS. Ini memungkinkan rotation tanpa redeploy.

Miskonsepsi & Jebakan Umum

  • Hanya mendukung SaaS connectors yang sudah ada, bukan custom REST APIs generik.
  • Bisa timeout untuk 50,000 records dengan rate limit.
  • Untuk menerima API calls, bukan consuming external APIs.
  • Tidak bisa scale ke 10K rps karena connection limit.
  • Menambah kompleksitas operasional untuk pre-populating cache.
  • Tidak mendukung direct integration tanpa Lambda dan tidak bisa handle caching di layer API Gateway tanpa Lambda proxy.
  • Bukan tempat yang tepat untuk credential management.
  • Bisa menyimpan credentials tapi tidak memiliki built-in rotation mechanism.
  • Tidak aman untuk credentials yang berubah dan sulit di-rotate.
  • Memiliki batas payload 10 MB dan bukan untuk consuming external API.
  • Bisa bekerja tapi lebih kompleks untuk dikelola.
  • Salah karena Lambda invocation payload limit adalah 6 MB (synchronous), bukan soal streaming.
  • Tidak memiliki native connectors untuk semua SaaS ini.
  • Hanya untuk events, bukan data ingestion bulk.
  • Membutuhkan custom code untuk setiap source.
  • Tidak ada mode synchronous di Redshift Data API.
  • Tetap asynchronous dan tidak mengembalikan hasil langsung.
  • Akan timeout karena Lambda memiliki batas 15 menit dan query memakan 10 menit.
  • Melewati API layer yang melanggar security boundaries.
  • Untuk real-time streaming, bukan batch retrieval.
  • Untuk composing multiple data sources server-side, bukan batch response.
  • Justru menyebabkan lebih banyak 429 errors.
  • Lambat dan masih consume RCU.
  • Membutuhkan mengetahui semua keys terlebih dahulu dan juga consume RCU.
  • Tidak mendukung client certificates.
  • Tidak aman karena private key terexpose di deployment package dan sulit di-rotate.
  • Hanya untuk server certificates di AWS services, bukan client certificates di Lambda outbound calls.
