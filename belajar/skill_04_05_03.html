Skill 4.5.3: Prevent replication to disallowed regions

SCPregionrestriction

Summary

Skill this including in Domain 4: Security & Governance (Task 4.5: Understand data privacy and governance), with fokus on prevent replication to disallowed regions. Materi berikut merangkum service AWS that relevan along with concept important that needs kamu kuasai for topik this.

Key Services & Concepts

Amazon API Gateway
Manages REST/HTTP/WebSocket API: throttling, otorisasi, caching, and integration backend.
Amazon EventBridge
Event bus serverless for routing event between service; supports schedule rule.
Service Control Policies
SCP in AWS Organizations for limits permission maksimum akun (e.g. larangan region certain).

Key Points

  • SCPs (Service Control Policies) is preventive controls that applies for ALL principals in account (including root user). SCP that deny actions when aws:RequestedRegion not including EU regions prevents creation resource in region that not is allowed. SCP must excludes global services (IAM, Route 53, CloudFront, dll) that operates from us-east-1 but bersifat global.
  • Bucket policy with condition on destination ARN is approach most correct for controls S3 replication destinations. Policy can uses condition StringLike on resource ARN or StringEquals on specific region identifier in ARN. Contoh: Deny s3:PutReplicationConfiguration except arn:aws:s3:::*eu-central-1* or *eu-west-1*. This prevents configuration replication to non-EU regions.
  • SCP that deny second actions (CreateDBInstanceReadReplica and CopyDBSnapshot) when aws:RequestedRegion not EU region is solution most simple and effective. For cross-region read replica, aws:RequestedRegion evaluates region destination. For CopyDBSnapshot cross-region, request is sent to destination region so that aws:RequestedRegion also mencerminkan destination. Satu SCP mencakup second requirement.
  • Control Tower supports custom SCPs as preventive guardrails. For granular control on Redshift snapshot copying, custom SCP that deny redshift:CopyClusterSnapshot when region not approved list provides precisely scoped control. This preventive — request will ditolak before snapshot copy started.
  • Approach defense-in-depth is that most correct: (1) Modifikasi backup plan for deletes copy rule to us-east-1 and adds EU destination — this fixes configuration when this, (2) Apply SCP as preventive guardrail so that there is no administrator that can creates cross-region copy to non-EU in masa depan. Condition on destination vault ARN ensures backup copies only can dituju to vaults in EU regions.
  • Custom AWS Config rule with Lambda function is solution most correct for memeriksa DynamoDB Global Tables replica regions. Lambda function can uses DynamoDB DescribeTable API for gets daftar replica regions, lalu membandingkan with approved region list. If there is replica in region that not is allowed, function returns NON_COMPLIANT. Config rule this runs periodic or when configuration change is detected.
  • S3 Object Lock (good Compliance maupun Governance mode) melindungi objects from DELETION and OVERWRITE during retention period — NOT from replication or copying. Objects that locked still can replicated to region other if replication rule is configured. For prevents cross-region replication, is required: (1) SCP that deny s3:ReplicateObject in region that not is allowed, (2) Bucket policy that prevents PutReplicationConfiguration to non-approved destinations.
  • Pattern that correct for region-restriction SCP is uses NotAction (not Action) on statement Deny. NotAction contains daftar global service actions that must dikecualikan from restriction. Statement becomes: "Deny everything NOT in this list UNLESS region is in approved list." Global services that needs in-exclude: iam:*, sts:*, organizations:*, route53:*, cloudfront:*, support:*, budgets:*, waf:*, dll.
  • Defense-in-depth approach requires multiple layers: (1) SCP as organizational-wide preventive guardrail for region restriction, (2) VPC endpoint policies adds network-level control — traffic to AWS services can is limited only to EU region endpoints, prevents Lambda or EC2 from calling APIs in non-EU regions, (3) S3 bucket policies as resource-level control specific for replication, (4) AWS Config rules as detective control for continuous compliance verification. Each layer handles attack vector different.
  • Remediation must is performed in a gradually and with risk management: (1) Immediate automated remediation: disable replication rule for STOP ongoing data transfer to unauthorized region — this urgent and low-risk. (2) Deleting 500 TB of already-replicated data requires careful handling — approval workflow is required because: data may still diakses, deletion 500 TB consumes time, needs confirm there is no dependencies. Automated deletion without approval for data skala large too berisiko.

Common Misconceptions & Pitfalls

  • Is detective control — resource already is created before is deleted, causes brief data exposure.
  • Anda can opt-in regions (that non-default) but EU and US regions is default regions that cannot in-disable through account settings.
  • Requires management in each account and can in-override by admin that creates new policies.
  • Config rule s3-bucket-replication-enabled memeriksa whether replication enabled, not limits destination — this detective not preventive.
  • Not there is condition key s3:DestinationRegion that valid for SCPs related S3 replication.
  • S3 Object Lock prevents deletion/modification object, not controls kemana object can replicated.
  • Mencampur IAM and SCP adds complexity without benefit; also DestinationRegion not condition key standard for RDS.
  • Detective control, not preventive — replika already is created before is deleted.
  • Rds:DatabaseEngine condition key there is no; and CopyDBClusterSnapshot different from CopyDBSnapshot (cluster vs instance).
  • Region deny setting memblokir ALL services in non-approved regions; this may too broad if there is legitimate services that needs runs in region other.
  • Detective guardrail only detects and alert after violation occurs, snapshot already ter-copy.
  • Not there is built-in Control Tower guardrail with nama persis said that specifically covers Redshift snapshot copying.
  • Vault Lock prevents deletion/modification recovery points, not controls kemana backups can in-copy.
  • Backup:CopyIntoRegion not IAM action that valid.
  • Only fixes configuration current but not prevents future misconfiguration.
  • Dynamodb-table-encrypted-kms memeriksa encryption, not replica regions.
  • Dynamodb-autoscaling-enabled there is no hubungannya with regional replication.
  • CloudTrail + CloudWatch can detects CreateTableReplica calls but not provides continuous compliance evaluation such as Config; also not memeriksa existing state.
  • Glacier Vault Lock also about deletion protection for archive, not cross-region movement prevention.
  • Incorrect — Legal Hold also only prevents deletion, not replication.
  • Incorrect — Object Lock not prevents replication.
  • SCPs are deny-only effective (Allow in SCP only membuka ceiling, not grant); two SCP separate not will produces efek that diinginkan because Deny still applies.
  • Approach this can works but not solves problem global services because mereka still in us-east-1.
  • Not there is condition key that identifies whether service "global" or regional.
  • Single SCP mencakup many but not handles network-level implicit access or resource-specific configurations.
  • Contractual agreement not technical control; not prevents misconfiguration by users.
  • Less granular dibanding opsi B because not mencakup VPC endpoint policies.
  • Can works but over-engineering for step 1 and still not should auto-delete without approval.
  • Manual remediation for step 1 (disabling replication) too slow because data terus ter-replicate during waits manual action.
  • Automatically deleting 500 TB without approval workflow too dangerous.
