Key Points

  • AWS Glue requires a self-referencing inbound rule on the connection's security group. This allows Glue workers (which share the same security group) to communicate with each other. Without this, the Glue job fails even if the connection test (which uses a single ENI) succeeds.
  • Redshift Federated Query supports connection directly to PostgreSQL (and MySQL) via JDBC. CREATE EXTERNAL SCHEMA with CONNECTION mendefinisikan connection. VPC peering enables network connectivity between VPCs.
  • numPartitions (or hashpartitions in Glue) determines number concurrent connections that Glue membuka to database. Menetapkan this in bawah max_connections (for example 50) prevents connection exhaustion. Connection pooling in JDBC URL reduces connection churn.
  • AWS Glue supports custom JDBC drivers. Driver JAR in-upload to S3 and direferensikan in Glue connection (class name and S3 path) or via --extra-jars job parameter. Glue automatic mendownload and memuat driver saat job dimulai.
  • Spark JDBC parallel read requires: partitionColumn (numeric column for split), lowerBound/upperBound (range values), and numPartitions (number parallel connections). Spark creates numPartitions queries with WHERE clauses that divides range.
  • Athena Federated Query uses Lambda-based data source connectors for query external data sources. Connector for Teradata available (from AWS or custom) that uses JDBC internally. Lambda runs in VPC with VPN access to on-premises.
  • Aurora (PostgreSQL) has idle_in_transaction_session_timeout and tcp_keepalives_idle parameters that menutup connection idle. For job that runs old, several connection can menjadi idle and in-close. Solusinya is adds parameter keepalive and validation connection in JDBC URL (for example tcpKeepAlive=true, connectTimeout, socketTimeout).
  • Redshift Federated Query supports AWS Secrets Manager for credential management. CREATE EXTERNAL SCHEMA ... FROM MYSQL/POSTGRES ... SECRET_ARN 'arn:aws:secretsmanager:...' retrieves credentials in a secure from Secrets Manager.
  • Hive supports JDBC storage handler (org.apache.hive.storage.jdbc.JdbcStorageHandler) that enables creates external table that backed by JDBC source. CREATE EXTERNAL TABLE ... STORED BY 'org.apache.hive.storage.jdbc.JdbcStorageHandler' WITH SERDEPROPERTIES ("hive.sql.jdbc.url"=...).
  • Encryption in transit for JDBC connections requires SSL/TLS. RDS supports SSL and provides CA certificates. JDBC URL is configured with SSL parameters: useSSL=true, requireSSL=true for MySQL; ssl=true, sslmode=require for PostgreSQL. Glue uses URL this for encrypted connections.

Common Misconceptions & Pitfalls

  • Salah — SQL Server supports JDBC.
  • Not suitable because connection test already succeeds.
  • Only for S3 data, not database.
  • Mengubah architecture and eliminates real-time access.
  • Not can is used from Redshift SQL directly.
  • Reduces data volume but not connection count per se.
  • Glue managed service without SSH access to workers.
  • ODBC also requires driver and Glue primarily uses JDBC.
  • Not mengaktifkan parallelism.
  • For shuffle operations, not JDBC reads.
  • Mengoptimalkan shuffle but not affect JDBC source parallelism.
  • Athena not receives JDBC connection strings directly in queries.
  • Athena not automatic uses Glue JDBC connections for query.
  • Redshift Spectrum only for S3 data.
  • Will fails from awal not intermittent.
  • Menyebabkan OOM not connection reset.
  • Mungkin not available on all external databases, especially non-AWS MySQL.
  • Adalah security risk and visible in system tables.
  • Not supported by Redshift schema definition.
  • Not integrates with Hive query engine.
  • Not ada built-in SQL Server connector in EMR configuration.
  • Mengubah architecture and eliminates real-time reference data.
  • RDS Interface Endpoints not automatic encrypt JDBC traffic.
  • Not can enforce encryption level.
  • Melindungi data in storage, not in transit.
