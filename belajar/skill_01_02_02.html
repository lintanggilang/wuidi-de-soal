Skill 1.2.2: Connect to data sources (JDBC, ODBC)

JDBCODBCconnections

Ringkasan

Skill ini termasuk dalam Domain 1: Ingestion & Transformation (Task 1.2: Transform and process data), dengan fokus pada connect to data sources (jdbc, odbc). Materi berikut merangkum layanan AWS yang relevan beserta konsep penting yang perlu kamu kuasai untuk topik ini.

Layanan & Konsep Utama

Lihat poin-poin kunci di bawah.

Poin-Poin Kunci

  • AWS Glue requires a self-referencing inbound rule on the connection's security group. This allows Glue workers (which share the same security group) to communicate with each other. Without this, the Glue job fails even if the connection test (which uses a single ENI) succeeds.
  • Redshift Federated Query mendukung koneksi langsung ke PostgreSQL (dan MySQL) via JDBC. CREATE EXTERNAL SCHEMA dengan CONNECTION mendefinisikan koneksi. VPC peering memungkinkan network connectivity antar VPCs.
  • numPartitions (atau hashpartitions dalam Glue) menentukan jumlah concurrent connections yang Glue membuka ke database. Menetapkan ini di bawah max_connections (misalnya 50) mencegah connection exhaustion. Connection pooling di JDBC URL mengurangi connection churn.
  • AWS Glue mendukung custom JDBC drivers. Driver JAR di-upload ke S3 dan direferensikan di Glue connection (class name dan S3 path) atau via --extra-jars job parameter. Glue otomatis mendownload dan memuat driver saat job dimulai.
  • Spark JDBC parallel read membutuhkan: partitionColumn (numeric column untuk split), lowerBound/upperBound (range values), dan numPartitions (jumlah parallel connections). Spark membuat numPartitions queries dengan WHERE clauses yang membagi range.
  • Athena Federated Query menggunakan Lambda-based data source connectors untuk query external data sources. Connector untuk Teradata tersedia (dari AWS atau custom) yang menggunakan JDBC internally. Lambda runs in VPC dengan VPN access ke on-premises.
  • Aurora (PostgreSQL) memiliki idle_in_transaction_session_timeout dan tcp_keepalives_idle parameters yang menutup koneksi idle. Untuk job yang berjalan lama, beberapa koneksi bisa menjadi idle dan di-close. Solusinya adalah menambahkan parameter keepalive dan validasi koneksi di JDBC URL (misalnya tcpKeepAlive=true, connectTimeout, socketTimeout).
  • Redshift Federated Query mendukung AWS Secrets Manager untuk credential management. CREATE EXTERNAL SCHEMA ... FROM MYSQL/POSTGRES ... SECRET_ARN 'arn:aws:secretsmanager:...' mengambil credentials secara secure dari Secrets Manager.
  • Hive mendukung JDBC storage handler (org.apache.hive.storage.jdbc.JdbcStorageHandler) yang memungkinkan membuat external table yang backed by JDBC source. CREATE EXTERNAL TABLE ... STORED BY 'org.apache.hive.storage.jdbc.JdbcStorageHandler' WITH SERDEPROPERTIES ("hive.sql.jdbc.url"=...).
  • Encryption in transit untuk JDBC connections membutuhkan SSL/TLS. RDS mendukung SSL dan menyediakan CA certificates. JDBC URL dikonfigurasi dengan SSL parameters: useSSL=true, requireSSL=true untuk MySQL; ssl=true, sslmode=require untuk PostgreSQL. Glue menggunakan URL ini untuk encrypted connections.

Miskonsepsi & Jebakan Umum

  • Salah — SQL Server mendukung JDBC.
  • Tidak cocok karena connection test sudah berhasil.
  • Hanya untuk S3 data, bukan database.
  • Mengubah arsitektur dan menghilangkan real-time access.
  • Tidak bisa digunakan dari Redshift SQL secara langsung.
  • Mengurangi data volume tapi tidak connection count per se.
  • Glue managed service tanpa SSH access ke workers.
  • ODBC juga memerlukan driver dan Glue primarily menggunakan JDBC.
  • Tidak mengaktifkan parallelism.
  • Untuk shuffle operations, bukan JDBC reads.
  • Mengoptimalkan shuffle tapi tidak affect JDBC source parallelism.
  • Athena tidak menerima JDBC connection strings langsung di queries.
  • Athena tidak otomatis menggunakan Glue JDBC connections untuk query.
  • Redshift Spectrum hanya untuk S3 data.
  • Akan gagal dari awal bukan intermittent.
  • Menyebabkan OOM bukan connection reset.
  • Mungkin tidak available pada semua external databases, terutama non-AWS MySQL.
  • Adalah security risk dan visible di system tables.
  • Tidak supported oleh Redshift schema definition.
  • Tidak mengintegrasikan dengan Hive query engine.
  • Tidak ada built-in SQL Server connector di EMR configuration.
  • Mengubah arsitektur dan menghilangkan real-time reference data.
  • RDS Interface Endpoints tidak otomatis encrypt JDBC traffic.
  • Tidak bisa enforce encryption level.
  • Melindungi data di storage, bukan in transit.
