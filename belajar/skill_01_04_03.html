Skill 1.4.3: Programming languages and frameworks

PythonSQLScalaJavaPySpark

Ringkasan

Skill ini termasuk dalam Domain 1: Ingestion & Transformation (Task 1.4: Apply programming concepts), dengan fokus pada programming languages and frameworks. Materi berikut merangkum layanan AWS yang relevan beserta konsep penting yang perlu kamu kuasai untuk topik ini.

Layanan & Konsep Utama

Apache Spark
Engine komputasi terdistribusi in-memory; inti Glue ETL dan EMR.

Poin-Poin Kunci

  • PySpark in AWS Glue is ideal for 500 GB datasets because it provides distributed processing across multiple workers, handling data that far exceeds single-machine memory. The team can leverage their Python skills since PySpark uses Python syntax.
  • Python with boto3 in Lambda is most cost-effective: Lambda charges only for execution time, boto3 natively integrates with DynamoDB and S3, and reference data (50 MB) fits within Lambda memory. Lambda can be triggered directly by Kinesis as an event source mapping, making simple key lookups efficient.
  • SQL window functions (ROW_NUMBER, SUM() OVER(), LAG/LEAD) are natively optimized in Redshift's MPP engine. Running totals, ranking, and gap detection are classic window function use cases. Processing stays within Redshift — no data movement, no external compute costs. Redshift's columnar storage and distribution keys optimize these operations.
  • Scala runs natively on the JVM alongside Spark, eliminating Python-JVM serialization overhead (via Py4J). For iterative graph algorithms with frequent shuffles and custom aggregations, Scala provides better performance because UDFs run in-process. On 2 TB with complex graph traversals, serialization overhead compounds significantly. Additionally, rewriting complex existing Scala introduces risk.
  • EMR bootstrap actions run on Amazon Linux instances where Bash is the native shell. Bash directly handles system operations: aws CLI for S3 downloads, export for environment variables, chmod for permissions, and pip install for packages — all without additional runtime dependencies. Bootstrap actions execute before applications start, so Bash guarantees availability.
  • STS assume_role() is the standard pattern for cross-account access — provides temporary credentials (security best practice). Botocore's retry configuration with exponential backoff and jitter handles API throttling automatically, essential when creating resources across 15 accounts. Pattern: sts.assume_role() → create session with temp credentials → create glue client → use Config(retries={'max_attempts': 10, 'mode': 'adaptive'}).
  • Window functions are purpose-built for these calculations: ROWS BETWEEN 6 PRECEDING AND CURRENT ROW creates exact 7-day windows, PARTITION BY category computes category-level aggregates alongside row-level detail, and LAG() accesses previous row values without self-joins. Athena (Presto/Trino) fully supports ANSI SQL window functions. Single pass over data = efficient.
  • Python consistently has among the fastest Lambda cold starts (typically 100-200ms) because the interpreter is lightweight and boto3 is included in the Lambda runtime (no additional dependencies). For simple JSON parsing + math + DynamoDB writes, Python is more than performant enough.
  • PySpark in Glue with Auto Scaling provides single codebase adaptability. Glue Auto Scaling dynamically adjusts the number of workers based on actual workload parallelism — fewer workers for 100 MB (minimum cost), more workers for 50 GB (maximum throughput). The same PySpark code runs identically regardless of data size.
  • AWS Glue's --extra-py-files parameter is the official mechanism for additional Python dependencies. Wheel files (.whl) are preferred because they contain pre-compiled binaries for the target platform. For libraries with C extensions (cryptography), the wheel must match Glue's Python version and manylinux platform. Multiple .whl files can be comma-separated in the parameter.

Miskonsepsi & Jebakan Umum

  • Lambda has 10 GB memory limit and 15-minute timeout, unsuitable for 500 GB.
  • Single EC2 instance with multiprocessing doesn't scale horizontally and requires infrastructure management.
  • SageMaker notebooks are for interactive exploration, not production batch processing of 500 GB.
  • R is not optimized for stream processing and EC2 requires always-on billing.
  • EMR with Spark is over-provisioned for simple key lookups on small reference data; minimum cluster cost is high.
  • Fargate continuously running incurs cost 24/7 regardless of traffic.
  • Extracting 100s of GBs to Python adds latency, network cost, and pandas cannot handle Redshift-scale data.
  • Glue adds unnecessary data movement; Redshift already has these capabilities.
  • R via JDBC is slow for large datasets and adds external dependency.
  • PySpark has serialization overhead for UDFs and custom aggregators; performance is NOT identical for UDF-heavy workloads.
  • Athena SQL cannot express complex graph traversals.
  • Scala requires JVM setup which may not be complete during bootstrap phase.
  • PowerShell is not natively available on Amazon Linux EMR nodes.
  • Python may not be fully configured yet during bootstrap (that's what bootstrap installs).
  • Storing long-term access keys is a security anti-pattern.
  • Subprocess CLI calls lose boto3's native retry handling and error typing.
  • No retry logic will fail under throttling with 15 accounts.
  • Self-joins create cartesian products, extremely expensive on large datasets.
  • Extracting to Python adds latency and doesn't scale for large Athena datasets.
  • Correlated subqueries execute per-row, O(n²) performance.
  • NET with full framework has significant cold start overhead.
  • Java with Spring Boot has notoriously slow cold starts (3-10 seconds) due to JVM initialization and framework bootstrapping.
  • Nodejs is also fast, but TypeScript requires compilation step which adds complexity; Node.js without TypeScript would be comparable to Python.
  • Over-provisioning wastes cost on weekdays (paying for unused DPUs).
  • Dask is not natively supported in AWS Glue.
  • Maintaining two code paths (pandas + PySpark) doubles testing effort and introduces bugs.
  • Glue doesn't automatically process requirements.txt (unlike some other services).
  • Loose source files won't be importable without proper package structure.
  • Subprocess pip at runtime is unreliable, slow, and may fail without internet access in VPC.
