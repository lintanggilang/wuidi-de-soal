Key Points

  • KEY distribution on column that most often in-join (such as product_id) ensures that rows with value that same berada in node that same, avoids data redistribution when join. Compound sort key that started with transaction_date enables zone maps for performs block-level pruning on filter date, very effective for range queries.
  • Pattern 1 (posts by user sorted by time): PK=user_id, SK=timestamp enables query with ScanIndexForward. Pattern 2 (specific post): can uses PK=user_id and filter on post_id (or encode post_id in sort key with composite key). Pattern 3 (hashtag + engagement): GSI with PK=hashtag, SK=engagement_score.
  • Strategi optimal: dimension small (< several million rows) gunakan ALL distribution so that entire table replicated in each node, avoids redistribution when join. Dimension large (5M+ rows) gunakan KEY distribution on column join to fact table, because ALL distribution for table large wastes storage and memperlambat write.
  • In single-table design, one-to-many relationship dimodelkan with places parent and children items in partition key that same. PK=CUSTOMER#123, SK=CUSTOMER#123 for record customer, and PK=CUSTOMER#123, SK=ORDER#456 for each order. This enables one Query operation for gets customer along with all order-nya.
  • Partitioning must mengikuti query patterns main. Because queries especially filter by date range and region, partition by region/year/month/day enables Athena and Redshift Spectrum performs partition pruning that effective.
  • Redshift SUPER data type designed for semi-structured data (JSON, arrays, nested objects). SUPER stores data in format binary that efficient, supports schemaless ingestion (schema-on-read), and can in-query uses PartiQL or dot notation. This is ideal when schema often changes.
  • Compound sort key with impression_date as leading column optimal when queries always filter by date range first. Zone maps in Redshift stores min/max values per block — leading sort column enables maximum block skipping. Date range filter mengeliminasi partly large blocks, then campaign_id filter is applied on subset that tersisa.
  • PK=player_id, SK=item_id supports all access patterns in a optimal: (1) Query PK=player_id gets all items, (2) GetItem PK=player_id SK=item_id gets item specific, (3) UpdateItem PK=player_id SK=item_id updates quantity. By 500 items per player, item collection still in below 10GB partition limit.
  • Star schema with denormalized dimensions is best practice for Amazon Redshift. Redshift dioptimalkan for join patterns simple (fact-to-dimension) and columnar storage creates denormalization cheap from segi storage. Denormalized dimension reduces number joins, increases query performance.
  • Apache Parquet with schema-on-write is best practice for data lake analytics. Parquet provides columnar storage that efficient, compression that good, and predicate pushdown. Registrasi in Glue Data Catalog enables discovery by all query engines (Athena, Spectrum, EMR). Partitioning by date enables partition pruning.
