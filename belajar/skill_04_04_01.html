Domain 4: Security & Governance — Task 4.4: Prepare logs for audit

Skill 4.4.1: CloudTrail for API tracking

CloudTrailAPItracking

Ringkasan

Skill ini termasuk dalam Domain 4: Security & Governance (Task 4.4: Prepare logs for audit), dengan fokus pada cloudtrail for api tracking. Materi berikut merangkum layanan AWS yang relevan beserta konsep penting yang perlu kamu kuasai untuk topik ini.

Layanan & Konsep Utama

Amazon API Gateway
Mengelola REST/HTTP/WebSocket API: throttling, otorisasi, caching, dan integrasi backend.
AWS CloudTrail
Audit trail panggilan API akun AWS; CloudTrail Lake untuk query SQL atas event.

Poin-Poin Kunci

  • S3 data events di CloudTrail mencatat operasi pada level objek seperti GetObject, PutObject, dan DeleteObject. Data events menyertakan identitas pemanggil (IAM principal), waktu, dan ARN objek spesifik yang diakses.
  • Organization trails yang dibuat dari management account secara otomatis diterapkan ke semua akun anggota di seluruh region. Member accounts tidak dapat memodifikasi atau menghapus organization trail — hanya management account yang memiliki kontrol penuh. Ini memberikan audit trail terpusat dan tamper-resistant.
  • Lambda data events mencatat setiap invokasi fungsi (Invoke API call). CloudTrail Lake memungkinkan pembuatan event data store yang menyimpan events dan mendukung SQL queries langsung tanpa perlu ekspor ke S3 atau konfigurasi Athena. Query bisa memfilter berdasarkan eventSource (lambda.amazonaws.com) dan eventName (Invoke).
  • CloudTrail log file integrity validation menggunakan SHA-256 hashing untuk setiap log file dan menandatangani digest files secara digital menggunakan private key yang dikelola AWS. Digest files dikirim setiap jam dan berisi hash dari semua log files yang dikirim dalam periode tersebut. Validasi menggunakan AWS CLI command `aws cloudtrail validate-logs`.
  • Advanced event selectors memberikan granularitas filtering yang lebih tinggi dibanding basic event selectors. Field selector resources.ARN dengan operator StartsWith memungkinkan filtering berdasarkan prefix (arn:aws:s3:::data-pipeline-*), dan operator Equals untuk tabel DynamoDB spesifik. Ini mencapai kedua kebutuhan dalam satu trail.
  • Amazon EventBridge menerima CloudTrail events dalam near real-time (biasanya dalam hitungan detik) tanpa perlu menunggu log file delivery ke S3 (yang bisa memakan waktu hingga 15 menit). EventBridge API destinations memungkinkan routing langsung ke SIEM endpoint via HTTPS.
  • Advanced event selectors memungkinkan filtering data events berdasarkan resource ARN, termasuk filtering berbasis account ID dalam ARN. Dengan mengecualikan data events dari development accounts (atau hanya meng-include production account resources), biaya data events berkurang signifikan tanpa mengorbankan audit compliance untuk production.
  • Data events harus diaktifkan secara terpisah dan hanya tersedia untuk layanan tertentu yang didukung (S3, Lambda, DynamoDB, EBS, S3 Object Lambda, dll). Tidak semua layanan AWS mendukung data events — misalnya Redshift query execution tidak dicatat sebagai data events di CloudTrail.
  • Object Lock Compliance mode mencegah penghapusan oleh siapapun termasuk root account selama retention period, memenuhi persyaratan anti-deletion. CloudTrail Lake menyediakan kemampuan SQL query yang mudah selama 90 hari pertama. Lifecycle rule ke Glacier Deep Archive setelah 90 hari memenuhi persyaratan cold storage dengan biaya paling rendah untuk 7 tahun.
  • Basic event selectors memiliki parameter readWriteType yang bisa diatur ke ReadOnly, WriteOnly, atau All. Jika diatur ke ReadOnly, hanya operasi baca (GetObject) yang dicatat dan operasi tulis (PutObject) akan difilter. Ini adalah penyebab umum missing events.

Miskonsepsi & Jebakan Umum

  • Salah karena S3 server access logs tidak bisa diekspor ke CloudTrail — keduanya sistem terpisah.
  • Mendeteksi anomali volume API calls tapi tidak mencatat detail individual object access.
  • Hanya mencatat operasi control plane seperti CreateBucket atau PutBucketPolicy, bukan akses data.
  • Bersifat reaktif dan ada delay antara disabling dan remediation.
  • Memerlukan konfigurasi manual di setiap akun dan administrator lokal bisa menonaktifkannya.
  • Bisa di-override oleh admin lokal yang memiliki permission untuk menghapus stack.
  • Hanya mendeteksi anomali, bukan mencatat setiap invokasi individual.
  • Bukan SQL standard dan tidak terintegrasi langsung dengan CloudTrail events.
  • Menggunakan management events yang tidak mencatat invocations individual.
  • Mencegah pembacaan tanpa key tapi tidak memvalidasi integritas post-delivery.
  • Mencegah deletion tapi bukan modifikasi konten jika governance mode di-bypass.
  • Sebagian benar tapi melewatkan aspek digital signatures yang krusial — tanpa signatures, digest files sendiri bisa ditamper.
  • Membuat dua trails yang tidak perlu dan meningkatkan biaya.
  • Tidak mendukung prefix matching pada ARN — hanya bisa memilih semua buckets atau bucket spesifik.
  • Harus mendaftar setiap bucket individu, tidak bisa menggunakan prefix pattern.
  • Bergantung pada S3 delivery yang memiliki latensi 5-15 menit.
  • Menambahkan latensi di atas S3 delivery time. EventBridge memberikan latensi terendah karena langsung menerima events dari CloudTrail.
  • Menambahkan latency karena CloudTrail harus menulis ke log group terlebih dahulu.
  • Mengacu pada S3 lifecycle, bukan fitur CloudTrail — dan mengurangi retention bisa melanggar compliance.
  • Menghilangkan visibility ke management events di development accounts yang masih diperlukan.
  • Memiliki pricing berbeda yang bisa lebih mahal tergantung volume query.
  • Salah karena management events hanya mencatat control plane operations.
  • Salah karena data events memerlukan konfigurasi eksplisit.
  • Sebagian salah — management events gratis untuk satu copy pertama tapi charged untuk copies tambahan, dan pricing data events memang dikenakan biaya per event.
  • Bisa di-bypass oleh user dengan permission s3:BypassGovernanceRetention, tidak sekuat Compliance mode.
  • Hanya melindungi dari deletion tanpa MFA tapi root account masih bisa menghapus.
  • Sangat mahal untuk penyimpanan jangka panjang.
  • Salah karena CloudTrail mencatat semua S3 data events tanpa pembatasan ukuran objek.
  • Kurang tepat — data events dicatat di region tempat operasi terjadi, tapi jika trail multi-region sudah aktif (default untuk organization trails), region seharusnya tidak jadi masalah.
  • Salah karena CloudTrail tidak memiliki throttling limit per hour untuk event logging.
