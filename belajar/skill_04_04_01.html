Skill 4.4.1: CloudTrail for API tracking

CloudTrailAPItracking

Summary

Skill this including in Domain 4: Security & Governance (Task 4.4: Prepare logs for audit), with fokus on cloudtrail for api tracking. Materi berikut merangkum service AWS that relevan beserta concept important that needs kamu kuasai for topik this.

Key Services & Concepts

Amazon API Gateway
Manages REST/HTTP/WebSocket API: throttling, otorisasi, caching, and integration backend.
AWS CloudTrail
Audit trail panggilan API akun AWS; CloudTrail Lake for query SQL atas event.

Key Points

  • S3 data events in CloudTrail logs operasi on level objek such as GetObject, PutObject, and DeleteObject. Data events menyertakan identitas pemanggil (IAM principal), time, and ARN objek specific that diakses.
  • Organization trails that is created from management account automatically is applied to all akun anggota in entire region. Member accounts cannot memodifikasi or deletes organization trail — only management account that has kontrol full. Ini provides audit trail terpusat and tamper-resistant.
  • Lambda data events logs each invokasi function (Invoke API call). CloudTrail Lake enables creation event data store that stores events and supports SQL queries directly without needing ekspor to S3 or configuration Athena. Query can memfilter based on eventSource (lambda.amazonaws.com) and eventName (Invoke).
  • CloudTrail log file integrity validation uses SHA-256 hashing for each log file and menandatangani digest files in a digital uses private key that is managed AWS. Digest files is sent each hours and contains hash from all log files that is sent in periode the said. Validasi uses AWS CLI command `aws cloudtrail validate-logs`.
  • Advanced event selectors provides granularitas filtering that higher dibanding basic event selectors. Field selector resources.ARN with operator StartsWith enables filtering based on prefix (arn:aws:s3:::data-pipeline-*), and operator Equals for table DynamoDB specific. Ini reaches kedua requirements in satu trail.
  • Amazon EventBridge receives CloudTrail events in near real-time (usually in hitungan seconds) without needing waits log file delivery to S3 (that can memakan time up to 15 minutes). EventBridge API destinations enables routing directly to SIEM endpoint via HTTPS.
  • Advanced event selectors enables filtering data events based on resource ARN, including filtering based on account ID in ARN. By excludes data events from development accounts (or only meng-include production account resources), cost data events berkurang significant without mengorbankan audit compliance for production.
  • Data events must diaktifkan in a separate and only available for service certain that is supported (S3, Lambda, DynamoDB, EBS, S3 Object Lambda, dll). Not all service AWS supports data events — for example Redshift query execution not is logged sebagai data events in CloudTrail.
  • Object Lock Compliance mode prevents deletion by siapapun including root account during retention period, memenuhi persyaratan anti-deletion. CloudTrail Lake provides capabilities SQL query that easy during 90 days pertama. Lifecycle rule to Glacier Deep Archive setelah 90 days memenuhi persyaratan cold storage with cost most low for 7 years.
  • Basic event selectors has parameter readWriteType that can is configured to ReadOnly, WriteOnly, or All. If is configured to ReadOnly, only operasi baca (GetObject) that is logged and operasi tulis (PutObject) will difilter. Ini is penyebab umum missing events.

Common Misconceptions & Pitfalls

  • Salah because S3 server access logs cannot diekspor to CloudTrail — keduanya system separate.
  • Mendeteksi anomali volume API calls but not logs detail individual object access.
  • Only logs operasi control plane such as CreateBucket or PutBucketPolicy, not access data.
  • Bersifat reaktif and ada delay between disabling and remediation.
  • Requires configuration manual in each akun and administrator local can menonaktifkannya.
  • Can in-override by admin local that has permission for deletes stack.
  • Only detects anomali, not logs each invokasi individual.
  • Not SQL standard and not terintegrasi directly with CloudTrail events.
  • Uses management events that not logs invocations individual.
  • Mencegah pembacaan without key but not validates integritas post-delivery.
  • Mencegah deletion but not modifikasi content if governance mode in-bypass.
  • Sebagian correct but melewatkan aspek digital signatures that krusial — without signatures, digest files itself can ditamper.
  • Creates dua trails that does not need and increases cost.
  • Not supports prefix matching on ARN — only can memilih all buckets or bucket specific.
  • Must mendaftar each bucket individu, cannot uses prefix pattern.
  • Bergantung on S3 delivery that has latensi 5-15 minutes.
  • Adds latensi in atas S3 delivery time. EventBridge provides latensi terendah because directly receives events from CloudTrail.
  • Adds latency because CloudTrail must writes to log group first.
  • Mengacu on S3 lifecycle, not feature CloudTrail — and reduces retention can melanggar compliance.
  • Eliminates visibility to management events in development accounts that still is required.
  • Has pricing different that can more expensive depends volume query.
  • Salah because management events only logs control plane operations.
  • Salah because data events requires configuration eksplisit.
  • Sebagian incorrect — management events gratis for satu copy pertama but charged for copies additional, and pricing data events memang dikenakan cost per event.
  • Can in-bypass by user with permission s3:BypassGovernanceRetention, not sekuat Compliance mode.
  • Only melindungi from deletion without MFA but root account still can deletes.
  • Very expensive for storage jangka panjang.
  • Salah because CloudTrail logs all S3 data events without pembatasan size objek.
  • Kurang correct — data events is logged in region tempat operasi occurs, but if trail multi-region already active (default for organization trails), region should not jadi problem.
  • Salah because CloudTrail not has throttling limit per hour for event logging.
