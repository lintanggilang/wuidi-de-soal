Domain 1: Ingestion & Transformation — Task 1.1: Perform data ingestion

Skill 1.1.2: Read data from batch sources

S3GlueEMRDMSRedshiftLambdaAppFlowbatch

Ringkasan

Skill ini termasuk dalam Domain 1: Ingestion & Transformation (Task 1.1: Perform data ingestion), dengan fokus pada read data from batch sources. Materi berikut merangkum layanan AWS yang relevan beserta konsep penting yang perlu kamu kuasai untuk topik ini.

Layanan & Konsep Utama

AWS DMS
Database Migration Service; migrasi full-load + CDC antar database, juga ke target seperti Kinesis/S3/Redshift.
AWS Glue
ETL serverless berbasis Spark + Data Catalog; ideal untuk transformasi dan katalogisasi data.
Amazon EMR
Cluster big data terkelola (Spark, Hive, Presto); mendukung Spot Instances untuk hemat biaya.
AWS Lambda
Komputasi serverless event-driven; batas timeout 15 menit dan memori hingga 10 GB.
Amazon Redshift
Data warehouse berskala petabyte; mendukung COPY/UNLOAD, materialized view, dan streaming ingestion.
Redshift Streaming Ingestion
Konsumsi langsung dari Kinesis/MSK ke materialized view Redshift, latensi detik, tanpa staging S3.
Amazon S3
Object storage tahan lama; dasar data lake, mendukung event notification, versioning, dan lifecycle.
Amazon AppFlow
Integrasi data SaaS (mis. Salesforce) ke AWS dengan flow terjadwal & transfer inkremental, tanpa kode.

Poin-Poin Kunci

  • AWS Glue crawler secara otomatis mendeteksi schema dari data di S3 dan membuat/memperbarui tabel di Glue Data Catalog. Ketika schema berubah, crawler akan mendeteksi perubahan tersebut.
  • Amazon AppFlow dirancang khusus untuk integrasi data dari SaaS applications seperti Salesforce ke AWS services. AppFlow mendukung scheduled flows dan incremental data transfer berdasarkan field filter (seperti last modified date), tanpa kode custom.
  • AWS DMS mendukung full load dan ongoing replication (CDC) dari Oracle ke Redshift. AWS SCT (Schema Conversion Tool) mengkonversi schema Oracle ke format yang kompatibel dengan Redshift. Kombinasi ini adalah solusi paling lengkap.
  • Amazon EMR dengan Spot Instances memberikan harga hingga 90% lebih murah dari On-Demand untuk workload yang toleran terhadap interupsi. Untuk job harian 500 GB yang harus selesai dalam 2 jam, EMR Spark dengan Spot sangat cost-effective.
  • COPY command adalah metode paling efisien untuk loading data ke Redshift dari S3. Dengan manifest file, Anda dapat mengontrol file mana yang dimuat, mencegah duplikasi, dan memastikan semua file yang diperlukan ada. COPY membaca Parquet natively dan melakukan parallel loading dari semua file.
  • AWS Glue mendukung parallel reads dari JDBC sources menggunakan hashexpression atau hashfield, yang membagi tabel menjadi beberapa partisi yang dibaca secara paralel. Menggunakan read replica memastikan produksi tidak terganggu.
  • AWS Glue crawler mendeteksi schema berbagai format (CSV, JSON, dll.) dan membuat tabel di Glue Data Catalog. Glue ETL dengan DynamicFrames dapat membaca dari berbagai format, menerapkan mapping dan transformasi, lalu menulis ke output yang terstandarisasi. Ini solusi paling efisien karena fully managed.
  • S3 byte-range fetches memungkinkan Lambda membaca file secara bertahap (chunk by chunk) tanpa memuat seluruh file ke memory. Ini menghindari timeout karena setiap invocation memproses sebagian data.
  • AWS Glue connections dapat dikonfigurasi untuk berjalan dalam VPC yang memiliki koneksi VPN ke jaringan on-premises/third-party. Glue ETL job akan menggunakan ENI di subnet VPC tersebut dan bisa mengakses database melalui VPN tunnel.
  • Cross-account S3 access paling scalable menggunakan bucket policies yang mengizinkan IAM role dari central account. AWS Glue dapat assume role ini untuk membaca data langsung dari bucket di akun lain tanpa copying data.

Miskonsepsi & Jebakan Umum

  • Bukan solusi untuk analitik batch data.
  • Membutuhkan Redshift cluster yang mahal untuk use case ini.
  • Tidak menangani perubahan schema.
  • Membutuhkan banyak custom code untuk pagination, error handling, dll.
  • Membutuhkan custom code dan konfigurasi JDBC.
  • Tidak mendukung Salesforce sebagai source natively.
  • Hanya untuk file transfer, bukan database migration.
  • Tidak mendukung CDC dari Oracle.
  • Memiliki biaya DPU per jam yang lebih tinggi.
  • Memiliki batas memory 10 GB dan timeout 15 menit, tidak cocok untuk 500 GB data.
  • Memuat semua data mentah ke Redshift dulu yang tidak efisien dan menambah biaya storage.
  • Bagus untuk query tapi INSERT INTO dari external table lebih lambat dari COPY langsung.
  • Jauh lebih lambat karena single-connection writing.
  • Adalah single-threaded dan mempengaruhi database.
  • Tidak memanfaatkan paralelisme.
  • Sulit untuk handling XML parsing dan normalisasi kompleks dalam batas 15 menit.
  • Membutuhkan banyak custom code.
  • Tidak mendukung XML natively.
  • Menambah latency dan tidak menyelesaikan timeout.
  • Tidak menyelesaikan masalah timeout karena membaca file besar dari S3 tetap memakan waktu lama.
  • Berguna tapi hanya jika yang dibutuhkan filtering kolom, bukan masalah ukuran file keseluruhan.
  • Tidak bisa mengakses database private tanpa VPN connectivity yang tepat.
  • Tidak mendukung koneksi ke PostgreSQL on-premises melalui VPN.
  • Bisa bekerja tapi memiliki batas timeout 15 menit untuk data besar.
  • Hanya untuk membatasi/deny permissions, bukan grant access.
  • Tidak scalable dan merupakan anti-pattern keamanan.
  • Menduplikasi data dan menambah biaya storage.
