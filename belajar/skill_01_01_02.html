Summary

Skill this including in Domain 1: Ingestion & Transformation (Task 1.1: Perform data ingestion), with fokus on read data from batch sources. Materi berikut merangkum service AWS that relevan beserta concept important that needs kamu kuasai for topik this.

Key Services & Concepts

AWS DMS
Database Migration Service; migration full-load + CDC between database, also to target such as Kinesis/S3/Redshift.
AWS Glue
ETL serverless based on Spark + Data Catalog; ideal for transformation and katalogisasi data.
Amazon EMR
Cluster big data managed (Spark, Hive, Presto); supports Spot Instances for hemat cost.
AWS Lambda
Komputasi serverless event-driven; limit timeout 15 minutes and memory up to 10 GB.
Amazon Redshift
Data warehouse scale petabyte; supports COPY/UNLOAD, materialized view, and streaming ingestion.
Redshift Streaming Ingestion
Konsumsi directly from Kinesis/MSK to materialized view Redshift, latensi seconds, without staging S3.
Amazon S3
Object storage tahan old; dasar data lake, supports event notification, versioning, and lifecycle.
Amazon AppFlow
Integrasi data SaaS (e.g. Salesforce) to AWS with flow terjadwal & transfer inkremental, without code.

Key Points

  • AWS Glue crawler automatically detects schema from data in S3 and creates/updates table in Glue Data Catalog. When schema changes, crawler will detects changes the said.
  • Amazon AppFlow designed khusus for integration data from SaaS applications such as Salesforce to AWS services. AppFlow supports scheduled flows and incremental data transfer based on field filter (such as last modified date), without code custom.
  • AWS DMS supports full load and ongoing replication (CDC) from Oracle to Redshift. AWS SCT (Schema Conversion Tool) mengkonversi schema Oracle to format that compatible with Redshift. Kombinasi this is solution most lengkap.
  • Amazon EMR with Spot Instances provides harga up to 90% cheaper from On-Demand for workload that toleran against interupsi. For job harian 500 GB that must complete in 2 hours, EMR Spark with Spot very cost-effective.
  • COPY command is metode most efficient for loading data to Redshift from S3. By manifest file, Anda can mengontrol file mana that dimuat, prevents duplikasi, and ensures all file that is required ada. COPY reads Parquet natively and performs parallel loading from all file.
  • AWS Glue supports parallel reads from JDBC sources uses hashexpression or hashfield, that divides table menjadi several partition that is read in parallel. Uses read replica ensures produksi not terganggu.
  • AWS Glue crawler detects schema berbagai format (CSV, JSON, dll.) and creates table in Glue Data Catalog. Glue ETL with DynamicFrames can reads from berbagai format, applies mapping and transformation, lalu writes to output that terstandarisasi. Ini solution most efficient because fully managed.
  • S3 byte-range fetches enables Lambda reads file in a gradually (chunk by chunk) without memuat entire file to memory. Ini avoids timeout because each invocation processes partly data.
  • AWS Glue connections can is configured for runs in VPC that has connection VPN to network on-premises/third-party. Glue ETL job will uses ENI in subnet VPC the said and can accesses database through VPN tunnel.
  • Cross-account S3 access most scalable uses bucket policies that allows IAM role from central account. AWS Glue can assume role this for reads data directly from bucket in akun other without copying data.

  • Only for file transfer, not database migration.
  • Not supports CDC from Oracle.
  • Has cost DPU per hours that higher.
  • Has limit memory 10 GB and timeout 15 minutes, not suitable for 500 GB data.
  • Memuat all data mentah to Redshift dulu that not efficient and adds cost storage.
  • Bagus for query but INSERT INTO from external table slower from COPY directly.
  • Jauh slower because single-connection writing.
  • Adalah single-threaded and affects database.
  • Not memanfaatkan paralelisme.
  • Sulit for handling XML parsing and normalisasi kompleks in limit 15 minutes.
  • Requires many custom code.
  • Not supports XML natively.
  • Adds latency and not solves timeout.
  • Not solves problem timeout because reads file large from S3 still memakan time old.
  • Berguna but only if that needed filtering kolom, not problem size file keseluruhan.
  • Not can accesses database private without VPN connectivity that correct.

  • Can works but has limit timeout 15 minutes for data large.
