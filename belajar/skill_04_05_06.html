Domain 4: Security & Governance — Task 4.5: Understand data privacy and governance

Skill 4.5.6: SageMaker Catalog projects

SageMakerCatalogDataZone

Ringkasan

Skill ini termasuk dalam Domain 4: Security & Governance (Task 4.5: Understand data privacy and governance), dengan fokus pada sagemaker catalog projects. Materi berikut merangkum layanan AWS yang relevan beserta konsep penting yang perlu kamu kuasai untuk topik ini.

Layanan & Konsep Utama

Glue Data Catalog
Metastore terpusat (Hive-compatible) berisi definisi tabel/partisi yang dipakai Athena, EMR, Redshift Spectrum.
Amazon SageMaker
Platform ML end-to-end; SageMaker Catalog/Unified Studio untuk governance & discovery data.
Amazon DataZone
Katalog bisnis & portal self-service untuk discovery, subscription, dan governed access (kini SageMaker Catalog).

Poin-Poin Kunci

  • Amazon DataZone (integrated as SageMaker Catalog) dirancang untuk exactly this use case: self-service data discovery dan governed access. Architecture-nya: (1) Domain — organizational container untuk governance, (2) Projects — memiliki data assets, dikategorikan per domain ownership (marketing, finance, etc), (3) Data catalog — memungkinkan data scientists search dan discover assets, (4) Subscription requests — consumers request access yang routes melalui approval workflow (owner/steward approval), (5) Environments — provisioned compute access setelah approval. Proses 2-3 minggu menjadi minutes-to-hours.
  • DataZone project structure separates concerns: Producer projects contain teams yang own dan publish data assets — members dengan "Project Owner" role bisa publish dan manage, "Project Contributor" bisa contribute assets. Consumer projects contain teams yang subscribe ke dan use data — mereka initiate subscription requests. Data Stewards dikonfigurasi sebagai approvers di domain atau project level untuk review subscription requests. Separation of producer/consumer projects mencerminkan organizational boundaries dan responsibility.
  • DataZone subscription workflow adalah inti dari governed data access: (1) Consumer discovers asset di catalog, (2) Consumer submits subscription request — menyertakan use case/purpose, (3) Asset owner atau designated steward reviews request, (4) Upon approval, DataZone automatically grants access — ini bisa berupa Lake Formation permissions, Redshift datashare access, atau Glue catalog permissions tergantung underlying data source, (5) Consumer bisa query data dari their project's environment. Catalog visibility ≠ data access — Anda bisa melihat metadata tapi harus request subscription untuk actual data access.
  • Complete audit trail memerlukan multiple layers: (1) DataZone tracks subscription lifecycle — who requested, what was requested, purpose stated, who approved/denied, timestamps for each state change. (2) CloudTrail captures API-level actions — DataZone API calls, environment provisioning, access grant operations. (3) Underlying service logs capture actual data usage — Athena query logs show what queries ran against subscribed tables, Redshift audit logs show query history, S3 access logs show object access patterns. Kombinasi tiga layer ini memberikan full picture: request → approval → actual usage.
  • Best practice untuk data products adalah menyediakan curated, ready-to-consume datasets. Consolidating three sources ke single curated table (via Glue ETL) kemudian publishing sebagai single asset memberikan: (1) clean consumer experience — satu subscription, satu table, (2) abstraction — consumers tidak perlu tahu tentang underlying 3 sources, (3) quality control — producer ensures data quality sebelum publishing, (4) rich metadata — description, schema documentation, data quality scores, lineage showing where data came from.
  • Ketika subscription approved untuk Glue-based asset, DataZone secara otomatis orchestrates access grants melalui AWS Lake Formation. Proses: (1) DataZone identifies consumer project's environment IAM role, (2) Grants Lake Formation SELECT permission pada Glue table/columns ke consumer role, (3) Jika cross-account, menggunakan RAM share untuk Lake Formation resource sharing, (4) Consumer bisa langsung query menggunakan Athena atau tools lain di their environment — data tetap di location asli (zero-copy). Ini adalah key architectural principle: access granting, bukan data copying.
  • Amazon DataZone mendukung subscription grants dengan expiration/time-based access. Ketika approving subscription request, approver atau policy bisa menetapkan grant duration. Setelah expiration date tercapai, DataZone secara otomatis revokes access — menghapus Lake Formation permissions, Redshift datashare access, atau access mechanism lain yang diberikan. Consumer perlu re-subscribe dan mendapat re-approval jika masih memerlukan akses setelah expiry. Ini built-in feature untuk temporary access patterns.
  • DataZone bisa manage assets berbagai jenis termasuk S3-based unstructured data. Process: (1) Register S3 location (prefix atau specific objects) sebagai asset di DataZone, (2) Enrich dengan metadata — description, classification tags, owner information, (3) Publish ke catalog agar discoverable, (4) Consumers subscribe dan setelah approved, DataZone provisions S3 access melalui IAM role permissions atau bucket policy updates yang allow consumer role untuk GetObject pada S3 path yang registered. Consumer kemudian access files melalui their environment.
  • DataZone mendukung metadata-driven approval policies. Assets bisa di-classify menggunakan metadata forms (sensitivity level: public, internal, confidential). Subscription approval policies dikonfigurasi per project atau domain dan bisa reference asset metadata untuk menentukan approval flow: (1) Public — auto-approve policy, no manual intervention needed, (2) Internal — single approver (project owner/manager), (3) Confidential — multi-level approval chain. Ini memberikan governance proportional to data sensitivity tanpa over-burdening access to low-risk data.
  • DataZone environment blueprints adalah templates yang provision ready-to-use compute environments untuk project members. Sebuah project bisa memiliki MULTIPLE environments dari different blueprints: (1) "Data Lake" blueprint provisions Athena workgroup dengan IAM role yang sudah memiliki access ke subscribed Glue tables, (2) "ML" blueprint provisions SageMaker Studio domain dengan IAM role yang bisa access subscribed data. Kedua environments share same underlying data access (via Lake Formation grants) tapi menyediakan different tools. Users bisa SQL query di Athena DAN run ML experiments di SageMaker pada data yang sama, semua governed oleh subscription.

Miskonsepsi & Jebakan Umum

  • Service Catalog untuk infrastructure provisioning, bukan data governance.
  • Glue + Lake Formation menyediakan access control tapi tidak discovery portal, approval workflow, atau self-service experience.
  • Custom build expensive dan doesn't leverage managed governance features.
  • Custom Lambda authorizers bukan bagian dari DataZone architecture.
  • Single project tidak mendukung proper governance separation; semua users seeing semua assets tanpa discovery process.
  • Separate domains terlalu extreme; domains typically represent organizations, bukan roles.
  • Catalog visibility tidak berarti data access; ini adalah key governance principle.
  • DataZone tidak memiliki "copy feature" yang bypass subscription.
  • Manual credential sharing bypasses governance.
  • CloudTrail mencatat API calls tapi tidak subscription workflow details atau actual data query activity.
  • Config tracks resource configuration, bukan access patterns atau approval workflows.
  • DataZone tidak memiliki built-in compliance reporting dashboard yang comprehensive.
  • Sharing raw bucket ARN bypasses catalog governance dan metadata enrichment.
  • DataZone tidak memiliki "composite asset" feature yang auto-joins sources.
  • Three separate subscriptions creates friction dan exposes implementation details ke consumers.
  • VPN tidak diperlukan; access dilakukan melalui AWS service APIs.
  • No data copying terjadi; ini zero-copy access.
  • Pre-signed URLs bukan mekanisme yang digunakan; ini would bypass governance setelah download.
  • IAM session duration max 12 hours (for assumed roles), bukan 90 days; ini bukan mekanisme yang tepat.
  • Over-engineered dan fragile solution untuk built-in capability.
  • Custom automation bisa bekerja tapi over-engineers sesuatu yang sudah built-in.
  • Kendra adalah search service; DataZone sendiri bisa register S3 assets.
  • DataZone tidak mengkonversi format; ini governance layer bukan transformation tool.
  • DataZone mendukung baik structured maupun unstructured data assets.
  • Separate domains untuk sensitivity levels is over-architecture dan prevents cross-sensitivity discovery.
  • Auto-approve everything undermines governance untuk sensitive data.
  • External workflow menambah complexity; DataZone memiliki built-in approval capabilities.
  • Blueprints digunakan baik producer maupun consumer sides.
  • Multiple environments per project are supported.
  • Blueprints tidak copy data; mereka provision compute access ke same underlying data.
