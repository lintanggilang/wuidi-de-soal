SageMakerCatalogDataZone

Summary

Skill this including in Domain 4: Security & Governance (Task 4.5: Understand data privacy and governance), with fokus on sagemaker catalog projects. Materi berikut merangkum service AWS that relevan along with concept important that needs kamu kuasai for topik this.

Key Services & Concepts

Glue Data Catalog
Metastore terpusat (Hive-compatible) contains definisi table/partition that dipakai Athena, EMR, Redshift Spectrum.
Amazon SageMaker
Platform ML end-to-end; SageMaker Catalog/Unified Studio for governance & discovery data.
Amazon DataZone
Katalog bisnis & portal self-service for discovery, subscription, and governed access (kini SageMaker Catalog).

Key Points

  • Amazon DataZone (integrated as SageMaker Catalog) designed for exactly this use case: self-service data discovery and governed access. Architecture-nya: (1) Domain — organizational container for governance, (2) Projects — has data assets, dikategorikan per domain ownership (marketing, finance, etc), (3) Data catalog — enables data scientists search and discover assets, (4) Subscription requests — consumers request access that routes through approval workflow (owner/steward approval), (5) Environments — provisioned compute access after approval. Proses 2-3 weeks becomes minutes-to-hours.
  • DataZone project structure separates concerns: Producer projects contain teams that own and publish data assets — members with "Project Owner" role can publish and manage, "Project Contributor" can contribute assets. Consumer projects contain teams that subscribe to and use data — mereka initiate subscription requests. Data Stewards is configured as approvers in domain or project level for review subscription requests. Separation of producer/consumer projects mencerminkan organizational boundaries and responsibility.
  • DataZone subscription workflow is inti from governed data access: (1) Consumer discovers asset in catalog, (2) Consumer submits subscription request — menyertakan use case/purpose, (3) Asset owner or designated steward reviews request, (4) Upon approval, DataZone automatically grants access — this can berupa Lake Formation permissions, Redshift datashare access, or Glue catalog permissions depends underlying data source, (5) Consumer can query data from their project's environment. Catalog visibility ≠ data access — Anda can melihat metadata but must request subscription for actual data access.
  • Complete audit trail requires multiple layers: (1) DataZone tracks subscription lifecycle — who requested, what was requested, purpose stated, who approved/denied, timestamps for each state change. (2) CloudTrail captures API-level actions — DataZone API calls, environment provisioning, access grant operations. (3) Underlying service logs capture actual data usage — Athena query logs show what queries ran against subscribed tables, Redshift audit logs show query history, S3 access logs show object access patterns. Kombinasi three layer this provides full picture: request → approval → actual usage.
  • Best practice for data products is provides curated, ready-to-consume datasets. Consolidating three sources to single curated table (via Glue ETL) then publishing as single asset provides: (1) clean consumer experience — one subscription, one table, (2) abstraction — consumers does not need tahu about underlying 3 sources, (3) quality control — producer ensures data quality before publishing, (4) rich metadata — description, schema documentation, data quality scores, lineage showing where data came from.
  • When subscription approved for Glue-based asset, DataZone automatically orchestrates access grants through AWS Lake Formation. Proses: (1) DataZone identifies consumer project's environment IAM role, (2) Grants Lake Formation SELECT permission on Glue table/columns to consumer role, (3) If cross-account, uses RAM share for Lake Formation resource sharing, (4) Consumer can directly query uses Athena or tools other in their environment — data still in location asli (zero-copy). This is key architectural principle: access granting, not data copying.
  • Amazon DataZone supports subscription grants with expiration/time-based access. When approving subscription request, approver or policy can sets grant duration. Setelah expiration date is reached, DataZone automatically revokes access — deletes Lake Formation permissions, Redshift datashare access, or access mechanism other that is provided. Consumer needs re-subscribe and mendapat re-approval if still requires access after expiry. This built-in feature for temporary access patterns.
  • DataZone can manage assets berbagai type including S3-based unstructured data. Process: (1) Register S3 location (prefix or specific objects) as asset in DataZone, (2) Enrich with metadata — description, classification tags, owner information, (3) Publish to catalog so that discoverable, (4) Consumers subscribe and after approved, DataZone provisions S3 access through IAM role permissions or bucket policy updates that allow consumer role for GetObject on S3 path that registered. Consumer then access files through their environment.
  • DataZone supports metadata-driven approval policies. Assets can in-classify uses metadata forms (sensitivity level: public, internal, confidential). Subscription approval policies is configured per project or domain and can reference asset metadata for determines approval flow: (1) Public — auto-approve policy, no manual intervention needed, (2) Internal — single approver (project owner/manager), (3) Confidential — multi-level approval chain. This provides governance proportional to data sensitivity without over-burdening access to low-risk data.
  • DataZone environment blueprints is templates that provision ready-to-use compute environments for project members. Sebuah project can has MULTIPLE environments from different blueprints: (1) "Data Lake" blueprint provisions Athena workgroup with IAM role that already has access to subscribed Glue tables, (2) "ML" blueprint provisions SageMaker Studio domain with IAM role that can access subscribed data. Kedua environments share same underlying data access (via Lake Formation grants) but provides different tools. Users can SQL query in Athena DAN run ML experiments in SageMaker on data that same, all governed by subscription.

Common Misconceptions & Pitfalls

  • Service Catalog for infrastructure provisioning, not data governance.
  • Glue + Lake Formation provides access control but not discovery portal, approval workflow, or self-service experience.
  • Custom build expensive and doesn't leverage managed governance features.
  • Custom Lambda authorizers not part from DataZone architecture.
  • Single project not supports proper governance separation; all users seeing all assets without discovery process.
  • Separate domains too extreme; domains typically represent organizations, not roles.
  • Catalog visibility not berarti data access; this is key governance principle.
  • DataZone not has "copy feature" that bypass subscription.
  • Manual credential sharing bypasses governance.
  • CloudTrail logs API calls but not subscription workflow details or actual data query activity.
  • Config tracks resource configuration, not access patterns or approval workflows.
  • DataZone not has built-in compliance reporting dashboard that comprehensive.
  • Sharing raw bucket ARN bypasses catalog governance and metadata enrichment.
  • DataZone not has "composite asset" feature that auto-joins sources.
  • Three separate subscriptions creates friction and exposes implementation details to consumers.
  • VPN not is required; access is performed through AWS service APIs.
  • No data copying occurs; this zero-copy access.
  • Pre-signed URLs not mekanisme that is used; this would bypass governance after download.
  • IAM session duration max 12 hours (for assumed roles), not 90 days; this not mekanisme that correct.
  • Over-engineered and fragile solution for built-in capability.
  • Custom automation can works but over-engineers sesuatu that already built-in.
  • Kendra is search service; DataZone itself can register S3 assets.
  • DataZone not mengkonversi format; this governance layer not transformation tool.
  • DataZone supports good structured maupun unstructured data assets.
  • Separate domains for sensitivity levels is over-architecture and prevents cross-sensitivity discovery.
  • Auto-approve everything undermines governance for sensitive data.
  • External workflow adds complexity; DataZone has built-in approval capabilities.
  • Blueprints is used good producer maupun consumer sides.
  • Multiple environments per project are supported.
  • Blueprints not copy data; mereka provision compute access to same underlying data.
