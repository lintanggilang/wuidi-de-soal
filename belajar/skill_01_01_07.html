Skill 1.1.7: Call Lambda from Kinesis

LambdaKinesiseventsource

Summary

Skill this including in Domain 1: Ingestion & Transformation (Task 1.1: Perform data ingestion), with fokus on call lambda from kinesis. Materi berikut merangkum service AWS that relevan beserta concept important that needs kamu kuasai for topik this.

Key Services & Concepts

Amazon Kinesis Data Streams
Service streaming real-time managed; data is partitioned to shard, order maintained per shard via partition key.
AWS Lambda
Komputasi serverless event-driven; limit timeout 15 minutes and memory up to 10 GB.
Amazon EventBridge
Event bus serverless for routing event between service; supports schedule rule.

Key Points

  • ParallelizationFactor (default 1, max 10) enables Lambda processes multiple batches from satu shard in a simultaneously. By 10 shards and parallelization factor 10, can ada up to 100 Lambda invocations concurrent. Ini increases throughput in a significant.
  • BisectBatchOnFunctionError divides batch menjadi dua bagian and mencoba each in a separate, in a rekursif identifies record that bermasalah. MaximumRetryAttempts limits number retry before sends to on-failure destination (SQS/SNS) for investigasi.
  • BatchSize determines number maksimum records per batch. MaximumBatchingWindowInSeconds determines berapa old waits for mengumpulkan records before invocation. Lambda will is called when incorrect satu kondisi terpenuhi more dahulu (500 records or 60 seconds).
  • Mengupdate event source mapping with StartingPosition AT_TIMESTAMP enables Lambda starts reads from posisi time certain. Ini is way most directly for replay records from titik time specific.
  • ParallelizationFactor directly increases throughput with processes multiple batches per shard in a simultaneously without changes code or infrastructure. Ini is first step most effective.
  • ReportBatchItemFailures (FunctionResponseTypes) enables Lambda melaporkan only records that fails is processed. Lambda mengembalikan batchItemFailures with sequence numbers from records that needs diretry. Records that succeeds not is processed ulang. Ini provides granular error handling per record.
  • Lambda event source mappings supports Tumbling Windows (up to 900 seconds) that enables stateful processing. Fungsi receives state from invocation sebelumnya and mengembalikan state that diperbarui. On akhir window, function receives isFinalInvokeForWindow=true for emit result akhir.
  • Maximum concurrent executions = number shards × ParallelizationFactor. By 5 shards and ParallelizationFactor 5, maximum is 5 × 5 = 25 concurrent Lambda invocations. If account-level concurrency limit or reserved concurrency less from 25, throttling occurs.
  • Lambda event source mapping supports event filtering (filter criteria) that memfilter records before invocation. Records that not suitable with filter not triggers Lambda, menghemat cost invocation. Filter pattern mengevaluasi record data setelah base64 decode.
  • Kinesis records that melewati retention period (24 hours) is deleted in a permanent from stream. When Lambda in-enable returns setelah 30 hours, iterator old already expired. Lambda will gets error iterator and automatic meresolve with reads from TRIM_HORIZON (data tertua that still available). Records from 6 hours terakhir (30-24) already hilang.
