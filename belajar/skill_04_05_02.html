Domain 4: Security & Governance — Task 4.5: Understand data privacy and governance

Skill 4.5.2: PII identification (Macie)

MaciePIILakeFormation

Ringkasan

Skill ini termasuk dalam Domain 4: Security & Governance (Task 4.5: Understand data privacy and governance), dengan fokus pada pii identification (macie). Materi berikut merangkum layanan AWS yang relevan beserta konsep penting yang perlu kamu kuasai untuk topik ini.

Layanan & Konsep Utama

AWS Lake Formation
Tata kelola data lake: izin berbasis tabel/kolom/baris dan LF-Tags di atas Glue Catalog.
Amazon Macie
Deteksi & klasifikasi PII di S3 secara otomatis menggunakan ML.

Poin-Poin Kunci

  • Kombinasi automated sensitive data discovery dan scheduled classification jobs memberikan coverage paling komprehensif. Automated sensitive data discovery melakukan sampling berkelanjutan terhadap bucket untuk membuat overview, sementara scheduled classification jobs memastikan setiap objek baru di-scan secara sistematis setiap hari. Ini memberikan both continuous monitoring dan comprehensive deep scanning.
  • Macie custom data identifiers memungkinkan pengguna mendefinisikan regex patterns untuk format data sensitif yang unik bagi organisasi. Konfigurasi mencakup: regex pattern (MRN-\d{6}-[A-Z]{2}), keywords untuk mengurangi false positives (harus muncul dalam proximity tertentu), dan maximum match distance yang menentukan seberapa dekat keyword harus berada dari match.
  • Macie terintegrasi native dengan Amazon EventBridge, mengirimkan findings sebagai events. EventBridge rule dapat mem-filter berdasarkan severity (HIGH) dan trigger Lambda function untuk automated remediation — misalnya menambahkan deny policy pada bucket untuk prefix tertentu, menambahkan object tags (classification=pii), atau memindahkan ke quarantine bucket. Parallel SNS notification memberitahu security team.
  • Suppression rules (findings filters with auto-archive) adalah cara paling tepat untuk menangani false positives dari bucket tertentu. Rule dapat dikonfigurasi untuk automatically archive findings dari bucket spesifik tersebut, sehingga tidak muncul di default findings view tapi tetap tersimpan untuk audit. Macie tetap scanning bucket tersebut (berguna jika real PII accidentally masuk ke test bucket).
  • Integrasi Macie-Lake Formation memerlukan orchestration melalui EventBridge dan Lambda karena tidak ada native direct integration. Lambda function melakukan: (1) tagging S3 object untuk classification tracking, (2) mendaftarkan S3 location di Lake Formation jika belum registered, (3) menggunakan Lake Formation API untuk GRANT permissions hanya ke DPO role dan REVOKE dari yang lain. Ini memenuhi GDPR requirement untuk access restriction segera setelah PII teridentifikasi.
  • Macie classification jobs mendukung object criteria filtering termasuk berdasarkan last modified date. Dengan hanya scanning objects yang berubah sejak last successful run, volume scanning berkurang drastis. Sampling depth mengontrol persentase eligible objects yang di-scan per run. Kombinasi incremental approach + appropriate sampling memastikan job selesai dalam window tanpa melewatkan data baru.
  • Macie severity levels ditentukan secara internal berdasarkan jumlah occurrences dan jenis data — pengguna tidak bisa mengubah severity scoring logic. Solusi yang tepat adalah membuat EventBridge rule yang memfilter berdasarkan tipe data identifier (classificationDetails.result.sensitiveData.detections.type = "CREDIT_CARD_NUMBER") tanpa memperhatikan severity field. Rule ini kemudian trigger remediation workflow yang sesuai policy internal (HIGH priority).
  • CCPA mendefinisikan personal information sangat luas. Macie managed data identifiers mencakup banyak standard PII (names, addresses, SSN, credit cards, emails, phone numbers) tetapi tidak mencakup semua kategori CCPA seperti geolocation coordinates, device IDs, atau browsing patterns. Solusi terbaik adalah kombinasi: managed identifiers untuk standard PII + custom data identifiers untuk format CCPA-specific yang tidak di-cover. Custom identifiers bisa mendeteksi patterns seperti koordinat GPS (regex untuk lat/long), MAC addresses, advertising IDs, dll.
  • Automated sensitive data discovery menggunakan sampling, jadi sensitivity score adalah estimasi. Langkah proper adalah: (1) Run targeted classification job untuk mendapatkan complete picture (object-by-object detail), (2) Berdasarkan findings, implementasi data masking/tokenization/encryption di ETL pipeline SEBELUM data landing di staging — ini memastikan PII tidak ada di staging area. Pendekatan ini mengatasi root cause (PII di staging) bukan gejalanya.
  • Security Hub adalah central aggregation point untuk security findings termasuk Macie. Dengan enabling Security Hub integration: (1) Macie findings dari semua member accounts otomatis flow ke Security Hub, (2) Security Hub juga menerima findings dari services lain (GuardDuty, Inspector, dll) memungkinkan cross-service reporting, (3) Security Hub findings bisa di-export ke S3 untuk querying dengan Athena dan visualization dengan QuickSight. Ini memberikan trending, per-account breakdown, dan aggregation yang diminta.

Miskonsepsi & Jebakan Umum

  • Melewatkan data yang masuk antara scan dan memerlukan manual intervention.
  • Bukan cara Macie bekerja — Macie menggunakan jobs, bukan per-object API calls.
  • Menggunakan sampling dan mungkin melewatkan beberapa objek — tidak cukup untuk compliance requirement yang memerlukan detection di semua data.
  • Allow lists digunakan untuk MENGECUALIKAN known non-sensitive matches (false positives), bukan untuk mendeteksi data sensitif baru.
  • Glue sensitive data detection ada tapi pertanyaan spesifik tentang Macie dan custom identifiers adalah fitur built-in Macie.
  • AWS tidak menerima request untuk menambah managed identifiers untuk format proprietary perusahaan.
  • Macie tidak mengirim metrics ke CloudWatch Alarms secara langsung, dan Auto Scaling + Glacier bukan remediation yang tepat.
  • Hanya notification tanpa automation.
  • AWS Config rules tidak directly triggered oleh Macie findings, dan menghapus objects terlalu agresif (mungkin masih diperlukan tapi perlu restricted access).
  • Memerlukan Anda memasukkan setiap synthetic number — tidak scalable jika ratusan test records.
  • Menghentikan scanning entirely — jika real PII masuk ke test bucket, tidak akan terdeteksi.
  • Mempengaruhi SEMUA buckets, bukan hanya test bucket — credit card detection hilang di production buckets juga.
  • Lake Formation tidak memiliki kemampuan membaca Macie findings secara otomatis.
  • Menambah data movement overhead dan bisa mengganggu downstream pipelines yang referencing original path.
  • Tidak ada built-in direct integration antara Macie dan Lake Formation.
  • Mengurangi identifiers mengurangi coverage dan bisa menyebabkan compliance gaps; runtime reduction-nya juga minimal karena bottleneck biasanya di object reading bukan pattern matching.
  • Multiple parallel jobs tidak mempercepat karena Macie memiliki account-level concurrency limits.
  • Meningkatkan sampling depth memperbanyak objects yang di-scan sehingga memperlama runtime, bukan mengurangi.
  • Custom data identifiers tidak memiliki "severity threshold setting" — severity tetap dihitung oleh Macie berdasarkan volume detections.
  • Macie tidak menyediakan konfigurasi untuk mengubah severity scoring per identifier type.
  • Security Hub tidak bisa memodifikasi severity findings sebelum EventBridge; findings flow ke EventBridge langsung dari Macie.
  • Menggunakan custom saja berarti membuat ulang detection yang sudah ada di managed identifiers (duplikasi effort).
  • Managed identifiers tidak cover SEMUA kategori CCPA (terutama behavioral data).
  • Macie bisa mendeteksi sebagian besar dengan managed + custom; third-party tidak diperlukan.
  • Memindahkan ke region tanpa Macie adalah security by obscurity yang tidak menyelesaikan PII exposure risk.
  • Deleting data mengganggu ETL pipeline dan mungkin menghapus data yang masih diperlukan.
  • Exclusion list menyembunyikan masalah, bukan menyelesaikan.
  • Per-account configuration tidak diperlukan jika menggunakan delegated administrator model; juga menambah management overhead.
  • Bisa bekerja tapi hanya untuk Macie findings — tidak mengaggregasi dengan security tools lain.
  • Macie tidak memiliki built-in PDF reporting dashboard.
