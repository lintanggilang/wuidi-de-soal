Skill 3.1.9: Events and schedulers

EventBridgeSchedulerevents

Ringkasan

Skill ini termasuk dalam Domain 3: Operations & Support (Task 3.1: Automate data processing), dengan fokus pada events and schedulers. Materi berikut merangkum layanan AWS yang relevan beserta konsep penting yang perlu kamu kuasai untuk topik ini.

Layanan & Konsep Utama

Amazon EventBridge
Event bus serverless untuk routing event antar layanan; mendukung schedule rule.
EventBridge Scheduler
Penjadwal terkelola (cron/rate) berskala besar untuk memicu target AWS.

Poin-Poin Kunci

  • EventBridge mendukung dua jenis rules pada satu event bus: schedule rules (cron/rate expressions) dan event pattern rules. Kedua rules dapat mengarah ke target yang sama (Step Functions). Ini adalah pendekatan paling sederhana dengan satu service managing kedua triggers.
  • Amazon EventBridge Scheduler (bukan EventBridge rules) dirancang khusus untuk scheduling use cases. Fiturnya termasuk: one-time schedules (at expressions) dengan FlexibleTimeWindow, auto-delete setelah execution, timezone-aware cron expressions (IANA timezone support), dan built-in retry policies.
  • EventBridge event patterns mendukung matching pada nested fields dalam event detail. Tiga rules terpisah, masing-masing matching pada "detail.state" yang spesifik, memungkinkan routing langsung ke target yang berbeda tanpa intermediate processing. Ini menggunakan EventBridge's native content-based routing.
  • Cross-account event routing di EventBridge dilakukan dengan: (1) membuat custom event bus di central account dengan resource-based policy yang mengizinkan PutEvents dari source accounts, (2) membuat rules di source accounts yang mengirim events ke central account's event bus sebagai target. Rules di central account kemudian memproses incoming events.
  • Amazon EventBridge Pipes dirancang untuk point-to-point integrations dengan pipeline stages: Source (DynamoDB Streams, SQS, Kinesis, etc.) → Filter (event pattern matching) → Enrichment (optional Lambda, Step Functions, API Gateway, or API Destination) → Target (Kinesis, Lambda, Step Functions, etc.). Ini menyediakan filtering tanpa Lambda code dan optional enrichment.
  • EventBridge rules mendukung dead-letter queue (SQS) configuration dimana events yang gagal dikirim setelah retry attempts dikirim ke DLQ untuk investigation. Retry policy mengonfigurasi: maximum event age (berapa lama EventBridge retry sebelum menyerah) dan maximum retry attempts. Ini memastikan tidak ada event yang hilang secara permanen.
  • EventBridge Archive menyimpan events yang match an archive rule, dan Replay memungkinkan re-delivery events dari archive untuk time window tertentu ke event bus. Events yang di-replay memiliki "replay-name" header sehingga rules dapat membedakan replay events dari live events. Ini built-in untuk exactly this use case — reprocessing historical events.
  • EventBridge event patterns mendukung content-based routing dengan matching pada S3 event detail fields termasuk object key. Tiga rules terpisah memberikan clear separation of concerns, mudah di-maintain (add/remove rules independently), dan leverages EventBridge's native routing capability tanpa custom code.
  • Custom event bus menyediakan: (1) isolasi dari default bus events — hanya events yang explicitly dikirim ke custom bus yang ada di sana, (2) resource-based policy yang mengontrol siapa yang boleh PutEvents, (3) independent archive configuration dengan retention policy terpisah. Ini memenuhi semua tiga requirements: isolation, access control, dan retention.
  • EventBridge Scheduler memiliki built-in features untuk semua requirements: (1) Retry Policy dengan configurable MaximumRetryAttempts dan MaximumEventAgeInSeconds untuk automatic retries pada transient failures, (2) FlexibleTimeWindow yang mendistribusikan invocations dalam time window untuk mengurangi thundering herd dan accommodate jitter, (3) CloudWatch metrics (InvocationAttemptCount, TargetErrorCount, InvocationDroppedCount) memberikan visibility ke execution history.

Miskonsepsi & Jebakan Umum

  • Redundant karena CloudWatch Events sekarang merupakan bagian dari EventBridge.
  • Salah — satu rule tidak bisa matching baik schedule maupun event pattern sekaligus.
  • Menggunakan dua service berbeda (EventBridge Scheduler + S3 notifications) yang menambah complexity.
  • Tidak mendukung one-time schedule dengan auto-cleanup natively — memerlukan custom cleanup logic.
  • Berlebihan overhead untuk simple scheduling needs.
  • Untuk patching/maintenance, bukan data pipeline scheduling.
  • Salah — Glue tidak mendukung direct notification configuration ke multiple services per state.
  • Bekerja tetapi menambah latency, cost, dan maintenance dibandingkan native EventBridge routing.
  • Salah — input transformers mengubah event format tetapi satu rule hanya bisa memiliki satu set targets, bukan routing conditional.
  • Salah — tidak ada auto-sharing di Organizations level untuk semua events.
  • Salah — default event bus tidak bisa menjadi target cross-account rule langsung.
  • Menambah component yang tidak perlu karena EventBridge sudah mendukung cross-account natively.
  • Memerlukan Lambda code untuk enrichment yang bertentangan dengan requirement.
  • Untuk time-based triggers, bukan stream processing.
  • Hanya mengubah format, bukan enrich dari external source.
  • Untuk memutar ulang archived events, bukan untuk handling delivery failures.
  • Tidak menyimpan event payload untuk reprocessing.
  • Hanya bekerja jika event berhasil sampai ke Lambda — jika EventBridge gagal deliver, Lambda DLQ tidak membantu.
  • Tidak menyimpan structured events untuk replay.
  • Mungkin tidak feasible — source system mungkin tidak mendukung historical resending.
  • Mencatat API calls, bukan event payloads.
  • Menambah latency, cost, dan maintenance burden.
  • Overhead untuk simple routing — Step Functions lebih cocok untuk complex orchestration.
  • Bisa bekerja tetapi memiliki limit per bucket dan kurang flexible dibanding EventBridge patterns.
  • Untuk point-to-point, bukan many-to-many event distribution.
  • Menambah component dan tidak menyediakan archive/retention natively.
  • Mencampur semua events di satu bus tanpa isolation yang bersih.
  • Memiliki retry tapi tidak FlexibleTimeWindow.
