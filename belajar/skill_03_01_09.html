Skill 3.1.9: Events and schedulers

Summary

Skill this including in Domain 3: Operations & Support (Task 3.1: Automate data processing), with fokus on events and schedulers. Materi berikut merangkum service AWS that relevan along with concept important that needs kamu kuasai for topik this.

Key Services & Concepts

Amazon EventBridge
Event bus serverless for routing event between service; supports schedule rule.
EventBridge Scheduler
Penjadwal managed (cron/rate) scale large for triggers target AWS.

Key Points

  • EventBridge supports two type rules on one event bus: schedule rules (cron/rate expressions) and event pattern rules. Kedua rules can mengarah to target that same (Step Functions). This is approach most simple with one service managing second triggers.
  • Amazon EventBridge Scheduler (not EventBridge rules) designed khusus for scheduling use cases. Fiturnya including: one-time schedules (at expressions) with FlexibleTimeWindow, auto-delete after execution, timezone-aware cron expressions (IANA timezone support), and built-in retry policies.
  • EventBridge event patterns supports matching on nested fields in event detail. Tiga rules separate, each matching on "detail.state" that specific, enables routing directly to target that different without intermediate processing. This uses EventBridge's native content-based routing.
  • Cross-account event routing in EventBridge is performed with: (1) creates custom event bus in central account with resource-based policy that allows PutEvents from source accounts, (2) creates rules in source accounts that sends events to central account's event bus as target. Rules in central account then processes incoming events.
  • Amazon EventBridge Pipes designed for point-to-point integrations with pipeline stages: Source (DynamoDB Streams, SQS, Kinesis, etc.) → Filter (event pattern matching) → Enrichment (optional Lambda, Step Functions, API Gateway, or API Destination) → Target (Kinesis, Lambda, Step Functions, etc.). This provides filtering without Lambda code and optional enrichment.
  • EventBridge rules supports dead-letter queue (SQS) configuration where events that fails is sent after retry attempts is sent to DLQ for investigation. Retry policy configures: maximum event age (how many old EventBridge retry before menyerah) and maximum retry attempts. This ensures there is no event that hilang in a permanent.
  • EventBridge Archive stores events that match an archive rule, and Replay enables re-delivery events from archive for time window certain to event bus. Events that in-replay has "replay-name" header so that rules can membedakan replay events from live events. This built-in for exactly this use case — reprocessing historical events.
  • EventBridge event patterns supports content-based routing with matching on S3 event detail fields including object key. Tiga rules separate provides clear separation of concerns, easy in-maintain (add/remove rules independently), and leverages EventBridge's native routing capability without custom code.
  • Custom event bus provides: (1) isolasi from default bus events — only events that explicitly is sent to custom bus that there is in sana, (2) resource-based policy that controls who that boleh PutEvents, (3) independent archive configuration with retention policy separate. This memenuhi all three requirements: isolation, access control, and retention.
  • EventBridge Scheduler has built-in features for all requirements: (1) Retry Policy with configurable MaximumRetryAttempts and MaximumEventAgeInSeconds for automatic retries on transient failures, (2) FlexibleTimeWindow that distributes invocations in time window for reduces thundering herd and accommodate jitter, (3) CloudWatch metrics (InvocationAttemptCount, TargetErrorCount, InvocationDroppedCount) provides visibility to execution history.
