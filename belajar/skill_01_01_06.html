Key Services & Concepts

Amazon S3
Object storage tahan old; dasar data lake, supports event notification, versioning, and lifecycle.
Amazon EventBridge
Event bus serverless for routing event between service; supports schedule rule.
Amazon SNS
Pub/sub notifikasi for fan-out messages to many subscriber (SQS, Lambda, HTTP).

Key Points

  • Amazon EventBridge integration with S3 is way most reliable for event-driven triggers. EventBridge captures all S3 events with at-least-once delivery and supports filtering based on prefix. This also can directly menargetkan Glue API.
  • EventBridge rules supports content-based filtering on event payload including S3 object key. Tiga rules separate with suffix filter (.csv, .json, .parquet) provides routing most bersih without code additional. Each rule menargetkan pipeline that different.
  • DLQ captures messages that fails is processed after max retries, prevents infinite reprocessing. Idempotent processing with DynamoDB tracking ensures that if message is processed ulang, hasilnya same (there is no duplikasi data).
  • Marker file (sentinel file) pattern is solution most simple and reliable. Source system mengupload "_COMPLETE" file after all data files complete diupload. S3 event notification only triggers pipeline when marker file muncul, guarantees all data already available.
  • SQS queue as buffer between S3 events and Lambda prevents event loss. SQS stores messages up to Lambda siap memprosesnya (retention up to 14 days). Lambda SQS event source mapping also configures batch size and concurrency automatically.
  • Enabling EventBridge on an S3 bucket works alongside existing S3 Event Notifications without konflik. EventBridge receives all S3 events in a independent and Anda can creates rules with multiple targets. Existing notification to SNS still berfungsi.
  • EventBridge captures Glue Job State Change events natively. By rule filtering on state "FAILED" and input transformation, event detail (jobName, error message) can diteruskan to Step Functions as input. This is pattern event-driven that most direct.
  • EventBridge supports content-based filtering including numeric matching on field such as object size. Rule can filters events where detail.object.size > 104857600 (100 MB). This avoids invokasi that does not need.
  • EventBridge S3 events include detail.reason field that indicates how object is created (PutObject, CompleteMultipartUpload, CopyObject, dll). Memfilter on field this in EventBridge rule ensures Lambda only is called for multipart uploads.
  • Cross-account EventBridge event forwarding is pattern most secure and native for cross-account event triggers. Account A allows Account B's event bus as target through resource-based policy. This uses IAM for security and not requires shared credentials.
