Domain 2: Data Store Management — Task 2.4: Design data models and schema evolution

Skill 2.4.4: Establish data lineage

lineageSageMakerTracking

Ringkasan

Skill ini termasuk dalam Domain 2: Data Store Management (Task 2.4: Design data models and schema evolution), dengan fokus pada establish data lineage. Materi berikut merangkum layanan AWS yang relevan beserta konsep penting yang perlu kamu kuasai untuk topik ini.

Layanan & Konsep Utama

Amazon SageMaker
Platform ML end-to-end; SageMaker Catalog/Unified Studio untuk governance & discovery data.

Poin-Poin Kunci

  • Amazon SageMaker ML Lineage Tracking secara otomatis mencatat hubungan antara datasets, processing steps, training jobs, dan model artifacts dalam bentuk grafik lineage. Ini menciptakan record end-to-end dari data source hingga model deployment.
  • Amazon DataZone menyediakan visualisasi lineage yang menunjukkan aliran data dari sumber ke tujuan secara end-to-end. Ini memungkinkan upstream tracing dari Redshift kembali ke raw S3 data melalui setiap transformasi Glue.
  • SageMaker ML Lineage Tracking menggunakan grafik lineage dengan entities (Artifacts, Contexts, Actions) yang dihubungkan oleh Associations. Untuk menemukan semua data sources yang berkontribusi ke model tertentu, Anda traverse upstream dari Model Artifact melalui Associations, yang akan menunjukkan semua processing steps dan input datasets.
  • OpenLineage adalah standar terbuka untuk lineage metadata yang memungkinkan interoperabilitas antar tools. AWS Glue mendukung integrasi OpenLineage yang memungkinkan emisi lineage events dalam format standar, sehingga bisa dikonsumsi oleh tools pihak ketiga seperti Marquez atau DataHub.
  • Impact analysis memerlukan downstream lineage traversal — yaitu menelusuri ke bawah dari dataset yang akan diubah untuk mengidentifikasi semua konsumen (reports, dashboards, ML models) yang bergantung padanya. Ini membantu tim memahami blast radius dari perubahan schema.
  • Data lineage dengan transformation metadata memungkinkan verifikasi bahwa langkah-langkah pemrosesan yang diperlukan (anonymization, pseudonymization) ada dalam jalur lineage antara data PII mentah dan output analytics. Ini memberikan bukti proses yang bisa diaudit.
  • Dengan membandingkan lineage graphs dari kedua model artifacts, tim dapat mengidentifikasi perbedaan spesifik — apakah input dataset berubah, apakah ada processing step baru, atau apakah hyperparameters berbeda. Ini memberikan root cause analysis yang komprehensif.
  • Amazon DataZone mendukung cross-account enrollment yang memungkinkan visualisasi lineage terpusat across multiple AWS accounts. Ini memberikan single-pane-of-glass view untuk memahami bagaimana data mengalir lintas account boundaries.
  • SageMaker Feature Store terintegrasi dengan SageMaker ML Lineage Tracking, dan ketika feature computation dijalankan melalui SageMaker Pipelines, lineage secara otomatis di-capture termasuk input data, transformasi, dan output features. Tidak diperlukan instrumentasi manual.
  • Amazon SageMaker Catalog (sebelumnya Amazon DataZone) dirancang untuk data mesh architecture, memungkinkan domain teams mempublikasikan data products ke katalog bisnis terpusat dengan lineage metadata. Ini mendukung berbagai compute engines dan memberikan organization-wide lineage visibility tanpa memaksa standarisasi tools.

Miskonsepsi & Jebakan Umum

  • Hanya melacak perubahan schema, bukan hubungan data-to-model.
  • Hanya mencatat API calls tanpa konteks ML pipeline.
  • Memerlukan effort manual dan tidak memberikan visualisasi lineage otomatis.
  • Hanya menunjukkan file mana yang di-load, bukan full transformation lineage.
  • Hanya menunjukkan siapa yang mengakses file, bukan bagaimana data ditransformasi.
  • Memerlukan effort manual yang signifikan dan tidak scalable.
  • Menunjukkan steps dalam satu trial tapi tidak full upstream lineage.
  • Mengelompokkan entitas tapi tidak memberikan directional lineage.
  • Terlalu broad, mencakup semua trials.
  • Memerlukan custom development yang mahal dan tidak mengikuti standar.
  • Fokus pada quality rules bukan lineage.
  • Adalah untuk access control, bukan lineage tracking.
  • Adalah fitur spesifik yang tidak menjawab kebutuhan impact analysis secara umum.
  • Menunjukkan sumber data, bukan konsumen.
  • Membandingkan schema tapi tidak menunjukkan siapa yang terpengaruh.
  • Memeriksa konfigurasi job tapi tidak membuktikan bahwa job tersebut benar-benar dieksekusi pada data tertentu.
  • Adalah reactive, bukan preventive, dan tidak membuktikan proses yang benar dijalankan.
  • Sangat mahal dan tidak scalable untuk 15 transformasi.
  • Menunjukkan resource usage bukan data/pipeline changes.
  • Menunjukkan versi model tapi tidak detail tentang apa yang berubah di pipeline.
  • Membantu debug training issues tapi tidak menunjukkan perubahan di input data atau preprocessing.
  • Tidak memberikan unified view.
  • Memungkinkan sharing catalog resources tapi tidak memberikan unified lineage visualization.
  • Tidak praktis dan melanggar best practices multi-account.
  • Memerlukan manual annotations.
  • Dan D memerlukan custom development yang signifikan dan tidak otomatis — keduanya memerlukan effort engineering untuk membangun dan memaintain.
  • Memerlukan custom development dan CloudTrail tidak memberikan transformation-level lineage.
  • Fokus pada access control, bukan lineage tracking lintas heterogeneous tools.
  • Tidak praktis karena memaksa semua tim menggunakan satu service.
