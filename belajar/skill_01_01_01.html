Summary

Skill this including in Domain 1: Ingestion & Transformation (Task 1.1: Perform data ingestion), with fokus on read data from streaming sources. Materi berikut merangkum service AWS that relevan beserta concept important that needs kamu kuasai for topik this.

Key Services & Concepts

Amazon Kinesis Data Streams
Service streaming real-time managed; data is partitioned to shard, order maintained per shard via partition key.
Amazon MSK
Apache Kafka managed; suitable for streaming high throughput with ecosystem Kafka.
MSK Connect
Runs Kafka Connect connector in a fully managed (e.g. S3 sink) without manages infrastructure.
DynamoDB Streams
Change data capture for changes item DynamoDB (insert/update/delete) in real-time without disrupting table.
AWS DMS
Database Migration Service; migration full-load + CDC between database, also to target such as Kinesis/S3/Redshift.
AWS Glue
ETL serverless based on Spark + Data Catalog; ideal for transformation and katalogisasi data.
Amazon Redshift
Data warehouse scale petabyte; supports COPY/UNLOAD, materialized view, and streaming ingestion.
Redshift Streaming Ingestion
Konsumsi directly from Kinesis/MSK to materialized view Redshift, latensi seconds, without staging S3.
Amazon DynamoDB
Database NoSQL key-value low latency; horizontal scaling, supports TTL and Streams.

Key Points

  • Amazon Kinesis Data Streams ensures order per shard uses partition key. By sets partition key to trading symbol, all event for symbol that same enters to shard that same, maintains order. Kinesis also designed for high throughput with millions of event per seconds.
  • Amazon MSK Connect is solution most operationally efficient for sends data from MSK to S3. MSK Connect is service fully managed that runs Kafka Connect connectors without needing manages infrastructure. S3 sink connector already available and just needs to be is configured.
  • DynamoDB Streams captures changes data (inserts, updates, deletes) in real-time without affects performa table produksi. Lambda sebagai consumer can processes each changes and triggers pipeline analytics when threshold is reached.
  • AWS DMS supports CDC (Change Data Capture) from Oracle sebagai source and Kinesis Data Streams sebagai target endpoint. Ini is solution most terintegrasi and managed for streaming change events to Kinesis.
  • Each shard Kinesis supports up to 1 MB/seconds or 1.000 records/seconds for write. Based on throughput data: 5.000 records × 50 KB = 250.000 KB/seconds = ~244 MB/seconds. Based on volume: 244 MB / 1 MB per shard = 244 shards (dibulatkan to 250). Based on number records: 5.000 / 1.000 = 5 shards. Bottleneck ada on throughput data (MB/s), so that minimal 250 shards is required.
  • AWS Glue streaming ETL can consumes data from MSK, performs lookup to DynamoDB uses DynamicFrame or native Spark lookups, and writes to Redshift. Ini is solution most scalable because fully managed and autoscaling.
  • Enhanced Fan-Out provides dedicated 2 MB/seconds throughput per consumer per shard uses HTTP/2 push (SubscribeToShard). Ini eliminates sharing throughput between consumer and provides latensi rata-rata ~70ms.
  • AWS Transfer Family provides SFTP endpoint that managed and directly writes to S3. S3 Event Notification triggers Lambda that reads CSV, changes to format that appropriate, and writes to Kinesis Data Streams. Ini suitable because source only can SFTP.
  • Kinesis Data Streams On-Demand mode automatically scales capacity based on throughput aktual without needing provisioning manual. Ini eliminates throttling without changes code producer.
  • Amazon Redshift Streaming Ingestion enables Redshift reads directly from Amazon MSK (or Kinesis) through materialized view, without needing staging in S3 or ETL pipeline additional. Data available in hitungan seconds. Ini is solution most simple with minimal ETL complexity.

  • Requires management ECS and JDBC connections to Redshift.
  • Increases total throughput but consumer still shares 2 MB/s per shard.
  • Only for scaling processing, not dedicated throughput.

  • Not can reads from S3 via streaming (only batch).
