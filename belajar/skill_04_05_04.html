Skill 4.5.4: Configuration changes (AWS Config)

AWSConfigcompliance

Summary

Skill this including in Domain 4: Security & Governance (Task 4.5: Understand data privacy and governance), with fokus on configuration changes (aws config). Materi berikut merangkum service AWS that relevan beserta concept important that needs kamu kuasai for topik this.

Key Services & Concepts

S3 Object Lock
WORM (write-once-read-many) for prevents deletion objek demi kepatuhan/retensi legal.
AWS Config
Merekam & mengevaluasi configuration source daya for kepatuhan from time to time.

Key Points

  • AWS Config and CloudTrail provides informasi komplementer: Config stores configuration timeline (state history) — menunjukkan configuration SEBELUM and SESUDAH changes beserta timestamp, enables Anda melihat persis what encryption setting old. CloudTrail merekam API calls including identity of caller (WHO — IAM user/role ARN, source IP). Kombinasi keduanya provides complete audit trail.
  • AWS Config Aggregator mengumpulkan configuration and compliance data from multiple accounts and regions to satu central view. Dikombinasi with Config advanced queries (that uses SQL-like syntax), security team can runs queries such as "SELECT resourceId, configuration WHERE resourceType = 'AWS::S3::Bucket' AND configuration.serverSideEncryptionConfiguration IS NULL" across all 15 accounts. Aggregator can in-setup through AWS Organizations (automatic enrollment) or individual account authorization.
  • AWS Config supports selective recording — Anda can memilih resource types that ingin direkam daripada merekam all resources. By memilih specific types (Redshift clusters, Glue jobs/crawlers/databases, S3 buckets), only changes on resource types the said that direkam. Ini reduces number configuration items that is stored and cost.
  • Config Conformance Packs is collection of Config rules and remediation actions that can be deployed as a single entity. When deployed through AWS Organizations, conformance packs automatic is applied to all member accounts including accounts new that bergabung. Conformance pack can contains managed rules (s3-bucket-server-side-encryption-enabled, s3-bucket-versioning-enabled, s3-bucket-public-read-prohibited, s3-bucket-logging-enabled) in satu template YAML.
  • AWS Config remediation actions uses AWS Systems Manager Automation documents. AWS provides pre-built SSM Automation documents for common remediations including AWS-DisableS3BucketPublicReadWrite. By configures automatic remediation on Config rule, each kali rule evaluates sebagai NON_COMPLIANT, SSM Automation document automatic dieksekusi. Retry mechanism ensures remediation dicoba several kali if fails.
  • Custom Config rules uses Lambda functions that in-trigger by Config saat configuration changes is detected or in a periodic. Lambda function receives event contains configuration item (resource details), mengevaluasi compliance (whether SecurityConfiguration ada and mereferensikan config that correct, whether logging enabled), lalu calls PutEvaluations API with result COMPLIANT or NON_COMPLIANT.
  • AWS Config Resource Timeline (also disebut Configuration Timeline) is feature that menampilkan complete history of configuration changes for specific resource. For Redshift cluster, timeline menunjukkan: each changes configuration (parameter group, VPC security groups, encryption, node type, dll), timestamp changes, and capabilities for compare configurations between dua titik time (diff view). Ini is way most directly and detail for melihat what that changes.
  • Organization conformance pack deploys Config rules to all member accounts automatically. EventBridge rules in each account forward compliance change events to central event bus saat Config rule evaluates NON_COMPLIANT. Central EventBridge rule then triggers SNS notification. Ini provides near real-time notification (Config evaluates saat resource creation detected, EventBridge forwards immediately).
  • Pertanyaan this about STATE on titik time certain, not EVENTS. AWS Config merekam configuration items — snapshot lengkap from configuration resource on each changes. By Config, Anda can melihat "on timestamp X, resource Y has configuration Z." Ini including security groups that attached to Redshift cluster on time certain. CloudTrail merekam EVENTS (API calls) — for menjawab question state, Anda must replay all events from awal that complex and error-prone.
  • Best practice is uses managed rules saat available (AWS maintains and updates them) and custom rules only when is required. AWS already provides managed rules for Redshift audit logging (redshift-audit-logging-enabled) and berbagai S3 checks. For S3 lifecycle, can is used custom rule or managed rule that appropriate. For Glue job encryption, custom rule is required because there is no managed rule. All rules dikelompokkan in conformance pack for unified compliance view and single deployment unit.

Common Misconceptions & Pitfalls

  • Trusted Advisor provides recommendations, not change history.
  • Config TIDAK merekam identitas who that creates changes; Config only merekam state changes.
  • CloudTrail merekam API request parameters but not always stores PREVIOUS state; also request parameters not always menunjukkan full previous configuration.
  • Organizations API not provides resource configuration details.
  • Security Hub aggregasi for security findings, not full configuration data.
  • Can works but requires additional infrastructure (Athena, Glue catalog) and data not real-time.
  • Config not supports tag-based recording selection; tag-based filtering only available for Config rules evaluation scope, not recording.
  • "Record all resources" merekam SEMUA resource types in account that adds cost; filtering only in display level, recording still occurs.
  • Not ada feature "service-linked recording" that auto-detect data services in Config.
  • Security Hub has S3 checks but this separate from Config rules and not provides Config-specific compliance reporting.
  • CloudFormation StackSets can deploy rules but requires manual update saat adds rules; also less terintegrasi with Config's compliance view.
  • Single custom rule less maintainable and not mengikuti best practice separation of concerns.
  • EventBridge + Lambda can works but this bypass Config's built-in remediation feature; less integrated and not memanfaatkan retry/tracking built-in.
  • Config auto-remediation uses SSM documents not direct Lambda invocation; for custom remediation, Anda creates custom SSM document that could call Lambda, but pre-built document already available.
  • Manual remediation not memenuhi requirement "automatic".
  • Config custom policy rules (Guard/Proactive rules) available but not all resource types is supported by Guard; for Glue jobs, Lambda-based rule more reliable.
  • CloudWatch Events not mekanisme delivery for custom Config rules; Config must trigger Lambda directly.
  • Advanced queries only menampilkan current state, not continuous compliance evaluation with tracking history.
  • Redshift maintenance history only mencakup maintenance events (patches, upgrades), not user-initiated configuration changes.
  • CloudTrail menunjukkan API calls (SIAPA performs APA) but not menampilkan full configuration state before/after; also parameter group detail may not lengkap in event.
  • Configuration snapshots to S3 can in-compare but manual and not se-user-friendly timeline view.
  • Config Aggregator mengumpulkan compliance data but not has native built-in notification mechanism that directly trigger SNS from compliance changes; aggregation can delay.
  • CloudTrail can detects API calls but parsing CreateDBInstance parameters for encryption requires complex filtering and may miss encrypt-after-create scenarios.
  • Polling each 5 minutes not near real-time and creates significant API overhead across 20 accounts.
  • Meskipun kombinasi useful, Config alone quite for question about state.
  • VPC Flow Logs logs network traffic, not security group configuration.
  • CloudTrail logs modification events but not stores resulting state directly; Anda must merekonstruksi state from sequence of events.
  • Advanced queries not compliance evaluation mechanism; mereka snapshot current state without tracking history or compliance status.
  • Single Lambda handling multiple resource types melanggar single responsibility principle and difficult in-maintain.
  • Tiga custom rules adds maintenance burden for checks that already ada sebagai managed rules.
