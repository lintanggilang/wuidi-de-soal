Skill 4.5.4: Configuration changes (AWS Config)

AWSConfigcompliance

Ringkasan

Skill ini termasuk dalam Domain 4: Security & Governance (Task 4.5: Understand data privacy and governance), dengan fokus pada configuration changes (aws config). Materi berikut merangkum layanan AWS yang relevan beserta konsep penting yang perlu kamu kuasai untuk topik ini.

Layanan & Konsep Utama

S3 Object Lock
WORM (write-once-read-many) untuk mencegah penghapusan objek demi kepatuhan/retensi legal.
AWS Config
Merekam & mengevaluasi konfigurasi sumber daya untuk kepatuhan dari waktu ke waktu.

Poin-Poin Kunci

  • AWS Config dan CloudTrail memberikan informasi komplementer: Config menyimpan configuration timeline (state history) — menunjukkan konfigurasi SEBELUM dan SESUDAH perubahan beserta timestamp, memungkinkan Anda melihat persis apa encryption setting lama. CloudTrail merekam API calls termasuk identity of caller (WHO — IAM user/role ARN, source IP). Kombinasi keduanya memberikan complete audit trail.
  • AWS Config Aggregator mengumpulkan configuration dan compliance data dari multiple accounts dan regions ke satu central view. Dikombinasi dengan Config advanced queries (yang menggunakan SQL-like syntax), security team bisa menjalankan queries seperti "SELECT resourceId, configuration WHERE resourceType = 'AWS::S3::Bucket' AND configuration.serverSideEncryptionConfiguration IS NULL" across semua 15 accounts. Aggregator bisa di-setup melalui AWS Organizations (automatic enrollment) atau individual account authorization.
  • AWS Config mendukung selective recording — Anda bisa memilih resource types yang ingin direkam daripada merekam semua resources. Dengan memilih spesifik types (Redshift clusters, Glue jobs/crawlers/databases, S3 buckets), hanya perubahan pada resource types tersebut yang direkam. Ini mengurangi jumlah configuration items yang disimpan dan biaya.
  • Config Conformance Packs adalah collection of Config rules dan remediation actions yang can be deployed as a single entity. Ketika deployed melalui AWS Organizations, conformance packs otomatis diterapkan ke semua member accounts termasuk accounts baru yang bergabung. Conformance pack bisa berisi managed rules (s3-bucket-server-side-encryption-enabled, s3-bucket-versioning-enabled, s3-bucket-public-read-prohibited, s3-bucket-logging-enabled) dalam satu template YAML.
  • AWS Config remediation actions menggunakan AWS Systems Manager Automation documents. AWS menyediakan pre-built SSM Automation documents untuk common remediations termasuk AWS-DisableS3BucketPublicReadWrite. Dengan mengonfigurasi automatic remediation pada Config rule, setiap kali rule evaluates sebagai NON_COMPLIANT, SSM Automation document otomatis dieksekusi. Retry mechanism memastikan remediation dicoba beberapa kali jika gagal.
  • Custom Config rules menggunakan Lambda functions yang di-trigger oleh Config saat configuration changes terdeteksi atau secara periodic. Lambda function menerima event berisi configuration item (resource details), mengevaluasi compliance (apakah SecurityConfiguration ada dan mereferensikan config yang benar, apakah logging enabled), lalu memanggil PutEvaluations API dengan hasil COMPLIANT atau NON_COMPLIANT.
  • AWS Config Resource Timeline (juga disebut Configuration Timeline) adalah fitur yang menampilkan complete history of configuration changes untuk specific resource. Untuk Redshift cluster, timeline menunjukkan: setiap perubahan configuration (parameter group, VPC security groups, encryption, node type, dll), timestamp perubahan, dan kemampuan untuk compare configurations antar dua titik waktu (diff view). Ini adalah cara paling langsung dan detail untuk melihat apa yang berubah.
  • Organization conformance pack deploys Config rules ke semua member accounts secara otomatis. EventBridge rules di setiap account forward compliance change events ke central event bus saat Config rule evaluates NON_COMPLIANT. Central EventBridge rule kemudian triggers SNS notification. Ini memberikan near real-time notification (Config evaluates saat resource creation detected, EventBridge forwards immediately).
  • Pertanyaan ini tentang STATE pada titik waktu tertentu, bukan EVENTS. AWS Config merekam configuration items — snapshot lengkap dari konfigurasi resource pada setiap perubahan. Dengan Config, Anda bisa melihat "pada timestamp X, resource Y memiliki configuration Z." Ini termasuk security groups yang attached ke Redshift cluster pada waktu tertentu. CloudTrail merekam EVENTS (API calls) — untuk menjawab pertanyaan state, Anda harus replay semua events dari awal yang complex dan error-prone.
  • Best practice adalah menggunakan managed rules saat tersedia (AWS maintains dan updates them) dan custom rules hanya ketika diperlukan. AWS sudah menyediakan managed rules untuk Redshift audit logging (redshift-audit-logging-enabled) dan berbagai S3 checks. Untuk S3 lifecycle, bisa digunakan custom rule atau managed rule yang sesuai. Untuk Glue job encryption, custom rule diperlukan karena tidak ada managed rule. Semua rules dikelompokkan dalam conformance pack untuk unified compliance view dan single deployment unit.

Miskonsepsi & Jebakan Umum

  • Trusted Advisor memberikan recommendations, bukan change history.
  • Config TIDAK merekam identitas siapa yang membuat perubahan; Config hanya merekam state changes.
  • CloudTrail merekam API request parameters tapi tidak selalu menyimpan PREVIOUS state; juga request parameters tidak selalu menunjukkan full previous configuration.
  • Organizations API tidak menyediakan resource configuration details.
  • Security Hub aggregasi untuk security findings, bukan full configuration data.
  • Bisa bekerja tapi memerlukan additional infrastructure (Athena, Glue catalog) dan data tidak real-time.
  • Config tidak mendukung tag-based recording selection; tag-based filtering hanya tersedia untuk Config rules evaluation scope, bukan recording.
  • "Record all resources" merekam SEMUA resource types di account yang menambah cost; filtering hanya di display level, recording tetap terjadi.
  • Tidak ada fitur "service-linked recording" yang auto-detect data services di Config.
  • Security Hub memiliki S3 checks tapi ini terpisah dari Config rules dan tidak memberikan Config-specific compliance reporting.
  • CloudFormation StackSets bisa deploy rules tapi memerlukan manual update saat menambah rules; juga kurang terintegrasi dengan Config's compliance view.
  • Single custom rule kurang maintainable dan tidak mengikuti best practice separation of concerns.
  • EventBridge + Lambda bisa bekerja tapi ini bypass Config's built-in remediation feature; kurang integrated dan tidak memanfaatkan retry/tracking built-in.
  • Config auto-remediation menggunakan SSM documents bukan direct Lambda invocation; untuk custom remediation, Anda membuat custom SSM document yang could call Lambda, tapi pre-built document sudah tersedia.
  • Manual remediation tidak memenuhi requirement "automatic".
  • Config custom policy rules (Guard/Proactive rules) tersedia tapi tidak semua resource types didukung oleh Guard; untuk Glue jobs, Lambda-based rule lebih reliable.
  • CloudWatch Events bukan mekanisme delivery untuk custom Config rules; Config harus trigger Lambda langsung.
  • Advanced queries hanya menampilkan current state, bukan continuous compliance evaluation dengan tracking history.
  • Redshift maintenance history hanya mencakup maintenance events (patches, upgrades), bukan user-initiated configuration changes.
  • CloudTrail menunjukkan API calls (SIAPA melakukan APA) tapi tidak menampilkan full configuration state before/after; juga parameter group detail mungkin tidak lengkap di event.
  • Configuration snapshots ke S3 bisa di-compare tapi manual dan tidak se-user-friendly timeline view.
  • Config Aggregator mengumpulkan compliance data tapi tidak memiliki native built-in notification mechanism yang langsung trigger SNS dari compliance changes; aggregation bisa delay.
  • CloudTrail bisa mendeteksi API calls tapi parsing CreateDBInstance parameters untuk encryption memerlukan complex filtering dan mungkin miss encrypt-after-create scenarios.
  • Polling setiap 5 menit bukan near real-time dan creates significant API overhead across 20 accounts.
  • Meskipun kombinasi berguna, Config alone cukup untuk pertanyaan tentang state.
  • VPC Flow Logs mencatat network traffic, bukan security group configuration.
  • CloudTrail mencatat modification events tapi tidak menyimpan resulting state secara langsung; Anda harus merekonstruksi state dari sequence of events.
  • Advanced queries bukan compliance evaluation mechanism; mereka snapshot current state tanpa tracking history atau compliance status.
  • Single Lambda handling multiple resource types melanggar single responsibility principle dan sulit di-maintain.
  • Tiga custom rules menambah maintenance burden untuk checks yang sudah ada sebagai managed rules.
