Domain 3: Operations & Support — Task 3.1: Automate data processing

Skill 3.1.1: Orchestrate data pipelines

MWAAStepFunctionsorchestrate

Ringkasan

Skill ini termasuk dalam Domain 3: Operations & Support (Task 3.1: Automate data processing), dengan fokus pada orchestrate data pipelines. Materi berikut merangkum layanan AWS yang relevan beserta konsep penting yang perlu kamu kuasai untuk topik ini.

Layanan & Konsep Utama

Amazon MWAA
Managed Workflows for Apache Airflow; orkestrasi pipeline berbasis DAG.
AWS Step Functions
Orkestrasi alur kerja serverless (state machine) dengan retry, paralel, dan error handling.

Poin-Poin Kunci

  • Amazon MWAA adalah pilihan terbaik karena: (1) tim sudah berpengalaman dengan Apache Airflow, (2) Airflow memiliki sensors yang unggul untuk menunggu external events, (3) mendukung complex dependency management dengan DAG, dan (4) memiliki rich operator ecosystem untuk Glue, Redshift, dan service AWS lainnya.
  • AWS Step Functions Standard Workflow adalah pilihan paling cost-effective untuk pipeline yang jarang berjalan (10-20/hari) karena pricing per state transition (bukan per jam seperti MWAA). Standard workflow cocok karena steps bisa sampai 5 menit dan memerlukan exactly-once execution semantics.
  • Run a Job (.sync) integration pattern adalah cara paling sederhana dan efisien untuk menunggu long-running jobs. Dengan menambahkan .sync suffix ke resource ARN, Step Functions secara otomatis polls Glue job status dan melanjutkan ke step berikutnya setelah job selesai, gagal, atau timeout.
  • Step Functions Map state (Distributed mode untuk large-scale) dirancang tepat untuk parallel processing of multiple items dengan logic yang sama tapi parameter berbeda. MaxConcurrency parameter memungkinkan kontrol berapa feeds diproses bersamaan, membantu manage resource limits downstream.
  • Airflow memiliki built-in retry mechanism dengan parameter retries, retry_delay, dan retry_exponential_backoff. Setting retries=5 dengan exponential backoff memberikan 5 attempts dengan increasing delay antara retries, yang ideal untuk intermittent API failures. Ini adalah cara yang proper dan idiomatic di Airflow.
  • Pattern fan-in menggunakan dummy/empty task sebagai join point dengan trigger_rule='all_success' memastikan bahwa semua 3 extraction tasks harus berhasil sebelum pipeline melanjutkan ke Glue job. Ini adalah pattern standard Airflow untuk synchronization.
  • AWS Step Functions dengan cross-account IAM role assumption adalah pendekatan paling secure. Step Functions execution role di central account assumes roles di target accounts menggunakan STS AssumeRole, yang memberikan temporary credentials tanpa menyimpan long-lived secrets. Centralized state machine memberikan single-pane monitoring.
  • Step Functions Retry field dengan ErrorEquals memungkinkan retry selektif berdasarkan tipe error spesifik. Konfigurasi: Retry dengan ErrorEquals: ["Glue.ConcurrentRunsExceededException"], IntervalSeconds: 600, MaxAttempts: 3. Catch field kemudian menangkap semua error lain ("States.ALL") dan routes ke notification step. Ini adalah built-in pattern yang bersih dan deklaratif.
  • Satu DAG dengan schedule harian dan trigger external via EventBridge + MWAA REST API adalah pattern yang clean. max_active_runs=1 memastikan tidak ada concurrent execution. EventBridge rule pada S3 PutObject event memanggil MWAA CLI/API untuk trigger DAG run di luar schedule normal. catchup=False mencegah backfill runs.
  • Parallel state di Step Functions menjalankan multiple branches secara concurrent. Karena Glue (15 min) dan Redshift load (5 min) keduanya hanya bergantung pada output EMR, mereka bisa berjalan bersamaan. Total time: EMR 30 min + max(Glue 15 min, Redshift 5 min) = 45 min → sebenarnya 35 min (30+15 dengan Redshift selesai lebih awal di dalam parallel).

Miskonsepsi & Jebakan Umum

  • Terbatas pada Glue services saja.
  • Terlalu sederhana untuk pipeline kompleks dengan dependencies.
  • Bisa melakukan ini tapi kurang intuitif untuk complex dependencies dan external event waiting dibandingkan Airflow sensors.
  • Dibatasi 5 menit total execution time, yang terlalu ketat jika multiple steps masing-masing hampir 5 menit.
  • Memiliki operational overhead tinggi.
  • Memiliki minimum cost ~$350/bulan untuk environment yang running 24/7, sangat mahal untuk 10-20 executions/hari.
  • Memerlukan Glue job untuk send callback — Glue tidak natively support ini tanpa custom code.
  • Memerlukan workflow terpisah dan lebih kompleks.
  • Memerlukan extra states dan logic yang tidak perlu.
  • Lebih kompleks untuk di-manage dan monitor, serta memerlukan logic tambahan untuk aggregasi results.
  • Untuk routing bukan parallel processing.
  • Akan sangat lambat — 200 feeds secara sequential tidak akan meet 2-hour SLA.
  • Sangat fragile dan tidak scalable.
  • Terlalu aggressive — me-restart seluruh DAG hanya karena satu task gagal.
  • Tidak memanfaatkan Airflow's built-in retry/logging/monitoring.
  • Hanya untuk visual grouping, tidak otomatis membuat join-point dependency.
  • Digunakan untuk cross-DAG dependencies, bukan intra-DAG synchronization.
  • Sudah deprecated di Airflow modern dan menambah complexity.
  • Adalah untuk event routing bukan full workflow orchestration dengan sequencing.
  • Adalah anti-pattern keamanan.
  • Kurang secure karena menggunakan long-lived credentials.
  • Memerlukan logic tambahan yang tidak perlu.
  • Tidak menyelesaikan masalah error handling.
  • Menambah operational overhead dan kehilangan Step Functions' native error handling visibility.
  • Tidak mencegah concurrent execution antar kedua DAG.
  • Sangat wasteful dan tidak event-driven.
  • Bisa bekerja tapi menambah extra Lambda layer yang tidak perlu.
  • Tidak membuat jobs berjalan lebih cepat — hanya berbeda pricing model.
  • Untuk processing multiple items dengan logic sama, bukan dua task berbeda.
  • Kehilangan centralized monitoring dan error handling.
