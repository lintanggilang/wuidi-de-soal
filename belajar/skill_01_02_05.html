Summary

Skill this including in Domain 1: Ingestion & Transformation (Task 1.2: Transform and process data), with fokus on implement transformation services. Materi berikut merangkum service AWS that relevan beserta concept important that needs kamu kuasai for topik this.

Key Services & Concepts

AWS Glue
ETL serverless based on Spark + Data Catalog; ideal for transformation and katalogisasi data.
Amazon EMR
Cluster big data managed (Spark, Hive, Presto); supports Spot Instances for hemat cost.
AWS Lambda
Komputasi serverless event-driven; limit timeout 15 minutes and memory up to 10 GB.
Amazon Redshift
Data warehouse scale petabyte; supports COPY/UNLOAD, materialized view, and streaming ingestion.
Redshift Streaming Ingestion
Konsumsi directly from Kinesis/MSK to materialized view Redshift, latensi seconds, without staging S3.
AWS Lake Formation
Tata kelola data lake: permission based on table/kolom/baris and LF-Tags in atas Glue Catalog.

Key Points

  • AWS Glue Studio provides visual drag-and-drop ETL editor that not requires coding. Transform nodes for dedup, mapping, and aggregation available out-of-the-box. 50 GB appropriate with Glue serverless capabilities. Team without Spark experience can productive in days.
  • EMR provides full control atas environment through bootstrap actions that can install any system-level packages (GDAL, PROJ, C++ libraries). Spark jobs can calls native libraries. 10 TB processing requires distributed computing that EMR Spark sediakan.
  • Lambda is choice most cost-effective for simple per-record transformations in volume moderat (1K records/sec). Pay-per-invocation model berarti Anda only membayar saat records is processed. Transformasi stateless simple (parse, add field, mask) ideal for Lambda.
  • Amazon Redshift uses PostgreSQL-compatible SQL. Existing SQL transformations can dimigrasikan with changes minimal (AWS SCT membantu konversi syntax). Stored procedures, scheduled queries, and materialized views available. Ini provides migration path most easy for SQL-heavy workloads.
  • Apache Flink excels at complex event processing: windowed aggregations (tumbling, sliding, session windows), pattern detection (FlinkCEP library), and stateful processing with exactly-once guarantees. 100K events/sec is well within Flink's throughput capabilities.
  • AWS Glue is fully serverless — no servers, no cluster management, no capacity planning. Auto Scaling handles resources. Built-in scheduler (triggers) handles scheduling. For simple transforms (flatten, rename, filter), Glue DynamicFrames provides native transforms. 5 GB per batch is ideal for Glue.
  • Redshift stored procedures mengelompokkan SQL transformation logic, and scheduled queries (or EventBridge) menjalankannya on jadwal. Ini solution most native for ELT in Redshift — logic and execution in satu system. SCD Type 2, running totals, and denormalization semuanya can diimplementasikan in SQL.
  • Amazon Data Firehose has built-in data transformation feature that calls Lambda function for memodifikasi records before delivery to destination. Not needs infrastructure additional — only configuration transformation Lambda on Firehose stream that already ada.
  • AWS Glue DataBrew is purpose-built for visual data preparation. Provides 250+ built-in transformations (fix data types, handle nulls, remove outliers, standardize formats) in interface visual that interaktif. Analysts can profile data and apply cleaning recipes without code.
  • EMR provides full control atas: Spark version selection, custom spark-defaults.conf, YARN resource manager configuration, instance types, and library versions. For team with deep Spark expertise that requires fine-grained tuning, EMR provides flexibility that not available in Glue.
