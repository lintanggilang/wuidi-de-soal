Skill 4.1.5: IAM policies (Access Points, PrivateLink)

IAMpoliciesAccessPointsPrivateLink

Summary

Skill this including in Domain 4: Security & Governance (Task 4.1: Apply authentication mechanisms), with fokus on iam policies (access points, privatelink). Materi berikut merangkum service AWS that relevan beserta concept important that needs kamu kuasai for topik this.

Key Services & Concepts

AWS IAM
Identity and Access Management: user, group, role, and policy for access least-privilege.
AWS PrivateLink
Akses private to service via interface endpoint without melewati internet public.
S3 Access Points
Endpoint bernama with policy itself for menyederhanakan access to bucket large bersama.

Key Points

  • S3 Access Points designed khusus for menyederhanakan access management on shared buckets. Each Access Point has hostname unik and access point policy tersendiri that can limits access to prefix certain. Tim Analytics accesses through access-point-analytics, ML through access-point-ml, dll. Ini menggantikan satu bucket policy that kompleks with multiple simple policies.
  • VPC endpoint policies control API calls that diperbolehkan through endpoint the said. By limits resource to ARN dua bucket specific (arn:aws:s3:::data-lake-bucket and arn:aws:s3:::data-lake-bucket/*), all request S3 through endpoint this only can accesses kedua bucket the said. Ini provides defense-in-depth additional.
  • Bucket policy with explicit Deny uses condition "aws:SourceVpc" ensures that SEMUA requests that not berasal from VPC that is determined will ditolak, terlepas from IAM permissions that ada. Statement: {"Effect": "Deny", "Principal": "*", "Action": "s3:*", "Resource": ["bucket-arn", "bucket-arn/*"], "Condition": {"StringNotEquals": {"aws:SourceVpc": "vpc-12345"}}}. Explicit Deny always override Allow.
  • AWS PrivateLink uses Interface Endpoints (powered by ENIs) in consumer VPC that connected to provider's VPC Endpoint Service (backed by NLB). Engineer needs: (1) Create Interface Endpoint in VPC-A with service name that is provided provider (com.amazonaws.vpce.region.vpce-svc-xxxxx). (2) Accept the connection (provider may needs approve). (3) Configure security group on endpoint ENI for allow traffic from data processing service. Data mengalir through AWS private network.
  • aws:PrincipalOrgID is global condition key that memeriksa whether calling principal berasal from AWS Organization certain. By adds Allow statement bersyarat on aws:PrincipalOrgID, only principals from accounts that merupakan member organization o-abc123def that mendapat access. Ini very useful for shared resources — saat account new is added to organization, mereka automatic mendapat access without needing mengupdate bucket policy.
  • VPC endpoint policies berfungsi sebagai additional access control layer (filter). Request must is allowed by SEMUA policies that relevan: IAM policy, resource policy (bucket policy), DAN VPC endpoint policy. If VPC endpoint policy not allows access to bucket the said, request will ditolak although IAM and bucket policy allows. VPC endpoint policy bersifat intersectional — request only succeeds if is allowed by all layer.
  • For provides cross-account access to specific role, gunakan role ARN sebagai Principal. Ini provides access only to DataProcessorRole in Account B, not all entities in account the said. Ini is approach most restrictive and mengikuti least privilege.
  • S3 Block Public Access in account level is preventive control most kuat. Saat diaktifkan, this automatically memblokir all configuration public access on SEMUA buckets in account — including public bucket policies, public ACLs, and new public bucket/access point policies. Bahkan if developer adds bucket policy with Principal "*", Block Public Access will override and still memblokir public access.
  • S3 Access Points not override bucket policies. Access dikontrol by INTERSECTION from Access Point policy and bucket policy (plus IAM policy). Explicit Deny in bucket policy always menang — this is prinsip fundamental IAM policy evaluation. Access Points dimaksudkan for menyederhanakan policy management, not for bypass existing restrictions. If bucket policy explicitly deny access from role certain, Access Point cannot provides access the said.
  • Defense-in-depth requires multiple layers of control: (1) IAM policy — controls what the Lambda role can do (only specific buckets). (2) VPC endpoint policy — controls what can be accessed through the endpoint (only same specific buckets). Bahkan if attacker mendapat credentials different, endpoint only allows traffic to designated buckets. (3) S3 bucket policy with aws:SourceVpce — ensures bucket only accessible from VPC endpoint certain, prevents access from location other. Ketiga layer bersama-same creates exfiltration very difficult.

Common Misconceptions & Pitfalls

  • Adds cost storage and complexity sinkronisasi shared data.
  • Not enables resource-based control and difficult manages for many team.
  • Only mengontrol from sisi identity, not provides resource-level simplification that same.
  • Can jadi defense-in-depth additional but not limits endpoint that itself — resources in VPC still can mencoba access bucket other.
  • Salah — Gateway endpoints not has security groups (only Interface endpoints that punya).
  • Salah — S3 Gateway endpoint uses prefix list in route table, not per-bucket IP routing.
  • Not scalable and not prevents policies is added returns.
  • Not concept that valid — S3 not "target" endpoint.
  • Only memblokir public access via ACLs/policies, not access from other VPCs or AWS accounts.
  • Berlebihan for single service connection.
  • Uses internet and slower.
  • Requires kooperasi provider and membuka access more luas.
  • Uses format ARN that incorrect for org condition.
  • Only memeriksa satu account, not entire organization.
  • Salah — aws:SourceAccount only available for service-to-service calls, not directly applicable for org ID.
  • Salah — endpoint policy also must allow.
  • Salah — endpoint policies bersifat enforcing, not advisory.
  • Salah — if traffic diroute through endpoint (via route table), there is no fallback to internet path; request will fail.
  • Mengizinkan ALL Lambda functions from all accounts — very not secure.
  • Provides access to SEMUA principals in Account B that has IAM permission — less restrictive.
  • By SourceAccount condition still too broad — allows all principals in Account B, and aws:SourceAccount condition not always available for direct API calls.
  • Adalah detective control (deteksi + remediate) — ada window where bucket already public before remediation.
  • Requires penerapan in each bucket and can is deleted by developer.
  • Only detection and alerting, not prevention.
  • Salah — Access Points not override.
  • Salah — Access Point still valid, only permissions that limited.
  • Salah if Deny is applied on all S3 actions (depends what that in-deny in bucket policy).
  • Kurang IAM restriction and NACLs cannot distinguish between S3 buckets.
  • Single layer, if credentials compromised, can is used from mana saja.
  • Lambda private IPs bersifat dynamic and changes each invocation.
