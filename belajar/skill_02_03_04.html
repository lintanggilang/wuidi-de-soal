Skill 2.3.4: S3 versioning and DynamoDB TTL

versioningDynamoDBTTL

Summary

Skill this including in Domain 2: Data Store Management (Task 2.3: Manage the lifecycle of data), with fokus on s3 versioning and dynamodb ttl. Materi berikut merangkum service AWS that relevan along with concept important that needs kamu kuasai for topik this.

Key Services & Concepts

Amazon S3
Object storage tahan old; dasar data lake, supports event notification, versioning, and lifecycle.
Amazon DynamoDB
Database NoSQL key-value low latency; horizontal scaling, supports TTL and Streams.
DynamoDB TTL
Deletes item automatic after timestamp kedaluwarsa without cost additional.

Key Points

  • Lifecycle rule for deletes noncurrent versions after 30 days enables recovery file that tertimpa in time 30 days sambil automatically membersihkan versi old for controls cost.
  • DynamoDB TTL membandingkan value atribut TTL (Unix epoch timestamp) with time when this. Item is deleted when current time > TTL value. Not there is "offset" that can is configured — atribut TTL must contains time ekspirasi absolut. By because that, atribut separate "expirationTime" that contains lastActivity + 86400 (24 hours in seconds) is implementation that correct.
  • MFA Delete requires autentikasi multi-faktor for deletes versi object in a permanent or changes status versioning bucket. This prevents deletion permanent without MFA, even by root account.
  • For retrieves versi specific, gunakan ListObjectVersions API or S3 console for melihat all versi object along with version ID-nya, then gunakan GetObject with parameter versionId for mengunduh versi that diinginkan.
  • DynamoDB Streams captures TTL deletions as event REMOVE with userIdentity.type = "Service" and userIdentity.principalId = "dynamodb.amazonaws.com". Lambda consumer can filters event this and writes data to S3 for archival. This fully event-driven and minimal overhead.
  • When versioning in-suspend, object new that diupload mendapat null version ID. If already there is object with null version ID, object said ditimpa. Versi-versi previously that has version ID non-null still dipertahankan.
  • S3 Lifecycle rules supports NoncurrentVersionExpiration with parameter NewerNoncurrentVersions that enables stores sejumlah N versi noncurrent terbaru and deletes that more old. This is solution native S3 that most efficient.
  • DynamoDB TTL not guarantees deletion instan — item usually is deleted in time 48 hours after expiration (generally in several hours). This by design and cannot dipercepat. Solution that correct is adds filter expression in query application for excludes item that already expired (TTL < current_time).
  • For deletes versi object in a permanent in bucket with versioning enabled, Anda must sends DeleteObject request with version ID specific. Without version ID, S3 only creates delete marker.
  • DynamoDB TTL deletions sepenuhnya gratis — not consumes write capacity units and not dikenakan cost. This menjadikan TTL way that most cost-effective for deletes data that already expired automatically.
