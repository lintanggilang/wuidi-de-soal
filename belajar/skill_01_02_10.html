Skill 1.2.10: Integrate LLMs for data processing

LLMBedrockAIML

Ringkasan

Skill ini termasuk dalam Domain 1: Ingestion & Transformation (Task 1.2: Transform and process data), dengan fokus pada integrate llms for data processing. Materi berikut merangkum layanan AWS yang relevan beserta konsep penting yang perlu kamu kuasai untuk topik ini.

Layanan & Konsep Utama

Amazon Bedrock
Akses model fondasi (LLM) terkelola untuk embedding dan generative AI.

Poin-Poin Kunci

  • Amazon Bedrock Batch Inference memproses large volumes of prompts secara batch dengan pricing discount (hingga 50% lebih murah dari real-time). Prompt template memastikan consistent extraction format. Batch job memproses 1M records tanpa managing individual API calls.
  • Amazon Comprehend is purpose-built untuk text classification dan sentiment analysis — lebih cost-effective dan faster than LLMs untuk standard NLP tasks. Custom classification models bisa di-train di Comprehend. Sentiment analysis built-in. Untuk simple classification + sentiment, Comprehend memberikan better cost/performance ratio dibanding Bedrock LLMs.
  • Bedrock Titan Embeddings model melalui Batch Inference API memproses millions of texts secara efisien tanpa managing infrastructure. Batch mode memberikan throughput tinggi dan pricing discount. Output embeddings di-bulk load ke Aurora pgvector.
  • Map-reduce summarization pattern: (1) Split document into chunks that fit context window, (2) "Map" — summarize each chunk independently, (3) "Reduce" — combine chunk summaries into final summary with another LLM call. This preserves information from the entire document. Overlapping chunks prevent losing context at boundaries.
  • SQS decouples ingestion from processing, allowing controlled consumption rate. Lambda consumers implement exponential backoff when Bedrock returns ThrottlingException. If max retries exceeded, message goes to DLQ for later processing — no data loss. This pattern respects rate limits while ensuring eventual processing of all records.
  • Best practices for structured LLM output: (1) Explicit JSON schema in system prompt, (2) Few-shot examples showing input→output format, (3) Post-processing validation to catch malformed responses. LLMs are NOT deterministic — same input can produce different formats. Validation catches edge cases and triggers retries.
  • mapPartitions allows processing a batch of records per partition with explicit concurrency control. Within each partition, concurrent.futures.ThreadPoolExecutor makes parallel API calls. Semaphore controls max concurrent calls to respect Bedrock rate limits. With 50 executors × 10 concurrent calls = 500 parallel calls, completing in ~5 minutes.
  • Amazon Bedrock Guardrails menyediakan PII filtering built-in yang mendeteksi dan secara otomatis meredact PII (SSN, credit cards, emails, dll) sebelum input reaches the model. Ini managed solution tanpa custom code.
  • In-context learning (providing schema in the prompt) is the most practical approach. Glue Data Catalog contains table metadata (columns, types, descriptions) yang bisa di-dynamically retrieved dan included in the system prompt. LLM uses this context to generate accurate SQL. RAG pattern bisa memilih relevant tables.
  • Multi-layered validation is essential for production data pipelines using LLMs: (1) Cross-reference outputs against authoritative sources, (2) Confidence scoring (LLM can output confidence), (3) Human-in-the-loop for uncertain cases. No model eliminates hallucinations entirely.

Miskonsepsi & Jebakan Umum

  • Membutuhkan labeled training data dan expertise.
  • Sangat mahal per-invocation dan slow, plus rate limiting.
  • Tidak bisa handle unstructured natural language reliably.
  • Sangat mahal untuk simple classification.
  • Bekerja tapi lebih mahal per-request.
  • 5M API calls secara real-time sangat lambat dan mahal.
  • Comprehend tidak menghasilkan general-purpose embeddings untuk semantic search.
  • Valid tapi membutuhkan model deployment dan management.
  • Kehilangan most of paper content.
  • 15 min timeout insufficient for many records.
  • Akan hit ThrottlingException dan potentially lose data.
  • Fine-tuning expensive for simple formatting task.
  • Raw LLM text may contain extra text or formatting issues.
  • LLMs are probabilistic, not deterministic; outputs can vary.
  • Defeats distributed processing.
  • Wastes compute resources if bottleneck is API latency not CPU.
  • Each map call is sequential within each task.
  • Meskipun Bedrock doesn't train on data, sending PII still violates compliance requirements.
  • Encrypted text tidak bisa diproses oleh LLM.
  • Terlalu agresif — removes legitimate numbers (quantities, dates).
  • Database content changes frequently, fine-tuning is static.
  • Security risk dan LLMs can't reliably query databases.
  • Reduces randomness but doesn't eliminate hallucinations — model can still generate incorrect information confidently.
  • No model is hallucination-free.
  • Same hallucination often occurs consistently.
