Skill 4.5.5: Maintain data sovereignty

Key Services & Concepts

Lihat poin-poin key in bawah.

Key Points

  • Approach that correct is separates personal data (must still in ap-southeast-1) from operational metrics (can in-share globally setelah anonymized/aggregated). SCPs ensures personal data cannot in-replicate or in-copy to region other in a technical. DevOps team can melihat aggregated metrics (CPU usage, error rates, throughput) without exposure personal data.
  • KMS keys bersifat REGIONAL — key that is created in us-east-1 only can is used in us-east-1. If data in sa-east-1 (São Paulo) is encrypted with key in us-east-1, each decrypt operation requires cross-region call to us-east-1. Ini menciptakan: (1) dependency jurisdiksi asing — if US government issues order related key in us-east-1, this can affects access to data Brasil, (2) availability risk — if connection to us-east-1 terputus, data in sa-east-1 cannot didekripsi. For sovereignty, key HARUS berada in region that same with data.
  • AWS global services (IAM, Route 53, dll) processes control plane metadata — not customer data content (actual customer records, PII). AWS provides Data Processing Addendum (DPA), Standard Contractual Clauses (SCCs), and compliance certifications that mencakup global services. GDPR Article 28 mensyaratkan data processing agreement that AWS already sediakan. Architect must: (1) ensures actual data (S3, RDS, etc) in EU regions, (2) document that global services only processes metadata, (3) ensure DPA signed with AWS.
  • For maximum data sovereignty where even cloud provider access must is limited: AWS Outposts provides AWS infrastructure in customer's own data center — data physically stays on-premises in jurisdiksi India. CloudHSM provides dedicated HSMs where customer has full control atas keys (AWS cannot access HSM keys). SCPs ensures there is no accidental deployment to cloud regions. Ini is level tertinggi sovereignty that AWS tawarkan.
  • Architecture that correct separates concerns: (1) Raw PII data stays localized in region that appropriate regulasi each — EU citizen data in eu-central-1, Brazilian in sa-east-1, Japanese in ap-northeast-1. (2) For global analytics, data in-anonymized/aggregated in local region first (eliminates PII), then aggregated data in-replicate to central analytics layer. Anonymized data not personal data so that can in-share globally.
  • VPC Interface Endpoints (PrivateLink) creates private connectivity between VPC and AWS services without traffic meninggalkan AWS network. Endpoint still in region the said. VPC endpoint policies can limits access: for example, S3 endpoint policy can restrict to only bucket ARNs in region that same, prevents EC2/Lambda from accesses S3 in region other. Ini ensures data plane traffic for AWS service calls stays within-region.
  • S3 Transfer Acceleration uses CloudFront edge locations sebagai network optimization points — data TRANSIT through edge locations but TIDAK is stored disana. Data is encrypted with TLS during transit and final destination (storage) still in bucket that berada in region that is determined. Kebanyakan data sovereignty frameworks (including GDPR) membedakan between data-at-rest location and encrypted in-transit routing. Namun, for organisasi with interpretasi sovereignty that very strict, mereka may memilih disable Transfer Acceleration. Assessment must is performed with legal counsel.
  • SCP with region restriction is organizational-level control that cannot in-bypass by any user including account administrators. Deny ALL actions (uses NotAction for exempt global services) when aws:RequestedRegion not ap-southeast-2 ensures there is no resource that can is created in region other — including via CloudFormation, console, CLI, or SDK. Ini is preventive control tertinggi in AWS Organizations.
  • me-south-1 (Bahrain) and me-central-1 (UAE) keduanya berada in GCC countries that memenuhi Middle East sovereignty requirements. Uses CRR to me-central-1 provides geographic DR without melanggar sovereignty. RDS read replicas in me-central-1 provides database DR. SCPs that only allow kedua regions this ensures there is no accidental deployment to region other.
  • AWS Organizations OU structure enables different policies in different levels. By creates OUs per BU sovereignty requirement: EU-OU mendapat SCP that restrict to eu-central-1, eu-west-1, dll; APAC-OU mendapat SCP restricting to ap-southeast-1; US-OU does not need region restriction. Accounts in-place in OU appropriate sovereignty requirement mereka. SCPs in OU level inherited by all accounts in bawahnya. Ini is pattern that direkomendasikan Control Tower for varying governance requirements.

Common Misconceptions & Pitfalls

  • PDPA not allows transfer personal data only because "business purpose"; adequate protection level in destination is required.
  • Encrypted data still dianggap personal data in bawah kebanyakan data protection laws including PDPA; encryption not exemption from sovereignty requirements.
  • Outposts too extreme and eliminates benefit cloud services; PDPA not mewajibkan on-premises.
  • Salah — KMS keys not auto-replicate (multi-Region keys ada but must explicitly configured).
  • Selain performance, sovereignty and jurisdictional control is concern main.
  • Salah — KMS keys not global.
  • GovCloud for US government workloads, not EU data sovereignty.
  • Menghindari IAM/Route53 not practical because all AWS deployments requires mereka.
  • Local Zones still uses global services; not solves concern.
  • Dedicated Hosts provides physical isolation from tenants other but data still in AWS facility.
  • Standard KMS keys in cloud regions still technically accessible by AWS (although heavily audited and restricted).
  • Nitro and CloudHSM in cloud region provides strong control but data still in AWS data center.
  • Centralized lake melanggar data localization all tiga regulasi.
  • Full cross-region replication menduplikasi PII data to region other, melanggar localization requirements.
  • Encryption not exempts from sovereignty; data still physically outside required jurisdiction.
  • Direct Connect provides private connection to AWS but not inherently restrict to single region; traffic can route to multiple regions via Direct Connect.
  • Security groups works in IP level; AWS regional IP ranges overlap and changes — this fragile and difficult in-maintain.
  • NAT Gateway sends traffic to internet then to AWS public endpoints; traffic technically exits VPC to internet.
  • "same continent" not standard sovereignty measure.
  • Transfer Acceleration TIDAK stores data in edge locations.
  • Terlalu absolute; most frameworks allow encrypted transit.
  • Anda only can opt-in/opt-out regions that not default; ap-southeast-2 and most standard regions are default and cannot be disabled.
  • IAM permission boundaries can in-override by admin that creates new policies without boundary; also requires enforcement per-account.
  • StackSet target restriction only prevents StackSet-deployed resources; not prevents direct resource creation via other means (console, CLI).
  • Us-east-1 jelas in luar Middle East and melanggar sovereignty; "sovereignty-tagged keys" not concept that ada in AWS.
  • Multi-AZ in single region protects from AZ failure but not from region-level disaster; this unnecessarily risky when me-central-1 available.
  • Eu-south-1 (Italy/Milan) in luar Middle East/GCC; although in a geografi relatively dekat, not memenuhi GCC sovereignty requirement.
  • SCPs not supports resource tag-based conditions for region restriction; SCP conditions limited on global condition keys.
  • IAM policies can in-override by admin; SCPs cannot.
  • Union of all regions (EU+SG+US) means EU accounts can create resources in Singapore, violating EU sovereignty.
