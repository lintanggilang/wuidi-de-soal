Domain 4: Security & Governance — Task 4.5: Understand data privacy and governance

Skill 4.5.5: Maintain data sovereignty

datasovereigntyGDPR

Ringkasan

Skill ini termasuk dalam Domain 4: Security & Governance (Task 4.5: Understand data privacy and governance), dengan fokus pada maintain data sovereignty. Materi berikut merangkum layanan AWS yang relevan beserta konsep penting yang perlu kamu kuasai untuk topik ini.

Layanan & Konsep Utama

Lihat poin-poin kunci di bawah.

Poin-Poin Kunci

  • Pendekatan yang benar adalah memisahkan personal data (harus tetap di ap-southeast-1) dari operational metrics (bisa di-share globally setelah anonymized/aggregated). SCPs memastikan personal data tidak bisa di-replicate atau di-copy ke region lain secara teknis. DevOps team bisa melihat aggregated metrics (CPU usage, error rates, throughput) tanpa exposure personal data.
  • KMS keys bersifat REGIONAL — key yang dibuat di us-east-1 hanya bisa digunakan di us-east-1. Jika data di sa-east-1 (São Paulo) dienkripsi dengan key di us-east-1, setiap decrypt operation memerlukan cross-region call ke us-east-1. Ini menciptakan: (1) dependency jurisdiksi asing — jika US government issues order terkait key di us-east-1, ini bisa mempengaruhi akses ke data Brasil, (2) availability risk — jika koneksi ke us-east-1 terputus, data di sa-east-1 tidak bisa didekripsi. Untuk sovereignty, key HARUS berada di region yang sama dengan data.
  • AWS global services (IAM, Route 53, dll) memproses control plane metadata — bukan customer data content (actual customer records, PII). AWS menyediakan Data Processing Addendum (DPA), Standard Contractual Clauses (SCCs), dan compliance certifications yang mencakup global services. GDPR Article 28 mensyaratkan data processing agreement yang AWS sudah sediakan. Architect harus: (1) memastikan actual data (S3, RDS, etc) di EU regions, (2) document bahwa global services hanya memproses metadata, (3) ensure DPA signed with AWS.
  • Untuk maximum data sovereignty dimana bahkan cloud provider access harus dibatasi: AWS Outposts memberikan AWS infrastructure di customer's own data center — data physically stays on-premises dalam jurisdiksi India. CloudHSM memberikan dedicated HSMs dimana customer memiliki full control atas keys (AWS tidak bisa access HSM keys). SCPs memastikan tidak ada accidental deployment ke cloud regions. Ini adalah level tertinggi sovereignty yang AWS tawarkan.
  • Architecture yang benar memisahkan concerns: (1) Raw PII data stays localized di region yang sesuai regulasi masing-masing — EU citizen data di eu-central-1, Brazilian di sa-east-1, Japanese di ap-northeast-1. (2) Untuk global analytics, data di-anonymized/aggregated di local region terlebih dahulu (menghilangkan PII), kemudian aggregated data di-replicate ke central analytics layer. Anonymized data bukan personal data sehingga bisa di-share globally.
  • VPC Interface Endpoints (PrivateLink) membuat private connectivity antara VPC dan AWS services tanpa traffic meninggalkan AWS network. Endpoint tetap di region tersebut. VPC endpoint policies bisa membatasi akses: misalnya, S3 endpoint policy bisa restrict ke hanya bucket ARNs di region yang sama, mencegah EC2/Lambda dari mengakses S3 di region lain. Ini memastikan data plane traffic untuk AWS service calls stays within-region.
  • S3 Transfer Acceleration menggunakan CloudFront edge locations sebagai network optimization points — data TRANSIT melalui edge locations tetapi TIDAK disimpan disana. Data dienkripsi dengan TLS selama transit dan final destination (storage) tetap di bucket yang berada di region yang ditentukan. Kebanyakan data sovereignty frameworks (termasuk GDPR) membedakan antara data-at-rest location dan encrypted in-transit routing. Namun, untuk organisasi dengan interpretasi sovereignty yang sangat strict, mereka mungkin memilih disable Transfer Acceleration. Assessment harus dilakukan dengan legal counsel.
  • SCP dengan region restriction adalah organizational-level control yang tidak bisa di-bypass oleh any user termasuk account administrators. Deny ALL actions (menggunakan NotAction untuk exempt global services) ketika aws:RequestedRegion bukan ap-southeast-2 memastikan tidak ada resource yang bisa dibuat di region lain — termasuk via CloudFormation, console, CLI, atau SDK. Ini adalah preventive control tertinggi di AWS Organizations.
  • me-south-1 (Bahrain) dan me-central-1 (UAE) keduanya berada di GCC countries yang memenuhi Middle East sovereignty requirements. Menggunakan CRR ke me-central-1 memberikan geographic DR tanpa melanggar sovereignty. RDS read replicas di me-central-1 memberikan database DR. SCPs yang hanya allow kedua regions ini memastikan tidak ada accidental deployment ke region lain.
  • AWS Organizations OU structure memungkinkan different policies di different levels. Dengan membuat OUs per BU sovereignty requirement: EU-OU mendapat SCP yang restrict ke eu-central-1, eu-west-1, dll; APAC-OU mendapat SCP restricting ke ap-southeast-1; US-OU tidak perlu region restriction. Accounts di-place di OU sesuai sovereignty requirement mereka. SCPs di OU level inherited oleh semua accounts di bawahnya. Ini adalah pattern yang direkomendasikan Control Tower untuk varying governance requirements.

Miskonsepsi & Jebakan Umum

  • PDPA tidak mengizinkan transfer personal data hanya karena "business purpose"; adequate protection level di destination diperlukan.
  • Encrypted data masih dianggap personal data di bawah kebanyakan data protection laws termasuk PDPA; encryption bukan exemption dari sovereignty requirements.
  • Outposts terlalu extreme dan menghilangkan benefit cloud services; PDPA tidak mewajibkan on-premises.
  • Salah — KMS keys tidak auto-replicate (multi-Region keys ada tapi harus explicitly configured).
  • Selain performance, sovereignty dan jurisdictional control adalah concern utama.
  • Salah — KMS keys tidak global.
  • GovCloud untuk US government workloads, bukan EU data sovereignty.
  • Menghindari IAM/Route53 tidak practical karena semua AWS deployments memerlukan mereka.
  • Local Zones tetap menggunakan global services; tidak menyelesaikan concern.
  • Dedicated Hosts memberikan physical isolation dari tenants lain tapi data tetap di AWS facility.
  • Standard KMS keys di cloud regions masih technically accessible oleh AWS (meskipun heavily audited dan restricted).
  • Nitro dan CloudHSM di cloud region memberikan strong control tapi data masih di AWS data center.
  • Centralized lake melanggar data localization semua tiga regulasi.
  • Full cross-region replication menduplikasi PII data ke region lain, melanggar localization requirements.
  • Encryption tidak exempts dari sovereignty; data masih physically outside required jurisdiction.
  • Direct Connect memberikan private connection ke AWS tapi tidak inherently restrict ke single region; traffic bisa route ke multiple regions via Direct Connect.
  • Security groups bekerja di IP level; AWS regional IP ranges overlap dan berubah — ini fragile dan sulit di-maintain.
  • NAT Gateway mengirim traffic ke internet kemudian ke AWS public endpoints; traffic technically keluar VPC ke internet.
  • "same continent" bukan standard sovereignty measure.
  • Transfer Acceleration TIDAK menyimpan data di edge locations.
  • Terlalu absolute; most frameworks allow encrypted transit.
  • Anda hanya bisa opt-in/opt-out regions yang bukan default; ap-southeast-2 dan most standard regions are default dan cannot be disabled.
  • IAM permission boundaries bisa di-override oleh admin yang creates new policies tanpa boundary; juga memerlukan enforcement per-account.
  • StackSet target restriction hanya mencegah StackSet-deployed resources; tidak mencegah direct resource creation via other means (console, CLI).
  • Us-east-1 jelas di luar Middle East dan melanggar sovereignty; "sovereignty-tagged keys" bukan konsep yang ada di AWS.
  • Multi-AZ di single region protects dari AZ failure tapi tidak dari region-level disaster; ini unnecessarily risky ketika me-central-1 tersedia.
  • Eu-south-1 (Italy/Milan) di luar Middle East/GCC; meskipun secara geografi relatively dekat, tidak memenuhi GCC sovereignty requirement.
  • SCPs tidak mendukung resource tag-based conditions untuk region restriction; SCP conditions terbatas pada global condition keys.
  • IAM policies bisa di-override oleh admin; SCPs tidak bisa.
  • Union of all regions (EU+SG+US) means EU accounts bisa create resources di Singapore, violating EU sovereignty.
