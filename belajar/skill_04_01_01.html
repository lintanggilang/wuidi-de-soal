Summary

Skill this including in Domain 4: Security & Governance (Task 4.1: Apply authentication mechanisms), with fokus on update vpc security groups. Materi berikut merangkum service AWS that relevan beserta concept important that needs kamu kuasai for topik this.

Key Services & Concepts

Amazon VPC
Jaringan terisolasi; security group & endpoint mengontrol konektivitas source daya.

Key Points

  • AWS Glue requires self-referencing inbound rule on security group that is used by Glue connection. Ini is required because Glue ENIs (Elastic Network Interfaces) needs communicates satu same other for koordinasi task in cluster. Without self-referencing rule this, Glue executors cannot communicates and job will timeout.
  • Konfigurasi most secure is provides access only on port that is required (5439 for Redshift) from source that specific: CIDR corporate network for analysts and security group ID for Glue. Security group referencing (SG-to-SG) more secure daripada CIDR because only resource that connected to security group the said that is allowed.
  • VPC Gateway Endpoint for S3 enables access to S3 through AWS private network without internet gateway or NAT gateway. Gateway endpoint not requires changes security group because traffic in-route through route table. Ini gratis and provides access private to S3.
  • Best practice for EMR is: (1) Separate security groups for master and core/task nodes with port-port specific that is required for inter-node communication (for example port 8443 for cluster management). (2) VPC Gateway Endpoints for S3 and DynamoDB (gratis, traffic still in AWS network). (3) NAT gateway for access to external API that requires internet.
  • Masalah most umum saat Glue connection fails is not adanya self-referencing inbound rule on security group Glue. AWS Glue requires ENI-nya for communicates satu same other (inter-node communication), that requires inbound rule from security group that itself (self-referencing). Ini is persyaratan specific Glue that often terlewat.
  • AWS Managed Prefix Lists enables pengelompokan several CIDR blocks to in satu objek that can direferensikan in satu security group rule. Ini in a effective reduces number rules that is required. Satu rule with prefix list can mencakup many CIDR ranges.
  • Perubahan security group rule in AWS take effect immediately without restart, reboot, or downtime. Ini applies for penambahan maupun deletion rules, and affects all connection (existing and new). Security groups bersifat stateful — if rule is deleted, connection that already terestablish also will terputus because return traffic not lagi is allowed.
  • Tiga security groups separate provides isolasi that is required: Aurora SG allows port 3306 from Lambda SG and Glue SG in a separate. Lambda SG and Glue SG not has rules that mereferensikan satu same other, so that cannot communicates directly.
  • In a default, security groups allows all outbound traffic. Namun, if engineer uses custom security group and memodifikasi outbound rules (for example only allows port certain), connection outbound to port 3306 can diblok. VPC flow logs mengkonfirmasi that traffic outbound that ditolak — this menunjukkan problem on outbound rules in security group EMR or NACL. Because soal menyebutkan "outbound traffic from EMR is being rejected" and security group has custom rules, possibility large outbound rule EMR SG that restrictive.
  • Creates common "data-access" security group and menambahkannya sebagai additional SG to each service is approach most maintainable. Redshift SG only requires satu inbound rule (port 5439 from data-access SG). When service new is added, quite attach data-access SG to service the said without memodifikasi Redshift SG.
