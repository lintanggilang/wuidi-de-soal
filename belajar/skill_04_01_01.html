Domain 4: Security & Governance — Task 4.1: Apply authentication mechanisms

Skill 4.1.1: Update VPC security groups

VPCsecuritygroups

Ringkasan

Skill ini termasuk dalam Domain 4: Security & Governance (Task 4.1: Apply authentication mechanisms), dengan fokus pada update vpc security groups. Materi berikut merangkum layanan AWS yang relevan beserta konsep penting yang perlu kamu kuasai untuk topik ini.

Layanan & Konsep Utama

Amazon VPC
Jaringan terisolasi; security group & endpoint mengontrol konektivitas sumber daya.

Poin-Poin Kunci

  • AWS Glue memerlukan self-referencing inbound rule pada security group yang digunakan oleh Glue connection. Ini diperlukan karena Glue ENIs (Elastic Network Interfaces) perlu berkomunikasi satu sama lain untuk koordinasi tugas dalam cluster. Tanpa self-referencing rule ini, Glue executors tidak dapat berkomunikasi dan job akan timeout.
  • Konfigurasi paling aman adalah memberikan akses hanya pada port yang diperlukan (5439 untuk Redshift) dari sumber yang spesifik: CIDR corporate network untuk analysts dan security group ID untuk Glue. Security group referencing (SG-to-SG) lebih aman daripada CIDR karena hanya resource yang terhubung ke security group tersebut yang diizinkan.
  • VPC Gateway Endpoint untuk S3 memungkinkan akses ke S3 melalui AWS private network tanpa internet gateway atau NAT gateway. Gateway endpoint tidak memerlukan perubahan security group karena traffic di-route melalui route table. Ini gratis dan menyediakan akses private ke S3.
  • Best practice untuk EMR adalah: (1) Separate security groups untuk master dan core/task nodes dengan port-port spesifik yang diperlukan untuk inter-node communication (misalnya port 8443 untuk cluster management). (2) VPC Gateway Endpoints untuk S3 dan DynamoDB (gratis, traffic tetap di AWS network). (3) NAT gateway untuk akses ke external API yang memerlukan internet.
  • Masalah paling umum saat Glue connection gagal adalah tidak adanya self-referencing inbound rule pada security group Glue. AWS Glue membutuhkan ENI-nya untuk berkomunikasi satu sama lain (inter-node communication), yang memerlukan inbound rule dari security group itu sendiri (self-referencing). Ini adalah persyaratan spesifik Glue yang sering terlewat.
  • AWS Managed Prefix Lists memungkinkan pengelompokan beberapa CIDR blocks ke dalam satu objek yang bisa direferensikan dalam satu security group rule. Ini secara efektif mengurangi jumlah rules yang diperlukan. Satu rule dengan prefix list bisa mencakup banyak CIDR ranges.
  • Perubahan security group rule di AWS take effect immediately tanpa restart, reboot, atau downtime. Ini berlaku untuk penambahan maupun penghapusan rules, dan mempengaruhi semua koneksi (existing dan new). Security groups bersifat stateful — jika aturan dihapus, koneksi yang sudah terestablish juga akan terputus karena return traffic tidak lagi diizinkan.
  • Tiga security groups terpisah memberikan isolasi yang diperlukan: Aurora SG mengizinkan port 3306 dari Lambda SG dan Glue SG secara terpisah. Lambda SG dan Glue SG tidak memiliki rules yang mereferensikan satu sama lain, sehingga tidak bisa berkomunikasi langsung.
  • Secara default, security groups mengizinkan semua outbound traffic. Namun, jika engineer menggunakan custom security group dan memodifikasi outbound rules (misalnya hanya mengizinkan port tertentu), koneksi outbound ke port 3306 bisa diblok. VPC flow logs mengkonfirmasi bahwa traffic outbound yang ditolak — ini menunjukkan masalah pada outbound rules di security group EMR atau NACL. Karena soal menyebutkan "outbound traffic from EMR is being rejected" dan security group memiliki custom rules, kemungkinan besar outbound rule EMR SG yang restrictive.
  • Membuat common "data-access" security group dan menambahkannya sebagai additional SG ke setiap service adalah pendekatan paling maintainable. Redshift SG hanya memerlukan satu inbound rule (port 5439 dari data-access SG). Ketika service baru ditambahkan, cukup attach data-access SG ke service tersebut tanpa memodifikasi Redshift SG.

Miskonsepsi & Jebakan Umum

  • Tidak cukup karena masalah utamanya adalah komunikasi antar Glue ENI.
  • Tidak diperlukan karena security groups bersifat stateful — outbound response traffic otomatis diizinkan.
  • Tidak diperlukan karena Glue yang melakukan koneksi ke RDS, bukan sebaliknya.
  • Melanggar prinsip least privilege.
  • Terlalu permissive dan membuka Redshift ke internet.
  • Terlalu broad — semua resource di VPC akan bisa akses.
  • Tidak akan berhasil karena tanpa internet gateway/NAT, tidak ada path ke internet meskipun security group mengizinkan.
  • Juga bisa berfungsi tetapi Gateway Endpoint untuk S3 lebih sederhana, lebih murah (gratis), dan direkomendasikan AWS.
  • Tidak possible — Lambda ENI tidak bisa memiliki elastic IP secara langsung.
  • Membuat nodes accessible dari internet — kurang aman untuk private subnet pattern.
  • Terlalu permissive meskipun antar SG sendiri.
  • Tidak memungkinkan granular control antara master dan core.
  • Penting tapi biasanya sudah enabled by default di VPC.
  • Tidak relevan karena keduanya dalam VPC yang sama.
  • Tidak diperlukan untuk komunikasi intra-VPC.
  • Bersifat stateless dan apply pada subnet level, kurang granular dibanding security groups, dan memiliki limit yang sama.
  • Mahal dan menambah kompleksitas manajemen data.
  • Bagus jika services berada di VPC yang sama, tapi tidak berfungsi untuk CIDR dari VPC berbeda atau on-premises.
  • Salah — penghapusan rule juga mempengaruhi existing connections.
  • Salah — tidak ada blocking period selama propagation.
  • Membuat keduanya berada dalam security group yang sama — jika ada self-referencing rule, mereka bisa berkomunikasi.
  • Tidak memungkinkan isolasi antar tier karena semua resource dalam SG yang sama bisa berkomunikasi.
  • Bisa bekerja tapi lebih sulit di-manage dan stateless.
  • Tidak mempengaruhi connectivity.
  • Tidak menyebabkan outbound rejection.
  • Bisa jadi penyebab, tetapi custom SG outbound restriction adalah penyebab paling umum.
  • Terlalu broad — semua resource di VPC bisa akses.
  • Bukan untuk sharing security groups antar services dalam account yang sama.
  • Berfungsi tapi memerlukan penambahan rule baru setiap kali ada service baru — kurang scalable dan bisa hit rule limit.
