Key Services & Concepts

Amazon Bedrock
Access model fondasi (LLM) managed for embedding and generative AI.

Key Points

  • Amazon Bedrock Knowledge Bases provides solution RAG end-to-end that automatic: memecah dokumen becomes chunks, creates vector embeddings, menyimpannya in vector store, and performs semantic search on query time for menemukan konteks relevan that is sent to foundation model.
  • Semantic chunking memecah dokumen based on limit topik that dideteksi by changes significant in embedding similarity between kalimat sequential. This is ideal for corpus campuran because automatically adjusts size chunk based on content — FAQ pendek may becomes one chunk, while manual technical dipecah in limit topik alami.
  • Amazon Titan Text Embeddings V2 supports multilingual content and has feature configurable output dimensions (256, 512, or 1024) that enables tradeoff between storage efficiency and quality. Dimensi 256 very suitable for use case with storage constraints sambil still mempertahankan kualitas that good for retrieval.
  • Amazon OpenSearch Serverless with vector search collection type designed for high-concurrency, low-latency vector similarity search. Serverless mode automatic scales for handles 10,000 concurrent users, and architecture-nya dioptimalkan for approximate nearest neighbor (ANN) search on scale large (50M vectors).
  • Cosine similarity mengukur sudut between two vektor, not depends on magnitude (panjang) vektor. This is ideal when Anda want membandingkan "arah" or makna semantik without is affected by panjang deskripsi. Produk that dideskripsikan singkat vs detail will has vectors with magnitude different but arah that same if kontennya similar.
  • Amazon Bedrock Knowledge Bases supports data source syncing that can scheduled or is triggered manually. Proses sync detects dokumen new, that is changed, and that is deleted, then updates embeddings in vector store appropriate changes.
  • Change data capture (CDC) pattern for detects dokumen that changes, then only processes changes through embedding pipeline and performs upsert to vector store, is approach most efficient. This avoids re-processing dokumen that not changes, saves time and cost embedding API calls.
  • When chunks too large, one embedding mewakili multiple topics that dicampur bersama, produces "diluted" vector that less specific for topik manapun. This causes irrelevant results because embedding not quite terfokus on one topik (such as drug interactions). The solution is uses chunks that smaller and terfokus.
  • Amazon OpenSearch Service in a native supports hybrid search that mengkombinasikan k-NN vector search (semantic) with BM25 text scoring (keyword) in single query. Score normalization enables penggabungan results from second method in a seamless.
  • HNSW (Hierarchical Navigable Small World) index is algoritma ANN (Approximate Nearest Neighbor) that creates graph structure multi-layer for navigasi fast menuju neighbors terdekat. By HNSW index, pgvector can performs similarity search in sub-second on 10M vectors with accuracy trade-off minimal (recall >95%).
