Key Services & Concepts

Amazon Managed Service for Apache Flink
Pemrosesan stream stateful (windowing, agregasi) based on Apache Flink in a managed.

Key Points

  • Running average requires akumulasi value from multiple events sebelumnya (sum and count). State this must dipertahankan between processing event. Ini is definisi klasik stateful processing — output depends on input saat this DAN state from input sebelumnya.
  • Processing this stateless because each event is processed in a independent — output (enriched record) only depends on input saat this (coordinates), not on event sebelumnya. External API call and DynamoDB write not creates processing stateful; mereka is side effects. Stateful berarti output depends on accumulated state from multiple events.
  • Apache Flink excels at stateful stream processing. Keyed state (grouped by user_id) enables Flink melacak number transaksi per user in windowed time frame. Event-time processing handles late-arriving events. Flink manages state in a internal with checkpointing for fault tolerance.
  • Konversi format tanggal is operasi per-record that only requires data in record that itself. Not needs context from record other — this stateless.
  • Lambda tumbling windows manages state per shard in a internal. Each invocation receives state sebelumnya via event payload (field 'state') and mengembalikan state that diperbarui in response. Lambda service manages storage state between invocations. State this per-shard so that not terpengaruh scaling.
  • Checkpointing is mekanisme main for fault-tolerant stateful processing. Framework such as Apache Flink performs periodic checkpoints that stores state to durable storage (S3). Setelah failure, processing resume from checkpoint terakhir with state that intact.
  • Pipeline A performs transformation per-record (type casting, rename) — each record is processed independent from that other = stateless processing. Pipeline B calculates session metrics that requires tracking events per user session over time = stateful processing.
  • Flink's exactly-once semantics requires: (1) Checkpointing in exactly-once mode that guarantees state consistency, (2) Two-phase commit (2PC) sink connectors that mengoordinasikan commit to external systems with Flink checkpoints. Kombinasi this ensures each record is processed and output correct satu kali.
  • Transfer between akun is stateful transaction — state (account balances) must changes in a atomik. DynamoDB TransactWriteItems guarantees atomicity: all operasi in transaksi sukses or all dibatalkan. Ini ACID (Atomic, Consistent, Isolated, Durable).
  • Apache Flink designed for stateful stream processing. State per-key is stored locally (RocksDB) in memory/disk worker, provides low-latency access. Checkpointing guarantees durability. Window operators (sliding 30-min window) built-in. Lambda BISA performs stateful processing (tumbling windows) but limited — only tumbling not sliding windows, requires external state store (DynamoDB) for custom state, that adds latency on each event.
