Domain 1: Ingestion & Transformation — Task 1.1: Perform data ingestion

Skill 1.1.5: Set up schedulers

EventBridgeAirflowMWAAcron

Ringkasan

Skill ini termasuk dalam Domain 1: Ingestion & Transformation (Task 1.1: Perform data ingestion), dengan fokus pada set up schedulers. Materi berikut merangkum layanan AWS yang relevan beserta konsep penting yang perlu kamu kuasai untuk topik ini.

Layanan & Konsep Utama

Amazon EventBridge
Event bus serverless untuk routing event antar layanan; mendukung schedule rule.
EventBridge Scheduler
Penjadwal terkelola (cron/rate) berskala besar untuk memicu target AWS.
Amazon MWAA
Managed Workflows for Apache Airflow; orkestrasi pipeline berbasis DAG.

Poin-Poin Kunci

  • EventBridge (penerus CloudWatch Events) mendukung cron expressions yang dapat menentukan hari dalam minggu. cron(0 6 ? * MON-FRI *) berjalan pada pukul 6:00 UTC hanya pada hari Senin hingga Jumat. Ini solusi paling sederhana dan native.
  • AWS Glue Workflows dirancang khusus untuk mengorkestrasikan multiple Glue jobs dengan dependensi. Workflows mendukung triggers conditional (on job success/failure) dan fan-out/fan-in patterns. Untuk pipeline yang sepenuhnya menggunakan Glue jobs, ini adalah solusi paling terintegrasi.
  • Amazon MWAA (Apache Airflow) adalah satu-satunya solusi yang menyediakan semua fitur: DAG visualization, cross-system orchestration (Glue, EMR, Redshift, APIs), retry policies, SLA monitoring, dan alerting built-in. Ini dirancang untuk pipeline orchestration berskala enterprise.
  • Menggunakan EventBridge untuk mendeteksi S3:PutObject events dan memicu crawler hanya ketika data baru tiba menghilangkan run yang tidak perlu. Crawler hanya berjalan saat ada data baru.
  • Apache Airflow mendukung timezone-aware scheduling menggunakan library pendulum. Dengan menentukan timezone di start_date, Airflow secara otomatis menangani transisi DST. DAG akan selalu berjalan pada 8:00 AM Eastern terlepas dari apakah EST atau EDT berlaku.
  • MWAA (Airflow) menyediakan built-in support untuk retries, retry_delay, dan callbacks (on_failure_callback) dalam satu konfigurasi DAG. Ini mencakup semua requirements: scheduling, retry logic, interval, dan notification.
  • MaxConcurrentRuns = 1 pada Glue job memastikan hanya satu instance job yang berjalan pada satu waktu. Jika schedule memicu run baru sementara run sebelumnya masih berjalan, run baru akan diskip atau queued.
  • MWAA menggunakan S3 bucket untuk DAGs (dags/ folder), plugins (plugins.zip), dan dependencies (requirements.txt). Custom Python packages didaftarkan di requirements.txt dan diinstall otomatis saat environment update. Plugins (custom operators) dipaket dalam plugins.zip.
  • Glue Workflow dengan conditional trigger adalah cara paling native dan straightforward untuk menjalankan crawler setelah job sukses. Trigger "SUCCEEDED" hanya memicu crawler ketika job selesai dengan sukses.
  • EventBridge Scheduler mendukung schedule groups. Dengan menempatkan semua related schedules dalam satu group, Anda bisa men-disable (atau delete) seluruh group sekaligus. Ini paling efisien untuk batch operations.

Miskonsepsi & Jebakan Umum

  • Berlebihan untuk scheduling sederhana satu job.
  • Menambah kompleksitas tidak perlu dengan Lambda filter.
  • Tidak bisa mengecualikan hari tertentu.
  • Bisa bekerja tapi lebih generik dan membutuhkan lebih banyak konfigurasi.
  • Adalah pilihan valid tapi menambah overhead operasional (cluster management).
  • Sulit untuk fan-in (menunggu multiple jobs selesai).
  • Tidak memiliki UI visualization dan SLA features.
  • Tidak memiliki DAG visualization dan SLA monitoring bawaan.
  • Hanya menambahkan partisi Hive-style yang sudah ada, tidak mendeteksi schema changes.
  • Mengurangi frekuensi tapi masih bisa berjalan tanpa data baru.
  • Justru lebih boros karena memproses semua data setiap kali.
  • Sangat manual dan error-prone.
  • Menyebabkan DAG berjalan pada jam yang salah saat DST berubah.
  • Menambah kompleksitas yang tidak perlu.
  • Memiliki retry interval yang sangat pendek (hingga 185 detik) bukan 10 menit.
  • Bekerja tapi membutuhkan integrasi 3 service.
  • Bisa retry tapi CloudWatch alarm harus dikonfigurasi terpisah dan retry interval tidak bisa dikustomisasi per Glue.
  • Tidak menyelesaikan masalah karena job masih bisa exceed 30 menit.
  • Mencegah pemrosesan ulang data tapi tidak mencegah concurrent executions.
  • Tidak mungkin karena MWAA adalah managed service tanpa akses SSH.
  • Mengubah arsitektur operator yang sudah ada secara tidak perlu.
  • Overkill untuk dua step sederhana.
  • Mixing orchestration logic dengan ETL logic yang bukan best practice.
  • Bekerja tapi membutuhkan konfigurasi di luar Glue.
  • Tidak efisien untuk banyak schedules.
  • Membutuhkan update setiap schedule dan perlu di-reset setelah maintenance.
  • Berisiko kehilangan konfigurasi.
