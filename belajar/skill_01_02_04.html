Key Points

  • Glue Auto Scaling automatically reduces number workers when mereka under-utilized. By 40% utilization, Auto Scaling will decreases worker count, reduces DPU-hours that dibayar. Job still complete correct time because Glue adds workers saat needed.
  • Parquet (columnar format) + compression + partitioning provides cost reduction terbesar. Parquet enables column pruning (only baca kolom that diquery). Snappy compression reduces size data 5-10x. Partitioning enables partition pruning (skip partition that not relevant). Kombinasi can reduces scan from 5TB to <100GB.
  • Transient clusters only runs during job execution (3 hours) vs 24 hours — cost berkurang 87.5% (from 24h to 3h). Spot Instances for task nodes adds savings 60-90% on compute. Total savings can 90%+.
  • Glue Python Shell jobs uses 1 DPU or 0.0625 DPU (1/16 DPU) — jauh cheaper from Spark ETL (minimum 2 DPUs). For data small (<1 GB) that not requires distributed processing, Python Shell very cost-effective. Processing pandas-style quite for volume small.
  • Auto Scaling for Managed Flink (KDA) automatically adjusts KPU count based on traffic. Selama malam with 1/10 traffic, application scales down, reducing KPU costs. Selama business hours, scales up for handle load.
  • Redshift Serverless automatically allocates compute appropriate workload. For heavy ETL (2 hours), compute scales up. For light queries, compute minimal. Saat idle, charges based on RPU usage not provisioned capacity. Ini jauh more cost-effective for variable workloads.
  • S3 Lifecycle expiration policy automatic deletes objects setelah X days. By expiration 1 days on prefix intermediate data, objects is deleted setelah 24 hours, prevents akumulasi storage costs.
  • If job only mempertahankan 10% records, pushdown predicates or S3 Select memfilter in source — Glue only processes 200 GB not 2 TB. Ini reduces workers that needed in a dramatis (may 10-20 workers quite), reduces DPU-hours 80-90%.
  • Targeted optimizations per service: Consolidating small Glue jobs reduces startup overhead; Auto Scaling right-sizes workers. For EMR ($25K), Spot Instances on task nodes save 60-90%, Savings Plans on core nodes save ~40%. Combined savings could be 50%+ of total $40K bill.
  • groupFiles combines file-file small menjadi groups before is read, reduces number Spark tasks from 100,000 to several ratus. Ini reduces scheduling overhead drastis, memperpendek runtime (may from 2 hours to 20 minutes), and automatic reduces DPU-hours that dibayar.

Common Misconceptions & Pitfalls

  • Not mengontrol resource usage.
  • Only for repeated identical queries.
  • Reduces size but still row-oriented (baca all kolom).
  • Provides savings but cluster still idle 21 hours.
  • Still paying 24/7 although cheaper per hours.
  • Membantu saat running but not eliminates idle time.
  • Still 2 DPU that 32x more expensive from 0.0625 DPU shell.
  • Mengubah from streaming to batch that may melanggar business requirements.
  • Kehilangan data or increases Kinesis retention costs.
  • Menyebabkan lag during peak hours.
  • Only membantu overnight but cluster still provisioned saat idle during day.
  • Adds capacity not reduce cost.
  • Memakan time and disrupts service.
  • Memindahkan to cheaper storage but still stores all data.
  • Reduces per-GB cost but data still terakumulasi.
  • Justru stores more copies.
  • DPU-hours still ~same (half time × double workers).
  • Mengubah business requirement.
  • Glue small jobs better suited sebagai serverless without cluster management.
  • Not can handle large-scale processing.
  • Large EMR job may more cost-effective on EMR.
  • Not can handle 100 GB in a efficient.
  • For incremental processing not file grouping.
  • Adds parallelism but scheduling overhead still because many tasks.
