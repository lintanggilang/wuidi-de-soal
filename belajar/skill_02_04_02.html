Key Points

  • Apache Iceberg supports schema evolution that secure: columns can is added without writes ulang data files that there is. Data files old that not has column new will returns NULL for column-column said. Iceberg uses unique column IDs (not nama or posisi) for mapping, so that existing queries still berfungsi without modifikasi.
  • When producer changes first and consumers not yet diupdate, is required FORWARD compatibility — artinya consumer with schema old still can reads data that is written with schema new. Type promotion int→long is forward compatible in Avro because consumer that mengharapkan int can reads long (with truncation risk but in a Avro resolution rules, long can in-read as compatible).
  • Apache Iceberg supports column rename as metadata-only operation. Because Iceberg uses column IDs (not nama) for mapping to data files, rename only changes metadata table without needing writes ulang file data. This instan terlepas from size table.
  • Amazon Redshift mengoptimasi ALTER TABLE ADD COLUMN with DEFAULT value — column new is added as metadata operation and default value is applied in a virtual without writes ulang entire table. This very fast even for table miliaran rows and not memblokir operation other.
  • AWS Glue Schema Registry supports compatibility modes (BACKWARD, FORWARD, FULL, NONE) that automatically menolak registrasi schema that not compatible. By BACKWARD compatibility, deletes required field without default value will ditolak when registrasi because consumer new cannot reads data old that has field said.
  • DynamoDB is schemaless — each item can has atribut different. Approach best is adds atribut new "price_numeric" with type Number, backfill existing items in a gradual (uses Scan+UpdateItem or DynamoDB Streams), and update application for writes to second atribut during transisi. Setelah migration complete, deprecated attribute can diabaikan.
  • Apache Iceberg supports safe type promotions as operation metadata-only: int→long, float→double, and improvement precision decimal. Data files that there is does not need is written ulang — Iceberg reader performs conversion automatically when reads data files old with type that more sempit.
  • Glue Crawlers can is configured with SchemaChangePolicy that determines behavior when schema changes. Setting "LOG" logs changes without directly updates Data Catalog, enables review manual before changes is applied. This prevents schema instability from affects downstream queries.
  • Apache Iceberg provides "migrate" procedure (or "add_files") that mendaftarkan existing Parquet files as Iceberg table without writes ulang data. Iceberg handles perbedaan schema between files through schema evolution metadata — files old with 50 columns returns NULL for 35 columns that there is no. This instan and without cost rewrite.
  • Amazon Redshift supports ALTER TABLE ALTER COLUMN for increases panjang VARCHAR. Operasi this only changes metadata and not requires rewrite data or exclusive lock that berkepanjangan. This because Redshift stores VARCHAR as variable-length and metadata length only is used for validation input, not storage format.
