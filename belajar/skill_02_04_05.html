Key Services & Concepts

Partition projection
Fitur Athena that calculates partition from pattern without calls metastore, speeds up query.

Key Points

  • Partitioning based on year/month/day/region is strategi optimal because appropriate with pattern query that uses filter transaction_date and region. Hierarki date-first enables partition pruning that effective because date range queries very umum.
  • Compound sort key (order_date, customer_id) is choice terbaik because order_date sebagai kolom pertama will very effective for zone map filtering on range queries that most often is used. customer_id sebagai kolom kedua membantu merge joins with dimension table.
  • GSI with sensor_type sebagai partition key and timestamp sebagai sort key enables query efficient based on sensor_type with time range filter without scan entire table. GSI provides access pattern that different from base table.
  • ZSTD (Zstandard) provides keseimbangan terbaik between compression ratio that high (mendekati Gzip) and kecepatan decompression that fast (mendekati Snappy). For analytical workload where data is read berulang kali, ZSTD reduces storage cost sekaligus mempertahankan query performance.
  • Small file problem is problem umum in data lakes. Each file requires overhead for opening, reading metadata, and closing. Menggabungkan file small menjadi file 128-512 MB reduces number file operations in a drastis and enables parallel processing that more efficient.
  • VACUUM FULL performs dua operasi important: (1) deletes deleted rows (reclaim space from tombstones) and (2) mengurutkan ulang rows based on sort key. ANALYZE then updates statistics that is used query optimizer. Kedua operasi this mengembalikan performa zone maps and query planning.
  • Z-ordering uses space-filling curves for memetakan data multi-dimensi to satu dimensi sambil mempertahankan locality. Ini enables data that dekat in multiple dimensions (lat, long, timestamp) also dekat in a fisik in storage, so that file pruning effective for all kombinasi filter.
  • Row group size 128 MB (default Parquet) provides keseimbangan optimal. For wide tables (200 kolom) where only 5-10 kolom is read, row group that quite large ensures column chunks has quite data for sequential I/O that efficient.
  • When data new in-load to Redshift (via COPY or INSERT), rows new is added sebagai unsorted region. Zone maps on unsorted region has min/max ranges that very wide, creates data skipping not effective. VACUUM SORT mengurutkan ulang data so that zone maps has ranges that tight and can performs effective pruning.
  • For high-cardinality columns, ORC min/max statistics (row index) not effective because each stripe likely has wide range of user_ids. Bloom filters in ORC provides probabilistic test that can determines whether suatu stripe definitely doesn't contain a specific user_id, enabling effective data skipping for equality predicates.
