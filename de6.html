An application needs the output of SELECT query from Amazon Athena to be stored in an Amazon S3 bucket in Apache Parquet format. The data engineer has been advised against creating any additional tables in Athena.

How can this be achieved with the LEAST possible effort?

Jawaban benar

Use the UNLOAD statement in Athena

Karena

Opsi yang benar:

Use the UNLOAD statement in Athena

Amazon Athena secara otomatis menyimpan hasil query dan informasi metadata untuk setiap query yang berjalan di lokasi hasil query di Amazon S3 yang dapat Anda tentukan.

Perintah UNLOAD menulis hasil query dari statement SELECT ke format data yang ditentukan. Format yang didukung UNLOAD meliputi Apache Parquet, ORC, Apache Avro, dan JSON. CSV adalah satu-satunya format output yang didukung perintah SELECT Athena, tetapi Anda dapat menggunakan perintah UNLOAD, yang mendukung berbagai format output, untuk membungkus query SELECT Anda dan menulis ulang outputnya ke salah satu format yang didukung UNLOAD.

Perintah UNLOAD berguna ketika Anda ingin menghasilkan output query SELECT dalam format non-CSV tetapi tidak memerlukan tabel terkait. Misalnya, aplikasi downstream mungkin memerlukan hasil query SELECT dalam format JSON, dan Parquet atau ORC mungkin memberikan keunggulan performa dibandingkan CSV jika Anda berencana menggunakan hasil query SELECT untuk analisis tambahan.

Opsi yang salah:

Use the CREATE TABLE AS SELECT (CTAS) query in Athena - Query CREATE TABLE AS SELECT (CTAS) membuat tabel baru di Athena dari hasil statement SELECT query lain.

Use the SELECT command in Athena - CSV adalah satu-satunya format output yang didukung perintah SELECT Athena, sehingga opsi ini salah.

Use the CREATE TABLE AS SELECT (CTAS) and INSERT INTO statements in Athena - Anda dapat menggunakan statement CTAS dan INSERT INTO di Athena untuk extract, transform, dan load (ETL) data ke Amazon S3 untuk pemrosesan data. Namun, tabel baru tetap akan dibuat di Athena.

💡 Tips

Jika hasil SELECT Athena harus ke S3 Parquet tanpa buat tabel baru maka pakai UNLOAD karena UNLOAD menulis hasil query ke S3 (Parquet/ORC/dll) tanpa membuat tabel.Ingat: ekspor hasil Athena ke S3 tanpa tabel → UNLOAD; buat tabel+data → CTAS.

A media analytics company runs Apache Spark jobs on an Amazon EMR cluster to process streaming playback events from connected devices. The Spark jobs transform the data and write the curated output to an Amazon S3 bucket. Analysts use Amazon Athena to query the curated data for viewing trends, device usage, and content engagement patterns. The company needs to choose data formats and metadata management approaches that provide the shortest Athena query times.

Which solutions will meet these requirements? (Select two)

Jawaban benar

Write the transformed data in ORC format and use AWS Glue Data Catalog to track schema metadata for Athena queries

Write the transformed data in Apache Parquet format and use AWS Glue Data Catalog to track schema metadata for Athena queries

Karena

Opsi yang benar:

Write the transformed data in ORC format and use AWS Glue Data Catalog to track schema metadata for Athena queries

Karena ORC adalah format penyimpanan columnar yang dioptimalkan untuk query analitik. Ketika Athena hanya meng-query kolom tertentu, ORC memungkinkan query engine membaca lebih sedikit data dibandingkan format berbasis baris seperti JSON atau CSV.

Menggunakan AWS Glue Data Catalog memberi Athena metadata tabel dan schema yang dibutuhkan untuk meng-query file ORC di Amazon S3. Schema yang di-katalogkan membantu analis meng-query output streaming yang sudah dikurasi tanpa harus mendefinisikan metadata secara manual untuk setiap query.

Solusi ini menghasilkan waktu query lebih singkat karena menggabungkan format columnar dengan catalog metadata terkelola. Job EMR Spark dapat menulis output ORC, dan Athena dapat menggunakan tabel Glue catalog untuk meng-query data tersebut secara efisien.

Write the transformed data in Apache Parquet format and use AWS Glue Data Catalog to track schema metadata for Athena queries

Apache Parquet juga merupakan format penyimpanan columnar yang banyak digunakan untuk analitik di Amazon S3. Parquet dapat mengurangi jumlah data yang dipindai Athena ketika query hanya mengakses sebagian kolom.

AWS Glue Data Catalog adalah lapisan metadata yang tepat untuk Athena. Perusahaan dapat meng-katalogkan data Parquet, melacak definisi tabel, dan memungkinkan Athena menggunakan catalog saat menjalankan query SQL.

Kombinasi ini memenuhi kebutuhan waktu query tersingkat karena Parquet dioptimalkan untuk pembacaan columnar, kompresi, dan predicate pushdown. Ini sangat cocok untuk data streaming yang sudah ditransformasi yang di-query analis melalui Athena.

via - https://docs.aws.amazon.com/athena/latest/ug/columnar-storage.html

Opsi yang salah:

Write the transformed data in Avro format and use AWS Glue Data Catalog to track schema metadata for Athena queries - Avro adalah format berorientasi baris yang mendukung schema evolution dan berguna untuk serialisasi data. Format ini cocok untuk pipeline streaming dan beban kerja berbasis pesan yang membutuhkan record ter-encode yang ringkas.

Opsi ini kurang tepat untuk performa query analitik Athena karena Avro tidak memberikan keuntungan pembacaan columnar seperti ORC atau Parquet. Ketika analis hanya meng-query kolom tertentu, Athena dapat memindai lebih sedikit data dengan format columnar.

Write the transformed data in ORC format and store schema definitions in separate JSON files in Amazon S3 - ORC adalah format file columnar yang valid untuk Athena dan dapat meningkatkan performa query dibandingkan format berbasis baris. Job EMR Spark dapat menulis output kurasi dalam format ORC.

Opsi ini tidak memenuhi kebutuhan pengelolaan metadata karena file schema terpisah di Amazon S3 bukanlah catalog standar yang digunakan Athena untuk metadata tabel. Menggunakan AWS Glue Data Catalog menyediakan lapisan schema terkelola yang dibutuhkan untuk query Athena.

Write the transformed data in Apache Parquet format and use an external DynamoDB table to track schema changes for Athena queries - Apache Parquet adalah format yang sangat baik untuk analitik Athena karena bersifat columnar dan efisien untuk query kolom tertentu. Bagian format data pada opsi ini valid.

Masalahnya ada pada pendekatan metadata. Athena tidak menggunakan tabel DynamoDB eksternal sebagai catalog schema standar untuk dataset S3. AWS Glue Data Catalog adalah catalog terkelola yang digunakan Athena untuk definisi tabel dan metadata schema.

💡 Tips

Jika Athena query tercepat atas output EMR/Spark maka tulis Parquet/ORC + lacak metadata di Glue Data Catalog karena format kolumnar + katalog = scan minimal & skema terkelola.Ingat: format query tercepat Athena = kolumnar (Parquet/ORC) + Glue Catalog.

A financial services company encrypts its Amazon Redshift provisioned cluster by using AWS Key Management Service. The company is implementing a disaster recovery strategy that requires automated snapshot copies to a different AWS Region.

A data engineer must configure cross-Region snapshot copy by using the AWS CLI. The copied snapshots must remain encrypted with a KMS key that is valid in the destination Region.

Which combination of steps will meet these requirements? (Select two)

Jawaban benar

Enable snapshot copying in the source Region and specify the snapshot copy grant name that exists in the destination Region

Create a KMS key in the destination Region and create a Redshift snapshot copy grant that uses that destination KMS key

Karena

Opsi yang benar:

Create a KMS key in the destination Region and create a Redshift snapshot copy grant that uses that destination KMS key

Karena Amazon Redshift memerlukan snapshot copy grant ketika menyalin snapshot dari cluster yang di-encrypt dengan AWS KMS ke Region lain. Grant ini mengizinkan Amazon Redshift menggunakan KMS key untuk meng-encrypt snapshot yang disalin.

KMS key harus valid di destination Region karena AWS KMS key adalah resource per-Region. Membuat KMS key dan snapshot copy grant di destination Region memungkinkan Redshift meng-encrypt snapshot yang disalin dengan benar.

Langkah ini diperlukan untuk disaster recovery karena perusahaan ingin salinan snapshot cross-Region tetap ter-encrypt. Tanpa KMS key destination Region dan snapshot copy grant, Redshift tidak dapat menggunakan konfigurasi encryption yang benar untuk snapshot yang disalin.

Enable snapshot copying in the source Region and specify the snapshot copy grant name that exists in the destination Region

Setelah snapshot copy grant destination Region ada, data engineer harus mengaktifkan snapshot copying untuk cluster Redshift dari source Region. Operasi aktivasi ini menentukan destination Region untuk snapshot yang disalin.

Untuk cluster Redshift yang ter-encrypt, konfigurasi enable-snapshot-copy harus merujuk snapshot copy grant yang dibuat untuk destination Region. Ini memberi tahu Redshift grant mana yang akan digunakan saat meng-encrypt snapshot yang disalin di Region target.

Langkah ini melengkapi setup penyalinan cross-Region. Grant destination Region menangani izin encryption, dan pengaturan snapshot copy source Region memulai perilaku penyalinan otomatis untuk disaster recovery.

via - https://aws.amazon.com/blogs/big-data/migrate-your-amazon-redshift-cluster-to-another-aws-region/

Opsi yang salah:

Create a KMS key in the source Region and create a Redshift snapshot copy grant that uses the source Region key - Membuat KMS key di source Region dapat mendukung encryption cluster Redshift sumber. Cluster sumber mungkin sudah menggunakan KMS key untuk encryption at rest.

Keterbatasannya adalah snapshot yang disalin di Region lain harus menggunakan KMS key yang valid di destination Region. Snapshot copy grant yang hanya terikat pada key source Region tidak memenuhi kebutuhan encryption destination Region.

Create an S3 bucket in the destination Region, export the encrypted Redshift snapshot to the bucket, and configure S3 replication - Amazon S3 replication dapat menyalin objek S3 lintas Region. Mengekspor data ke S3 bisa berguna untuk beberapa pola analitik, pengarsipan, atau recovery berbasis lake.

Opsi ini kurang tepat karena cross-Region snapshot copy Redshift tidak memerlukan ekspor snapshot ter-encrypt ke S3. Fitur snapshot copy Redshift yang terkelola menggunakan snapshot copy grant dan KMS key destination Region.

Enable snapshot copying in the destination Region and specify the snapshot copy grant name that exists in the source Region - Mengaktifkan snapshot copy melibatkan konfigurasi cluster Redshift untuk menyalin snapshot ke Region lain. Nama snapshot copy grant adalah bagian dari konfigurasi penyalinan snapshot ter-encrypt.

Opsi ini membalik arah yang dibutuhkan. Engineer mengaktifkan snapshot copying dari source Region dan merujuk grant yang dibuat untuk destination Region, bukan sebaliknya.

💡 Tips

Jika cross-region snapshot Redshift terenkripsi (KMS) via CLI maka buat KMS key + snapshot copy grant di region tujuan lalu enable snapshot copy (sebut grant name) karena salinan terenkripsi lintas region butuh grant + key di region tujuan.Ingat: copy snapshot terenkripsi lintas region → snapshot copy grant + KMS key di region destinasi.

A heavy equipment manufacturer uses AWS Glue jobs to prepare IoT telemetry data for predictive maintenance reporting. The telemetry dataset includes vibration readings, operating temperature, machine identifiers, and event timestamps. A data engineer must add automated data quality checks that identify vibration readings outside the expected range of 0 to 85 mm/s and records that are missing event_timestamp values. The solution must require minimal coding and must automatically flag the specified issues.

Which solution will meet these requirements?

Jawaban benar

Create an AWS Glue DataBrew project to profile the telemetry data, define completeness rules for event_timestamp, and configure numeric range validation for vibration values

Karena

Opsi yang benar:

Create an AWS Glue DataBrew project to profile the telemetry data, define completeness rules for event_timestamp, and configure numeric range validation for vibration values

Karena AWS Glue DataBrew paling cocok untuk kebutuhan ini karena menyediakan cara visual dan low-code untuk memprofil dataset dan mendefinisikan aturan kualitas data. Data engineer dapat membuat project DataBrew untuk dataset telemetri dan memeriksa hasil profil untuk memahami nilai yang hilang, distribusi nilai, dan karakteristik numerik.

Ruleset DataBrew dapat mendefinisikan pengecekan validasi untuk kolom tertentu. Dalam skenario ini, engineer dapat mendefinisikan completeness rule untuk event_timestamp dan numeric range rule yang memeriksa apakah nilai vibration tetap berada di antara 0 dan 85 mm/s.

Solusi ini memenuhi kebutuhan dengan coding minimal karena DataBrew menyediakan kemampuan profiling bawaan dan validasi berbasis aturan. Perusahaan tidak perlu menulis scanner kustom, membangun framework transformasi terpisah, atau menggunakan deteksi anomali machine learning untuk aturan bisnis yang tetap.

Opsi yang salah:

Use AWS Glue Data Quality rules with ML-based anomaly detection to learn unusual vibration behavior and detect records that do not include event timestamps - AWS Glue Data Quality dapat mendefinisikan pengecekan berbasis aturan, dan anomaly detection dapat membantu mengidentifikasi perilaku data yang tidak biasa. Ini berguna ketika tim data perlu memantau pola data yang berubah seiring waktu.

Namun, kebutuhannya adalah memvalidasi kondisi tetap: timestamp yang hilang dan nilai vibration di luar rentang yang diketahui. Pola solusi yang diharapkan adalah AWS Glue DataBrew karena menyediakan profiling visual dan aturan yang dapat dikonfigurasi untuk pengecekan ini dengan coding minimal.

Use Amazon CloudWatch anomaly detection on custom vibration metrics and configure AWS Glue crawlers to identify records that have missing timestamp values - CloudWatch anomaly detection dapat membantu mengidentifikasi tren yang tidak biasa pada metrik yang dipublikasikan. Ini berguna untuk pemantauan operasional ketika aplikasi memancarkan metrik secara terus-menerus.

Namun, opsi ini tidak memvalidasi setiap record sumber terhadap rentang numerik yang tetap. AWS Glue crawler menemukan metadata schema, tetapi tidak mengidentifikasi record individual yang kehilangan nilai timestamp.

Create an AWS Glue DynamicFrame with a custom validation operator and use Amazon SageMaker Data Wrangler transforms to validate timestamps and vibration ranges - AWS Glue DynamicFrame dapat mendukung transformasi kustom selama pemrosesan ETL. SageMaker Data Wrangler dapat membantu menyiapkan dan mentransformasi data untuk alur kerja machine learning.

Namun, opsi ini memperkenalkan logika kustom yang tidak perlu dan tool persiapan ML tambahan. Pengecekan yang diminta adalah validasi kualitas data sederhana yang dapat dikonfigurasi DataBrew melalui profiling dan aturan.

💡 Tips

Jika cek kualitas (range 0–85 & completeness timestamp) minim koding maka pakai Glue DataBrew (completeness rule + numeric range) karena DataBrew no-code untuk aturan kualitas.Ingat: validasi kualitas no-code → DataBrew ruleset; dalam job ETL → Glue Data Quality (DQDL).

A logistics company needs a fully automated solution to check for new records in several operational data stores and process any records that the solution finds. The solution must run every hour and must work with Amazon RDS, Amazon DynamoDB, and Amazon OpenSearch Service. Each processing run will handle up to 8 MB of data at a time. The company wants to minimize cost and operational overhead while using reliable error handling.

Which solution will meet these requirements?

Jawaban benar

Use Amazon EventBridge Scheduler to invoke a Lambda function every hour to check each data store, send processing messages to Amazon SQS when the function finds new data, and use a second Lambda function to process the messages with retries and a dead-letter queue

Karena

Opsi yang benar:

Use Amazon EventBridge Scheduler to invoke a Lambda function every hour to check each data store, send processing messages to Amazon SQS when the function finds new data, and use a second Lambda function to process the messages with retries and a dead-letter queue

Karena Amazon EventBridge Scheduler dapat meng-invoke fungsi AWS Lambda pada jadwal setiap jam. Fungsi Lambda pertama dapat terhubung ke Amazon RDS, Amazon DynamoDB, dan Amazon OpenSearch Service untuk memeriksa data baru dan membuat pesan pemrosesan ketika menemukan record yang perlu diproses.

Amazon SQS memisahkan langkah penemuan dari langkah pemrosesan. Pesan dapat berisi metadata, identifier, atau pointer ke record alih-alih seluruh dataset. Fungsi Lambda kedua dapat membaca pesan dari antrean SQS, mengambil data terkait dari layanan sumber, dan memproses hingga working set 8 MB yang dibutuhkan.

Solusi ini memiliki overhead operasional rendah karena menggunakan layanan serverless terkelola. Solusi ini juga memiliki penanganan error yang kuat karena integrasi Lambda dengan SQS mendukung retry, perilaku visibility timeout, dan dead-letter queue untuk pesan yang berulang kali gagal diproses.

via - https://docs.aws.amazon.com/lambda/latest/dg/with-eventbridge-scheduler.html

Opsi yang salah:

Use Amazon Managed Workflows for Apache Airflow to create a DAG that runs every hour, checks each data store for new records, processes the records, and handles errors in Python operators - Amazon MWAA dapat menjadwalkan alur kerja dan mengimplementasikan manajemen dependensi melalui DAG Apache Airflow. MWAA juga dapat menjalankan Python operator yang memeriksa beberapa data store dan memproses hasilnya.

Namun, Amazon MWAA memperkenalkan lingkungan Airflow, operasi DAG, konfigurasi worker, pemantauan, dan administrasi tingkat platform. Untuk proses setiap jam yang hanya menangani sedikit data, Lambda dengan EventBridge Scheduler dan SQS lebih hemat biaya dan lebih sederhana secara operasional.

Run an Apache Spark application on Amazon EMR every hour to check Amazon RDS, Amazon DynamoDB, and Amazon OpenSearch Service for new records, process the results, and handle errors in the Spark code - Amazon EMR dengan Apache Spark dapat memproses dataset berskala besar dan terhubung ke beberapa sumber data. Spark juga memungkinkan developer mengimplementasikan penanganan error kustom di dalam kode aplikasi.

Namun, EMR terlalu berat untuk beban kerja yang berjalan setiap jam dan hanya memproses hingga 8 MB data pada satu waktu. Perusahaan harus membayar dan mengelola lingkungan pemrosesan big data padahal desain berbasis Lambda yang serverless sudah mencukupi.

Use AWS Glue workflows to run a crawler every hour against Amazon RDS, Amazon DynamoDB, and Amazon OpenSearch Service, then start AWS Glue ETL jobs to process all records that the crawlers discover - AWS Glue crawler membantu menemukan schema dan memperbarui AWS Glue Data Catalog. AWS Glue workflow dapat mengorkestrasi job, crawler, dan trigger Glue.

Namun, crawler bukan mekanisme yang tepat untuk memeriksa record operasional baru di Amazon OpenSearch Service setiap jam, dan crawler tidak menyediakan alur pemrosesan record yang ringan untuk volume data kecil. Desain ini menambah overhead catalog dan ETL yang tidak dibutuhkan.

💡 Tips

Jika cek data store tiap jam, ≤8 MB/run, hemat, error handling andal maka EventBridge Scheduler → Lambda (deteksi) → SQS → Lambda (proses, retry + DLQ) karena serverless + SQS/DLQ beri retry & tahan error.Ingat: error handling andal untuk pesan → SQS + DLQ; jadwal → EventBridge Scheduler.

As a data engineer, you have been tasked to ensure that user teams and groups can access only the PII that they require.

How will you implement a solution for this requirement with the LEAST operational effort?

Jawaban benar

Set up AWS Lake Formation and create data filters based on the access permissions needed to each user group. Grant the data filter permissions to different IAM roles. Assign the IAM roles to users based on PII access needs. Use Athena to query the data

Karena

Opsi yang benar:

Set up AWS Lake Formation and create data filters based on the access permissions needed for each user group. Grant the data filter permissions to different IAM roles. Assign the IAM roles to users as needed. Use Athena to query the data

Karena Anda dapat menerapkan keamanan column-level, row-level, dan cell-level dengan membuat data filter. Anda memilih data filter saat memberikan permission SELECT Lake Formation pada tabel. Jika tabel Anda berisi struktur kolom bersarang, Anda dapat mendefinisikan data filter dengan menyertakan atau mengecualikan kolom anak dan mendefinisikan ekspresi filter row-level pada atribut bersarang.

Anda dapat memberikan permission SELECT, DESCRIBE, dan DROP Lake Formation pada data filter kepada principal.

Creating data filter from the Lake Formation console: via - https://docs.aws.amazon.com/lake-formation/latest/dg/data-filters-about.html

Granting data filter permissions: via - https://docs.aws.amazon.com/lake-formation/latest/dg/granting-filter-perms.html

AWS Lake Formation memungkinkan Anda mendefinisikan dan menegakkan kebijakan akses tingkat database, tabel, dan kolom saat menggunakan query Athena untuk membaca data yang tersimpan di Amazon S3. Lake Formation menyediakan lapisan otorisasi dan tata kelola pada data yang tersimpan di Amazon S3.

Permission Lake Formation berlaku saat menggunakan Athena untuk meng-query data sumber dari lokasi Amazon S3 yang terdaftar di Lake Formation. Permission Lake Formation juga berlaku saat Anda membuat database dan tabel yang menunjuk ke lokasi data Amazon S3 yang terdaftar. Untuk menggunakan Athena dengan data yang terdaftar menggunakan Lake Formation, Athena harus dikonfigurasi untuk menggunakan AWS Glue Data Catalog.

Opsi yang salah:

Use Amazon QuickSight to restrict access to a dataset by configuring row-level security (RLS) on it based on the PII needs of each team. To do this, you create a query or file that has one column named UserName or GroupNameand then add one column to the query or file for each field that you want to grant or restrict access to - Menggunakan row-level security (RLS) dengan aturan berbasis pengguna untuk membatasi akses ke dataset hanya tersedia pada edisi Enterprise.

Use Amazon S3 Access Points to create unique access control policies for each access point to easily control access to shared datasets. Create different Access Points for different user groups with different PII access requirements - Amazon S3 Access Points, sebuah fitur S3, menyederhanakan akses data untuk layanan AWS atau aplikasi pelanggan yang menyimpan data di S3. Dengan S3 Access Points, pelanggan dapat membuat kebijakan access control unik untuk setiap access point agar mudah mengontrol akses ke dataset bersama. Kontrol akses row-level dan column-level yang halus tidak dimungkinkan dengan S3 Access Points.

Create IAM roles that have different levels of granular access for different PII requirements. Assign the IAM roles to IAM groups. Use an identity-based policy to row and column level access to the IAM groups - Kebijakan IAM berbasis identitas tidak dapat memberikan akses halus yang dibutuhkan untuk use case ini.

💡 Tips

Jika tiap tim/grup hanya akses PII yang diperlukan, overhead minim maka Lake Formation data filters + grant ke IAM role lalu query via Athena karena LF menerapkan izin halus (kolom/baris) terpusat.Ingat: akses PII granular lintas tim → Lake Formation data filters.

The pipeline uses Lambda functions that respond to S3 events, clean the activity data, and start an AWS Glue workflow for downstream processing.

The Lambda functions are configured with 128 MB of memory, 512 MB of ephemeral storage, and a timeout of 20 seconds. The functions complete successfully, but monitoring shows that CPU usage is frequently close to 100 percent, which slows the pipeline. The company wants to improve function performance and reduce total pipeline runtime.

Which solution will meet these requirements?

Jawaban benar

Increase the memory allocation of the Lambda functions to 512 MB so the functions receive more proportional CPU capacity

Karena

Opsi yang benar:

Create an IAM role with permissions to write to the S3 bucket and associate the IAM role with the Amazon Redshift cluster

Karena AWS Glue menggunakan pola integrasi Amazon Redshift yang memindahkan data melalui Amazon S3 saat membaca dari atau menulis ke Redshift. Untuk perpindahan data berthroughput tinggi, AWS Glue dapat menjalankan perintah COPY dan UNLOAD Amazon Redshift, yang mengharuskan Amazon Redshift mengakses lokasi S3 terkait.

Amazon Redshift membutuhkan IAM role yang memberikan permission S3 yang diperlukan, seperti menulis data yang di-unload ke path S3 target atau sementara. Setelah role dibuat, data engineer harus meng-associate IAM role tersebut dengan cluster Amazon Redshift agar Redshift dapat meng-assume role selama operasi perpindahan data.

Langkah ini melengkapi konfigurasi jaringan yang sudah selesai. Konektivitas privat menyediakan jalur antar layanan, tetapi permission IAM yang mengotorisasi Redshift untuk menulis ke Amazon S3. Tanpa IAM role Redshift yang ter-associate, job Glue tetap dapat gagal ketika Redshift mencoba meng-unload data ke S3 bucket.

Opsi yang salah:

Bucket policy berguna untuk mengontrol siapa yang dapat membaca atau menulis objek di bucket.

Namun, memberikan akses luas ke service principal AWS Glue dan menghapus role job Glue bukanlah model permission yang tepat. Job AWS Glue menggunakan IAM role, dan Amazon Redshift juga membutuhkan IAM role ter-associate untuk melakukan operasi COPY dan UNLOAD terhadap S3.

Enable Amazon Redshift data sharing and configure the S3 bucket as the target location for the shared dataset - Amazon Redshift data sharing memungkinkan Redshift berbagi data live antar cluster Redshift, workgroup, akun AWS, atau konsumen analitik tanpa menyalin data. Ini berguna untuk isolasi beban kerja dan berbagi data yang tertata.

Namun, Redshift data sharing tidak menggunakan S3 bucket sebagai lokasi target untuk menyimpan salinan data. Perusahaan membutuhkan permission Redshift dan AWS Glue untuk perpindahan data berbasis S3, bukan konfigurasi Redshift data sharing.

Store the Amazon Redshift database credentials in AWS Secrets Manager and reference the secret in the AWS Glue job configuration - AWS Secrets Manager adalah tempat yang baik untuk menyimpan kredensial database yang dapat digunakan job AWS Glue untuk terhubung ke Amazon Redshift. Menyimpan kredensial secara aman lebih baik daripada hardcoding username dan password di script.

Namun, skenario menyatakan bahwa detail koneksi sudah dikonfigurasi dan masalah yang tersisa adalah mengaktifkan ekspor terjadwal ke Amazon S3. Secrets Manager tidak memberikan izin kepada Amazon Redshift untuk menulis data yang di-unload ke S3 bucket.

💡 Tips

Jika Lambda CPU ~100% memperlambat pipeline maka naikkan memori (mis. 512 MB) karena di Lambda, CPU proporsional dengan memori yang dialokasikan.Ingat: Lambda — naikkan memori = naikkan CPU & jaringan (vCPU penuh ~1769 MB).

A company is building a new data pipeline that prepares customer activity data for executive dashboards. Business users report that some dashboard records are incomplete because required fields are missing and some records do not match the related reference data.

A data engineer must add data quality checks before the pipeline writes the curated output to storage. The checks must detect null values in required columns and validate referential integrity against related datasets with the least operational overhead.

Which solution will meet these requirements?

Jawaban benar

Use AWS Glue ETL jobs with an Evaluate Data Quality transform, IsComplete rules for required columns, and ReferentialIntegrity rules for related datasets

Karena

Opsi yang benar:

Use AWS Glue ETL jobs with an Evaluate Data Quality transform, IsComplete rules for required columns, and ReferentialIntegrity rules for related datasets

Ini menghindari staging data streaming di Amazon S3 sebelum memuatnya ke Redshift, yang mengurangi penundaan ingestion dan membantu membuat data clickstream yang segar tersedia untuk analitik dengan cepat.

Solusi ini memberikan latensi query paling rendah untuk analitik karena Redshift dapat meng-query materialized view yang menerima data streaming. Arsitektur ini menghilangkan langkah batch loading perantara seperti pengiriman Firehose-ke-S3 dan job COPY Redshift, sehingga analis dapat bekerja dengan event yang baru di-ingest dengan latensi end-to-end lebih rendah.

Opsi yang salah:

Use Amazon Kinesis Data Streams to capture the events, invoke AWS Lambda functions to transform the stream records, write the transformed events to Amazon S3 through Amazon Data Firehose, and schedule Amazon Redshift COPY jobs for analytics loading - Opsi ini menggunakan Kinesis Data Streams untuk ingestion dan Lambda untuk transformasi, yang dapat menjadi bagian valid dari arsitektur streaming. Ia juga menggunakan Firehose dan Amazon S3 untuk men-staging data yang ditransformasi sebelum memuatnya ke Redshift.

Langkah staging dan COPY terjadwal meningkatkan latensi analitik. Kebutuhan meminta latensi query paling rendah, sehingga Redshift streaming ingestion ke materialized view lebih cocok daripada pipeline Firehose-ke-S3-ke-COPY.

Use Amazon MSK to capture the events, use Amazon EMR to process the data, and use federated queries to access the data from Amazon Redshift - Amazon MSK dapat menangkap event streaming berthroughput tinggi, dan Amazon EMR dapat memproses data berskala besar. Layanan ini dapat mendukung arsitektur streaming dan batch yang kompleks.

Namun, opsi ini tidak memuat data streaming langsung ke Redshift untuk analitik latensi rendah. Federated query bukan mekanisme yang tepat untuk meminimalkan latensi query bagi data clickstream yang baru di-ingest di Redshift.

Use Amazon DynamoDB Streams to capture the events, use AWS Glue to process the records, and use a zero-ETL integration to load the data into Amazon Redshift - DynamoDB Streams menangkap perubahan tingkat item dari tabel DynamoDB. Ini berguna untuk change data capture dari beban kerja DynamoDB.

Data sumber dalam skenario ini adalah aktivitas clickstream dari website ecommerce dan aplikasi mobile. DynamoDB Streams bukan layanan ingestion yang tepat untuk menangkap event stream asli bervolume tinggi, dan AWS Glue plus zero-ETL tidak menyediakan jalur streaming latensi terendah ke Redshift.
