A data engineer has a daily ETL pipeline that loads customer records from multiple sources into an Amazon S3 data lake. Before downstream analytics consumes this data, the engineer needs to automatically verify that no critical fields (customer_id, email, transaction_date) contain NULL values, and that transaction_amount falls within the range of $0.01 to $1,000,000. Which AWS service provides the MOST integrated and declarative approach for these checks?
  • A. Create a DataBrew recipe with validation steps and run it before the analytics pipeline, applying schema conversion and enrichment inline
  • B. Use AWS Glue Data Quality rules defined in the Glue Data Catalog with automatic evaluation during ETL jobs
  • C. Deploy a SageMaker Data Wrangler flow with data quality checks as processing steps configured for optimal performance
  • D. Write an Amazon Athena query that counts NULLs and out-of-range values, triggered by a Lambda function
Correct Answer: B
AWS Glue Data Quality enables definisi rules in a deklaratif uses Data Quality Definition Language (DQDL). Rules can dievaluasi automatically during ETL job execution and terintegrasi directly with Glue Data Catalog. Rules such as Completeness, ColumnValues range check can didefinisikan without coding.

Option A: INCORRECT. More suitable for transformation visual daripada automated quality gates.
Option B: CORRECT.
Option C: INCORRECT. Designed for ML data preparation, not pipeline data quality automation — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option D: INCORRECT. Requires code custom and orchestration separate.

A company has a data lake with historical transaction records in Amazon S3. A data analyst suspects that some records have duplicate transaction_id values due to a bug in the upstream system. The analyst needs to quickly identify the scale of the duplication problem and find specific duplicate records. Which approach provides the FASTEST investigation with minimal setup?
  • A. Create an AWS Glue ETL job that uses FindMatches ML transform to identify duplicates, scaling horizontally as ingestion throughput keeps growing
  • B. Load data into Amazon Redshift and run GROUP BY with HAVING COUNT(*) > 1 with native S3 integration and optimized data transfer
  • C. Use Amazon QuickSight to create a visual showing transaction_id distribution, satisfying all of the stated requirements with minimal effort
  • D. Use Amazon Athena to run a SQL query with GROUP BY transaction_id HAVING COUNT(*) > 1 directly on S3
Correct Answer: D
Amazon Athena is solution serverless that can directly query data in S3 without loading or provisioning. Query GROUP BY with HAVING COUNT > 1 will segera menunjukkan skala duplikasi and record specific. Ini most fast because zero setup.

Option A: INCORRECT. For fuzzy matching, not exact duplicate that already can dideteksi with GROUP BY simple.
Option B: INCORRECT. Requires loading data to Redshift (time and cost) — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option C: INCORRECT. Not provides detail granular per record that is required for investigasi.
Option D: CORRECT.

A streaming data pipeline ingests IoT sensor data into Amazon Kinesis Data Streams. Some sensors occasionally send malformed JSON or values outside physically possible ranges (e.g., temperature > 1000°C for room sensors). The data engineer needs to validate and filter these records in real-time before they reach the data lake. Which solution BEST addresses this requirement?
  • A. Write validation rules in AWS Glue streaming ETL to discard invalid records
  • B. Use Amazon Kinesis Data Analytics (Apache Flink) with in-application stream to filter anomalous values
  • C. Configure Amazon Data Firehose with a transformation Lambda that validates and cleans records
  • D. Use an AWS Lambda function as a Kinesis consumer to validate JSON structure and value ranges, routing valid records to the data lake and invalid records to a dead-letter queue
Correct Answer: C
Amazon Data Firehose with transformation Lambda is solution most terintegrasi for validation real-time before data enters to data lake (S3). Lambda performs validation JSON and range check, mengembalikan status Ok for valid records and ProcessingFailed for invalid records. Firehose automatically separates failed records to error prefix.

Option A: INCORRECT. Has startup time more old and less suitable for simple filtering.
Option B: INCORRECT. Terlalu kompleks for simple validation.
Option C: CORRECT.
Option D: INCORRECT. Requires manajemen consumer and DLQ separate.

The dataset contains customer addresses from multiple countries with inconsistent formatting (varying date formats, phone number formats, and address structures). The scientist needs to interactively explore different cleaning strategies before committing to a production pipeline. Which tool provides the BEST interactive data cleaning experience for this scenario?
  • A. Jupyter Notebooks on EMR using PySpark with pandas UDFs for iterative exploration

Data scientist can mencoba berbagai strategi cleaning in a iteratif, writes custom parsing logic, and directly melihat hasilnya. Ini most suitable for complexity format that requires logic custom.

Option B: INCORRECT. Bagus for visual transformation but limited for complex custom logic.
Option C: INCORRECT. Has built-in transforms but less flexible for format internasional that very bervariasi.
Option D: INCORRECT. Kurang interaktif and regex in SQL limited for multi-step cleaning.

A data engineer needs to build an automated data quality pipeline that runs after each nightly batch load. The pipeline must check: (1) referential integrity between orders and customers tables, (2) freshness - data should not be older than 24 hours, and (3) uniqueness of primary keys. Failed checks should halt downstream processing and send alerts. Which architecture is MOST appropriate?
  • A. DataBrew profile job scheduled after each load, with Lambda reading profile results and halting pipeline if thresholds exceeded, handling the described workload reliably at scale
  • B. Custom Python script on EMR that performs all validation checks and writes results to DynamoDB, guaranteeing exactly-ordered delivery within each key group
  • C. AWS Glue Data Quality rules with EvaluateDataQuality transform in Glue workflow, configured to fail the job on rule violations, with CloudWatch alarms for notification
  • D. Step Functions orchestrating multiple Athena queries for each check, with conditional branching based on results configured for optimal performance and minimal operational overhead
Correct Answer: C
AWS Glue Data Quality with EvaluateDataQuality transform enables definisi rules deklaratif for referential integrity (ReferentialIntegrity), freshness (DataFreshness), and uniqueness (Uniqueness). Rules dievaluasi inline in Glue workflow and can is configured for menghentikan job if fails. Integrasi with CloudWatch enables alerting automatic.

Option A: INCORRECT. Not designed for referential integrity checks lintas table.
Option B: INCORRECT. Requires maintenance code custom.
Option C: CORRECT.
Option D: INCORRECT. Requires orchestration custom that kompleks — although its description sounds convincing, in a fundamental still not appropriate for requirements this.

A data engineer discovers that a dataset loaded into Amazon S3 has approximately 15% of records with inconsistent date formats (mix of YYYY-MM-DD, DD/MM/YYYY, and MM-DD-YYYY). The dataset has 200 million records. The engineer needs to standardize all dates to ISO 8601 format (YYYY-MM-DD) before the data is used by downstream Athena queries. What is the MOST cost-effective approach?
  • A. Use AWS Glue ETL with a custom PySpark transformation to parse and standardize date formats
  • B. Use Athena CTAS with CASE statements and date_parse functions to create a cleaned table
  • C. Use Amazon SageMaker Data Wrangler to define date parsing transformations and export as a processing job
  • D. Use AWS Glue DataBrew with built-in date format transformations in a recipe job
Correct Answer: B
Athena CTAS (CREATE TABLE AS SELECT) is approach most cost-effective because serverless and Anda only membayar per data that in-scan. By function date_parse and CASE statements, Anda can detects format and mengkonversi to standar. Hasilnya directly available sebagai table new in Glue Data Catalog.

Option A: INCORRECT. Berfungsi but more expensive with DPU costs for job simple this.
Option B: CORRECT.
Option C: INCORRECT. Designed for ML workflows and overkill.
Option D: INCORRECT. Has cost per-node that higher dibanding Athena for transformation simple on 200M records.

A data team uses Amazon SageMaker Data Wrangler to prepare features for a machine learning model. During the data cleaning phase, they notice that a numeric column (annual_income) has outliers where values exceed $10 million, which represent data entry errors. They want to cap these values at the 99th percentile and also impute missing values with the median. Which Data Wrangler capability should they use?
  • A. Use the Handle Outliers transform with the Winsorization method and Handle Missing Values with Impute option
  • B. Export the dataset to a Jupyter notebook and handle cleaning with pandas and Handle Missing Values with Impute option
  • C. Use the Featurize transform with normalization to automatically handle outliers and missing values
  • D. Write custom PySpark code in the Data Wrangler custom transform step, handling peak volume without any manual intervention
Correct Answer: A
SageMaker Data Wrangler provides built-in transforms for Handle Outliers (including Winsorization that caps values on percentile certain) and Handle Missing Values (including imputation with median, mean, or custom value). Kedua operasi this available sebagai visual transforms without coding.

Option A: CORRECT.
Option B: INCORRECT. Kehilangan integration with Data Wrangler pipeline — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option C: INCORRECT. For feature engineering such as one-hot encoding, not outlier handling.
Option D: INCORRECT. Not needs because built-in transforms already available.

The system needs to track data quality metrics over time, detect quality degradation trends, and provide a visual dashboard showing quality scores per source system. Quality rules are already defined in AWS Glue Data Quality. How should the engineer implement the monitoring dashboard?
  • A. Use AWS Glue DataBrew profile job statistics as the quality monitoring dashboard, handling the described workload reliably at scale
  • B. Store quality results in DynamoDB and build a custom web dashboard using API Gateway and Lambda
  • C. Use CloudWatch custom metrics to publish quality scores and create CloudWatch dashboards with Glue and visualize trends in Amazon QuickSight

AWS Glue Data Quality evaluation results can in-export to S3 in format that can in-catalog by Glue Crawler. By data historis in S3, QuickSight can creates dashboard interaktif that menampilkan tren quality scores per source, trend degradation, and drill-down to specific rules. Ini provides visualisasi most kaya and interaktif.

Option A: INCORRECT. Only provides snapshot profiling, not time-series quality monitoring.
Option B: INCORRECT. Requires custom development.
Option C: INCORRECT. Has limitations visualization and retention — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option D: CORRECT.

An e-commerce company receives product catalog data from 50 different suppliers via daily CSV uploads to Amazon S3. Each supplier uses slightly different column names and formats for the same information (e.g., "product_name", "item_title", "prod_desc" all represent the product title). The data engineer needs to standardize these into a unified schema. Which approach is MOST maintainable as new suppliers are added?
  • A. Use Amazon Athena views with COALESCE across all possible column names for each logical field configured for optimal performance and minimal
  • B. Use AWS Glue ETL with a DynamicFrame and apply ApplyMapping transforms driven by a mapping configuration stored in DynamoDB
  • C. Use AWS Glue DataBrew with a parameterized recipe that applies column mapping rules from a configuration table
  • D. Create 50 separate AWS Glue ETL jobs, each with hardcoded column mappings for its supplier, applying schema conversion and enrichment inline
Correct Answer: B
Uses Glue ETL with configuration mapping in DynamoDB is approach most maintainable. When supplier new is added, quite adds entry in table configuration without changes code ETL. DynamicFrame with ApplyMapping supports schema that flexible.

Option A: INCORRECT. Menjadi very complex with 50+ supplier and cannot handles transformation format that different — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option B: CORRECT.
Option C: INCORRECT. Has limitations parameterisasi dibanding Glue ETL.
Option D: INCORRECT. Not scalable and maintenance nightmare.

A data engineer needs to verify data consistency between a source Amazon RDS MySQL database and a target Amazon Redshift data warehouse after an initial full load migration. The tables contain 500 million rows each. The verification must confirm that row counts match, aggregate values (SUM, AVG) for numeric columns are identical, and there are no missing records. What is the MOST efficient verification approach?
  • A. Use AWS DMS data validation feature which automatically compares source and target data during migration tasks
  • B. Write Python scripts to compute checksums on both databases and compare results and target data during migration tasks
  • C. Export both datasets to S3 and use a Glue ETL job to perform a full outer join to identify mismatches
  • D. Use Amazon Redshift federated queries to directly compare Redshift tables with RDS source tables
Correct Answer: A
AWS DMS has feature data validation bawaan that automatically membandingkan data between source and target during migration task. Fitur this performs row-by-row comparison, memeriksa row count, and melaporkan mismatches. Ini most efficient because terintegrasi directly with process migration.

Option A: CORRECT.
Option B: INCORRECT. Requires pengembangan and not scalable for volume this — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option C: INCORRECT. Very resource-intensive for 500M rows.
Option D: INCORRECT. Adds load to RDS production and network transfer large.
