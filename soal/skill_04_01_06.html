A company is migrating their on-premises PostgreSQL database to AWS. The security team requires that all operating system patches be applied within 48 hours of release and that the database engine is always on a supported version. They want to minimize operational overhead for these security requirements. Which service model best meets these needs?
  • A. Deploy PostgreSQL in containers on Amazon ECS with automated image rebuilds, meeting the latency and throughput goals of the design
  • B. Use Amazon EMR with PostgreSQL installed on cluster nodes and engine upgrades as part of AWS's shared responsibility
  • C. Deploy PostgreSQL on Amazon EC2 instances with a custom patching schedule using AWS Systems Manager Patch Manager
  • D. Use Amazon RDS for PostgreSQL, which handles OS patching and engine upgrades as part of AWS's shared responsibility
Correct Answer: D
Amazon RDS is managed service where AWS bertanggung jawab above OS patching, hardware maintenance, and provides engine version upgrades. In shared responsibility model for RDS, AWS manages: infrastructure layer, OS patching, database engine patching (scheduled maintenance windows), and hardware reliability. Customer only bertanggung jawab for: data encryption configuration, network access (Security Groups), IAM authentication, and managing database users/permissions.

Option A: INCORRECT. Still requires customer manages image updates and patching.
Option B: INCORRECT. Not database service that correct for PostgreSQL workload — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option C: INCORRECT. Is unmanaged — all patching becomes tanggung jawab customer including OS and database engine.
Option D: CORRECT.

A data engineering team is comparing AWS Glue (fully managed ETL) with Amazon EMR (semi-managed) for a data processing pipeline that handles sensitive healthcare data (HIPAA compliance required). The team needs to understand the security responsibility differences. Which statement CORRECTLY describes the shared responsibility model differences between these two services?
  • A. Amazon EMR is fully managed like Glue, so both have identical security responsibilities for customers configured for optimal performance and minimal operational overhead, integrating natively with the rest of the pipeline
  • B. For both Glue and EMR, customers are responsible for OS patching, network configuration, and encryption at rest, transforming records into the required target format and enforcing encryption and fine-grained access control
  • C. AWS Glue handles all security including data encryption and access control automatically, requiring no customer configuration, transforming records into the required target format and applying schema conversion and enrichment inline
  • D. For Glue, AWS manages the compute infrastructure, OS, and runtime security; for EMR, customers are additionally responsible for cluster OS hardening, security configurations on nodes, and custom bootstrap security scripts
Correct Answer: D
AWS Glue is fully managed — customer not melihat or manages underlying compute infrastructure, OS, or runtime. AWS handles all that. Customer Glue responsibilities: IAM permissions, data encryption settings, VPC connectivity, and job-level security configurations. Amazon EMR is semi-managed — AWS provides cluster provisioning and Hadoop ecosystem, but customer bertanggung jawab for: OS-level security hardening (custom AMIs), SSH key management, security group configurations on nodes, Kerberos/LDAP setup, encryption configuration in cluster level, and bootstrap action security.

Option A: INCORRECT. Incorrect — EMR and Glue has responsibility model that different — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option B: INCORRECT. Incorrect — Glue customers not manage OS.
Option C: INCORRECT. Incorrect — customers still must configure encryption and access control in Glue.
Option D: CORRECT.

This is example klasik perbedaan shared responsibility model between managed and unmanaged services. Amazon Redshift (managed): AWS manages underlying OS, hardware, patching, and infrastructure security. Customer bertanggung jawab for data, access control, network config (VPC/Security Groups), and encryption settings. EC2 + Spark (unmanaged/self-managed): Customer bertanggung jawab for ALL layer including OS patching, security hardening, middleware updates, and application security. AWS only bertanggung jawab for physical infrastructure (hypervisor to below).

Option A: INCORRECT. Incorrect — Redshift nodes has OS, but is managed AWS — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option B: INCORRECT. Not akurat — Redshift patching occurs during maintenance windows, not real-time zero-downtime.
Option C: INCORRECT. Incorrect — customer TIDAK bertanggung jawab patch OS Redshift.
Option D: CORRECT.

  • D.   • A. For both RDS and EC2 databases, AWS manages all network security including security groups and NACLs, running as a fully managed service with minimal operational overhead and satisfying all of the stated requirements with minimal effort and satisfying strict compliance and audit requirements
  • B. For RDS, AWS manages the internal network between primary and read replicas and handles failover networking, while customers manage Security Groups and subnet placement; for EC2 databases, customers manage ALL networking including replication traffic, failover, Security Groups, NACLs, and OS-level firewall rules (iptables)
  • C. EC2 databases have simpler network security because they only need Security Groups for EC2 databases, removing the need to provision or patch any infrastructure and enforcing encryption and fine-grained access control and protecting the data both in transit and at rest
  • D. RDS does not support VPC deployment and uses AWS-managed networking exclusively, removing the need to provision or patch any infrastructure and reducing day-to-day operational effort and satisfying strict compliance and audit requirements and satisfying all of the stated requirements with minimal effort
Correct Answer: B
Network security responsibilities different significant between managed and unmanaged. EC2 database (unmanaged): Customer manages ALL networking: replication traffic routing and encryption, failover mechanism (custom scripts/third-party), Security Groups, NACLs, OS-level firewall (iptables/nftables), DNS management, load balancing.

Option A: INCORRECT. Incorrect — customer manages Security Groups for RDS.
