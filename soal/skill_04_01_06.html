Skill 4.1.6: Describe the Differences Between Managed Services and Unmanaged Services

Understanding shared responsibility model for managed vs unmanaged data services

1
A company is migrating their on-premises PostgreSQL database to AWS. The security team requires that all operating system patches be applied within 48 hours of release and that the database engine is always on a supported version. They want to minimize operational overhead for these security requirements. Which service model best meets these needs?
  • A. Deploy PostgreSQL in containers on Amazon ECS with automated image rebuilds
  • B. Use Amazon EMR with PostgreSQL installed on cluster nodes and engine upgrades as part of AWS's shared responsibility
  • C. Deploy PostgreSQL on Amazon EC2 instances with a custom patching schedule using AWS Systems Manager Patch Manager
  • D. Use Amazon RDS for PostgreSQL, which handles OS patching and engine upgrades as part of AWS's shared responsibility
Jawaban Benar: D
Amazon RDS adalah managed service dimana AWS bertanggung jawab atas OS patching, hardware maintenance, dan menyediakan engine version upgrades. Dalam shared responsibility model untuk RDS, AWS mengelola: infrastructure layer, OS patching, database engine patching (scheduled maintenance windows), dan hardware reliability. Customer hanya bertanggung jawab untuk: data encryption configuration, network access (Security Groups), IAM authentication, dan managing database users/permissions.

Opsi A: SALAH. Masih memerlukan customer mengelola image updates dan patching.
Opsi B: SALAH. Bukan database service yang tepat untuk PostgreSQL workload — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi C: SALAH. Adalah unmanaged — semua patching menjadi tanggung jawab customer termasuk OS dan database engine.
Opsi D: BENAR.
2
A data engineering team is comparing AWS Glue (fully managed ETL) with Amazon EMR (semi-managed) for a data processing pipeline that handles sensitive healthcare data (HIPAA compliance required). The team needs to understand the security responsibility differences. Which statement CORRECTLY describes the shared responsibility model differences between these two services?
  • A. Amazon EMR is fully managed like Glue, so both have identical security responsibilities for customers configured for optimal performance and minimal operational overhead
  • B. For both Glue and EMR, customers are responsible for OS patching, network configuration, and encryption at rest
  • C. AWS Glue handles all security including data encryption and access control automatically, requiring no customer configuration
  • D. For Glue, AWS manages the compute infrastructure, OS, and runtime security; for EMR, customers are additionally responsible for cluster OS hardening, security configurations on nodes, and custom bootstrap security scripts
Jawaban Benar: D
AWS Glue adalah fully managed — customer tidak melihat atau mengelola underlying compute infrastructure, OS, atau runtime. AWS handles semua itu. Customer Glue responsibilities: IAM permissions, data encryption settings, VPC connectivity, dan job-level security configurations. Amazon EMR adalah semi-managed — AWS menyediakan cluster provisioning dan Hadoop ecosystem, tapi customer bertanggung jawab untuk: OS-level security hardening (custom AMIs), SSH key management, security group configurations pada nodes, Kerberos/LDAP setup, encryption configuration di cluster level, dan bootstrap action security.

Opsi A: SALAH. Salah — EMR dan Glue memiliki responsibility model yang berbeda — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi B: SALAH. Salah — Glue customers tidak manage OS.
Opsi C: SALAH. Salah — customers tetap harus configure encryption dan access control di Glue.
Opsi D: BENAR.
3
A company runs a data warehouse on Amazon Redshift (managed) and also has a self-managed Apache Spark cluster on EC2 instances. A security audit reveals that the Spark cluster's OS has unpatched vulnerabilities from 3 months ago. The auditors ask why Redshift doesn't have the same issue. What is the correct explanation?
  • A. Redshift doesn't use an operating system, so OS patches are not applicable with fully managed infrastructure and automatic scaling
  • B. Redshift automatically applies patches in real-time with zero downtime, unlike EC2 instances
  • C. The customer is responsible for patching both Redshift and EC2 instances, but Redshift has built-in automation that the customer must enable
  • D. Redshift is a managed service where AWS is responsible for applying OS patches and infrastructure maintenance within its shared responsibility, while the EC2-based Spark cluster requires the customer to manage all OS patching
Jawaban Benar: D
Ini adalah contoh klasik perbedaan shared responsibility model antara managed dan unmanaged services. Amazon Redshift (managed): AWS mengelola underlying OS, hardware, patching, dan infrastructure security. Customer bertanggung jawab untuk data, access control, network config (VPC/Security Groups), dan encryption settings. EC2 + Spark (unmanaged/self-managed): Customer bertanggung jawab untuk SEMUA layer termasuk OS patching, security hardening, middleware updates, dan application security. AWS hanya bertanggung jawab untuk physical infrastructure (hypervisor ke bawah).

Opsi A: SALAH. Salah — Redshift nodes memiliki OS, tapi dikelola AWS — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi B: SALAH. Tidak akurat — Redshift patching terjadi selama maintenance windows, bukan real-time zero-downtime.
Opsi C: SALAH. Salah — customer TIDAK bertanggung jawab patch OS Redshift.
Opsi D: BENAR.
4
A financial services company must demonstrate compliance with SOC 2 and PCI DSS for their data analytics platform. They are evaluating whether to use Amazon Athena (serverless/managed) or deploy Presto on EC2 instances (unmanaged). How do compliance certifications differ between these approaches?
  • A. Both approaches inherit AWS compliance certifications equally since they both run on AWS infrastructure
  • B. Amazon Athena inherits AWS compliance certifications (SOC 2, PCI DSS) for the service infrastructure layer, while EC2+Presto only inherits physical infrastructure certifications — the customer must independently certify all software layers above the hypervisor
  • C. Neither approach provides any compliance certifications — the customer must obtain all certifications independently regardless of the service model
  • D. Amazon Athena provides automatic PCI DSS compliance for all data processed through it without additional customer controls configured for optimal performance and minimal operational overhead
Jawaban Benar: B
Managed services seperti Athena termasuk dalam scope AWS compliance programs (SOC 2, PCI DSS, HIPAA eligible, dll.) — artinya AWS telah disertifikasi untuk mengelola infrastructure dan service layer dengan standar tersebut. Customer mewarisi sertifikasi ini untuk bagian yang dikelola AWS. Untuk EC2+Presto (unmanaged), AWS compliance hanya mencakup physical infrastructure (data center, hardware, hypervisor). Semua layer di atas — OS, database software, application — menjadi tanggung jawab customer untuk memenuhi standar compliance. Customer harus melakukan: OS hardening, access logging, encryption implementation, dan mendokumentasikan semua controls untuk auditor.

Opsi A: SALAH. Salah — level inheritance berbeda.
Opsi B: BENAR.
Opsi C: SALAH. Salah — AWS certifications DO transfer sebagian.
Opsi D: SALAH. Salah — compliance masih memerlukan customer controls (encryption, access management, dll — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.).
5
A data engineer needs to implement encryption at rest for sensitive data. They are comparing the encryption responsibilities between Amazon DynamoDB (managed) and a MongoDB deployment on EC2 (unmanaged). Which statement accurately describes the encryption responsibility differences?
  • A. DynamoDB requires customers to implement their own encryption libraries, while MongoDB on EC2 has built-in encryption
  • B. Encryption is only available for managed services and cannot be implemented on EC2-based databases
  • C. For DynamoDB, AWS provides integrated encryption at rest using AWS-managed keys or customer-managed CMKs with no OS-level configuration needed; for MongoDB on EC2, the customer must configure encryption at multiple layers: EBS volume encryption, MongoDB's WiredTiger encryption engine, and manage key rotation independently
  • D. Both services encrypt data automatically with no customer action required and manage key rotation independently for MongoDB on EC2
Jawaban Benar: C
DynamoDB (managed) menyediakan encryption at rest secara terintegrasi — customer cukup memilih antara AWS owned key, AWS managed key, atau customer managed CMK. AWS menangani semua implementasi teknis (no OS/filesystem level config). Untuk MongoDB di EC2 (unmanaged), customer bertanggung jawab untuk multiple encryption layers: (1) EBS volume encryption — menggunakan KMS key, (2) MongoDB WiredTiger encryption — konfigurasi encryptionKeyFile dan encryptionCipherMode, (3) Key management — rotasi, storage, access control untuk encryption keys, (4) TLS/SSL configuration untuk in-transit encryption. Operational overhead jauh lebih tinggi.

Opsi A: SALAH. Salah — DynamoDB memiliki native encryption, bukan customer-built.
Opsi B: SALAH. Salah — encryption sangat bisa diimplementasikan di EC2.
Opsi C: BENAR.
Opsi D: SALAH. Salah — MongoDB di EC2 memerlukan explicit configuration — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
6
A startup is choosing between Amazon Kinesis Data Streams (managed) and self-managed Apache Kafka on EC2 for real-time data streaming. The team has only 2 data engineers and limited operational capacity. Which security and operational considerations MOST strongly favor the managed service in this scenario?
  • A. Kinesis supports more message formats than Kafka
  • B. With Kinesis, AWS manages infrastructure patching, availability (multi-AZ replication), and provides integrated IAM-based access control; with Kafka on EC2, the team would need to manage ZooKeeper security, broker certificate management, SASL/SCRAM authentication setup, OS patching, and multi-AZ deployment manually
  • C. Kafka on EC2 provides better security because the team has full control over all security configurations
  • D. Kinesis costs less than Kafka on EC2 at all scales with Kafka on EC2
Jawaban Benar: B
Untuk tim kecil (2 engineers), operational overhead security dari self-managed Kafka sangat berat: ZooKeeper security hardening, Kafka broker TLS certificate management dan rotation, SASL/SCRAM atau mTLS authentication configuration, ACL management, OS patching pada semua nodes, multi-AZ setup untuk HA, monitoring cluster security posture. Amazon Kinesis sebagai managed service menghilangkan semua itu — AWS menangani infrastructure security, menyediakan native IAM integration untuk access control, built-in encryption (at rest dan in-transit), dan automatic multi-AZ availability. Tim hanya perlu fokus pada IAM policies dan application-level security.

Opsi A: SALAH. Salah — keduanya format-agnostic (bytes).
Opsi B: BENAR.
Opsi C: SALAH. Keliru — full control tanpa expertise/resources justru meningkatkan risk.
Opsi D: SALAH. Tidak selalu benar — cost tergantung scale dan usage — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
7
A data engineer is reviewing the network security model for Amazon RDS (managed) vs a database running on EC2 (unmanaged), both deployed in a VPC. Which statement CORRECTLY describes the network security responsibility differences?
  • A. For both RDS and EC2 databases, AWS manages all network security including security groups and NACLs
  • B. For RDS, AWS manages the internal network between primary and read replicas and handles failover networking, while customers manage Security Groups and subnet placement; for EC2 databases, customers manage ALL networking including replication traffic, failover, Security Groups, NACLs, and OS-level firewall rules (iptables)
  • C. EC2 databases have simpler network security because they only need Security Groups for EC2 databases
  • D. RDS does not support VPC deployment and uses AWS-managed networking exclusively
Jawaban Benar: B
Network security responsibilities berbeda signifikan antara managed dan unmanaged. RDS (managed): AWS mengelola internal networking antara primary instance dan replicas, Multi-AZ synchronous replication traffic, automated failover routing, dan DNS endpoint management. Customer mengelola: VPC subnet group selection, Security Group rules (inbound/outbound), public accessibility setting, dan SSL/TLS enforcement. EC2 database (unmanaged): Customer mengelola SEMUA networking: replication traffic routing dan encryption, failover mechanism (custom scripts/third-party), Security Groups, NACLs, OS-level firewall (iptables/nftables), DNS management, load balancing.

Opsi A: SALAH. Salah — customer mengelola Security Groups untuk RDS.
Opsi B: BENAR.
Opsi C: SALAH. Salah — EC2 memerlukan lebih banyak network security layers — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi D: SALAH. Salah — RDS berjalan di VPC.
8
A company must choose between AWS Glue DataBrew (fully managed) and running custom PySpark data quality scripts on EMR (semi-managed) for data preparation. The CISO asks about the security update lifecycle differences. Which answer correctly explains the patching and update responsibilities?
  • A. Both services require manual patching by the customer on a monthly schedule with no customer action needed for the compute/runtime layer; EMR requires customers and handle bootstrap script security
  • B. EMR automatically patches all cluster nodes without any customer intervention similar to Glue DataBrew
  • C. Glue DataBrew receives security updates transparently from AWS with no customer action needed for the compute/runtime layer; EMR requires customers to manage AMI updates, apply security patches to cluster nodes, update Hadoop/Spark framework versions, and handle bootstrap script security
  • D. AWS does not provide security patches for either service — customers must build custom security solutions
Jawaban Benar: C
AWS Glue DataBrew (serverless/fully managed): AWS menangani semua patching — OS, runtime, libraries, dan framework updates terjadi transparently. Customer tidak perlu schedule maintenance windows atau track CVEs untuk infrastructure layer. EMR (semi-managed): Meskipun AWS menyediakan EMR releases dengan updated software, customer bertanggung jawab untuk: (1) Memilih dan updating ke EMR release version terbaru, (2) Custom AMI patching jika menggunakan custom AMIs, (3) Monitoring untuk security vulnerabilities di Hadoop ecosystem components, (4) Updating bootstrap actions yang mungkin install software tambahan, (5) Cluster replacement untuk menerapkan patches (in-place patching tidak selalu feasible).

Opsi A: SALAH. Salah — DataBrew tidak perlu manual patching — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi B: SALAH. Salah — EMR tidak auto-patch existing clusters.
Opsi C: BENAR.
Opsi D: SALAH. Salah — AWS menyediakan patched releases.

An organization is evaluating Amazon OpenSearch Service (managed) versus self-hosted Elasticsearch on EC2 for their log analytics platform. A security requirement mandates that all inter-node communication must be encrypted. How does this requirement differ between the two approaches?
  • A. Amazon OpenSearch Service provides node-to-node encryption as a configurable option that AWS manages (certificate provisioning, rotation, and TLS termination); self-hosted Elasticsearch on EC2 requires the customer to generate, distribute, and rotate TLS certificates across all nodes, configure elasticsearch.yml for transport layer TLS, and manage a PKI infrastructure
  • B. Both approaches require identical manual TLS certificate configuration on each node
  • C. Amazon OpenSearch Service encrypts inter-node traffic by default with no option to disable it, while EC2 Elasticsearch never encrypts inter-node traffic
  • D. Inter-node encryption is not possible with self-hosted Elasticsearch and is exclusive to the managed service for transport layer TLS
Jawaban Benar: A
Amazon OpenSearch Service (managed): Node-to-node encryption diaktifkan dengan single checkbox/API call. AWS menangkan seluruh PKI infrastructure — certificate generation, distribution ke semua nodes, automatic rotation, dan TLS configuration. Customer tidak perlu mengelola certificates. Self-hosted Elasticsearch pada EC2 (unmanaged): Customer harus mengelola complete PKI: (1) Setup Certificate Authority (CA), (2) Generate certificates per node, (3) Distribute certificates secara secure, (4) Configure elasticsearch.yml dengan xpack.security.transport.ssl settings, (5) Implement certificate rotation sebelum expiry, (6) Monitor certificate validity. Operational overhead sangat signifikan.

Opsi A: BENAR.
Opsi B: SALAH. Salah — managed service tidak perlu manual cert config.
Opsi C: SALAH. Tidak akurat — OpenSearch Service node-to-node encryption adalah opt-in feature saat domain creation.
Opsi D: SALAH. Salah — inter-node encryption sangat mungkin di self-hosted (Elasticsearch X-Pack/OpenSearch Security) — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.

A company's security policy requires a comprehensive inventory of all software components and their versions for vulnerability management. The data platform uses both Amazon Redshift Serverless (managed) and Apache Hive on EMR EC2 instances (semi-managed). The security team asks: "For which components is the customer responsible for tracking software versions and applying security patches?" Which answer is MOST accurate?
  • A. For Redshift Serverless, AWS manages all software component versions and patching (customers only manage their SQL code and access controls); for EMR, customers must track versions and patch: the EMR release, custom applications installed via bootstrap, any additional libraries/JARs added to the cluster, and custom AMI components if used
  • B. Customers must request specific patch versions from AWS support for both managed and unmanaged services with fully managed infrastructure and automatic scaling
  • C. Customers are responsible for tracking and patching all software versions on both Redshift Serverless and EMR
  • D. Neither service requires customer involvement in software version management since AWS patches everything automatically
Jawaban Benar: A
Redshift Serverless (fully managed): AWS bertanggung jawab penuh atas semua software layers — engine version, OS, libraries, dependencies. Customer TIDAK perlu track atau patch infrastructure components. Tanggung jawab customer hanya: SQL stored procedures, user management, access controls, dan data classification. EMR (semi-managed): Meskipun AWS menyediakan pre-packaged EMR releases, customer bertanggung jawab untuk: (1) Memilih EMR release version yang sesuai (dan upgrading), (2) Custom software installed via bootstrap actions — tracking versions dan security, (3) Additional JAR dependencies yang di-upload, (4) Custom AMI components jika digunakan, (5) Python/R packages yang di-install via pip/conda. Untuk vulnerability management, tim harus maintain Software Bill of Materials (SBOM) untuk semua custom components di EMR.

Opsi A: BENAR.
Opsi B: SALAH. Bukan cara kerja AWS patching — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi C: SALAH. Salah — Redshift Serverless fully managed.
Opsi D: SALAH. Salah — EMR memerlukan customer involvement.
