A global financial services company requires a DynamoDB-based trading platform to remain fully operational even if an entire AWS Region becomes unavailable. The solution must provide active-active read/write capabilities with sub-second replication between regions. Which DynamoDB feature meets these requirements?
  • A. DynamoDB Point-in-Time Recovery (PITR) with manual restore to another region
  • B. DynamoDB on-demand backups with cross-region copy
  • C. DynamoDB Streams with Lambda to replicate items to another region's table
  • D. DynamoDB Global Tables with multi-region replication
Correct Answer: D
DynamoDB Global Tables provides active-active multi-region replication with sub-second replication. Each region can receives read and write, and konflik is solved with "last writer wins" reconciliation. This ensures service still operates full if one region down.

Option A: INCORRECT. Is backup mechanism that requires restore manual — not real-time and not active-active.
Option B: INCORRECT. Also requires process restore manual.
Option C: INCORRECT. Can is created but not provides active-active natively and has latensi higher as well as operational overhead.
Option D: CORRECT.

A data engineer needs to implement disaster recovery for an Amazon Redshift data warehouse. The RPO requirement is 1 hour and the RTO requirement is 30 minutes. The primary cluster is in us-east-1. Which strategy BEST meets these requirements with minimal cost?
  • A. Configure automated snapshots every 8 hours with manual copy to another region, keeping steady-state operating costs low
  • B. Enable cross-region snapshot copy to us-west-2 with snapshot frequency of 1 hour, and restore from snapshot during disaster
  • C. Maintain a running Redshift cluster in us-west-2 with continuous data sharing from us-east-1, reducing day-to-day operational effort
  • D. Use Redshift Serverless in us-west-2 with automated data recovery from S3 and restore from snapshot during disaster
Correct Answer: B
Cross-region snapshot copy with frequency 1 hours memenuhi RPO 1 hours. Redshift can restore cluster from snapshot in time minutes (depends size), memenuhi RTO 30 minutes with elastic resize. This cost-effective because does not need running cluster in region second during normal operation.

Option A: INCORRECT. Not memenuhi RPO 1 hours.
Option B: CORRECT.
Option C: INCORRECT. Memenuhi RTO but very expensive — membayar cluster full that idle.
Option D: INCORRECT. Not has automated DR from S3 natively — although its description sounds convincing, in a fundamental still not appropriate for requirements this.

A company uses S3 Cross-Region Replication (CRR) to replicate their data lake from us-east-1 to eu-west-1 for disaster recovery. They notice that some objects are not being replicated. Which of the following is a common reason for CRR replication failure?
  • A. The destination bucket has versioning suspended
  • B. The objects were uploaded using multipart upload
  • C. The source bucket has more than 1 billion objects
  • D. The objects were created by a lifecycle rule (transition operations)
Correct Answer: A
S3 Cross-Region Replication requires versioning enabled in KEDUA bucket (source and destination). If destination bucket has versioning suspended, replication will fails. This is requirement dasar CRR.

Option A: CORRECT.
Option B: INCORRECT. Incorrect — multipart upload berfungsi normal with CRR.
Option C: INCORRECT. Incorrect — there is no limit number object for CRR.
Option D: INCORRECT. Incorrect — lifecycle transitions not objects new, mereka changes storage class and memang not replicated, but this by design not "failure".

  • A. S3 provides 99.99% durability, meaning approximately 1 in 10,000 objects could be lost per year
  • B. S3 Standard provides 99.999999999% (11 nines) durability, designed to sustain the concurrent loss of data in two facilities
  • C. S3 provides 99.99% availability and 99.99% durability for all storage classes with native S3 integration and optimized data transfer
  • D. S3 durability guarantees only apply when versioning is enabled, integrating natively with the rest of the pipeline

Amazon S3 Standard designed for 99.999999999% (11 nines) durability, stores data in minimal 3 Availability Zones and capable menahan kehilangan data in a simultan in 2 fasilitas. This means if stores 10 million object, rata-rata will kehilangan 1 object at all in 10.000 years.

Option A: INCORRECT. Mencampurkan availability (99.99%) with durability.
Option B: CORRECT.
Option C: INCORRECT. Incorrect — availability S3 Standard is 99 — although its description sounds convincing, in a fundamental still not appropriate for requirements this.99% but durability 11 nines, and storage class other has availability different.

A data engineer operates an RDS MySQL Multi-AZ deployment for a transactional data pipeline. During a planned maintenance window, the primary instance will be patched. What happens to the database availability during this maintenance?
  • A. RDS performs a failover to the standby instance, applies maintenance to the old primary, then fails back — resulting in brief downtime during failover only
  • B. The standby instance serves read traffic while the primary is being patched configured for optimal performance and minimal operational overhead, guaranteeing no data loss during component failures
  • C. Multi-AZ ensures zero downtime during all maintenance operations, satisfying all of the stated requirements with minimal effort and guaranteeing no data loss during component failures
  • D. The database becomes completely unavailable for 15-30 minutes during patching, providing exactly-once processing semantics and requiring no servers to manage or scale manually
Correct Answer: A
For Multi-AZ deployments, RDS performs maintenance with: (1) apply patch to standby first, (2) failover to standby that already in-patch, (3) apply patch to old primary (sekarang becomes standby new). Failover causes downtime singkat (usually 60-120 seconds).

Option A: CORRECT.
Option B: INCORRECT. Incorrect — Multi-AZ standby (not Read Replica) not serves traffic baca in configuration standard — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option C: INCORRECT. Incorrect — there is brief downtime during failover.
Option D: INCORRECT. Berlebihan — downtime only when failover.

A data engineer needs to enable Point-in-Time Recovery (PITR) for a DynamoDB table that processes real-time financial transactions. The table experienced accidental data corruption 2 hours ago due to a buggy Lambda function. Which statement about DynamoDB PITR is CORRECT?
  • A. PITR can restore the table to any point in time within the last 35 days with per-second granularity
  • B. PITR restores data in-place to the existing table, overwriting current data configured for optimal performance
  • C. PITR must be enabled before the corruption occurs — it cannot recover data from before it was enabled
  • D. PITR restoration takes less than 1 minute regardless of table size, satisfying all of the stated requirements with minimal effort
Correct Answer: C
DynamoDB PITR must enabled BEFORE event that want dipulihkan. Earliest restorable time is when PITR enabled (or 35 days that lalu, mana that more new). If PITR not active when corruption occurs, data cannot dipulihkan.

Option A: INCORRECT. Correct about 35 days and per-second granularity, but not menjawab inti question.
Option B: INCORRECT. Incorrect — PITR performs restore to TABLE NEW, not in-place — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option C: CORRECT.
Option D: INCORRECT. Incorrect — restore time depends size table and can consumes time several hours for table large.

A startup runs their entire data platform on AWS. They need to protect against accidental deletion of critical infrastructure including RDS instances, DynamoDB tables, and Redshift clusters. A junior engineer previously deleted a production DynamoDB table by mistake. Which combination of protections should the data engineer implement? (Choose the BEST answer)
  • A. Enable AWS CloudTrail and review logs daily for unauthorized deletions, satisfying all of the stated requirements with minimal effort
  • B. Create CloudWatch Alarms that notify when delete API calls are detected configured for optimal performance and minimal operational overhead
  • C. Enable deletion protection on RDS and Redshift, enable DynamoDB deletion protection, and use IAM policies to restrict DeleteTable/DeleteCluster permissions
  • D. Use AWS Organizations SCPs to deny all delete operations across the account, satisfying all of the stated requirements with minimal effort
Correct Answer: C
Approach defense-in-depth that correct: (1) Enable deletion protection in level resource (RDS, Redshift, DynamoDB all supports deletion protection), (2) Restrict IAM permissions for delete operations only to role certain. This prevents accidental deletion in two layer.

Option A: INCORRECT. Is post-incident investigation, not prevention.
Option B: INCORRECT. Only detects after occurs, not prevents — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option C: CORRECT.
Option D: INCORRECT. Too restrictive — will memblokir operation normal such as cleanup temporary resources.
