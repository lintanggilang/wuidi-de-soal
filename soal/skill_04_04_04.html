A data engineering team stores CloudTrail logs in S3 partitioned by year/month/day. They need to query these logs to investigate a security incident that occurred on a specific date. The CloudTrail log bucket contains 5 years of data totaling 50 TB. The team wants to minimize query costs. Which Athena configuration provides the MOST cost-effective querying?
  • A. Create an Athena table with Hive-style partitioning matching the S3 path structure and use WHERE clauses on partition columns
  • B. Create a CTAS (Create Table As Select) query to copy the relevant day's data to a new table in Parquet format, then query that table
  • C. Create an Athena table without partitions and use the built-in CloudTrail SerDe to filter by eventTime with date-type partition keys matching the S3 path pattern
  • D. Use Athena partition projection with date-type partition keys matching the S3 path pattern to avoid partition metadata management
Jawaban Benar: D
Partition projection menghilangkan kebutuhan untuk menjalankan MSCK REPAIR TABLE atau menambah partisi secara manual, yang sangat penting untuk data yang terus bertambah setiap hari. Dengan date-type projection matching path pattern (s3://bucket/AWSLogs/account/CloudTrail/region/yyyy/mm/dd/), Athena secara otomatis menghitung partisi tanpa metadata calls ke Glue catalog. Query dengan WHERE date = '2024-03-15' hanya scan data hari itu (~27 GB vs 50 TB), sangat mengurangi biaya.

Opsi A: SALAH. Berfungsi tapi memerlukan maintenance partisi manual.
Opsi B: SALAH. Memerlukan scan full data terlebih dahulu dan menambah biaya storage.
Opsi C: SALAH. Tanpa partisi akan scan seluruh 50 TB (sangat mahal) — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi D: BENAR.
2
A DevOps engineer needs to quickly identify the top 10 Lambda functions generating the most errors in the past hour across all production Lambda log groups. The log groups follow the naming pattern /aws/lambda/prod-*. The engineer needs results within seconds. Which tool and approach is MOST appropriate?
  • A. Use Amazon Athena to query exported Lambda logs in S3 with a GROUP BY function name
  • B. Use CloudWatch Logs Insights to query multiple log groups simultaneously with a stats command grouping by function name
  • C. Use CloudWatch Metrics to view the Errors metric filtered by FunctionName dimension with a stats command grouping by function name
  • D. Use Amazon OpenSearch Service with a pre-built Kibana dashboard showing Lambda error rates, streaming results downstream in near real time
Jawaban Benar: B
CloudWatch Logs Insights dapat query hingga 50 log groups secara bersamaan dan memberikan hasil dalam hitungan detik untuk data recent. Query: `filter @message like /ERROR/ | stats count(*) as errorCount by @logGroup | sort errorCount desc | limit 10` akan memberikan top 10 functions dengan error terbanyak. Mendukung wildcard pattern untuk log group selection.

Opsi A: SALAH. Memerlukan export ke S3 terlebih dahulu dan tidak memberikan hasil real-time.
Opsi B: BENAR.
Opsi C: SALAH. Menunjukkan error count per function tapi tidak memberikan ranking top-N dalam satu query dan memerlukan navigasi manual — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi D: SALAH. Memerlukan setup dan ingestion pipeline yang sudah berjalan — bukan solusi "quick".

A company needs to build a real-time security dashboard that displays: login failures, API throttling events, and unauthorized access attempts with sub-second search latency. The dashboard must support full-text search across all log fields and provide alerting capabilities. Data volume is 2 TB per day. Which AWS service is BEST suited for this use case?
  • A. Amazon OpenSearch Service with OpenSearch Dashboards and alerting plugin
  • B. CloudWatch Logs Insights with CloudWatch Dashboards and CloudWatch Alarms
  • C. Amazon Redshift Serverless with materialized views refreshed every minute
  • D. Amazon Athena with scheduled queries feeding a QuickSight dashboard
Jawaban Benar: A
Amazon OpenSearch Service memenuhi semua requirements: sub-second search latency melalui inverted indexing, full-text search across all fields, real-time dashboards via OpenSearch Dashboards (Kibana successor), dan built-in alerting plugin untuk notifications. Dengan 2 TB/day, OpenSearch dapat menangani volume ini dengan cluster yang appropriately sized.

Opsi A: BENAR.
Opsi B: SALAH. Memiliki query latency beberapa detik dan tidak mendukung full-text search dengan sub-second response pada 2 TB daily data.
Opsi C: SALAH. Tidak dioptimasi untuk full-text search dan materialized view refresh setiap menit bukan real-time.
Opsi D: SALAH. Bersifat batch dan tidak memberikan sub-second latency untuk interactive search.

A data engineer writes the following CloudWatch Logs Insights query to analyze API Gateway access logs but gets no results despite logs being present in the log group. What is the MOST likely issue?

fields @timestamp, @message | filter status >= 500 | stats count(*) by bin(5m)
  • A. The stats command cannot be used after a filter command — the order must be reversed, handling the described workload reliably at scale and integrating natively with the rest of the pipeline
  • B. The bin() function requires a time field parameter — it should be bin(@timestamp, 5m) configured for optimal performance and minimal operational overhead, satisfying all of the stated requirements with minimal effort
  • C. The field "status" needs to be parsed from the log message first using the parse command since API Gateway logs store it as part of a JSON or text string
  • D. CloudWatch Logs Insights does not support the >= comparison operator for string fields, handling the described workload reliably at scale and meeting the latency and throughput goals of the design
Jawaban Benar: C
API Gateway access logs, jika dalam format custom atau CLF, menyimpan status code sebagai bagian dari pesan log. CloudWatch Logs Insights memerlukan `parse` command untuk mengekstrak fields dari log messages yang tidak dalam format JSON yang otomatis di-discover. Contoh: `parse @message "* * * *" as ip, method, path, status | filter status >= 500`. Untuk JSON logs, fields otomatis tersedia tapi harus direferensikan dengan prefix yang benar.

Opsi A: SALAH. Salah — filter sebelum stats adalah urutan yang benar dan valid.
Opsi B: SALAH. Salah — `bin(5m)` adalah syntax valid yang menggunakan @timestamp secara implisit — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi C: BENAR.
Opsi D: SALAH. Salah — >= operator bekerja setelah field di-parse dengan benar.

A company has the following log analysis requirements: (1) VPC Flow Logs — 500 GB/day, queried weekly for compliance reports, (2) Application logs — 50 GB/day, queried interactively multiple times daily, (3) CloudTrail logs — 10 GB/day, queried occasionally during investigations. Which combination of tools provides the MOST cost-effective solution while meeting latency requirements?
  • A. Use CloudWatch Logs Insights for all three log types since they all originate from AWS services with partitioned Parquet)
  • B. VPC Flow Logs → Athena (S3 with Parquet), Application logs → CloudWatch Logs Insights, CloudTrail → CloudTrail Lake
  • C. VPC Flow Logs → Athena (S3 with partitioned Parquet), Application logs → OpenSearch Service, CloudTrail → Athena with partition projection
  • D. Use Amazon OpenSearch Service for all three log types with index lifecycle management for cost optimization, minimizing end-to-end processing latency
Jawaban Benar: C
Solusi optimal memilih tool berdasarkan volume, frekuensi query, dan latency requirement: (1) VPC Flow Logs 500 GB/day yang di-query weekly cocok untuk Athena + S3 Parquet — biaya storage rendah dan bayar per query, partisi mengurangi scan. (2) Application logs 50 GB/day dengan interactive queries multiple times/day cocok untuk OpenSearch yang memberikan sub-second latency dan rich dashboards. (3) CloudTrail 10 GB/day yang jarang di-query cocok untuk Athena — biaya sangat rendah karena jarang query.

Opsi A: SALAH. CloudWatch Logs Insights memiliki biaya ingestion tinggi untuk 500 GB/day — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi B: SALAH. Bisa bekerja tapi CloudWatch Logs Insights kurang ideal untuk 50 GB/day interactive analysis dan CloudTrail Lake mahal untuk occasional queries.
Opsi C: BENAR.
Opsi D: SALAH. Sangat mahal untuk 500 GB/day VPC logs yang jarang diquery.

A data engineer needs to create an Athena table for structured query of CloudTrail logs stored in S3. The logs are in JSON format with nested fields like userIdentity, requestParameters, and responseElements. Which table creation approach provides the BEST query performance and cost efficiency?
  • A. Use CTAS to convert all CloudTrail JSON to Parquet format with columnar storage, then query the Parquet table
  • B. Use CREATE TABLE with the CloudTrail SerDe, define struct types for nested fields, add partition projection for date-based partitions
  • C. Use CREATE TABLE with OpenX JSON SerDe (org.openx.data.jsonserde.JsonSerDe) and define all fields as STRING type for simplicity
  • D. Use CREATE TABLE with the CloudTrail SerDe (com.amazon.emr.hive.serde.CloudTrailSerde) and define the full nested schema including partition columns for date
Jawaban Benar: B
Menggunakan CloudTrail SerDe yang didesain khusus untuk format CloudTrail JSON, mendefinisikan struct types untuk nested fields (userIdentity STRUCT), dan partition projection untuk tanggal memberikan kombinasi terbaik. Struct types memungkinkan dot notation queries (userIdentity.arn) dan partition projection mengeliminasi overhead metadata management.

Opsi A: SALAH. Memberikan performance terbaik per-query tapi memerlukan proses konversi ongoing dan double storage costs.
Opsi B: BENAR.
Opsi C: SALAH. Kehilangan kemampuan query nested fields secara langsung — harus menggunakan JSON functions yang lebih lambat.
Opsi D: SALAH. Tanpa partition projection memerlukan manual partition management.

A company uses Amazon OpenSearch Service for log analytics. Their OpenSearch cluster stores 30 days of hot data (5 TB) for dashboards and alerting. After 30 days, data should still be searchable but with relaxed latency requirements (up to 10 seconds). After 90 days, data should be archived for compliance only. Which index lifecycle configuration is MOST cost-effective?
  • A. Hot tier (0-30 days) → Delete after 30 days and export to S3 for Athena queries
  • B. Hot tier (0-30 days) → Warm tier (30-90 days) → Delete after 90 days with snapshots to S3
  • C. Hot tier (0-30 days) → UltraWarm tier (30-90 days) → Cold storage (90+ days)
  • D. Single hot tier for all data with force merge of older indices to reduce shard count
Jawaban Benar: C
OpenSearch Service menyediakan tiga tiers: Hot (instance store/EBS, fastest), UltraWarm (S3-backed, cost-effective untuk data yang jarang diakses tapi masih searchable), dan Cold storage (paling murah, data harus di-attach kembali ke warm sebelum bisa di-search). Konfigurasi B memenuhi semua requirements: hot untuk dashboards real-time (0-30d), UltraWarm untuk searchable dengan latency lebih tinggi (30-90d), cold untuk compliance archival (90d+).

Opsi A: SALAH. Kehilangan kemampuan search di OpenSearch setelah 30 hari.
Opsi B: SALAH. Menghapus data setelah 90 hari padahal compliance masih memerlukan retention.
Opsi C: BENAR.
Opsi D: SALAH. Sangat mahal karena hot tier untuk semua data.

A data platform team wants to identify the top contributors to high API error rates using CloudWatch. They need to see which specific API endpoints, client IPs, and user agents contribute most to 5xx errors, updated in real-time. Which CloudWatch feature is specifically designed for this type of top-N analysis?
  • A. CloudWatch Contributor Insights with rules matching error status codes and grouping by endpoint, IP, and user agent
  • B. CloudWatch Logs Insights with stats command and sort by count descending and grouping by endpoint, IP, and user agent
  • C. CloudWatch Metrics with high-resolution custom metrics and dimension filtering, minimizing end-to-end processing latency and keeping steady-state operating costs low
  • D. CloudWatch Anomaly Detection to identify unusual patterns in error rates per dimension, delivering records with consistent sub-second latency
Jawaban Benar: A
CloudWatch Contributor Insights dirancang khusus untuk top-N analysis secara real-time. Rules dapat dikonfigurasi untuk memfilter log events (misalnya status >= 500) dan mengelompokkan berdasarkan field keys (endpoint, sourceIP, userAgent). Dashboard secara otomatis menampilkan top contributors yang berubah secara real-time.

Opsi A: BENAR.
Opsi B: SALAH. Bukan real-time — setiap query adalah point-in-time dan harus dijalankan ulang secara manual — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi C: SALAH. Memerlukan pre-aggregation dan tidak memberikan dynamic top-N ranking.
Opsi D: SALAH. Mendeteksi deviasi dari baseline tapi tidak dirancang untuk ranking top contributors.

A company spends $15,000/month on log analytics across multiple tools. Their current setup uses OpenSearch Service for all log types (application, infrastructure, security) with 10 TB of active data. Most queries target the last 24 hours of security logs (500 GB). Infrastructure logs (7 TB) are queried only monthly for capacity planning. Which optimization reduces costs the MOST while maintaining functionality?
  • A. Reduce OpenSearch instance sizes and enable UltraWarm for all data older than 1 hour with Athena monthly
  • B. Replace OpenSearch entirely with Amazon Managed Grafana querying CloudWatch metrics, keeping steady-state operating costs low and providing exactly-once processing semantics
  • C. Migrate all logs from OpenSearch to CloudWatch Logs Insights to eliminate cluster management costs, handling the described workload reliably at scale
  • D. Keep security and application logs in OpenSearch (3 TB), move infrastructure logs to S3 and query with Athena monthly
Jawaban Benar: D
Infrastructure logs (7 TB) yang hanya di-query monthly merupakan 70% dari active data tapi jarang diakses. Memindahkannya ke S3 (biaya ~$0.023/GB/month) dan query dengan Athena ($5/TB scanned) monthly jauh lebih murah dari menyimpan di OpenSearch hot nodes. Mengecilkan OpenSearch cluster dari 10 TB ke 3 TB memberikan penghematan signifikan pada instance costs.

Opsi A: SALAH. Terlalu agresif dan membuat interactive queries lambat untuk security investigation — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi B: SALAH. Kehilangan kemampuan full log analysis — metrics bukan pengganti log search.
Opsi C: SALAH. Akan sangat mahal untuk 10 TB data ingestion.
Opsi D: BENAR.

A data engineer needs to create a CloudWatch Logs Insights query that calculates the p99 latency for each API endpoint from application logs. The logs are in JSON format with fields: endpoint, method, latency_ms, status_code, and timestamp. Which query correctly produces the p99 latency per endpoint sorted by highest latency first?
  • A. filter ispresent(latency_ms) | stats avg(latency_ms) as p99 by endpoint | sort p99 desc
  • B. fields endpoint, latency_ms | stats percentile(latency_ms, 99) as p99 by endpoint | sort p99 desc
  • C. fields endpoint, latency_ms | stats p99(latency_ms) as p99_latency by endpoint | sort p99_latency desc
  • D. fields endpoint, latency_ms | stats pct(latency_ms, 99) as p99 by endpoint | sort p99 desc
Jawaban Benar: B
Dalam CloudWatch Logs Insights, fungsi `percentile(field, percent)` menghitung persentil yang ditentukan. Syntax `stats percentile(latency_ms, 99) as p99 by endpoint` mengelompokkan berdasarkan endpoint dan menghitung p99 latency. `sort p99 desc` mengurutkan dari tertinggi.

Opsi A: SALAH. Menggunakan `avg()` yang menghitung rata-rata, bukan persentil ke-99.
Opsi B: BENAR.
Opsi C: SALAH. Menggunakan `p99()` yang bukan syntax function yang valid — harus menggunakan percentile(field, 99).
Opsi D: SALAH. Menggunakan `pct()` yang bukan fungsi valid di CloudWatch Logs Insights — fungsi yang benar adalah `percentile()`.
