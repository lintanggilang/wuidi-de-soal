A data engineering team needs to orchestrate a complex ETL pipeline that includes: running an AWS Glue crawler, then a Glue ETL job, followed by an Amazon Redshift COPY command, and finally a data quality validation step. The pipeline has complex dependencies between steps, and some steps must wait for external events (like file arrivals). The team already has extensive experience with Apache Airflow. Which orchestration service is MOST appropriate?
  • A. Amazon MWAA (Managed Workflows for Apache Airflow)
  • B. AWS Glue Workflows for Apache Airflow)
  • C. Amazon EventBridge Scheduler with Lambda functions
  • D. AWS Step Functions with a Standard workflow
Jawaban Benar: A
Amazon MWAA adalah pilihan terbaik karena: (1) tim sudah berpengalaman dengan Apache Airflow, (2) Airflow memiliki sensors yang unggul untuk menunggu external events, (3) mendukung complex dependency management dengan DAG, dan (4) memiliki rich operator ecosystem untuk Glue, Redshift, dan service AWS lainnya.

Opsi A: BENAR.
Opsi B: SALAH. Terbatas pada Glue services saja — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi C: SALAH. Terlalu sederhana untuk pipeline kompleks dengan dependencies.
Opsi D: SALAH. Bisa melakukan ini tapi kurang intuitif untuk complex dependencies dan external event waiting dibandingkan Airflow sensors.

#StepFunctions#MWAA#Lambda#S3#DynamoDB#ECS
A company needs to build a serverless data pipeline that processes uploaded files through a series of steps: validate format, transform data, load to DynamoDB, and send notification. Each step takes less than 5 minutes. The pipeline runs infrequently (10-20 times per day) and the team wants to minimize operational overhead and cost. Which orchestration approach is MOST cost-effective?
  • A. AWS Step Functions Express Workflow triggered by S3 event notifications
  • B. Self-managed Apache Airflow on Amazon ECS with spot instances
  • C. AWS Step Functions Standard Workflow triggered by S3 event notifications
  • D. Amazon MWAA with a DAG that triggers Lambda functions for each step
Jawaban Benar: C
AWS Step Functions Standard Workflow adalah pilihan paling cost-effective untuk pipeline yang jarang berjalan (10-20/hari) karena pricing per state transition (bukan per jam seperti MWAA). Standard workflow cocok karena steps bisa sampai 5 menit dan memerlukan exactly-once execution semantics.

Opsi A: SALAH. Dibatasi 5 menit total execution time, yang terlalu ketat jika multiple steps masing-masing hampir 5 menit.
Opsi B: SALAH. Memiliki operational overhead tinggi.
Opsi C: BENAR.
Opsi D: SALAH. Memiliki minimum cost ~$350/bulan untuk environment yang running 24/7, sangat mahal untuk 10-20 executions/hari.

#StepFunctions#EventBridge#Glue
A data engineer is designing a Step Functions workflow that starts an AWS Glue ETL job which typically runs for 45 minutes. The workflow must wait for the Glue job to complete before proceeding to the next step. Which Step Functions integration pattern should the engineer use?
  • A. Request Response pattern (.waitForTaskToken) with a callback from the Glue job, applying schema conversion and enrichment inline
  • B. Fire and Forget pattern with an EventBridge rule to detect Glue job completion
  • C. Run a Job (.sync) integration pattern that automatically waits for the Glue job to complete
  • D. Request Response pattern with a Wait state polling the Glue job status every 5 minutes
Jawaban Benar: C
Run a Job (.sync) integration pattern adalah cara paling sederhana dan efisien untuk menunggu long-running jobs. Dengan menambahkan .sync suffix ke resource ARN, Step Functions secara otomatis polls Glue job status dan melanjutkan ke step berikutnya setelah job selesai, gagal, atau timeout.

Opsi A: SALAH. Memerlukan Glue job untuk send callback — Glue tidak natively support ini tanpa custom code.
Opsi B: SALAH. Memerlukan workflow terpisah dan lebih kompleks.
Opsi C: BENAR.
Opsi D: SALAH. Memerlukan extra states dan logic yang tidak perlu.

#StepFunctions
A data platform processes 200 independent data feeds daily. Each feed requires the same ETL logic but with different parameters (source location, target table, transformations). The team wants to process all feeds in parallel to meet an SLA of completing within 2 hours. Which Step Functions pattern is MOST appropriate?
  • A. A single state machine with a Map state that processes all 200 feeds concurrently with configurable max concurrency
  • B. 200 separate state machine executions triggered by a parent state machine using nested workflows, applying schema conversion and enrichment inline
  • C. A Choice state that routes each feed to a different branch based on feed type
  • D. A sequential loop using a Wait state between each feed processing iteration with a Map state that processes all 200 feeds concurrently
Jawaban Benar: A
Step Functions Map state (Distributed mode untuk large-scale) dirancang tepat untuk parallel processing of multiple items dengan logic yang sama tapi parameter berbeda. MaxConcurrency parameter memungkinkan kontrol berapa feeds diproses bersamaan, membantu manage resource limits downstream.

Opsi A: BENAR.
Opsi B: SALAH. Lebih kompleks untuk di-manage dan monitor, serta memerlukan logic tambahan untuk aggregasi results.
Opsi C: SALAH. Untuk routing bukan parallel processing.
Opsi D: SALAH. Akan sangat lambat — 200 feeds secara sequential tidak akan meet 2-hour SLA — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.

#MWAA
A data pipeline orchestrated by Amazon MWAA includes a task that calls an external API to fetch exchange rates. This API has intermittent failures (about 5% of calls fail with HTTP 503). The task should automatically retry on failure with exponential backoff, and the entire DAG should not fail unless the task fails 5 times consecutively. How should this be configured in the Airflow DAG?
  • A. Create 5 duplicate tasks in the DAG, each attempting the API call, with TriggerRule.ALL_FAILED dependencies
  • B. Configure an on_failure_callback that restarts the entire DAG up to 5 times with retry_exponential_backoff=True in the task's default_args
  • C. Implement a try-except block within the Python callable that retries the API call 5 times
  • D. Set retries=5 and retry_delay=timedelta(minutes=2) with retry_exponential_backoff=True in the task's default_args
Jawaban Benar: D
Airflow memiliki built-in retry mechanism dengan parameter retries, retry_delay, dan retry_exponential_backoff. Setting retries=5 dengan exponential backoff memberikan 5 attempts dengan increasing delay antara retries, yang ideal untuk intermittent API failures. Ini adalah cara yang proper dan idiomatic di Airflow.

Opsi A: SALAH. Sangat fragile dan tidak scalable.
Opsi B: SALAH. Terlalu aggressive — me-restart seluruh DAG hanya karena satu task gagal — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi C: SALAH. Tidak memanfaatkan Airflow's built-in retry/logging/monitoring.
Opsi D: BENAR.

#MWAA#Glue#Redshift#QuickSight
A company runs a nightly ETL pipeline that must complete by 6:00 AM. The pipeline involves: (1) extracting data from 3 source systems in parallel, (2) running a Glue job to join all extracted data, (3) loading results to Redshift, and (4) triggering a QuickSight dataset refresh. Step 2 cannot start until all 3 extractions in step 1 are complete. The team uses Amazon MWAA. Which DAG pattern correctly implements this dependency?
  • A. Use a TaskGroup with three parallel extraction tasks, then set downstream dependencies to the Glue job task, integrating natively with the rest of the pipeline
  • B. Use ExternalTaskSensor for each extraction and start the Glue job when all sensors pass, satisfying all of the stated requirements with minimal effort
  • C. Use SubDAGs for each extraction, then chain them sequentially before the Glue job with a dummy/empty task as a join point (using trigger_rule='all_success') and QuickSight tasks in sequence
  • D. Use three parallel extraction tasks with a dummy/empty task as a join point (using trigger_rule='all_success'), followed by Glue, Redshift, and QuickSight tasks in sequence
Jawaban Benar: D
Pattern fan-in menggunakan dummy/empty task sebagai join point dengan trigger_rule='all_success' memastikan bahwa semua 3 extraction tasks harus berhasil sebelum pipeline melanjutkan ke Glue job. Ini adalah pattern standard Airflow untuk synchronization.

Opsi A: SALAH. Hanya untuk visual grouping, tidak otomatis membuat join-point dependency.
Opsi B: SALAH. Digunakan untuk cross-DAG dependencies, bukan intra-DAG synchronization.
Opsi C: SALAH. Sudah deprecated di Airflow modern dan menambah complexity — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi D: BENAR.

A data engineering team needs to orchestrate a pipeline that spans multiple AWS services across different accounts: a Glue job in the data lake account, a Redshift query in the warehouse account, and an EMR job in the processing account. The orchestration must use a single workflow with centralized monitoring. Which approach provides the MOST secure cross-account orchestration?
  • A. EventBridge event bus in the central account that forwards events to target account services, satisfying strict compliance and audit requirements
  • B. AWS Step Functions in the central account with IAM roles that assume cross-account roles in each target account
  • C. AWS Lambda in the central account that uses hardcoded credentials to invoke services in other accounts
  • D. Amazon MWAA in the central account with access keys for each target account stored in Airflow connections
Jawaban Benar: B
AWS Step Functions dengan cross-account IAM role assumption adalah pendekatan paling secure. Step Functions execution role di central account assumes roles di target accounts menggunakan STS AssumeRole, yang memberikan temporary credentials tanpa menyimpan long-lived secrets. Centralized state machine memberikan single-pane monitoring.

Opsi A: SALAH. Adalah untuk event routing bukan full workflow orchestration dengan sequencing.
Opsi B: BENAR.
Opsi C: SALAH. Adalah anti-pattern keamanan.
Opsi D: SALAH. Kurang secure karena menggunakan long-lived credentials.

A Step Functions workflow for a data pipeline needs to handle the following error scenario: if a Glue job fails with a "ConcurrentRunsExceededException", the workflow should wait 10 minutes and retry up to 3 times. For any other error type, the workflow should immediately transition to a failure notification step. Which Step Functions error handling configuration achieves this?
  • A. Use a single Catch block with a Choice state that examines the error type for the specific Glue exception, minimizing end-to-end processing latency
  • B. Use a Retry field with ErrorEquals for the specific Glue exception, and a Catch field for all other errors routing to the notification step
  • C. Use a Parallel state with one branch for the job and another for error monitoring, minimizing end-to-end processing latency and delivering records with consistent sub-second latency
  • D. Implement the retry logic in a Lambda function wrapper that calls the Glue API, streaming results downstream in near real time and minimizing end-to-end processing latency
Jawaban Benar: B
Step Functions Retry field dengan ErrorEquals memungkinkan retry selektif berdasarkan tipe error spesifik. Konfigurasi: Retry dengan ErrorEquals: ["Glue.ConcurrentRunsExceededException"], IntervalSeconds: 600, MaxAttempts: 3. Catch field kemudian menangkap semua error lain ("States.ALL") dan routes ke notification step. Ini adalah built-in pattern yang bersih dan deklaratif.

Opsi A: SALAH. Memerlukan logic tambahan yang tidak perlu — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi B: BENAR.
Opsi C: SALAH. Tidak menyelesaikan masalah error handling.
Opsi D: SALAH. Menambah operational overhead dan kehilangan Step Functions' native error handling visibility.

The pipeline should not run concurrently (only one execution at a time). Which configuration achieves this?
  • A. Create two separate DAGs — one with an S3KeySensor and one with a cron schedule — both with max_active_runs=1 with native S3 integration and optimized data transfer
  • B. Create one DAG with schedule_interval='0 0 * * *' and an EventBridge rule that triggers the DAG via MWAA CLI on S3 events, with max_active_runs=1 and catchup=False
  • C. Set the DAG schedule_interval to every minute and check for new S3 files within the first task, satisfying all of the stated requirements with minimal effort

Opsi A: SALAH. Tidak mencegah concurrent execution antar kedua DAG — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.

#StepFunctions#Glue#EMR#Redshift
A media company's data pipeline orchestrated by Step Functions processes video metadata through: EMR job (30 min) → Glue job (15 min) → Redshift load (5 min). The pipeline currently runs sequentially, taking 50 minutes total. The team discovers that the Glue job and Redshift load are independent of each other (both only depend on EMR output). How should the workflow be restructured to minimize total execution time?
  • A. Use Express Workflows for the Glue and Redshift steps to make them run faster with parallel processing and horizontal scaling capabilities
  • B. Use a Map state to distribute EMR output to multiple processing targets simultaneously, running as a fully managed service with minimal operational overhead
  • C. Use a Parallel state after EMR to run both Glue and Redshift load concurrently, reducing total time to approximately 35 minutes
  • D. Create two separate Step Functions workflows — one for Glue and one for Redshift — triggered by EMR completion event
Jawaban Benar: C
Parallel state di Step Functions menjalankan multiple branches secara concurrent. Karena Glue (15 min) dan Redshift load (5 min) keduanya hanya bergantung pada output EMR, mereka bisa berjalan bersamaan. Total time: EMR 30 min + max(Glue 15 min, Redshift 5 min) = 45 min → sebenarnya 35 min (30+15 dengan Redshift selesai lebih awal di dalam parallel).

Opsi A: SALAH. Tidak membuat jobs berjalan lebih cepat — hanya berbeda pricing model — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi B: SALAH. Untuk processing multiple items dengan logic sama, bukan dua task berbeda.
Opsi C: BENAR.
Opsi D: SALAH. Kehilangan centralized monitoring dan error handling.
