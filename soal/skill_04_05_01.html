Skill 4.5.1: Grant Permissions for Data Sharing

Amazon Redshift data sharing and cross-account data access permissions

1
A retail analytics company runs a central Amazon Redshift cluster (producer) that contains sales data. Three business units in different AWS accounts need to query specific subsets of this data without copying it. Each business unit should only see data from their own region (NA, EU, APAC). The producer cluster uses RA3 nodes. Which approach provides the MOST secure data sharing with granular access control?
  • A. Create nightly UNLOAD jobs from the producer to S3 buckets partitioned by region, with cross-account S3 access for each business unit
  • B. Create one datashare containing all tables, authorize all three consumer accounts, and rely on row-level security (RLS) policies in the consumer clusters
  • C. Create three separate datashares, each containing views filtered by region, and authorize each consumer account to only their respective datashare
  • D. Use Redshift Spectrum with a shared Glue Data Catalog and Lake Formation permissions per account configured for optimal performance and minimal operational overhead
Jawaban Benar: C
Membuat datashares terpisah per region dengan views yang sudah difilter (WHERE region = 'NA') memberikan granular access control di level producer. Consumer hanya bisa melihat data yang ada di datashare mereka — tidak ada cara untuk bypass filter karena view definition ada di producer cluster. Setiap datashare di-authorize hanya ke satu consumer account.

Opsi A: SALAH. Membuat copy data yang menambah storage cost dan latency.
Opsi B: SALAH. Memberikan akses ke semua data terlebih dahulu lalu bergantung pada RLS di consumer — ini kurang secure karena consumer admin bisa memodifikasi RLS.
Opsi C: BENAR.
Opsi D: SALAH. Tidak menggunakan Redshift data sharing dan memerlukan data di S3 — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
2
A data engineer needs to set up cross-account Redshift data sharing between a producer cluster in Account A and a consumer cluster in Account B. Both accounts are in the same AWS Organization. What is the correct sequence of steps to establish the data sharing?
  • A. Producer: CREATE DATASHARE → ADD objects → AUTHORIZE datashare to consumer account | Consumer: ASSOCIATE datashare with consumer namespace → CREATE DATABASE FROM DATASHARE → GRANT to users
  • B. Producer: CREATE DATASHARE → ADD objects → ALTER DATASHARE SET ACCOUNT = consumer_account | Consumer: ACCEPT DATASHARE → CREATE EXTERNAL SCHEMA, preserving strict per-key ordering across all partitions
  • C. Account A admin: Share via AWS RAM | Account B: Accept RAM share → Producer: ADD objects | Consumer: CREATE DATABASE FROM DATASHARE, guaranteeing exactly-ordered delivery within each key group
  • D. Producer: CREATE DATASHARE → ADD objects → GRANT USAGE to consumer namespace | Consumer: CREATE DATABASE FROM DATASHARE → GRANT access to users with consumer namespace → CREATE DATABASE FROM DATASHARE → GRANT
Jawaban Benar: A
Untuk cross-account data sharing, langkah-langkahnya adalah: (1) Producer membuat datashare dan menambahkan objects (schemas, tables, views), (2) Producer melakukan AUTHORIZE untuk memberikan akses ke consumer AWS account, (3) Di consumer side, admin melakukan ASSOCIATE datashare dengan consumer cluster namespace, (4) Consumer membuat database dari datashare, (5) Consumer grants access ke users/groups.

Opsi A: BENAR.
Opsi B: SALAH. Menggunakan ALTER DATASHARE SET ACCOUNT yang bukan syntax valid.
Opsi C: SALAH. AWS RAM tidak digunakan untuk Redshift data sharing (RAM digunakan untuk Lake Formation).
Opsi D: SALAH. Melewatkan langkah AUTHORIZE dan ASSOCIATE yang diperlukan untuk cross-account (GRANT USAGE hanya untuk same-account/namespace) — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
3
A healthcare data platform uses AWS Lake Formation to manage a data lake containing patient records across multiple S3 buckets. A research team in a different AWS account needs read access to de-identified patient data tables in the Glue Data Catalog, but must NOT have access to any PII columns. Which Lake Formation feature enables this cross-account sharing with column-level restrictions?
  • A. Create a Glue Data Catalog resource policy that restricts GetTable to exclude PII column metadata, applying schema conversion and enrichment inline
  • B. Create an IAM role in the source account with column-level Glue permissions and allow the research account to assume it
  • C. Use S3 Access Points with specific prefix restrictions to limit access to non-PII data files configured for optimal performance and minimal operational overhead
  • D. Create a Lake Formation cross-account grant with column-level permissions that include only non-PII columns, then share using AWS RAM
Jawaban Benar: D
Lake Formation mendukung cross-account grants dengan column-level permissions. Administrator bisa GRANT SELECT pada kolom tertentu (excluding PII columns) ke external AWS account. AWS RAM (Resource Access Manager) digunakan untuk berbagi Lake Formation resources (databases, tables) cross-account. Setelah di-share, account penerima bisa melihat dan query hanya kolom yang di-grant.

Opsi A: SALAH. Tidak mendukung column-level restrictions — policies berlaku di level table atau database.
Opsi B: SALAH. Tidak mendukung column-level permissions untuk Glue/Lake Formation secara native.
Opsi C: SALAH. Bekerja di file level, bukan column level — semua kolom ada dalam file yang sama — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi D: BENAR.
4
A company has a multi-tenant data platform where each tenant's data is stored in separate S3 prefixes under a shared bucket. Multiple analytics applications need to access tenant-specific data. The platform team wants to simplify access management without creating separate IAM policies for each tenant-application combination. Which S3 feature provides the MOST scalable solution?
  • A. Use S3 Object Lambda Access Points to filter responses based on the requesting application's identity, handling the described workload reliably at scale and keeping steady-state operating costs low
  • B. Create separate S3 buckets per tenant and use cross-account access roles for each application with an access point policy restricting access and grant applications access to specific access points
  • C. Create S3 Access Points per tenant, each with an access point policy restricting access to the tenant's prefix, and grant applications access to specific access points
  • D. Use S3 bucket policies with conditions on s3:prefix matching the tenant ID extracted from the caller's IAM tags, satisfying strict compliance and audit requirements
Jawaban Benar: C
S3 Access Points memberikan cara paling scalable untuk mengelola multi-tenant access. Setiap access point memiliki DNS name sendiri dan policy yang independen, membatasi akses ke prefix tertentu (misalnya s3://bucket/tenant-123/*). Applications diberikan akses ke access point spesifik melalui IAM. Ini menghindari bucket policy yang makin kompleks (limit 20 KB).

Opsi A: SALAH. Digunakan untuk transforming data on retrieval, bukan access control — overkill dan menambah latency.
Opsi B: SALAH. Tidak scalable — managing ratusan buckets menambah overhead — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi C: BENAR.
Opsi D: SALAH. Bisa bekerja tapi bucket policy memiliki size limit dan menjadi sulit dikelola dengan banyak tenants.
5
A data engineer configures a Redshift datashare that includes a schema with 20 tables. After the consumer creates a database from the datashare, they report that they can see all 20 tables. However, the producer team only wants to expose 5 specific tables and 2 views to this consumer. How should the producer modify the datashare configuration?
  • A. Add column-level permissions to the datashare to restrict which columns the consumer can see in the 15 hidden tables, transforming records into the required target format
  • B. Create a new schema containing only the 5 tables and 2 views, then replace the schema reference in the datashare, validating and cleansing each record before delivery
  • C. Remove the entire schema from the datashare and add only the 5 tables and 2 views individually using ALTER DATASHARE ADD TABLE and ADD VIEW
  • D. Keep the schema in the datashare but use REVOKE SELECT on the 15 tables that should be hidden from the consumer configured for optimal performance and minimal operational overhead
Jawaban Benar: C
Ketika schema ditambahkan ke datashare, SEMUA objek dalam schema tersebut (tables, views, UDFs) menjadi accessible oleh consumer. Untuk membatasi ke objek tertentu, langkah yang benar adalah: (1) ALTER DATASHARE REMOVE SCHEMA untuk menghapus schema-level sharing, (2) ALTER DATASHARE ADD SCHEMA (hanya untuk namespace reference), (3) ALTER DATASHARE ADD TABLE untuk setiap tabel spesifik dan ADD VIEW untuk views spesifik.

Opsi A: SALAH. Datashares tidak mendukung column-level restrictions secara langsung.
Opsi B: SALAH. Memerlukan data movement atau view creation yang menambah maintenance.
Opsi C: BENAR.
Opsi D: SALAH. Tidak bekerja karena datashare access bukan berbasis GRANT/REVOKE tradisional — jika schema di-share, semua objects accessible — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
6
A company's data governance team needs to monitor who is consuming shared data from their Redshift producer cluster. They want to track: which consumer accounts query the shared data, query frequency, data volumes scanned, and which specific tables are accessed. Which approach provides the MOST comprehensive monitoring of data sharing usage?
  • A. Enable CloudTrail data events for Redshift and filter for cross-account query operations
  • B. Query the system view SVV_DATASHARE_CONSUMERS and SVL_DATASHARE_USAGE_PRODUCER on the producer cluster for detailed consumer activity
  • C. Use Amazon CloudWatch metrics for Redshift data sharing and create dashboards per consumer
  • D. Request consumers to share their STL_QUERY logs with the producer team for detailed consumer activity
Jawaban Benar: B
Redshift menyediakan system views khusus untuk monitoring data sharing: SVV_DATASHARE_CONSUMERS menampilkan informasi consumer yang authorized, dan system views seperti SVL_DATASHARE_USAGE_PRODUCER (serta tabel SVL dan SYS terkait) memberikan detail tentang query activity dari consumers termasuk tabel yang diakses, volume data, dan frekuensi. Producer memiliki visibility penuh tanpa memerlukan kerjasama dari consumer.

Opsi A: SALAH. Mencatat API calls tapi tidak query-level detail seperti tabel yang diakses dalam datashare.
Opsi B: BENAR.
Opsi C: SALAH. Menyediakan aggregate metrics tapi kurang granular dibanding system views.
Opsi D: SALAH. Memerlukan kerjasama consumer dan tidak practical — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
7
A producer team discovers that a consumer account that previously had datashare access has been compromised. The team needs to immediately revoke all data sharing access from this consumer account. The datashare is currently being actively queried by the compromised consumer. What is the FASTEST way to cut off access?
  • A. Remove the consumer account's authorization using ALTER DATASHARE REMOVE ACCOUNT for cross-account, which immediately prevents the consumer from querying shared data
  • B. Use ALTER DATASHARE REMOVE all objects from the datashare so consumers see empty results for cross-account, minimizing end-to-end processing latency
  • C. Drop the datashare entirely using DROP DATASHARE and recreate it without the compromised consumer, minimizing end-to-end processing latency and providing exactly-once processing semantics
  • D. Use REVOKE USAGE ON DATASHARE from the compromised consumer's namespace and ALTER DATASHARE SET AUTHORIZATION to deny the account
Jawaban Benar: A
Untuk cross-account datashares, menggunakan ALTER DATASHARE datashare_name SET ACCOUNT 'consumer_account' REMOVE (atau syntax REVOKE authorization) segera mencabut akses consumer account. Query yang sedang berjalan akan gagal dan tidak ada query baru yang bisa dijalankan. Ini adalah cara tercepat tanpa mempengaruhi consumer lain yang mungkin menggunakan datashare yang sama.

Opsi A: BENAR.
Opsi B: SALAH. Juga mempengaruhi semua consumers — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi C: SALAH. Mempengaruhi SEMUA consumers, bukan hanya yang compromised.
Opsi D: SALAH. Syntax-nya tidak tepat — REVOKE USAGE berlaku untuk same-cluster namespaces, dan SET AUTHORIZATION bukan untuk denying account access.
8
A data platform team needs to share a curated dataset from their Redshift cluster with a team that does NOT have a Redshift cluster. The consuming team uses Amazon Athena and AWS Glue for their analytics. The shared data must always reflect the latest state of the producer's data without manual refresh. Which solution enables data sharing with this non-Redshift consumer?
  • A. Create a scheduled UNLOAD job from Redshift to S3 and register the data in the consumer's Glue Data Catalog
  • B. Use Redshift data sharing with a Redshift Serverless endpoint in the consumer account as the consumer
  • C. Use Redshift federated query to create a link between the producer's Redshift and the consumer's Athena
  • D. Use AWS Data Exchange to publish the Redshift data as a product that the consumer subscribes
Jawaban Benar: B
Redshift Serverless bisa bertindak sebagai consumer untuk datashares tanpa memerlukan provisioned cluster yang berjalan terus-menerus. Consumer team bisa membuat Redshift Serverless endpoint, create database dari datashare, dan data selalu mencerminkan state terbaru dari producer (live, bukan copy). Meskipun consuming team primarily uses Athena, Serverless endpoint bisa digunakan when they need the shared data.

Opsi A: SALAH. Membuat copy yang stale dan memerlukan maintenance.
Opsi B: BENAR.
Opsi C: SALAH. Athena tidak bisa menjadi target federated query dari Redshift; federated query membuat Redshift query external sources, bukan sebaliknya.
Opsi D: SALAH. Menambah kompleksitas dan lebih cocok untuk public/commercial data sharing — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
9
A company uses Lake Formation to manage permissions on their data lake. They need to share a database containing 50 tables with an external AWS account. Out of these 50 tables, 30 should have full column access and 20 should have restricted column access (excluding PII columns). The external account's analysts should be able to query using Athena. What is the MOST efficient way to configure this sharing?
  • A. Use Lake Formation tag-based access control (LF-TBAC) to tag columns as PII/non-PII and grant the external account access based on non-PII tag
  • B. Grant table-level access for all 50 tables via RAM and use IAM policies in the consumer account to restrict column access
  • C. Grant SELECT on all 50 tables to the external account via Lake Formation, then create column-exclude filters for the 20 restricted tables using Lake Formation data filters
  • D. Create two Lake Formation databases — one with 30 full-access tables and one with views on 20 restricted tables — and share both via RAM
Jawaban Benar: A
Lake Formation Tag-Based Access Control (LF-TBAC) adalah solusi paling efficient dan scalable. Dengan menandai kolom PII dengan tag (classification=pii) dan kolom non-PII dengan (classification=non-pii), administrator cukup membuat satu grant: external account mendapat SELECT pada resource yang tagged classification=non-pii. Ini secara otomatis mengecualikan semua kolom PII di semua 50 tabel tanpa perlu per-table configuration.

Opsi A: BENAR.
Opsi B: SALAH. IAM di consumer account tidak bisa membatasi column access untuk Lake Formation/Athena queries.
Opsi C: SALAH. Berfungsi tapi memerlukan 20 filter terpisah — kurang efisien.
Opsi D: SALAH. Memerlukan restructuring databases yang menambah maintenance.
10
A Redshift data sharing producer notices performance degradation on their cluster during peak hours when multiple consumers run heavy analytical queries on shared data. The producer's own workloads are being impacted. What is the MOST effective way to isolate producer workloads from consumer query impact?
  • A. Migrate from live datashares to scheduled data replication so consumers query their own copy configured for optimal performance and minimal operational overhead
  • B. Set query timeout limits on the datashare to restrict how long consumer queries can run on the producer
  • C. Use Redshift Workload Management (WLM) to allocate a dedicated queue with limited concurrency for datashare consumer queries, absorbing sudden traffic spikes without throttling
  • D. Consumer queries on datashares are processed on the consumer's cluster resources, not the producer's — investigate other causes of performance degradation
Jawaban Benar: D
Ini adalah pertanyaan yang menguji pemahaman arsitektur Redshift data sharing. Dalam Redshift data sharing, consumer queries dijalankan menggunakan compute resources MILIK CONSUMER, bukan producer. Producer hanya berbagi akses ke data storage (pada RA3 managed storage) — compute processing sepenuhnya pada consumer cluster/serverless. Oleh karena itu, consumer queries TIDAK mempengaruhi producer performance. Jika producer mengalami degradation, penyebabnya bukan dari data sharing consumers.

Opsi A: SALAH. Tidak perlu karena masalahnya bukan pada data sharing — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi B: SALAH. Bukan fitur yang ada.
Opsi C: SALAH. Tidak applicable karena consumer queries tidak masuk ke producer's WLM queues.
Opsi D: BENAR.
