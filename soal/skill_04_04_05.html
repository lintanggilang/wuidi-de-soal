1
A large e-commerce company generates 5 TB of log data daily from multiple sources: CloudTrail (management and data events), VPC Flow Logs, application logs from ECS containers, and WAF logs. They need to aggregate all logs into a central data lake for unified security analysis and compliance reporting. The solution must handle the high volume with minimal data loss. Which architecture is MOST appropriate for log ingestion at this scale?
  • A. Each log source → CloudWatch Logs → Subscription filters → Amazon Data Firehose → S3 data lake
  • B. Each log source → Amazon Kinesis Data Streams → AWS Lambda consumers → S3 data lake with dynamic partitioning
  • C. Each log source → S3 direct delivery → AWS Glue ETL jobs (scheduled hourly) → S3 data lake (curated)
  • D. Each log source → Amazon Data Firehose (direct PUT or service integrations) → S3 data lake with dynamic partitioning
Correct Answer: D
Amazon Data Firehose (sebelumnya Kinesis Data Firehose) is solution most correct for high-volume log ingestion to S3. Firehose supports direct integration from many AWS services (VPC Flow Logs, WAF, CloudTrail), auto-scaling without management, built-in buffering for batch writes that efficient to S3, dynamic partitioning for organisasi data, and format conversion (JSON to Parquet).

Option A: INCORRECT. Adds hop through CloudWatch Logs that adds cost ingestion and latency — does not need for route to S3.
Option B: INCORRECT. Has concurrency limits and timeout that membuatnya not ideal for 5 TB/day — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option C: INCORRECT. Has gap 1 hours and Glue not ideal for continuous ingestion.
Option D: CORRECT.
2
A financial services company needs to process 10 TB of historical CloudTrail logs stored in S3 to identify potential compliance violations. The processing involves parsing JSON, joining with an IAM policy database, applying complex business rules, and generating summary reports. The job should complete within 4 hours. Which AWS service is BEST suited for this batch processing task?
  • A. Amazon Athena CTAS queries to transform and filter the logs with Spark
  • B. AWS Glue ETL with Spark jobs using DynamicFrames, satisfying strict compliance and audit requirements
  • C. Amazon EMR with Spark configured with memory-optimized instances for the 10 TB dataset
  • D. AWS Lambda with S3 batch operations processing each log file independently
Correct Answer: C
Amazon EMR with Spark provides kontrol full atas cluster sizing, memory configuration, and processing optimization that is required for 10 TB data with complex joins and business rules in limit time 4 hours. Memory-optimized instances (r5/r6g) optimal for large-scale data joining. EMR also supports custom libraries for business rules.

Option A: INCORRECT. Not supports complex business rules, custom UDFs limited, and has query timeout limits — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option B: INCORRECT. Has auto-scaling but less control over cluster configuration and can less predictable for strict 4-hour SLA on 10 TB.
Option C: CORRECT.
Option D: INCORRECT. Not can performs joins cross-file and has 15-minute timeout per invocation.
3
A company needs to combine CloudTrail logs, VPC Flow Logs, and DNS query logs for security correlation analysis. Each log source has a different schema and timestamp format. The combined dataset must be queryable with a unified schema in their data lake. Which approach provides the MOST maintainable solution for log format standardization?
  • A. Use Amazon Data Firehose with Lambda transformation functions to normalize each log source to a common schema before delivery to S3, applying schema conversion and enrichment inline
  • B. Store raw logs in S3 and create Athena views that normalize schemas using CASE statements and type casting, validating and cleansing each record before delivery
  • C. Use AWS Glue ETL crawlers to auto-detect schemas and create a unified Glue Data Catalog with consistent column naming with native S3 integration and optimized data transfer
  • D. Define an OCSF (Open Cybersecurity Schema Framework) schema in AWS Glue, use Glue ETL jobs to transform each source to OCSF format, store in S3 as Parquet
Correct Answer: D
OCSF (Open Cybersecurity Schema Framework) is standar industri for normalisasi security log data. Uses AWS Glue ETL for mentransformasi each source to format OCSF provides: (1) schema that consistent and well-documented, (2) Parquet format for query efficiency, (3) maintainability because OCSF is standard that evolving with community support. AWS Security Lake also uses OCSF.

Option A: INCORRECT. Berfungsi but custom schema without standard can menjadi maintenance burden.
Option B: INCORRECT. Not mentransformasi data fisik and views can menjadi complex and slow.
Option C: INCORRECT. Mendeteksi schema but not menormalkan — each source still has schema different — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option D: CORRECT.
4
A multinational company has 200 AWS accounts across 4 regions. They need a log aggregation architecture that: (1) collects all logs centrally, (2) allows each business unit to query only their own logs, (3) provides a unified view for the security team, and (4) minimizes cross-region data transfer costs. Which architecture is MOST appropriate?
  • A. Use AWS Security Lake to automatically collect and centralize security logs with subscriber-based access per business unit
  • B. Store logs in regional S3 buckets, replicate to a central bucket for security team, use S3 Access Points and IAM policies per business unit
  • C. Send all logs to a central S3 bucket in one region, use Lake Formation for fine-grained access control per business unit, and accept cross-region transfer costs
  • D. Deploy OpenSearch clusters in each region with cross-cluster search for the security team and index-level access control per business unit
Correct Answer: A
AWS Security Lake automatically mengumpulkan log from berbagai AWS sources (CloudTrail, VPC Flow Logs, Route 53, Security Hub findings, dll), menormalisasi to OCSF schema, and stores in S3. Security Lake supports rollup regions for reduces cross-region transfer, subscriber-based access control that enables business units only melihat data mereka, and delegated administrator for security team.

Option A: CORRECT.
Option B: INCORRECT. Menggandakan storage and requires custom access management.
Option C: INCORRECT. Maximizes cross-region transfer costs.
Option D: INCORRECT. Very expensive for 200 accounts and requires cluster management that significant.
5
A data engineer needs to build a real-time log processing pipeline that: detects security threats within 30 seconds of log generation, enriches events with threat intelligence data, and stores processed events for historical analysis. The pipeline processes 100,000 events per second from multiple log sources. Which architecture provides the LOWEST detection latency?
  • A. Log sources → CloudWatch Logs → Metric Filters → CloudWatch Alarms → SNS → Lambda → threat detection, minimizing end-to-end processing latency and providing exactly-once processing semantics
  • B. Log sources → Amazon Kinesis Data Streams → Amazon Managed Service for Apache Flink → threat detection with enrichment → Firehose → S3 + OpenSearch
  • C. Log sources → Amazon Data Firehose → S3 → Lambda (triggered by S3) → threat detection → DynamoDB with enrichment → Firehose → S3 + OpenSearch
  • D. Log sources → Amazon MSK → Spark Streaming on EMR → threat detection → Redshift for storage, applying schema conversion and enrichment inline
Correct Answer: B
Kinesis Data Streams → Managed Flink provides latency terendah for real-time processing: Kinesis provides sub-second delivery, and Flink processes events via streaming with stateful enrichment (lookup to threat intelligence database uses async I/O). Output to Firehose → S3 for historical analysis and OpenSearch for real-time dashboards.

Option A: INCORRECT. Only detect based on pattern count, not enrichment-based threat detection, and alarm evaluation adds latency.
Option B: CORRECT.
Option C: INCORRECT. Has buffering delay Firehose (minimum 60 seconds) that melebihi requirement 30 seconds — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option D: INCORRECT. Has micro-batch latency higher from Flink and EMR cluster startup time menjadi problem.
6
A company stores 2 PB of historical log data in S3 across multiple years. They need to generate a one-time compliance report that requires scanning all data to find specific patterns of unauthorized access. The report must be delivered within 48 hours. Cost optimization is critical as this is a one-time job. Which approach is MOST cost-effective?
  • A. Use Amazon Athena to query the data directly in S3 using partition pruning where possible
  • B. Use Amazon EMR with Spot instances running Spark to process all 2 PB of data
  • C. Use AWS Glue with auto-scaling workers to process the data in parallel
  • D. Launch a large Amazon Redshift Serverless endpoint and use COPY to load all data for analysis
Correct Answer: B
For one-time processing 2 PB data, EMR with Spot instances provides cost terendah. Spot instances can 60-90% cheaper from On-Demand. EMR Spark provides full kontrol over cluster sizing and processing parallelism for memenuhi 48-hour deadline. For one-time jobs, Spot interruption can is handled with checkpointing.

Option A: INCORRECT. Charges $5/TB scanned = $10,000 for 2 PB, without Spot pricing benefit, and has concurrent query limits.
Option B: CORRECT.
Option C: INCORRECT. Has per-DPU-hour pricing that usually more expensive from EMR Spot for workloads scale large.
Option D: INCORRECT. Requires loading 2 PB that itself memakan time significant and very expensive for one-time use.

A company's compliance team requires a monthly report showing: total API calls per service, unique IAM principals accessing production resources, any access from non-approved IP ranges, and data access patterns on S3 sensitive buckets. The data sources include CloudTrail logs, VPC Flow Logs, and S3 access logs. Which approach provides the MOST automated and repeatable reporting solution?
  • A. Build a custom dashboard in Amazon Managed Grafana querying CloudWatch metrics with Amazon QuickSight and visualize with Amazon QuickSight, enforcing encryption and fine-grained access control
  • B. Use CloudWatch Logs Insights with saved queries and export results to S3 monthly, handling the described workload reliably at scale and satisfying strict compliance and audit requirements
  • C. Use AWS Glue ETL jobs scheduled monthly to process all log sources, generate summary tables in a Glue Data Catalog, and visualize with Amazon QuickSight
  • D. Create Athena saved queries for each report metric and manually run them monthly, protecting the data both in transit and at rest and minimizing end-to-end processing latency
Correct Answer: C
Glue ETL jobs that dijadwalkan bulanan provides solution most automatic and repeatable: scheduled triggers ensures jobs runs without intervensi manual, jobs can processes multiple log sources (CloudTrail + VPC Flow Logs + S3 access logs), produces summary tables that terstruktur in Data Catalog, and QuickSight dashboards automatic refresh from summary tables.

Option A: INCORRECT. Only menampilkan metrics, not detailed log analysis that is required for unique principals and IP range checking — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option B: INCORRECT. Has limit query scope and cannot join between log sources that different.
Option C: CORRECT.
Option D: INCORRECT. Not automatic — requires human intervention each months.

A data platform team manages a log storage system on S3 that grows 500 GB daily. After 30 days, logs are rarely accessed but must be retained for 7 years. After 1 year, logs are never accessed unless for legal hold. The team wants to minimize storage costs without losing data accessibility when needed. Which S3 storage tiering strategy is MOST cost-effective?
  • A. S3 Intelligent-Tiering for all data with Archive Access and Deep Archive Access tiers enabled, avoiding charges for idle provisioned capacity
  • B. S3 Standard (0-30 days) → S3 One Zone-IA (30-365 days) → S3 Glacier Flexible Retrieval (365+ days)
  • C. S3 Standard (0-30 days) → S3 Glacier Instant Retrieval (30-365 days) → S3 Glacier Deep Archive (365+ days)
  • D. S3 Standard (0-30 days) → S3 Standard-IA (30-365 days) → S3 Glacier Deep Archive (365+ days)
Correct Answer: C
S3 Glacier Instant Retrieval optimal for data that diakses rarely (sekali per kuartal) but requires millisecond retrieval when diakses — suitable for 30-365 days in mana access rarely but must segera available. Deep Archive (365+ days) provides cost terendah ($0.00099/GB/month) for data that almost not pernah diakses except legal hold (retrieval in 12 hours still acceptable).

Option A: INCORRECT. Adds monitoring fee per object that significant for 500 GB/day × 7 years = millions of objects.
Option B: INCORRECT. Not has multi-AZ durability that less correct for compliance logs.
Option C: CORRECT.
Option D: INCORRECT. More expensive from Glacier Instant Retrieval for access that very rarely.
9
A company uses Amazon Data Firehose to deliver VPC Flow Logs to S3 for analysis. They notice that Athena queries on the delivered data are slow and expensive because the files are small (5 MB each) and in JSON format. Which Firehose configuration changes will MOST improve Athena query performance?
  • A. Add a Lambda transformation function to compress JSON files with GZIP before delivery, applying schema conversion and enrichment inline
  • B. Enable Firehose dynamic partitioning to organize files by source IP and destination IP with Snappy compression and increase buffer size to 128 MB
  • C. Increase the Firehose buffer size to 128 MB and buffer interval to 900 seconds to create larger files
  • D. Enable Firehose data format conversion to Apache Parquet with Snappy compression, and increase buffer size to 128 MB
Correct Answer: D
Konversi to Parquet provides improvement terbesar for Athena: columnar format enables Athena only reads kolom that is required (reduces data scanned significant), Snappy compression reduces size file more lanjut, and buffer 128 MB produces file berukuran optimal for Athena (ideal 128 MB-512 MB). Kombinasi Parquet + larger files can reduces query cost and time up to 90%.

Option A: INCORRECT. Reduces storage but Athena still must decompress and scan entire file because row-format.
Option B: INCORRECT. Membantu filter but without columnar format, improvement limited — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option C: INCORRECT. Still JSON row-format that memaksa full file scan.
Option D: CORRECT.
10
A security operations center (SOC) needs to correlate events across CloudTrail, GuardDuty findings, VPC Flow Logs, and custom application security logs in near real-time. When a high-severity correlation is detected (e.g., GuardDuty finding + unusual VPC traffic from same IP within 5 minutes), an alert must be triggered. Which architecture provides the MOST effective real-time correlation?
  • A. All sources → Amazon Kinesis Data Streams → Amazon Managed Service for Apache Flink with windowed joins → SNS/Lambda for alerting
  • B. All sources → Amazon EventBridge → EventBridge rules with pattern matching → Lambda for correlation → SNS, delivering records with consistent sub-second latency
  • C. All sources → S3 data lake → Athena scheduled queries every 5 minutes → SNS for alerting with windowed joins → SNS/Lambda for alerting
  • D. All sources → CloudWatch Logs → CloudWatch Contributor Insights → CloudWatch Alarms → SNS, streaming results downstream in near real time
Correct Answer: A
Apache Flink (via Managed Service) is satu-satunya opsi that supports windowed joins — capabilities for combines events from multiple streams in time window certain (5 minutes). Flink processes events in a stateful, stores state per IP address, and detects when GuardDuty finding and unusual VPC traffic from IP that same occurs in window 5 minutes. Ini provides true real-time correlation.

Option A: CORRECT.
Option B: INCORRECT. Only performs single-event pattern matching — not supports temporal correlation between events different.
Option C: INCORRECT. Has latency 5+ minutes and not streaming — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option D: INCORRECT. Melakukan top-N analysis, not multi-source temporal correlation.
