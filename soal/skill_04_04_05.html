Skill 4.4.5: Integrate Various AWS Services to Perform Logging

Amazon EMR and other services for large-scale log data processing and analysis

1
A large e-commerce company generates 5 TB of log data daily from multiple sources: CloudTrail (management and data events), VPC Flow Logs, application logs from ECS containers, and WAF logs. They need to aggregate all logs into a central data lake for unified security analysis and compliance reporting. The solution must handle the high volume with minimal data loss. Which architecture is MOST appropriate for log ingestion at this scale?
  • A. Each log source → CloudWatch Logs → Subscription filters → Amazon Data Firehose → S3 data lake
  • B. Each log source → Amazon Data Firehose (direct PUT or service integrations) → S3 data lake with dynamic partitioning
  • C. Each log source → Amazon Kinesis Data Streams → AWS Lambda consumers → S3 data lake
  • D. Each log source → S3 direct delivery → AWS Glue ETL jobs (scheduled hourly) → S3 data lake (curated)
Jawaban Benar: B
Amazon Data Firehose (sebelumnya Kinesis Data Firehose) adalah solusi paling tepat untuk high-volume log ingestion ke S3. Firehose mendukung direct integration dari banyak AWS services (VPC Flow Logs, WAF, CloudTrail), auto-scaling tanpa management, built-in buffering untuk batch writes yang efisien ke S3, dynamic partitioning untuk organisasi data, dan format conversion (JSON ke Parquet). Opsi A menambahkan hop melalui CloudWatch Logs yang menambah biaya ingestion dan latency — tidak perlu untuk route ke S3. Opsi C (Lambda consumers) memiliki concurrency limits dan timeout yang membuatnya tidak ideal untuk 5 TB/day. Opsi D (hourly Glue jobs) memiliki gap 1 jam dan Glue tidak ideal untuk continuous ingestion.
2
A financial services company needs to process 10 TB of historical CloudTrail logs stored in S3 to identify potential compliance violations. The processing involves parsing JSON, joining with an IAM policy database, applying complex business rules, and generating summary reports. The job should complete within 4 hours. Which AWS service is BEST suited for this batch processing task?
  • A. AWS Glue ETL with Spark jobs using DynamicFrames
  • B. Amazon EMR with Spark configured with memory-optimized instances for the 10 TB dataset
  • C. Amazon Athena CTAS queries to transform and filter the logs
  • D. AWS Lambda with S3 batch operations processing each log file independently
Jawaban Benar: B
Amazon EMR dengan Spark memberikan kontrol penuh atas cluster sizing, memory configuration, dan processing optimization yang diperlukan untuk 10 TB data dengan complex joins dan business rules dalam batas waktu 4 jam. Memory-optimized instances (r5/r6g) optimal untuk large-scale data joining. EMR juga mendukung custom libraries untuk business rules. Opsi A (Glue) memiliki auto-scaling tapi less control over cluster configuration dan bisa kurang predictable untuk strict 4-hour SLA pada 10 TB. Opsi C (Athena CTAS) tidak mendukung complex business rules, custom UDFs terbatas, dan memiliki query timeout limits. Opsi D (Lambda) tidak bisa melakukan joins cross-file dan memiliki 15-minute timeout per invocation.
3
A company needs to combine CloudTrail logs, VPC Flow Logs, and DNS query logs for security correlation analysis. Each log source has a different schema and timestamp format. The combined dataset must be queryable with a unified schema in their data lake. Which approach provides the MOST maintainable solution for log format standardization?
  • A. Use Amazon Data Firehose with Lambda transformation functions to normalize each log source to a common schema before delivery to S3
  • B. Store raw logs in S3 and create Athena views that normalize schemas using CASE statements and type casting
  • C. Use AWS Glue ETL crawlers to auto-detect schemas and create a unified Glue Data Catalog with consistent column naming
  • D. Define an OCSF (Open Cybersecurity Schema Framework) schema in AWS Glue, use Glue ETL jobs to transform each source to OCSF format, store in S3 as Parquet
Jawaban Benar: D
OCSF (Open Cybersecurity Schema Framework) adalah standar industri untuk normalisasi security log data. Menggunakan AWS Glue ETL untuk mentransformasi setiap sumber ke format OCSF memberikan: (1) schema yang konsisten dan well-documented, (2) Parquet format untuk query efficiency, (3) maintainability karena OCSF adalah standard yang evolving dengan community support. AWS Security Lake juga menggunakan OCSF. Opsi A (Firehose Lambda) berfungsi tapi custom schema tanpa standard bisa menjadi maintenance burden. Opsi B (Athena views) tidak mentransformasi data fisik dan views bisa menjadi complex dan lambat. Opsi C (crawlers) mendeteksi schema tapi tidak menormalkan — setiap sumber tetap memiliki schema berbeda.
4
A multinational company has 200 AWS accounts across 4 regions. They need a log aggregation architecture that: (1) collects all logs centrally, (2) allows each business unit to query only their own logs, (3) provides a unified view for the security team, and (4) minimizes cross-region data transfer costs. Which architecture is MOST appropriate?
  • A. Send all logs to a central S3 bucket in one region, use Lake Formation for fine-grained access control per business unit, and accept cross-region transfer costs
  • B. Store logs in regional S3 buckets, replicate to a central bucket for security team, use S3 Access Points and IAM policies per business unit
  • C. Use AWS Security Lake to automatically collect and centralize security logs with subscriber-based access per business unit
  • D. Deploy OpenSearch clusters in each region with cross-cluster search for the security team and index-level access control per business unit
Jawaban Benar: C
AWS Security Lake secara otomatis mengumpulkan log dari berbagai AWS sources (CloudTrail, VPC Flow Logs, Route 53, Security Hub findings, dll), menormalisasi ke OCSF schema, dan menyimpan di S3. Security Lake mendukung rollup regions untuk mengurangi cross-region transfer, subscriber-based access control yang memungkinkan business units hanya melihat data mereka, dan delegated administrator untuk security team. Opsi A (central bucket satu region) maximizes cross-region transfer costs. Opsi B (regional + replication) menggandakan storage dan memerlukan custom access management. Opsi D (OpenSearch per region) sangat mahal untuk 200 accounts dan memerlukan cluster management yang signifikan.
5
A data engineer needs to build a real-time log processing pipeline that: detects security threats within 30 seconds of log generation, enriches events with threat intelligence data, and stores processed events for historical analysis. The pipeline processes 100,000 events per second from multiple log sources. Which architecture provides the LOWEST detection latency?
  • A. Log sources → Amazon Data Firehose → S3 → Lambda (triggered by S3) → threat detection → DynamoDB
  • B. Log sources → Amazon Kinesis Data Streams → Amazon Managed Service for Apache Flink → threat detection with enrichment → Firehose → S3 + OpenSearch
  • C. Log sources → CloudWatch Logs → Metric Filters → CloudWatch Alarms → SNS → Lambda → threat detection
  • D. Log sources → Amazon MSK → Spark Streaming on EMR → threat detection → Redshift for storage
Jawaban Benar: B
Kinesis Data Streams → Managed Flink memberikan latency terendah untuk real-time processing: Kinesis memberikan sub-second delivery, dan Flink memproses events secara streaming dengan stateful enrichment (lookup ke threat intelligence database menggunakan async I/O). Output ke Firehose → S3 untuk historical analysis dan OpenSearch untuk real-time dashboards. Opsi A (Firehose → S3 → Lambda) memiliki buffering delay Firehose (minimum 60 seconds) yang melebihi requirement 30 detik. Opsi C (CloudWatch metric filters) hanya detect berdasarkan pattern count, bukan enrichment-based threat detection, dan alarm evaluation adds latency. Opsi D (EMR Spark Streaming) memiliki micro-batch latency lebih tinggi dari Flink dan EMR cluster startup time menjadi masalah.
6
A company stores 2 PB of historical log data in S3 across multiple years. They need to generate a one-time compliance report that requires scanning all data to find specific patterns of unauthorized access. The report must be delivered within 48 hours. Cost optimization is critical as this is a one-time job. Which approach is MOST cost-effective?
  • A. Use Amazon EMR with Spot instances running Spark to process all 2 PB of data
  • B. Use Amazon Athena to query the data directly in S3 using partition pruning where possible
  • C. Launch a large Amazon Redshift Serverless endpoint and use COPY to load all data for analysis
  • D. Use AWS Glue with auto-scaling workers to process the data in parallel
Jawaban Benar: A
Untuk one-time processing 2 PB data, EMR dengan Spot instances memberikan biaya terendah. Spot instances bisa 60-90% lebih murah dari On-Demand. EMR Spark memberikan full kontrol over cluster sizing dan processing parallelism untuk memenuhi 48-hour deadline. Untuk one-time jobs, Spot interruption bisa ditangani dengan checkpointing. Opsi B (Athena) charges $5/TB scanned = $10,000 untuk 2 PB, tanpa Spot pricing benefit, dan memiliki concurrent query limits. Opsi C (Redshift) memerlukan loading 2 PB yang sendiri memakan waktu signifikan dan sangat mahal untuk one-time use. Opsi D (Glue) memiliki per-DPU-hour pricing yang biasanya lebih mahal dari EMR Spot untuk workloads berskala besar.
7
A company's compliance team requires a monthly report showing: total API calls per service, unique IAM principals accessing production resources, any access from non-approved IP ranges, and data access patterns on S3 sensitive buckets. The data sources include CloudTrail logs, VPC Flow Logs, and S3 access logs. Which approach provides the MOST automated and repeatable reporting solution?
  • A. Use AWS Glue ETL jobs scheduled monthly to process all log sources, generate summary tables in a Glue Data Catalog, and visualize with Amazon QuickSight
  • B. Create Athena saved queries for each report metric and manually run them monthly
  • C. Use CloudWatch Logs Insights with saved queries and export results to S3 monthly
  • D. Build a custom dashboard in Amazon Managed Grafana querying CloudWatch metrics
Jawaban Benar: A
Glue ETL jobs yang dijadwalkan bulanan memberikan solusi paling otomatis dan repeatable: scheduled triggers memastikan jobs berjalan tanpa intervensi manual, jobs dapat memproses multiple log sources (CloudTrail + VPC Flow Logs + S3 access logs), menghasilkan summary tables yang terstruktur di Data Catalog, dan QuickSight dashboards otomatis refresh dari summary tables. Opsi B (manual Athena queries) tidak otomatis — memerlukan human intervention setiap bulan. Opsi C (CloudWatch Logs Insights) memiliki batas query scope dan tidak bisa join antar log sources yang berbeda. Opsi D (Grafana + CloudWatch Metrics) hanya menampilkan metrics, bukan detailed log analysis yang diperlukan untuk unique principals dan IP range checking.
8
A data platform team manages a log storage system on S3 that grows 500 GB daily. After 30 days, logs are rarely accessed but must be retained for 7 years. After 1 year, logs are never accessed unless for legal hold. The team wants to minimize storage costs without losing data accessibility when needed. Which S3 storage tiering strategy is MOST cost-effective?
  • A. S3 Standard (0-30 days) → S3 Standard-IA (30-365 days) → S3 Glacier Deep Archive (365+ days)
  • B. S3 Standard (0-30 days) → S3 Glacier Instant Retrieval (30-365 days) → S3 Glacier Deep Archive (365+ days)
  • C. S3 Intelligent-Tiering for all data with Archive Access and Deep Archive Access tiers enabled
  • D. S3 Standard (0-30 days) → S3 One Zone-IA (30-365 days) → S3 Glacier Flexible Retrieval (365+ days)
Jawaban Benar: B
S3 Glacier Instant Retrieval optimal untuk data yang diakses jarang (sekali per kuartal) tapi memerlukan millisecond retrieval ketika diakses — cocok untuk 30-365 hari di mana akses jarang tapi harus segera available. Deep Archive (365+ hari) memberikan biaya terendah ($0.00099/GB/month) untuk data yang hampir tidak pernah diakses kecuali legal hold (retrieval dalam 12 jam masih acceptable). Opsi A (Standard-IA) lebih mahal dari Glacier Instant Retrieval untuk akses yang sangat jarang. Opsi C (Intelligent-Tiering) menambah monitoring fee per object yang signifikan untuk 500 GB/day × 7 years = jutaan objects. Opsi D (One Zone-IA) tidak memiliki multi-AZ durability yang kurang tepat untuk compliance logs.
9
A company uses Amazon Data Firehose to deliver VPC Flow Logs to S3 for analysis. They notice that Athena queries on the delivered data are slow and expensive because the files are small (5 MB each) and in JSON format. Which Firehose configuration changes will MOST improve Athena query performance?
  • A. Increase the Firehose buffer size to 128 MB and buffer interval to 900 seconds to create larger files
  • B. Enable Firehose data format conversion to Apache Parquet with Snappy compression, and increase buffer size to 128 MB
  • C. Add a Lambda transformation function to compress JSON files with GZIP before delivery
  • D. Enable Firehose dynamic partitioning to organize files by source IP and destination IP
Jawaban Benar: B
Konversi ke Parquet memberikan improvement terbesar untuk Athena: columnar format memungkinkan Athena hanya membaca kolom yang diperlukan (mengurangi data scanned signifikan), Snappy compression mengurangi ukuran file lebih lanjut, dan buffer 128 MB menghasilkan file berukuran optimal untuk Athena (ideal 128 MB-512 MB). Kombinasi Parquet + larger files bisa mengurangi query cost dan waktu hingga 90%. Opsi A (larger buffer only) masih JSON row-format yang memaksa full file scan. Opsi C (GZIP JSON) mengurangi storage tapi Athena masih harus decompress dan scan seluruh file karena row-format. Opsi D (dynamic partitioning) membantu filter tapi tanpa columnar format, improvement terbatas.
10
A security operations center (SOC) needs to correlate events across CloudTrail, GuardDuty findings, VPC Flow Logs, and custom application security logs in near real-time. When a high-severity correlation is detected (e.g., GuardDuty finding + unusual VPC traffic from same IP within 5 minutes), an alert must be triggered. Which architecture provides the MOST effective real-time correlation?
  • A. All sources → S3 data lake → Athena scheduled queries every 5 minutes → SNS for alerting
  • B. All sources → Amazon Kinesis Data Streams → Amazon Managed Service for Apache Flink with windowed joins → SNS/Lambda for alerting
  • C. All sources → Amazon EventBridge → EventBridge rules with pattern matching → Lambda for correlation → SNS
  • D. All sources → CloudWatch Logs → CloudWatch Contributor Insights → CloudWatch Alarms → SNS
Jawaban Benar: B
Apache Flink (via Managed Service) adalah satu-satunya opsi yang mendukung windowed joins — kemampuan untuk menggabungkan events dari multiple streams dalam time window tertentu (5 menit). Flink memproses events secara stateful, menyimpan state per IP address, dan mendeteksi ketika GuardDuty finding dan unusual VPC traffic dari IP yang sama terjadi dalam window 5 menit. Ini memberikan true real-time correlation. Opsi A (scheduled Athena) memiliki latency 5+ menit dan bukan streaming. Opsi C (EventBridge) hanya melakukan single-event pattern matching — tidak mendukung temporal correlation antar events berbeda. Opsi D (Contributor Insights) melakukan top-N analysis, bukan multi-source temporal correlation.
