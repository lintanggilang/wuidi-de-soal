A data engineer is building an ETL pipeline using AWS Glue to process semi-structured JSON data from Amazon S3. The source data contains nested arrays and fields with inconsistent data types across records. The engineer needs to resolve these schema inconsistencies before writing to a relational target. Which AWS Glue feature is MOST appropriate for handling this scenario?
  • A. Use AWS Glue DataBrew to manually define transformations for each nested field with the Relationalize transform and handle schema variations
  • B. Convert to a Spark DataFrame immediately and use explicit schema casting on all columns
  • C. Use Glue DynamicFrames with the Relationalize transform to flatten nested structures and handle schema variations
  • D. Create a Glue crawler to infer the schema and use the resulting table definition to force a fixed schema
Correct Answer: C
AWS Glue DynamicFrames designed khusus for handles data semi-structured with schema that not consistent. DynamicFrame has feature "choice type" that detects when field has type data different in record that different, and transform Relationalize automatically memecah nested arrays menjadi table relasional separate.

Option A: INCORRECT. Cocok for data preparation visual but not solution optimal for ETL pipeline automatic with nested structures kompleks — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option B: INCORRECT. Will fails if ada type mismatch because requires schema still.
Option C: CORRECT.
Option D: INCORRECT. Only menginfer schema but not handles inkonsistensi saat processing.

During peak processing hours, Spot Instance interruptions cause task failures and slow down the overall job. The team wants to improve resilience while maintaining cost optimization. Which EMR feature should the data engineer configure?

  • C. Configure a single instance fleet with one Spot Instance type and enable automatic failover to On-Demand
  • D. Enable EMR managed scaling with only On-Demand instances in the core node group and configure multiple instance types
Correct Answer: B
EMR instance fleets with allocation strategy "capacity-optimized" memilih instance types from Spot capacity pools that most available, reduces possibility interruption. By configures multiple instance types, EMR has more opsi for gets capacity Spot that stabil.

Option A: INCORRECT. Eliminates cost optimization sepenuhnya.
Option B: CORRECT.
Option C: INCORRECT. Justru increases risiko interruption because depends on satu capacity pool saja.
Option D: INCORRECT. Also eliminates keuntungan Spot pricing — although its description sounds convincing, in a fundamental still not appropriate for requirements this.

A retail analytics team uses Amazon Redshift as their data warehouse. They have complex ETL transformations that aggregate sales data hourly from staging tables into summary tables. The transformations involve multiple JOINs and window functions. The team wants to simplify their ETL pipeline while keeping the summary data automatically refreshed. Which Redshift feature is BEST suited for this requirement?
  • A. Create materialized views with AUTO REFRESH enabled on the summary queries
  • B. Use Redshift stored procedures scheduled with Amazon EventBridge to rebuild summary tables
  • C. Create standard views and schedule a Lambda function to run REFRESH queries hourly
  • D. Implement external ETL using AWS Glue to perform the aggregations and write back to Redshift
Correct Answer: A
Materialized views in Amazon Redshift stores result query that already in-precompute and supports AUTO REFRESH that automatically updates data when table base changes. Ini menyederhanakan ETL because not requires orchestration external.

Option A: CORRECT.
Option B: INCORRECT. Bekerja but more complex and not automatic merespons changes data.
Option C: INCORRECT. Adds complexity with komponen external and standard views not stores result.
Option D: INCORRECT. Adds latensi and cost with moves data exits and enters returns to Redshift.

A financial institution needs to implement a complex ELT workflow in Amazon Redshift that involves loading raw transaction data, applying business rules for fraud detection, updating multiple dimension tables, and generating audit trails. The logic must be executed as a single atomic unit within Redshift. Which approach is MOST appropriate?
  • A. Use Amazon Redshift stored procedures with explicit transaction control (BEGIN/COMMIT/ROLLBACK)
  • B. Use Amazon Redshift materialized views with cascading refresh to implement the transformation chain
  • C. Execute individual SQL statements from an external AWS Glue Python shell job with error handling
  • D. Create a Step Functions workflow that executes each SQL statement via the Redshift Data API sequentially
Correct Answer: A
Redshift stored procedures supports procedural logic (IF/ELSE, loops, variables) with transaction control full (BEGIN/COMMIT/ROLLBACK), enables entire ELT workflow dieksekusi sebagai atomic unit in in Redshift. This is ideal for business logic kompleks that requires konsistensi.

Option A: CORRECT.
Option B: INCORRECT. Not supports update/insert to dimension tables or audit trail.
Option C: INCORRECT. Mengeksekusi from luar Redshift, adds latensi network and not guarantees atomicity if connection putus.
Option D: INCORRECT. Bersifat asynchronous and not runs in single transaction.

A data engineer is migrating an ETL pipeline from Apache Spark to AWS Glue. The existing pipeline uses Spark DataFrames extensively with complex operations like custom UDFs, broadcast joins, and window functions. Some of these operations are not natively supported by Glue DynamicFrames. What is the RECOMMENDED approach to handle this migration?
  • A. Use AWS Glue DataBrew instead, which supports all Spark DataFrame operations natively for complex operations, handling the described workload reliably at scale
  • B. Run the existing Spark code on Amazon EMR instead of migrating to AWS Glue, satisfying all of the stated requirements with minimal effort
  • C. Rewrite all transformations using only DynamicFrame APIs and avoid Spark DataFrame operations entirely, meeting the latency and throughput goals of the design
  • D. Convert DynamicFrames to Spark DataFrames for complex operations using .toDF(), then convert back to DynamicFrames using fromDF() when needed for Glue-specific features
Correct Answer: D
AWS Glue supports interoperabilitas between DynamicFrames and Spark DataFrames. Uses .toDF() for konversi to DataFrame enables usage entire Spark API (UDFs, broadcast joins, window functions), while fromDF() enables konversi returns to DynamicFrame for memanfaatkan feature Glue such as bookmarks and error handling.

Option A: INCORRECT. Salah because DataBrew is tool visual that not supports Spark operations — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option B: INCORRECT. Menghindari migration sepenuhnya without gets keuntungan Glue (serverless, bookmarks, catalog integration).
Option C: INCORRECT. Membatasi fungsionalitas because DynamicFrame API more limited.
Option D: CORRECT.

A healthcare company uses Amazon Redshift to analyze patient visit data. They need to implement an ELT workflow where raw data is loaded into staging tables, then transformed using complex SQL with multiple CTEs, temporary tables, and conditional logic. The workflow must handle errors gracefully and provide detailed logging. The team prefers keeping all processing within Redshift. Which combination of Redshift features provides the MOST complete solution?
  • A. Redshift Spectrum external tables combined with Lambda functions for error handling configured for optimal performance and minimal operational overhead
  • B. Scheduled queries with SNS notifications combined with Redshift audit logging, applying schema conversion and enrichment inline
  • C. Stored procedures with exception handling (BEGIN...EXCEPTION...END) combined with system tables (STL_LOAD_ERRORS, SVL_QLOG) for logging
  • D. Materialized views with AUTO REFRESH combined with Amazon CloudWatch alarms for error detection
Correct Answer: C
Redshift stored procedures supports exception handling (BEGIN...EXCEPTION...END blocks), conditional logic (IF/ELSE), loops, variabel, CTEs, and temporary tables — all in satu procedural unit. System tables such as STL_LOAD_ERRORS and SVL_QLOG provides detailed logging native in Redshift. Ini memenuhi all requirements without exits from Redshift.

Option A: INCORRECT. Membawa processing to luar Redshift — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option B: INCORRECT. Not has exception handling or conditional logic that is required.
Option C: CORRECT.
Option D: INCORRECT. Not supports procedural logic or error handling.
