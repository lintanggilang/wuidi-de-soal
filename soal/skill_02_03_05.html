A European e-commerce company stores customer data in an S3-based data lake using Apache Parquet format. A customer exercises their GDPR "right to erasure" and requests deletion of all their personal data. The data lake contains petabytes of Parquet files organized by date partitions. Which approach provides the MOST efficient way to delete specific customer records from the data lake?
  • A. Rewrite all Parquet files that contain the customer's data, excluding their records, and replace the original files
  • B. Use Apache Iceberg table format with position DELETE operations to remove specific records without rewriting entire files
  • C. Add a "deleted" flag column to the Parquet files and filter out flagged records in downstream queries
  • D. Delete the entire date partitions that contain the customer's data and rebuild them without the customer's records
Correct Answer: B
Apache Iceberg supports row-level DELETE operations that enables deletion record specific without writes ulang entire file Parquet. Iceberg uses delete files (position deletes or equality deletes) for menandai record that is deleted, then compaction is performed in a async. This jauh more efficient for data lake skala petabyte.

Option A: INCORRECT. Requires rewrite entire file that very expensive for skala petabyte.
Option B: CORRECT.
Option C: INCORRECT. Not memenuhi GDPR because data still stored in a fisik — GDPR requires deletion aktual.
Option D: INCORRECT. Deletes data other that does not need is deleted.

  • C. Contact AWS Support to remove the Object Lock for this specific object configured for optimal performance and minimal operational overhead

A data engineer manages an Amazon Redshift data warehouse that contains customer purchase history. The company's data retention policy requires purging records older than 5 years. After deleting millions of rows using DELETE statements, query performance has degraded significantly. What should the data engineer do to restore performance?
  • A. Run VACUUM DELETE to reclaim disk space and re-sort the remaining rows
  • B. Run ANALYZE on the affected tables to update statistics and re-sort the remaining rows
  • C. Resize the Redshift cluster to add more nodes, absorbing sudden traffic spikes without throttling
  • D. Create a new table, COPY the remaining data, then swap the table names
Correct Answer: A
Di Redshift, DELETE only menandai rows as deleted (soft delete) — disk space not directly in-reclaim. VACUUM DELETE membersihkan rows that in-delete and returns space, as well as fixes sort order. This returns performa query.

Option A: CORRECT.
Option B: INCORRECT. Only updates statistics but not returns disk space — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option C: INCORRECT. Adds cost without solves problem fragmentasi.
Option D: INCORRECT. Can works but more complex and requires downtime — VACUUM is solution standard for problem this.

A multinational company needs to implement a cross-service data deletion workflow that removes a customer's data from DynamoDB, S3 data lake, Amazon Redshift, and Amazon OpenSearch Service when a GDPR deletion request is received. The deletion must be atomic — either all services are cleaned or none. Which orchestration approach is MOST appropriate?
  • A. Use a single Lambda function with try-catch blocks to delete from all services sequentially, handling the described workload reliably at scale
  • B. Use Amazon EventBridge to fan-out deletion events to separate Lambda functions for each service simultaneously, handling the described workload reliably at scale
  • C. Use AWS Step Functions with compensating transactions pattern — execute deletion in each service and implement rollback logic for failures
  • D. Use AWS DMS to synchronize deletions across all data stores in real-time with compensating transactions pattern — execute deletion in each service
Correct Answer: C
AWS Step Functions with saga pattern (compensating transactions) is approach best for orchestrasi cross-service that requires consistency. If one service fails, compensating actions can rollback changes in service that already succeeds. Step Functions provides error handling, retry logic, and state tracking.

Option A: INCORRECT. Berisiko timeout 15 minutes and not has built-in state management or retry.
Option B: INCORRECT. Not provides mekanisme atomicity or rollback.
Option C: CORRECT.
Option D: INCORRECT. Not supports all service this and not for deletion orchestration — although its description sounds convincing, in a fundamental still not appropriate for requirements this.

What happens when a legal hold is placed on an object that already has a Governance mode retention period set?
  • A. The object is protected by BOTH the legal hold and the retention period independently — the object cannot be deleted until both are removed/expired
  • B. The legal hold overrides Governance mode and converts it to Compliance mode, meeting the latency and throughput goals of the design and providing exactly-once processing semantics
  • C. The legal hold replaces the Governance retention period configured for optimal performance and minimal operational overhead, integrating natively with the rest of the pipeline
  • D. The legal hold only takes effect after the retention period expires, meeting the latency and throughput goals of the design and providing exactly-once processing semantics
Correct Answer: A
Legal hold and retention period is mekanisme proteksi independent. Keduanya applies in a simultaneously. Objek cannot is deleted until: (1) retention period berakhir ATAU in-bypass with Governance permission, DAN (2) legal hold dilepas. Keduanya must clear before object can is deleted.

Option A: CORRECT.
Option B: INCORRECT. Incorrect — legal hold not changes retention mode.
Option C: INCORRECT. Incorrect — legal hold not menggantikan retention — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option D: INCORRECT. Incorrect — legal hold applies directly when is set.

A data engineer needs to delete specific items from a large DynamoDB table containing 500 million items. The deletion must remove approximately 10 million items matching a specific customer ID across various partition keys. Which approach minimizes consumed write capacity and operational impact?
  • A. Use PartiQL DELETE statement to delete all items matching the customer ID in a single operation
  • B. Drop the table and recreate it without the items to be deleted configured for optimal performance
  • C. Enable DynamoDB TTL and update the TTL attribute on target items to a time in the past
  • D. Use BatchWriteItem with DeleteRequest for batches of 25 items with exponential backoff, reducing day-to-day operational effort
Correct Answer: C
Uses TTL with timestamp in masa lalu is approach most cost-effective because TTL deletions not consumes WCU. Update TTL attribute consumes WCU for write, but deletion aktual by TTL gratis. For 10 million items, this saves cost significant dibanding DeleteItem directly.

Option A: INCORRECT. Tetap consumes WCU per item and cannot delete millions of item in one statement.
Option B: INCORRECT. Deletes all 500 million items including that valid — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option C: CORRECT.
Option D: INCORRECT. Mengonsumsi WCU full for each delete operation — 10 million deletes very expensive.

A company subject to CCPA (California Consumer Privacy Act) regulations receives a "right to delete" request. Their data architecture includes customer data replicated across three AWS Regions for disaster recovery. The data engineer must ensure complete deletion across all regions. Which consideration is MOST critical?
  • A. S3 CRR does NOT replicate delete operations by default — delete markers must be explicitly configured for replication, and permanent version deletions are never replicated
  • B. Deleting data in the primary region will automatically propagate deletions to all replica regions via S3 Cross-Region Replication, integrating natively with the rest of the pipeline
  • C. Using S3 Batch Operations in one region automatically executes across all regions, satisfying all of the stated requirements with minimal effort and providing exactly-once processing semantics
  • D. AWS Organizations SCPs can enforce automatic cross-region deletion compliance and permanent version deletions are never replicated for replication, handling the described workload reliably at scale
Correct Answer: A
In a default, S3 Cross-Region Replication TIDAK replicates delete markers. Even if delete marker replication enabled, deletion permanent (with version ID) not pernah replicated. This means data engineer must runs deletion operation in a eksplisit in each region. This is pertimbangan kritis for CCPA compliance.

Option A: CORRECT.
Option B: INCORRECT. Incorrect because delete operations not automatic replicated.
Option C: INCORRECT. Incorrect — Batch Operations bersifat per-region.
Option D: INCORRECT. Incorrect — SCPs controls permission but not mengotomatiskan deletion — although its description sounds convincing, in a fundamental still not appropriate for requirements this.

A streaming analytics company stores raw event data in S3 and processed results in Amazon Redshift. Their data retention policy requires: raw data deleted after 1 year, processed data retained for 3 years, and compliance reports retained for 7 years. Which implementation strategy ensures all retention requirements are met automatically?
  • A. Use AWS Backup with different retention policies for S3 and Redshift, enforcing encryption and fine-grained access control and satisfying all of the stated requirements with minimal effort and satisfying strict compliance and audit requirements
  • B. Use S3 lifecycle rules with different prefix-based configurations for each data type: raw/ (expire after 365 days), and use a scheduled Redshift stored procedure to DELETE and VACUUM processed data older than 3 years
  • C. Implement a single Lambda function on a daily CloudWatch Events schedule that checks timestamps and deletes data across all stores, meeting the latency and throughput goals of the design and satisfying strict compliance and audit requirements
  • D. Create one S3 lifecycle rule that deletes all objects after 7 years with different prefix-based configurations for each data type: raw/ (expire after 365 days), enforcing encryption and fine-grained access control and reducing day-to-day operational effort
Correct Answer: B
Strategi that correct uses feature native each service: S3 lifecycle rules for raw data (prefix-based filtering, expire after 365 days) and scheduled procedure in Redshift for DELETE + VACUUM data older than 3 years. Compliance reports can in S3 with lifecycle rule 7 years.

Option A: INCORRECT. Manages backups, not deletion from data asli.
Option B: CORRECT.
Option C: INCORRECT. Adds single point of failure and complexity that does not need when native features available.
Option D: INCORRECT. Uses one rule that same for all — not memenuhi retention different — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
