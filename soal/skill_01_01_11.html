A data engineer discovers that an ETL pipeline had a bug that corrupted 3 days of data in the data warehouse. The pipeline reads from Amazon Kinesis Data Streams (retention set to 24 hours). The raw data beyond 24 hours is no longer in Kinesis. What design pattern would have enabled replay for this scenario?
  • A. Enable Kinesis Enhanced Fan-Out for the ETL consumer, integrating natively with the rest of the pipeline and providing exactly-once processing semantics
  • B. Use DynamoDB Streams instead of Kinesis for unlimited retention, meeting the latency and throughput goals of the design
  • C. Increase Kinesis retention to 365 days with native S3 integration and optimized data transfer, transforming records into the required target format
  • D. Archive raw Kinesis data to S3 using Amazon Data Firehose before ETL processing, creating a replayable raw data layer
Jawaban Benar: D
Best practice untuk replayability adalah menyimpan raw data di immutable storage (S3) sebelum pemrosesan. S3 berfungsi sebagai "source of truth" yang bisa digunakan kapan saja untuk replay. Firehose mengarchive ke S3 secara otomatis.

Opsi A: SALAH. Untuk throughput bukan retention.
Opsi B: SALAH. Hanya retain data 24 jam juga.
Opsi C: SALAH. Mahal dan Kinesis tetap lebih costly dibanding S3 — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi D: BENAR.

A company wants to implement a replayable data pipeline architecture. They want to be able to reprocess any day's data from the last 7 years. The daily data volume is 500 GB. Which storage strategy provides the MOST cost-effective replay capability?
  • A. Keep all data in S3 Standard storage class with versioning enabled, avoiding charges for idle provisioned capacity and integrating natively with the rest of the pipeline
  • B. Store raw data in S3 with lifecycle policies: Standard for 30 days, Glacier Instant Retrieval for 1 year, Glacier Deep Archive for remaining years, partitioned by date
  • C. Use Amazon Kinesis with 7-year retention period for 30 days, avoiding charges for idle provisioned capacity and satisfying all of the stated requirements with minimal effort
  • D. Store raw data in Amazon Redshift with Historical tables, avoiding charges for idle provisioned capacity and keeping steady-state operating costs low and handling the described workload reliably at scale
Jawaban Benar: B
S3 lifecycle policies mengoptimalkan biaya berdasarkan umur data. Recent data di Standard (fast access), moderate di Glacier Instant Retrieval (millisecond access, lower cost), dan old data di Deep Archive (cheapest). Date partitioning memungkinkan replay hanya hari spesifik.

Opsi A: SALAH. Sangat mahal untuk 7 tahun × 500 GB/day (~1.2 PB).
Opsi B: BENAR.
Opsi C: SALAH. Kinesis tidak mendukung 7-year retention (max 365 days) — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi D: SALAH. Sangat mahal untuk cold storage.

#DynamoDB
A data pipeline processes streaming data and writes to a DynamoDB table. The pipeline needs to be replayable without creating duplicate entries in DynamoDB. Which design principle ensures idempotent replay?
  • A. Use a natural unique key from the source data as the DynamoDB partition key, so replaying the same record overwrites rather than duplicates
  • B. Delete all DynamoDB data before each replay, satisfying all of the stated requirements with minimal effort and integrating natively with the rest of the pipeline
  • C. Use DynamoDB conditional writes with attribute_not_exists to reject duplicates, integrating natively with the rest of the pipeline and handling the described workload reliably at scale
  • D. Generate a UUID for each record's partition key to ensure uniqueness with partition-level ordering and dedicated throughput, integrating natively with the rest of the pipeline
Jawaban Benar: A
Menggunakan natural unique key (misalnya order_id, transaction_id) sebagai partition key membuat operasi idempotent. PutItem dengan key yang sama akan overwrite record yang sudah ada dengan data yang identik — tidak ada duplikasi. Ini memungkinkan replay tanpa cleanup.

Opsi A: BENAR.
Opsi B: SALAH. Menghilangkan data yang mungkin masih valid dan bukan scalable approach.
Opsi C: SALAH. Akan menolak replay yang justru diinginkan.
Opsi D: SALAH. Membuat setiap replay menghasilkan record baru (duplikasi) — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.

#MSK#Kafka#SQS
A data engineer uses Apache Kafka (Amazon MSK) for event streaming. A consumer application crashed and needs to replay events from 48 hours ago. The topic retention is set to 7 days. How does Kafka's architecture inherently support replay?
  • A. Kafka automatically replays messages to any new consumer group from the beginning configured for optimal performance and minimal operational overhead, handling the described workload reliably at scale
  • B. Kafka queues messages until acknowledged; unacknowledged messages are automatically redelivered, satisfying all of the stated requirements with minimal effort and integrating natively with the rest of the pipeline
  • C. Kafka stores messages in an immutable log; consumers can reset their consumer group offset to any point within the retention period to replay from that position
  • D. Kafka maintains a backup of consumed messages in a separate replay topic, satisfying all of the stated requirements with minimal effort and reducing day-to-day operational effort
Jawaban Benar: C
Kafka menyimpan messages dalam append-only immutable log. Messages tidak dihapus setelah consumed (berbeda dengan traditional queues). Consumers melacak posisi (offset) mereka sendiri. Offset bisa di-reset ke timestamp tertentu menggunakan kafka-consumer-groups.sh --reset-offsets atau API. Ini memungkinkan replay kapan saja dalam retention period.

Opsi A: SALAH. Perilaku default bisa "earliest" atau "latest" tergantung config — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi B: SALAH. Mendeskripsikan traditional queue (SQS), bukan Kafka.
Opsi C: BENAR.
Opsi D: SALAH. Tidak ada replay topic built-in.

#S3
A data lake architecture uses the medallion pattern (bronze/silver/gold layers) stored in S3. A bug is found in the silver layer transformation logic. The engineer needs to replay bronze data through the corrected transformation. Which characteristic of the bronze layer enables this replay?
  • A. Bronze layer uses ACID transactions to maintain data consistency, validating and cleansing each record before delivery
  • B. Bronze layer stores pre-processed and deduplicated data with append-only writes, satisfying all of the stated requirements with minimal effort
  • C. Bronze layer stores raw, immutable data in its original format with append-only writes, partitioned by ingestion timestamp
  • D. Bronze layer automatically version-controls all transformations, handling the described workload reliably at scale and reducing day-to-day operational effort
Jawaban Benar: C
Bronze layer dalam medallion pattern menyimpan data mentah persis seperti diterima (raw, immutable). Append-only berarti data tidak pernah diubah atau dihapus. Partisi berdasarkan waktu ingestion memungkinkan replay dari periode waktu tertentu. Ini adalah prinsip utama replayability — selalu simpan raw source data yang tidak dimodifikasi.

Opsi A: SALAH. Adalah fitur data format bukan prinsip replay.
Opsi B: SALAH. Bukan definisi bronze layer — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi C: BENAR.
Opsi D: SALAH. Adalah tentang code bukan data.

An e-commerce company processes order events in real-time. They need to guarantee that replaying the pipeline produces exactly the same output regardless of how many times it's run. The pipeline involves aggregating order totals per customer per day. What makes this pipeline safely replayable?
  • A. Process records in any order since aggregation is commutative, satisfying all of the stated requirements with minimal effort
  • B. Use exactly-once delivery in the messaging system, preserving strict per-key ordering across all partitions and minimizing end-to-end processing latency
  • C. Cache aggregation results and return cached values on replay and source data that doesn't change between replays
  • D. Use deterministic processing logic, idempotent writes (upsert by customer_id + date), and source data that doesn't change between replays
Jawaban Benar: D
Safe replayability membutuhkan tiga hal: (1) Deterministic logic — same input selalu menghasilkan same output, (2) Idempotent writes — menghindari duplikasi saat replay (upsert by natural key), (3) Immutable source — data sumber tidak berubah antara replays. Kombinasi ini menjamin output identik.

Opsi A: SALAH. Hanya membantu ordering tapi tidak menjamin idempotency.
Opsi B: SALAH. Membantu tapi tidak sufficient tanpa idempotent writes.
Opsi C: SALAH. Menghasilkan stale data jika replay diperlukan karena bug fix — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi D: BENAR.

A data engineer needs to design a pipeline that can replay from Kinesis Data Streams. The stream has 24-hour retention. The company wants to maintain replayability for 30 days with minimal cost and operational overhead. Which architecture achieves this?
  • A. Kinesis → Amazon Data Firehose → S3 (raw layer, 30-day retention) with the ETL pipeline reading from S3 for replay scenarios
  • B. Kinesis → Lambda → DynamoDB (raw events) with 30-day TTL for replay scenarios, running as a fully managed service with minimal operational overhead
  • C. Increase Kinesis retention to 30 days (720 hours), handling the described workload reliably at scale and optimizing cost for the described workload
  • D. Use Kinesis on-demand mode for automatic extended retention, avoiding charges for idle provisioned capacity and integrating natively with the rest of the pipeline
Jawaban Benar: A
Firehose automatically delivers semua Kinesis records ke S3 dengan near-zero operational overhead. S3 sebagai replay source sangat cost-effective. Pipeline ETL didesain untuk bisa membaca dari Kinesis (real-time) atau S3 (replay). S3 lifecycle policies menghapus data setelah 30 hari.

Opsi A: BENAR.
Opsi B: SALAH. Mahal untuk high-volume event storage — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi C: SALAH. Sangat mahal — extended retention dicharge per shard-hour.
Opsi D: SALAH. On-demand mode untuk throughput bukan retention.

#Redshift
A data pipeline writes processed data to Amazon Redshift. After a replay, the engineer notices duplicate rows in Redshift because the pipeline ran twice for the same time window. How should the pipeline be modified to support idempotent replay into Redshift?
  • A. Run VACUUM DELETE after each pipeline run to remove duplicates, meeting the latency and throughput goals of the design
  • B. Add a UNIQUE constraint on all columns to prevent duplicates, satisfying all of the stated requirements with minimal effort
  • C. Use INSERT with no-duplicate detection with partition-level ordering and dedicated throughput, handling the described workload reliably at scale
  • D. Use a staging table pattern: TRUNCATE the target partition, then INSERT new data within a transaction (DELETE+INSERT or MERGE)
Jawaban Benar: D
Staging table pattern (atau DELETE+INSERT within transaction) adalah best practice untuk idempotent writes ke Redshift. Langkahnya: (1) Load data ke staging table, (2) Begin transaction, (3) DELETE existing records untuk time window dari target, (4) INSERT from staging ke target, (5) Commit. Replay akan menghapus data lama dan memasukkan yang baru.

Opsi A: SALAH. Tidak menghapus logical duplicates.
Opsi B: SALAH. Redshift tidak enforce uniqueness constraints.
Opsi C: SALAH. Tidak mencegah duplikasi — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi D: BENAR.

#S3
A company is evaluating whether their data pipeline is replayable. The pipeline reads from a third-party API that provides data for a specific date range. The API has a 7-day lookback limit. After 7 days, historical data is no longer available from the API. What is the impact on replayability?
  • A. The pipeline is fully replayable if the API is called with the original date range parameters, satisfying all of the stated requirements with minimal effort and handling the described workload reliably at scale
  • B. The pipeline is NOT fully replayable from source after 7 days; the company must capture and persist raw API responses in S3 at ingestion time to enable replay beyond 7 days
  • C. Replayability is not affected because AWS services maintain copies of all API responses, satisfying all of the stated requirements with minimal effort and handling the described workload reliably at scale
  • D. The pipeline is fully replayable because the data is already in the data warehouse with native S3 integration and optimized data transfer, satisfying all of the stated requirements with minimal effort
Jawaban Benar: B
Jika source data memiliki window terbatas (7 hari), pipeline kehilangan kemampuan replay dari source setelah window tersebut. Untuk memastikan replayability, raw responses HARUS disimpan di S3 saat ingestion (capture at source). Ini adalah prinsip fundamental: jika source bisa hilang, simpan salinan raw data.

Opsi A: SALAH. Salah karena API tidak punya data setelah 7 hari.
Opsi B: BENAR.
Opsi C: SALAH. AWS tidak menyimpan third-party API responses.
Opsi D: SALAH. Berisi processed data, bukan raw — tidak bisa replay transformasi — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.

#MSK#Kafka#S3#Iceberg
A streaming pipeline uses Apache Kafka (MSK) for ingestion and writes to an Apache Iceberg table on S3. A data engineer needs to replay and recompute the last 5 days of data in the Iceberg table after fixing a transformation bug. Which Iceberg feature enables safe replay without affecting downstream consumers during the process?
  • A. Overwrite the last 5 partitions directly in the main table, meeting the latency and throughput goals of the design and applying schema conversion and enrichment inline
  • B. Delete the Iceberg table and recreate it from scratch, validating and cleansing each record before delivery and applying schema conversion and enrichment inline
  • C. Use Iceberg's time travel to identify the snapshot before the buggy data, create a branch, reprocess into the branch, then fast-forward merge when validated
  • D. Use Iceberg's expire_snapshots to remove buggy data configured for optimal performance and minimal operational overhead, satisfying all of the stated requirements with minimal effort
Jawaban Benar: C
Iceberg's branching (table branching) memungkinkan reprocessing di branch terpisah tanpa mempengaruhi main table yang dibaca downstream consumers. Setelah validasi, branch di-merge (fast-forward) ke main. Time travel membantu identify correct snapshot. Ini adalah safe replay pattern.

Opsi A: SALAH. Mempengaruhi downstream consumers selama reprocessing.
Opsi B: SALAH. Menyebabkan downtime dan kehilangan history.
Opsi C: BENAR.
Opsi D: SALAH. Menghapus metadata bukan data correction — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
