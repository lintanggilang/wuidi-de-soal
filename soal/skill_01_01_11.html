Skill 1.1.11: Describe Replayability of Data Ingestion Pipelines

Designing pipelines that can replay/reprocess data from any point in time, retention policies, and idempotent processing

1
A data engineer discovers that an ETL pipeline had a bug that corrupted 3 days of data in the data warehouse. The pipeline reads from Amazon Kinesis Data Streams (retention set to 24 hours). The raw data beyond 24 hours is no longer in Kinesis. What design pattern would have enabled replay for this scenario?
  • A. Archive raw Kinesis data to S3 using Amazon Data Firehose before ETL processing, creating a replayable raw data layer
  • B. Increase Kinesis retention to 365 days
  • C. Enable Kinesis Enhanced Fan-Out for the ETL consumer
  • D. Use DynamoDB Streams instead of Kinesis for unlimited retention
Jawaban Benar: A
Best practice untuk replayability adalah menyimpan raw data di immutable storage (S3) sebelum pemrosesan. S3 berfungsi sebagai "source of truth" yang bisa digunakan kapan saja untuk replay. Firehose mengarchive ke S3 secara otomatis. Opsi B (365 day retention) mahal dan Kinesis tetap lebih costly dibanding S3. Opsi C (Enhanced Fan-Out) untuk throughput bukan retention. Opsi D (DynamoDB Streams) hanya retain data 24 jam juga.
2
A company wants to implement a replayable data pipeline architecture. They want to be able to reprocess any day's data from the last 7 years. The daily data volume is 500 GB. Which storage strategy provides the MOST cost-effective replay capability?
  • A. Store raw data in S3 with lifecycle policies: Standard for 30 days, Glacier Instant Retrieval for 1 year, Glacier Deep Archive for remaining years, partitioned by date
  • B. Keep all data in S3 Standard storage class with versioning enabled
  • C. Store raw data in Amazon Redshift with Historical tables
  • D. Use Amazon Kinesis with 7-year retention period
Jawaban Benar: A
S3 lifecycle policies mengoptimalkan biaya berdasarkan umur data. Recent data di Standard (fast access), moderate di Glacier Instant Retrieval (millisecond access, lower cost), dan old data di Deep Archive (cheapest). Date partitioning memungkinkan replay hanya hari spesifik. Opsi B (Standard only) sangat mahal untuk 7 tahun × 500 GB/day (~1.2 PB). Opsi C (Redshift) sangat mahal untuk cold storage. Opsi D — Kinesis tidak mendukung 7-year retention (max 365 days).
3
A data pipeline processes streaming data and writes to a DynamoDB table. The pipeline needs to be replayable without creating duplicate entries in DynamoDB. Which design principle ensures idempotent replay?
  • A. Use a natural unique key from the source data as the DynamoDB partition key, so replaying the same record overwrites rather than duplicates
  • B. Generate a UUID for each record's partition key to ensure uniqueness
  • C. Use DynamoDB conditional writes with attribute_not_exists to reject duplicates
  • D. Delete all DynamoDB data before each replay
Jawaban Benar: A
Menggunakan natural unique key (misalnya order_id, transaction_id) sebagai partition key membuat operasi idempotent. PutItem dengan key yang sama akan overwrite record yang sudah ada dengan data yang identik — tidak ada duplikasi. Ini memungkinkan replay tanpa cleanup. Opsi B (UUID) membuat setiap replay menghasilkan record baru (duplikasi). Opsi C (conditional writes) akan menolak replay yang justru diinginkan. Opsi D (delete all) menghilangkan data yang mungkin masih valid dan bukan scalable approach.
4
A data engineer uses Apache Kafka (Amazon MSK) for event streaming. A consumer application crashed and needs to replay events from 48 hours ago. The topic retention is set to 7 days. How does Kafka's architecture inherently support replay?
  • A. Kafka stores messages in an immutable log; consumers can reset their consumer group offset to any point within the retention period to replay from that position
  • B. Kafka automatically replays messages to any new consumer group from the beginning
  • C. Kafka queues messages until acknowledged; unacknowledged messages are automatically redelivered
  • D. Kafka maintains a backup of consumed messages in a separate replay topic
Jawaban Benar: A
Kafka menyimpan messages dalam append-only immutable log. Messages tidak dihapus setelah consumed (berbeda dengan traditional queues). Consumers melacak posisi (offset) mereka sendiri. Offset bisa di-reset ke timestamp tertentu menggunakan kafka-consumer-groups.sh --reset-offsets atau API. Ini memungkinkan replay kapan saja dalam retention period. Opsi B (auto replay new group) — perilaku default bisa "earliest" atau "latest" tergantung config. Opsi C mendeskripsikan traditional queue (SQS), bukan Kafka. Opsi D tidak ada replay topic built-in.
5
A data lake architecture uses the medallion pattern (bronze/silver/gold layers) stored in S3. A bug is found in the silver layer transformation logic. The engineer needs to replay bronze data through the corrected transformation. Which characteristic of the bronze layer enables this replay?
  • A. Bronze layer stores raw, immutable data in its original format with append-only writes, partitioned by ingestion timestamp
  • B. Bronze layer stores pre-processed and deduplicated data
  • C. Bronze layer uses ACID transactions to maintain data consistency
  • D. Bronze layer automatically version-controls all transformations
Jawaban Benar: A
Bronze layer dalam medallion pattern menyimpan data mentah persis seperti diterima (raw, immutable). Append-only berarti data tidak pernah diubah atau dihapus. Partisi berdasarkan waktu ingestion memungkinkan replay dari periode waktu tertentu. Ini adalah prinsip utama replayability — selalu simpan raw source data yang tidak dimodifikasi. Opsi B (pre-processed) bukan definisi bronze layer. Opsi C (ACID) adalah fitur data format bukan prinsip replay. Opsi D (version control transformations) adalah tentang code bukan data.
6
An e-commerce company processes order events in real-time. They need to guarantee that replaying the pipeline produces exactly the same output regardless of how many times it's run. The pipeline involves aggregating order totals per customer per day. What makes this pipeline safely replayable?
  • A. Use deterministic processing logic, idempotent writes (upsert by customer_id + date), and source data that doesn't change between replays
  • B. Process records in any order since aggregation is commutative
  • C. Use exactly-once delivery in the messaging system
  • D. Cache aggregation results and return cached values on replay
Jawaban Benar: A
Safe replayability membutuhkan tiga hal: (1) Deterministic logic — same input selalu menghasilkan same output, (2) Idempotent writes — menghindari duplikasi saat replay (upsert by natural key), (3) Immutable source — data sumber tidak berubah antara replays. Kombinasi ini menjamin output identik. Opsi B (commutative) hanya membantu ordering tapi tidak menjamin idempotency. Opsi C (exactly-once) membantu tapi tidak sufficient tanpa idempotent writes. Opsi D (caching) menghasilkan stale data jika replay diperlukan karena bug fix.
7
A data engineer needs to design a pipeline that can replay from Kinesis Data Streams. The stream has 24-hour retention. The company wants to maintain replayability for 30 days with minimal cost and operational overhead. Which architecture achieves this?
  • A. Kinesis → Amazon Data Firehose → S3 (raw layer, 30-day retention) with the ETL pipeline reading from S3 for replay scenarios
  • B. Increase Kinesis retention to 30 days (720 hours)
  • C. Kinesis → Lambda → DynamoDB (raw events) with 30-day TTL
  • D. Use Kinesis on-demand mode for automatic extended retention
Jawaban Benar: A
Firehose automatically delivers semua Kinesis records ke S3 dengan near-zero operational overhead. S3 sebagai replay source sangat cost-effective. Pipeline ETL didesain untuk bisa membaca dari Kinesis (real-time) atau S3 (replay). S3 lifecycle policies menghapus data setelah 30 hari. Opsi B (30-day Kinesis retention) sangat mahal — extended retention dicharge per shard-hour. Opsi C (Lambda→DynamoDB) mahal untuk high-volume event storage. Opsi D — on-demand mode untuk throughput bukan retention.
8
A data pipeline writes processed data to Amazon Redshift. After a replay, the engineer notices duplicate rows in Redshift because the pipeline ran twice for the same time window. How should the pipeline be modified to support idempotent replay into Redshift?
  • A. Use a staging table pattern: TRUNCATE the target partition, then INSERT new data within a transaction (DELETE+INSERT or MERGE)
  • B. Use INSERT with no-duplicate detection
  • C. Add a UNIQUE constraint on all columns to prevent duplicates
  • D. Run VACUUM DELETE after each pipeline run to remove duplicates
Jawaban Benar: A
Staging table pattern (atau DELETE+INSERT within transaction) adalah best practice untuk idempotent writes ke Redshift. Langkahnya: (1) Load data ke staging table, (2) Begin transaction, (3) DELETE existing records untuk time window dari target, (4) INSERT from staging ke target, (5) Commit. Replay akan menghapus data lama dan memasukkan yang baru. Opsi B (INSERT) tidak mencegah duplikasi. Opsi C (UNIQUE constraint) — Redshift tidak enforce uniqueness constraints. Opsi D (VACUUM) tidak menghapus logical duplicates.
9
A company is evaluating whether their data pipeline is replayable. The pipeline reads from a third-party API that provides data for a specific date range. The API has a 7-day lookback limit. After 7 days, historical data is no longer available from the API. What is the impact on replayability?
  • A. The pipeline is NOT fully replayable from source after 7 days; the company must capture and persist raw API responses in S3 at ingestion time to enable replay beyond 7 days
  • B. The pipeline is fully replayable because the data is already in the data warehouse
  • C. The pipeline is fully replayable if the API is called with the original date range parameters
  • D. Replayability is not affected because AWS services maintain copies of all API responses
Jawaban Benar: A
Jika source data memiliki window terbatas (7 hari), pipeline kehilangan kemampuan replay dari source setelah window tersebut. Untuk memastikan replayability, raw responses HARUS disimpan di S3 saat ingestion (capture at source). Ini adalah prinsip fundamental: jika source bisa hilang, simpan salinan raw data. Opsi B (data warehouse) berisi processed data, bukan raw — tidak bisa replay transformasi. Opsi C salah karena API tidak punya data setelah 7 hari. Opsi D — AWS tidak menyimpan third-party API responses.
10
A streaming pipeline uses Apache Kafka (MSK) for ingestion and writes to an Apache Iceberg table on S3. A data engineer needs to replay and recompute the last 5 days of data in the Iceberg table after fixing a transformation bug. Which Iceberg feature enables safe replay without affecting downstream consumers during the process?
  • A. Use Iceberg's time travel to identify the snapshot before the buggy data, create a branch, reprocess into the branch, then fast-forward merge when validated
  • B. Delete the Iceberg table and recreate it from scratch
  • C. Overwrite the last 5 partitions directly in the main table
  • D. Use Iceberg's expire_snapshots to remove buggy data
Jawaban Benar: A
Iceberg's branching (table branching) memungkinkan reprocessing di branch terpisah tanpa mempengaruhi main table yang dibaca downstream consumers. Setelah validasi, branch di-merge (fast-forward) ke main. Time travel membantu identify correct snapshot. Ini adalah safe replay pattern. Opsi B (delete+recreate) menyebabkan downtime dan kehilangan history. Opsi C (overwrite) mempengaruhi downstream consumers selama reprocessing. Opsi D (expire_snapshots) menghapus metadata bukan data correction.
