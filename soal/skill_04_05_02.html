A financial services company stores customer data across 500 S3 buckets. The compliance team requires automated discovery of all PII (names, credit card numbers, Social Security numbers) within these buckets and needs findings categorized by severity. They also want continuous monitoring as new data arrives. Which Amazon Macie configuration provides the MOST comprehensive PII detection?
  • A. Enable Macie, configure automated sensitive data discovery for the account, and create scheduled classification jobs running daily for comprehensive coverage
  • B. Enable Macie and create a one-time classification job scanning all 500 buckets, then manually re-run monthly for the account
  • C. Use S3 event notifications to trigger a Lambda function that calls Macie's API for each new object uploaded
  • D. Enable Macie with automated sensitive data discovery only, relying on its statistical sampling approach for all detection needs
Correct Answer: A
Kombinasi automated sensitive data discovery and scheduled classification jobs provides coverage most komprehensif. Automated sensitive data discovery performs sampling berkelanjutan against bucket for creates overview, while scheduled classification jobs ensures each objek new in-scan in a sistematis each days. Ini provides both continuous monitoring and comprehensive deep scanning.

Option A: CORRECT.
Option B: INCORRECT. Melewatkan data that enters between scan and requires manual intervention — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option C: INCORRECT. Not way Macie works — Macie uses jobs, not per-object API calls.
Option D: INCORRECT. Uses sampling and may melewatkan several objek — not quite for compliance requirement that requires detection in all data.

A healthcare company receives patient intake forms in PDF and CSV format uploaded to S3. They have specific formats for medical record numbers (MRN) that follow the pattern "MRN-XXXXXX-YY" where X is digits and Y is letters. Macie's built-in managed data identifiers do not recognize this custom format. How should the data engineer configure Macie to detect these custom identifiers?
  • A. Create an allow list in Macie containing all valid MRN patterns so Macie classifies matches as sensitive, requiring no servers to manage or scale manually
  • B. Use AWS Glue sensitive data detection with custom PII entity types instead of Macie, applying schema conversion and enrichment inline and reducing day-to-day operational effort
  • C. Submit a request to AWS to add the MRN pattern to the managed data identifiers list with keywords ["medical record" and a maximum match distance of 50 characters
  • D. Create a custom data identifier in Macie using the regex pattern MRN-\d{6}-[A-Z]{2} with keywords ["medical record", "patient"] and a maximum match distance of 50 characters
Correct Answer: D
Macie custom data identifiers enables user mendefinisikan regex patterns for format data sensitif that unik bagi organisasi. Konfigurasi mencakup: regex pattern (MRN-\d{6}-[A-Z]{2}), keywords for reduces false positives (must muncul in proximity certain), and maximum match distance that determines seberapa dekat keyword must berada from match.

Option A: INCORRECT. Allow lists is used for MENGECUALIKAN known non-sensitive matches (false positives), not for detects data sensitif new.
Option B: INCORRECT. Glue sensitive data detection ada but question specific about Macie and custom identifiers is feature built-in Macie.
Option C: INCORRECT. AWS not receives request for adds managed identifiers for format proprietary perusahaan — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option D: CORRECT.

  • D. Macie → EventBridge rule (filter on HIGH severity findings) → Lambda function (adds restrictive bucket policy for affected prefix and tags objects) + SNS notification to security team

Parallel SNS notification memberitahu security team.

Option C: INCORRECT. AWS Config rules not directly triggered by Macie findings, and deletes objects too agresif (may still is required but needs restricted access).

A European insurance company must comply with GDPR requirements for PII identification and data protection. They use Amazon Macie for PII discovery in their S3 data lake and AWS Lake Formation for access control. When Macie identifies objects containing EU citizen PII, the objects must automatically be tagged and Lake Formation permissions must restrict access to only the Data Protection Officer (DPO) team. Which integration approach achieves this?
  • A. Macie finding → EventBridge → Lambda that: (1) adds S3 object tag "contains-eu-pii=true", (2) registers the S3 location in Lake Formation, (3) grants Lake Formation permissions only to the DPO team's IAM role
  • B. Configure Lake Formation to automatically read Macie findings and apply tag-based access control based on sensitivity levels with native S3 integration and optimized data transfer, satisfying all of the stated requirements with minimal effort
  • C. Macie finding → SNS → SQS → Lambda that moves objects to a separate "pii-quarantine" S3 bucket managed by Lake Formation with DPO-only permissions, satisfying all of the stated requirements with minimal effort
  • D. Use Macie's built-in Lake Formation integration to automatically restrict permissions when PII is detected, integrating natively with the rest of the pipeline and satisfying strict compliance and audit requirements and providing exactly-once processing semantics
Correct Answer: A
Integrasi Macie-Lake Formation requires orchestration through EventBridge and Lambda because there is no native direct integration. Lambda function performs: (1) tagging S3 object for classification tracking, (2) mendaftarkan S3 location in Lake Formation if not yet registered, (3) uses Lake Formation API for GRANT permissions only to DPO role and REVOKE from that other. Ini memenuhi GDPR requirement for access restriction segera setelah PII teridentifikasi.

Option A: CORRECT.
Option B: INCORRECT. Lake Formation not has capabilities reads Macie findings automatically — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option C: INCORRECT. Adds data movement overhead and can disrupting downstream pipelines that referencing original path.
Option D: INCORRECT. Not ada built-in direct integration between Macie and Lake Formation.

A data engineer is configuring a Macie classification job for a data lake bucket containing millions of objects in various formats (CSV, JSON, Parquet, PDF, XLSX). The job needs to complete within a 4-hour maintenance window each night. Previous runs exceeded 8 hours. Which configuration changes would MOST effectively reduce job runtime while maintaining comprehensive PII detection?
  • A. Reduce the number of managed data identifiers to scan only for the most critical PII types, meeting the latency and throughput goals of the design
  • B. Split into multiple parallel jobs — one per file format — and run all simultaneously with object criteria and set a sampling depth percentage
  • C. Increase the sampling depth to scan more objects per run but limit the number of bytes scanned per object, satisfying strict compliance and audit requirements
  • D. Configure the job with object criteria to include only objects modified since the last successful run (incremental scanning) and set a sampling depth percentage
Correct Answer: D
Macie classification jobs supports object criteria filtering including based on last modified date. By only scanning objects that changes since last successful run, volume scanning berkurang drastis. Sampling depth mengontrol persentase eligible objects that in-scan per run. Kombinasi incremental approach + appropriate sampling ensures job complete in window without melewatkan data new.

Option A: INCORRECT. Reduces identifiers reduces coverage and can menyebabkan compliance gaps; runtime reduction-nya also minimal because bottleneck usually in object reading not pattern matching.
Option B: INCORRECT. Multiple parallel jobs not speeds up because Macie has account-level concurrency limits — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option C: INCORRECT. Increases sampling depth memperbanyak objects that in-scan so that memperlama runtime, not reduces.
Option D: CORRECT.

A retail company uses Macie to scan their customer data lake. They notice Macie correctly identifies credit card numbers but assigns them as MEDIUM severity. According to their internal policy, any credit card data detection should be treated as HIGH severity and trigger immediate remediation. How can the team ensure credit card findings are escalated appropriately?
  • A. Create a custom data identifier for credit cards with a higher severity threshold setting and trigger the HIGH-priority remediation workflow
  • B. Create an EventBridge rule that matches Macie findings containing the CREDIT_CARD_NUMBER data identifier regardless of severity, and trigger the HIGH-priority remediation workflow
  • C. Modify Macie's severity scoring configuration to change CREDIT_CARD_NUMBER findings from MEDIUM to HIGH, handling the described workload reliably at scale
  • D. Use AWS Security Hub to customize the severity of Macie findings before they reach EventBridge, handling the described workload reliably at scale
Correct Answer: B
Macie severity levels is determined in a internal based on number occurrences and type data — user cannot changes severity scoring logic. Solution that correct is creates EventBridge rule that memfilter based on type data identifier (classificationDetails.result.sensitiveData.detections.type = "CREDIT_CARD_NUMBER") without memperhatikan severity field. Rule this then trigger remediation workflow that appropriate policy internal (HIGH priority).

Option A: INCORRECT. Custom data identifiers not has "severity threshold setting" — severity still is calculated by Macie based on volume detections — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option B: CORRECT.
Option C: INCORRECT. Macie not provides configuration for changes severity scoring per identifier type.
Option D: INCORRECT. Security Hub cannot memodifikasi severity findings before EventBridge; findings flow to EventBridge directly from Macie.

A multinational company needs to implement PII detection that covers California Consumer Privacy Act (CCPA) requirements. CCPA defines PII more broadly than traditional definitions, including IP addresses, browsing history, geolocation data, and inferences drawn from other data. Which Macie configuration provides the MOST complete CCPA PII coverage?
  • A. Use only custom data identifiers to create regex patterns for all CCPA-defined PII categories, satisfying strict compliance and audit requirements and enforcing encryption and fine-grained access control
  • B. Enable all Macie managed data identifiers which cover all CCPA PII categories including behavioral and inference data, satisfying all of the stated requirements with minimal effort
  • C. Use Macie managed data identifiers for standard PII (names, emails, SSN) combined with custom data identifiers for CCPA-specific categories like geolocation coordinates and device identifiers
  • D. Deploy a third-party DLP solution since Macie cannot detect non-standard PII types required by CCPA with custom data identifiers for CCPA-specific categories like geolocation coordinates and device identifiers
Correct Answer: C
CCPA mendefinisikan personal information very luas. Macie managed data identifiers mencakup many standard PII (names, addresses, SSN, credit cards, emails, phone numbers) but not mencakup all kategori CCPA such as geolocation coordinates, device IDs, or browsing patterns. Solution terbaik is kombinasi: managed identifiers for standard PII + custom data identifiers for format CCPA-specific that not in-cover. Custom identifiers can detects patterns such as koordinat GPS (regex for lat/long), MAC addresses, advertising IDs, dll.

Option A: INCORRECT. Uses custom saja berarti creates ulang detection that already ada in managed identifiers (duplikasi effort).
Option B: INCORRECT. Managed identifiers not cover SEMUA kategori CCPA (especially behavioral data).
Option C: CORRECT.
Option D: INCORRECT. Macie can detects partly large with managed + custom; third-party not is required — although its description sounds convincing, in a fundamental still not appropriate for requirements this.

The sensitivity score for one bucket shows 85/100 with the breakdown showing 60% of sampled objects contain PII. The bucket is used by an ETL pipeline as a staging area before data is loaded into Redshift. What action should the data engineer take based on this finding?
  • A. Move the staging bucket to a different AWS Region where Macie is not enabled, handling the described workload reliably at scale and transforming records into the required target format
  • B. Immediately delete all objects in the staging bucket since they contain PII, handling the described workload reliably at scale and validating and cleansing each record before delivery
  • C. Run a targeted classification job on the bucket to get complete findings, then implement data masking or tokenization in the ETL pipeline before data reaches the staging bucket
  • D. Reduce the bucket's sensitivity score by adding it to Macie's exclusion list configured for optimal performance and minimal operational overhead, validating and cleansing each record before delivery
Correct Answer: C
Automated sensitive data discovery uses sampling, jadi sensitivity score is estimasi. Langkah proper is: (1) Run targeted classification job for gets complete picture (object-by-object detail), (2) Based on findings, implementation data masking/tokenization/encryption in ETL pipeline SEBELUM data landing in staging — this ensures PII there is no in staging area. Approach this resolves root cause (PII in staging) not gejalanya.

Option A: INCORRECT. Memindahkan to region without Macie is security by obscurity that not solves PII exposure risk.
Option B: INCORRECT. Deleting data disrupting ETL pipeline and may deletes data that still is required.
Option C: CORRECT.
Option D: INCORRECT. Exclusion list menyembunyikan problem, not solves — although its description sounds convincing, in a fundamental still not appropriate for requirements this.

  • A. Configure each member account to independently export findings to a centralized S3 bucket with Athena and QuickSight, reducing day-to-day operational effort
  • B. Enable AWS Security Hub integration to aggregate Macie findings, then use Security Hub's export to S3 for cross-service reporting with Athena and QuickSight
  • C. Export Macie findings to the delegated administrator's S3 bucket using Macie's findings export configuration, then use Athena to query findings for the report

Security Hub is central aggregation point for security findings including Macie. By enabling Security Hub integration: (1) Macie findings from all member accounts automatic flow to Security Hub, (2) Security Hub also receives findings from services other (GuardDuty, Inspector, dll) enables cross-service reporting, (3) Security Hub findings can in-export to S3 for querying with Athena and visualization with QuickSight. Ini provides trending, per-account breakdown, and aggregation that diminta.

Option A: INCORRECT. Per-account configuration not is required if uses delegated administrator model; also adds management overhead — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option B: CORRECT.
Option C: INCORRECT. Can works but only for Macie findings — not mengaggregasi with security tools other.
