A company receives the following data: (1) 100 TB of historical transaction records updated monthly, (2) 500,000 IoT sensor readings per second, (3) customer feedback in emails, social media posts, and survey responses. How are these BEST characterized by the 3 V's?
  • A. All three are characterized primarily by high Volume
  • B. (1) High Volume/Low Velocity, (2) High Velocity/Moderate Volume, (3) High Variety
  • C. (1) High Variety, (2) High Variety, (3) High Velocity
  • D. (1) High Velocity, (2) High Volume, (3) High Volume configured for optimal performance
Jawaban Benar: B
(1) 100 TB adalah high volume, tapi monthly updates berarti low velocity (batch). (2) 500K events/second adalah high velocity (real-time streaming), volume moderat per event tapi high aggregate. (3) Emails, social media, surveys = different formats dan structures = high variety (unstructured dan semi-structured data). Setiap dataset memiliki dominant "V" yang berbeda, mempengaruhi architecture choices.

Opsi A: SALAH.
Opsi B: BENAR.
Opsi C: SALAH.
Opsi D: SALAH. Meskipun terdengar meyakinkan, tetap tidak tepat untuk skenario ini.

A data engineer is designing a pipeline for a dataset with HIGH VOLUME (50 TB daily), LOW VELOCITY (batch, once per day), and LOW VARIETY (structured CSV from one source). Which AWS service combination is MOST appropriate for this profile?
  • A. AWS Lambda for processing, DynamoDB for storage, scaling elastically to millions of events per second and providing exactly-once processing semantics
  • B. Amazon Kinesis for real-time processing, DynamoDB for storage, scaling elastically to millions of events per second
  • C. Amazon EMR with Spark for distributed batch processing, writing to S3 in Parquet format, queried via Redshift Spectrum
  • D. AWS Glue with 2 DPUs, writing to a single RDS instance for distributed batch processing
Jawaban Benar: C
50 TB daily membutuhkan distributed processing framework (Spark on EMR). Batch velocity berarti tidak perlu streaming services. Low variety (structured CSV) simplifies transformation. S3 + Parquet optimal untuk large-volume analytics. Redshift Spectrum queries without loading.

Opsi A: SALAH. Cannot process 50 TB.
Opsi B: SALAH. Overkill untuk batch processing — Kinesis untuk streaming, DynamoDB untuk operational data bukan 50 TB analytics.
Opsi C: BENAR.
Opsi D: SALAH. Vastly underpowered — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.

A social media company ingests data from multiple sources: user posts (JSON), images (binary), videos (binary), click events (structured logs), and relationship graphs (graph data). This data exhibits high VARIETY. Which storage strategy accommodates all these data types in a unified data lake?
  • A. Use separate AWS accounts for each data type, satisfying all of the stated requirements with minimal effort and handling the described workload reliably at scale and providing exactly-once processing semantics
  • B. Convert all data to CSV and store in a single S3 prefix with different prefixes per data type and format-appropriate processing services per type, handling the described workload reliably at scale
  • C. Store all data in Amazon RDS with BLOB columns for binary data, integrating natively with the rest of the pipeline and meeting the latency and throughput goals of the design
  • D. Amazon S3 as the central data lake with different prefixes per data type, AWS Glue Data Catalog for metadata management across all formats, and format-appropriate processing services per type
Jawaban Benar: D
S3 data lake adalah solusi terbaik untuk high variety karena menerima semua format tanpa schema requirements (schema-on-read). Prefix-based organization memisahkan data types. Glue Data Catalog menyediakan unified metadata layer. Tiap tipe data bisa diproses dengan service yang sesuai (Athena untuk structured, Rekognition untuk images, dll).

Opsi A: SALAH. Menambah complexity.
Opsi B: SALAH. Kehilangan fidelity data dan impractical untuk images/videos — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi C: SALAH. Tidak cocok untuk binary/unstructured data at scale.
Opsi D: BENAR.

A company needs to process data that is HIGH VELOCITY (1 million events per second) with LOW latency requirements (results needed within 100ms). Each event is a small JSON payload (500 bytes). Which processing architecture meets these requirements?
  • A. Amazon Kinesis Data Streams with Enhanced Fan-Out consumers running on Amazon Managed Service for Apache Flink for sub-second stateful processing
  • B. AWS Batch with scheduled jobs every minute, satisfying all of the stated requirements with minimal effort and minimizing end-to-end processing latency
  • C. AWS Glue Streaming ETL writing to S3 every 60 seconds, absorbing sudden traffic spikes without throttling and minimizing end-to-end processing latency
  • D. Amazon SQS with Lambda consumers for Apache Flink for sub-second stateful processing, satisfying all of the stated requirements with minimal effort
Jawaban Benar: A
1M events/sec dengan 100ms latency requirement membutuhkan true streaming with low latency. Kinesis + Enhanced Fan-Out provides dedicated throughput (~70ms latency). Apache Flink melakukan stateful processing dengan millisecond-level latency.

Opsi A: BENAR.
Opsi B: SALAH. Batch processing cannot achieve 100ms latency.
Opsi C: SALAH. Micro-batch setiap 60 detik, tidak bisa 100ms.
Opsi D: SALAH. SQS polling adds latency, Lambda cold starts, not designed for 1M/sec — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.

#Glue#Redshift
A healthcare company stores structured patient records (SQL databases), semi-structured lab results (JSON/HL7), and unstructured clinical notes (free text documents). They need to query across all three types simultaneously. Which approach handles this variety for cross-type querying?
  • A. ETL all data into a common structured format in Amazon Redshift using Glue to normalize schemas, enabling SQL queries across all data types
  • B. Store everything as unstructured text files configured for optimal performance and minimal operational overhead, integrating natively with the rest of the pipeline
  • C. Keep each data type in its native format and query separately, satisfying all of the stated requirements with minimal effort and reducing day-to-day operational effort
  • D. Use Amazon Comprehend Medical on all data types directly, meeting the latency and throughput goals of the design and delivering records with consistent sub-second latency
Jawaban Benar: A
Untuk cross-type querying, data harus di-normalize ke format yang queriable bersama. ETL processes extract structured fields dari semi-structured (JSON parsing) dan unstructured (NLP/NER extraction) data, creating a unified schema di Redshift. SQL queries kemudian bisa join across patient records, lab results, dan extracted entities dari clinical notes.

Opsi A: BENAR.
Opsi B: SALAH. Kehilangan structure — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi C: SALAH. Tidak memungkinkan cross-type joins.
Opsi D: SALAH. Untuk NLP extraction bukan querying.

A data engineer is asked to classify a dataset: 10 GB of CSV files arriving once per week from an FTP server, containing structured inventory counts. Which characterization is CORRECT?
  • A. High Volume — requires EMR cluster for distributed processing, satisfying all of the stated requirements with minimal effort and integrating natively with the rest of the pipeline
  • B. Low Volume (10 GB is relatively small), Low Velocity (weekly batch), Low Variety (single structured format) — suitable for simple batch processing with Glue or even Lambda
  • C. High Variety — requires multiple parsing engines, meeting the latency and throughput goals of the design and handling the described workload reliably at scale and reducing day-to-day operational effort
  • D. High Velocity — requires Kinesis for real-time processing with Glue or even Lambda, integrating natively with the rest of the pipeline and handling the described workload reliably at scale
Jawaban Benar: B
10 GB per week is low volume (by big data standards). Weekly arrival is low velocity. Single CSV format is low variety. This dataset doesn't require big data tools. AWS Glue with minimal DPUs atau bahkan Lambda (jika file < 10 GB dan processing simple) sudah cukup. Over-engineering dengan EMR atau Kinesis membuang resources.

Opsi A: SALAH. 10 GB easily fits single-node processing.
Opsi B: BENAR.
Opsi C: SALAH. Single CSV format is lowest variety.
Opsi D: SALAH. Weekly batch is opposite of high velocity — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.

An e-commerce platform processes: clickstream (100K events/sec), orders (1K/sec), and product reviews (100/day). The data engineer needs to determine which requires streaming vs. batch processing. Which classification is CORRECT?
  • A. Clickstream: batch, Orders: streaming, Reviews: streaming, guaranteeing exactly-ordered delivery within each key group and providing exactly-once processing semantics
  • B. All three should use streaming for consistency, preserving strict per-key ordering across all partitions and minimizing end-to-end processing latency
  • C. Clickstream: streaming (high velocity, time-sensitive for recommendations). Orders: streaming (real-time inventory/payment). Reviews: batch (low velocity, not time-sensitive)
  • D. All three should use batch processing for simplicity with real-time processing and low-latency data delivery
Jawaban Benar: C
Processing paradigm depends on velocity AND time-sensitivity of insights. Clickstream (100K/sec) membutuhkan streaming untuk real-time personalization. Orders (1K/sec) membutuhkan streaming untuk real-time inventory deduction dan payment processing. Reviews (100/day) sangat low velocity dan insights tidak time-critical — batch processing harian sudah memadai dan lebih cost-effective.

Opsi A: SALAH. Inverts priorities.
Opsi B: SALAH. Over-engineers reviews.
Opsi C: BENAR.
Opsi D: SALAH. Misses real-time requirements — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.

A data engineer is designing storage for a data lake that receives structured data (60%), semi-structured JSON/XML (30%), and unstructured data like PDFs and images (10%). Which S3 storage organization strategy BEST handles this variety?
  • A. Create separate S3 buckets for each format type with sub-folders by source system, meeting the latency and throughput goals of the design
  • B. Store all data in a single flat prefix sorted by date, satisfying all of the stated requirements with minimal effort
  • C. Organize by data zone (raw/curated/consumption) with sub-folders by source system and format, using Glue crawlers to catalog structured and semi-structured data separately
  • D. Convert all data to Parquet before storing, meeting the latency and throughput goals of the design and handling the described workload reliably at scale
Jawaban Benar: C
Zone-based organization (raw → curated → consumption) memisahkan data by processing stage. Sub-folders by source/format enable format-appropriate processing. Glue crawlers auto-discover schemas untuk structured and semi-structured data. Unstructured data (PDFs, images) disimpan di raw zone untuk processing oleh AI/ML services.

Opsi A: SALAH. Over-complicates governance — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi B: SALAH. Menyulitkan format-specific processing.
Opsi C: BENAR.
Opsi D: SALAH. PDFs dan images tidak bisa di-convert ke Parquet.

A telecommunications company processes call detail records (CDRs). During normal hours, the volume is 50,000 records per second. During New Year's midnight, volume spikes to 500,000 records per second for 30 minutes. Which AWS service configuration handles this velocity variability?
  • A. Amazon Kinesis Data Streams in On-Demand mode which automatically scales to handle the 10x traffic spike without pre-provisioning
  • B. AWS Glue Streaming ETL with fixed DPUs with parallel processing and horizontal scaling capabilities, absorbing sudden traffic spikes without throttling
  • C. Amazon SQS Standard queue with Lambda consumers, meeting the latency and throughput goals of the design
  • D. Kinesis with fixed 500 shards provisioned 24/7 to handle the peak, scaling elastically to millions of events per second
Jawaban Benar: A
Kinesis On-Demand mode secara otomatis scales capacity berdasarkan throughput aktual. Untuk spike events yang jarang (New Year), On-Demand menghindari paying for 500 shards 24/7 ketika hanya 50 shards needed normally. Scales up dalam detik untuk spike dan scales down setelah.

Opsi A: BENAR.
Opsi B: SALAH. Tidak auto-scale — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi C: SALAH. Bisa handle variability tapi SQS doesn't guarantee ordering needed for CDR processing.
Opsi D: SALAH. Sangat mahal — membayar 10x capacity 99.9% waktu.

A data architect needs to design a solution that handles ALL three V's simultaneously: 10 TB daily volume of data arriving at 100K events/second (velocity) in 20 different formats from various systems (variety). Which architecture addresses all three dimensions?
  • A. AWS Glue batch job running every hour with real-time processing and low-latency data delivery, transforming records into the required target format
  • B. Amazon DynamoDB for all data storage and processing, handling the described workload reliably at scale and applying schema conversion and enrichment inline
  • C. Single RDS database to receive all data, applying schema conversion and enrichment inline and transforming records into the required target format
  • D. Kinesis Data Streams (velocity) → Lambda/Firehose for format normalization (variety) → S3 data lake in Parquet (volume) → EMR/Athena for analytics
Jawaban Benar: D
Architecture addresses each V: Kinesis handles high velocity (100K/sec). Lambda/Firehose transformation layer normalizes 20 formats (variety) into common schema. S3 data lake stores 10 TB/day cost-effectively (volume). EMR/Athena process large volume data for analytics. This is the Lambda Architecture pattern addressing all three V's simultaneously.

Opsi A: SALAH. Doesn't address velocity requirement — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi B: SALAH. Expensive at 10 TB/day and doesn't handle variety well.
Opsi C: SALAH. Cannot handle any of the three V's at this scale.
Opsi D: BENAR.
