Skill 1.2.9: Define Volume, Velocity, and Variety of Data

Understanding the 3 V's of big data: structured/unstructured data, batch/streaming patterns, and scale considerations

1
A company receives the following data: (1) 100 TB of historical transaction records updated monthly, (2) 500,000 IoT sensor readings per second, (3) customer feedback in emails, social media posts, and survey responses. How are these BEST characterized by the 3 V's?
  • A. (1) High Volume/Low Velocity, (2) High Velocity/Moderate Volume, (3) High Variety
  • B. (1) High Velocity, (2) High Volume, (3) High Volume
  • C. All three are characterized primarily by high Volume
  • D. (1) High Variety, (2) High Variety, (3) High Velocity
Jawaban Benar: A
(1) 100 TB adalah high volume, tapi monthly updates berarti low velocity (batch). (2) 500K events/second adalah high velocity (real-time streaming), volume moderat per event tapi high aggregate. (3) Emails, social media, surveys = different formats dan structures = high variety (unstructured dan semi-structured data). Setiap dataset memiliki dominant "V" yang berbeda, mempengaruhi architecture choices.
2
A data engineer is designing a pipeline for a dataset with HIGH VOLUME (50 TB daily), LOW VELOCITY (batch, once per day), and LOW VARIETY (structured CSV from one source). Which AWS service combination is MOST appropriate for this profile?
  • A. Amazon EMR with Spark for distributed batch processing, writing to S3 in Parquet format, queried via Redshift Spectrum
  • B. Amazon Kinesis for real-time processing, DynamoDB for storage
  • C. AWS Lambda for processing, DynamoDB for storage
  • D. AWS Glue with 2 DPUs, writing to a single RDS instance
Jawaban Benar: A
50 TB daily membutuhkan distributed processing framework (Spark on EMR). Batch velocity berarti tidak perlu streaming services. Low variety (structured CSV) simplifies transformation. S3 + Parquet optimal untuk large-volume analytics. Redshift Spectrum queries without loading. Opsi B (Kinesis + DynamoDB) overkill untuk batch processing — Kinesis untuk streaming, DynamoDB untuk operational data bukan 50 TB analytics. Opsi C (Lambda) cannot process 50 TB. Opsi D (2 DPUs + single RDS) vastly underpowered.
3
A social media company ingests data from multiple sources: user posts (JSON), images (binary), videos (binary), click events (structured logs), and relationship graphs (graph data). This data exhibits high VARIETY. Which storage strategy accommodates all these data types in a unified data lake?
  • A. Amazon S3 as the central data lake with different prefixes per data type, AWS Glue Data Catalog for metadata management across all formats, and format-appropriate processing services per type
  • B. Store all data in Amazon RDS with BLOB columns for binary data
  • C. Use separate AWS accounts for each data type
  • D. Convert all data to CSV and store in a single S3 prefix
Jawaban Benar: A
S3 data lake adalah solusi terbaik untuk high variety karena menerima semua format tanpa schema requirements (schema-on-read). Prefix-based organization memisahkan data types. Glue Data Catalog menyediakan unified metadata layer. Tiap tipe data bisa diproses dengan service yang sesuai (Athena untuk structured, Rekognition untuk images, dll). Opsi B (RDS) tidak cocok untuk binary/unstructured data at scale. Opsi C (separate accounts) menambah complexity. Opsi D (convert to CSV) kehilangan fidelity data dan impractical untuk images/videos.
4
A company needs to process data that is HIGH VELOCITY (1 million events per second) with LOW latency requirements (results needed within 100ms). Each event is a small JSON payload (500 bytes). Which processing architecture meets these requirements?
  • A. Amazon Kinesis Data Streams with Enhanced Fan-Out consumers running on Amazon Managed Service for Apache Flink for sub-second stateful processing
  • B. AWS Glue Streaming ETL writing to S3 every 60 seconds
  • C. Amazon SQS with Lambda consumers
  • D. AWS Batch with scheduled jobs every minute
Jawaban Benar: A
1M events/sec dengan 100ms latency requirement membutuhkan true streaming with low latency. Kinesis + Enhanced Fan-Out provides dedicated throughput (~70ms latency). Apache Flink melakukan stateful processing dengan millisecond-level latency. Opsi B (Glue Streaming) — micro-batch setiap 60 detik, tidak bisa 100ms. Opsi C (SQS + Lambda) — SQS polling adds latency, Lambda cold starts, not designed for 1M/sec. Opsi D (Batch) — batch processing cannot achieve 100ms latency.
5
A healthcare company stores structured patient records (SQL databases), semi-structured lab results (JSON/HL7), and unstructured clinical notes (free text documents). They need to query across all three types simultaneously. Which approach handles this variety for cross-type querying?
  • A. ETL all data into a common structured format in Amazon Redshift using Glue to normalize schemas, enabling SQL queries across all data types
  • B. Keep each data type in its native format and query separately
  • C. Store everything as unstructured text files
  • D. Use Amazon Comprehend Medical on all data types directly
Jawaban Benar: A
Untuk cross-type querying, data harus di-normalize ke format yang queriable bersama. ETL processes extract structured fields dari semi-structured (JSON parsing) dan unstructured (NLP/NER extraction) data, creating a unified schema di Redshift. SQL queries kemudian bisa join across patient records, lab results, dan extracted entities dari clinical notes. Opsi B (separate queries) tidak memungkinkan cross-type joins. Opsi C (text files) kehilangan structure. Opsi D (Comprehend Medical) untuk NLP extraction bukan querying.
6
A data engineer is asked to classify a dataset: 10 GB of CSV files arriving once per week from an FTP server, containing structured inventory counts. Which characterization is CORRECT?
  • A. Low Volume (10 GB is relatively small), Low Velocity (weekly batch), Low Variety (single structured format) — suitable for simple batch processing with Glue or even Lambda
  • B. High Volume — requires EMR cluster for distributed processing
  • C. High Velocity — requires Kinesis for real-time processing
  • D. High Variety — requires multiple parsing engines
Jawaban Benar: A
10 GB per week is low volume (by big data standards). Weekly arrival is low velocity. Single CSV format is low variety. This dataset doesn't require big data tools. AWS Glue with minimal DPUs atau bahkan Lambda (jika file < 10 GB dan processing simple) sudah cukup. Over-engineering dengan EMR atau Kinesis membuang resources. Opsi B — 10 GB easily fits single-node processing. Opsi C — weekly batch is opposite of high velocity. Opsi D — single CSV format is lowest variety.
7
An e-commerce platform processes: clickstream (100K events/sec), orders (1K/sec), and product reviews (100/day). The data engineer needs to determine which requires streaming vs. batch processing. Which classification is CORRECT?
  • A. Clickstream: streaming (high velocity, time-sensitive for recommendations). Orders: streaming (real-time inventory/payment). Reviews: batch (low velocity, not time-sensitive)
  • B. All three should use streaming for consistency
  • C. All three should use batch processing for simplicity
  • D. Clickstream: batch, Orders: streaming, Reviews: streaming
Jawaban Benar: A
Processing paradigm depends on velocity AND time-sensitivity of insights. Clickstream (100K/sec) membutuhkan streaming untuk real-time personalization. Orders (1K/sec) membutuhkan streaming untuk real-time inventory deduction dan payment processing. Reviews (100/day) sangat low velocity dan insights tidak time-critical — batch processing harian sudah memadai dan lebih cost-effective. Opsi B (all streaming) over-engineers reviews. Opsi C (all batch) misses real-time requirements. Opsi D inverts priorities.
8
A data engineer is designing storage for a data lake that receives structured data (60%), semi-structured JSON/XML (30%), and unstructured data like PDFs and images (10%). Which S3 storage organization strategy BEST handles this variety?
  • A. Organize by data zone (raw/curated/consumption) with sub-folders by source system and format, using Glue crawlers to catalog structured and semi-structured data separately
  • B. Store all data in a single flat prefix sorted by date
  • C. Create separate S3 buckets for each format type
  • D. Convert all data to Parquet before storing
Jawaban Benar: A
Zone-based organization (raw → curated → consumption) memisahkan data by processing stage. Sub-folders by source/format enable format-appropriate processing. Glue crawlers auto-discover schemas untuk structured and semi-structured data. Unstructured data (PDFs, images) disimpan di raw zone untuk processing oleh AI/ML services. Opsi B (flat by date) menyulitkan format-specific processing. Opsi C (separate buckets) over-complicates governance. Opsi D — PDFs dan images tidak bisa di-convert ke Parquet.
9
A telecommunications company processes call detail records (CDRs). During normal hours, the volume is 50,000 records per second. During New Year's midnight, volume spikes to 500,000 records per second for 30 minutes. Which AWS service configuration handles this velocity variability?
  • A. Amazon Kinesis Data Streams in On-Demand mode which automatically scales to handle the 10x traffic spike without pre-provisioning
  • B. Kinesis with fixed 500 shards provisioned 24/7 to handle the peak
  • C. Amazon SQS Standard queue with Lambda consumers
  • D. AWS Glue Streaming ETL with fixed DPUs
Jawaban Benar: A
Kinesis On-Demand mode secara otomatis scales capacity berdasarkan throughput aktual. Untuk spike events yang jarang (New Year), On-Demand menghindari paying for 500 shards 24/7 ketika hanya 50 shards needed normally. Scales up dalam detik untuk spike dan scales down setelah. Opsi B (500 shards fixed) sangat mahal — membayar 10x capacity 99.9% waktu. Opsi C (SQS + Lambda) bisa handle variability tapi SQS doesn't guarantee ordering needed for CDR processing. Opsi D (Glue fixed DPUs) tidak auto-scale.
10
A data architect needs to design a solution that handles ALL three V's simultaneously: 10 TB daily volume of data arriving at 100K events/second (velocity) in 20 different formats from various systems (variety). Which architecture addresses all three dimensions?
  • A. Kinesis Data Streams (velocity) → Lambda/Firehose for format normalization (variety) → S3 data lake in Parquet (volume) → EMR/Athena for analytics
  • B. Single RDS database to receive all data
  • C. AWS Glue batch job running every hour
  • D. Amazon DynamoDB for all data storage and processing
Jawaban Benar: A
Architecture addresses each V: Kinesis handles high velocity (100K/sec). Lambda/Firehose transformation layer normalizes 20 formats (variety) into common schema. S3 data lake stores 10 TB/day cost-effectively (volume). EMR/Athena process large volume data for analytics. This is the Lambda Architecture pattern addressing all three V's simultaneously. Opsi B (RDS) cannot handle any of the three V's at this scale. Opsi C (hourly Glue) doesn't address velocity requirement. Opsi D (DynamoDB) expensive at 10 TB/day and doesn't handle variety well.
