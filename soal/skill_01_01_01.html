1
A financial services company needs to process stock trade events in real time with sub-second latency. The data must be processed in the exact order it was produced per trading symbol. The system must scale to handle millions of events per second during market peaks. Which AWS service and configuration best meets these requirements?
  • A. Amazon Kinesis Data Streams with partition keys set to the trading symbol
  • B. Amazon MSK with a single partition per topic
  • C. Amazon SQS FIFO queues with message group IDs set to the trading symbol
  • D. Amazon DynamoDB Streams with a global secondary index on the trading symbol
Jawaban Benar: A
Amazon Kinesis Data Streams memastikan urutan per shard menggunakan partition key. Dengan menetapkan partition key ke trading symbol, semua event untuk simbol yang sama masuk ke shard yang sama, menjaga urutan. Kinesis juga dirancang untuk throughput tinggi dengan jutaan event per detik. Opsi B dengan satu partisi tidak bisa scale. Opsi C (SQS FIFO) memiliki batas throughput 3.000 pesan/detik per message group. Opsi D (DynamoDB Streams) bukan untuk ingestion berskala besar tapi untuk change data capture.
2
A media company streams clickstream data from their website to Amazon MSK. A data engineer needs to consume this data and write it to Amazon S3 in near real-time for downstream analytics. Which approach provides the MOST operationally efficient solution?
  • A. Write a custom Kafka consumer on Amazon EC2 that reads from MSK and writes to S3
  • B. Use Amazon MSK Connect with an S3 sink connector
  • C. Use AWS Lambda to poll MSK topics and write to S3
  • D. Create an AWS Glue streaming job to consume from MSK and write to S3
Jawaban Benar: B
Amazon MSK Connect adalah solusi paling operasionally efisien untuk mengirim data dari MSK ke S3. MSK Connect adalah layanan fully managed yang menjalankan Kafka Connect connectors tanpa perlu mengelola infrastruktur. S3 sink connector sudah tersedia dan tinggal dikonfigurasi. Opsi A memerlukan pengelolaan EC2 instances. Opsi C (Lambda) memiliki batas timeout 15 menit dan overhead cold start. Opsi D (Glue) bisa dilakukan tapi lebih mahal dan memiliki kompleksitas lebih untuk use case sederhana ini.
3
A retail company uses Amazon DynamoDB as their primary database for inventory management. They need to capture all changes to inventory items and trigger downstream analytics pipelines whenever items reach low-stock thresholds. The solution must not impact the performance of the production DynamoDB table. Which approach should the data engineer implement?
  • A. Enable DynamoDB Streams on the table and configure a Lambda function as a stream consumer
  • B. Use AWS DMS with DynamoDB as a source and Kinesis Data Streams as a target
  • C. Schedule an AWS Glue crawler to scan the DynamoDB table every minute
  • D. Use Amazon CloudWatch metrics on the table and trigger alarms based on item counts
Jawaban Benar: A
DynamoDB Streams menangkap perubahan data (inserts, updates, deletes) secara real-time tanpa mempengaruhi performa tabel produksi. Lambda sebagai consumer dapat memproses setiap perubahan dan memicu pipeline analytics ketika threshold tercapai. Opsi B (DMS) lebih cocok untuk migrasi atau replikasi berkelanjutan ke target lain, bukan untuk triggering logic. Opsi C (Glue crawler) memindai metadata schema bukan data aktual, dan tidak real-time. Opsi D (CloudWatch) tidak bisa mendeteksi perubahan per-item secara granular.
4
A healthcare company is migrating their on-premises Oracle database to Amazon Aurora PostgreSQL. During the migration period, they need to continuously replicate changes from Oracle to a Kinesis Data Stream so that downstream microservices can consume the change events. Which solution meets this requirement?
  • A. Use AWS DMS with change data capture (CDC) and a Kinesis Data Stream as the target endpoint
  • B. Use Oracle GoldenGate to write directly to Kinesis Data Streams
  • C. Export Oracle redo logs to S3 and use a Lambda function to write to Kinesis
  • D. Configure AWS Glue to read Oracle CDC logs and stream data to Kinesis
Jawaban Benar: A
AWS DMS mendukung CDC (Change Data Capture) dari Oracle sebagai source dan Kinesis Data Streams sebagai target endpoint. Ini adalah solusi paling terintegrasi dan managed untuk streaming change events ke Kinesis. Opsi B membutuhkan lisensi tambahan dan infrastruktur GoldenGate. Opsi C sangat kompleks dan tidak real-time. Opsi D (Glue) tidak memiliki native CDC reader untuk Oracle redo logs secara streaming.
5
A data engineer is designing a real-time analytics pipeline using Amazon Kinesis Data Streams. The stream receives 5,000 records per second with an average record size of 50 KB. The engineer needs to determine the number of shards required. What is the MINIMUM number of shards needed to handle this throughput?
  • A. 5 shards
  • B. 50 shards
  • C. 250 shards
  • D. 500 shards
Jawaban Benar: C
Setiap shard Kinesis mendukung hingga 1 MB/detik atau 1.000 records/detik untuk write. Berdasarkan throughput data: 5.000 records × 50 KB = 250.000 KB/detik = ~244 MB/detik. Berdasarkan volume: 244 MB / 1 MB per shard = 244 shards (dibulatkan ke 250). Berdasarkan jumlah records: 5.000 / 1.000 = 5 shards. Bottleneck ada pada throughput data (MB/s), sehingga minimal 250 shards diperlukan. Opsi A dan B terlalu sedikit. Opsi D berlebihan.
6
A logistics company uses Amazon MSK to process GPS location events from their fleet of delivery trucks. They want to enrich each event with driver information stored in Amazon DynamoDB before loading it into Amazon Redshift. The enrichment must happen in real-time. Which architecture provides the MOST scalable solution?
  • A. Use AWS Glue streaming ETL to consume from MSK, lookup DynamoDB, and write to Redshift
  • B. Use Kafka Streams application on Amazon ECS to join MSK data with DynamoDB and write to Redshift via JDBC
  • C. Use Amazon Kinesis Data Analytics (Apache Flink) to consume MSK, use async I/O to query DynamoDB, and sink to Redshift Streaming Ingestion
  • D. Use Lambda triggered by MSK to query DynamoDB and insert into Redshift using Data API
Jawaban Benar: A
AWS Glue streaming ETL dapat mengonsumsi data dari MSK, melakukan lookup ke DynamoDB menggunakan DynamicFrame atau native Spark lookups, dan menulis ke Redshift. Ini adalah solusi paling scalable karena fully managed dan autoscaling. Opsi B membutuhkan pengelolaan ECS dan JDBC connections ke Redshift. Opsi C menggunakan Flink yang lebih kompleks, dan Redshift Streaming Ingestion hanya mendukung Kinesis/MSK langsung, bukan dari Flink. Opsi D (Lambda) memiliki batas concurrency dan timeout, serta Redshift Data API bersifat asynchronous yang menambah latensi.
7
A data engineer needs to read data from an Amazon Kinesis Data Stream with multiple consumer applications. Each application must be able to read the full stream independently with dedicated throughput. The engineer also needs to minimize read latency to under 200ms. Which feature should be enabled?
  • A. Enable Kinesis Enhanced Fan-Out for registered consumers
  • B. Increase the number of shards to provide more read capacity
  • C. Use Kinesis Client Library (KCL) with multiple worker instances
  • D. Configure GetRecords API with a shorter polling interval
Jawaban Benar: A
Enhanced Fan-Out memberikan dedicated 2 MB/detik throughput per consumer per shard menggunakan HTTP/2 push (SubscribeToShard). Ini menghilangkan sharing throughput antar consumer dan memberikan latensi rata-rata ~70ms. Opsi B (menambah shard) meningkatkan total throughput tapi consumer masih berbagi 2 MB/s per shard. Opsi C (KCL workers) hanya untuk scaling processing, bukan dedicated throughput. Opsi D (polling) dibatasi 5 GetRecords calls/detik per shard shared antar semua consumer, dengan latensi lebih tinggi (~200-1000ms).
8
A telecommunications company needs to implement a streaming data pipeline that reads call detail records (CDRs) from an on-premises system. The data must be ingested into AWS in near real-time for fraud detection. The on-premises system can only produce data in CSV format over SFTP. Which combination of AWS services provides the MOST efficient streaming ingestion path?
  • A. AWS Transfer Family (SFTP) → Amazon S3 → S3 Event Notification → Lambda → Kinesis Data Streams
  • B. AWS Direct Connect → Amazon Kinesis Agent on-premises → Kinesis Data Streams
  • C. AWS DataSync → Amazon S3 → AWS Glue Streaming ETL → Kinesis Data Streams
  • D. AWS DMS with SFTP as a source endpoint → Kinesis Data Streams as target
Jawaban Benar: A
AWS Transfer Family menyediakan SFTP endpoint yang managed dan langsung menulis ke S3. S3 Event Notification memicu Lambda yang membaca CSV, mengubah ke format yang sesuai, dan menulis ke Kinesis Data Streams. Ini cocok karena source hanya bisa SFTP. Opsi B (Kinesis Agent) membutuhkan instalasi agent di on-premises dan tidak mendukung SFTP natively. Opsi C (Glue Streaming) tidak bisa membaca dari S3 secara streaming (hanya batch). Opsi D (DMS) tidak mendukung SFTP sebagai source endpoint.
9
A gaming company streams player activity events to Amazon Kinesis Data Streams. During a new game launch, the stream experiences significant throttling with ProvisionedThroughputExceededException errors. The data engineer wants to dynamically scale the stream without changing the producer application code. Which solution addresses this issue?
  • A. Switch to Kinesis Data Streams On-Demand capacity mode
  • B. Implement exponential backoff in the producer application
  • C. Use UpdateShardCount API to double the number of shards
  • D. Enable server-side encryption to improve throughput
Jawaban Benar: A
Kinesis Data Streams On-Demand mode secara otomatis menskalakan kapasitas berdasarkan throughput aktual tanpa perlu provisioning manual. Ini menghilangkan throttling tanpa perubahan kode producer. Opsi B (exponential backoff) hanya menangani retry tapi tidak menyelesaikan masalah kapasitas, dan membutuhkan perubahan kode. Opsi C (UpdateShardCount) membutuhkan monitoring manual dan tetap bisa throttle jika traffic spike melebihi kapasitas baru. Opsi D (encryption) tidak berhubungan dengan throughput.
10
A data engineer at an e-commerce company needs to implement real-time streaming ingestion into Amazon Redshift from an Amazon MSK cluster. The data should be available for querying in Redshift within seconds of being produced to MSK. The engineer wants to minimize ETL complexity. Which approach is MOST appropriate?
  • A. Use Amazon Redshift Streaming Ingestion to create a materialized view on the MSK topic
  • B. Use MSK Connect with a Redshift JDBC sink connector
  • C. Use AWS Glue streaming job to read from MSK and write to Redshift using JDBC
  • D. Use Amazon Data Firehose to consume from MSK and deliver to Redshift
Jawaban Benar: A
Amazon Redshift Streaming Ingestion memungkinkan Redshift membaca langsung dari Amazon MSK (atau Kinesis) melalui materialized view, tanpa perlu staging di S3 atau ETL pipeline tambahan. Data tersedia dalam hitungan detik. Ini adalah solusi paling sederhana dengan minimal ETL complexity. Opsi B (JDBC sink) membutuhkan konfigurasi connector dan management. Opsi C (Glue) menambah layer ETL. Opsi D (Firehose) menambahkan latensi karena buffering interval (minimum 60 detik) dan staging ke S3.
