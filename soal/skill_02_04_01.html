1
A data engineer is designing an Amazon Redshift schema for a sales analytics data warehouse. The primary query pattern involves filtering by date and joining the fact table with dimension tables. The fact table contains 5 billion rows with sales transactions spanning 3 years. Which distribution and sort key strategy provides OPTIMAL query performance?
  • A. EVEN distribution on the fact table with an interleaved sort key on date and product_id
  • B. KEY distribution on the most frequently joined column (product_id) with a compound sort key starting with transaction_date
  • C. ALL distribution on the fact table with a compound sort key on transaction_date
  • D. KEY distribution on transaction_date with no sort key for maximum write performance
Jawaban Benar: B
KEY distribution pada kolom yang paling sering di-join (seperti product_id) memastikan bahwa rows dengan value yang sama berada di node yang sama, menghindari data redistribution saat join. Compound sort key yang dimulai dengan transaction_date memungkinkan zone maps untuk melakukan block-level pruning pada filter tanggal, sangat efektif untuk range queries. Opsi A (EVEN + interleaved) — interleaved sort key memiliki overhead maintenance yang tinggi untuk tabel besar. Opsi C (ALL distribution) tidak mungkin untuk tabel 5 miliar rows — ALL hanya cocok untuk dimension tables kecil. Opsi D (distribute on date) akan menyebabkan data skew jika tanggal tidak merata.
2
A social media company is designing a DynamoDB table to store user posts. Access patterns include: (1) Get all posts by a user sorted by timestamp, (2) Get a specific post by user and post ID, (3) Get all posts with a specific hashtag sorted by engagement score. Which key design supports ALL three access patterns?
  • A. Partition key: user_id, Sort key: timestamp. GSI with partition key: hashtag, sort key: engagement_score
  • B. Partition key: post_id only. GSI with partition key: user_id, sort key: timestamp
  • C. Partition key: user_id, Sort key: post_id. GSI with partition key: hashtag, sort key: timestamp
  • D. Partition key: hashtag, Sort key: engagement_score. GSI with partition key: user_id, sort key: timestamp
Jawaban Benar: A
Pattern 1 (posts by user sorted by time): PK=user_id, SK=timestamp memungkinkan query dengan ScanIndexForward. Pattern 2 (specific post): bisa menggunakan PK=user_id dan filter pada post_id (atau encode post_id dalam sort key dengan composite key). Pattern 3 (hashtag + engagement): GSI dengan PK=hashtag, SK=engagement_score. Opsi B tidak mendukung pattern 1 efisien dari base table. Opsi C menggunakan post_id sebagai sort key yang tidak mendukung sorting by timestamp secara native. Opsi D menggunakan hashtag sebagai PK utama yang menyebabkan hot partition untuk hashtag populer.
3
A data engineer is implementing a star schema in Amazon Redshift for a retail analytics platform. The dimension tables range from 1,000 rows (store dimension) to 5 million rows (customer dimension). The fact table has 10 billion rows. Which distribution strategy should be applied to the dimension tables?
  • A. ALL distribution for all dimension tables regardless of size
  • B. ALL distribution for small dimensions (store: 1,000 rows) and KEY distribution for large dimensions (customer: 5M rows) on their primary key
  • C. EVEN distribution for all dimension tables
  • D. KEY distribution for all dimension tables on their primary key
Jawaban Benar: B
Strategi optimal: dimension kecil (< beberapa juta rows) gunakan ALL distribution sehingga seluruh tabel direplikasi di setiap node, menghindari redistribution saat join. Dimension besar (5M+ rows) gunakan KEY distribution pada kolom join ke fact table, karena ALL distribution untuk tabel besar membuang storage dan memperlambat write. Opsi A membuang storage untuk dimension 5M rows yang direplikasi di setiap node. Opsi C (EVEN) akan memerlukan data redistribution saat setiap join. Opsi D (KEY semua) tidak optimal untuk dimension kecil yang lebih baik direplikasi penuh.
4
A data engineer designs a DynamoDB single-table design for an e-commerce platform. The table stores Orders, Products, and Customers in one table using overloaded partition and sort keys (PK/SK). The engineer needs to model a one-to-many relationship where one customer has many orders. Which key pattern correctly implements this?
  • A. PK: CUSTOMER#<id>, SK: CUSTOMER#<id> for customer record; PK: CUSTOMER#<id>, SK: ORDER#<order_id> for each order
  • B. PK: ORDER#<order_id>, SK: CUSTOMER#<customer_id> for linking orders to customers
  • C. PK: CUSTOMER#<id>, SK: METADATA for customer; separate PK: ORDER#<order_id>, SK: METADATA for each order with no partition key connection
  • D. Store a list of order IDs as a Set attribute within the customer item
Jawaban Benar: A
Dalam single-table design, one-to-many relationship dimodelkan dengan menempatkan parent dan children items di partition key yang sama. PK=CUSTOMER#123, SK=CUSTOMER#123 untuk record customer, dan PK=CUSTOMER#123, SK=ORDER#456 untuk setiap order. Ini memungkinkan satu Query operation untuk mendapatkan customer beserta semua order-nya. Opsi B memisahkan orders ke partition berbeda sehingga tidak bisa query customer + orders dalam satu operasi. Opsi C tidak memanfaatkan item collection. Opsi D melanggar best practice karena Set memiliki batas 400KB per item dan tidak scalable.
5
A data lake architect needs to design a partitioning strategy for a Lake Formation table that stores IoT sensor data. The table receives 100 million records daily and common queries filter by device_type (5 types), region (10 regions), and date. Current query patterns primarily filter by date range and region. Which partitioning strategy BEST optimizes query performance?
  • A. Partition by year/month/day/hour for maximum granularity
  • B. Partition by region and year/month/day (multi-level partitioning)
  • C. Partition by device_type, region, and year/month/day/hour
  • D. No partitioning — rely on columnar format (Parquet) with predicate pushdown
Jawaban Benar: B
Partitioning harus mengikuti query patterns utama. Karena queries terutama filter by date range dan region, partition by region/year/month/day memungkinkan Athena dan Redshift Spectrum melakukan partition pruning yang efektif. Opsi A (hanya date hourly) terlalu banyak partisi (365×24 = 8.760/tahun) dan tidak memanfaatkan region filter. Opsi C (3 level + hourly) menghasilkan partition explosion: 5×10×365×24 = 438.000 partisi/tahun yang terlalu banyak dan menyebabkan overhead metadata. Opsi D (no partition) memaksa full scan 100M records/hari yang sangat lambat untuk tabel besar.
6
A data engineer receives JSON data with nested and variable structures from multiple API sources. They need to store and query this data in Amazon Redshift. The JSON schema changes frequently with new fields added by upstream teams. Which Redshift data type is MOST appropriate for this use case?
  • A. VARCHAR(MAX) to store raw JSON strings and parse with JSON_EXTRACT_PATH_TEXT at query time
  • B. SUPER data type with schemaless storage and PartiQL queries for navigation
  • C. Multiple VARCHAR columns with one column per known JSON field
  • D. VARBYTE type for binary JSON storage with UDF for parsing
Jawaban Benar: B
Redshift SUPER data type dirancang untuk semi-structured data (JSON, arrays, nested objects). SUPER menyimpan data dalam format binary yang efisien, mendukung schemaless ingestion (schema-on-read), dan bisa di-query menggunakan PartiQL atau dot notation. Ini ideal ketika schema sering berubah. Opsi A (VARCHAR + JSON functions) bekerja tapi less efficient — tidak ada columnar optimization dan parsing ulang setiap query. Opsi C (multiple columns) tidak flexible ketika fields berubah. Opsi D (VARBYTE) untuk binary data, bukan structured JSON navigation.
7
A data engineer is designing a Redshift schema for an advertising analytics platform. Queries frequently aggregate impression counts by campaign_id for specific date ranges. The table has 20 billion rows distributed across a 10-node cluster. Which sort key strategy minimizes I/O for these queries?
  • A. Interleaved sort key on (impression_date, campaign_id) for equal weight filtering
  • B. Compound sort key with impression_date as the leading column followed by campaign_id
  • C. Compound sort key with campaign_id as the leading column followed by impression_date
  • D. No sort key — use materialized views for pre-aggregation instead
Jawaban Benar: B
Compound sort key dengan impression_date sebagai leading column optimal ketika queries selalu filter by date range terlebih dahulu. Zone maps di Redshift menyimpan min/max values per block — leading sort column memungkinkan maximum block skipping. Date range filter mengeliminasi sebagian besar blocks, kemudian campaign_id filter diterapkan pada subset yang tersisa. Opsi A (interleaved) memiliki overhead VACUUM yang tinggi untuk tabel 20B rows dan tidak seefisien compound ketika ada satu dominant filter pattern. Opsi C menempatkan campaign_id pertama — kurang efisien karena range scan pada date lebih selective. Opsi D menghindari masalah tapi menambah storage cost.
8
A gaming company uses DynamoDB to track player inventory. Each player can have up to 500 items. The most common operations are: (1) Get all items for a player, (2) Get a specific item for a player, (3) Update quantity of a specific item. The data engineer wants to avoid hot partitions. Which table design is MOST appropriate?
  • A. Partition key: player_id, Sort key: item_id. Store each inventory item as a separate DynamoDB item
  • B. Partition key: player_id only. Store entire inventory as a JSON Map attribute in a single item
  • C. Partition key: item_id, Sort key: player_id. Create GSI with player_id as partition key
  • D. Partition key: composite of player_id#shard_number with write sharding
Jawaban Benar: A
PK=player_id, SK=item_id mendukung semua access patterns secara optimal: (1) Query PK=player_id mendapatkan semua items, (2) GetItem PK=player_id SK=item_id mendapatkan item spesifik, (3) UpdateItem PK=player_id SK=item_id memperbarui quantity. Dengan 500 items per player, item collection masih di bawah 10GB partition limit. Opsi B (single item JSON) memiliki batas 400KB per item dan setiap update memerlukan read-modify-write seluruh map. Opsi C (item_id sebagai PK) tidak efisien untuk "get all items by player". Opsi D (write sharding) tidak diperlukan — player_id sudah memberikan distribusi yang baik natural.
9
A retail data warehouse team is debating between star schema and snowflake schema for their Redshift implementation. The warehouse serves both ad-hoc analyst queries and BI dashboard reports. The product dimension has sub-dimensions: category → subcategory → brand hierarchy. Which approach is RECOMMENDED for Amazon Redshift?
  • A. Snowflake schema to normalize product dimensions into separate tables for storage efficiency
  • B. Star schema with denormalized product dimension containing all hierarchy levels in one table
  • C. Third normal form (3NF) for all tables to maintain data integrity
  • D. Separate schemas for analysts (snowflake) and dashboards (star) with ETL between them
Jawaban Benar: B
Star schema dengan denormalized dimensions adalah best practice untuk Amazon Redshift. Redshift dioptimalkan untuk join patterns sederhana (fact-to-dimension) dan columnar storage membuat denormalization murah dari segi storage. Denormalized dimension mengurangi jumlah joins, meningkatkan query performance. Opsi A (snowflake) menambah joins yang mahal di Redshift — setiap join memerlukan data redistribution. Opsi C (3NF) sangat tidak cocok untuk analytics workload — terlalu banyak joins. Opsi D menambah kompleksitas maintenance tanpa benefit signifikan — satu star schema melayani keduanya dengan baik.
10
A data engineer is designing a data lake table in AWS Lake Formation for customer transaction data. The table will be queried by multiple teams using Athena, Redshift Spectrum, and EMR. The data arrives as JSON and needs to be stored optimally. Which combination of format and schema approach is MOST appropriate for the data lake?
  • A. Store as raw JSON with schema-on-read using Glue Crawlers to infer schema automatically
  • B. Convert to Apache Parquet with schema-on-write, register in Glue Data Catalog, and partition by date
  • C. Store as CSV with explicit headers and create Athena views for schema abstraction
  • D. Convert to Apache ORC and store without Glue Data Catalog registration
Jawaban Benar: B
Apache Parquet dengan schema-on-write adalah best practice untuk data lake analytics. Parquet menyediakan columnar storage yang efficient, compression yang baik, dan predicate pushdown. Registrasi di Glue Data Catalog memungkinkan discovery oleh semua query engines (Athena, Spectrum, EMR). Partitioning by date memungkinkan partition pruning. Opsi A (raw JSON) sangat tidak efisien untuk analytics — tidak columnar, tidak compressed optimal, dan schema inference bisa bermasalah. Opsi C (CSV) tidak mendukung complex types, tidak columnar, dan compression kurang baik. Opsi D (ORC tanpa catalog) tidak bisa di-discover oleh Lake Formation dan tools lainnya.
