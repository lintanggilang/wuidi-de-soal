Using SageMaker Catalog (DataZone) projects to control and govern data access

1
A large enterprise has 200+ data assets across multiple AWS accounts. Data scientists frequently request access to datasets but the current process involves manual Jira tickets, taking 2-3 weeks for approval. They want to implement a self-service data access platform with governance guardrails. Which Amazon DataZone (SageMaker Catalog) architecture enables this?
  • A. Create a DataZone domain, organize data assets into projects by domain ownership, enable the data catalog for discovery, configure approval workflows for subscription requests, and provision environments for approved consumers
  • B. Use AWS Service Catalog to create pre-approved data access products that teams can self-provision, integrating natively with the rest of the pipeline and satisfying all of the stated requirements with minimal effort
  • C. Create an AWS Glue Data Catalog shared across accounts and use Lake Formation for access control without DataZone, meeting the latency and throughput goals of the design and providing exactly-once processing semantics
  • D. Build a custom portal using Amazon API Gateway and Lambda that automates IAM role creation for data access and provision environments for approved consumers, handling the described workload reliably at scale
Correct Answer: A
Amazon DataZone (integrated as SageMaker Catalog) designed for exactly this use case: self-service data discovery and governed access. Architecture-nya: (1) Domain — organizational container for governance, (2) Projects — has data assets, dikategorikan per domain ownership (marketing, finance, etc), (3) Data catalog — enables data scientists search and discover assets, (4) Subscription requests — consumers request access that routes through approval workflow (owner/steward approval), (5) Environments — provisioned compute access setelah approval. Proses 2-3 weeks menjadi minutes-to-hours.

Option A: CORRECT.
Option B: INCORRECT. Service Catalog for infrastructure provisioning, not data governance.
Option C: INCORRECT. Glue + Lake Formation provides access control but not discovery portal, approval workflow, or self-service experience.
Option D: INCORRECT. Custom build expensive and doesn't leverage managed governance features — although its description sounds convincing, in a fundamental still not appropriate for requirements this.

A data governance team is setting up Amazon DataZone projects. They need to define who can publish data products, who can subscribe to them, and who approves subscription requests. The organization has three roles: Data Producers (publish datasets), Data Consumers (use datasets), and Data Stewards (approve access). How should project membership and roles be configured?
  • A. Use a single project with custom Lambda authorizers to handle role-based actions for publishing), handling the described workload reliably at scale and integrating natively with the rest of the pipeline and meeting the latency and throughput goals of the design
  • B. Create one project for all users and use IAM policies to differentiate roles, integrating natively with the rest of the pipeline and satisfying all of the stated requirements with minimal effort and handling the described workload reliably at scale
  • C. Create producer projects where data teams publish assets (members have "Project Owner" or "Project Contributor" roles for publishing), create consumer projects for analytics teams (members request subscriptions), and assign Data Stewards as reviewers in the domain's approval workflow configuration
  • D. Create separate DataZone domains for producers and consumers with cross-domain sharing, handling the described workload reliably at scale and integrating natively with the rest of the pipeline and meeting the latency and throughput goals of the design
Correct Answer: C
DataZone project structure separates concerns: Producer projects contain teams that own and publish data assets — members with "Project Owner" role can publish and manage, "Project Contributor" can contribute assets. Consumer projects contain teams that subscribe to and use data — mereka initiate subscription requests. Data Stewards is configured sebagai approvers in domain or project level for review subscription requests. Separation of producer/consumer projects mencerminkan organizational boundaries and responsibility.

Option A: INCORRECT. Custom Lambda authorizers not bagian from DataZone architecture — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option B: INCORRECT. Single project not supports proper governance separation; all users seeing all assets without discovery process.
Option C: CORRECT.
Option D: INCORRECT. Separate domains too extreme; domains typically represent organizations, not roles.

A data scientist discovers a dataset called "customer_transactions" in the Amazon DataZone catalog and wants to use it for a churn prediction model. The dataset is owned by the Finance team's project. What is the correct workflow for the data scientist to get access to this dataset?
  • A. Directly access the underlying S3 path of the dataset since it's visible in the catalog, integrating natively with the rest of the pipeline and meeting the latency and throughput goals of the design
  • B. Clone the dataset into the data scientist's own project using the catalog's copy feature, integrating natively with the rest of the pipeline and meeting the latency and throughput goals of the design
  • C. Submit a subscription request through the DataZone portal specifying the dataset and purpose → Finance team's project owner/steward reviews the request → Upon approval, DataZone automatically provisions access in the data scientist's project environment
  • D. Ask the Finance team to manually share IAM credentials for the dataset's S3 bucket configured for optimal performance and minimal operational overhead, satisfying all of the stated requirements with minimal effort and reducing day-to-day operational effort
Correct Answer: C
DataZone subscription workflow is inti from governed data access: (1) Consumer discovers asset in catalog, (2) Consumer submits subscription request — menyertakan use case/purpose, (3) Asset owner or designated steward reviews request, (4) Upon approval, DataZone automatically grants access — this can berupa Lake Formation permissions, Redshift datashare access, or Glue catalog permissions depends underlying data source, (5) Consumer can query data from their project's environment. Catalog visibility ≠ data access — Anda can melihat metadata but must request subscription for actual data access.

Option A: INCORRECT. Catalog visibility not berarti data access; this is key governance principle.
Option B: INCORRECT. DataZone not has "copy feature" that bypass subscription.
Option C: CORRECT.
Option D: INCORRECT. Manual credential sharing bypasses governance — although its description sounds convincing, in a fundamental still not appropriate for requirements this.

A company's compliance team needs an audit trail showing: who requested access to which data assets, when requests were approved/denied, who approved them, and when access was actually used. They use Amazon DataZone for data governance. Which combination of features provides this complete audit trail?
  • A. CloudTrail alone provides all audit information for DataZone activities with CloudTrail for API-level actions, integrating natively with the rest of the pipeline and protecting the data both in transit and at rest
  • B. DataZone subscription activity logs (showing requests, approvals, denials) combined with CloudTrail for API-level actions and the underlying data service logs (Athena query logs, Redshift audit logs) for actual data usage
  • C. AWS Config records all DataZone configuration changes which serves as the audit trail, meeting the latency and throughput goals of the design and handling the described workload reliably at scale
  • D. DataZone's built-in compliance reporting dashboard provides all required audit data in one view, integrating natively with the rest of the pipeline and meeting the latency and throughput goals of the design
Correct Answer: B
Complete audit trail requires multiple layers: (1) DataZone tracks subscription lifecycle — who requested, what was requested, purpose stated, who approved/denied, timestamps for each state change. (2) CloudTrail captures API-level actions — DataZone API calls, environment provisioning, access grant operations. (3) Underlying service logs capture actual data usage — Athena query logs show what queries ran against subscribed tables, Redshift audit logs show query history, S3 access logs show object access patterns. Kombinasi tiga layer this provides full picture: request → approval → actual usage.

Option A: INCORRECT. CloudTrail logs API calls but not subscription workflow details or actual data query activity — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option B: CORRECT.
Option C: INCORRECT. Config tracks resource configuration, not access patterns or approval workflows.
Option D: INCORRECT. DataZone not has built-in compliance reporting dashboard that comprehensive.

A data platform team wants to publish a curated "customer_360" dataset as a data product in Amazon DataZone. The underlying data comes from three sources: S3 (raw data), Redshift (aggregated metrics), and a Glue table (transformed features). They want consumers to access a unified view without knowing the underlying sources. Which DataZone publishing approach achieves this?
  • A. Export all data to a single S3 bucket and share the bucket ARN through DataZone, applying schema conversion and enrichment inline and integrating natively with the rest of the pipeline and handling the described workload reliably at scale and meeting the latency and throughput goals of the design
  • B. Create a DataZone "composite asset" that virtually joins the three sources at query time with comprehensive metadata and lineage tracking, transforming records into the required target format and validating and cleansing each record before delivery and applying schema conversion and enrichment inline and providing exactly-once processing semantics
  • C. Publish each source (S3, Redshift, Glue) as separate assets and let consumers subscribe to all three individually, meeting the latency and throughput goals of the design and transforming records into the required target format and integrating natively with the rest of the pipeline and reducing day-to-day operational effort
  • D. Create a Glue ETL job that consolidates all three sources into a single curated table, register this table as a data asset in the DataZone catalog with comprehensive metadata (description, schema, quality metrics, lineage), and publish it as a single data product from the producer project
Correct Answer: D
Best practice for data products is provides curated, ready-to-consume datasets. Consolidating three sources to single curated table (via Glue ETL) then publishing sebagai single asset provides: (1) clean consumer experience — satu subscription, satu table, (2) abstraction — consumers does not need tahu about underlying 3 sources, (3) quality control — producer ensures data quality before publishing, (4) rich metadata — description, schema documentation, data quality scores, lineage showing where data came from.

Option A: INCORRECT. Sharing raw bucket ARN bypasses catalog governance and metadata enrichment.
Option B: INCORRECT. DataZone not has "composite asset" feature that auto-joins sources — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option C: INCORRECT. Three separate subscriptions creates friction and exposes implementation details to consumers.
Option D: CORRECT.

A company uses Amazon DataZone with multiple projects across different AWS accounts. When a subscription is approved for a Glue table asset, DataZone needs to automatically grant the consumer project's environment access to the underlying data. What happens behind the scenes when a subscription is approved for a Glue-based asset?
  • A. DataZone creates a VPN connection between producer and consumer VPCs for data transfer, integrating natively with the rest of the pipeline and handling the described workload reliably at scale
  • B. DataZone copies the data to the consumer's AWS account S3 bucket, satisfying all of the stated requirements with minimal effort and meeting the latency and throughput goals of the design
  • C. DataZone sends the consumer a pre-signed URL to download the dataset configured for optimal performance and minimal operational overhead, handling the described workload reliably at scale and reducing day-to-day operational effort
  • D. DataZone grants Lake Formation permissions on the Glue table to the consumer project's IAM role, enabling the consumer to query the data through their environment (e.g., Athena) without data movement
Correct Answer: D
When subscription approved for Glue-based asset, DataZone automatically orchestrates access grants through AWS Lake Formation. Proses: (1) DataZone identifies consumer project's environment IAM role, (2) Grants Lake Formation SELECT permission on Glue table/columns to consumer role, (3) If cross-account, uses RAM share for Lake Formation resource sharing, (4) Consumer can directly query uses Athena or tools other in their environment — data still in location asli (zero-copy). Ini is key architectural principle: access granting, not data copying.

Option A: INCORRECT. VPN not is required; access is performed through AWS service APIs.
Option B: INCORRECT. No data copying occurs; this zero-copy access.
Option C: INCORRECT. Pre-signed URLs not mekanisme that is used; this would bypass governance setelah download — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option D: CORRECT.

A data governance team wants to implement time-limited data access through Amazon DataZone. When a data scientist subscribes to a sensitive dataset for a specific research project, access should automatically expire after 90 days. How can they implement this time-bound access pattern?
  • A. Set the IAM role's session duration to 90 days so credentials expire, enforcing encryption and fine-grained access control
  • B. Configure the DataZone subscription grant with an expiration date; DataZone automatically revokes access when the subscription expires
  • C. Add a DynamoDB TTL entry that triggers automatic access revocation through DynamoDB Streams with an expiration date; DataZone automatically revokes access when
  • D. Use an EventBridge scheduled rule that triggers a Lambda function after 90 days to call DataZone's revoke-subscription API and remove Lake Formation grants
Correct Answer: B
Amazon DataZone supports subscription grants with expiration/time-based access. When approving subscription request, approver or policy can sets grant duration. Setelah expiration date is reached, DataZone automatically revokes access — deletes Lake Formation permissions, Redshift datashare access, or access mechanism other that is provided. Consumer needs re-subscribe and mendapat re-approval if still requires access setelah expiry. Ini built-in feature for temporary access patterns.

Option A: INCORRECT. IAM session duration max 12 hours (for assumed roles), not 90 days; this not mekanisme that correct.
Option B: CORRECT.
Option C: INCORRECT. Over-engineered and fragile solution for built-in capability — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option D: INCORRECT. Custom automation can works but over-engineers sesuatu that already built-in.

A company has both structured data (in Redshift and Glue tables) and unstructured data (documents in S3) that they want to catalog and govern through DataZone. A marketing team needs access to customer survey PDFs stored in S3 for sentiment analysis. How does DataZone handle access to unstructured S3 data assets?
  • A. Unstructured data must be registered through a separate AWS service (Kendra) before DataZone can govern it, integrating natively with the rest of the pipeline and meeting the latency and throughput goals of the design and minimizing end-to-end processing latency
  • B. Register the S3 location as a DataZone asset with appropriate metadata, publish to catalog. Upon subscription approval, DataZone grants S3 access (via IAM/bucket policies) to the consumer project's environment role, allowing them to access the S3 objects
  • C. DataZone automatically converts unstructured data to structured format before granting access with appropriate metadata, meeting the latency and throughput goals of the design and satisfying all of the stated requirements with minimal effort and minimizing end-to-end processing latency
  • D. DataZone only supports structured data; unstructured S3 objects cannot be cataloged or governed, meeting the latency and throughput goals of the design and handling the described workload reliably at scale and integrating natively with the rest of the pipeline
Correct Answer: B
DataZone can manage assets berbagai type including S3-based unstructured data. Process: (1) Register S3 location (prefix or specific objects) sebagai asset in DataZone, (2) Enrich with metadata — description, classification tags, owner information, (3) Publish to catalog so that discoverable, (4) Consumers subscribe and setelah approved, DataZone provisions S3 access through IAM role permissions or bucket policy updates that allow consumer role for GetObject on S3 path that registered. Consumer then access files through their environment.

Option A: INCORRECT. Kendra is search service; DataZone itself can register S3 assets.
Option B: CORRECT.
Option C: INCORRECT. DataZone not mengkonversi format; this governance layer not transformation tool — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option D: INCORRECT. DataZone supports baik structured maupun unstructured data assets.

A DataZone domain administrator needs to define different approval workflows for different sensitivity levels of data. Public datasets should be auto-approved (no manual review needed), internal datasets require manager approval, and confidential datasets require both the data steward AND the CISO's approval. How should they configure the approval workflows?
  • A. Configure metadata forms with a sensitivity classification field on assets, then set up subscription approval policies at the project or domain level that route approvals based on the asset's sensitivity metadata — auto-approve for "public", single approver for "internal", multi-level approval for "confidential"
  • B. Create three separate DataZone domains — one for each sensitivity level — with different approval configurations configured for optimal performance and minimal operational overhead, enforcing encryption and fine-grained access control and satisfying strict compliance and audit requirements and handling the described workload reliably at scale
  • C. Use a single auto-approve policy for all assets and rely on IAM policies to restrict access to confidential data, meeting the latency and throughput goals of the design and handling the described workload reliably at scale and satisfying strict compliance and audit requirements
  • D. Implement approval workflows entirely outside DataZone using Step Functions and notify DataZone after external approval, satisfying strict compliance and audit requirements and enforcing encryption and fine-grained access control and protecting the data both in transit and at rest and minimizing end-to-end processing latency
Correct Answer: A
DataZone supports metadata-driven approval policies. Assets can in-classify uses metadata forms (sensitivity level: public, internal, confidential). Subscription approval policies is configured per project or domain and can reference asset metadata for determines approval flow: (1) Public — auto-approve policy, no manual intervention needed, (2) Internal — single approver (project owner/manager), (3) Confidential — multi-level approval chain. Ini provides governance proportional to data sensitivity without over-burdening access to low-risk data.

Option A: CORRECT.
Option B: INCORRECT. Separate domains for sensitivity levels is over-architecture and prevents cross-sensitivity discovery — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option C: INCORRECT. Auto-approve everything undermines governance for sensitive data.
Option D: INCORRECT. External workflow adds complexity; DataZone has built-in approval capabilities.

A company's data platform team is evaluating whether to use Amazon DataZone environments provisioned through "Blueprints" or to manage environments separately. A consumer project needs access to subscribed data through both Athena (for SQL queries) and SageMaker Studio (for ML experiments). What is the role of DataZone environment blueprints in this scenario?
  • A. Blueprints are only for data producers to configure how data is stored, not for consumer access, integrating natively with the rest of the pipeline and meeting the latency and throughput goals of the design and handling the described workload reliably at scale
  • B. Blueprints only support one tool per project — the consumer must choose either Athena or SageMaker with access and ML access to the same governed data, handling the described workload reliably at scale and satisfying all of the stated requirements with minimal effort
  • C. Blueprints create separate copies of data optimized for each tool (columnar for Athena, tensor for SageMaker), handling the described workload reliably at scale and integrating natively with the rest of the pipeline and meeting the latency and throughput goals of the design
  • D. Blueprints are templates that provision compute environments (like Athena workgroups, SageMaker Studio domains) pre-configured with access to subscribed data assets. The project can have multiple environments from different blueprints, giving users both SQL and ML access to the same governed data
Correct Answer: D
DataZone environment blueprints is templates that provision ready-to-use compute environments for project members. Sebuah project can has MULTIPLE environments from different blueprints: (1) "Data Lake" blueprint provisions Athena workgroup with IAM role that already has access to subscribed Glue tables, (2) "ML" blueprint provisions SageMaker Studio domain with IAM role that can access subscribed data. Kedua environments share same underlying data access (via Lake Formation grants) but provides different tools. Users can SQL query in Athena DAN run ML experiments in SageMaker on data that same, all governed by subscription.

Option A: INCORRECT. Blueprints is used baik producer maupun consumer sides.
Option B: INCORRECT. Multiple environments per project are supported — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option C: INCORRECT. Blueprints not copy data; mereka provision compute access to same underlying data.
Option D: CORRECT.
