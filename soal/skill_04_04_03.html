A security team at a large enterprise needs to investigate a potential data breach that occurred across multiple AWS accounts over the past 6 months. They need to run SQL queries to identify all IAM users who accessed specific S3 buckets containing PII data. The team currently stores CloudTrail logs in S3. Which approach provides the FASTEST time to investigation with the LEAST operational setup?
  • A. Set up Amazon Athena tables pointing to the CloudTrail S3 logs and run SQL queries using partition projection
  • B. Deploy Amazon OpenSearch Service, ingest the 6 months of CloudTrail logs, and use OpenSearch SQL for investigation
  • C. Import existing CloudTrail logs from S3 into a CloudTrail Lake event data store and query immediately after import completes
  • D. Create a CloudTrail Lake organization event data store, wait for events to be ingested, and run SQL queries directly
Correct Answer: C
CloudTrail Lake supports import of existing CloudTrail logs from S3 to event data store. Setelah import complete, team can directly runs SQL queries on data historis the said. Ini provides fastest time-to-investigation because does not need waits events new terkumpul and does not need setup infrastructure.

Option A: INCORRECT. Requires setup: creates table, configuration partition projection, and memahami format log — more operational setup.
Option B: INCORRECT. Requires provisioning cluster, configuration ingestion, and time indexing — most many setup.
Option C: CORRECT.
Option D: INCORRECT. Only will captures events new setelah creation, not data historis 6 months.

A company with 100 AWS accounts under AWS Organizations wants to centrally query CloudTrail events using SQL. They need to capture both management events and S3 data events across all accounts. The solution must retain events for 2555 days (7 years) for compliance. Which CloudTrail Lake configuration is MOST appropriate?
  • A. Create one organization event data store with both management and data events enabled, set retention to 2555 days with one-year extendable pricing
  • B. Create one organization event data store for management events with 2555-day retention using seven-year extendable pricing, and a separate one for S3 data events
  • C. Create individual event data stores in each account and query them separately from the management account with 2555-day retention using seven-year extendable pricing
  • D. Create separate event data stores for management events (7-year retention) and data events (1-year retention) to optimize costs, handling the described workload reliably at scale
Correct Answer: B
Memisahkan management events and data events to event data stores that different is best practice because: (1) data events usually produces volume jauh higher with cost that significant, (2) retention requirements may different, (3) seven-year extendable pricing more cost-effective for retention 2555 days dibanding one-year extendable pricing. Organization event data store automatically mengumpulkan events from all member accounts.

Option A: INCORRECT. Menggabungkan semuanya that less optimal from segi cost and management.
Option B: CORRECT.
Option C: INCORRECT. Not scalable for 100 accounts and cannot cross-account query — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option D: INCORRECT. Has retention too pendek for data events if compliance requires 7 years.

A data engineer needs to write a CloudTrail Lake SQL query to find all IAM role assumption events (AssumeRole) that originated from outside the company's known IP ranges (10.0.0.0/8 and 172.16.0.0/12) in the past 24 hours. Which query is CORRECT?
  • A. SELECT eventTime, element_at(userIdentity, 'arn') as user_arn, sourceIPAddress FROM $EDS_ID WHERE eventName = 'AssumeRole' AND sourceIPAddress NOT LIKE '10.%' AND sourceIPAddress NOT LIKE '172.16.%' AND eventTime > '2024-01-01'
  • B. SELECT eventTime, userIdentity.arn, sourceIPAddress FROM event_data_store_id WHERE eventName = 'AssumeRole' AND sourceIPAddress NOT LIKE '10.%' AND sourceIPAddress NOT LIKE '172.16.%' AND eventTime > date_add('hour', -24, now())
  • C. SELECT eventTime, userIdentity.arn, sourceIPAddress FROM $EDS_ID WHERE eventName = 'AssumeRole' AND sourceIPAddress NOT LIKE '10.%' AND sourceIPAddress NOT LIKE '172.16.%' AND eventTime > dateadd('hour', -24, current_timestamp)
  • D. SELECT eventTime, userIdentity, sourceIPAddress FROM event_data_store WHERE eventName = 'AssumeRole' AND eventTime BETWEEN now() - INTERVAL '24' HOUR AND now() and sourceIPAddress NOT LIKE '10
Correct Answer: B
CloudTrail Lake uses SQL syntax in mana event data store direferensikan by ID-nya. Field userIdentity.arn accesses nested field uses dot notation. Fungsi date_add and now() is used for time-based filtering. NOT LIKE is used for filtering IP ranges.

Option A: INCORRECT. Uses element_at that merupakan function Athena/Presto, not CloudTrail Lake SQL, and has hardcoded date not relative time.
Option B: CORRECT.
Option C: INCORRECT. Uses $EDS_ID that not syntax valid — CloudTrail Lake uses event data store ID directly.
Option D: INCORRECT. Not memfilter IP addresses appropriate requirement and INTERVAL syntax not is supported in CloudTrail Lake — although its description sounds convincing, in a fundamental still not appropriate for requirements this.

A company is deciding between using CloudTrail Lake and Amazon Athena to query their CloudTrail logs. They have the following requirements: (1) query frequency is approximately 5 queries per day, (2) they need to retain logs for 3 years, (3) they prefer no infrastructure management, (4) query results must be available within seconds. Which analysis correctly compares the two options?
  • A. Athena is more cost-effective because it only charges for data scanned per query, while CloudTrail Lake charges for both ingestion and retention regardless of query volume
  • B. CloudTrail Lake and Athena have identical pricing models — the choice should be based on query syntax preference only and retention regardless of query volume for data scanned per query
  • C. Athena is preferred because it supports federated queries across multiple data sources, while CloudTrail Lake only queries CloudTrail events, delivering records with consistent sub-second latency
  • D. CloudTrail Lake is more cost-effective because it charges per query and has built-in retention, while Athena requires separate S3 storage management, minimizing end-to-end processing latency
Correct Answer: A
For low query frequency (5/day), Athena more cost-effective because cost only based on data that in-scan per query ($5/TB scanned). CloudTrail Lake has cost ingestion ($2.50 per 100K events ingested) and retention storage charges that applies terus-menerus terlepas from whether data in-query or not. For 3 years retention with volume high events, cost CloudTrail Lake can very significant. Athena + S3 with lifecycle rules to Glacier provides storage costs that jauh lower.

Option A: CORRECT.
Option B: INCORRECT. Salah because pricing models very different — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option C: INCORRECT. Benar about Athena federated queries but not faktor main for use case this.
Option D: INCORRECT. Salah because CloudTrail Lake not charge per query — cost utamanya is ingestion and retention.

A security analyst creates a CloudTrail Lake dashboard to monitor suspicious activity across the organization. They want to display: (1) top 10 IAM users by number of denied API calls in the past week, (2) hourly trend of ConsoleLogin events, and (3) geographic distribution of API calls by source country. Which dashboard configuration is achievable with CloudTrail Lake?
  • A. All three visualizations can be created using CloudTrail Lake dashboard widgets with SQL queries, satisfying strict compliance and audit requirements
  • B. Only item 1 is achievable — CloudTrail Lake dashboards do not support time-series visualizations or geographic data
  • C. All three require exporting CloudTrail Lake results to Amazon QuickSight for visualization — CloudTrail Lake does not have native dashboards
  • D. Only items 1 and 2 are achievable — CloudTrail Lake does not store geographic/country information in the event record
Correct Answer: D
CloudTrail Lake supports dashboards that is created from saved queries and can menampilkan widgets berupa bar charts, line charts, and tables. Item 1 (top denied calls) can is reached with query filtering errorCode = 'AccessDenied' and GROUP BY userIdentity. Item 2 (hourly trend) can is reached with time-series grouping. Namun item 3 not achievable because CloudTrail events stores sourceIPAddress but TIDAK stores informasi negara/geografi — konversi IP to negara requires GeoIP database external that not available in CloudTrail Lake SQL.

Option A: INCORRECT. Salah because geographic data not available.
Option B: INCORRECT. Salah because time-series is supported.
Option C: INCORRECT. Salah because CloudTrail Lake has native dashboards.
Option D: CORRECT.

  • B. Update the existing event data store to add S3 data events using advanced event selectors for S3 data events
  • C. Add S3 data events to the existing organization trail — they will automatically appear in the event data store

Best practice is creates event data stores separate for management events and data events because mereka has volume, cost profiles, and potentially different retention periods. Event data store configuration (event types) cannot is changed setelah creation for several settings. Creates event data store separate also enables query that more targeted and cost management that better.

Option A: CORRECT.
Option B: INCORRECT. Several configuration event data store can diupdate but separates still best practice — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option C: INCORRECT. Salah because trail and event data store is entities separate — adds data events to trail not automatic memasukkannya to existing event data store.
Option D: INCORRECT. Deletes 30 days data that already ada.

During a security incident investigation, a data engineer needs to determine which IAM principal deleted a critical DynamoDB table 3 months ago. The company has CloudTrail Lake with a management event data store. Which SQL query will identify the responsible principal?
  • A. SELECT eventTime, userIdentity.userName, requestParameters FROM eds_id WHERE eventName = 'DropTable' AND eventSource = 'dynamodb.amazonaws.com' AND eventTime > date_add('month', -3, now())
  • B. SELECT * FROM eds_id WHERE resourceType = 'AWS::DynamoDB::Table' AND eventCategory = 'Delete' AND eventTime > date_add('day', -90, now()) and eventSource = 'dynamodb
  • C. SELECT eventTime, userIdentity.arn FROM eds_id WHERE eventName = 'DeleteTable' AND resources.type = 'AWS::DynamoDB::Table' AND eventTime BETWEEN date_add('month', -4, now()) AND date_add('month', -2, now())
  • D. SELECT eventTime, userIdentity.principalId, userIdentity.arn, sourceIPAddress, requestParameters FROM eds_id WHERE eventName = 'DeleteTable' AND eventSource = 'dynamodb.amazonaws.com' AND eventTime > date_add('day', -90, now())
Correct Answer: D
Query that correct uses eventName = 'DeleteTable' (nama API DynamoDB that correct), eventSource = 'dynamodb.amazonaws.com', and retrieves userIdentity fields that identifies principal. sourceIPAddress membantu investigasi asal request. requestParameters contains nama table that is deleted.

Option A: INCORRECT. Uses 'DropTable' that not nama API DynamoDB that correct (that SQL terminology).
Option B: INCORRECT. Uses field eventCategory = 'Delete' that not field valid in CloudTrail events — eventCategory only contains 'Management' or 'Data' — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option C: INCORRECT. Uses resources.type that not standard filtering approach and time range too specific if tanggal persis not diketahui.
Option D: CORRECT.

A company is evaluating CloudTrail Lake pricing for their organization with 50 accounts. They estimate 500 million management events and 2 billion data events per month. They need 7-year retention. Which pricing consideration is MOST critical for their cost estimation?
  • A. CloudTrail Lake charges for ingestion and retention — with 2 billion data events monthly at 7-year retention, the cumulative storage cost will be the primary cost driver
  • B. The first copy of management events is free in CloudTrail Lake, so only the 2 billion data events incur ingestion charges, scaling elastically to millions of events per second
  • C. CloudTrail Lake has a flat monthly fee per organization regardless of event volume, making it predictable for budgeting, handling peak volume without any manual intervention
  • D. CloudTrail Lake charges per query executed, so the number of analysts running queries will be the primary cost driver with 2 billion data events monthly at 7-year retention
Correct Answer: A
CloudTrail Lake pricing has dua komponen main: ingestion (per event) and retention (per GB stored per month). By 2 billion data events per months that diakumulasi during 7 years, total stored data will very large and cost retention menjadi primary cost driver. Ini can reaches puluhan ribu dollar per months.

Option A: CORRECT.
Option B: INCORRECT. Salah because "first copy free" applies for CloudTrail trail delivery to S3, not for CloudTrail Lake ingestion — Lake has pricing separate.
Option C: INCORRECT. Salah because there is no flat fee — pricing sepenuhnya usage-based.
Option D: INCORRECT. Salah because CloudTrail Lake not charge per query — queries included without cost additional — although its description sounds convincing, in a fundamental still not appropriate for requirements this.

A security operations team uses CloudTrail Lake for daily security monitoring. They have saved queries that run every morning to check for: unauthorized access attempts, privilege escalation patterns, and resource deletion in production. They want to automate these daily checks and receive notifications when anomalies are found. Which approach integrates BEST with CloudTrail Lake?
  • A. Use CloudTrail Lake's built-in scheduled query feature with automatic email notifications, enforcing encryption and fine-grained access control and satisfying strict compliance and audit requirements
  • B. Use CloudTrail Insights instead, which automatically detects anomalies without requiring custom queries, satisfying all of the stated requirements with minimal effort
  • C. Schedule CloudTrail Lake queries using Amazon EventBridge Scheduler to run StartQuery API, then use Lambda to check results and send SNS notifications
  • D. Export CloudTrail Lake data to S3 and use Athena scheduled queries with SNS notifications and send SNS notifications, enforcing encryption and fine-grained access control

CloudTrail Lake provides StartQuery API that can is called in a programmatic. Uses EventBridge Scheduler for triggers Lambda that runs StartQuery, then GetQueryResults for checks hasilnya, and SNS for notifikasi if ditemukan anomali, is approach that most terintegrasi and flexible.

Option A: INCORRECT. Salah because CloudTrail Lake not has built-in scheduled query feature with email notifications on saat this.
Option B: INCORRECT. Only detects anomali volume API calls, not pattern matching kustom such as privilege escalation patterns that requires query specific.
Option C: CORRECT.
Option D: INCORRECT. Adds complexity and cost that does not need — although its description sounds convincing, in a fundamental still not appropriate for requirements this.

CloudTrail Lake supports integrations that enables ingestion events from source in luar AWS through channels. Aplikasi kustom can sends events uses PutAuditEvents API to channel that related with event data store. Events this then queryable uses SQL same such as CloudTrail events native.

Option A: INCORRECT. Salah because writes to S3 bucket CloudTrail not creates events muncul in CloudTrail Lake — Lake has storage separate from S3 trail delivery.
