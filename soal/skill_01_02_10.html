A data engineer needs to extract structured fields (product name, price, category) from 1 million unstructured product descriptions stored in S3. The descriptions are in natural language and don't follow a consistent format. Which approach using LLMs is MOST cost-effective for this batch processing scenario?
  • A. Use Amazon Bedrock Batch Inference with a prompt template for structured extraction, processing all descriptions in a batch job at reduced cost
  • B. Call Bedrock InvokeModel API synchronously for each of the 1 million records via Lambda
  • C. Fine-tune a custom model on SageMaker for extraction
  • D. Use regex patterns to extract the structured fields
Jawaban Benar: A
Amazon Bedrock Batch Inference memproses large volumes of prompts secara batch dengan pricing discount (hingga 50% lebih murah dari real-time). Prompt template memastikan consistent extraction format. Batch job memproses 1M records tanpa managing individual API calls. Opsi B (synchronous Lambda) sangat mahal per-invocation dan slow, plus rate limiting. Opsi C (fine-tuning) membutuhkan labeled training data dan expertise. Opsi D (regex) tidak bisa handle unstructured natural language reliably.

A data pipeline processes customer support tickets and needs to classify each ticket into categories (billing, technical, account) and extract sentiment. The pipeline processes 10,000 tickets per hour. Which integration pattern with Amazon Bedrock minimizes latency while controlling costs?
  • A. Use Amazon Bedrock with a lightweight model (e.g., Claude Haiku) for classification and sentiment in a single prompt, calling InvokeModel with batched tickets via Glue ETL
  • B. Use the largest available model (Claude Opus) for each individual ticket
  • C. Build a custom BERT model on SageMaker for classification
  • D. Use Amazon Comprehend for both classification and sentiment without Bedrock
Jawaban Benar: D
Amazon Comprehend is purpose-built untuk text classification dan sentiment analysis — lebih cost-effective dan faster than LLMs untuk standard NLP tasks. Custom classification models bisa di-train di Comprehend. Sentiment analysis built-in. Untuk simple classification + sentiment, Comprehend memberikan better cost/performance ratio dibanding Bedrock LLMs. Opsi A (Bedrock Haiku) bekerja tapi lebih mahal per-request. Opsi B (Opus) sangat mahal untuk simple classification. Opsi C (custom BERT) membutuhkan ML expertise.

A data engineer needs to generate embeddings for 5 million product descriptions to enable semantic search in the data warehouse. The embeddings will be stored in Amazon Aurora PostgreSQL with pgvector extension. Which approach generates embeddings at scale efficiently?
  • A. Use Amazon Bedrock's Titan Embeddings model with Batch Inference API to generate embeddings for all 5 million descriptions, then bulk load into Aurora
  • B. Use a real-time Bedrock InvokeModel call per description from a Lambda function
  • C. Deploy a custom embedding model on SageMaker with batch transform
  • D. Use Amazon Comprehend to generate word embeddings
Jawaban Benar: A
Bedrock Titan Embeddings model melalui Batch Inference API memproses millions of texts secara efisien tanpa managing infrastructure. Batch mode memberikan throughput tinggi dan pricing discount. Output embeddings di-bulk load ke Aurora pgvector. Opsi B (real-time per description) — 5M API calls secara real-time sangat lambat dan mahal. Opsi C (SageMaker batch transform) valid tapi membutuhkan model deployment dan management. Opsi D — Comprehend tidak menghasilkan general-purpose embeddings untuk semantic search.

A data pipeline needs to summarize 100,000 medical research papers (each 10-20 pages) stored in S3. The summaries will be stored in a Redshift table for analyst consumption. Each paper exceeds the context window of the LLM. How should the data engineer handle this?
  • A. Implement a chunking strategy: split each paper into overlapping chunks that fit the context window, summarize each chunk, then use a final LLM call to create an overall summary from chunk summaries (map-reduce pattern)
  • B. Truncate each paper to fit within the context window
  • C. Use only the first page of each paper for summarization
  • D. Store papers without summarization since they're too long
Jawaban Benar: A
Map-reduce summarization pattern: (1) Split document into chunks that fit context window, (2) "Map" — summarize each chunk independently, (3) "Reduce" — combine chunk summaries into final summary with another LLM call. This preserves information from the entire document. Overlapping chunks prevent losing context at boundaries. Opsi B (truncate) kehilangan most of paper content. Opsi C (first page only) loses 90%+ of content. Opsi D (no summarization) defeats the purpose.

A data engineer wants to use Amazon Bedrock to enrich customer records with inferred attributes (industry, company size) based on company names and domains. The pipeline must handle rate limits from Bedrock API. Which pattern ensures reliable processing without data loss?
  • A. Use an SQS queue for records pending enrichment, Lambda consumers calling Bedrock with exponential backoff on throttling, and a dead-letter queue for persistent failures
  • B. Call Bedrock synchronously from a Glue job without rate limiting
  • C. Process all records in a single Lambda invocation
  • D. Skip records that receive throttling errors
Jawaban Benar: A
SQS decouples ingestion from processing, allowing controlled consumption rate. Lambda consumers implement exponential backoff when Bedrock returns ThrottlingException. If max retries exceeded, message goes to DLQ for later processing — no data loss. This pattern respects rate limits while ensuring eventual processing of all records. Opsi B (no rate limiting) akan hit ThrottlingException dan potentially lose data. Opsi C (single Lambda) — 15 min timeout insufficient for many records. Opsi D (skip) causes data loss.

A company needs to build a data pipeline that uses an LLM to standardize free-text address fields into structured components (street, city, state, zip). The output must be consistent JSON for database insertion. What is the BEST practice for ensuring structured output from the LLM?
  • A. Use a structured output prompt with explicit JSON schema instructions, include few-shot examples in the prompt, and validate the LLM output against the expected schema before database insertion
  • B. Trust the LLM output without validation since models are deterministic
  • C. Use the LLM output directly as database input without parsing
  • D. Fine-tune the model on a small set of address examples
Jawaban Benar: A
Best practices for structured LLM output: (1) Explicit JSON schema in system prompt, (2) Few-shot examples showing input→output format, (3) Post-processing validation to catch malformed responses. LLMs are NOT deterministic — same input can produce different formats. Validation catches edge cases and triggers retries. Opsi B — LLMs are probabilistic, not deterministic; outputs can vary. Opsi C — raw LLM text may contain extra text or formatting issues. Opsi D — fine-tuning expensive for simple formatting task.

A data engineer integrates Amazon Bedrock into a Glue ETL job to classify documents. The Glue job processes 50,000 documents. Each Bedrock API call takes 2-3 seconds. Running sequentially would take 28+ hours. How should the engineer parallelize the LLM calls within the Glue job?
  • A. Use Spark's mapPartitions with concurrent API calls within each partition using Python's concurrent.futures, respecting Bedrock's rate limits with a semaphore
  • B. Increase the number of Glue DPUs to 1000
  • C. Use Spark's map function which automatically parallelizes API calls
  • D. Process all documents in the driver node sequentially
Jawaban Benar: A
mapPartitions allows processing a batch of records per partition with explicit concurrency control. Within each partition, concurrent.futures.ThreadPoolExecutor makes parallel API calls. Semaphore controls max concurrent calls to respect Bedrock rate limits. With 50 executors × 10 concurrent calls = 500 parallel calls, completing in ~5 minutes. Opsi B (1000 DPUs) wastes compute resources if bottleneck is API latency not CPU. Opsi C (map) — each map call is sequential within each task. Opsi D (driver sequential) defeats distributed processing.

A company uses Amazon Bedrock to process customer feedback and wants to ensure that sensitive PII data (credit card numbers, SSNs) is not sent to the LLM. Which approach provides PII protection in the data pipeline?
  • A. Enable Amazon Bedrock Guardrails with PII detection filters that automatically redact sensitive information before it reaches the model
  • B. Trust that Bedrock doesn't store or learn from customer data
  • C. Use regex to remove all numbers from the text before sending
  • D. Encrypt the text before sending to the LLM
Jawaban Benar: A
Amazon Bedrock Guardrails menyediakan PII filtering built-in yang mendeteksi dan secara otomatis meredact PII (SSN, credit cards, emails, dll) sebelum input reaches the model. Ini managed solution tanpa custom code. Opsi B — meskipun Bedrock doesn't train on data, sending PII still violates compliance requirements. Opsi C (remove all numbers) terlalu agresif — removes legitimate numbers (quantities, dates). Opsi D (encryption) — encrypted text tidak bisa diproses oleh LLM.

A data engineer wants to use an LLM to generate SQL queries from natural language questions for a data warehouse. The LLM needs context about the database schema (tables, columns, relationships). Which technique provides this context to the model?
  • A. Include the relevant table schemas and sample data in the system prompt (in-context learning), using the Glue Data Catalog metadata to dynamically construct the prompt
  • B. Fine-tune the LLM on the company's entire database
  • C. Give the LLM direct access to query the database
  • D. Train a custom model from scratch on SQL queries
Jawaban Benar: A
In-context learning (providing schema in the prompt) is the most practical approach. Glue Data Catalog contains table metadata (columns, types, descriptions) yang bisa di-dynamically retrieved dan included in the system prompt. LLM uses this context to generate accurate SQL. RAG pattern bisa memilih relevant tables. Opsi B (fine-tune on database) — database content changes frequently, fine-tuning is static. Opsi C (direct access) — security risk dan LLMs can't reliably query databases. Opsi D (custom model) expensive and unnecessary.

A data pipeline uses Amazon Bedrock to enrich records. The LLM occasionally returns hallucinated (incorrect) data that doesn't match reality. For a data pipeline where accuracy is critical, what is the BEST strategy to mitigate hallucinations?
  • A. Implement a validation layer: cross-reference LLM outputs against known-good data sources, use confidence thresholds, and flag uncertain outputs for human review rather than auto-inserting
  • B. Use a more expensive model which never hallucinates
  • C. Set temperature to 0 which eliminates all hallucinations
  • D. Run the same prompt twice and only accept if both outputs match
Jawaban Benar: A
Multi-layered validation is essential for production data pipelines using LLMs: (1) Cross-reference outputs against authoritative sources, (2) Confidence scoring (LLM can output confidence), (3) Human-in-the-loop for uncertain cases. No model eliminates hallucinations entirely. Opsi B — no model is hallucination-free. Opsi C (temperature 0) reduces randomness but doesn't eliminate hallucinations — model can still generate incorrect information confidently. Opsi D (run twice) — same hallucination often occurs consistently.
