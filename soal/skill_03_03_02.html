A data engineering team runs multiple AWS Glue ETL jobs that process customer data nightly. The compliance team requires that all job execution logs be retained for 2 years and be searchable for audit investigations. The team wants to minimize operational overhead for log management. Which solution meets these requirements?
  • A. Configure Glue jobs to write logs to CloudWatch Logs with continuous logging enabled. Set the log group retention to 730 days. Use CloudWatch Logs Insights for audit queries.
  • B. Configure Glue jobs to write custom logs to an S3 bucket. Create an Athena table for querying.
  • C. Configure Glue jobs to write logs to CloudWatch Logs. Create a subscription filter to stream logs to Amazon OpenSearch Service for analysis.
  • D. Configure Glue jobs to write logs to CloudWatch Logs with a 7-day retention. Export logs nightly to S3 using CreateExportTask.
Jawaban Benar: A
AWS Glue continuous logging delivers real-time logs to CloudWatch Logs with minimal latency. Setting retention to 730 days (2 years) ensures compliance without manual management. CloudWatch Logs Insights provides serverless SQL-like querying for audit investigations. Option B: Custom S3 logging requires additional code and doesn't capture Glue's native driver/executor logs. Option C: OpenSearch adds significant cost and operational overhead for infrequent audit queries. Option D: Nightly exports create operational complexity and potential data loss if exports fail.
2
A company operates data pipelines across three AWS accounts (development, staging, production). The security team requires centralized logging where all CloudWatch Logs from data pipeline services are aggregated into a single account for audit purposes. Which approach provides centralized log aggregation with the LEAST operational effort?
  • A. Create CloudWatch Logs subscription filters in each account to stream logs to a Kinesis Data Stream in the central account, then deliver to S3.
  • B. Use CloudWatch cross-account observability by designating the security account as the monitoring account and source accounts as linked accounts.
  • C. Install CloudWatch agents in each account configured to send logs directly to the central account's log groups using cross-account IAM roles.
  • D. Create nightly scheduled Lambda functions in each account to export CloudWatch Logs to a central S3 bucket using CreateExportTask API.
Jawaban Benar: B
CloudWatch cross-account observability is the AWS-native solution for centralized multi-account monitoring with minimal operational effort. It allows a monitoring account to view and query logs, metrics, and traces from linked source accounts without data movement. Option A: Subscription filters + Kinesis works but requires managing streams, delivery failures, and IAM policies across accounts. Option C: CloudWatch agent cannot directly write to cross-account log groups without complex networking setup. Option D: Nightly exports are not real-time and require managing Lambda functions in every account.

A data engineer needs to implement structured logging for an AWS Lambda function that processes data pipeline events. The logs must include a correlation ID that traces a single data record through multiple Lambda invocations and downstream services. Which implementation approach enables end-to-end traceability?
  • A. Use AWS X-Ray with active tracing enabled on Lambda. Embed the trace ID in log messages using structured JSON logging with the trace_id field.
  • B. Generate a UUID in the first Lambda invocation and pass it through SQS message attributes to downstream services for logging.
  • C. Use the Lambda request ID as the correlation ID and include it in all log messages.
  • D. Configure CloudWatch Logs to automatically correlate logs from multiple Lambda functions using log group prefixes.
Jawaban Benar: A
AWS X-Ray with active tracing provides a distributed trace ID that spans multiple services. Embedding this trace ID in structured JSON logs creates end-to-end traceability that correlates log entries across Lambda invocations and downstream services. CloudWatch Logs Insights can then query by trace_id to reconstruct the full processing path. Option B: Manual UUID passing works but requires custom implementation in every service and doesn't integrate with AWS tracing tools. Option C: Lambda request ID is unique per invocation and cannot trace across multiple invocations. Option D: CloudWatch Logs has no automatic correlation capability based on log group prefixes.
4
A company's data pipeline logs contain sensitive information including database connection strings and API keys that were accidentally logged. The security team requires that all sensitive patterns be filtered from CloudWatch Logs before they can be viewed by operations staff. Which solution prevents sensitive data exposure in logs?
  • A. Create a CloudWatch Logs data protection policy that detects and masks sensitive data patterns (credentials, API keys) in the log group.
  • B. Create a subscription filter that sends logs to a Lambda function for redaction before storing in a separate clean log group.
  • C. Configure IAM policies to restrict access to specific log streams that contain sensitive data.
  • D. Enable CloudWatch Logs encryption with KMS and restrict key access to authorized personnel only.
Jawaban Benar: A
CloudWatch Logs data protection policies automatically detect and mask sensitive data (like credentials, credit card numbers, API keys) using managed data identifiers. Masked data appears as asterisks to unauthorized viewers while maintaining audit trails for authorized users. Option B: Lambda-based redaction is complex, adds latency, and requires maintaining custom regex patterns. Option C: IAM restrictions don't mask the sensitive data; anyone with access still sees it. Option D: Encryption protects data at rest but doesn't mask sensitive content from authorized viewers of the logs.

A data engineering team needs to create a metric filter on CloudWatch Logs to automatically detect when their Glue ETL jobs encounter OutOfMemoryError exceptions. When detected, the filter should increment a custom CloudWatch metric for alerting. Which metric filter pattern correctly matches Java OutOfMemoryError in Glue job logs?
  • A. { $.errorType = "OutOfMemoryError" }
  • B. "java.lang.OutOfMemoryError"
  • C. [timestamp, requestId, level = "ERROR", message = "*OutOfMemory*"]
  • D. { $.message = "OutOfMemoryError" AND $.level = "ERROR" }
Jawaban Benar: B
For CloudWatch Logs metric filters, a simple quoted string pattern performs a text match anywhere in the log event. "java.lang.OutOfMemoryError" will match any log line containing that exact text, which is how Glue (Spark/Java) reports OOM errors. Option A: JSON filter syntax { $.errorType } only works with structured JSON logs; Glue continuous logging outputs mixed formats. Option C: Space-delimited filter syntax doesn't support wildcards within field values in this format. Option D: JSON filter syntax with AND requires the logs to be in structured JSON format with specific field names, which Glue's native logs don't follow.

A data platform team needs to monitor their EMR cluster's application logs for traceability. They want to ensure that YARN application logs, step logs, and bootstrap action logs are preserved after the cluster terminates for post-mortem analysis. Which configuration ensures log persistence?
  • A. Configure the EMR cluster with a log URI pointing to an S3 bucket. Enable log encryption with a KMS key.
  • B. Install the CloudWatch agent on EMR master and core nodes to stream /var/log/ to CloudWatch Logs.
  • C. Configure YARN log aggregation to write to HDFS, which persists after cluster termination.
  • D. Use EMR Managed Scaling to prevent cluster termination until logs are manually exported.
Jawaban Benar: A
Configuring an EMR cluster with a log URI (S3 path) ensures that all cluster logs (YARN application logs, step logs, bootstrap action logs) are automatically pushed to S3 every 5 minutes and upon cluster termination. KMS encryption ensures log security. Option B: CloudWatch agent installation adds complexity and may not capture all EMR-specific log types (bootstrap actions). Option C: HDFS storage is ephemeral and lost when the cluster terminates. Option D: EMR Managed Scaling is for capacity management, not log preservation.

A data engineer uses CloudWatch Logs Insights to investigate a data pipeline failure that occurred 3 hours ago. They need to find all error-level log entries from a specific Glue job within that timeframe, including the error message and the affected data partition. Which CloudWatch Logs Insights query structure is MOST appropriate?
  • A. fields @timestamp, @message | filter @message like /ERROR/ | filter @logStream like /job-name/ | sort @timestamp desc | limit 100
  • B. SELECT timestamp, message FROM logs WHERE level = 'ERROR' AND job_name = 'my-job' ORDER BY timestamp DESC LIMIT 100
  • C. stats count(*) by @message | filter @message like /ERROR/
  • D. fields @timestamp, @message | parse @message "* ERROR *" as timestamp, errorDetail | display @timestamp, errorDetail
Jawaban Benar: A
This CloudWatch Logs Insights query correctly uses the supported syntax: fields to select displayed columns, filter with like and regex to narrow results by ERROR level and specific job log stream, sort by timestamp descending, and limit for manageable output. Option B: SQL syntax is not supported in CloudWatch Logs Insights (it uses its own query language). Option C: stats provides aggregated counts, not individual log entries needed for investigation. Option D: The parse command syntax is incorrect and the display command doesn't exist in Logs Insights.
8
A company needs to encrypt all CloudWatch Logs generated by their data pipeline services using a customer-managed KMS key. The logs are generated by AWS Glue jobs, Lambda functions, and Step Functions. Which approach correctly implements KMS encryption for CloudWatch Logs?
  • A. Associate a KMS key with each CloudWatch Logs log group using the associate-kms-key API. Update the KMS key policy to grant the CloudWatch Logs service principal encrypt/decrypt permissions.
  • B. Configure the Glue jobs, Lambda functions, and Step Functions to encrypt log output before sending to CloudWatch Logs.
  • C. Enable default encryption on the AWS account level for all CloudWatch Logs using AWS Config.
  • D. Create an S3 bucket with KMS encryption and redirect all CloudWatch Logs to S3 using subscription filters.
Jawaban Benar: A
CloudWatch Logs encryption is configured at the log group level using associate-kms-key. The KMS key policy must grant the logs.{region}.amazonaws.com service principal permissions to generate data keys and decrypt. This encrypts all log data at rest in that log group. Option B: Services send logs to CloudWatch Logs in plaintext; encryption is handled by the CloudWatch Logs service, not the producing services. Option C: There is no account-level default encryption setting for CloudWatch Logs via AWS Config. Option D: Redirecting to S3 changes the storage location entirely and doesn't encrypt CloudWatch Logs in place.

A data pipeline uses multiple AWS Step Functions state machines that invoke Lambda functions and Glue jobs. The operations team needs a unified view to trace the execution flow of a single data record through the entire pipeline for debugging purposes. Which combination of services provides the BEST end-to-end traceability?
  • A. Enable AWS X-Ray tracing on Step Functions and Lambda. Use X-Ray service map to visualize the execution flow and identify latency bottlenecks.
  • B. Enable Step Functions execution history logging to CloudWatch Logs. Cross-reference with Lambda and Glue CloudWatch log groups manually.
  • C. Use CloudWatch ServiceLens to automatically correlate Step Functions, Lambda, and Glue execution traces.
  • D. Create a custom DynamoDB table to record each processing step with timestamps and record IDs for manual tracing.
Jawaban Benar: A
AWS X-Ray integrates with Step Functions and Lambda to provide distributed tracing. When X-Ray tracing is enabled, trace IDs propagate through the entire execution, and the service map visualizes the complete flow including latency at each step. This provides true end-to-end traceability. Option B: Manual cross-referencing of separate log groups is time-consuming and error-prone without correlation IDs. Option C: CloudWatch ServiceLens works with X-Ray traces but doesn't automatically correlate without X-Ray being enabled first. Option D: Custom DynamoDB tracking adds code complexity and still requires custom tooling to visualize.

A data engineering team uses the CloudWatch agent on EC2-based pipeline components. They need to collect both system-level metrics (CPU, memory, disk) and application logs in a structured JSON format. The agent configuration must support log rotation and multi-line log events from Java stack traces. Which CloudWatch agent configuration element addresses multi-line log collection?
  • A. Set the multi_line_start_pattern parameter in the agent configuration to a regex matching the start of each log entry (e.g., timestamp pattern).
  • B. Set the max_event_size parameter to accommodate the maximum expected stack trace length.
  • C. Configure the log_group_name with a separate group for multi-line events to avoid mixing with single-line logs.
  • D. Set the encoding parameter to "utf-8-multi" to enable multi-line event detection.
Jawaban Benar: A
The multi_line_start_pattern parameter in the CloudWatch agent configuration defines a regex pattern that identifies the beginning of a new log event. Lines not matching this pattern are appended to the previous event. For Java logs, a common pattern is the timestamp (e.g., "^\\d{4}-\\d{2}-\\d{2}") which ensures stack traces are grouped with their originating error line. Option B: max_event_size limits event size but doesn't handle multi-line detection. Option C: Separate log groups don't solve the multi-line parsing problem. Option D: "utf-8-multi" is not a valid encoding option for the CloudWatch agent.
