A retail company needs to integrate data from three sources: (1) transaction data in Amazon RDS MySQL, (2) product catalog in DynamoDB, and (3) customer clickstream in S3 (JSON format). The integrated dataset must be available for analytics in Amazon Redshift. Which approach provides the MOST efficient integration?
  • A. Use three separate Lambda functions, each writing to a staging S3 bucket, then load to Redshift, validating and cleansing each record before delivery
  • B. Use Amazon AppFlow to extract all three sources into S3, applying schema conversion and enrichment inline and validating and cleansing each record before delivery
  • C. Load all raw data into Redshift first, then join using SQL and write the unified result to Redshift, applying schema conversion and enrichment inline
  • D. Use AWS Glue ETL job to read all three sources, perform joins using DynamicFrames/Spark DataFrames, and write the unified result to Redshift
Jawaban Benar: D
AWS Glue ETL job bisa membaca dari multiple heterogeneous sources (JDBC untuk RDS, DynamoDB connector, S3 untuk files) dalam satu job. DynamicFrames/DataFrames memungkinkan joins dan transformasi sebelum menulis hasil akhir ke Redshift. Ini paling efisien karena satu job menangani semua.

Opsi A: SALAH. Sulit untuk large datasets dan complex joins.
Opsi B: SALAH. AppFlow tidak mendukung DynamoDB dan RDS sebagai sources.
Opsi C: SALAH. Membuang Redshift resources untuk raw data staging — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi D: BENAR.

A data engineer needs to combine streaming data from Amazon Kinesis (real-time orders) with static reference data in Amazon S3 (product master data) for enrichment. The enriched data must be written to a data lake. Which service handles this stream-to-batch integration BEST?
  • A. Amazon Kinesis Data Analytics (Flink) with a batch source table for S3 data, handling the described workload reliably at scale
  • B. AWS Glue Streaming ETL job that reads from Kinesis and performs a lookup join with S3 reference data
  • C. Amazon Data Firehose with a Lambda transformation that reads S3, streaming results downstream in near real time
  • D. Lambda function consuming Kinesis that reads S3 for each record with S3 reference data and performs a lookup join
Jawaban Benar: B
Glue Streaming ETL mendukung stream-to-batch joins. Streaming source (Kinesis) di-join dengan static/slowly changing data dari S3 menggunakan broadcast join atau lookup. Glue menangani micro-batching dan writes ke data lake secara otomatis.

Opsi A: SALAH. Valid tapi lebih complex untuk setup.
Opsi B: BENAR.
Opsi C: SALAH. Memiliki payload limits dan timeout constraints.
Opsi D: SALAH. Sangat inefficient — S3 read per record adalah N+1 problem — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.

A healthcare company wants to integrate patient records from five different hospital databases (MySQL, PostgreSQL, Oracle, SQL Server, and MongoDB) into a centralized data lake. Each database has different schemas for patient data. Which approach creates the MOST maintainable integration?
  • A. Use AWS Glue with crawlers to discover schemas from each source, create a standardized canonical schema in the Data Catalog, and use Glue ETL jobs with schema mapping to transform all sources to the canonical format
  • B. Use Amazon AppFlow to connect to all five databases with crawlers, integrating natively with the rest of the pipeline and satisfying all of the stated requirements with minimal effort and applying schema conversion and enrichment inline
  • C. Use AWS DMS to replicate all databases to a single RDS instance, then export to S3, satisfying all of the stated requirements with minimal effort and meeting the latency and throughput goals of the design
  • D. Write custom Python scripts for each database connection, handling the described workload reliably at scale and applying schema conversion and enrichment inline and integrating natively with the rest of the pipeline and delivering records with consistent sub-second latency
Jawaban Benar: A
Glue crawlers mendeteksi schema berbagai database. Data Catalog menjadi metadata registry pusat. Glue ETL jobs dengan schema mapping (ApplyMapping transform) menstandarkan heterogeneous schemas ke format canonical yang konsisten. Ini paling maintainable karena schema changes terdeteksi otomatis.

Opsi A: BENAR.
Opsi B: SALAH. AppFlow tidak support RDBMS/MongoDB directly — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi C: SALAH. Memindahkan masalah schema heterogeneity.
Opsi D: SALAH. Sulit di-maintain untuk 5 sources.

A data engineer needs to integrate data from a Salesforce CRM, a REST API (weather data), and an on-premises data warehouse (via JDBC). The integrated dataset updates daily. Which combination of AWS services provides a unified integration solution?
  • A. Use AWS DMS for all three sources with native S3 integration and optimized data transfer, meeting the latency and throughput goals of the design and satisfying all of the stated requirements with minimal effort
  • B. Use a single Glue job to read from all three sources simultaneously, handling the described workload reliably at scale and satisfying all of the stated requirements with minimal effort and providing exactly-once processing semantics
  • C. Amazon AppFlow for Salesforce → S3, Lambda for REST API → S3, AWS Glue JDBC connection for the data warehouse → S3, then a consolidation Glue job to integrate all three S3 datasets
  • D. Use Amazon Kinesis to stream data from all three sources, meeting the latency and throughput goals of the design and satisfying all of the stated requirements with minimal effort and minimizing end-to-end processing latency
Jawaban Benar: C
Setiap source membutuhkan connector yang berbeda: AppFlow memiliki native Salesforce connector, Lambda bisa consume REST APIs, dan Glue JDBC menghubungkan ke data warehouse on-premises. Landing data ke S3 sebagai common layer, kemudian satu consolidation job mengintegrasikan semuanya.

Opsi A: SALAH. DMS tidak support Salesforce dan REST APIs — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi B: SALAH. Glue tidak bisa native connect ke Salesforce atau REST APIs dalam satu job.
Opsi C: BENAR.
Opsi D: SALAH. Kinesis untuk streaming bukan batch integration.

A company has data in multiple AWS accounts (5 accounts, each with their own S3 data lake). A central analytics team needs to query across all accounts without copying data. Which approach enables cross-account data integration for querying?
  • A. Create IAM users in each account for the analytics team, satisfying all of the stated requirements with minimal effort and reducing day-to-day operational effort
  • B. Set up S3 replication from all accounts to the central account, integrating natively with the rest of the pipeline and providing exactly-once processing semantics
  • C. Use AWS Organizations consolidated billing to access all data with a unified Glue Data Catalog, handling the described workload reliably at scale

Opsi A: SALAH. Tidak scalable dan security concern.
Opsi B: SALAH. Mahal karena menduplikasi semua data.
Opsi C: SALAH. Hanya untuk billing, tidak memberikan data access — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.

A data engineer needs to join a large fact table (2 billion rows in S3) with a small dimension table (10,000 rows in DynamoDB) in an AWS Glue ETL job. The join key is product_id. Which join strategy is MOST efficient?
  • A. Read the dimension table from DynamoDB into a DynamicFrame, broadcast it to all workers, and perform a broadcast join with the fact table
  • B. Perform a shuffle/sort-merge join between both datasets, validating and cleansing each record before delivery and integrating natively with the rest of the pipeline
  • C. Load both tables into Redshift and join using SQL with the fact table and perform a broadcast join with the fact table
  • D. For each record in the fact table, query DynamoDB using GetItem, transforming records into the required target format and applying schema conversion and enrichment inline
Jawaban Benar: A
Broadcast join sangat efisien ketika satu tabel kecil (fits in memory per worker). Dimension table 10,000 rows di-broadcast ke semua executors, sehingga join dilakukan locally tanpa expensive data shuffling. Ini menghindari shuffle dari 2 billion row fact table.

Opsi A: BENAR.
Opsi B: SALAH. Membutuhkan shuffle besar untuk fact table yang sangat mahal.
Opsi C: SALAH. Menambah service dan biaya loading 2B rows — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi D: SALAH. Adalah N+1 problem — 2 billion DynamoDB calls.

A media company needs to integrate data that arrives at different times: hourly website logs (S3), daily CRM exports (S3), and weekly survey results (uploaded manually to S3). The integrated view should always reflect the latest available data from each source. Which pattern ensures correct integration despite different arrival times?
  • A. Wait until all sources are available (weekly) before running any integration, satisfying all of the stated requirements with minimal effort and meeting the latency and throughput goals of the design
  • B. Trigger integration every time any file arrives in S3 with partition-level ordering and dedicated throughput, satisfying all of the stated requirements with minimal effort and keeping steady-state operating costs low
  • C. Use AWS Step Functions to poll all sources until they're all updated, integrating natively with the rest of the pipeline and meeting the latency and throughput goals of the design
  • D. Implement a medallion architecture where each source lands in bronze independently, and a scheduled integration job creates silver layer by joining the latest available partition from each source
Jawaban Benar: D
Medallion architecture memisahkan ingestion (bronze) dari integration (silver). Setiap source di-ingest pada jadwalnya masing-masing. Integration job membaca "latest available" partition dari setiap source, sehingga view selalu ter-update meskipun data arrives asynchronously.

Opsi A: SALAH. Menunda insights.
Opsi B: SALAH. Menyebabkan excessive runs saat hourly logs tiba — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi C: SALAH. Memblokir processing dan wastes compute waiting.
Opsi D: BENAR.

A data engineer integrates customer data from two systems using customer_email as the join key. However, one system stores emails in uppercase and the other in lowercase, causing join failures. Which transformation technique resolves this in an AWS Glue ETL job?
  • A. Use a fuzzy matching algorithm for the join condition, validating and cleansing each record before delivery
  • B. Apply a lowercase transformation to the email column in both DynamicFrames before performing the join
  • C. Configure Glue to perform case-insensitive joins automatically, satisfying all of the stated requirements with minimal effort
  • D. Create a lookup table mapping uppercase to lowercase emails configured for optimal performance and minimal operational overhead
Jawaban Benar: B
Standardisasi data sebelum join adalah best practice. Menggunakan lower() function pada kolom email di kedua sources sebelum join memastikan matching yang akurat. Ini simpel, efisien, dan deterministic.

Opsi A: SALAH. Overkill untuk masalah casing sederhana dan memakan resources.
Opsi B: BENAR.
Opsi C: SALAH. Glue/Spark joins case-sensitive secara default tanpa auto case-insensitive mode.
Opsi D: SALAH. Menambah complexity yang tidak diperlukan — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.

A financial company needs to integrate real-time market data (from an API), historical trade data (in Redshift), and risk parameters (in a configuration file on S3). An analyst needs to query the integrated view using SQL. Which architecture enables real-time integrated querying?
  • A. Store all data in DynamoDB and query with PartiQL for other Redshift tables, making the data queryable within seconds of arrival and meeting the latency and throughput goals of the design and minimizing end-to-end processing latency
  • B. Copy all data to a single PostgreSQL RDS instance, streaming results downstream in near real time and meeting the latency and throughput goals of the design and making the data queryable within seconds of arrival
  • C. Land API data in Kinesis → materialize in Redshift via Streaming Ingestion, use Redshift Federated Query for other Redshift tables, and external tables for S3 config — all queryable via single Redshift SQL interface
  • D. Use Athena to query all three sources independently, making the data queryable within seconds of arrival and delivering records with consistent sub-second latency and streaming results downstream in near real time and minimizing end-to-end processing latency
Jawaban Benar: C
Redshift menyediakan unified SQL interface: Streaming Ingestion untuk real-time data dari Kinesis, internal tables untuk historical data, dan Redshift Spectrum external tables untuk S3 files. Semua bisa di-join dalam single SQL query.

Opsi A: SALAH. Bukan untuk complex analytical queries — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi B: SALAH. Tidak scalable dan tidak support real-time streaming ingestion.
Opsi C: BENAR.
Opsi D: SALAH. Tidak bisa query Redshift internal tables tanpa federated connector tambahan.

A data engineer is building an integration pipeline that merges incremental changes from a source system with the existing data lake. The source sends daily delta files (new records, updates, and deletes). The data lake uses Apache Parquet format on S3. Which approach handles all three operation types (insert, update, delete) on the data lake?
  • A. Overwrite the entire dataset with the latest full snapshot each day and deletes to the existing data in a single atomic operation
  • B. Use Apache Iceberg table format with MERGE INTO statement to apply inserts, updates, and deletes to the existing data in a single atomic operation
  • C. Append all delta files and use a view that deduplicates at query time, handling the described workload reliably at scale and minimizing end-to-end processing latency
  • D. Use AWS Glue job bookmarks to track which deltas have been applied, meeting the latency and throughput goals of the design and minimizing end-to-end processing latency
Jawaban Benar: B
Apache Iceberg (dan Delta Lake, Hudi) mendukung MERGE INTO (upsert) yang menangani insert, update, dan delete dalam satu operasi atomic. Iceberg melakukan row-level operations pada Parquet files tanpa rewriting entire partitions. Ini paling efisien untuk CDC (Change Data Capture) integration.

Opsi A: SALAH. Membuang resources untuk seluruh dataset — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi B: BENAR.
Opsi C: SALAH. Menambah query complexity dan storage costs.
Opsi D: SALAH. Tracking saja, tidak menangani merging logic.
