A data engineering team runs Apache Spark jobs on Amazon EKS for daily ETL processing. The jobs experience unpredictable memory usage spikes that cause OOMKilled errors. The team wants to handle these spikes without over-provisioning memory for all pods. Which EKS configuration BEST addresses this?
  • A. Use Horizontal Pod Autoscaler (HPA) to add more pods when memory is high
  • B. Enable Kubernetes memory overcommit by setting requests to 0
  • C. Set memory requests equal to limits for all Spark executor pods and limits based on historical usage patterns
  • D. Configure Vertical Pod Autoscaler (VPA) in "Auto" mode to adjust pod memory requests and limits based on historical usage patterns
Jawaban Benar: D
VPA menganalisis historical resource usage dan secara otomatis menyesuaikan memory requests/limits untuk pods. Dalam "Auto" mode, VPA akan evict pods dan restart mereka dengan right-sized resources. Ini ideal untuk workloads dengan variable memory patterns.

Opsi A: SALAH. Menambah pods tapi setiap pod tetap bisa OOM.
Opsi B: SALAH. Tidak aman dan bisa menyebabkan node-level OOM.
Opsi C: SALAH. Mencegah bursting tapi memaksa over-provisioning — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi D: BENAR.
2
A company runs data transformation tasks on Amazon ECS with Fargate. Each task processes a batch of files and the processing time varies from 5 minutes to 2 hours depending on file size. The company wants to minimize cost while maintaining performance. Which Fargate configuration strategy is MOST cost-effective?
  • A. Run all tasks on EC2 launch type with Reserved Instances for fault-tolerant batch tasks with retry logic
  • B. Use the maximum vCPU and memory configuration for all tasks to ensure they complete quickly
  • C. Configure a single large task definition to process all files sequentially
  • D. Use Fargate Spot for fault-tolerant batch tasks with retry logic, reserving Fargate On-Demand for time-critical tasks only
Jawaban Benar: D
Fargate Spot menawarkan diskon hingga 70% dibanding On-Demand untuk workloads yang toleran terhadap interruption. Batch ETL tasks yang memiliki retry logic bisa memanfaatkan ini. Tasks yang time-critical tetap gunakan On-Demand.

Opsi A: SALAH. Menambah operational overhead dan tidak cocok untuk variable workloads — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi B: SALAH. Membuang resources dan biaya.
Opsi C: SALAH. Sangat lambat dan tidak memanfaatkan parallelism.
Opsi D: BENAR.
3
A data engineering team uses Amazon EKS to run Apache Flink stream processing. The Flink cluster has 10 TaskManager pods that need to communicate with each other for data shuffling. The team notices high network latency between pods. Which optimization reduces inter-pod network latency?
  • A. Use pod anti-affinity rules to spread pods across different Availability Zones for high availability
  • B. Configure pod affinity rules to co-locate TaskManager pods on the same node or within the same placement group
  • C. Enable service mesh (Istio) for all pod-to-pod communication
  • D. Increase the EKS cluster's VPC CIDR block for more IP addresses configured for optimal performance and minimal operational overhead
Jawaban Benar: B
Pod affinity rules memastikan pods di-schedule pada node yang sama atau dekat secara fisik (same AZ, placement group). Ini mengurangi network latency untuk inter-pod communication yang heavy (seperti Flink data shuffling).

Opsi A: SALAH. Justru menyebarkan pods lebih jauh, meningkatkan latency.
Opsi B: BENAR.
Opsi C: SALAH. Menambah overhead networking layer yang meningkatkan latency.
Opsi D: SALAH. Tidak mempengaruhi latency — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
4
A company uses Amazon ECS with EC2 launch type for data processing. They need to run GPU-accelerated ML inference as part of their data pipeline. The GPU tasks run intermittently (2-3 hours per day). Which configuration minimizes cost while providing GPU when needed?
  • A. Create a separate ECS capacity provider with GPU instances using Auto Scaling that scales to 0 when no GPU tasks are pending
  • B. Use Fargate with GPU task definitions with parallel processing and horizontal scaling capabilities
  • C. Keep GPU instances running 24/7 in the ECS cluster
  • D. Run GPU workloads on a separate EKS cluster with always-on GPU nodes
Jawaban Benar: A
ECS capacity providers dengan managed scaling memungkinkan cluster auto-scale GPU instances berdasarkan pending tasks. Dengan scale-to-zero, GPU instances hanya berjalan saat ada tasks yang membutuhkan GPU (2-3 jam/hari), menghemat biaya signifikan.

Opsi A: BENAR.
Opsi B: SALAH. Fargate tidak mendukung GPU instances — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi C: SALAH. Membuang biaya 21-22 jam per hari.
Opsi D: SALAH. Juga membuang biaya jika nodes selalu on.
5
A data pipeline on Amazon EKS processes large CSV files (10 GB each) that need to be read from Amazon S3, transformed, and written back to S3. The pods frequently experience disk pressure because the default ephemeral storage is insufficient. What is the MOST appropriate solution?
  • A. Stream data directly from S3 without writing to local disk
  • B. Mount Amazon EFS as shared storage for all pods configured for optimal performance and minimal operational overhead
  • C. Increase the node instance type to get more ephemeral storage
  • D. Attach Amazon EBS volumes as PersistentVolumes to the data processing pods for temporary storage during processing
Jawaban Benar: D
EBS volumes sebagai PersistentVolumes memberikan storage yang bisa dikonfigurasi sesuai kebutuhan (size, IOPS). Untuk file 10GB yang perlu processing lokal, EBS memberikan performa I/O yang baik.

Opsi A: SALAH. Tidak selalu feasible untuk transformasi yang membutuhkan random access ke seluruh file.
Opsi B: SALAH. Memiliki latency lebih tinggi dari EBS dan mahal untuk temporary processing storage — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi C: SALAH. Over-provisioning compute untuk masalah storage.
Opsi D: BENAR.
6
A data engineer is containerizing a Python-based ETL application that processes data using pandas. The application requires 8 GB of memory and 4 vCPUs during peak processing. The engineer needs to choose between ECS Fargate and ECS with EC2. The workload runs continuously 24/7. Which option is MORE cost-effective for this scenario?
  • A. ECS with EC2 launch type using Compute Savings Plans or Reserved Instances for the continuous workload
  • B. ECS with EC2 On-Demand instances for the continuous workload
  • C. ECS Fargate Spot for cost savings
  • D. ECS Fargate with Compute Savings Plans
Jawaban Benar: A
Untuk workloads 24/7 yang continuous, EC2 dengan Savings Plans atau Reserved Instances memberikan diskon signifikan (hingga 72%) dibanding On-Demand. Dengan known fixed resource requirements, EC2 lebih murah dari Fargate pada sustained usage.

Opsi A: BENAR.
Opsi B: SALAH. Tanpa discount paling mahal — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi C: SALAH. Bisa terinterrupsi — tidak cocok untuk continuous processing.
Opsi D: SALAH. Masih lebih mahal dari EC2 RI untuk 24/7.
7
A data engineering team deploys multiple Spark applications on Amazon EKS. They use the Spark Operator for job management. During peak hours, jobs queue because there aren't enough cluster resources. Which EKS scaling strategy provides the FASTEST response to resource demands?
  • A. Pre-provision a fixed number of large nodes with diverse instance type selection
  • B. Configure Karpenter as the node provisioner for rapid node scaling with diverse instance type selection
  • C. Use Horizontal Pod Autoscaler to scale Spark executors
  • D. Use Cluster Autoscaler with a single node group
Jawaban Benar: B
Karpenter provisions nodes dalam hitungan detik (vs minutes untuk Cluster Autoscaler) dan secara otomatis memilih instance types optimal berdasarkan pending pod requirements. Karpenter juga support mixed instance types dan consolidation.

Opsi A: SALAH. Membuang biaya saat idle — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi B: BENAR.
Opsi C: SALAH. Scale pods bukan nodes — pods tetap pending jika node resources habis.
Opsi D: SALAH. Lebih lambat karena harus scale node groups yang sudah didefinisikan.
8
A company uses Amazon ECS to run a containerized data processing application that reads from Amazon Kinesis. The application uses the Kinesis Client Library (KCL). There are 10 Kinesis shards. The ECS service needs to ensure exactly one KCL worker per shard for optimal processing. How should the service be configured?
  • A. Set desired count to 1 task with 10 threads inside the container
  • B. Set desired count to 20 tasks for redundancy with one KCL worker per task
  • C. Set the ECS service desired count to 10 tasks, matching the number of shards, with one KCL worker per task
  • D. Use ECS Service Auto Scaling based on CPU utilization
Jawaban Benar: C
KCL distributes shard leases among workers. Dengan 10 shards, 10 tasks (workers) memastikan setiap task memproses tepat 1 shard — beban terdistribusi merata. Jika satu task fails, KCL akan redistribusi shard ke remaining workers.

Opsi A: SALAH. Single point of failure, jika task dies semua processing berhenti.
Opsi B: SALAH. 10 tasks akan idle karena hanya ada 10 shards, membuang resources — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi C: BENAR.
Opsi D: SALAH. Tidak tahu tentang shard count.

A data engineer is building a container image for an ETL application that will run on ECS Fargate. The application requires Python, pandas, numpy, and scikit-learn. The initial image size is 2.5 GB, causing slow task startup times. How can the image be optimized for faster start?
  • A. Use Amazon Linux 2 base image and compile Python from source
  • B. Use the full python:3.11 image for compatibility with a slim Python base image (python:3 and remove cache files
  • C. Use a multi-stage build with a slim Python base image (python:3.11-slim), install only production dependencies, and remove cache files
  • D. Install all dependencies at runtime using an entrypoint script
Jawaban Benar: C
Multi-stage build mengurangi image size dengan memisahkan build stage (compile dependencies) dari runtime stage (hanya binary/packages yang diperlukan). python:3.11-slim jauh lebih kecil dari full image. Menghapus pip cache dan unnecessary files mengurangi ukuran lebih lanjut. Smaller image = faster pull = faster task startup.

Opsi A: SALAH. Menambah complexity tanpa benefit signifikan.
Opsi B: SALAH. 2 — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.5GB tetap besar.
Opsi C: BENAR.
Opsi D: SALAH. Memperlambat setiap task start.
10
A company runs an EKS-based data pipeline that processes customer data. Compliance requires that data processing containers cannot communicate with the internet. The containers only need access to S3, DynamoDB, and the Kubernetes API server. Which network configuration enforces this?
  • A. Remove the Internet Gateway from the VPC
  • B. Use Kubernetes NetworkPolicy to block egress to 0.0.0.0/0
  • C. Deploy pods in private subnets without NAT Gateway, create VPC endpoints for S3 and DynamoDB, and use EKS private endpoint access
  • D. Configure security groups to deny all outbound traffic and DynamoDB, and use EKS private endpoint access for S3 and DynamoDB
Jawaban Benar: C
Private subnets tanpa NAT Gateway memastikan tidak ada internet access. VPC endpoints (Gateway endpoint untuk S3/DynamoDB) memungkinkan akses ke AWS services tanpa internet. EKS private endpoint memungkinkan kubelet/pods berkomunikasi dengan control plane secara private.

Opsi A: SALAH. Mempengaruhi seluruh VPC termasuk resources yang butuh internet.
Opsi B: SALAH. Bergantung pada CNI plugin dan bisa di-bypass.
Opsi C: BENAR.
Opsi D: SALAH. Memblokir semua termasuk VPC endpoints — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
