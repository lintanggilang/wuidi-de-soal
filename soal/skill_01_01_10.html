1
A company has a single Amazon Kinesis Data Stream receiving clickstream events. Three different consumer applications need to read from this stream independently: a real-time dashboard, a fraud detection service, and a data lake writer. Without Enhanced Fan-Out, consumers share 2 MB/s per shard. What happens when all three consumers read from the same shard?
  • A. Only one consumer can read at a time; others are queued with partition-level ordering and dedicated throughput
  • B. Each consumer gets the full 2 MB/s independently, making the data queryable within seconds of arrival
  • C. Each consumer gets approximately 666 KB/s of read throughput per shard, potentially causing increased latency
  • D. The stream automatically creates additional shards for each consumer, handling the described workload reliably at scale
Correct Answer: C
Without Enhanced Fan-Out, all consumers shares 2 MB/s read throughput per shard uses GetRecords API (polling). By 3 consumers, each in a effective mendapat ~666 KB/s. Selain that, GetRecords is limited 5 calls/second per shard that also is divided. Ini increases read latency.

Option A: INCORRECT. Salah — multiple consumers can polling simultaneously — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option B: INCORRECT. Only applies with Enhanced Fan-Out.
Option C: CORRECT.
Option D: INCORRECT. Kinesis not auto-shard based on consumer count.
2
A data engineer is designing a fan-out architecture where a single event stream must be delivered to 5 different downstream services, each requiring different processing. The total event rate is 10,000 events per second. Which architecture provides the MOST scalable fan-out?
  • A. Amazon SNS topic receiving events, with SQS queues as subscriptions for each downstream service
  • B. Single Lambda function that forwards events to 5 different SQS queues with SQS queues as subscriptions for each
  • C. Amazon Kinesis Data Stream with 5 separate consumer applications using Enhanced Fan-Out
  • D. Amazon MSK topic with 5 consumer groups, meeting the latency and throughput goals of the design
Correct Answer: A
SNS + SQS fan-out pattern is that most scalable. SNS can handle millions of messages/second and delivers to all subscribers (SQS queues) in a independent. Each SQS queue buffers messages for consumer each, provides decoupling sempurna.

Option A: CORRECT.
Option B: INCORRECT. Menjadi bottleneck and single point of failure — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option C: INCORRECT. Baik for streaming but Enhanced Fan-Out max 20 consumers and has cost per-consumer per-shard.
Option D: INCORRECT. Valid but more operational overhead.
3
A company has 500 IoT gateways (fan-in producers) each sending telemetry data to a central processing system. The total data rate is 50 MB/s. The system must maintain ordering within each gateway and support real-time processing. Which fan-in architecture is MOST appropriate?
  • A. Amazon SQS standard queue receiving from all gateways, keeping every related record in its produced order and delivering records with consistent sub-second latency
  • B. Amazon Kinesis Data Streams with gateway ID as partition key, ensuring each gateway's data goes to the same shard for ordering
  • C. Amazon S3 with each gateway writing to its own prefix, streaming results downstream in near real time and minimizing end-to-end processing latency
  • D. Direct Lambda invocation from each gateway with gateway ID as partition key for ordering, handling the described workload reliably at scale
Correct Answer: B
Kinesis with gateway ID sebagai partition key guarantees ordering per gateway (all records from gateway that same enters to shard that same). By 50 MB/s, needed minimal 50 shards (1 MB/s per shard). 500 gateways will terdistribusi in between 50 shards (~10 gateways per shard). Ini scalable and real-time.

Option A: INCORRECT. Not guarantees ordering.
Option B: CORRECT.
Option C: INCORRECT. Not real-time processing.
Option D: INCORRECT. Not suitable for high-throughput streaming — although its description sounds convincing, in a fundamental still not appropriate for requirements this.

A data engineer needs to implement a pattern where data from one Kinesis stream is filtered and routed to three different Kinesis streams based on content (e.g., priority level: high, medium, low). Which service provides the MOST efficient stream-to-stream fan-out with filtering?
  • A. AWS Glue streaming ETL job that reads from one stream and writes to three streams
  • B. Amazon Data Firehose with dynamic partitioning to route records to different destinations
  • C. Lambda function consuming from the source stream that puts records into the appropriate target stream based on content
  • D. Amazon EventBridge Pipes with filtering and enrichment to route to target streams
Correct Answer: D
Amazon EventBridge Pipes supports source (Kinesis), filtering (content-based), optional enrichment, and target (another Kinesis stream). By multiple pipes from source that same with different filters, records can in-route to target streams different. Ini serverless and minimal code.

Option A: INCORRECT. Overkill for simple routing.
Option B: INCORRECT. Supports dynamic partitioning but target-nya S3/Redshift/dll, not Kinesis stream other.
Option C: INCORRECT. Bekerja but requires code maintenance.
Option D: CORRECT.

A media company needs to distribute live video metadata events to 20 different microservices. Each microservice needs to receive ALL events. The event rate is 100,000 events per second. Which fan-out pattern handles this scale with guaranteed delivery to all consumers?
  • A. Amazon Kinesis with Enhanced Fan-Out registered for 20 consumers configured for optimal performance and minimal operational overhead
  • B. Amazon SNS topic with 20 SQS subscriptions for guaranteed delivery, scaling horizontally as ingestion throughput keeps growing
  • C. Amazon EventBridge custom event bus with 20 rules targeting different services, scaling horizontally as ingestion throughput keeps growing
  • D. Amazon MSK (Kafka) topic with 20 consumer groups, each independently consuming all messages from the topic
Correct Answer: D
Amazon MSK (Kafka) consumer groups enables each group reads all messages from topic in a independent. Kafka designed for high-throughput (100K+ events/sec) with multiple consumer groups without performance degradation because messages is stored in log.

Option A: INCORRECT. Only supports max 20 consumers but with 100K events/sec requires many shards that expensive — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option B: INCORRECT. Has message size limit 256KB and can costly in volume this.
Option C: INCORRECT. Has throughput limits that may not quite.
Option D: CORRECT.
6
A data platform aggregates events from three different Kinesis streams (orders, payments, inventory) into a single unified stream for downstream analytics. Each source stream has different schemas. Which fan-in approach provides the MOST maintainable solution?
  • A. Amazon EventBridge Pipes from each source stream to the unified target stream with transformation
  • B. Amazon Data Firehose streams from each source, all writing to the same S3 prefix
  • C. AWS Glue streaming ETL with three source connections merging into one output stream
  • D. Three Lambda functions (one per source stream) that normalize schemas and write to the unified target stream
Correct Answer: A
EventBridge Pipes can consume from Kinesis source, apply transformation (including schema normalization via enrichment or input transformer), and write to target Kinesis stream. Three pipes (one per source) fan-in to satu target stream. Ini serverless, no-code, and maintainable.

Option A: CORRECT.
Option B: INCORRECT. Not streaming fan-in to Kinesis.
Option C: INCORRECT. Can multiple sources but has cost DPU and startup time.
Option D: INCORRECT. Bekerja but requires code for each stream.
7
A ride-sharing company uses Kinesis to stream ride events. They need to fan-out the stream to: (1) a real-time pricing engine that needs sub-second latency, (2) a data lake writer that can tolerate 5-minute latency, and (3) an ML model training pipeline. Each consumer has different throughput and latency requirements. Which architecture satisfies all requirements?
  • A. Enhanced Fan-Out for the pricing engine (low latency), standard shared consumer for the data lake writer, and a separate Kinesis Analytics application for ML preprocessing
  • B. Amazon Data Firehose for all three consumers with different buffer intervals, meeting the latency and throughput goals of the design and delivering records with consistent sub-second latency
  • C. Three separate Kinesis streams, one for each consumer configured for optimal performance and minimal operational overhead, integrating natively with the rest of the pipeline
  • D. Single Lambda function that writes to three different targets, integrating natively with the rest of the pipeline and streaming results downstream in near real time
Correct Answer: A
Enhanced Fan-Out provides dedicated 2MB/s and ~70ms latency via HTTP/2 push — ideal for pricing engine that butuh sub-second. Standard shared consumer (GetRecords) quite for data lake writer that toleran latency. Kinesis Analytics (Flink) performs preprocessing for ML. Ini optimizes cost appropriate requirement each.

Option A: CORRECT.
Option B: INCORRECT. Minimum buffer 60 seconds, not suitable for sub-second pricing engine.
Option C: INCORRECT. Requires producing to 3 streams that expensive — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option D: INCORRECT. Menjadi bottleneck.

A data engineer is implementing a fan-in pattern where multiple AWS accounts produce events that need to be consolidated into a single Kinesis stream in a central analytics account. Each producer account generates 1,000 events/second. Which is the MOST secure cross-account fan-in approach?
  • A. Create IAM users with access keys in the central account for each producer and have producers assume a cross-account role to write
  • B. Use VPC Peering between all accounts and write via private endpoints, handling the described workload reliably at scale and providing exactly-once processing semantics
  • C. Configure a Kinesis stream resource policy allowing PutRecord from producer account roles, and have producers assume a cross-account role to write
  • D. Each producer writes to their local stream, then replicate via DMS to central stream, satisfying strict compliance and audit requirements
Correct Answer: C
Kinesis resource policy (since 2023) enables cross-account access directly. Producer accounts uses IAM roles (AssumeRole) for mendapat temporary credentials and writes to stream in central account. Ini mengikuti least privilege and not requires static credentials.

Option A: INCORRECT. Anti-pattern security — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option B: INCORRECT. Adds complexity and not is required because Kinesis is regional service.
Option C: CORRECT.
Option D: INCORRECT. Overkill and adds latency.

A company uses Amazon MSK for event streaming. They need to implement a fan-out where one source topic distributes to multiple destination topics based on message attributes. Messages with attribute "region=US" go to topic-us, "region=EU" to topic-eu, etc. Which MSK-native approach is BEST?
  • A. Use MSK Connect with a custom SMT (Single Message Transform) to route messages
  • B. Configure MSK topic-level routing rules in the broker settings, integrating natively with the rest of the pipeline
  • C. Use Kafka Streams application with branching (KStream.branch) to route messages to different topics based on predicates
  • D. Use multiple consumer groups each filtering for their region with branching, handling the described workload reliably at scale
Correct Answer: C
Kafka Streams KStream.branch() (or split() in newer versions) enables routing messages to multiple output topics based on predicates (conditions). Ini runs sebagai stream processing application that reads from source topic and writes to destination topics. Ini MSK-native and scalable.

Option A: INCORRECT. Biasanya for transformation, not multi-topic routing.
Option B: INCORRECT. Kafka brokers not has routing rules built-in.
Option C: CORRECT.
Option D: INCORRECT. Each group reads ALL messages and membuang that not needed (inefficient) — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
10
A data pipeline uses Kinesis Data Streams with 20 shards. The company adds a new consumer application, making it 5 total consumers using standard GetRecords (no Enhanced Fan-Out). Performance degrades significantly. Which metric confirms the fan-out bottleneck and what is the immediate solution?
  • A. GetRecords.IteratorAgeMilliseconds increases; increase Lambda concurrency, integrating natively with the rest of the pipeline
  • B. ReadProvisionedThroughputExceeded metric increases; enable Enhanced Fan-Out for at least the latency-sensitive consumers
  • C. IncomingBytes metric decreases; fix the producers for at least the latency-sensitive consumers
  • D. WriteProvisionedThroughputExceeded metric increases; add more shards, handling the described workload reliably at scale
Correct Answer: B
ReadProvisionedThroughputExceeded menunjukkan that consumers melebihi read capacity (2 MB/s shared or 5 GetRecords calls/s per shard). By 5 consumers shares, each consumer only can GetRecords 1x/second per shard. Enhanced Fan-Out provides dedicated 2 MB/s per consumer per shard via HTTP/2 push, eliminates sharing.

Option A: INCORRECT. Adalah symptom, not confirmation metric for fan-out bottleneck.
Option B: CORRECT.
Option C: INCORRECT. Terkait ingestion not consumption — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option D: INCORRECT. Terkait producers not consumers.
