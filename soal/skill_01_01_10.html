Skill 1.1.10: Manage Fan-In and Fan-Out for Streaming Data Distribution

Patterns for distributing streaming data to multiple consumers and aggregating from multiple producers

12345 678910
1
A company has a single Amazon Kinesis Data Stream receiving clickstream events. Three different consumer applications need to read from this stream independently: a real-time dashboard, a fraud detection service, and a data lake writer. Without Enhanced Fan-Out, consumers share 2 MB/s per shard. What happens when all three consumers read from the same shard?
  • A. Each consumer gets approximately 666 KB/s of read throughput per shard, potentially causing increased latency
  • B. Each consumer gets the full 2 MB/s independently
  • C. Only one consumer can read at a time; others are queued
  • D. The stream automatically creates additional shards for each consumer
Jawaban Benar: A
Tanpa Enhanced Fan-Out, semua consumers berbagi 2 MB/s read throughput per shard menggunakan GetRecords API (polling). Dengan 3 consumers, masing-masing secara efektif mendapat ~666 KB/s. Selain itu, GetRecords dibatasi 5 calls/second per shard yang juga dibagi. Ini meningkatkan read latency. Opsi B hanya berlaku dengan Enhanced Fan-Out. Opsi C salah — multiple consumers bisa polling bersamaan. Opsi D — Kinesis tidak auto-shard berdasarkan consumer count.
2
A data engineer is designing a fan-out architecture where a single event stream must be delivered to 5 different downstream services, each requiring different processing. The total event rate is 10,000 events per second. Which architecture provides the MOST scalable fan-out?
  • A. Amazon SNS topic receiving events, with SQS queues as subscriptions for each downstream service
  • B. Amazon Kinesis Data Stream with 5 separate consumer applications using Enhanced Fan-Out
  • C. Single Lambda function that forwards events to 5 different SQS queues
  • D. Amazon MSK topic with 5 consumer groups
Jawaban Benar: A
SNS + SQS fan-out pattern adalah yang paling scalable. SNS dapat handle millions of messages/second dan delivers ke semua subscribers (SQS queues) secara independen. Setiap SQS queue buffers messages untuk consumer masing-masing, memberikan decoupling sempurna. Opsi B (Kinesis EFO) baik untuk streaming tapi Enhanced Fan-Out max 20 consumers dan memiliki biaya per-consumer per-shard. Opsi C (Lambda forwarder) menjadi bottleneck dan single point of failure. Opsi D (MSK) valid tapi lebih operational overhead.
3
A company has 500 IoT gateways (fan-in producers) each sending telemetry data to a central processing system. The total data rate is 50 MB/s. The system must maintain ordering within each gateway and support real-time processing. Which fan-in architecture is MOST appropriate?
  • A. Amazon Kinesis Data Streams with gateway ID as partition key, ensuring each gateway's data goes to the same shard for ordering
  • B. Amazon SQS standard queue receiving from all gateways
  • C. Direct Lambda invocation from each gateway
  • D. Amazon S3 with each gateway writing to its own prefix
Jawaban Benar: A
Kinesis dengan gateway ID sebagai partition key menjamin ordering per gateway (semua records dari gateway yang sama masuk ke shard yang sama). Dengan 50 MB/s, dibutuhkan minimal 50 shards (1 MB/s per shard). 500 gateways akan terdistribusi di antara 50 shards (~10 gateways per shard). Ini scalable dan real-time. Opsi B (SQS) tidak menjamin ordering. Opsi C (Lambda) tidak cocok untuk high-throughput streaming. Opsi D (S3) bukan real-time processing.
4
A data engineer needs to implement a pattern where data from one Kinesis stream is filtered and routed to three different Kinesis streams based on content (e.g., priority level: high, medium, low). Which service provides the MOST efficient stream-to-stream fan-out with filtering?
  • A. Amazon Data Firehose with dynamic partitioning to route records to different destinations
  • B. Lambda function consuming from the source stream that puts records into the appropriate target stream based on content
  • C. Amazon EventBridge Pipes with filtering and enrichment to route to target streams
  • D. AWS Glue streaming ETL job that reads from one stream and writes to three streams
Jawaban Benar: C
Amazon EventBridge Pipes mendukung source (Kinesis), filtering (content-based), optional enrichment, dan target (another Kinesis stream). Dengan multiple pipes dari source yang sama dengan different filters, records bisa di-route ke target streams berbeda. Ini serverless dan minimal code. Opsi A (Firehose) mendukung dynamic partitioning tapi target-nya S3/Redshift/dll, bukan Kinesis stream lain. Opsi B (Lambda) bekerja tapi membutuhkan code maintenance. Opsi D (Glue streaming) overkill untuk simple routing.
5
A media company needs to distribute live video metadata events to 20 different microservices. Each microservice needs to receive ALL events. The event rate is 100,000 events per second. Which fan-out pattern handles this scale with guaranteed delivery to all consumers?
  • A. Amazon MSK (Kafka) topic with 20 consumer groups, each independently consuming all messages from the topic
  • B. Amazon Kinesis with Enhanced Fan-Out registered for 20 consumers
  • C. Amazon SNS topic with 20 SQS subscriptions for guaranteed delivery
  • D. Amazon EventBridge custom event bus with 20 rules targeting different services
Jawaban Benar: A
Amazon MSK (Kafka) consumer groups memungkinkan setiap group membaca semua messages dari topic secara independen. Kafka dirancang untuk high-throughput (100K+ events/sec) dengan multiple consumer groups tanpa performance degradation karena messages disimpan di log. Opsi B (Kinesis EFO) hanya mendukung max 20 consumers tapi dengan 100K events/sec membutuhkan banyak shards yang mahal. Opsi C (SNS+SQS) memiliki message size limit 256KB dan bisa costly di volume ini. Opsi D (EventBridge) memiliki throughput limits yang mungkin tidak cukup.
6
A data platform aggregates events from three different Kinesis streams (orders, payments, inventory) into a single unified stream for downstream analytics. Each source stream has different schemas. Which fan-in approach provides the MOST maintainable solution?
  • A. Three Lambda functions (one per source stream) that normalize schemas and write to the unified target stream
  • B. AWS Glue streaming ETL with three source connections merging into one output stream
  • C. Amazon Data Firehose streams from each source, all writing to the same S3 prefix
  • D. Amazon EventBridge Pipes from each source stream to the unified target stream with transformation
Jawaban Benar: D
EventBridge Pipes dapat consume dari Kinesis source, apply transformation (including schema normalization via enrichment or input transformer), dan write ke target Kinesis stream. Three pipes (one per source) fan-in ke satu target stream. Ini serverless, no-code, dan maintainable. Opsi A (Lambda) bekerja tapi membutuhkan code untuk setiap stream. Opsi B (Glue streaming) bisa multiple sources tapi memiliki biaya DPU dan startup time. Opsi C (Firehose→S3) bukan streaming fan-in ke Kinesis.
7
A ride-sharing company uses Kinesis to stream ride events. They need to fan-out the stream to: (1) a real-time pricing engine that needs sub-second latency, (2) a data lake writer that can tolerate 5-minute latency, and (3) an ML model training pipeline. Each consumer has different throughput and latency requirements. Which architecture satisfies all requirements?
  • A. Enhanced Fan-Out for the pricing engine (low latency), standard shared consumer for the data lake writer, and a separate Kinesis Analytics application for ML preprocessing
  • B. Three separate Kinesis streams, one for each consumer
  • C. Single Lambda function that writes to three different targets
  • D. Amazon Data Firehose for all three consumers with different buffer intervals
Jawaban Benar: A
Enhanced Fan-Out memberikan dedicated 2MB/s dan ~70ms latency via HTTP/2 push — ideal untuk pricing engine yang butuh sub-second. Standard shared consumer (GetRecords) cukup untuk data lake writer yang toleran latency. Kinesis Analytics (Flink) melakukan preprocessing untuk ML. Ini mengoptimalkan cost sesuai requirement masing-masing. Opsi B (3 streams) membutuhkan producing ke 3 streams yang mahal. Opsi C (single Lambda) menjadi bottleneck. Opsi D (Firehose) minimum buffer 60 detik, tidak cocok untuk sub-second pricing engine.
8
A data engineer is implementing a fan-in pattern where multiple AWS accounts produce events that need to be consolidated into a single Kinesis stream in a central analytics account. Each producer account generates 1,000 events/second. Which is the MOST secure cross-account fan-in approach?
  • A. Configure a Kinesis stream resource policy allowing PutRecord from producer account roles, and have producers assume a cross-account role to write
  • B. Create IAM users with access keys in the central account for each producer
  • C. Use VPC Peering between all accounts and write via private endpoints
  • D. Each producer writes to their local stream, then replicate via DMS to central stream
Jawaban Benar: A
Kinesis resource policy (sejak 2023) memungkinkan cross-account access secara langsung. Producer accounts menggunakan IAM roles (AssumeRole) untuk mendapat temporary credentials dan menulis ke stream di central account. Ini mengikuti least privilege dan tidak memerlukan static credentials. Opsi B (IAM users + access keys) anti-pattern keamanan. Opsi C (VPC Peering) menambah complexity dan tidak diperlukan karena Kinesis adalah regional service. Opsi D (DMS replication) overkill dan menambah latency.
9
A company uses Amazon MSK for event streaming. They need to implement a fan-out where one source topic distributes to multiple destination topics based on message attributes. Messages with attribute "region=US" go to topic-us, "region=EU" to topic-eu, etc. Which MSK-native approach is BEST?
  • A. Use Kafka Streams application with branching (KStream.branch) to route messages to different topics based on predicates
  • B. Use MSK Connect with a custom SMT (Single Message Transform) to route messages
  • C. Use multiple consumer groups each filtering for their region
  • D. Configure MSK topic-level routing rules in the broker settings
Jawaban Benar: A
Kafka Streams KStream.branch() (atau split() di newer versions) memungkinkan routing messages ke multiple output topics berdasarkan predicates (conditions). Ini berjalan sebagai stream processing application yang membaca dari source topic dan menulis ke destination topics. Ini MSK-native dan scalable. Opsi B (MSK Connect SMT) biasanya untuk transformasi, bukan multi-topic routing. Opsi C (consumer groups) — setiap group membaca ALL messages dan membuang yang tidak dibutuhkan (inefficient). Opsi D — Kafka brokers tidak memiliki routing rules built-in.
10
A data pipeline uses Kinesis Data Streams with 20 shards. The company adds a new consumer application, making it 5 total consumers using standard GetRecords (no Enhanced Fan-Out). Performance degrades significantly. Which metric confirms the fan-out bottleneck and what is the immediate solution?
  • A. ReadProvisionedThroughputExceeded metric increases; enable Enhanced Fan-Out for at least the latency-sensitive consumers
  • B. WriteProvisionedThroughputExceeded metric increases; add more shards
  • C. GetRecords.IteratorAgeMilliseconds increases; increase Lambda concurrency
  • D. IncomingBytes metric decreases; fix the producers
Jawaban Benar: A
ReadProvisionedThroughputExceeded menunjukkan bahwa consumers melebihi read capacity (2 MB/s shared atau 5 GetRecords calls/s per shard). Dengan 5 consumers berbagi, setiap consumer hanya bisa GetRecords 1x/second per shard. Enhanced Fan-Out memberikan dedicated 2 MB/s per consumer per shard via HTTP/2 push, menghilangkan sharing. Opsi B (Write exceeded) terkait producers bukan consumers. Opsi C (IteratorAge) adalah symptom, bukan confirmation metric untuk fan-out bottleneck. Opsi D (IncomingBytes) terkait ingestion bukan consumption.
