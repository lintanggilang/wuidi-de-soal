A company stores daily sales reports as CSV files in an Amazon S3 bucket with the prefix `sales/year=2024/month=01/day=01/`. The data engineering team needs to read these files into a data lake and make them queryable via Amazon Athena. The schema changes occasionally. Which approach BEST handles this scenario?
  • A. Use an AWS Glue crawler to catalog the data and define the table schema automatically
  • B. Copy the data to DynamoDB and create a secondary index for queries and define the table schema automatically
  • C. Use Amazon Redshift Spectrum to query the S3 data directly, handling the described workload reliably at scale
  • D. Manually create an Athena table with a fixed schema pointing to the S3 prefix
Correct Answer: A
AWS Glue crawler automatically detects schema from data in S3 and creates/updates table in Glue Data Catalog. When schema changes, crawler will detects changes said.

Option A: CORRECT.
Option B: INCORRECT. Not solution for analitik batch data — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option C: INCORRECT. Requires Redshift cluster that expensive for use case this.
Option D: INCORRECT. Not handles changes schema.

A data engineer needs to ingest data from a Salesforce CRM system into Amazon S3 on a scheduled basis. The data should be incrementally loaded based on the last modified timestamp. The solution must require minimal custom code. Which AWS service is MOST appropriate?
  • A. AWS Lambda with a custom Python script calling Salesforce REST API
  • B. AWS Glue with a custom PySpark script using Salesforce JDBC connector
  • C. AWS DMS with Salesforce as a source endpoint and incremental transfer
  • D. Amazon AppFlow with a scheduled flow and incremental transfer
Correct Answer: D
Amazon AppFlow designed khusus for integration data from SaaS applications such as Salesforce to AWS services. AppFlow supports scheduled flows and incremental data transfer based on field filter (such as last modified date), without code custom.

Option A: INCORRECT. Requires many custom code for pagination, error handling, dll.
Option B: INCORRECT. Requires custom code and configuration JDBC.
Option C: INCORRECT. Not supports Salesforce as source natively — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option D: CORRECT.

An organization has a 50 TB Oracle data warehouse on-premises. They want to perform a one-time full load migration to Amazon Redshift, followed by ongoing CDC (Change Data Capture) replication. Which service combination provides the MOST complete solution?
  • A. AWS DataSync for full load and AWS DMS for ongoing CDC
  • B. AWS Glue for full load ETL and Amazon AppFlow for ongoing changes
  • C. AWS DMS for full load and CDC, with AWS SCT for schema conversion
  • D. Amazon EMR with Sqoop for full load and custom Spark streaming for CDC
Correct Answer: C
AWS DMS supports full load and ongoing replication (CDC) from Oracle to Redshift. AWS SCT (Schema Conversion Tool) mengkonversi schema Oracle to format that compatible with Redshift. Kombinasi this is solution most lengkap.

Option A: INCORRECT. Only for file transfer, not database migration.
Option B: INCORRECT. Not supports CDC from Oracle.
Option C: CORRECT.
Option D: INCORRECT. Too kompleks.

A data engineer needs to process 500 GB of JSON files stored in Amazon S3. The files need to be read, filtered, and aggregated before being loaded into a Redshift table. The processing job runs once daily and must complete within 2 hours. Cost optimization is a priority. Which approach is MOST cost-effective?
  • A. Amazon EMR cluster with Spot Instances running Apache Spark
  • B. AWS Glue ETL job with auto-scaling enabled
  • C. AWS Lambda functions processing files in parallel
  • D. Amazon Redshift COPY command to load raw JSON, then transform with SQL
Correct Answer: A
Amazon EMR with Spot Instances provides harga up to 90% cheaper from On-Demand for workload that toleran against interupsi. For job harian 500 GB that must complete in 2 hours, EMR Spark with Spot very cost-effective.

Option A: CORRECT.
Option B: INCORRECT. Has cost DPU per hours that higher.
Option C: INCORRECT. Has limit memory 10 GB and timeout 15 minutes, not suitable for 500 GB data.
Option D: INCORRECT. Memuat all data mentah to Redshift dulu that not efficient and adds cost storage.

A company uses Amazon Redshift as their data warehouse. A data engineer needs to regularly load large datasets from S3 into Redshift. The data files are in Parquet format and are organized with Hive-style partitioning. Which loading method provides the BEST performance?
  • A. Use INSERT INTO...SELECT from an external table using Redshift Spectrum, applying schema conversion and enrichment inline
  • B. Use AWS Glue to read from S3 and write to Redshift using a JDBC connection
  • C. Use the COPY command with a manifest file specifying the exact files to load
  • D. Use the Redshift Data API to execute batch INSERT statements with a manifest file
Correct Answer: C
COPY command is method most efficient for loading data to Redshift from S3. By manifest file, Anda can controls file mana that loaded, prevents duplikasi, and ensures all file that is required there is. COPY reads Parquet natively and performs parallel loading from all file.

Option A: INCORRECT. Bagus for query but INSERT INTO from external table slower from COPY directly.
Option B: INCORRECT. Jauh slower because single-connection writing.
Option C: CORRECT.
Option D: INCORRECT. Is method most slow — although its description sounds convincing, in a fundamental still not appropriate for requirements this.

A retail company receives product catalog updates from 50 suppliers daily via different file formats (CSV, JSON, XML) dropped into separate S3 prefixes. The data engineer needs to create a unified pipeline that reads all formats and loads them into a single normalized table. Which service provides the MOST efficient solution?
  • A. AWS Lambda functions triggered by S3 events for each prefix, meeting the latency and throughput goals of the design
  • B. Amazon EMR with custom Spark code for each file format and a unified ETL job with dynamic frames
  • C. Amazon Athena CTAS queries for each format, meeting the latency and throughput goals of the design
  • D. AWS Glue ETL with multiple crawlers for each format and a unified ETL job with dynamic frames
Correct Answer: D
AWS Glue crawler detects schema berbagai format (CSV, JSON, dll.) and creates table in Glue Data Catalog. Glue ETL with DynamicFrames can reads from berbagai format, applies mapping and transformation, lalu writes to output that terstandarisasi. This solution most efficient because fully managed.

Option A: INCORRECT. Difficult for handling XML parsing and normalisasi kompleks in limit 15 minutes.
Option B: INCORRECT. Requires many custom code — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option C: INCORRECT. Not supports XML natively.
Option D: CORRECT.

A data engineer is using AWS Lambda to read batch files from Amazon S3 for processing. The Lambda function times out when processing files larger than 500 MB. The engineer cannot change the overall architecture. What modification should be made to handle large files?
  • A. Mount an Amazon EFS volume to Lambda and stream the file to EFS first
  • B. Use S3 byte-range fetches to process the file in chunks within Lambda
  • C. Configure Lambda with 10 GB memory and use multi-threaded processing
  • D. Increase Lambda timeout to the maximum of 15 minutes and use S3 Select to read only required columns
Correct Answer: B
S3 byte-range fetches enables Lambda reads file in a gradually (chunk by chunk) without memuat entire file to memory. This avoids timeout because each invocation processes partly data.

Option A: INCORRECT. Adds latency and not solves timeout.
Option B: CORRECT.
Option C: INCORRECT. Not solves problem timeout because reads file large from S3 still consumes time old.
Option D: INCORRECT. Berguna but only if that needed filtering column, not problem size file keseluruhan.

A media company stores video metadata in Amazon S3 across multiple AWS accounts. A central data engineering team needs to read data from S3 buckets in 10 different accounts and consolidate it into a single data lake account. What is the MOST scalable approach to manage cross-account S3 access?
  • A. Use AWS Organizations with Service Control Policies to grant blanket access, handling the described workload reliably at scale and integrating natively with the rest of the pipeline
  • B. Configure S3 bucket policies in each account granting access to an IAM role in the central account, and use AWS Glue with an assumed role
  • C. Create IAM users with access keys in each account and store credentials in Secrets Manager, integrating natively with the rest of the pipeline
  • D. Copy all data to the central account using S3 Replication rules with an assumed role and use AWS Glue with an assumed role
Correct Answer: B
Cross-account S3 access most scalable uses bucket policies that allows IAM role from central account. AWS Glue can assume role this for reads data directly from bucket in akun other without copying data.

Option A: INCORRECT. Only for limits/deny permissions, not grant access.
Option B: CORRECT.
Option C: INCORRECT. Not scalable and merupakan anti-pattern security.
Option D: INCORRECT. Menduplikasi data and adds cost storage — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
