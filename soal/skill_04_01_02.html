A company has a data engineering team of 15 members who all need read access to production S3 data lake buckets, write access to development S3 buckets, and the ability to run AWS Glue jobs. Three senior engineers additionally need access to manage EMR clusters. Which IAM configuration follows AWS best practices for managing these permissions?
  • A. Create an IAM group "DataEngineers" with the common permissions attached as managed policies, and a second group "SeniorDataEngineers" with EMR management policies. Add engineers to appropriate groups.
  • B. Create a single IAM role "DataEngineerRole" with all permissions and have all engineers assume the role when needed with fully managed infrastructure and automatic scaling
  • C. Create individual IAM users with inline policies tailored to each engineer's specific needs
  • D. Create one IAM group with full administrator access and use AWS Organizations SCPs to restrict permissions at the account level
Jawaban Benar: A
AWS best practice adalah menggunakan IAM Groups untuk mengelola permissions berdasarkan job function. Group "DataEngineers" berisi common policies (S3 read prod, S3 write dev, Glue job run) yang berlaku untuk semua 15 engineer. Group "SeniorDataEngineers" menambahkan EMR management policies. Senior engineers menjadi member di kedua groups dan mewarisi semua permissions.

Opsi A: BENAR.
Opsi B: SALAH. Memberikan semua orang permissions yang sama termasuk EMR — melanggar least privilege — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi C: SALAH. Tidak scalable dan sulit di-maintain.
Opsi D: SALAH. Terlalu permissive dan SCP tidak dimaksudkan untuk granular user permissions.

A data engineer needs to create an IAM role that allows AWS Glue to access an S3 bucket in another AWS account (Account B). The Glue job runs in Account A. Which combination of configurations is required for cross-account access?
  • A. In Account A: Create IAM role with trust policy for s3.amazonaws.com. In Account B: Create an IAM user with access keys and store them in Secrets Manager for Glue to use.
  • B. In Account A: Create a VPC endpoint for S3 pointing to Account B. In Account B: Allow access from Account A's VPC endpoint in the bucket policy, with trust policy for glue and a policy allowing s3:GetObject on Account B's bucket
  • C. In Account A: Create IAM role with AdministratorAccess. In Account B: Disable S3 Block Public Access on the bucket.
  • D. In Account A: Create IAM role with trust policy for glue.amazonaws.com and a policy allowing s3:GetObject on Account B's bucket. In Account B: Add a bucket policy allowing the Account A Glue role to access the bucket.
Jawaban Benar: D
Cross-account S3 access memerlukan konfigurasi di kedua akun: (1) Account A: IAM role untuk Glue dengan trust policy yang mengizinkan glue.amazonaws.com sebagai principal, plus IAM policy dengan permission s3:GetObject pada ARN bucket Account B. (2) Account B: Bucket policy yang mengizinkan Account A's Glue role ARN untuk mengakses bucket. Kedua sisi harus explicitly mengizinkan.

Opsi A: SALAH. Melanggar best practice — gunakan roles, bukan long-term credentials.
Opsi B: SALAH. Tidak memberikan cross-account access — VPC endpoint hanya route traffic, tidak memberikan permission — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi C: SALAH. Sangat tidak aman.
Opsi D: BENAR.

A data engineer needs to allow an Amazon Redshift cluster to access data in Amazon S3 and also to call AWS Lambda UDFs (User-Defined Functions). The engineer creates an IAM role for Redshift. Which trust policy configuration is correct for this IAM role?
  • A. Trust policy with Principal: {"AWS": "arn:aws:iam::ACCOUNT_ID:root"} allowing any service in the account to assume the role
  • B. Trust policy with Principal: {"Service": ["redshift.amazonaws.com", "lambda.amazonaws.com"]} and permission policy allowing s3:* and lambda:InvokeFunction
  • C. Trust policy with Principal: {"Service": "redshift.amazonaws.com"} and permission policy allowing s3:* and lambda:InvokeFunction
  • D. Trust policy with Principal: {"Service": "s3.amazonaws.com"} and separate trust for lambda.amazonaws.com
Jawaban Benar: C
Trust policy menentukan SIAPA yang boleh assume role (Principal), sedangkan permission policy menentukan APA yang boleh dilakukan setelah assuming role. Redshift yang akan assume role, jadi trust policy harus memiliki Principal: redshift.amazonaws.com. Permission policy kemudian memberikan akses ke S3 dan izin lambda:InvokeFunction.

Opsi A: SALAH. Terlalu permissive dan tidak mengikuti service-specific trust.
Opsi B: SALAH. Salah karena Lambda tidak perlu assume role ini — Redshift yang memanggil Lambda menggunakan role Redshift sendiri — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi C: BENAR.
Opsi D: SALAH. Salah karena S3 tidak assume role.

A data engineer needs to provide an EMR cluster with access to Amazon DynamoDB for a Hive-DynamoDB integration. The engineer creates an IAM role but the EMR cluster cannot access DynamoDB. The trust policy is configured for elasticmapreduce.amazonaws.com. What is the issue?
  • A. The trust policy should include both elasticmapreduce.amazonaws.com and dynamodb.amazonaws.com as principals
  • B. DynamoDB access requires a service-linked role that must be created separately
  • C. The EMR cluster must be launched in a VPC with a DynamoDB VPC endpoint before IAM permissions take effect and an EC2 instance profile role (for ec2
  • D. EMR requires two separate roles — a service role (for elasticmapreduce.amazonaws.com) and an EC2 instance profile role (for ec2.amazonaws.com). The DynamoDB permissions should be on the instance profile role.
Jawaban Benar: D
EMR menggunakan dua IAM roles: (1) EMR Service Role — trusted oleh elasticmapreduce.amazonaws.com — untuk provisioning dan managing cluster resources. (2) EC2 Instance Profile Role — trusted oleh ec2.amazonaws.com — digunakan oleh EC2 instances dalam cluster untuk mengakses AWS services seperti S3, DynamoDB, dll. Hive/Spark jobs running pada EC2 instances menggunakan instance profile role, jadi DynamoDB permissions harus ada di role tersebut.

Opsi A: SALAH. Salah — DynamoDB tidak assume role.
Opsi B: SALAH. Salah — DynamoDB tidak memerlukan service-linked role untuk access.
Opsi C: SALAH. Salah — VPC endpoint tidak diperlukan untuk permission (meskipun membantu routing).
Opsi D: BENAR.

A company needs to access Amazon SageMaker, AWS Glue, and Amazon Athena from within a VPC without traversing the public internet. The data engineer evaluates endpoint options. Which statement correctly describes the differences between Gateway Endpoints and Interface Endpoints?
  • A. Gateway Endpoints require security groups for access control. Interface Endpoints use route table entries and VPC endpoint policies only.
  • B. Gateway Endpoints use ENIs and support all AWS services. Interface Endpoints use route tables and only support S3 and DynamoDB.
  • C. Gateway Endpoints support S3 and DynamoDB only, are free, and use route table entries. Interface Endpoints support most AWS services, incur hourly and data processing charges, and use private IP addresses via ENIs.
  • D. Both endpoint types are functionally identical but Gateway Endpoints have higher throughput limits than Interface Endpoints. and DynamoDB only, are free, and use route table entries
Jawaban Benar: C
Gateway Endpoints hanya tersedia untuk S3 dan DynamoDB, gratis, dan bekerja melalui route table entries — traffic diarahkan melalui gateway tanpa ENI. Interface Endpoints (powered by AWS PrivateLink) mendukung sebagian besar AWS services (termasuk SageMaker, Glue, Athena), menggunakan ENI dengan private IP di subnet, dan memiliki biaya per jam plus data processing. Interface Endpoints juga memerlukan security group pada ENI untuk access control.

Opsi A: SALAH. Salah — Gateway Endpoints tidak memerlukan security group, dan Interface Endpoints yang memerlukan security group.
Opsi B: SALAH. Membalikkan definisi keduanya.
Opsi C: BENAR.
Opsi D: SALAH. Salah — keduanya berbeda secara fundamental dalam arsitektur — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
6
A data engineer attempts to configure role chaining where an AWS Glue job assumes Role A, which then assumes Role B to access resources in a different account. The role chaining fails with an AccessDenied error. All IAM policies and trust policies appear correct. What is the MOST likely limitation causing this failure?
  • A. Role chaining is limited to a maximum of 2 roles in a single chain
  • B. Role chaining has a maximum session duration of 1 hour regardless of the individual role's maximum session duration settings
  • C. AWS Glue does not support role chaining — it can only use the directly assigned IAM role configured for optimal performance and minimal operational overhead
  • D. The intermediate Role A must have sts:AssumeRole permission and its trust policy must allow the Glue service role as a principal, which is often missed
Jawaban Benar: B
Role chaining di AWS memiliki limitasi penting: session duration maximum dibatasi 1 jam (3600 detik) terlepas dari MaxSessionDuration yang dikonfigurasi pada role individual. Jika Glue job berjalan lebih dari 1 jam, temporary credentials dari role chain akan expire dan menyebabkan AccessDenied. Ini adalah limitasi yang sering tidak diketahui.

Opsi A: SALAH. Salah — AWS mengizinkan chaining lebih dari 2 roles.
Opsi B: BENAR.
Opsi C: SALAH. Salah — Glue dapat melakukan role chaining melalui boto3 STS calls dalam job script — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi D: SALAH. Bisa jadi masalah tapi soal menyebutkan "all policies appear correct" — limitasi 1 jam session duration adalah penyebab paling umum yang terlewat.

A company wants to share data in their S3 data lake with a partner organization (Account 222222222222). The data engineer in the source account (111111111111) creates a cross-account IAM role. The partner needs to access specific prefixes in the bucket only during business hours (8 AM - 6 PM UTC). Which IAM configuration meets these requirements?
  • A. Create a Lambda function that generates pre-signed URLs only during business hours and share the function endpoint
  • B. Create role with trust policy allowing Account 222222222222 to assume role, with permission policy granting s3:GetObject on specific prefixes, and a Condition block using aws:CurrentTime for time restriction
  • C. Create an IAM user in Account 111111111111 for the partner with time-based MFA requirement
  • D. Use S3 Access Points with a bucket policy that restricts access to business hours only for time restriction
Jawaban Benar: B
Cross-account IAM role dengan: (1) Trust policy yang mengizinkan Account 222222222222 sebagai Principal untuk AssumeRole. (2) Permission policy dengan s3:GetObject pada resource ARN spesifik (arn:aws:s3:::bucket/prefix/*). (3) Condition menggunakan "aws:CurrentTime" dengan StringGreaterThanEquals dan StringLessThanEquals untuk membatasi waktu akses. Ini memenuhi semua requirement secara native IAM.

Opsi A: SALAH. Tidak scalable dan sulit di-audit.
Opsi B: BENAR.
Opsi C: SALAH. Melanggar best practice — selalu gunakan roles untuk cross-account access.
Opsi D: SALAH. Bagus untuk access management tapi tidak memiliki native time-based condition — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.

A data engineer is designing IAM policies for a new data platform. Multiple AWS services are used: Glue for ETL, Redshift for warehousing, and Athena for ad-hoc queries. The engineer wants to understand how IAM evaluates policies when a request is made. A user has an explicit Allow in their IAM group policy but an explicit Deny in an S3 bucket policy. What is the result when the user tries to access the S3 object?
  • A. Access is allowed because resource-based policies and identity-based policies are evaluated independently, and one Allow is sufficient
  • B. Access depends on which policy was created most recently configured for optimal performance and minimal operational overhead
  • C. Access is allowed because identity-based policies (IAM group) take precedence over resource-based policies (bucket policy)
  • D. Access is denied because an explicit Deny in any policy always overrides an Allow in any other policy
Jawaban Benar: D
IAM policy evaluation logic mengikuti aturan: Explicit Deny selalu menang. Urutan evaluasi: (1) Jika ada explicit Deny di policy manapun → DENY. (2) Jika ada explicit Allow → ALLOW. (3) Jika tidak ada explicit Allow → implicit DENY. Karena ada explicit Deny di bucket policy, akses akan ditolak meskipun IAM group policy mengizinkan. Ini berlaku terlepas dari jenis policy (identity-based, resource-based, SCP, permission boundary).

Opsi A: SALAH. Salah — ini hanya berlaku untuk cross-account access dimana kedua sisi harus Allow.
Opsi B: SALAH. Salah — waktu pembuatan tidak mempengaruhi evaluasi — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi C: SALAH. Salah — tidak ada hirarki prioritas antara identity dan resource-based policies untuk Deny.
Opsi D: BENAR.

A data engineer discovers that the AWS Glue service-linked role (AWSServiceRoleForGlue) does not have sufficient permissions for a specific use case — the Glue crawler needs to access a KMS-encrypted S3 bucket with a customer-managed key. What should the engineer do?
  • A. Service-linked roles cannot be modified. Instead, add the Glue service-linked role's ARN to the KMS key policy as an authorized principal.
  • B. Delete the service-linked role and recreate it with additional KMS permissions in the trust policy
  • C. Create a custom IAM role for the Glue crawler with both the required S3 and KMS permissions, and use that instead of the service-linked role
  • D. Modify the AWSServiceRoleForGlue by attaching an additional IAM policy with KMS decrypt permissions configured for optimal performance and minimal operational overhead
Jawaban Benar: A
Service-linked roles adalah pre-defined oleh AWS dan tidak bisa dimodifikasi — Anda tidak bisa menambah atau mengubah permission policies-nya. Untuk KMS customer-managed keys, solusinya adalah menambahkan ARN service-linked role ke KMS key policy sebagai authorized principal untuk kms:Decrypt dan kms:GenerateDataKey. KMS key policy memberikan akses dari sisi resource.

Opsi A: BENAR.
Opsi B: SALAH. Salah — service-linked roles tidak bisa di-custom saat creation.
Opsi C: SALAH. Bisa bekerja tetapi bukan solusi yang tepat jika Anda sudah menggunakan service-linked role dan hanya perlu akses KMS — lebih baik update KMS key policy.
Opsi D: SALAH. Salah — service-linked roles tidak bisa dimodifikasi — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.

A company deploys a data pipeline where Account A runs Glue jobs that write to an S3 bucket in Account B, and an EMR cluster in Account C reads from that bucket. The data engineer needs to set up IAM roles to enable this cross-account data flow. Which configuration correctly enables this three-account access pattern?
  • A. Grant Account A and Account C full administrator access to Account B using AWS Organizations trusted access
  • B. Account B bucket policy allows Account A Glue role to PutObject and Account C EMR role to GetObject. Account A has Glue role with s3:PutObject permission. Account C EMR instance profile has s3:GetObject permission.
  • C. Create a single cross-account role in Account B that both Account A and Account C assume to access the bucket
  • D. Use S3 replication to copy data from Account A to Account C, avoiding cross-account access entirely with s3:PutObject permission and Account C EMR role to GetObject
Jawaban Benar: B
Untuk cross-account S3 access, diperlukan permission di kedua sisi: (1) Identity-based policy di source account (IAM role permission) — Account A Glue role perlu s3:PutObject, Account C EMR role perlu s3:GetObject. (2) Resource-based policy di destination account (S3 bucket policy) — explicitly allow Account A's Glue role ARN untuk PutObject dan Account C's EMR role ARN untuk GetObject. Ini mengikuti principle of least privilege.

Opsi A: SALAH. Sangat tidak aman dan melanggar least privilege.
Opsi B: BENAR.
Opsi C: SALAH. Kurang secure — kedua account mendapat permissions yang sama.
Opsi D: SALAH. Menambah biaya dan complexity — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
