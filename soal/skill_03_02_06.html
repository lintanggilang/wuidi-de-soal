A data engineer needs to calculate a 7-day rolling average of daily revenue in Amazon Redshift. The query should include the current day and the 6 preceding days. For days with fewer than 7 data points (first 6 days of the dataset), the average should still be calculated using available data. Which SQL window function clause correctly implements this?
  • A. AVG(revenue) OVER (ORDER BY date ROWS BETWEEN 6 PRECEDING AND CURRENT ROW)
  • B. AVG(revenue) OVER (ORDER BY date ROWS BETWEEN 7 PRECEDING AND 1 PRECEDING)
  • C. AVG(revenue) OVER (ORDER BY date RANGE BETWEEN INTERVAL '7 days' PRECEDING AND CURRENT ROW)
  • D. SUM(revenue) OVER (ORDER BY date ROWS BETWEEN 6 PRECEDING AND CURRENT ROW) / 7
Jawaban Benar: A
AVG() dengan ROWS BETWEEN 6 PRECEDING AND CURRENT ROW menghitung rata-rata dari maximum 7 rows (6 sebelumnya + current). AVG() secara otomatis membagi dengan jumlah rows yang ada dalam window, jadi untuk 6 hari pertama akan menggunakan jumlah data yang tersedia. Opsi B mengecualikan current row. Opsi C menggunakan RANGE yang di Redshift memiliki behavior berbeda dengan ROWS untuk date types. Opsi D (SUM/7) selalu membagi dengan 7 meskipun kurang dari 7 data points tersedia, menghasilkan rata-rata yang salah untuk hari-hari pertama.

A data analyst needs to create a report showing total sales by product category for each quarter, with an additional row showing the grand total across all categories and all quarters. The report also needs subtotals per quarter. Which SQL clause in Amazon Redshift provides this multi-level aggregation in a single query?
  • A. GROUP BY category, quarter with UNION ALL to add subtotals and grand total
  • B. GROUP BY ROLLUP(quarter, category)
  • C. GROUP BY CUBE(quarter, category)
  • D. GROUP BY GROUPING SETS((quarter, category), (quarter), ())
Jawaban Benar: D
GROUPING SETS memberikan kontrol eksplisit atas level agregasi yang diinginkan. (quarter, category) memberikan detail per quarter per category, (quarter) memberikan subtotal per quarter, dan () memberikan grand total. Ini persis memenuhi requirement. Opsi A memerlukan multiple passes dan UNION yang kurang efisien. Opsi B (ROLLUP) akan menghasilkan subtotals hierarchical dari kanan: (quarter, category), (quarter), () yang sebenarnya juga benar dalam kasus ini - namun GROUPING SETS lebih eksplisit. Opsi C (CUBE) menghasilkan semua kemungkinan kombinasi termasuk (category) alone yang tidak diminta.

A data engineer has a table with columns: date, product, region, and sales_amount. The business team wants a pivot table showing products as rows, regions as columns, with total sales as values. The query runs in Amazon Redshift. Which approach correctly creates this pivot?
  • A. Use PIVOT clause: SELECT * FROM sales_table PIVOT (SUM(sales_amount) FOR region IN ('East', 'West', 'North', 'South'))
  • B. Use conditional aggregation: SELECT product, SUM(CASE WHEN region='East' THEN sales_amount END) as East, SUM(CASE WHEN region='West' THEN sales_amount END) as West, ... GROUP BY product
  • C. Use CROSSTAB function from the tablefunc extension
  • D. Use UNPIVOT to reshape and then GROUP BY
Jawaban Benar: B
Conditional aggregation dengan CASE WHEN adalah teknik pivot yang paling reliable dan widely supported di Amazon Redshift. Setiap kolom output didefinisikan sebagai aggregate dengan CASE yang memfilter region tertentu. Opsi A (PIVOT clause) tersedia di beberapa database (SQL Server, Oracle) dan Redshift baru saja menambahkan dukungannya, namun conditional aggregation tetap menjadi pendekatan paling portable dan well-understood. Opsi C (CROSSTAB) bukan fitur Redshift. Opsi D (UNPIVOT then GROUP BY) melakukan kebalikan dari yang diminta.

A data engineer is building a real-time dashboard that shows approximate unique visitor counts per page for the last hour. The dataset has billions of events and exact COUNT(DISTINCT visitor_id) is too slow. The acceptable error margin is 2%. Which Redshift function provides the BEST performance-accuracy tradeoff?
  • A. COUNT(DISTINCT visitor_id) with a LIMIT clause to sample data
  • B. APPROXIMATE COUNT(DISTINCT visitor_id) which uses HyperLogLog algorithm
  • C. COUNT(visitor_id) / AVG(frequency) as an estimation technique
  • D. Use a pre-computed materialized view with exact COUNT(DISTINCT)
Jawaban Benar: B
APPROXIMATE COUNT(DISTINCT) di Redshift menggunakan HyperLogLog algorithm yang memberikan estimasi cardinality dengan error rate sekitar 2% sambil jauh lebih cepat dari exact count distinct. Ini ideal untuk dashboard real-time dimana speed lebih penting dari exact precision. Opsi A (LIMIT) memberikan estimasi yang tidak akurat dan tidak representative. Opsi C bukan teknik statistik yang valid. Opsi D (materialized view) memerlukan refresh time dan storage, serta still slow to compute initially.

A data engineer is using PySpark on Amazon EMR to process IoT sensor data. Each record has a timestamp and a sensor_value. The engineer needs to compute a 1-hour rolling average grouped by sensor_id, handling late-arriving data with watermarks. Which PySpark approach correctly implements this?
  • A. df.groupBy("sensor_id").agg(avg("sensor_value")) with a filter on timestamp
  • B. df.groupBy(window(col("timestamp"), "1 hour"), col("sensor_id")).agg(avg("sensor_value"))
  • C. df.withColumn("rolling_avg", avg("sensor_value").over(Window.partitionBy("sensor_id").orderBy("timestamp").rangeBetween(-3600, 0)))
  • D. df.groupBy("sensor_id", "hour").pivot("hour").agg(avg("sensor_value"))
Jawaban Benar: C
Window function dengan rangeBetween(-3600, 0) pada kolom timestamp (dalam detik) menghitung rolling average 1 jam untuk setiap row, looking back 3600 seconds dari current row. partitionBy("sensor_id") memastikan kalkulasi per sensor. Ini memberikan true rolling average bukan tumbling window. Opsi A hanya memberikan overall average, bukan rolling. Opsi B menggunakan tumbling window (fixed 1-hour windows) bukan rolling window. Opsi D (pivot) mengubah shape data, bukan menghitung rolling average.

A data analyst is querying a time-series table in Amazon Athena. The table has columns: event_timestamp, user_id, and event_type. The analyst needs to aggregate events into 15-minute buckets showing the count of each event type per bucket. Which Athena SQL function is MOST appropriate for creating the time buckets?
  • A. DATE_TRUNC('minute', event_timestamp) with additional modulo arithmetic for 15-minute alignment
  • B. date_trunc('hour', event_timestamp) + (minute(event_timestamp) / 15) * interval '15' minute
  • C. FROM_UNIXTIME(FLOOR(TO_UNIXTIME(event_timestamp) / 900) * 900) to create 15-minute aligned buckets
  • D. EXTRACT(HOUR FROM event_timestamp) || ':' || LPAD(CAST(FLOOR(EXTRACT(MINUTE FROM event_timestamp)/15)*15 AS VARCHAR), 2, '0')
Jawaban Benar: C
Mengkonversi timestamp ke unix time (seconds), membagi dengan 900 (15 menit × 60 detik), floor untuk rounding down, lalu kali kembali 900 dan konversi ke timestamp. Ini memberikan 15-minute aligned buckets yang akurat. Digunakan dengan GROUP BY untuk aggregation. Opsi A (DATE_TRUNC minute) hanya truncate ke menit, memerlukan logic tambahan yang rumit. Opsi B secara konseptual benar tapi syntax integer division di Athena (Presto) memerlukan CAST yang membuat kurang clean. Opsi D menghasilkan string bukan timestamp, kehilangan temporal ordering.
7
A data engineer has a table with NULL values in the quantity column. When computing SUM(quantity) grouped by category, some categories have all NULL quantities. The business requirement is: categories with all-NULL quantities should show 0 in the report, not NULL. Which approach correctly handles this in Amazon Redshift?
  • A. SELECT category, SUM(quantity) FROM table GROUP BY category
  • B. SELECT category, COALESCE(SUM(quantity), 0) FROM table GROUP BY category
  • C. SELECT category, SUM(COALESCE(quantity, 0)) FROM table GROUP BY category
  • D. SELECT category, NVL(SUM(quantity), 0) FROM table GROUP BY category
Jawaban Benar: B
COALESCE(SUM(quantity), 0) menangani kasus dimana SUM() mengembalikan NULL (ketika semua values dalam group adalah NULL). SUM() di SQL mengabaikan NULLs, dan jika SEMUA values adalah NULL, hasilnya NULL. COALESCE mengkonversi NULL final menjadi 0. Opsi A akan menampilkan NULL untuk all-NULL categories. Opsi C (COALESCE inside SUM) mengubah setiap NULL menjadi 0 sebelum SUM - ini menghasilkan 0 juga tapi mengubah semantics karena NULLs yang seharusnya diabaikan malah dihitung sebagai 0. Opsi D (NVL) equivalent dengan COALESCE di Redshift dan juga benar - namun COALESCE lebih standar SQL.

A data engineer needs to transform a narrow table (sensor_id, metric_name, metric_value) into a wide format where each unique metric_name becomes its own column. The table has 50 different metric names. This operation needs to be performed in Amazon Athena. What is the challenge and recommended approach?
  • A. Use PIVOT clause in Athena which supports dynamic column generation
  • B. Use conditional aggregation with MAX(CASE WHEN metric_name = 'temperature' THEN metric_value END) for each of the 50 metrics, grouped by sensor_id
  • C. Use the UNPIVOT function to reshape the data
  • D. Create 50 separate queries and UNION ALL the results
Jawaban Benar: B
Conditional aggregation (MAX/MIN with CASE WHEN) adalah teknik standar untuk pivoting di Athena (Trino/Presto). Setiap metric_name menjadi satu CASE expression. Tantangannya adalah 50 kolom membuat query panjang tapi tetap efisien karena single table scan. MAX digunakan karena setiap sensor_id + metric_name combination hanya memiliki satu value. Opsi A salah karena Athena (Trino) tidak memiliki PIVOT clause native dengan dynamic columns. Opsi C (UNPIVOT) melakukan kebalikan - wide ke narrow. Opsi D (50 UNION ALL) sangat tidak efisien dan menghasilkan narrow format, bukan wide.

A data engineer needs to compute year-over-year growth percentage for monthly revenue in Amazon Redshift. The table has columns: month_date and revenue. The result should show each month alongside its year-over-year growth rate. Which SQL approach is MOST efficient?
  • A. Self-join the table on month number where the left table's year is one more than the right table's year
  • B. Use LAG(revenue, 12) OVER (ORDER BY month_date) to get the same month from previous year, then calculate percentage change
  • C. Use a correlated subquery that finds revenue for the same month in the previous year
  • D. Create two CTEs (current year and previous year) and join them on month number
Jawaban Benar: B
LAG(revenue, 12) OVER (ORDER BY month_date) efisien karena mengakses row 12 posisi sebelumnya (12 bulan = 1 tahun) dalam single pass. Kemudian (revenue - LAG(revenue,12)) / LAG(revenue,12) * 100 memberikan growth percentage. Window functions di Redshift sangat optimized. Opsi A (self-join) memerlukan full table scan dua kali. Opsi C (correlated subquery) sangat tidak efisien untuk large tables. Opsi D (CTEs + join) lebih verbose dan kurang efisien dibanding single window function pass.

A data engineer is using PySpark on EMR to process a large dataset of e-commerce transactions. They need to compute: (1) total revenue per customer, (2) average order value per customer, (3) number of unique products purchased per customer, and (4) days since last purchase per customer. All aggregations should be computed in a single pass over the data. Which PySpark approach is MOST efficient?
  • A. Run four separate groupBy operations and join the results on customer_id
  • B. Use df.groupBy("customer_id").agg(sum("revenue"), avg("order_value"), countDistinct("product_id"), datediff(current_date(), max("purchase_date")))
  • C. Convert to pandas DataFrame and use pandas groupby with multiple aggregation functions
  • D. Use a window function with PARTITION BY customer_id for each metric separately
Jawaban Benar: B
PySpark groupBy().agg() dengan multiple aggregate functions menghitung semua metrik dalam single shuffle operation. sum(), avg(), countDistinct(), dan max() semua dikomputasi dalam satu pass setelah groupBy. datediff dengan max(purchase_date) memberikan days since last purchase. Ini paling efisien karena hanya satu shuffle. Opsi A (4 separate groupBy) menghasilkan 4 shuffle operations dan 3 joins tambahan. Opsi C (pandas) akan gagal pada large datasets karena memory constraints. Opsi D (window functions) tidak mengagregasi rows, hanya menambah kolom ke setiap row.
