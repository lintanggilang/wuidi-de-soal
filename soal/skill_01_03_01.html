A data engineering team needs to orchestrate a complex ETL workflow with the following requirements: 20+ steps, conditional branching based on data quality checks, parallel execution of independent steps, and retry logic with exponential backoff. The team prefers infrastructure-as-code definition. Which orchestration service is MOST appropriate?
  • A. AWS Step Functions with Amazon States Language (ASL) defined in CloudFormation/CDK
  • B. AWS Glue Workflows with triggers configured for optimal performance and minimal operational overhead
  • C. EventBridge rules chained together
  • D. A single Lambda function with internal branching logic
Jawaban Benar: A
Step Functions mendukung semua requirements: complex workflows (up to 25,000 events), Choice states for conditional branching, Parallel states for concurrent execution, built-in retry with exponential backoff, dan ASL definition yang bisa di-define di CloudFormation/CDK. Opsi B (Glue Workflows) lebih limited dalam conditional logic dan hanya untuk Glue jobs/crawlers — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini. Opsi C (EventBridge chaining) tidak memiliki native branching atau parallel state management. Opsi D (single Lambda) batas 15 menit dan anti-pattern untuk complex workflows.
2
A company has an ETL pipeline that: (1) extracts data from 5 databases, (2) transforms each dataset independently, (3) joins all transformed datasets, (4) loads to Redshift. Steps 1-2 can run in parallel for each database, but step 3 must wait for ALL to complete. Which Step Functions pattern implements this?
  • A. Use a Parallel state with 5 branches (one per database), each containing extraction and transformation steps. After the Parallel state completes (all branches done), execute the join and load steps sequentially
  • B. Use a Map state iterating over 5 database configurations
  • C. Chain 5 sequential extraction tasks followed by 5 sequential transformations
  • D. Use 5 separate state machines triggered simultaneously with 5 branches (one per database) and transformation steps
Jawaban Benar: A
Parallel state runs all branches concurrently dan waits for ALL branches to complete before proceeding (fan-out/fan-in). Each branch handles one database (extract → transform). After Parallel completes, the next states (join → load) execute knowing all data is ready. This is exactly the fan-in pattern needed. Opsi B (Map) valid alternative tapi Parallel lebih explicit untuk fixed known branches. Opsi C (sequential) wastes time — 5x slower. Opsi D (separate state machines) membutuhkan external coordination for fan-in — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
3
A data pipeline uses Amazon MWAA (Apache Airflow) for orchestration. The DAG has a task that calls an AWS Glue job. The Glue job takes 45 minutes to complete. How should the Airflow task be configured to wait for the Glue job to finish without consuming Airflow worker resources during the wait?
  • A. Use the GlueJobOperator with a deferrable (async) mode or AwsGlueJobSensor in deferrable mode that uses asyncio to wait without occupying a worker slot
  • B. Use a BashOperator with a while loop checking job status configured for optimal performance and minimal operational overhead
  • C. Set the task timeout to 60 minutes and use synchronous GlueJobOperator
  • D. Use a PythonOperator with time.sleep() polling
Jawaban Benar: A
Deferrable operators (introduced in Airflow 2.2+) release the worker slot while waiting for external jobs. The task is deferred to a triggerer that uses asyncio — no worker blocked. When Glue job completes, triggerer resumes the task. This is essential for long-running external jobs to avoid worker starvation. Opsi B (BashOperator while loop) blocks a worker for 45 minutes — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini. Opsi C (synchronous) also blocks a worker slot. Opsi D (sleep polling) same blocking issue and wastes resources.
4
A data engineer needs to orchestrate a simple 3-step pipeline: (1) trigger a Glue crawler, (2) wait for crawler to finish, (3) start a Glue ETL job. This runs daily. The team wants the LEAST operational overhead. Which orchestration approach is SIMPLEST?
  • A. AWS Glue Workflow with a scheduled trigger starting the crawler, and a conditional trigger starting the ETL job upon crawler success
  • B. Amazon MWAA DAG with GlueCrawlerOperator and GlueJobOperator
  • C. AWS Step Functions state machine with Glue API calls configured for optimal performance and minimal operational overhead
  • D. EventBridge scheduled rule triggering Lambda that manages both steps
Jawaban Benar: A
Glue Workflow adalah solusi paling sederhana untuk orchestrating Glue-native resources (crawlers + ETL jobs). Zero additional infrastructure — fully integrated dalam Glue console. Scheduled trigger → crawler → conditional trigger (on success) → ETL job. Minimal operational overhead. Opsi B (MWAA) requires managing Airflow environment — overkill untuk 3 steps. Opsi C (Step Functions) valid tapi requires defining ASL and Lambda functions — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini. Opsi D (Lambda) requires custom code for polling crawler status.
5
A data pipeline orchestrated by Step Functions needs to process 10,000 files. Each file requires the same transformation logic. The processing of each file is independent. Which Step Functions state type enables dynamic parallel processing of all files?
  • A. Map state in Distributed mode with MaxConcurrency set to control parallelism, iterating over the list of files
  • B. Parallel state with 10,000 branches with parallel processing and horizontal scaling capabilities
  • C. Choice state routing each file to different processors
  • D. Task state with a loop using Wait state
Jawaban Benar: A
Map state (Distributed mode) iterates over an array (file list) dan executes the same steps for each item. Distributed Map supports up to 10,000 concurrent executions and can process millions of items. MaxConcurrency controls parallelism. Perfect for processing independent items with same logic. Opsi B (Parallel 10,000 branches) — Parallel state has limit of ~50 branches and is for fixed, different branches — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini. Opsi C (Choice) for conditional routing, not iteration. Opsi D (loop) sequential processing, very slow.
6
A data engineering team manages 100+ DAGs in Amazon MWAA. Several DAGs have cross-DAG dependencies (DAG B should only run after DAG A completes successfully). How should these inter-DAG dependencies be implemented in MWAA?
  • A. Use the ExternalTaskSensor in DAG B to wait for a specific task completion in DAG A, or use TriggerDagRunOperator in DAG A to trigger DAG B upon completion
  • B. Combine all dependent DAGs into a single large DAG
  • C. Use cron schedules ensuring DAG B starts after DAG A's estimated completion time
  • D. Use Airflow variables to communicate state between DAGs for a specific task completion in DAG
Jawaban Benar: A
ExternalTaskSensor waits (polls/defers) until a task in another DAG reaches a successful state for the same execution_date. TriggerDagRunOperator explicitly triggers another DAG, creating a clear dependency chain. Both are Airflow-native patterns for inter-DAG dependencies. Opsi B (merge DAGs) creates unmaintainable mega-DAGs. Opsi C (time-based) fragile — if DAG A runs longer than estimated, DAG B starts with incomplete data. Opsi D (variables) race-condition prone and not reliable for dependency management — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
7
A Step Functions workflow calls a Glue ETL job using the StartJobRun API. The workflow needs to wait for the Glue job to complete before proceeding to the next step. The Glue job takes 30 minutes. Which integration pattern should be used?
  • A. Use the .sync integration pattern (resource ARN ending with .sync) which automatically waits for the Glue job to complete before transitioning to the next state
  • B. Use a Wait state for 30 minutes after starting the job
  • C. Use a Lambda function in a loop to poll the Glue job status
  • D. Use the Request Response pattern and immediately proceed with .sync) which automatically waits for the Glue job
Jawaban Benar: A
Step Functions .sync integration pattern (Run a Job) memanggil service API dan secara otomatis menunggu job completion sebelum transition ke state berikutnya. Untuk Glue, ini berarti StartJobRun.sync akan wait sampai Glue job finishes (success/failure). Tidak perlu custom polling logic. Opsi B (Wait 30 min) — hardcoded wait tidak account for variable run times. Opsi C (Lambda polling) reinvents what .sync does natively. Opsi D (Request Response) returns immediately without waiting — workflow proceeds before job finishes — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
8
A data pipeline uses AWS Step Functions. When any step fails, the team needs to be notified via SNS and the failure details must be logged. Currently, each task state has its own Catch block with duplicate error handling logic. How should error handling be simplified?
  • A. Wrap all task states in a single Parallel state (with one branch) that has a Catch block, redirecting to a shared error-handling state that publishes to SNS and logs details
  • B. Keep individual Catch blocks on each state for granular control
  • C. Remove all error handling and rely on CloudWatch Alarms and logs details
  • D. Use Step Functions Express Workflows which have automatic error handling
Jawaban Benar: A
Wrapping states in a Parallel state (single branch) creates a "try-catch" block equivalent. Any failure in any enclosed state bubbles up to the Parallel's Catch block. The shared error state handles notification and logging once, eliminating duplication. Alternative: use EventBridge integration to capture state machine failure events. Opsi B (individual catches) has code duplication. Opsi C (no handling) loses context about which step failed — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini. Opsi D (Express Workflows) don't have automatic error handling — they have different execution model.

A company migrates from on-premises Airflow to Amazon MWAA. Their existing DAGs use KubernetesPodOperator to run tasks in containers. MWAA doesn't support KubernetesPodOperator natively. What is the RECOMMENDED alternative for running containerized tasks from MWAA?
  • A. Use the EcsRunTaskOperator to run containerized tasks on Amazon ECS (Fargate or EC2), replacing KubernetesPodOperator
  • B. Set up a separate EKS cluster and configure MWAA to use KubernetesPodOperator with it
  • C. Convert all containerized tasks to PythonOperator
  • D. Use BashOperator to run Docker commands on the MWAA worker configured for optimal performance and minimal operational overhead
Jawaban Benar: A
EcsRunTaskOperator is the recommended replacement for KubernetesPodOperator in MWAA. It runs containers as ECS tasks (Fargate = serverless). Container images stay the same, just the orchestration layer changes. ECS Fargate requires no cluster management. Opsi B (separate EKS) adds operational complexity — valid but more overhead than ECS. Opsi C (convert to PythonOperator) requires significant code refactoring and loses container isolation benefits. Opsi D (Docker on worker) — MWAA workers don't have Docker daemon access — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
10
A data engineer needs to orchestrate a workflow that: starts a Glue job, waits up to 1 hour for completion, and if the job hasn't finished, sends an alert and continues waiting. The total workflow might run for up to 3 hours. Which Step Functions workflow type should be used and why?
  • A. Standard Workflow — supports executions up to 1 year, .sync integrations for waiting on external jobs, and allows Wait states with timeout-based transitions
  • B. Express Workflow — for faster execution and lower cost with timeout-based transitions and allows Wait states with timeout-based transitions
  • C. Standard Workflow with a nested Express Workflow for the wait logic
  • D. Express Workflow with increased timeout setting
Jawaban Benar: A
Standard Workflows support long-running executions (up to 1 year). The .sync pattern waits for Glue completion. Wait state with Seconds or Timestamp combined with Choice state can implement "send alert after 1 hour if not done, continue waiting." Standard supports exactly-once execution semantics. Opsi B (Express) has 5-minute maximum duration — far too short for 3-hour workflow — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini. Opsi C unnecessary complexity. Opsi D (Express timeout) cannot exceed 5 minutes regardless of configuration.
