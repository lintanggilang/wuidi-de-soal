A data engineer needs to process messages from an Amazon SQS queue using AWS Lambda. Each message contains a reference to a file in S3 that needs to be transformed. During peak hours, the queue depth reaches 100,000 messages. The Lambda function takes 30 seconds per message. The team wants to process the backlog as quickly as possible without exceeding 100 concurrent Lambda invocations. Which configuration achieves this?
  • A. Set the SQS visibility timeout to 30 seconds and use provisioned concurrency of 100, satisfying all of the stated requirements with minimal effort
  • B. Configure the SQS queue with a redrive policy and set Lambda timeout to 5 minutes and maximum concurrency of 100 on the event source mapping
  • C. Configure the SQS event source mapping with a batch size of 10 and maximum concurrency of 100 on the event source mapping
  • D. Configure the SQS event source mapping with a batch size of 1 and set the Lambda function's reserved concurrency to 100
Correct Answer: C
Event source mapping maximum concurrency (feature that more new) directly limits number concurrent Lambda invocations that is triggered by SQS, provides kontrol that presisi. Batch size 10 processes more messages per invocation, speeds up processing.

Option A: INCORRECT. Reduces cold starts but not limits total concurrent invocations — reserved concurrency that limits.
Option B: INCORRECT. Not mengontrol concurrency — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option C: CORRECT.
Option D: INCORRECT. Membatasi function in a global but can menyebabkan throttling and message returns to queue if exceeded.

A data pipeline uses Lambda to process records from a Kinesis Data Stream. When the Lambda function encounters a malformed record, it throws an error causing the entire batch to be retried repeatedly, blocking subsequent records in the shard. Which Lambda event source mapping configuration BEST handles this poison pill scenario?
  • A. Set the Kinesis stream retention period to 24 hours so failed records expire automatically configured for optimal performance and minimal operational overhead
  • B. Configure the Lambda function's dead-letter queue (async invocation DLQ) for failed events, meeting the latency and throughput goals of the design
  • C. Configure bisect on function error, maximum retry attempts, and an on-failure destination (SQS dead-letter queue) on the event source mapping
  • D. Add try/catch in the Lambda code to skip all errors silently, satisfying all of the stated requirements with minimal effort
Correct Answer: C
For Kinesis event source mappings, "bisect on function error" memecah batch menjadi dua if occurs error, in a progresif mengisolasi record that bermasalah. "Maximum retry attempts" limits berapa kali record diretryi. "On-failure destination" sends failed record to SQS DLQ setelah retry limit is reached, enables processing melanjutkan to record berikutnya.

Option A: INCORRECT. Berarti waits 24 hours — unacceptable delay — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option B: INCORRECT. Not applies for stream-based invocations (Kinesis) that synchronous — DLQ on function only for async invocations.
Option C: CORRECT.
Option D: INCORRECT. Kehilangan visibility to problem data.

Multiple Lambda functions in a data pipeline share common dependencies: a custom data validation library (50 MB), pandas (80 MB), and database connection utilities. Each function is deployed independently. The team wants to reduce deployment package sizes and centralize dependency management. Which Lambda feature is MOST appropriate?
  • A. Store dependencies in Amazon EFS and mount the filesystem in each Lambda function configured for optimal performance and minimal operational overhead
  • B. Use container images for Lambda with a shared base image containing all dependencies, handling the described workload reliably at scale
  • C. Package all functions into a single monolithic deployment with all dependencies included, handling the described workload reliably at scale
  • D. Create Lambda layers containing the shared libraries and attach them to each function, updating the layer version when dependencies change
Correct Answer: D
Lambda layers enables packaging shared dependencies in a separate from function code. Layers can in-share between multiple functions and in-version independently. When dependency diupdate, only layer version new that in-publish and functions uses versi new. Ini reduces deployment package size (function code without dependencies) and centralize management.

Option A: INCORRECT. Adds latency cold start because mount operation and cost EFS that higher — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option B: INCORRECT. Viable but more overhead for sharing dependencies.
Option C: INCORRECT. Eliminates keuntungan microservices and memperbesar blast radius.
Option D: CORRECT.

When processing fails after all retries, the team needs to be notified and the failed event should be routed to a different Lambda function for error analysis. Which Lambda feature provides built-in support for this routing pattern?
  • A. Use CloudWatch Logs subscription filters to detect error patterns and trigger the analysis function
  • B. Wrap the function in a Step Functions state machine with a Catch block configured for optimal performance and minimal operational overhead
  • C. Configure Lambda destinations with an on-failure destination pointing to the error analysis Lambda function
  • D. Configure a dead-letter queue (DLQ) on the Lambda function pointing to an SQS queue consumed by the error analysis function
Correct Answer: C
Lambda destinations (feature async invocation) enables routing result invocation — baik success maupun failure — to target destinations such as Lambda function, SQS, SNS, or EventBridge. On-failure destination directly sends event payload beserta error details to Lambda other for analysis. Ini more rich dibanding DLQ because menyertakan response payload and metadata.

Option A: INCORRECT. Kompleks and has delay.
Option B: INCORRECT. Overhead that berlebihan for use case this — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option C: CORRECT.
Option D: INCORRECT. Can works but only sends original event without error context details and requires intermediate SQS queue.

AWS Lambda Power Tuning is open-source tool (Step Functions-based) that automatically runs function with berbagai memory configurations, mengukur execution time and cost for each, and produces visualization curve that menunjukkan sweet spot optimal. Ini data-driven and comprehensive.

The pipeline consists of 5 sequential steps: validation, enrichment, transformation, quality check, and loading. Each step has different error handling requirements and some steps can run in parallel. Which architecture provides the BEST orchestration for this multi-step Lambda pipeline?
  • A. Use SNS topics between each step with Lambda subscriptions and conditional branching for each step, applying schema conversion and enrichment inline
  • B. Use AWS Step Functions to orchestrate the Lambda functions with parallel states, error handling (Retry/Catch), and conditional branching for each step
  • C. Use a single Lambda function that calls the other functions synchronously using the invoke API, validating and cleansing each record before delivery
  • D. Chain Lambda functions using S3 event notifications — each step writes output to a different S3 prefix that triggers the next step

AWS Step Functions provides orchestration visual with: parallel states for steps that can run concurrently, Retry policies per step (configurable intervals, max attempts, backoff rate), Catch blocks for error handling specific per step, and conditional branching (Choice state). Ini provides full control and visibility atas multi-step pipeline.

Option A: INCORRECT. Bersifat fire-and-forget without orchestration state or error handling — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option B: CORRECT.
Option C: INCORRECT. Menghadapi Lambda timeout limit and single point of failure.
Option D: INCORRECT. Sulit in-debug, not has built-in retry, and not supports conditional logic.

The endpoint needs to: accept GET requests with query parameters, return JSON responses, require no authentication (public data), and handle up to 1000 requests per second. The team wants the simplest possible deployment without API Gateway. Which Lambda feature meets this requirement?

Lambda function URLs provides dedicated HTTPS endpoint directly for Lambda function without requires API Gateway or load balancer. By auth type NONE, endpoint menjadi public. Function URLs supports request/response streaming, built-in HTTPS, and CORS configuration. Ini is solution most simple for simple HTTP endpoints.

Option A: CORRECT.
Option B: INCORRECT. Bekerja but requirement specific menyebutkan "without API Gateway" — and function URL simpler for use case this — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
