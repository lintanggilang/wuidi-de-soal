1
A data engineer manages a data lake on Amazon S3 with 10 TB of event data stored in JSON format. Athena queries on this data are slow and expensive, scanning the entire dataset for most queries. The most common query pattern filters by event_date and event_type. Which combination of optimizations will provide the GREATEST reduction in query cost and execution time?
  • A. Convert data to Apache Parquet format with Snappy compression and partition by event_date and event_type
  • B. Add an S3 Lifecycle policy to compress old JSON files and increase Athena DPU allocation
  • C. Create Athena views that pre-filter data by event_date and use LIMIT clauses in all queries
  • D. Enable S3 Intelligent-Tiering and use Athena query result caching with Snappy compression and partition by event_date and event_type
Jawaban Benar: A
Kombinasi konversi ke Parquet (columnar format — hanya kolom yang diquery di-scan), Snappy compression (mengurangi ukuran data yang di-scan), dan partitioning by event_date dan event_type (Athena hanya membaca partisi yang relevan) memberikan pengurangan drastis pada data scanned. Parquet sendiri bisa mengurangi scan 90%+ untuk query yang hanya memerlukan beberapa kolom. Partitioning menghindari full table scan.

Opsi A: BENAR.
Opsi B: SALAH. Tetap memerlukan parsing seluruh file karena JSON row-based.
Opsi C: SALAH. Views tidak menyimpan data dan LIMIT berjalan setelah full scan.
Opsi D: SALAH. Tidak mengurangi scan size — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
2
A company has multiple business units using Amazon Athena. The finance team frequently runs expensive queries that consume most of the query capacity, impacting other teams. Management wants to: limit finance team spending to $500/month on Athena, track usage per team, and prevent any single query from scanning more than 100 GB. Which Athena feature addresses ALL these requirements?
  • A. Use IAM policies to restrict the tables each team can query and set billing alarms with per-query data scan limits for tracking
  • B. Create separate AWS accounts for each team with AWS Budgets alerts
  • C. Configure Athena workgroups — one per team — with per-query data scan limits and workgroup-level spending thresholds with CloudWatch metrics for tracking
  • D. Implement a Lambda-based query proxy that checks query cost estimates before execution
Jawaban Benar: C
Athena workgroups menyediakan: (1) per-query data usage control — membatasi maximum data yang boleh di-scan per query (100 GB limit), (2) workgroup-level data scan limits yang bisa dikonfigurasi per periode (equivalent spending control), (3) CloudWatch metrics per workgroup untuk tracking usage per team. Ini single feature yang memenuhi semua kebutuhan.

Opsi A: SALAH. Mengontrol akses tabel bukan spending — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi B: SALAH. Berlebihan dan menambah complexity.
Opsi C: BENAR.
Opsi D: SALAH. Memerlukan custom development dan tidak bisa akurat memperkirakan cost sebelum execution.
3
A data engineer needs to use Athena to create transformed datasets for downstream analytics. The requirement is to read raw data from the "events_raw" table, apply aggregations and filters, and write the results as a new Parquet table partitioned by date in a different S3 location. Which Athena feature accomplishes this as a single SQL operation?
  • A. Use CREATE TABLE AS SELECT (CTAS) with format='PARQUET', partitioned_by, and external_location properties
  • B. Use INSERT INTO with a pre-existing external table pointing to the new S3 location and external_location properties
  • C. Create a VIEW on the aggregated query and export it using Athena's export to S3 feature
  • D. Run a SELECT query and configure the workgroup's query results location to the target S3 path
Jawaban Benar: A
CTAS (CREATE TABLE AS SELECT) di Athena memungkinkan transformasi data dan pembuatan tabel baru dalam satu operasi SQL. Properties yang bisa dikonfigurasi termasuk: format (PARQUET, ORC, JSON, etc.), compression, partitioned_by columns, external_location untuk S3 path, dan bucketing. Ini ideal untuk ETL operations.

Opsi A: BENAR.
Opsi B: SALAH. Bisa digunakan tetapi memerlukan tabel sudah dibuat sebelumnya — bukan single operation — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi C: SALAH. Athena views tidak menyimpan data dan tidak ada native "export" feature.
Opsi D: SALAH. Menyimpan sebagai CSV query results, bukan partitioned Parquet table.
4
A data engineer has built an Athena-based reporting system where user-supplied parameters (date ranges, product IDs) are incorporated into SQL queries. The application constructs queries by string concatenation. A security review has flagged this as a SQL injection risk. Which Athena feature mitigates this vulnerability?
  • A. Implement input validation in the application layer using regex patterns with parameterized queries
  • B. Use Athena prepared statements with parameterized queries to safely bind user-supplied values
  • C. Use IAM policies to limit the SQL statements users can execute
  • D. Create Athena views that pre-filter data and restrict users to only query through views
Jawaban Benar: B
Athena prepared statements memungkinkan parameterized queries dimana user-supplied values di-bind sebagai parameter (menggunakan ?) dan tidak diinterpretasi sebagai SQL code. Ini adalah best practice keamanan standard untuk mencegah SQL injection.

Opsi A: SALAH. Adalah defense-in-depth yang baik tetapi rentan terhadap bypass dan tidak menyelesaikan root cause — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi B: BENAR.
Opsi C: SALAH. Mengontrol akses ke resources, bukan content dari SQL queries.
Opsi D: SALAH. Membatasi akses tetapi tidak menyelesaikan injection jika views menerima parameter.
5
A company has data distributed across multiple sources: a data lake in S3, operational data in Amazon RDS PostgreSQL, and reference data in Amazon DynamoDB. A data analyst needs to write a single Athena SQL query that joins data from all three sources. Which Athena capability enables this?
  • A. Export data from RDS and DynamoDB to S3 first, then query all data through standard Athena tables
  • B. Create Glue ETL jobs to replicate all data into a single Redshift cluster, then use Athena to query Redshift
  • C. Athena Federated Query using data source connectors for RDS and DynamoDB, allowing cross-source JOINs in a single query
  • D. Use Athena CTAS to materialize RDS and DynamoDB data into S3 tables before joining and DynamoDB, allowing cross-source JOINs in a single query
Jawaban Benar: C
Athena Federated Query memungkinkan eksekusi SQL queries terhadap berbagai data sources menggunakan Lambda-based data source connectors. Connectors tersedia untuk RDS (PostgreSQL, MySQL), DynamoDB, Redshift, CloudWatch Logs, dan lainnya. Ini memungkinkan JOIN lintas sumber dalam satu query tanpa memindahkan data.

Opsi A: SALAH. Dan C (export/materialize) memerlukan data movement dan tidak memberikan real-time access ke data terbaru.
Opsi B: SALAH. Berlebihan dan mahal untuk satu kebutuhan query.
Opsi C: BENAR.
Opsi D: SALAH. Meskipun terdengar meyakinkan, tetap tidak tepat untuk skenario ini.
6
A data analytics team runs the same expensive aggregation query multiple times per hour across different dashboards. The underlying data only updates once every 6 hours. Each execution scans 500 GB and costs approximately $2.50. The team wants to reduce costs without modifying the dashboards. Which Athena feature directly addresses this?
  • A. Create a materialized view in Athena that pre-computes the aggregation with appropriate max-age setting
  • B. Enable Athena query result reuse with appropriate max-age setting, so identical queries return cached results without re-scanning data
  • C. Schedule a Lambda function to run the query every 6 hours and store results in a separate S3 table
  • D. Increase the number of Athena DPUs to make queries run faster
Jawaban Benar: B
Athena query result reuse memungkinkan identical queries (same SQL) mengembalikan hasil yang sudah di-cache tanpa re-scanning data. Dengan max-age setting (misalnya 6 jam sesuai update frequency), queries berulang tidak dikenakan biaya scan tambahan. Ini transparan bagi dashboards — tidak perlu modifikasi.

Opsi A: SALAH. Salah karena Athena tidak mendukung materialized views (itu fitur Redshift) — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi B: BENAR.
Opsi C: SALAH. Memerlukan modifikasi dashboard untuk membaca dari tabel berbeda.
Opsi D: SALAH. Mempercepat execution tetapi tidak mengurangi biaya scan.
7
A data engineer manages a large Athena table with 5 years of historical data (50 TB total). Most queries only access the last 30 days of data. The table is partitioned by date. However, some queries still scan more data than expected because analysts forget to add partition filters. Which approach BEST prevents unnecessary full-table scans?
  • A. Split the table into "recent" and "archive" tables and only grant access to the recent table
  • B. Enable partition projection to make Athena automatically detect which partitions to scan with a WHERE clause limiting
  • C. Move data older than 30 days to S3 Glacier and only keep recent data accessible
  • D. Create an Athena view with a WHERE clause limiting to the last 30 days as the default access point, and configure workgroup per-query data scan limits as a safety net
Jawaban Benar: D
Athena views dengan built-in WHERE clause pada partition column memastikan bahwa queries melalui view hanya scan 30 hari data secara default. Workgroup per-query data scan limits memberikan safety net — jika query melebihi threshold (misalnya 1 TB), query akan dibatalkan. Kombinasi ini mencegah accidental full scans.

Opsi A: SALAH. Memerlukan maintenance dua tabel dan logic pemisahan.
Opsi B: SALAH. Membantu performance metadata lookup tetapi tidak mencegah user dari scanning semua partisi — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi C: SALAH. Membuat data historis tidak queryable jika diperlukan.
Opsi D: BENAR.
8
A data lake contains millions of small files (average 1 MB each) generated by IoT devices. Athena queries on this data are extremely slow despite the total data volume being only 100 GB. The data is already in Parquet format and properly partitioned. What is the PRIMARY cause and the BEST solution?
  • A. The small file problem causes excessive S3 LIST and GET operations — use Athena CTAS or AWS Glue to compact files into larger sizes (128 MB - 512 MB optimal range)
  • B. The partitioning scheme has too many partitions — reduce the number of partitions by using monthly instead of daily
  • C. Athena needs more compute resources — switch to Athena provisioned capacity for consistent performance
  • D. Parquet format is not efficient for small files — convert to ORC format which handles small files better with native S3 integration and optimized data transfer
Jawaban Benar: A
Small file problem adalah masalah umum di data lakes. Setiap file memerlukan overhead: S3 LIST operations untuk menemukan file, GET requests untuk membuka file, dan Parquet footer reading per file. Dengan jutaan file kecil, overhead ini mendominasi query time. Solusinya adalah compaction — menggabungkan file kecil menjadi file berukuran 128-512 MB yang optimal untuk Athena/Presto. CTAS atau Glue job dapat melakukan compaction ini.

Opsi A: BENAR.
Opsi B: SALAH. Tidak menyelesaikan masalah file per partition yang terlalu banyak.
Opsi C: SALAH. Membantu throughput tetapi overhead per-file tetap ada.
Opsi D: SALAH. Salah — ORC tidak menangani small files lebih baik dari Parquet — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
9
A data engineer needs to provide business analysts with a simplified view of a complex data lake schema. The raw tables have cryptic column names (col_a1, col_b2), contain technical columns not relevant to analysts, and require complex JOINs between multiple tables. Analysts should be able to query using business-friendly names without knowing the underlying table structure. Which Athena approach is MOST appropriate?
  • A. Create a Glue crawler to re-catalog the tables with new business-friendly column names
  • B. Use AWS Lake Formation to create virtual columns with business names on top of existing tables
  • C. Build a CTAS that creates a denormalized copy of all tables with renamed columns for analysts
  • D. Create Athena views with aliased column names (business-friendly names), pre-built JOINs, and only expose relevant columns to simplify the schema for analysts
Jawaban Benar: D
Athena views menyediakan abstraction layer yang ideal: column aliases memberikan business-friendly names, pre-built JOINs menyederhanakan access pattern, dan column selection menyembunyikan technical fields. Views tidak menyimpan data duplikat dan selalu reflect data terbaru.

Opsi A: SALAH. Akan mengubah metadata yang bisa memecah pipeline lain yang menggunakan nama kolom asli.
Opsi B: SALAH. Salah — Lake Formation tidak memiliki fitur "virtual columns" untuk renaming.
Opsi C: SALAH. Membuat duplikat data yang perlu di-refresh — mahal dan not real-time — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi D: BENAR.
10
A data engineer is optimizing Athena query performance for a 2 TB partitioned Parquet table. Queries that filter on non-partition columns (e.g., WHERE customer_segment = 'enterprise') still scan all files within the matching partitions. The table has 50 columns but most queries only access 5-10 columns. Which optimization technique provides the BEST improvement for this query pattern?
  • A. Increase the Parquet file size to 1 GB to reduce the number of files to open
  • B. Add customer_segment as an additional partition column to enable partition pruning
  • C. Convert the data to CSV format which supports faster full-file scanning with row group statistics
  • D. Ensure Parquet files are written with row group statistics and page-level column indexes enabled, allowing predicate pushdown to skip irrelevant row groups within files
Jawaban Benar: D
Parquet row group statistics (min/max values) dan page-level column indexes memungkinkan predicate pushdown — Athena (Presto/Trino) dapat skip row groups dimana filter condition (customer_segment = 'enterprise') tidak bisa dipenuhi berdasarkan statistics, tanpa membaca actual data. Ini signifikan mengurangi I/O untuk non-partition column filters.

Opsi A: SALAH. Mengurangi open operations tetapi tidak membantu filtering within files tanpa statistics.
Opsi B: SALAH. Bisa over-partition dan meningkatkan small file problem jika cardinality tinggi.
Opsi C: SALAH. Kehilangan semua keuntungan columnar format — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi D: BENAR.
