Skill 3.4.4: Describe Data Sampling Techniques

Statistical sampling methods for data quality assessment and testing at scale

1
A data engineer needs to estimate the data quality of a 10 TB dataset stored in S3 (Parquet format) containing 5 billion records. Running quality checks on the full dataset takes 4 hours and costs $50 in Athena query charges. The team wants to estimate quality metrics with 95% confidence and ±1% margin of error. Which sampling approach is MOST cost-effective while meeting the statistical requirements?
  • A. Use Athena's TABLESAMPLE BERNOULLI(0.02) clause to randomly sample approximately 0.02% of rows (1 million records), which provides sufficient sample size for 95% confidence with ±1% margin of error based on the standard statistical formula n = (Z²×p×(1-p))/E².
  • B. Process only the most recent partition (today's data) as a representative sample of overall data quality.
  • C. Use TABLESAMPLE(50 PERCENT) to get half the data, ensuring high confidence in the quality estimate.
  • D. Read only the first 10,000 rows from the dataset using LIMIT 10000 as a quick quality indicator.
Jawaban Benar: A
For 95% confidence and ±1% margin of error, the required sample size is approximately n = (1.96² × 0.5 × 0.5) / 0.01² ≈ 9,604 records minimum. However, for a population of 5 billion, a sample of ~1 million records provides extremely robust estimates while scanning only 0.02% of data—reducing Athena costs from $50 to approximately $0.01. Bernoulli sampling provides true random selection. Option B: The most recent partition may not represent historical data quality patterns (seasonality, source changes over time). Option C: 50% sampling saves only half the cost while providing no meaningful statistical improvement over a properly sized small sample. Option D: LIMIT 10000 returns the first rows encountered (not random), introducing selection bias—rows may be ordered by time or source, giving a non-representative sample.
2
A data pipeline processes IoT sensor data from 1,000 devices across 50 geographic regions. Device data quality varies significantly by region (some regions have 2% error rates while others have 15%). The team needs to assess overall data quality while ensuring each region is adequately represented in the quality assessment. Which sampling technique is MOST appropriate?
  • A. Stratified sampling: divide the dataset into strata by geographic region, then randomly sample a proportional (or fixed) number of records from each stratum to ensure every region is represented in the quality assessment regardless of its relative data volume.
  • B. Simple random sampling across the entire dataset without regard to region, relying on the large sample size to naturally include all regions.
  • C. Cluster sampling: randomly select 10 regions and analyze all data from those selected regions as representative of the whole.
  • D. Systematic sampling: take every 1000th record from the chronologically ordered dataset.
Jawaban Benar: A
Stratified sampling is optimal when the population has known subgroups (strata) with different characteristics. By sampling from each region independently, you guarantee representation of all regions including small ones that simple random sampling might miss. This is critical when quality varies significantly by region—underrepresenting high-error regions would underestimate overall quality issues. Option B: Simple random sampling may underrepresent small regions; if a region has only 0.5% of total data, it might have zero records in a small sample. Option C: Cluster sampling (selecting entire regions) introduces high variance because selected clusters may not represent excluded ones; with quality varying by region, this is risky. Option D: Systematic sampling on chronologically ordered data may miss entire regions if data arrives in geographic batches, and periodic patterns in data could align with the sampling interval.
3
A real-time data pipeline uses Kinesis Data Streams to ingest 100,000 events per second. The team needs to continuously monitor data quality on this stream without adding significant processing latency or cost. The monitoring should detect sudden quality degradation (e.g., spike in malformed records) within 60 seconds. Which sampling approach for the streaming context is BEST?
  • A. Implement reservoir sampling in a Lambda consumer that maintains a fixed-size sample (10,000 records) per 60-second window. At the end of each window, evaluate quality rules on the sample and publish metrics to CloudWatch.
  • B. Use Kinesis Data Analytics to process every record with quality checks in real-time, using the full stream throughput.
  • C. Configure a Kinesis Data Firehose delivery stream that samples 1% of records by randomly discarding 99% in a transformation Lambda, then run quality checks on the delivered sample in S3.
  • D. Run quality checks only on the first record of each Kinesis shard to minimize processing overhead.
Jawaban Benar: A
Reservoir sampling is the ideal algorithm for streaming data quality monitoring: it maintains a statistically representative fixed-size sample regardless of stream volume, uses O(1) memory per record decision, and doesn't require knowing the total stream size in advance. A 10,000-record sample per 60-second window provides sufficient statistical power to detect quality degradation while processing overhead is minimal. Option B: Processing every record (100K/second) for quality checks adds significant cost and may introduce backpressure/latency on the stream. Option C: Firehose delivery to S3 adds latency (minimum 60-second buffer) before quality checks can run, and the Firehose → S3 → analysis path may exceed the 60-second detection requirement. Option D: Sampling only the first record per shard is not random; it introduces temporal bias and with typically few shards, provides an extremely small sample.
4
A data engineer uses AWS Glue DataBrew for data profiling on a 500 GB dataset. DataBrew's profiling job is configured to use sampling to reduce profiling cost and time. The engineer notices that rare data quality issues (occurring in only 0.01% of records) are not being detected by the profiling results. What is the fundamental limitation and how should it be addressed?
  • A. DataBrew's default sample size may be too small to reliably detect rare events. Increase the sample size in the profile configuration, or for critical rare-event detection, run a full dataset profile on a reduced column set focused on the columns where rare issues are suspected.
  • B. DataBrew profiling always uses 100% of data, so the rare events should be detected. The issue is likely in how the profiling results are displayed.
  • C. Switch from DataBrew to a custom Spark profiling job that processes all records.
  • D. Run the profiling job multiple times and average the results to increase the probability of detecting rare events.
Jawaban Benar: A
This is a fundamental limitation of sampling: rare events (0.01% = 1 in 10,000 records) require sample sizes large enough to capture them with statistical confidence. If DataBrew samples 20,000 records from 500 GB, it expects only ~2 occurrences of a 0.01% event—too few for reliable detection. Increasing sample size or profiling the full dataset for specific columns addresses this directly. Option B: DataBrew does support sampling for profiling jobs; it doesn't always process 100% of data. Option C: Switching to Spark adds operational complexity when DataBrew's sample size adjustment is sufficient. Option D: Multiple independent runs with small samples don't overcome the fundamental sample size limitation; each run independently misses the rare events.
5
A team wants to use Athena to analyze a 20 TB dataset but needs to minimize query costs. They decide to create a representative sample table for exploratory analysis and quality assessment. The source data has a highly skewed distribution: 80% of records come from the top 5 customers (out of 10,000 total customers). Which sampling strategy creates the MOST useful sample for quality assessment across all customers?
  • A. Use stratified sampling with equal allocation per customer (same number of records from each customer regardless of their volume), stored as a materialized sample table. This ensures small customers are adequately represented for quality assessment.
  • B. Use TABLESAMPLE BERNOULLI(1) to create a 1% random sample, which will naturally reflect the skewed distribution with 80% of sample records from the top 5 customers.
  • C. Sample only from the top 5 customers since they represent 80% of the data and are most important for quality.
  • D. Use systematic sampling by selecting every 100th record ordered by customer_id.
Jawaban Benar: A
For quality assessment "across all customers," stratified sampling with equal allocation ensures every customer (including the 9,995 smaller ones) has enough records in the sample for meaningful quality evaluation. A simple random sample would have very few records from small customers, making it impossible to assess their data quality. Equal allocation per stratum prevents the dominant customers from drowning out quality issues specific to smaller customers. Option B: A 1% random sample maintains the 80/20 skew—small customers might have 0-1 records in the sample, providing no quality signal for those customers. Option C: Sampling only top customers completely ignores quality issues that may be specific to smaller customers (different data entry processes, different systems). Option D: Systematic sampling ordered by customer_id would give proportionally more records to large customers and doesn't control representation.
6
A data engineering team is performing A/B testing on a new data transformation pipeline. They need to compare the output quality of the new pipeline (B) against the existing pipeline (A) using the same input data. The input dataset has 100 million records. They want to detect quality differences of 0.5% or greater between pipelines with 99% confidence. How should they design the test?
  • A. Process a statistically powered sample through both pipelines: calculate the required sample size using power analysis for comparing two proportions (approximately 150,000 records for 99% confidence, 0.5% detectable difference), then compare quality metrics between both pipeline outputs on the same sample.
  • B. Run both pipelines on the full 100 million records and compare aggregate quality scores to determine which performs better.
  • C. Process 50 million records through pipeline A and 50 million through pipeline B, then compare quality metrics.
  • D. Sample 1,000 records, run both pipelines, and if the quality difference exceeds 0.5%, conclude the pipelines differ.
Jawaban Benar: A
Proper A/B testing requires: (1) processing the SAME records through both pipelines (paired comparison), (2) statistically powered sample size based on the desired confidence level and detectable difference, and (3) appropriate statistical tests to compare proportions. Power analysis for comparing two proportions with 99% confidence and 0.5% detectable difference requires approximately 150,000 records—far fewer than 100M but sufficient for statistically valid conclusions. Option B: Processing 100M records through both pipelines is wasteful when a sample provides the same statistical conclusion at a fraction of the cost. Option C: Using different records for each pipeline confounds data differences with pipeline differences—you can't tell if quality differences are due to the pipeline or the specific input data. Option D: 1,000 records is far too few for 99% confidence at 0.5% difference detection; the required sample size is ~150K.
7
A data lake contains time-series data from financial markets with 3 years of data (1 TB per month, 36 TB total). The team needs to profile this data for quality issues but suspects that data quality degraded after a system migration that occurred 8 months ago. Which sampling strategy provides the MOST informative quality assessment given this temporal hypothesis?
  • A. Use temporal stratified sampling: sample proportionally more records from the period around the migration (months 7-9 ago) and create two explicit strata—pre-migration and post-migration—to enable direct comparison of quality metrics between periods.
  • B. Use simple random sampling across all 36 months to get an overall quality picture regardless of when issues occurred.
  • C. Only sample from the last 8 months (post-migration) since that's where the suspected quality issues exist.
  • D. Profile only the most recent month as representative of current data quality.
Jawaban Benar: A
When there's a known temporal event (system migration) that may have affected quality, the sampling strategy should enable direct comparison between pre and post periods. Stratified sampling by time period, with denser sampling around the migration, allows: (1) measuring baseline quality pre-migration, (2) detecting exactly when degradation began, and (3) comparing current quality against the historical baseline. This provides actionable insights about whether the migration caused quality issues. Option B: Simple random sampling dilutes the signal—if quality degraded 8 months ago, mixing good pre-migration data with potentially bad post-migration data obscures the change point. Option C: Only sampling post-migration prevents establishing a baseline—you can't prove quality degraded without comparing against pre-migration quality. Option D: The most recent month doesn't reveal whether issues are getting better or worse over time since the migration.
8
A data engineer builds a quality monitoring system for a pipeline that processes 50 million records daily. Due to processing costs, they can only afford to run comprehensive quality checks (20+ rules) on a sample of 500,000 records. After sampling, they discover that 0.3% of sampled records have quality issues. What confidence interval can they report to stakeholders about the true population quality?
  • A. With n=500,000 and observed proportion p=0.003, the 95% confidence interval is approximately 0.3% ± 0.05% (using the formula: p ± Z×√(p(1-p)/n)), meaning the true error rate in the full 50 million records is between 0.25% and 0.35% with 95% confidence.
  • B. The confidence interval is exactly 0.3% because the sample is large enough to represent the population perfectly.
  • C. No confidence interval can be calculated because the sample is less than 1% of the total population.
  • D. The confidence interval is 0.3% ± 3% (±100% of the observed rate) because the sample represents only 1% of the population.
Jawaban Benar: A
The confidence interval for a proportion is calculated using: CI = p ± Z × √(p(1-p)/n). With p=0.003, n=500,000, and Z=1.96 (95% confidence): margin = 1.96 × √(0.003 × 0.997 / 500,000) ≈ 1.96 × 0.000245 ≈ 0.00048 or ~0.05%. This narrow interval demonstrates that large samples provide very precise estimates even when the sample fraction is small. Option B: No sample gives an exact population parameter; there's always sampling error, though it's very small here. Option C: The sample fraction (sample/population ratio) is largely irrelevant for confidence intervals when the population is much larger than the sample; sample SIZE matters, not sample fraction. Option D: Confidence interval width is determined by sample size, not sample fraction; 500,000 records provides very high precision regardless of population size.
9
A data engineer needs to implement sampling for a Spark-based Glue ETL job to perform quick quality checks during development and testing. In production, the full dataset should be processed. Which implementation allows the same Glue job to support both sampled (development) and full (production) execution?
  • A. Use a Glue job parameter (--SAMPLE_FRACTION) that controls sampling: in the script, apply df.sample(fraction=args['SAMPLE_FRACTION']) when the parameter is set to a value less than 1.0. Set the parameter to 1.0 for production (full data) and 0.01 for development (1% sample).
  • B. Create two separate Glue jobs: one for development with hardcoded sampling and one for production without sampling.
  • C. Use Glue's built-in development endpoint feature which automatically samples data for interactive development.
  • D. Partition the data so development environments only have access to a single day's partition as a natural sample.
Jawaban Benar: A
Using a Glue job parameter to control sampling provides a single codebase that works for both environments. The parameter-driven approach is clean, testable, and maintains code consistency between development and production. Spark's DataFrame.sample() is efficient and doesn't require reading all data first (for Parquet/columnar formats with pushdown). Option B: Two separate jobs require maintaining duplicate code, risking drift between development and production logic. Option C: Glue development endpoints (now deprecated in favor of interactive sessions) provide interactive access but don't automatically sample data for quality check validation. Option D: Using a single day's partition isn't truly sampling—it's a time-bounded subset that may not represent the full data characteristics (e.g., different customer mix on different days).

A security team needs to audit 2 billion access log records stored in S3 to estimate the percentage of requests from unauthorized IP ranges. They know from previous audits that the unauthorized access rate is approximately 0.001% (very rare). What is the key challenge with using sampling for this analysis, and what is the recommended approach?
  • A. For extremely rare events (0.001%), the required sample size to achieve reasonable confidence is impractically large. Instead, use targeted filtering (Athena query filtering on IP ranges) to identify all matching records, rather than sampling to estimate the proportion.
  • B. Use a 1% random sample (20 million records) which is sufficient to detect events occurring at 0.001% frequency.
  • C. Use stratified sampling by IP address range to oversample from suspicious ranges.
  • D. Use Athena's TABLESAMPLE with BERNOULLI(10) to get a 10% sample, which guarantees detection of rare events.
Jawaban Benar: A
At 0.001% prevalence, a 1% sample of 2 billion (20 million records) would expect only ~200 unauthorized events—barely enough for a stable estimate. For security auditing where you need to identify ALL unauthorized access (not just estimate the rate), targeted filtering is superior to sampling. Athena can efficiently filter on IP ranges using predicate pushdown on Parquet/columnar data, effectively finding the needle in the haystack without scanning all bytes. Option B: 20M records would contain ~200 events of interest—while detectable, the confidence interval would be very wide (±30% relative error) for practical security decisions. Option C: Stratified sampling by IP range requires knowing which ranges are suspicious beforehand—but discovering unauthorized ranges IS the goal of the analysis. Option D: TABLESAMPLE doesn't guarantee detection of rare events; it provides statistical probability of inclusion, and even at 10%, some rare events may be missed.
