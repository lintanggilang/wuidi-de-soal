A data engineering team has a Glue ETL job that connects to an Amazon RDS PostgreSQL database. Currently, the database credentials (username/password) are hardcoded in the job script. The security team mandates that credentials must be rotated every 30 days automatically without any pipeline downtime. Which solution meets ALL requirements?
  • A. Store credentials in AWS Systems Manager Parameter Store (Standard tier) and create a CloudWatch Events rule to trigger rotation every 30 days, meeting the latency and throughput goals of the design and satisfying strict compliance and audit requirements
  • B. Use environment variables in the Glue job configuration and update them manually every 30 days with a 30-day schedule using the built-in RDS rotation Lambda function, applying schema conversion and enrichment inline and reducing day-to-day operational effort
  • C. Use AWS Secrets Manager to store the RDS credentials, enable automatic rotation with a 30-day schedule using the built-in RDS rotation Lambda function, and configure the Glue job to retrieve credentials from Secrets Manager at runtime
  • D. Store credentials in an S3 file encrypted with SSE-KMS and update the file monthly using a scheduled Lambda function, applying schema conversion and enrichment inline and satisfying all of the stated requirements with minimal effort
Jawaban Benar: C
AWS Secrets Manager adalah satu-satunya service yang menyediakan BUILT-IN automatic rotation untuk RDS/Aurora credentials. Cara kerjanya: (1) Secret disimpan di Secrets Manager dengan rotation enabled, (2) Rotation Lambda function (provided by AWS untuk RDS) secara otomatis: creates new password, updates the database, updates the secret value, (3) Menggunakan staging labels (AWSCURRENT, AWSPENDING) untuk zero-downtime rotation — old credentials tetap valid selama transition, (4) Glue job memanggil GetSecretValue saat runtime — selalu mendapat credential terbaru.

Opsi A: SALAH. TIDAK memiliki native rotation feature — harus build sendiri. Advanced tier PS bisa trigger rotation tapi tanpa built-in RDS rotation Lambda.
Opsi B: SALAH. Requires manual intervention dan credentials exposed in configuration — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi C: BENAR.
Opsi D: SALAH. Memerlukan custom Lambda dan tidak memiliki built-in database password update mechanism.

#Lambda#Glue#RDS#KMS#SecretsManager
A data engineer sets up automatic rotation for an RDS MySQL secret in Secrets Manager. After the first rotation, the Glue ETL job fails with "Authentication failed" errors. The secret's rotation status shows "Rotation successful". What is the MOST likely cause?
  • A. The Glue job is caching the old credentials — it retrieved the secret value at startup and stores it in memory for the duration of the job, not re-fetching after rotation occurs mid-job execution
  • B. The KMS key used to encrypt the secret has expired for the duration of the job, integrating natively with the rest of the pipeline and applying schema conversion and enrichment inline and minimizing end-to-end processing latency
  • C. Secrets Manager automatically revokes the old password immediately upon rotation, meeting the latency and throughput goals of the design and handling the described workload reliably at scale and integrating natively with the rest of the pipeline
  • D. The rotation Lambda function is in a different VPC than the database, meeting the latency and throughput goals of the design and satisfying all of the stated requirements with minimal effort and minimizing end-to-end processing latency
Jawaban Benar: A
Common issue dengan credential rotation: Long-running jobs (Glue ETL can run hours) yang retrieve credentials at startup dan cache them. Jika rotation happens DURING job execution: (1) Job started with old password at T=0, (2) Rotation occurs at T=30min — database password changes, (3) Job's cached credential becomes invalid, (4) Next database connection attempt fails. Solutions: (1) Implement credential refresh logic — periodically call GetSecretValue, (2) Use connection pooling with credential refresh, (3) For Glue specifically — use Glue Connections which can be configured to retrieve secrets, (4) Schedule rotations during maintenance windows when no long-running jobs are active.

Opsi A: BENAR.
Opsi B: SALAH. Jika KMS key expired, rotation itself would have failed — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi C: SALAH. Secrets Manager uses staging labels (AWSCURRENT/AWSPREVIOUS) dan old credential (AWSPREVIOUS) biasanya tetap valid briefly, tapi database already has new password setelah rotation.
Opsi D: SALAH. Jika networking was wrong, rotation status would show failed.

  • A. In the Security account: add a resource-based policy on the secret allowing the Analytics account's role to call secretsmanager:GetSecretValue; ensure the KMS key policy also grants Decrypt to the Analytics account's role. In the Analytics account: the role's IAM policy allows secretsmanager:GetSecretValue on the secret ARN in the Security account
  • B. Create an identical secret in both accounts and synchronize manually configured for optimal performance and minimal operational overhead, meeting the latency and throughput goals of the design and handling the described workload reliably at scale and satisfying all of the stated requirements with minimal effort and satisfying strict compliance and audit requirements
  • C. Share the AWS account credentials of the Security account with the Analytics team, enforcing encryption and fine-grained access control and meeting the latency and throughput goals of the design and integrating natively with the rest of the pipeline and satisfying all of the stated requirements with minimal effort
  • D. Copy the secret to the Analytics account using cross-region replication, meeting the latency and throughput goals of the design and integrating natively with the rest of the pipeline and handling the described workload reliably at scale and satisfying all of the stated requirements with minimal effort and minimizing end-to-end processing latency
Jawaban Benar: A
Cross-account secret access memerlukan permissions di KEDUA sisi: Security Account (resource owner) — Secret resource policy: {"Effect": "Allow", "Principal": {"AWS": "arn:aws:iam::111111111111:role/AnalyticsRole"}, "Action": "secretsmanager:GetSecretValue", "Resource": "*"}. KMS key policy: HARUS grant kms:Decrypt ke Analytics role karena secret terenkripsi KMS. Tanpa ini, GetSecretValue akan gagal dengan AccessDenied meskipun secret policy mengizinkan. Analytics Account (consumer): IAM policy pada role: Allow secretsmanager:GetSecretValue pada ARN secret "arn:aws:secretsmanager:region:999999999999:secret:redshift-creds-*". BOTH permissions (secret policy + KMS policy + IAM policy) diperlukan.

Opsi A: BENAR.
Opsi B: SALAH. Manual sync tidak scalable dan credential bisa out of sync — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi C: SALAH. Severe anti-pattern.
Opsi D: SALAH. Secrets Manager cross-region replication exists tapi ini cross-ACCOUNT bukan cross-region.

#Lambda#Aurora#IAM#SecretsManager
A data engineer implements Secrets Manager rotation for an Aurora MySQL cluster. During the rotation, applications experience brief connection failures. The rotation Lambda function uses the "single user" rotation strategy. The engineer wants to eliminate connection failures during rotation. Which rotation strategy should they switch to?
  • A. Disable rotation and manually update credentials during maintenance windows, handling the described workload reliably at scale and meeting the latency and throughput goals of the design and integrating natively with the rest of the pipeline and delivering records with consistent sub-second latency
  • B. Increase the rotation Lambda timeout to avoid failures configured for optimal performance and minimal operational overhead, handling the described workload reliably at scale and integrating natively with the rest of the pipeline and satisfying all of the stated requirements with minimal effort
  • C. Use IAM database authentication instead of password rotation, integrating natively with the rest of the pipeline and meeting the latency and throughput goals of the design and satisfying all of the stated requirements with minimal effort and enforcing encryption and fine-grained access control
  • D. Switch to the "alternating users" rotation strategy — this uses TWO database users that alternate between active roles, so the previous user's credentials remain valid while the new user is being set up, eliminating any window where no valid credentials exist
Jawaban Benar: D
Rotation strategies di Secrets Manager: Single User Strategy: Uses ONE database user. During rotation: (1) Change password in database, (2) Update secret. Brief window exists dimana password sudah berubah di DB tapi applications masih punya old cached value → connection failures. Alternating Users Strategy: Uses TWO database users (e.g., app_user dan app_user_clone). Rotation cycle: (1) AWSCURRENT points to user_A (currently active), (2) Rotation creates/updates user_B with new password, (3) Tests user_B connectivity, (4) Swaps labels: user_B becomes AWSCURRENT, user_A becomes AWSPREVIOUS. At NO point are both users simultaneously invalid — eliminates connection failures. Applications using GetSecretValue always get working credentials because AWSCURRENT is always valid.

Opsi A: SALAH. Removes automation benefit.
Opsi B: SALAH. Doesn't address the root cause — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi C: SALAH. Is valid alternative tapi changes the entire authentication mechanism, tidak hanya rotation strategy.
Opsi D: BENAR.

A data engineer stores database credentials in Secrets Manager with versioning enabled. They need to implement a rollback capability — if a new credential version causes issues, they should be able to quickly revert to the previous working version. How does Secrets Manager versioning support this?
  • A. Secrets Manager only keeps the latest version; previous versions are permanently deleted, meeting the latency and throughput goals of the design and satisfying all of the stated requirements with minimal effort and integrating natively with the rest of the pipeline
  • B. Use staging labels — the current version has label AWSCURRENT, and the previous version has label AWSPREVIOUS. To rollback, move the AWSCURRENT label to the previous version using UpdateSecretVersionStage API, making applications immediately retrieve the old (working) credential
  • C. Delete the current secret and recreate it with the old value, handling the described workload reliably at scale and integrating natively with the rest of the pipeline and satisfying all of the stated requirements with minimal effort
  • D. Contact AWS Support to restore a previous secret version and the previous version has label AWSPREVIOUS, integrating natively with the rest of the pipeline and handling the described workload reliably at scale and guaranteeing no data loss during component failures
Jawaban Benar: B
Secrets Manager versioning menggunakan staging labels untuk manage version lifecycle: AWSCURRENT: The version returned by default when GetSecretValue is called. This is the "active" version. AWSPREVIOUS: The version that was AWSCURRENT before the last rotation/update. AWSPENDING: Used during rotation process (temporary state). Rollback process: (1) Identify issue dengan current credential, (2) Call UpdateSecretVersionStage to move AWSCURRENT label from problematic version to AWSPREVIOUS version, (3) Immediately, all subsequent GetSecretValue calls return the rolled-back version. Important notes: Ini hanya rollback di Secrets Manager — jika database password sudah berubah, perlu juga rollback database password ke match. Untuk rotation-related rollbacks, both database and secret must be consistent.

Opsi A: SALAH. Salah — SM keeps multiple versions.
Opsi B: BENAR.
Opsi C: SALAH. Loses version history dan audit trail.
Opsi D: SALAH. Not needed, self-service available — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
