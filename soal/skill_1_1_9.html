A data pipeline writes to a DynamoDB table with provisioned capacity of 5,000 WCUs. During peak data ingestion, the pipeline experiences ProvisionedThroughputExceededException errors. The engineer wants to handle spikes without over-provisioning. Which solution BEST handles unpredictable traffic patterns?
  • A. Switch the DynamoDB table to On-Demand capacity mode
  • B. Enable DynamoDB Auto Scaling with target utilization of 70%
  • C. Implement exponential backoff with jitter in the data pipeline
  • D. Increase provisioned WCUs to 50,000 to handle any spike
Jawaban Benar: A
On-Demand capacity mode secara otomatis menyesuaikan kapasitas berdasarkan traffic aktual tanpa planning. Ini ideal untuk unpredictable workloads. Tidak ada throttling selama traffic tidak melebihi 2x previous peak. Opsi B (Auto Scaling) memiliki delay 5-15 menit untuk merespons spike, sehingga masih bisa throttle selama ramp-up. Opsi C (backoff) hanya menangani retry tapi tidak menyelesaikan kapasitas. Opsi D (50K WCUs) mahal dan tetap bisa insufficient untuk spike tak terduga.

A Kinesis Data Stream has 10 shards with producers writing at 8 MB/s total. Producers occasionally receive ProvisionedThroughputExceededException. Investigation reveals that 60% of records use the same partition key. What is the root cause and the BEST solution?
  • A. Hot shard due to partition key skew; redesign the partition key to distribute writes more evenly across shards
  • B. Insufficient total stream capacity; double the number of shards to 20
  • C. Producer retry logic is causing duplicate writes; implement deduplication
  • D. Stream encryption is causing throughput overhead; disable encryption
Jawaban Benar: A
Dengan 10 shards, total kapasitas adalah 10 MB/s write. Traffic 8 MB/s seharusnya cukup. Masalahnya adalah 60% records menggunakan partition key yang sama, sehingga satu shard menerima ~4.8 MB/s (melebihi 1 MB/s per shard limit). Solusinya adalah mendesain ulang partition key untuk distribusi merata. Opsi B menambah shard tapi hot shard tetap menerima semua traffic yang sama. Opsi C (deduplication) tidak relevan dengan throttling. Opsi D (encryption) overhead negligible.

An AWS Glue ETL job reads from an Amazon RDS MySQL database with max_connections set to 150. The Glue job uses 100 DPUs, and each DPU opens multiple connections. The job fails with "Too many connections" error. Which configuration change resolves this without modifying the RDS instance?
  • A. Reduce the Glue job's number of workers and use hashpartitions with a value lower than max_connections
  • B. Use Amazon RDS Proxy in front of the database to pool connections
  • C. Increase the Glue job timeout to allow connections to queue
  • D. Enable Glue Auto Scaling to dynamically adjust the number of connections
Jawaban Benar: A
Glue hashpartitions menentukan jumlah koneksi paralel ke database. Dengan menetapkan hashpartitions ke nilai di bawah max_connections (misalnya 50), Glue membatasi jumlah concurrent connections. Mengurangi workers juga mengurangi parallelism. Opsi B (RDS Proxy) valid tapi "without modifying the RDS instance" — RDS Proxy adalah komponen terpisah yang bisa ditambahkan. Opsi C (timeout) tidak menyelesaikan connection limit. Opsi D (Auto Scaling) bisa menambah lebih banyak workers yang memperburuk masalah.

A data engineer is writing records to a DynamoDB table using BatchWriteItem. The response frequently contains UnprocessedItems. The table has provisioned capacity. What is the MOST appropriate approach to handle UnprocessedItems?
  • A. Retry the UnprocessedItems with exponential backoff, starting with a short delay and doubling with each retry
  • B. Immediately retry all items in the batch including already processed ones
  • C. Increase batch size to 100 items to reduce the number of API calls
  • D. Log the UnprocessedItems and continue processing new batches
Jawaban Benar: A
UnprocessedItems menunjukkan items yang gagal karena throttling. Best practice adalah retry hanya UnprocessedItems (bukan seluruh batch) dengan exponential backoff untuk memberikan waktu tabel recover. AWS SDK melakukan ini secara default. Opsi B membuang resources karena memproses ulang items yang sudah berhasil. Opsi C (batch size 100) — BatchWriteItem sudah dibatasi 25 items per batch. Opsi D (skip) menyebabkan data loss.

A real-time data pipeline ingests data from 1,000 IoT devices into Kinesis Data Streams. Each device sends data every second. The Kinesis PutRecord API is experiencing throttling. The current stream has 5 shards. The data engineer wants to reduce API throttling WITHOUT adding more shards. Which approach is MOST effective?
  • A. Switch from PutRecord to PutRecords (batch API) to aggregate multiple records into fewer API calls
  • B. Use the Kinesis Producer Library (KPL) with aggregation enabled to combine multiple user records into single Kinesis records
  • C. Implement client-side buffering with a 1-second window before sending
  • D. Enable server-side encryption to optimize record processing
Jawaban Benar: B
KPL aggregation menggabungkan multiple user records menjadi satu Kinesis record, dramatically mengurangi jumlah API calls. Dengan 1,000 records/detik dan 5 shards (limit 1,000 records/shard/detik = 5,000 total), throttling mungkin terjadi karena hot partition. KPL juga memiliki built-in retry dan batching. Opsi A (PutRecords) mengurangi HTTP calls tapi masih 1 record = 1 Kinesis record. Opsi C (buffering) membantu tapi kurang sophisticated dibanding KPL. Opsi D (encryption) tidak terkait throughput.

A data pipeline reads from DynamoDB using Scan operations for daily reporting. The scan consumes all provisioned RCUs and causes throttling for the production application that shares the table. How should the engineer configure the scan to minimize impact on production?
  • A. Use a rate limiter to control scan throughput and set Limit parameter to read fewer items per request with a delay between pages
  • B. Use DynamoDB Export to S3 feature to export data without consuming table RCUs
  • C. Run the scan during off-peak hours only
  • D. Create a Global Secondary Index and scan the index instead
Jawaban Benar: B
DynamoDB Export to S3 menggunakan PITR backup dan tidak mengonsumsi RCU tabel sama sekali. Ini memberikan zero impact pada production workload. Data diekspor ke S3 dalam format DynamoDB JSON atau ION dan bisa diquery dengan Athena. Opsi A (rate limiter) masih mengonsumsi RCU walaupun lebih terkontrol. Opsi C (off-peak) masih compete untuk RCU selama scan. Opsi D (GSI scan) tetap mengonsumsi RCU dari GSI yang bisa affect main table jika terjadi GSI backpressure.

An application uses Amazon API Gateway backed by Lambda to serve data from DynamoDB. During a product launch, the API receives 50,000 requests per second, causing DynamoDB throttling. The data doesn't change frequently (updates every 5 minutes). Which solution MOST effectively reduces DynamoDB load?
  • A. Enable API Gateway caching with a TTL of 300 seconds to serve repeated requests from cache
  • B. Add DynamoDB Accelerator (DAX) as a read-through cache in front of DynamoDB
  • C. Increase DynamoDB provisioned RCUs to 100,000
  • D. Enable DynamoDB Auto Scaling with aggressive scaling policy
Jawaban Benar: A
API Gateway caching menyajikan responses dari cache tanpa memanggil Lambda atau DynamoDB. Dengan data yang hanya berubah setiap 5 menit, TTL 300 detik sangat efektif mengurangi backend calls hingga ~99% selama cache hit rate tinggi. Opsi B (DAX) mengurangi DynamoDB load tapi Lambda masih dipanggil setiap request (biaya compute). Opsi C (100K RCU) sangat mahal. Opsi D (Auto Scaling) memiliki delay dan tetap costly untuk 50K rps sustained.

A data engineer is building an ingestion pipeline that calls an external API with a strict rate limit of 10 requests per second. The pipeline needs to process 100,000 records, each requiring one API call. Using AWS Step Functions, which pattern implements precise rate limiting?
  • A. Use a Map state with MaxConcurrency set to 10, with each iteration including a Wait state of 1 second
  • B. Use a Choice state to check current time and skip if too many requests were sent
  • C. Process all 100,000 records in a single Lambda function with sleep intervals
  • D. Use an SQS FIFO queue with a message delay of 100ms between sends
Jawaban Benar: A
Step Functions Map state dengan MaxConcurrency=10 membatasi parallelism ke 10 iterations bersamaan. Dengan Wait state 1 detik di setiap iteration, ini menghasilkan ~10 requests/second yang sesuai rate limit. Ini scalable dan fault-tolerant. Opsi B (Choice + time check) tidak bisa mengontrol concurrency dengan presisi. Opsi C (single Lambda) timeout setelah 15 menit — 100K records × 0.1s = 2.7 jam. Opsi D (SQS delay) tidak bisa mengontrol exactly 10/second dari consumer side.

A Lambda function writes to DynamoDB and occasionally receives throttling errors. The function uses the AWS SDK with default retry configuration. The data engineer notices that retries are consuming Lambda execution time and causing timeouts. Which SDK configuration change addresses this?
  • A. Configure the SDK client with adaptive retry mode (RetryMode.ADAPTIVE) which includes token bucket rate limiting
  • B. Set max retries to 0 and handle failures with a dead-letter queue
  • C. Increase Lambda timeout to 15 minutes to accommodate retries
  • D. Disable SDK retries and implement custom retry logic with shorter delays
Jawaban Benar: A
Adaptive retry mode menggunakan token bucket algorithm untuk proaktif mengurangi request rate sebelum throttling terjadi, bukan hanya retry setelah failure. Ini mencegah thundering herd dan mengurangi total retry overhead. AWS SDK v2/v3 mendukung STANDARD, LEGACY, dan ADAPTIVE modes. Opsi B kehilangan data dan menambah complexity. Opsi C menambah biaya dan tidak menyelesaikan root cause. Opsi D custom retry mungkin tidak lebih baik dari built-in adaptive mode.

A company migrates data from PostgreSQL to DynamoDB using AWS DMS. The full load migration consistently throttles DynamoDB writes even though DynamoDB is set to On-Demand mode. What is the MOST likely cause and solution?
  • A. DynamoDB On-Demand has an initial throughput limit for new tables; pre-warm the table by gradually increasing load before the full migration, or contact AWS Support to increase initial limits
  • B. DMS is not compatible with DynamoDB On-Demand mode
  • C. The DMS replication instance is too small
  • D. DynamoDB On-Demand mode doesn't support batch writes from DMS
Jawaban Benar: A
DynamoDB On-Demand memiliki initial throughput limit untuk tabel baru (dimulai dengan kapasitas terbatas dan scales berdasarkan traffic history). Jika full load dimulai langsung dengan throughput tinggi tanpa ramp-up, tabel belum punya history untuk scale. Solusinya adalah pre-warming (gradual increase) atau minta AWS Support untuk raise initial limits. Opsi B salah — DMS kompatibel dengan On-Demand. Opsi C (instance size) mempengaruhi DMS bukan DynamoDB throttling. Opsi D salah — On-Demand mendukung batch writes.
