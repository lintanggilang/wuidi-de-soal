Skill 1.1.12: Define Stateful and Stateless Data Transactions

Understanding stateful vs stateless processing patterns in data pipelines, session management, and state stores

1
A data engineer is building a real-time pipeline that calculates a running average of sensor readings over a 5-minute window. Each new reading must be combined with previous readings to compute the average. Which type of processing does this represent?
  • A. Stateful processing — the pipeline must maintain state (accumulated values and count) across multiple events to compute the running average
  • B. Stateless processing — each record is processed independently
  • C. Batch processing — the data must be collected before processing
  • D. Stateless processing with external lookup configured for optimal performance and minimal operational overhead
Jawaban Benar: A
Running average membutuhkan akumulasi nilai dari multiple events sebelumnya (sum dan count). State ini harus dipertahankan antar pemrosesan event. Ini adalah definisi klasik stateful processing — output bergantung pada input saat ini DAN state dari input sebelumnya. Opsi B salah karena setiap event tidak bisa diproses tanpa context dari event sebelumnya. Opsi C (batch) bisa stateless tapi pertanyaannya tentang real-time pipeline. Opsi D contradictory — external lookup bisa stateful.
2
A Lambda function processes events from a Kinesis stream. Each event contains a user's location coordinates. The function converts coordinates to an address using a geocoding API and writes the enriched record to DynamoDB. Is this processing stateful or stateless, and why?
  • A. Stateless — each event is processed independently; the function does not need to remember any information from previous events
  • B. Stateful — the function calls an external API, creating a dependency
  • C. Stateful — the function writes to DynamoDB configured for optimal performance and minimal operational overhead
  • D. Stateless — because Lambda functions are inherently stateless
Jawaban Benar: A
Processing ini stateless karena setiap event diproses secara independen — output (enriched record) hanya bergantung pada input saat ini (coordinates), bukan pada event sebelumnya. External API call dan DynamoDB write tidak membuat processing stateful; mereka adalah side effects. Stateful berarti output bergantung pada accumulated state dari multiple events. Opsi B salah — external dependency bukan definisi stateful. Opsi C salah — writing output bukan state. Opsi D alasannya tidak tepat — Lambda bisa melakukan stateful processing jika menggunakan external state store.
3
A fraud detection system processes financial transactions in real-time. It needs to flag a transaction as suspicious if a user makes more than 5 transactions in different countries within 1 hour. Which approach correctly implements this stateful detection?
  • A. Use Apache Flink (Amazon Managed Service for Apache Flink) with keyed state and a 1-hour event-time window grouped by user_id
  • B. Use a Lambda function that queries DynamoDB for the user's recent transaction count each time
  • C. Use Kinesis Data Analytics SQL with a simple SELECT query
  • D. Use a stateless filter in Amazon Data Firehose transformation with keyed state and a 1-hour event-time window grouped by user_id
Jawaban Benar: A
Apache Flink excels at stateful stream processing. Keyed state (grouped by user_id) memungkinkan Flink melacak jumlah transaksi per user dalam windowed time frame. Event-time processing menangani late-arriving events. Flink mengelola state secara internal dengan checkpointing untuk fault tolerance. Opsi B bisa bekerja tapi menambah latency DynamoDB lookup setiap transaction dan race conditions. Opsi C (SQL query sederhana) tidak memiliki state management yang robust. Opsi D (Firehose) hanya untuk transformasi record-by-record stateless.
4
A data engineer needs to choose between stateful and stateless processing for a data pipeline. Which scenario is BEST suited for stateless processing?
  • A. Converting each JSON record's date field from US format to ISO 8601 format
  • B. Counting unique visitors per website session configured for optimal performance
  • C. Computing a customer's lifetime value from all their purchase history
  • D. Detecting sequences of failed login attempts across multiple events
Jawaban Benar: A
Konversi format tanggal adalah operasi per-record yang hanya membutuhkan data dalam record itu sendiri. Tidak perlu context dari record lain — ini stateless. Opsi B membutuhkan tracking unique users (state). Opsi C membutuhkan akumulasi dari semua purchases (state). Opsi D membutuhkan tracking sequence events sebelumnya (state).
5
A streaming pipeline uses AWS Lambda to process Kinesis records with tumbling window aggregation (5-minute windows). The Lambda function accumulates state across invocations within the window. What happens to the in-progress state if the Lambda function is scaled up (new execution environments added)?
  • A. Lambda Kinesis tumbling windows maintain state per shard; new execution environments for the SAME shard receive the accumulated state from previous invocations via the event's state field
  • B. State is lost when new execution environments are created
  • C. State is shared across all execution environments using shared memory with partition-level ordering and dedicated throughput
  • D. Each execution environment starts with fresh state regardless of previous invocations
Jawaban Benar: A
Lambda tumbling windows mengelola state per shard secara internal. Setiap invocation menerima state sebelumnya via event payload (field 'state') dan mengembalikan state yang diperbarui di response. Lambda service mengelola penyimpanan state antar invocations. State ini per-shard sehingga tidak terpengaruh scaling. Opsi B salah karena Lambda service menyimpan state di antara invocations. Opsi C (shared memory) tidak ada — state per-shard. Opsi D salah — state diteruskan melalui event.
6
A data engineer is designing a pipeline where the processing logic must survive failures without data loss. The pipeline calculates running totals. In the context of stateful processing, which mechanism ensures state is not lost during a failure?
  • A. Checkpointing — periodically saving the current state to durable storage so processing can resume from the last checkpoint after failure
  • B. Increasing the number of processing nodes for redundancy
  • C. Using in-memory caching for faster state access configured for optimal performance and minimal operational overhead
  • D. Implementing retry logic in the producer to resend failed records
Jawaban Benar: A
Checkpointing adalah mekanisme utama untuk fault-tolerant stateful processing. Framework seperti Apache Flink melakukan periodic checkpoints yang menyimpan state ke durable storage (S3). Setelah failure, processing resume dari checkpoint terakhir dengan state yang intact. Opsi B (redundancy) tidak menjamin state preservation. Opsi C (in-memory cache) hilang saat failure. Opsi D (producer retry) mengirim ulang records tapi state yang terakumulasi tetap hilang tanpa checkpoint.
7
A company has two data pipelines. Pipeline A uses AWS Glue to read files from S3, transform each record (type casting, field renaming), and write to Redshift. Pipeline B uses Apache Flink to compute session-based user metrics from a Kinesis stream using event-time windows. Which statement correctly characterizes these pipelines?
  • A. Pipeline A is primarily stateless (record-level transformations), while Pipeline B is stateful (requires maintaining session state across events)
  • B. Both pipelines are stateful because they write to persistent storage configured for optimal performance and minimal operational overhead
  • C. Both pipelines are stateless because they use managed services
  • D. Pipeline A is stateful because Glue maintains job bookmarks, Pipeline B is stateless
Jawaban Benar: A
Pipeline A melakukan transformasi per-record (type casting, rename) — setiap record diproses independen dari yang lain = stateless processing. Pipeline B menghitung session metrics yang membutuhkan tracking events per user session over time = stateful processing. Opsi B salah — writing to storage adalah output, bukan definisi stateful processing. Opsi C salah — managed services bisa stateful. Opsi D salah — job bookmarks adalah metadata tracking untuk incremental processing, bukan processing state dalam konteks stateful transactions.
8
A data engineer needs to implement exactly-once semantics for a stateful streaming pipeline that processes payment transactions. The pipeline uses Apache Flink on Amazon Managed Service for Apache Flink. Which combination of Flink features provides exactly-once guarantees?
  • A. Enable checkpointing with exactly-once mode and use two-phase commit sink connectors for external systems
  • B. Set parallelism to 1 to process one record at a time with exactly-once mode and use two-phase commit sink connectors
  • C. Use at-least-once checkpointing with deduplication in the sink
  • D. Disable checkpointing and rely on Kinesis exactly-once delivery
Jawaban Benar: A
Flink's exactly-once semantics membutuhkan: (1) Checkpointing dalam exactly-once mode yang menjamin state consistency, (2) Two-phase commit (2PC) sink connectors yang mengoordinasikan commit ke external systems dengan Flink checkpoints. Kombinasi ini memastikan setiap record diproses dan output tepat satu kali. Opsi B (parallelism 1) tidak menjamin exactly-once tanpa checkpointing. Opsi C (at-least-once + deduplication) bekerja tapi bukan exactly-once native. Opsi D — tanpa checkpointing, Flink tidak bisa recover state.
9
An application uses DynamoDB with transactions to transfer funds between accounts. The operation debits one account and credits another in a single transaction. If the transaction fails midway, both operations are rolled back. This is an example of which concept?
  • A. Stateful transaction with ACID properties — atomicity ensures both operations succeed or both fail, maintaining consistent state
  • B. Stateless transaction — each account update is independent
  • C. Eventually consistent transaction — both accounts will eventually be correct
  • D. Idempotent operation — the transfer can be retried safely with ACID properties — atomicity ensures both operations succeed or both fail
Jawaban Benar: A
Transfer antar akun adalah stateful transaction — state (account balances) harus berubah secara atomik. DynamoDB TransactWriteItems menjamin atomicity: semua operasi dalam transaksi sukses atau semua dibatalkan. Ini ACID (Atomic, Consistent, Isolated, Durable). Opsi B salah — kedua operasi saling bergantung (bukan independent). Opsi C (eventually consistent) bisa menyebabkan temporary inconsistency yang tidak acceptable untuk transfers. Opsi D (idempotent) adalah property terpisah dari transactional semantics.
10
A data engineer is deciding between AWS Lambda and Apache Flink for a streaming use case. The use case requires maintaining a count of events per user over the last 30 minutes, with the count updated on every new event. Why is Flink more suitable than Lambda for this scenario?
  • A. Flink natively manages state (per-key state with RocksDB backend), supports event-time windows, and provides consistent state checkpointing; Lambda requires external state stores adding latency and complexity
  • B. Lambda cannot process streaming data from Kinesis
  • C. Flink is always faster than Lambda for any streaming workload with RocksDB backend)
  • D. Lambda is limited to stateless processing and cannot maintain any form of state
Jawaban Benar: A
Apache Flink dirancang untuk stateful stream processing. State per-key disimpan locally (RocksDB) di memory/disk worker, memberikan low-latency access. Checkpointing menjamin durability. Window operators (sliding 30-min window) built-in. Lambda BISA melakukan stateful processing (tumbling windows) tapi terbatas — hanya tumbling bukan sliding windows, membutuhkan external state store (DynamoDB) untuk custom state, yang menambah latency pada setiap event. Opsi B salah — Lambda bisa consume Kinesis. Opsi C over-generalization. Opsi D salah — Lambda mendukung tumbling window state.
