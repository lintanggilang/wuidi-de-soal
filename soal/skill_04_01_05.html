A company has a shared S3 data lake bucket accessed by three different teams: Analytics, Machine Learning, and Data Engineering. Each team needs access to different prefixes within the bucket. The bucket policy has become extremely complex with over 50 statements. Which solution simplifies access management while maintaining per-team isolation?
  • A. Split the data into three separate S3 buckets, one per team, and replicate shared data with each Access Point having its own policy that restricts access
  • B. Create S3 Access Points for each team, with each Access Point having its own policy that restricts access to the team's specific prefixes
  • C. Use IAM policies only and remove the bucket policy entirely, satisfying all of the stated requirements with minimal effort and reducing day-to-day operational effort
  • D. Create IAM groups per team with inline policies that restrict access to specific key prefixes using conditions, integrating natively with the rest of the pipeline
Correct Answer: B
S3 Access Points designed khusus for menyederhanakan access management on shared buckets. Each Access Point has hostname unik and access point policy tersendiri that can limits access to prefix certain. Tim Analytics accesses through access-point-analytics, ML through access-point-ml, dll. This menggantikan one bucket policy that kompleks with multiple simple policies.

Option A: INCORRECT. Adds cost storage and complexity sinkronisasi shared data — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option B: CORRECT.
Option C: INCORRECT. Not enables resource-based control and difficult manages for many team.
Option D: INCORRECT. Only controls from sisi identity, not provides resource-level simplification that same.

A data engineer configures a VPC endpoint for Amazon S3 (Gateway type) and wants to restrict the endpoint so that it can only access two specific S3 buckets: a data lake bucket and a code artifacts bucket. Which policy should be applied?
  • A. Modify the S3 bucket policy to deny access from all VPC endpoints except the specific endpoint ID
  • B. Apply a security group on the VPC endpoint to restrict traffic to the S3 bucket IP ranges
  • C. Apply a VPC endpoint policy that allows s3:* only on the two specific bucket ARNs and their objects
  • D. Modify the VPC route table to only route traffic for the two bucket IP addresses through the endpoint
Correct Answer: C
VPC endpoint policies control API calls that diperbolehkan through endpoint said. By limits resource to ARN two bucket specific (arn:aws:s3:::data-lake-bucket and arn:aws:s3:::data-lake-bucket/*), all request S3 through endpoint this only can accesses second bucket said. This provides defense-in-depth additional.

Option A: INCORRECT. Can jadi defense-in-depth additional but not limits endpoint that itself — resources in VPC still can mencoba access bucket other.
Option B: INCORRECT. Incorrect — Gateway endpoints not has security groups (only Interface endpoints that punya).
Option C: CORRECT.
Option D: INCORRECT. Incorrect — S3 Gateway endpoint uses prefix list in route table, not per-bucket IP routing.

A company needs to ensure that their S3 data lake bucket can ONLY be accessed from within their VPC — no access from the internet or other VPCs should be allowed, even if IAM policies permit it. Which approach enforces this network-level restriction?
  • A. Remove all IAM policies that allow access from outside the VPC, integrating natively with the rest of the pipeline
  • B. Configure the S3 bucket as a VPC endpoint target, enforcing encryption and fine-grained access control and minimizing end-to-end processing latency
  • C. Add a bucket policy with a Deny statement using the condition "aws:SourceVpc" not equal to the company's VPC ID
  • D. Enable S3 Block Public Access at the account level with a Deny statement using the condition "aws:SourceVpc" not equal
Correct Answer: C
Bucket policy with explicit Deny uses condition "aws:SourceVpc" ensures that ALL requests that not berasal from VPC that is determined will ditolak, terlepas from IAM permissions that there is. Statement: {"Effect": "Deny", "Principal": "*", "Action": "s3:*", "Resource": ["bucket-arn", "bucket-arn/*"], "Condition": {"StringNotEquals": {"aws:SourceVpc": "vpc-12345"}}}. Explicit Deny always override Allow.

Option A: INCORRECT. Not scalable and not prevents policies is added returns.
Option B: INCORRECT. Not concept that valid — S3 not "target" endpoint.
Option C: CORRECT.
Option D: INCORRECT. Only memblokir public access via ACLs/policies, not access from other VPCs or AWS accounts — although its description sounds convincing, in a fundamental still not appropriate for requirements this.

A data engineer implements AWS PrivateLink to allow a data processing service in VPC-A to access a third-party SaaS data provider's API without traversing the public internet. The SaaS provider has set up a VPC endpoint service (NLB-backed). What must the data engineer configure in VPC-A to use this PrivateLink connection?
  • A. Create a VPC Interface Endpoint in VPC-A pointing to the SaaS provider's endpoint service name, and configure security groups on the endpoint to allow outbound traffic
  • B. Create a Transit Gateway attachment to reach the SaaS provider's VPC configured for optimal performance and minimal operational overhead, meeting the latency and throughput goals of the design
  • C. Create a VPN connection from VPC-A to the SaaS provider's on-premises endpoint, meeting the latency and throughput goals of the design and applying schema conversion and enrichment inline
  • D. Create a VPC peering connection between VPC-A and the SaaS provider's VPC, integrating natively with the rest of the pipeline and handling the described workload reliably at scale
Correct Answer: A
AWS PrivateLink uses Interface Endpoints (powered by ENIs) in consumer VPC that connected to provider's VPC Endpoint Service (backed by NLB). Engineer needs: (1) Create Interface Endpoint in VPC-A with service name that is provided provider (com.amazonaws.vpce.region.vpce-svc-xxxxx). (2) Accept the connection (provider may needs approve). (3) Configure security group on endpoint ENI for allow traffic from data processing service. Data mengalir through AWS private network.

Option A: CORRECT.
Option B: INCORRECT. Berlebihan for single service connection — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option C: INCORRECT. Uses internet and slower.
Option D: INCORRECT. Requires kooperasi provider and membuka access more luas.

A data engineer needs to restrict access to an S3 bucket so that it can only be accessed by principals within the same AWS Organization (org-id: o-abc123def). The bucket contains shared datasets used by multiple accounts in the organization. Which bucket policy condition provides this restriction?
  • A. Condition: {"ArnLike": {"aws:PrincipalArn": "arn:aws:organizations::*:organization/o-abc123def"}}
  • B. Condition: {"StringEquals": {"aws:PrincipalAccount": "management-account-id"}}
  • C. Condition: {"StringEquals": {"aws:SourceAccount": "o-abc123def"}}
  • D. Condition: {"StringEquals": {"aws:PrincipalOrgID": "o-abc123def"}}
Correct Answer: D
aws:PrincipalOrgID is global condition key that memeriksa whether calling principal berasal from AWS Organization certain. By adds Allow statement bersyarat on aws:PrincipalOrgID, only principals from accounts that merupakan member organization o-abc123def that mendapat access. This very useful for shared resources — when account new is added to organization, mereka automatic mendapat access without needing updates bucket policy.

Option A: INCORRECT. Uses format ARN that incorrect for org condition.
Option B: INCORRECT. Only memeriksa one account, not entire organization.
Option C: INCORRECT. Incorrect — aws:SourceAccount only available for service-to-service calls, not directly applicable for org ID.
Option D: CORRECT.

A data engineer is implementing a multi-layer security model for an S3 bucket. The bucket has: an IAM policy on the Glue role allowing s3:GetObject on the bucket, an S3 bucket policy allowing the Glue role, and a VPC endpoint policy that does NOT include this bucket. The Glue job runs in a VPC and accesses S3 through the VPC endpoint. What is the result when the Glue job tries to read from the bucket?
  • A. Access is denied because the VPC endpoint policy does not allow access to the bucket, and the endpoint policy acts as an additional filter
  • B. Access is allowed because the IAM policy and bucket policy both grant access and the endpoint policy acts as an additional filter
  • C. Access is allowed because VPC endpoint policies are advisory only and do not enforce restrictions, protecting the data both in transit and at rest
  • D. The request bypasses the VPC endpoint and goes directly to S3 over the internet when the endpoint policy denies access, enforcing encryption and fine-grained access control
Correct Answer: A
VPC endpoint policies berfungsi as additional access control layer (filter). Request must is allowed by ALL policies that relevan: IAM policy, resource policy (bucket policy), DAN VPC endpoint policy. If VPC endpoint policy not allows access to bucket said, request will ditolak although IAM and bucket policy allows. VPC endpoint policy bersifat intersectional — request only succeeds if is allowed by all layer.

Option A: CORRECT.
Option B: INCORRECT. Incorrect — endpoint policy also must allow — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option C: INCORRECT. Incorrect — endpoint policies bersifat enforcing, not advisory.
Option D: INCORRECT. Incorrect — if traffic diroute through endpoint (via route table), there is no fallback to internet path; request will fail.

A data engineer needs to grant cross-account access to an S3 bucket for a specific Lambda function in Account B (account 222222222222). The Lambda function's role ARN is arn:aws:iam::222222222222:role/DataProcessorRole. The engineer wants to use a resource-based policy. Which S3 bucket policy statement correctly grants this access?
  • A. {"Effect": "Allow", "Principal": {"Service": "lambda.amazonaws.com"}, "Action": "s3:GetObject", "Resource": "arn:aws:s3:::mybucket/*"}
  • B. {"Effect": "Allow", "Principal": {"AWS": "222222222222"}, "Action": "s3:GetObject", "Resource": "arn:aws:s3:::mybucket/*"} with native S3 integration and optimized data transfer
  • C. {"Effect": "Allow", "Principal": {"AWS": "arn:aws:iam::222222222222:role/DataProcessorRole"}, "Action": "s3:GetObject", "Resource": "arn:aws:s3:::mybucket/*"}
  • D. {"Effect": "Allow", "Principal": "*", "Action": "s3:GetObject", "Resource": "arn:aws:s3:::mybucket/*", "Condition": {"StringEquals": {"aws:SourceAccount": "222222222222"}}}
Correct Answer: C
For provides cross-account access to specific role, gunakan role ARN as Principal. This provides access only to DataProcessorRole in Account B, not all entities in account said. This is approach most restrictive and mengikuti least privilege.

Option A: INCORRECT. Mengizinkan ALL Lambda functions from all accounts — very not secure.

A company's security policy requires that S3 buckets storing sensitive data must NEVER be publicly accessible, regardless of any bucket policy changes made by developers. The data engineer needs to implement a preventive control that enforces this across all S3 buckets in the account. Which approach provides the STRONGEST preventive control?
  • A. Create an AWS Config rule to detect public S3 buckets and automatically remediate, handling the described workload reliably at scale
  • B. Enable S3 Block Public Access at the account level (s3:PutAccountPublicAccessBlock) to block all current and future public access configurations
  • C. Add a Deny statement in every bucket policy preventing public access and future public access configurations
  • D. Use Amazon Macie to scan for publicly exposed buckets and alert the security team, handling the described workload reliably at scale
Correct Answer: B
S3 Block Public Access in account level is preventive control most kuat. When enabled, this automatically memblokir all configuration public access on ALL buckets in account — including public bucket policies, public ACLs, and new public bucket/access point policies. Even if developer adds bucket policy with Principal "*", Block Public Access will override and still memblokir public access.

Option A: INCORRECT. Is detective control (deteksi + remediate) — there is window where bucket already public before remediation.
Option B: CORRECT.
Option C: INCORRECT. Requires penerapan in each bucket and can is deleted by developer — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option D: INCORRECT. Only detection and alerting, not prevention.

A data engineer sets up an S3 Access Point for the analytics team. The Access Point policy allows the team's IAM role to perform s3:GetObject and s3:ListBucket. However, the underlying bucket policy has a Deny statement that blocks the team's role from s3:GetObject. What happens when the analytics team accesses the bucket through the Access Point?
  • A. Access is denied because the bucket policy Deny still applies — Access Points cannot override explicit Deny statements in bucket policies
  • B. Access is allowed because the Access Point policy overrides the bucket policy, satisfying all of the stated requirements with minimal effort
  • C. The Access Point becomes invalid because it conflicts with the bucket policy configured for optimal performance and minimal operational overhead
  • D. Only s3:ListBucket works (via Access Point policy) but s3:GetObject is denied (by bucket policy), meeting the latency and throughput goals of the design
Correct Answer: A
S3 Access Points not override bucket policies. Access dikontrol by INTERSECTION from Access Point policy and bucket policy (plus IAM policy). Explicit Deny in bucket policy always menang — this is prinsip fundamental IAM policy evaluation. Access Points dimaksudkan for menyederhanakan policy management, not for bypass existing restrictions. If bucket policy explicitly deny access from role certain, Access Point cannot provides access said.

Option A: CORRECT.
Option B: INCORRECT. Incorrect — Access Points not override.
Option C: INCORRECT. Incorrect — Access Point still valid, only permissions that limited — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option D: INCORRECT. Incorrect if Deny is applied on all S3 actions (depends what that in-deny in bucket policy).

A data engineer is implementing defense-in-depth for a data pipeline that processes sensitive financial data. The pipeline uses Lambda functions in a VPC accessing S3 through a Gateway Endpoint. The engineer wants to ensure that even if a Lambda function is compromised, it can only access designated S3 buckets and cannot exfiltrate data to external locations. Which combination of policies provides the MOST comprehensive data exfiltration protection?
  • A. VPC endpoint policy restricting to specific buckets + Network ACLs blocking all outbound traffic except to S3 IP ranges, enforcing encryption and fine-grained access control and satisfying strict compliance and audit requirements
  • B. IAM policy on Lambda role restricting S3 access to specific bucket ARNs only with aws:SourceVpce condition allowing only the specific VPC endpoint, handling the described workload reliably at scale
  • C. S3 bucket policy with aws:SourceIp condition restricting to the Lambda function's private IP addresses, satisfying all of the stated requirements with minimal effort and satisfying strict compliance and audit requirements
  • D. IAM policy restricting to specific buckets + VPC endpoint policy limiting S3 access to those same buckets + S3 bucket policy with aws:SourceVpce condition allowing only the specific VPC endpoint
Correct Answer: D
Defense-in-depth requires multiple layers of control: (1) IAM policy — controls what the Lambda role can do (only specific buckets). (2) VPC endpoint policy — controls what can be accessed through the endpoint (only same specific buckets). Even if attacker mendapat credentials different, endpoint only allows traffic to designated buckets. (3) S3 bucket policy with aws:SourceVpce — ensures bucket only accessible from VPC endpoint certain, prevents access from location other. Ketiga layer bersama-same creates exfiltration very difficult.

Option A: INCORRECT. Less IAM restriction and NACLs cannot distinguish between S3 buckets.
Option B: INCORRECT. Single layer, if credentials compromised, can is used from mana only — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option C: INCORRECT. Lambda private IPs bersifat dynamic and changes each invocation.
Option D: CORRECT.
