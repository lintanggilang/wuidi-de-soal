A retail analytics team needs to create interactive dashboards that combine data from Amazon Redshift and Amazon S3. The dashboards must load within 3 seconds even when querying billions of rows. Users should be able to interact with filters without waiting for queries to re-execute against the source. Which Amazon QuickSight feature should the data engineer enable to meet this requirement?
  • A. Enable direct query mode to push all computations to the source databases
  • B. Use QuickSight Q to auto-generate optimized queries against the sources
  • C. Create a QuickSight dataset with custom SQL that includes pre-aggregated results
  • D. Import data into SPICE (Super-fast, Parallel, In-memory Calculation Engine)
Correct Answer: D
SPICE is in-memory calculation engine milik QuickSight that stores data in a local so that interaksi dashboard very fast without needing query ulang to source data. SPICE supports miliaran rows and provides sub-second response time for filter and drill-down.

Option A: INCORRECT. Justru will slow because each interaksi triggers query to source.
Option B: INCORRECT. Is feature NLP for bertanya in bahasa alami, not for optimization performa.
Option C: INCORRECT. Reduces fleksibilitas and not guarantees kecepatan interaksi.
Option D: CORRECT.

  • B. Export the dashboard to PDF and distribute via email on a scheduled basis
  • C. Create 500 QuickSight Reader accounts and share the dashboard with each user
  • D. Use QuickSight embedded analytics with anonymous access enabled
Correct Answer: D
QuickSight embedded analytics enables penyematan dashboard to application or portal web external. By anonymous embedding, user does not need akun AWS or QuickSight, quite accesses via URL that in-embed. This most cost-effective for ratusan user external because dikenakan cost per session, not per user.

Option A: INCORRECT. Requires setup IdP and still requires lisensi per-user.
Option B: INCORRECT. Kehilangan interaktivitas.
Option C: INCORRECT. Requires manajemen 500 akun.
Option D: CORRECT.

Which DataBrew feature provides this capability with the LEAST effort?

DataBrew profile jobs automatically menganalisis all column and produces statistics komprehensif including null rate, distribution value, korelasi between column, duplikat, and outlier without needing writes code. This is way tercepat for gets overview kualitas data.

Option A: INCORRECT. Requires definisi manual per column.
Option B: INCORRECT. Not designed for profiling data mentah.

A healthcare organization has built an Amazon QuickSight dashboard showing patient visit metrics. Different hospital departments must only see data for their own department. The data is stored in a single Amazon Redshift table with a department_id column. How should the data engineer implement this access control in QuickSight?
  • A. Create separate Redshift views for each department and map each to a different dashboard
  • B. Create separate QuickSight datasets with SQL filters for each department
  • C. Implement row-level security (RLS) rules in QuickSight using a permissions dataset
  • D. Use QuickSight column-level security to hide department_id from unauthorized users
Correct Answer: C
Row-Level Security (RLS) in QuickSight enables creation one dataset and one dashboard that automatically filters data based on user/group. Permissions dataset contains mapping between username/group and value department_id that boleh dilihat. This is solution most scalable and maintainable.

Option A: INCORRECT. Requires many dashboard that difficult in-maintain.
Option B: INCORRECT. Requires many dataset duplikat.
Option C: CORRECT.
Option D: INCORRECT. Menyembunyikan column, not filters rows.

A data engineer is creating an Amazon QuickSight dataset that combines data from an Amazon RDS PostgreSQL database and a CSV file stored in Amazon S3. The combined dataset will be used for monthly sales analysis. The data in RDS changes daily while the CSV is updated monthly. What is the MOST efficient approach to configure the dataset refresh?
  • A. Import into SPICE with a weekly full refresh schedule for cost optimization, handling the described workload reliably at scale
  • B. Use direct query mode for both sources to always get the latest data with incremental refresh on the RDS source
  • C. Import into SPICE with incremental refresh on the RDS source and full refresh monthly for the S3 source
  • D. Import both sources into SPICE with a daily full refresh schedule, meeting the latency and throughput goals of the design
Correct Answer: C
QuickSight SPICE supports incremental refresh that only retrieves data new/changes based on column date/timestamp. For RDS that changes harian, incremental refresh saves time and SPICE capacity. For S3 CSV that only update bulanan, full refresh bulanan already quite.

Option A: INCORRECT. Can causes data stale up to seminggu for source RDS that changes harian.
Option B: INCORRECT. Kehilangan keuntungan performa SPICE — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option C: CORRECT.
Option D: INCORRECT. Wastes resource with full refresh each days.

A data engineering team has scheduled an Amazon QuickSight SPICE dataset to refresh every 6 hours. Occasionally the refresh fails because the source Amazon Redshift cluster is undergoing maintenance. The team wants to be notified immediately when a refresh failure occurs so they can take corrective action. What is the MOST operationally efficient way to implement this notification?
  • A. Create a CloudWatch alarm that monitors QuickSight SPICE refresh metrics and triggers an SNS notification
  • B. Configure QuickSight email reports to include refresh status in the report header, reducing day-to-day operational effort
  • C. Write a Lambda function that polls QuickSight API every 15 minutes to check dataset refresh status
  • D. Use Amazon EventBridge to capture QuickSight dataset refresh failure events and route to an SNS topic
Correct Answer: D
Amazon EventBridge captures event from QuickSight including dataset refresh success/failure in real-time. Event rule can is configured for filters only failure events and mengirimkannya to SNS topic for notifikasi email/SMS. This is approach event-driven that most operationally efficient.

Option A: INCORRECT. Not available for QuickSight refresh metrics in a native.
Option B: INCORRECT. Not real-time and not specific for failure.
Option C: INCORRECT. Adds overhead and latensi deteksi.
Option D: CORRECT.
