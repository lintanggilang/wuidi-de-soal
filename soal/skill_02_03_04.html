A data engineering team stores daily ETL output files in an S3 bucket with versioning enabled. Over time, storage costs have increased significantly due to accumulated noncurrent object versions. The team wants to reduce costs while retaining the ability to recover accidentally overwritten files for 30 days. Which solution BEST meets these requirements?
  • A. Create a lifecycle rule to expire noncurrent versions after 30 days and transition them to S3 Glacier after 7 days
  • B. Create a lifecycle rule to permanently delete noncurrent versions after 30 days
  • C. Suspend versioning on the bucket and delete all noncurrent versions manually
  • D. Disable versioning and enable S3 Cross-Region Replication for data protection
Correct Answer: B
Lifecycle rule for deletes noncurrent versions setelah 30 days enables recovery file that tertimpa in time 30 days sambil automatically membersihkan versi old for mengontrol cost.

Option A: INCORRECT. Salah because transition to Glacier occurs before expiration, but lifecycle rule for noncurrent versions must uses NoncurrentVersionExpiration, not Expiration.
Option B: CORRECT.
Option C: INCORRECT. Not deletes versi that ada and eliminates proteksi to depan.
Option D: INCORRECT. Not may — versioning only can in-suspend, not in-disable, and CRR requires versioning enabled.
2
A company has a DynamoDB table storing user session data. Each session record includes a "lastActivity" attribute (Unix epoch timestamp). The team wants sessions to automatically expire 24 hours after the last activity. Which configuration correctly implements this requirement?
  • A. Enable TTL on the table using a dedicated "expirationTime" attribute that stores lastActivity + 86400 seconds
  • B. Enable TTL on the table using the "lastActivity" attribute and set the TTL value to 86400
  • C. Enable TTL on the table using the "lastActivity" attribute and configure the TTL offset to 86400 seconds in the DynamoDB console
  • D. Create a DynamoDB Stream that triggers a Lambda function to delete expired items every 24 hours
Correct Answer: A
DynamoDB TTL membandingkan value atribut TTL (Unix epoch timestamp) with time saat this. Item is deleted when current time > TTL value. Not ada "offset" that can is configured — atribut TTL must contains time ekspirasi absolut. By because that, atribut separate "expirationTime" that contains lastActivity + 86400 (24 hours in seconds) is implementation that correct.

Option A: CORRECT.
Option B: INCORRECT. Salah because uses lastActivity directly berarti item directly expired.
Option C: INCORRECT. Not ada — DynamoDB not has feature TTL offset.
Option D: INCORRECT. Adds complexity that does not need.

A financial institution requires that specific compliance-critical objects in their S3 bucket cannot be permanently deleted, even by the root account user, without multi-factor authentication. Which feature should the data engineer enable?
  • A. S3 Versioning with a lifecycle rule preventing deletion
  • B. S3 Bucket Policy denying s3:DeleteObject for all principals
  • C. S3 Versioning with MFA Delete enabled
  • D. S3 Object Lock in Compliance mode
Correct Answer: C
MFA Delete requires autentikasi multi-faktor for deletes versi objek in a permanent or changes status versioning bucket. Ini prevents deletion permanent without MFA, even by root account.

Option A: INCORRECT. Not prevents deletion manual. Pertanyaan specific menyebut "without multi-factor authentication" that directly mengarah to MFA Delete.
Option B: INCORRECT. Can in-bypass by root account that can changes policy.
Option C: CORRECT.
Option D: INCORRECT. Mencegah deletion during retention period but not requires MFA — ia memblokir all deletion including root.

A data engineer has an S3 bucket with versioning enabled. They need to retrieve a specific previous version of a data file that was accidentally overwritten yesterday. The engineer knows the object key but not the version ID. Which approach should they use?
  • A. Use aws s3 cp with the --restore flag to retrieve the previous version with native S3 integration and optimized data transfer
  • B. Use the S3 console to view object versions, identify the correct version ID, then use GetObject with the versionId parameter
  • C. Use S3 Replication Time Control to restore the previous version, satisfying all of the stated requirements with minimal effort
  • D. Use S3 Inventory to find the version ID and then restore using S3 Batch Operations, handling the described workload reliably at scale
Correct Answer: B
For retrieves versi specific, gunakan ListObjectVersions API or S3 console for melihat all versi objek beserta version ID-nya, then gunakan GetObject with parameter versionId for mengunduh versi that diinginkan.

Option A: INCORRECT. Digunakan for restore from Glacier, not for accesses versi sebelumnya — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option B: CORRECT.
Option C: INCORRECT. For mengontrol SLA replication, not for restore.
Option D: INCORRECT. Not real-time and requires time for generate report.

A company uses DynamoDB to store IoT sensor readings. They enable TTL to automatically delete readings older than 90 days. The team also needs to archive expired items to S3 for long-term analytics. Which architecture achieves this with MINIMAL operational overhead?
  • A. Use DynamoDB Export to S3 feature daily to export the full table, then let TTL handle deletion with userIdentity and use Lambda to write to S3
  • B. Create a Global Secondary Index on the TTL attribute and periodically query items near expiration to copy to S3
  • C. Schedule a Lambda function to scan the table hourly and move items older than 90 days to S3 before they expire
  • D. Enable DynamoDB Streams on the table, filter for TTL-deleted events (REMOVE with userIdentity.type = "Service"), and use Lambda to write to S3
Correct Answer: D
DynamoDB Streams captures TTL deletions sebagai event REMOVE with userIdentity.type = "Service" and userIdentity.principalId = "dynamodb.amazonaws.com". Lambda consumer can memfilter event this and writes data to S3 for archival. Ini fully event-driven and minimal overhead.

Option A: INCORRECT. Very expensive for table large and produces data duplikat — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option B: INCORRECT. Not efficient — GSI cannot is used for query items based on time mendekati TTL in a effective.
Option C: INCORRECT. Requires scan that expensive and berisiko race condition with TTL.
Option D: CORRECT.

A data engineer suspends versioning on an S3 bucket that previously had versioning enabled. What happens when a new object is uploaded with the same key as an existing versioned object?
  • A. A new version with a null version ID is created, and the previous null version ID object (if any) is overwritten
  • B. The upload fails because the bucket previously had versioning enabled with a null version ID is created and the previous null version
  • C. A new version with a null version ID is created, and all previous versions are retained, handling the described workload reliably at scale
  • D. The new object overwrites the current version and all previous versions are permanently deleted, handling the described workload reliably at scale
Correct Answer: A
When versioning in-suspend, objek new that diupload mendapat null version ID. If already ada objek with null version ID, objek the said ditimpa. Versi-versi sebelumnya that has version ID non-null still dipertahankan.

Option A: CORRECT.
Option B: INCORRECT. Salah — upload still succeeds — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option C: INCORRECT. Hampir correct but not menyebutkan that null version ID sebelumnya ditimpa.
Option D: INCORRECT. Salah — versi sebelumnya not is deleted automatic. Ini important dipahami: suspend versioning TIDAK deletes versi that already ada.

A company stores machine learning model artifacts in a versioned S3 bucket. The bucket has accumulated thousands of noncurrent versions over two years. The team wants to keep only the 3 most recent noncurrent versions and delete older ones. Which S3 feature should the data engineer use?
  • A. S3 Lifecycle rule with NoncurrentVersionExpiration and NewerNoncurrentVersions set to 3
  • B. S3 Lifecycle rule with AbortIncompleteMultipartUpload set to 3 versions
  • C. S3 Batch Operations to delete all but the 3 most recent versions per object
  • D. S3 Intelligent-Tiering with version management enabled and NewerNoncurrentVersions set to 3
Correct Answer: A
S3 Lifecycle rules supports NoncurrentVersionExpiration with parameter NewerNoncurrentVersions that enables stores sejumlah N versi noncurrent terbaru and deletes that more old. Ini is solution native S3 that most efficient.

Option A: CORRECT.
Option B: INCORRECT. For multipart upload that not complete, not versi.
Option C: INCORRECT. Can is performed but requires management manual and not automatic.
Option D: INCORRECT. Manages storage class not number versi — although its description sounds convincing, in a fundamental still not appropriate for requirements this.

A data engineer observes that DynamoDB TTL is not deleting expired items immediately at the specified expiration time. Some items remain in the table for several hours after their TTL timestamp has passed. The application queries are returning stale data. What is the MOST appropriate solution?
  • A. Increase the table's write capacity units to speed up TTL deletions configured for optimal performance and minimal operational overhead
  • B. Contact AWS Support to increase the TTL deletion throughput for the table, meeting the latency and throughput goals of the design
  • C. Disable and re-enable TTL to reset the background deletion process, integrating natively with the rest of the pipeline
  • D. Add a filter expression in application queries to exclude items where the TTL attribute is less than the current time
Correct Answer: D
DynamoDB TTL not guarantees deletion instan — item usually is deleted in time 48 hours setelah expiration (generally in several hours). Ini by design and cannot dipercepat. Solution that correct is adds filter expression in query application for excludes item that already expired (TTL < current_time).

Option A: INCORRECT. Salah — TTL deletion uses background process that separate from WCU provisioned — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option B: INCORRECT. Not ada mekanisme for increases TTL throughput manually.
Option C: INCORRECT. Not will speeds up process.
Option D: CORRECT.

A healthcare company stores patient records in a versioned S3 bucket. Due to a regulatory requirement, they must ensure that once an object version is deleted, it cannot be recovered. Currently, when users delete objects, only delete markers are created. What must the data engineer do to permanently remove specific object versions?
  • A. Use S3 Batch Operations with the DeleteObject operation without specifying version IDs
  • B. Create a lifecycle rule with an Expiration action targeting the specific objects
  • C. Issue DeleteObject requests specifying the exact version ID for each version to be permanently deleted
  • D. Disable versioning on the bucket, then delete the objects for each version to be permanently deleted
Correct Answer: C
For deletes versi objek in a permanent in bucket with versioning enabled, Anda must sends DeleteObject request with version ID specific. Without version ID, S3 only creates delete marker.

Option A: INCORRECT. Without version ID only will creates delete markers, not deletion permanent.
Option B: INCORRECT. Not can menargetkan objek specific based on key.
Option C: CORRECT.
Option D: INCORRECT. Salah — versioning cannot in-disable, only in-suspend, and that not deletes versi that ada — although its description sounds convincing, in a fundamental still not appropriate for requirements this.

A company has a DynamoDB table with TTL enabled for automatic session cleanup. They want to understand the cost implications of TTL deletions. Which statement about DynamoDB TTL cost is CORRECT?
  • A. TTL deletions consume write capacity units (WCU) from the table's provisioned capacity
  • B. TTL deletions are free but incur additional charges for DynamoDB Streams if enabled
  • C. TTL deletions are charged at 50% of the normal write cost per item deleted
  • D. TTL deletions are free of charge and do not consume any write capacity units
Correct Answer: D
DynamoDB TTL deletions sepenuhnya gratis — not consumes write capacity units and not dikenakan cost. Ini menjadikan TTL way that most cost-effective for deletes data that already expired automatically.

Option A: INCORRECT. Salah — TTL uses background process separate that not affects WCU.
Option B: INCORRECT. Salah — TTL deletions that tercatat in DynamoDB Streams also not menimbulkan cost additional in luar cost normal Streams (cost read from stream still applies if ada consumer).
Option C: INCORRECT. Not ada schema cost such as this.
Option D: CORRECT.
