A data engineer needs to configure an AWS Glue connection to access an Amazon RDS PostgreSQL database in a private subnet. The Glue job fails with a connection timeout error. The RDS security group allows inbound traffic on port 5432 from the Glue connection's security group. What additional security group configuration is required to resolve this issue?
  • A. Add an outbound rule to the Glue security group allowing traffic only on port 5432 to the RDS subnet CIDR
  • B. Add an outbound rule to the RDS security group allowing all traffic to the Glue security group
  • C. Add a self-referencing inbound rule to the Glue connection's security group allowing all TCP traffic from itself
  • D. Add an inbound rule to the Glue security group allowing traffic on port 5432 from the RDS security group
Correct Answer: C
AWS Glue requires self-referencing inbound rule on security group that is used by Glue connection. This is required because Glue ENIs (Elastic Network Interfaces) needs communicates one same other for koordinasi task in cluster. Without self-referencing rule this, Glue executors cannot communicates and job will timeout.

Option A: INCORRECT. Not quite because problem utamanya is komunikasi between Glue ENI.
Option B: INCORRECT. Not is required because security groups bersifat stateful — outbound response traffic automatic is allowed.
Option C: CORRECT.
Option D: INCORRECT. Not is required because Glue that performs connection to RDS, not sebaliknya.

A company has an Amazon Redshift cluster in a VPC that needs to be accessed by data analysts from the corporate network (10.0.0.0/8) and by AWS Glue ETL jobs. The data engineer needs to configure the Redshift cluster's security group. Which set of inbound rules provides the MOST secure configuration?
  • A. Allow port 5439 from 10.0.0.0/8 and allow port 5439 from the Glue connection's security group ID
  • B. Allow all TCP ports from 10.0.0.0/8 and allow all TCP ports from the Glue security group ID
  • C. Allow port 5439 from 0.0.0.0/0 configured for optimal performance and minimal operational overhead
  • D. Allow port 5439 from 10.0.0.0/8 and allow all traffic from the VPC CIDR range
Correct Answer: A
Konfigurasi most secure is provides access only on port that is required (5439 for Redshift) from source that specific: CIDR corporate network for analysts and security group ID for Glue. Security group referencing (SG-to-SG) more secure daripada CIDR because only resource that connected to security group said that is allowed.

Option A: CORRECT.
Option B: INCORRECT. Violates prinsip least privilege.
Option C: INCORRECT. Too permissive and membuka Redshift to internet — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option D: INCORRECT. Too broad — all resource in VPC will can access.

A data engineer deploys a Lambda function in a VPC to process data from an RDS MySQL instance. The Lambda function can successfully connect to RDS but cannot access Amazon S3 to write processed results. The VPC has no internet gateway or NAT gateway. Which solution allows the Lambda function to access S3 without exposing traffic to the public internet?
  • A. Create a VPC Gateway Endpoint for S3 and update the route table associated with the Lambda subnet
  • B. Add an outbound rule in the Lambda security group allowing HTTPS (port 443) to 0.0.0.0/0
  • C. Create a VPC Interface Endpoint for S3 and modify the Lambda security group to allow outbound traffic to the endpoint
  • D. Attach an elastic IP to the Lambda function's ENI for internet access with the Lambda subnet and update the route
Correct Answer: A
VPC Gateway Endpoint for S3 enables access to S3 through AWS private network without internet gateway or NAT gateway. Gateway endpoint not requires changes security group because traffic in-route through route table. This gratis and provides access private to S3.

Option A: CORRECT.
Option B: INCORRECT. Not will succeeds because without internet gateway/NAT, there is no path to internet although security group allows.
Option C: INCORRECT. Also can berfungsi but Gateway Endpoint for S3 simpler, cheaper (gratis), and direkomendasikan AWS.
Option D: INCORRECT. Not possible — Lambda ENI cannot has elastic IP directly — although its description sounds convincing, in a fundamental still not appropriate for requirements this.

An Amazon EMR cluster runs in a VPC private subnet and processes data from multiple sources. The cluster needs to communicate with Amazon S3, Amazon DynamoDB, and an external API on the internet. The data engineer needs to configure security groups for the EMR master and core nodes. Which security group configuration follows AWS best practices for EMR?
  • A. Default EMR-managed security groups with an internet gateway attached to the subnet for all external communications with native S3 integration and optimized data transfer, satisfying strict compliance and audit requirements
  • B. Separate security groups for master and core nodes with required inter-node communication ports, VPC Gateway Endpoints for S3 and DynamoDB, and a NAT gateway for the external API
  • C. One security group for master with all ports open from core nodes SG, one for core nodes with all ports open from master SG, and a NAT gateway for internet access
  • D. A single shared security group for both master and core nodes allowing all internal traffic, with VPC endpoints for all services, protecting the data both in transit and at rest
Correct Answer: B
Best practice for EMR is: (1) Separate security groups for master and core/task nodes with port-port specific that is required for inter-node communication (for example port 8443 for cluster management). (2) VPC Gateway Endpoints for S3 and DynamoDB (gratis, traffic still in AWS network). (3) NAT gateway for access to external API that requires internet.

Option A: INCORRECT. Creates nodes accessible from internet — less secure for private subnet pattern — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option B: CORRECT.
Option C: INCORRECT. Too permissive although between SG itself.
Option D: INCORRECT. Not enables granular control between master and core.

A data engineer is troubleshooting connectivity between an AWS Glue job and an Amazon Redshift Serverless endpoint. Both are in the same VPC. The Glue job uses security group sg-glue and Redshift Serverless uses security group sg-redshift. The current configuration has: sg-redshift inbound allows port 5439 from sg-glue, and sg-glue has default outbound (all traffic allowed). The job still fails to connect. What should the engineer check FIRST?
  • A. Whether the VPC has DNS resolution and DNS hostnames enabled, enforcing encryption and fine-grained access control
  • B. Whether the Redshift Serverless workgroup is configured to be publicly accessible, reducing day-to-day operational effort
  • C. Whether the subnet route table has a route to an internet gateway for all TCP traffic
  • D. Whether the Glue connection's security group (sg-glue) has a self-referencing inbound rule for all TCP traffic
Correct Answer: D
Masalah most umum when Glue connection fails is not adanya self-referencing inbound rule on security group Glue. AWS Glue requires ENI-nya for communicates one same other (inter-node communication), that requires inbound rule from security group that itself (self-referencing). This is requirement specific Glue that often terlewat.

Option A: INCORRECT. Important but usually already enabled by default in VPC.
Option B: INCORRECT. Not relevan because both in VPC that same.
Option C: INCORRECT. Not is required for komunikasi intra-VPC — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option D: CORRECT.

A company has reached the limit of 60 inbound rules on a security group attached to their Amazon RDS instance. Multiple data processing services from different VPC CIDR blocks need access to the database. The engineer cannot increase the limit further. Which approach allows additional services to connect while maintaining security?
  • A. Use a Network ACL (NACL) to allow the additional IP ranges instead of security group rules
  • B. Create a managed prefix list containing all the CIDR blocks and reference it in a single security group rule
  • C. Create a second RDS instance with a different security group for the overflow connections, handling the described workload reliably at scale
  • D. Replace individual CIDR-based rules with security group references, grouping multiple services under shared security groups, enforcing encryption and fine-grained access control
Correct Answer: B
AWS Managed Prefix Lists enables pengelompokan several CIDR blocks to in one object that can direferensikan in one security group rule. This in a effective reduces number rules that is required. Satu rule with prefix list can mencakup many CIDR ranges.

Option A: INCORRECT. Bersifat stateless and apply on subnet level, less granular dibanding security groups, and has limit that same.
Option B: CORRECT.
Option C: INCORRECT. Expensive and adds complexity manajemen data.
Option D: INCORRECT. Bagus if services berada in VPC that same, but not berfungsi for CIDR from VPC different or on-premises.

A data engineer needs to update the security group of a production Amazon Redshift cluster to add a new data pipeline's access without causing any downtime. The current security group has rules allowing access from 3 existing ETL services. Which statement about security group updates is CORRECT?
  • A. New inbound rules take effect immediately, but removal of existing rules only affects new connections
  • B. Security group changes require a cluster reboot to take effect, so maintenance window should be scheduled
  • C. Security group changes propagate within 60 seconds and temporarily block all traffic during propagation
  • D. Security group rule changes take effect immediately on all existing and new connections without requiring restart
Correct Answer: D
Perubahan security group rule in AWS take effect immediately without restart, reboot, or downtime. This applies for penambahan maupun deletion rules, and affects all connection (existing and new). Security groups bersifat stateful — if rule is deleted, connection that already terestablish also will terputus because return traffic not lagi is allowed.

Option A: INCORRECT. Incorrect — deletion rule also affects existing connections.
Option B: INCORRECT. Incorrect — does not need reboot.
Option C: INCORRECT. Incorrect — there is no blocking period during propagation.
Option D: CORRECT.

The security requirement states that tier 1 and tier 3 should not be able to communicate directly with each other. How should the security groups be configured?
  • A. Create two security groups — one for Lambda and Glue, another for Aurora. Aurora SG allows inbound from the shared SG, satisfying strict compliance and audit requirements
  • B. Use one security group for all three tiers with rules restricting port-based access, enforcing encryption and fine-grained access control and handling the described workload reliably at scale
  • C. Create three separate security groups. Aurora SG allows inbound 3306 from Lambda SG and Glue SG. Lambda SG and Glue SG have no rules referencing each other.
  • D. Use Network ACLs to block traffic between Lambda and Glue subnets, with a single security group for all services and Glue SG, enforcing encryption and fine-grained access control
Correct Answer: C
Tiga security groups separate provides isolasi that is required: Aurora SG allows port 3306 from Lambda SG and Glue SG in a separate. Lambda SG and Glue SG not has rules that mereferensikan one same other, so that cannot communicates directly.

Option A: INCORRECT. Creates both berada in security group that same — if there is self-referencing rule, mereka can communicates.
Option B: INCORRECT. Not enables isolasi between tier because all resource in SG that same can communicates.
Option C: CORRECT.
Option D: INCORRECT. Can works but more difficult in-manage and stateless — although its description sounds convincing, in a fundamental still not appropriate for requirements this.

A data engineer configures an Amazon EMR cluster with a custom security group. The EMR cluster needs to access an Amazon RDS MySQL database on port 3306. After launching the cluster, the EMR steps fail to connect to RDS. The engineer verifies that the RDS security group allows inbound port 3306 from the EMR security group. VPC flow logs show that outbound traffic from EMR to RDS is being rejected. What is the MOST likely cause?
  • A. The RDS instance is in a different Availability Zone than the EMR cluster, satisfying strict compliance and audit requirements
  • B. The EMR security group's outbound rules have been modified to restrict traffic, preventing outbound connections to port 3306
  • C. EMR requires an additional managed security group that was not attached to the cluster, enforcing encryption and fine-grained access control
  • D. The Network ACL on the EMR subnet is blocking outbound traffic to the RDS subnet configured for optimal performance and minimal operational overhead
Correct Answer: B
In a default, security groups allows all outbound traffic. However, if engineer uses custom security group and memodifikasi outbound rules (for example only allows port certain), connection outbound to port 3306 can diblok. VPC flow logs mengkonfirmasi that traffic outbound that ditolak — this indicates problem on outbound rules in security group EMR or NACL. Because soal menyebutkan "outbound traffic from EMR is being rejected" and security group has custom rules, possibility large outbound rule EMR SG that restrictive.

Option A: INCORRECT. Not affects connectivity.
Option B: CORRECT.
Option C: INCORRECT. Not causes outbound rejection.
Option D: INCORRECT. Can jadi penyebab, but custom SG outbound restriction is penyebab most umum — although its description sounds convincing, in a fundamental still not appropriate for requirements this.

A company is deploying a data lake architecture where multiple AWS services need to access an Amazon Redshift cluster: AWS Glue for ETL, Amazon QuickSight for visualization, and Lambda functions for data validation. The security team requires that each service has its own security group and only port 5439 is allowed. The engineer wants to simplify security group management as new services are added. Which approach provides the MOST maintainable solution?
  • A. Create a single inbound rule on the Redshift security group using the VPC CIDR range on port 5439, integrating natively with the rest of the pipeline and handling the described workload reliably at scale
  • B. Use AWS Resource Access Manager to share the Redshift security group with all service accounts configured for optimal performance and minimal operational overhead, protecting the data both in transit and at rest
  • C. Create a common "data-access" security group, assign it as an additional security group to all services that need Redshift access, and add one inbound rule on Redshift SG referencing this common SG
  • D. Create individual inbound rules on the Redshift security group referencing each service's security group ID on port 5439, handling the described workload reliably at scale and applying schema conversion and enrichment inline
Correct Answer: C
Creates common "data-access" security group and menambahkannya as additional SG to each service is approach most maintainable. Redshift SG only requires one inbound rule (port 5439 from data-access SG). When service new is added, quite attach data-access SG to service said without memodifikasi Redshift SG.

Option A: INCORRECT. Too broad — all resource in VPC can access.
Option B: INCORRECT. Not for sharing security groups between services in account that same — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option C: CORRECT.
Option D: INCORRECT. Berfungsi but requires penambahan rule new each kali there is service new — less scalable and can hit rule limit.
