A data engineer needs to configure an AWS Glue connection to access an Amazon RDS PostgreSQL database in a private subnet. The Glue job fails with a connection timeout. The RDS security group currently only allows connections from the application's EC2 instances. What must be configured to allow Glue to connect?
  • A. Configure a VPC endpoint for Glue and whitelist the endpoint IP, handling the described workload reliably at scale and protecting the data both in transit and at rest
  • B. Move the RDS instance to a public subnet and allow all inbound traffic configured for optimal performance and minimal operational overhead, enforcing encryption and fine-grained access control
  • C. Add the AWS Glue service IP range to the RDS security group inbound rules, protecting the data both in transit and at rest and minimizing end-to-end processing latency
  • D. Add a self-referencing inbound rule to the Glue connection's security group, and add the Glue security group as an allowed source in the RDS security group
Correct Answer: D
AWS Glue connections uses ENI (Elastic Network Interface) in VPC with security group that is set. Glue requires self-referencing rule (inbound from security group itself) for komunikasi between worker nodes. RDS security group must allows inbound from Glue security group.

Option A: INCORRECT. For access to Glue API, not for Glue accesses resources in VPC.
Option B: INCORRECT. Melanggar security best practices — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option C: INCORRECT. Salah because Glue uses ENI in VPC, not IP range service.
Option D: CORRECT.

The on-premises firewall requires specific IP addresses to be allowlisted for outbound database connections. The DMS replication instance is in a VPC. How should the data engineer determine which IP to allowlist on the on-premises firewall?
  • A. Allowlist the entire AWS IP range for the region and allowlist that EIP on the on-premises firewall, handling the described workload reliably at scale
  • B. Use the DMS replication instance's private IP address, meeting the latency and throughput goals of the design and reducing day-to-day operational effort
  • C. Assign an Elastic IP (EIP) to the DMS replication instance in a public subnet, and allowlist that EIP on the on-premises firewall
  • D. Use the VPC's NAT Gateway public IP address as the allowlisted IP, handling the described workload reliably at scale and reducing day-to-day operational effort
Correct Answer: C
For connection from DMS to source on-premises through internet, DMS replication instance must berada in public subnet with Elastic IP. EIP this static and can in-allowlist in firewall on-premises.

Option A: INCORRECT. Terlalu luas and insecure — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option B: INCORRECT. Not routable through internet to on-premises.
Option C: CORRECT.
Option D: INCORRECT. Can works if replication instance in private subnet but EIP in replication instance more direct.

An AWS Glue ETL job in a VPC needs to access both an S3 bucket and an on-premises database through a VPN connection. The job currently cannot reach S3. The subnet has no internet access. What is the MOST secure solution to allow S3 access?
  • A. Create a VPC Gateway Endpoint for S3 and update the route table of the Glue subnet
  • B. Move the Glue connection to a public subnet with an Internet Gateway, applying schema conversion and enrichment inline
  • C. Allowlist S3 public IP ranges in the security group outbound rules, enforcing encryption and fine-grained access control
  • D. Add a NAT Gateway and route internet traffic through it and update the route table of the Glue subnet
Correct Answer: A
VPC Gateway Endpoint for S3 enables access to S3 without internet, maintains traffic in in AWS network. Route table in-update for mengarahkan traffic S3 through endpoint. Ini most secure because traffic not pernah meninggalkan AWS network.

Option A: CORRECT.
Option B: INCORRECT. Adds attack surface.
Option C: INCORRECT. Security groups are stateful and allow all outbound by default; masalahnya routing not security group.
Option D: INCORRECT. Enables internet access that more luas from that is required — although its description sounds convincing, in a fundamental still not appropriate for requirements this.

A company's data pipeline connects to a third-party SaaS API that rotates its IP addresses frequently. The data engineer needs to allowlist these IPs in the VPC security group, but manual updates are not feasible. Which approach automates IP allowlist management?
  • A. Configure the security group with the domain name instead of IP addresses
  • B. Use a prefix list that automatically resolves domain names to IPs with domain-based filtering rules instead
  • C. Use AWS Network Firewall with domain-based filtering rules instead of IP-based security groups
  • D. Use AWS Lambda triggered by DNS resolution changes (via Route 53 health checks) to automatically update security group rules with current IPs
Correct Answer: C
AWS Network Firewall supports domain name filtering (stateful rule groups) that automatically resolve domain to IP saat evaluasi. This is ideal when IPs changes often because rules based on domain name, not static IPs.

Option A: INCORRECT. Not supported - security groups only receives IP/CIDR, not domain names.
Option B: INCORRECT. Not resolve DNS - only contains static CIDR blocks — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option C: CORRECT.
Option D: INCORRECT. Can works but very custom and fragile.

A data engineer needs to allow an Amazon EMR cluster in a private subnet to access a partner's SFTP server on the internet. The partner requires the company to provide static IP addresses for their firewall allowlist. How should this be architected?
  • A. Configure a VPN connection to the partner and use the VPN endpoint IP, satisfying all of the stated requirements with minimal effort and providing exactly-once processing semantics
  • B. Place the EMR cluster in a private subnet with a NAT Gateway in the public subnet; provide the NAT Gateway's Elastic IP to the partner
  • C. Assign Elastic IPs to all EMR cluster nodes and provide those to the partner with a NAT Gateway in the public subnet; provide the NAT Gateway's Elastic IP
  • D. Use AWS PrivateLink to establish a private connection to the partner's SFTP server, satisfying all of the stated requirements with minimal effort and minimizing end-to-end processing latency
Correct Answer: B
NAT Gateway has Elastic IP that static. All outbound traffic from private subnet to internet melewati NAT Gateway, so that partner will always melihat connection from NAT Gateway's EIP. Ini provides satu static IP for allowlisting.

Option A: INCORRECT. Over-engineering for SFTP access.
Option B: CORRECT.
Option C: INCORRECT. Not feasible because EMR nodes can auto-scale and private subnet nodes cannot punya public IP — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option D: INCORRECT. Requires partner also in AWS and mengekspos NLB.

A data pipeline uses AWS Lambda in a VPC to connect to an on-premises database through AWS Direct Connect. The on-premises team reports that they see connections from many different IP addresses and cannot create a stable allowlist. What causes this issue and how should it be resolved?
  • A. Configure the on-premises firewall to allow the entire VPC CIDR range
  • B. Assign static IP addresses to Lambda functions directly
  • C. Lambda functions use multiple ENIs with different private IPs; configure a NAT Gateway in the VPC so all Lambda traffic egresses from a single private IP over Direct Connect
  • D. Use Lambda reserved concurrency to limit the number of ENIs
Correct Answer: A
Lambda functions in VPC uses Hyperplane ENIs with IPs from subnet CIDR. Because Lambda can creates many ENIs with IPs different (depends concurrency), solution most praktis is allows entire VPC CIDR range (that usually is private IP range certain) in firewall on-premises.

Option A: CORRECT.
Option B: INCORRECT. Not may — Lambda not supports static IP assignment.
Option C: INCORRECT. For Direct Connect traffic, NAT Gateway not is used because traffic already private-to-private.
Option D: INCORRECT. Membatasi performa.

  • B. Configure Kinesis VPC allowlist in the stream settings with aws:SourceIp condition

  • D. Use IAM policy with aws:SourceIp condition to restrict access to specific CIDR ranges
Correct Answer: D
IAM policy with aws:SourceIp condition limits access API to Kinesis based on source IP address. Ini can is applied on IAM role/user that is used consumer application. For cross-region access, this is mekanisme that effective because Kinesis is service managed that not has security group itself.

Option A: INCORRECT. Salah — Kinesis not has security group.
Option B: INCORRECT. Fitur this there is no in Kinesis — although its description sounds convincing, in a fundamental still not appropriate for requirements this.

A data engineer manages an Amazon RDS MySQL instance that must accept connections from multiple AWS services: AWS Glue, Lambda, and an EC2-based application. Each service runs in different security groups within the same VPC. What is the MOST maintainable way to configure the RDS security group?
  • A. Add individual IP addresses of each Glue ENI, Lambda ENI, and EC2 instance, enforcing encryption and fine-grained access control and providing exactly-once processing semantics
  • B. Use a managed prefix list containing all service IP ranges configured for optimal performance and minimal operational overhead, enforcing encryption and fine-grained access control
  • C. Add three inbound rules referencing each service's security group ID as the source (Glue SG, Lambda SG, EC2 SG) on port 3306
  • D. Add one inbound rule allowing the entire VPC CIDR range on port 3306, protecting the data both in transit and at rest
Correct Answer: C
Security group references (SG-to-SG rules) is best practice because rules still valid even when IP addresses changes. Each resource that uses SG that in-reference automatically mendapat access. Ini most maintainable because does not need update when instances changes.

Option A: INCORRECT. Not maintainable because ENI IPs changes.
Option B: INCORRECT. For static CIDR ranges, not dynamic service IPs — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option C: CORRECT.
Option D: INCORRECT. Terlalu luas and melanggar least privilege.
