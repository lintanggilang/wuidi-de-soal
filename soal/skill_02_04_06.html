A company wants to build a customer support chatbot that can answer questions based on their internal documentation (10,000+ PDF documents stored in S3). The chatbot must provide accurate, contextual answers grounded in the company's actual documentation rather than general knowledge. Which AWS approach provides the MOST effective implementation of Retrieval-Augmented Generation (RAG)?
  • A. Fine-tune an Amazon Bedrock foundation model on all 10,000 documents
  • B. Create an Amazon Bedrock Knowledge Base that automatically chunks, embeds, and indexes documents, then use it with a foundation model for RAG
  • C. Store all documents in Amazon Kendra and use keyword search to find relevant passages before sending to a language model
  • D. Load all documents into the LLM's context window at query time for accurate responses with a foundation model for RAG
Jawaban Benar: B
Amazon Bedrock Knowledge Bases menyediakan solusi RAG end-to-end yang otomatis: memecah dokumen menjadi chunks, membuat vector embeddings, menyimpannya di vector store, dan melakukan semantic search pada query time untuk menemukan konteks relevan yang dikirim ke foundation model. Opsi A (fine-tuning) mahal, memerlukan waktu lama, dan tidak update otomatis saat dokumen berubah. Opsi C (Kendra keyword search) kurang efektif untuk semantic understanding dibandingkan vector similarity search. Opsi D tidak mungkin karena context window memiliki batas token yang tidak bisa menampung 10,000 dokumen.
2
A data engineer is configuring an Amazon Bedrock Knowledge Base and needs to choose a chunking strategy for their document corpus. The documents include both long technical manuals (500+ pages) and short FAQ entries (1-2 paragraphs). Which chunking strategy is MOST appropriate for this mixed-length corpus?
  • A. Fixed-size chunking with 300 tokens per chunk for all documents
  • B. Hierarchical chunking that creates parent chunks with larger context and child chunks with specific details
  • C. No chunking — store each document as a single vector embedding configured for optimal performance and minimal
  • D. Semantic chunking that splits documents based on topic boundaries detected by the embedding model
Jawaban Benar: D
Semantic chunking memecah dokumen berdasarkan batas topik yang dideteksi oleh perubahan signifikan dalam embedding similarity antar kalimat berurutan. Ini ideal untuk corpus campuran karena secara otomatis menyesuaikan ukuran chunk berdasarkan konten — FAQ pendek mungkin menjadi satu chunk, sementara manual teknis dipecah di batas topik alami. Opsi A (fixed-size) akan memecah FAQ secara tidak tepat dan mungkin memotong konteks di manual. Opsi B (hierarchical) berguna tapi lebih kompleks dan belum tentu menangani variasi ukuran dokumen sebaik semantic chunking. Opsi C (no chunking) membuat embeddings terlalu general untuk dokumen panjang, kehilangan detail spesifik.

A machine learning team needs to select an embedding model for their RAG application that will handle multilingual customer inquiries (English, Japanese, Spanish, and Arabic). The vector database has storage constraints, so embedding dimensions should be minimized while maintaining quality. Which Amazon Bedrock embedding model selection is MOST appropriate?
  • A. Amazon Titan Text Embeddings V2 with configurable output dimensions set to 256 for storage efficiency
  • B. Cohere Embed English v3 with 1024 dimensions for highest accuracy configured for optimal performance and minimal
  • C. Amazon Titan Text Embeddings V1 with fixed 1536 dimensions
  • D. Amazon Titan Multimodal Embeddings for handling diverse content types
Jawaban Benar: A
Amazon Titan Text Embeddings V2 mendukung multilingual content dan memiliki fitur configurable output dimensions (256, 512, atau 1024) yang memungkinkan tradeoff antara storage efficiency dan quality. Dimensi 256 sangat cocok untuk use case dengan storage constraints sambil tetap mempertahankan kualitas yang baik untuk retrieval. Opsi B (Cohere Embed English) hanya optimal untuk English, tidak multilingual. Opsi C (Titan V1) memiliki fixed 1536 dimensions yang boros storage. Opsi D (Multimodal) dirancang untuk image+text, overkill untuk text-only queries.

A data engineer is designing a vector storage solution for a RAG application that will serve 10,000 concurrent users with sub-100ms latency requirements. The vector corpus contains 50 million embeddings of 1536 dimensions. Which AWS vector storage option BEST meets these requirements?
  • A. Amazon Aurora PostgreSQL with pgvector extension with fully managed
  • B. Amazon OpenSearch Serverless with vector search collection type
  • C. Amazon S3 with a custom similarity search Lambda function
  • D. Amazon DynamoDB with vector embeddings stored as binary attributes
Jawaban Benar: B
Amazon OpenSearch Serverless dengan vector search collection type dirancang untuk high-concurrency, low-latency vector similarity search. Serverless mode otomatis scales untuk menangani 10,000 concurrent users, dan arsitektur-nya dioptimalkan untuk approximate nearest neighbor (ANN) search pada scale besar (50M vectors). Opsi A (Aurora pgvector) baik untuk smaller scales tapi akan struggle dengan 50M vectors pada 10K concurrent users tanpa significant tuning. Opsi C (S3 + Lambda) tidak bisa memberikan sub-100ms latency untuk similarity search pada 50M vectors. Opsi D (DynamoDB) tidak memiliki native vector similarity search capabilities.

A recommendation engine needs to find the top-10 most similar products to a given product based on their feature embeddings. The similarity metric must capture the directional relationship between vectors regardless of their magnitude (e.g., a product described briefly should match a similar product described in detail). Which similarity metric is MOST appropriate?
  • A. Euclidean distance (L2) because it measures absolute distance between vector endpoints
  • B. Cosine similarity because it measures the angle between vectors independent of magnitude
  • C. Dot product because it accounts for both direction and magnitude configured for optimal performance
  • D. Manhattan distance (L1) because it is computationally cheaper for high-dimensional vectors
Jawaban Benar: B
Cosine similarity mengukur sudut antara dua vektor, tidak bergantung pada magnitude (panjang) vektor. Ini ideal ketika Anda ingin membandingkan "arah" atau makna semantik tanpa dipengaruhi oleh panjang deskripsi. Produk yang dideskripsikan singkat vs detail akan memiliki vectors dengan magnitude berbeda tapi arah yang sama jika kontennya serupa. Opsi A (Euclidean) dipengaruhi oleh magnitude sehingga deskripsi panjang vs pendek akan terlihat "jauh". Opsi C (Dot product) juga dipengaruhi magnitude. Opsi D (Manhattan) juga magnitude-dependent dan kurang umum untuk semantic similarity.

A legal firm has set up an Amazon Bedrock Knowledge Base backed by Amazon OpenSearch Serverless. They notice that when source documents are updated or deleted from their S3 data source, the Knowledge Base still returns outdated information in RAG responses. What should the data engineer configure to keep embeddings synchronized with source data?
  • A. Enable S3 event notifications to trigger a Lambda function that calls the Knowledge Base sync API whenever objects change
  • B. Configure the Knowledge Base data source sync to run on a schedule or trigger manual sync after document updates
  • C. Delete and recreate the entire Knowledge Base whenever documents change
  • D. Configure S3 versioning and the Knowledge Base will automatically detect version changes configured for optimal performance
Jawaban Benar: B
Amazon Bedrock Knowledge Bases mendukung data source syncing yang dapat dijadwalkan atau dipicu secara manual. Proses sync mendeteksi dokumen baru, yang diubah, dan yang dihapus, kemudian memperbarui embeddings di vector store sesuai perubahan. Opsi A terlalu kompleks dan Knowledge Base sudah menyediakan built-in sync mechanism. Opsi C sangat tidak efisien dan menyebabkan downtime. Opsi D salah — S3 versioning saja tidak memicu re-embedding otomatis tanpa proses sync.

A data engineer is building a vectorization pipeline for an enterprise search application. Documents from various sources (Confluence, SharePoint, S3) need to be converted to embeddings and stored in a vector database. The pipeline must handle incremental updates efficiently without re-processing unchanged documents. Which architecture pattern is MOST appropriate?
  • A. Batch process all documents nightly using AWS Glue, generating embeddings for the entire corpus each time
  • B. Use change data capture patterns to detect modified documents, then process only changed documents through an embedding pipeline that upserts to the vector store
  • C. Generate embeddings on-the-fly at query time for each document rather than pre-computing them configured for optimal performance and minimal operational overhead
  • D. Store raw documents in the vector database and let the database generate embeddings internally
Jawaban Benar: B
Change data capture (CDC) pattern untuk mendeteksi dokumen yang berubah, kemudian hanya memproses perubahan melalui embedding pipeline dan melakukan upsert ke vector store, adalah pendekatan paling efisien. Ini menghindari re-processing dokumen yang tidak berubah, menghemat waktu dan biaya embedding API calls. Opsi A (full reprocess nightly) sangat wasteful untuk large corpus yang jarang berubah seluruhnya. Opsi C (query-time embedding) menambahkan latensi signifikan ke setiap query. Opsi D tidak realistis — vector databases umumnya tidak generate embeddings secara internal.

A healthcare company stores patient research papers in S3 and uses Amazon Bedrock Knowledge Base for their medical research assistant. Researchers report that the assistant sometimes returns irrelevant results when searching for specific drug interactions. The embedding model used is Amazon Titan Text Embeddings V2 with 1024 dimensions. What is the MOST likely cause and solution?
  • A. The embedding dimensions are too high; reduce to 256 to improve retrieval precision configured for optimal performance and minimal operational overhead
  • B. The chunking strategy produces chunks that are too large, mixing multiple topics in a single embedding; use smaller, more focused chunks
  • C. The similarity threshold is too low; increase it to filter out less relevant results
  • D. Amazon Titan embeddings are not suitable for medical text; switch to a domain-specific model
Jawaban Benar: B
Ketika chunks terlalu besar, satu embedding mewakili multiple topics yang dicampur bersama, menghasilkan "diluted" vector yang kurang spesifik untuk topik manapun. Ini menyebabkan irrelevant results karena embedding tidak cukup terfokus pada satu topik (seperti drug interactions). Solusinya adalah menggunakan chunks yang lebih kecil dan terfokus. Opsi A salah — mengurangi dimensi justru kehilangan informasi. Opsi C (threshold) bisa membantu sedikit tapi tidak menyelesaikan root cause bahwa embeddings sendiri kurang spesifik. Opsi D tidak diperlukan — Titan V2 capable untuk medical text jika chunking benar.

A data engineer needs to implement a hybrid search approach for an e-commerce product catalog that combines vector semantic search with traditional keyword matching. Some queries are better served by exact keyword matches (e.g., SKU numbers, brand names) while others benefit from semantic understanding (e.g., "comfortable shoes for standing all day"). Which AWS service natively supports this hybrid search pattern?
  • A. Amazon OpenSearch Service with both k-NN vector search and BM25 text search combined using score normalization
  • B. Amazon Aurora PostgreSQL with pgvector for semantic search and standard SQL LIKE queries for keywords
  • C. Two separate searches — Amazon Kendra for keywords and Bedrock Knowledge Base for semantic — with results merged in Lambda
  • D. Amazon DynamoDB with both vector embeddings and keyword indexes configured and BM25 text search combined using score normalization
Jawaban Benar: A
Amazon OpenSearch Service secara native mendukung hybrid search yang mengkombinasikan k-NN vector search (semantic) dengan BM25 text scoring (keyword) dalam single query. Score normalization memungkinkan penggabungan results dari kedua metode secara seamless. Opsi B bisa dilakukan tapi memerlukan custom logic untuk menggabungkan scores dari dua tipe query yang berbeda. Opsi C (dua service terpisah) menambah latency dan complexity dalam result merging. Opsi D salah — DynamoDB tidak mendukung native vector search atau full-text search.
10
A financial services company uses Amazon Aurora PostgreSQL with pgvector to store embeddings for their document search application. As the number of vectors grows to 10 million, they notice that exact nearest neighbor search queries (using the <=> operator) are taking over 5 seconds. They need sub-second query performance while accepting a small accuracy tradeoff. Which optimization should they implement?
  • A. Increase the Aurora instance size to provide more memory for vector operations configured for optimal performance and minimal operational overhead
  • B. Create an HNSW (Hierarchical Navigable Small World) index on the vector column for approximate nearest neighbor search
  • C. Partition the vector table by a categorical column and search only relevant partitions
  • D. Reduce the vector dimensions from 1536 to 256 to decrease computational overhead
Jawaban Benar: B
HNSW (Hierarchical Navigable Small World) index adalah algoritma ANN (Approximate Nearest Neighbor) yang membuat graph structure multi-layer untuk navigasi cepat menuju neighbors terdekat. Dengan HNSW index, pgvector dapat melakukan similarity search dalam sub-second pada 10M vectors dengan accuracy trade-off minimal (recall >95%). Opsi A (scale up) membantu sedikit tapi exact search tetap O(n) yang tidak scalable. Opsi C (partitioning) membantu jika ada filter yang baik tapi tidak menyelesaikan masalah dasar exact search. Opsi D (reduce dimensions) mengurangi kualitas retrieval secara signifikan dan masih memerlukan linear scan tanpa index.
