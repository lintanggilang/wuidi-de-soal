1
A large enterprise has multiple business units — Marketing, Finance, and Engineering — each with distinct data governance requirements. They want to implement Amazon DataZone (SageMaker Unified Studio) to enable data sharing while maintaining organizational boundaries. Which construct should they use to represent each business unit's top-level governance boundary?
  • A. Create a separate DataZone Project for each business unit
  • B. Create a single DataZone Domain and use Domain Units to represent each business unit's governance boundary
  • C. Create separate AWS accounts for each business unit instead of using DataZone
  • D. Create a single DataZone Domain with Environment Profiles for each business unit
Jawaban Benar: B
Domain Units dalam DataZone/SageMaker Unified Studio dirancang khusus untuk merepresentasikan organizational boundaries di dalam sebuah Domain. Domain adalah top-level container yang merepresentasikan keseluruhan perusahaan, sedangkan Domain Units merepresentasikan subdivisi seperti business units atau departments. Setiap Domain Unit dapat memiliki: (1) Governance policies tersendiri, (2) Data steward/owner assignments, (3) Approval workflows untuk data access, (4) Hierarchical structure (nested domain units). Opsi A (Projects) salah — Projects adalah collaboration environments untuk tim yang bekerja bersama, bukan governance boundaries. Opsi C (separate accounts) tidak leverage DataZone's built-in governance capabilities. Opsi D (Environment Profiles) salah — Environment Profiles mendefinisikan compute configurations, bukan governance boundaries.
2
A data mesh architecture team uses Amazon DataZone. The Analytics team has published a "Customer 360" dataset to the DataZone catalog. The Marketing team wants to access this dataset for campaign analysis. What is the correct workflow for the Marketing team to gain access through DataZone's governance model?
  • A. The Marketing team directly accesses the S3 location of the Customer 360 dataset using IAM permissions
  • B. The Marketing team discovers the asset in the DataZone catalog, submits a subscription request specifying the business justification, and the data owner/steward in the Analytics domain unit approves or rejects the request
  • C. The DataZone administrator grants blanket access to all published datasets for all domain units
  • D. The Marketing team creates their own copy of the dataset by running a Glue ETL job
Jawaban Benar: B
DataZone mengimplementasikan publish-subscribe governance model: (1) Data Producer (Analytics) publishes asset ke catalog, (2) Data Consumer (Marketing) discovers asset, (3) Consumer submits subscription request dengan business justification, (4) Data Owner/Steward reviews dan approves/rejects, (5) Setelah approved, DataZone automatically provisions access (creates grants) sehingga consumer's project environment dapat mengakses data. Workflow ini ensures: auditability (siapa minta akses, kapan, kenapa), governance control (owner approval), automated provisioning (no manual IAM policy updates). Opsi A bypasses governance model. Opsi C violates least-privilege principle. Opsi D tidak mengikuti proper data sharing workflow dan bisa violate data governance policies.
3
A data engineer is setting up a new DataZone project for the Data Science team. The project needs access to Athena for querying, Redshift for analytics, and a SageMaker notebook environment. Which DataZone construct defines the available compute environments for this project?
  • A. Domain Policies
  • B. Environment Profiles — which define blueprint templates for compute environments that projects can provision (e.g., Athena environment, Redshift environment, SageMaker environment)
  • C. Domain Units
  • D. Subscription Grants
Jawaban Benar: B
Environment Profiles dalam DataZone mendefinisikan template untuk compute environments yang dapat di-provision oleh projects. Setiap Environment Profile mencakup: (1) Blueprint type (Athena, Redshift, SageMaker, dll.), (2) Configuration parameters (instance types, cluster settings), (3) IAM roles dan permissions yang akan di-provision, (4) Network configuration (VPC, subnets). Project members dapat membuat Environment dari available Profiles. Saat subscription di-approve, DataZone secara otomatis grants access melalui environment yang sesuai. Opsi A (Domain Policies) mengatur governance rules bukan compute configuration. Opsi C (Domain Units) adalah organizational boundaries. Opsi D (Subscription Grants) adalah mechanism setelah approval untuk memberikan akses ke data, bukan compute environment definition.
4
A company has DataZone configured with the following hierarchy: Domain "Acme Corp" → Domain Unit "Finance" → Project "Revenue Analytics". A data steward in the Finance domain unit publishes a sensitive revenue dataset. They want to ensure that ONLY projects within the Finance domain unit can subscribe to this dataset, and no other domain units (Marketing, Engineering) can even discover it. How should this be configured?
  • A. Set the asset visibility at the Domain level so only the Finance domain unit can see it
  • B. Configure the publishing settings to restrict the asset's visibility and subscription scope to the owning domain unit only, ensuring the catalog listing is not visible to members of other domain units
  • C. Remove all other domain units from the DataZone domain
  • D. Encrypt the dataset with a KMS key that only Finance team can access
Jawaban Benar: B
DataZone allows publishers to control asset visibility and subscription scope. When publishing an asset, the data steward can restrict: (1) Discovery scope — who can see the asset in the catalog (domain unit level restriction), (2) Subscription scope — who can request access. Dengan membatasi visibility ke Finance domain unit only, members dari Marketing/Engineering domain units tidak akan menemukan asset ini di catalog search. Ini implements "need-to-know" principle pada data discovery level, bukan hanya access level. Opsi A terlalu vague dan Domain-level visibility terlalu broad. Opsi C (remove domain units) akan menghancurkan seluruh organizational structure. Opsi D (KMS encryption) adalah access control at infrastructure layer tapi tidak mencegah discovery di catalog — users masih bisa melihat metadata.
5
A data engineer needs to enable cross-account data sharing between two AWS accounts using DataZone. Account A (Production) hosts the data lake, and Account B (Analytics) needs to query production data. Both accounts are in the same DataZone domain. What is the recommended approach?
  • A. Copy data from Account A to Account B using S3 replication and manage access independently
  • B. Account A's domain unit publishes data assets to the DataZone catalog; Account B's project subscribes to those assets through the governance workflow; DataZone automatically manages the cross-account IAM grants and Lake Formation permissions needed for access
  • C. Create VPC peering between Account A and Account B and access databases directly
  • D. Share AWS credentials from Account A with users in Account B
Jawaban Benar: B
DataZone natively supports cross-account data sharing within the same domain. The workflow: (1) Account A registers as a data source and publishes assets, (2) Account B's project discovers and requests subscription, (3) After approval, DataZone automatically provisions cross-account access — typically using AWS Lake Formation cross-account grants, RAM shares, or cross-account IAM roles depending on the data source type. Key benefit: centralized governance — all access is auditable, revocable, and managed through single governance plane regardless of AWS account boundaries. Opsi A (S3 replication) creates data duplication, increases costs, dan bypasses governance. Opsi C (VPC peering) addresses network connectivity, bukan data governance. Opsi D (credential sharing) is a severe anti-pattern yang violates security best practices.
6
A DataZone administrator needs to assign roles within a project. The project has: a Project Owner who manages settings, Data Engineers who build pipelines, and Business Analysts who only query data. Which DataZone role-based access model correctly maps these responsibilities?
  • A. All users get the same "Project Member" role with identical permissions
  • B. Project Owner role (manages project settings, environments, and membership), Project Contributor role for Data Engineers (can create/manage assets, publish data, request subscriptions), and Project Viewer/Consumer role for Business Analysts (can browse catalog, subscribe to data, and query through provisioned environments)
  • C. Create separate DataZone domains for each role type
  • D. Use IAM policies exclusively without DataZone roles
Jawaban Benar: B
DataZone projects support role-based access with different permission levels: Project Owner: Full control — manage project settings, add/remove members, configure environments, approve requests within project scope. Project Contributor: Active participant — create assets, publish data, run jobs, request subscriptions, manage environments they've created. Project Viewer/Reader: Consumption-focused — browse available data, request subscriptions, query data through provisioned environments, but cannot publish or modify assets. Ini memungkinkan least-privilege access di dalam project. Opsi A (same role) violates least privilege. Opsi C (separate domains per role) adalah over-engineering dan breaks collaboration. Opsi D (IAM only) doesn't leverage DataZone's data governance capabilities dan fine-grained project-level control.
7
A company has deployed DataZone and wants to implement a data governance policy where all datasets containing PII must be reviewed by the Privacy team before being made available to any consumer. The Privacy team sits in the "Compliance" domain unit. How should this governance workflow be configured?
  • A. Add a tag "PII" to datasets and use IAM policies to restrict access based on resource tags
  • B. Configure approval workflows in DataZone so that subscription requests for PII-tagged assets require approval from both the data owner AND the Compliance domain unit steward before access is granted
  • C. Store all PII datasets in a separate S3 bucket with no DataZone integration
  • D. Create a separate DataZone domain exclusively for PII data
Jawaban Benar: B
DataZone supports configurable approval workflows yang dapat memerlukan multi-level approvals. Untuk PII datasets: (1) Assets diberi metadata/glossary terms indicating PII classification, (2) Subscription request policies dikonfigurasi sehingga PII-classified assets memerlukan approval dari multiple approvers, (3) Data Owner approves dari business relevance perspective, (4) Compliance domain unit steward approves dari privacy/regulatory perspective. Hanya setelah SEMUA approvers menyetujui, DataZone provisions access. Ini memastikan governance tanpa blocking legitimate access. Opsi A (IAM tags) bekerja di infrastructure level tapi tidak menyediakan business-level approval workflow. Opsi C (separate bucket) isolates data tapi removes it from governed sharing. Opsi D (separate domain) makes cross-domain sharing unnecessarily complex.
8
A data engineer is troubleshooting an access issue in DataZone. A user in "Project Alpha" successfully subscribed to a dataset, but when they try to query it through their Athena environment, they get an "Access Denied" error. The subscription status shows "Approved". What is the MOST likely cause?
  • A. The DataZone subscription was revoked after initial approval
  • B. The Environment within the project has not been properly provisioned with the subscription grant — the environment profile may not have the correct IAM role or Lake Formation permissions to access the underlying data location, even though the subscription is approved at the DataZone governance layer
  • C. Athena does not support DataZone integration
  • D. The user needs to manually add S3 bucket policy permissions
Jawaban Benar: B
DataZone operates at two levels: (1) Governance layer — subscription approval, catalog management; (2) Infrastructure layer — actual IAM/Lake Formation permissions provisioned to environments. Jika subscription approved tapi access denied saat query: masalahnya kemungkinan di provisioning layer. Common causes: Environment profile's IAM role tidak memiliki Lake Formation permissions ke underlying table/database, Subscription grant fulfillment gagal (race condition atau misconfiguration), Lake Formation resource-link belum terbuat di consumer's Glue catalog, Environment blueprint tidak properly configured untuk handle subscription grants. Troubleshooting: check DataZone subscription grant status detail, verify Lake Formation permissions pada environment's execution role. Opsi A — status menunjukkan "Approved" jadi belum revoked. Opsi C salah — Athena adalah primary DataZone environment type. Opsi D — manual bucket policy seharusnya tidak diperlukan; DataZone automates ini.
9
An organization wants to implement the "data mesh" pattern using DataZone. Each team (domain) should be able to independently manage their data products while adhering to organization-wide governance standards. How does DataZone's domain-project hierarchy support this pattern?
  • A. By creating completely separate DataZone instances for each team with no cross-connectivity
  • B. The Domain provides organization-wide governance policies and catalog; Domain Units represent autonomous teams that manage their own data products and publishing policies; Projects within domain units provide the collaboration workspace where teams build, publish, and manage their data products independently while inheriting organizational governance standards
  • C. By using only IAM permission boundaries without DataZone
  • D. By creating one large project containing all teams with shared governance
Jawaban Benar: B
DataZone's hierarchy maps perfectly ke data mesh principles: Domain = Organization (federated governance plane): Provides centralized catalog, shared glossary/metadata standards, organization-wide policies. Domain Units = Autonomous Teams/Business Domains: Each team independently manages their data products, defines local governance (who can publish, approval workflows), assigns data stewards. Projects = Data Product Workspaces: Teams build pipelines, prepare data, publish data products to catalog, manage lifecycle. Key data mesh alignment: (1) Domain ownership — teams own their domain units, (2) Data as product — publishing workflow makes data discoverable, (3) Self-serve infrastructure — environment profiles provide compute, (4) Federated governance — domain-level standards inherited by all units. Opsi A breaks cross-domain discovery. Opsi C lacks governance features. Opsi D centralizes everything (anti-mesh).
10
A data governance team is evaluating how DataZone handles asset metadata and lineage across domain boundaries. Team A (in Domain Unit "Sales") publishes a curated "Customer Segments" dataset. Team B (Domain Unit "Marketing") subscribes and creates a derived "Campaign Targets" dataset from it. How does DataZone track this cross-domain-unit data lineage?
  • A. DataZone does not support cross-domain-unit lineage tracking; each domain unit's data is independent
  • B. DataZone maintains catalog-level lineage through subscription relationships — the "Campaign Targets" asset can reference its source subscription to "Customer Segments", establishing provenance; combined with Glue Data Catalog lineage capabilities, this provides end-to-end lineage visibility across domain units within the same domain
  • C. Lineage is only tracked within a single project and cannot span multiple domain units
  • D. Third-party tools are required because AWS services cannot track lineage
Jawaban Benar: B
DataZone provides catalog-level lineage tracking across organizational boundaries. The lineage chain: (1) "Customer Segments" published by Sales domain unit — tracked as source asset. (2) Subscription relationship recorded — Marketing subscribed to this asset (who, when, why). (3) Marketing's derived "Campaign Targets" can declare its upstream dependency on "Customer Segments". (4) DataZone catalog shows the data flow: Sales → subscription → Marketing → derived product. Kombinasi dengan AWS Glue Data Catalog lineage (yang tracks transformations di ETL level) memberikan end-to-end visibility. Ini critical untuk: impact analysis (jika source berubah, siapa affected?), compliance auditing (data provenance), dan quality management. Opsi A salah — cross-domain lineage didukung. Opsi C salah — lineage bisa span domain units. Opsi D salah — AWS provides native lineage capabilities.
