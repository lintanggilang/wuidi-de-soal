A data mesh architecture team uses Amazon DataZone. The Analytics team has published a "Customer 360" dataset to the DataZone catalog. The Marketing team wants to access this dataset for campaign analysis. What is the correct workflow for the Marketing team to gain access through DataZone's governance model?
  • A. The Marketing team discovers the asset in the DataZone catalog, submits a subscription request specifying the business justification, and the data owner/steward in the Analytics domain unit approves or rejects the request
  • B. The Marketing team directly accesses the S3 location of the Customer 360 dataset using IAM permissions, meeting the latency and throughput goals of the design and handling the described workload reliably at scale
  • C. The Marketing team creates their own copy of the dataset by running a Glue ETL job configured for optimal performance and minimal operational overhead, handling the described workload reliably at scale
  • D. The DataZone administrator grants blanket access to all published datasets for all domain units, satisfying all of the stated requirements with minimal effort and meeting the latency and throughput goals of the design
Correct Answer: A
DataZone implements publish-subscribe governance model: (1) Data Producer (Analytics) publishes asset to catalog, (2) Data Consumer (Marketing) discovers asset, (3) Consumer submits subscription request with business justification, (4) Data Owner/Steward reviews and approves/rejects, (5) Setelah approved, DataZone automatically provisions access (creates grants) so that consumer's project environment can accesses data. Workflow this ensures: auditability (who minta access, when, kenapa), governance control (owner approval), automated provisioning (no manual IAM policy updates).

Option A: CORRECT.
Option B: INCORRECT. Bypasses governance model.
Option C: INCORRECT. Not mengikuti proper data sharing workflow and can violate data governance policies — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option D: INCORRECT. Violates least-privilege principle.

A data engineer needs to enable cross-account data sharing between two AWS accounts using DataZone. Account A (Production) hosts the data lake, and Account B (Analytics) needs to query production data. Both accounts are in the same DataZone domain. What is the recommended approach?
  • A. Share AWS credentials from Account A with users in Account B, satisfying all of the stated requirements with minimal effort and meeting the latency and throughput goals of the design and handling the described workload reliably at scale
  • B. Copy data from Account A to Account B using S3 replication and manage access independently, satisfying all of the stated requirements with minimal effort and integrating natively with the rest of the pipeline and providing exactly-once processing semantics
  • C. Create VPC peering between Account A and Account B and access databases directly and Lake Formation permissions needed for access for access, integrating natively with the rest of the pipeline and handling the described workload reliably at scale
  • D. Account A's domain unit publishes data assets to the DataZone catalog; Account B's project subscribes to those assets through the governance workflow; DataZone automatically manages the cross-account IAM grants and Lake Formation permissions needed for access
Correct Answer: D
DataZone natively supports cross-account data sharing within the same domain. The workflow: (1) Account A registers as a data source and publishes assets, (2) Account B's project discovers and requests subscription, (3) After approval, DataZone automatically provisions cross-account access — typically using AWS Lake Formation cross-account grants, RAM shares, or cross-account IAM roles depending on the data source type. Key benefit: centralized governance — all access is auditable, revocable, and managed through single governance plane regardless of AWS account boundaries.

Option A: INCORRECT. Is a severe anti-pattern that violates security best practices.
Option B: INCORRECT. Creates data duplication, increases costs, and bypasses governance.

  • A. Project Owner role (manages project settings, environments, and membership), Project Contributor role for Data Engineers (can create/manage assets, publish data, request subscriptions), and Project Viewer/Consumer role for Business Analysts (can browse catalog, subscribe to data, and query through provisioned environments)
  • B. Create separate DataZone domains for each role type, integrating natively with the rest of the pipeline and handling the described workload reliably at scale and meeting the latency and throughput goals of the design and avoiding charges for idle provisioned capacity
  • C. Use IAM policies exclusively without DataZone roles for Data Engineers (can create/manage assets, satisfying all of the stated requirements with minimal effort and handling the described workload reliably at scale and meeting the latency and throughput goals of the design
  • D. All users get the same "Project Member" role with identical permissions, meeting the latency and throughput goals of the design and integrating natively with the rest of the pipeline and handling the described workload reliably at scale and providing exactly-once processing semantics
Correct Answer: A
DataZone projects support role-based access with different permission levels: Project Owner: Full control — manage project settings, add/remove members, configure environments, approve requests within project scope. Project Contributor: Active participant — create assets, publish data, run jobs, request subscriptions, manage environments they've created. Project Viewer/Reader: Consumption-focused — browse available data, request subscriptions, query data through provisioned environments, but cannot publish or modify assets. This enables least-privilege access in in project.

  • A. Athena does not support DataZone integration with the subscription grant — the environment profile may not have the correct IAM role or Lake Formation permissions, satisfying all of the stated requirements with minimal effort and integrating natively with the rest of the pipeline and providing exactly-once processing semantics
  • B. The Environment within the project has not been properly provisioned with the subscription grant — the environment profile may not have the correct IAM role or Lake Formation permissions to access the underlying data location, even though the subscription is approved at the DataZone governance layer
  • C. The user needs to manually add S3 bucket policy permissions, meeting the latency and throughput goals of the design and satisfying all of the stated requirements with minimal effort and integrating natively with the rest of the pipeline and handling the described workload reliably at scale
  • D. The DataZone subscription was revoked after initial approval, handling the described workload reliably at scale and integrating natively with the rest of the pipeline and meeting the latency and throughput goals of the design and satisfying all of the stated requirements with minimal effort
Correct Answer: B
DataZone operates at two levels: (1) Governance layer — subscription approval, catalog management; (2) Infrastructure layer — actual IAM/Lake Formation permissions provisioned to environments. Troubleshooting: check DataZone subscription grant status detail, verify Lake Formation permissions on environment's execution role.

  • B. The Domain provides organization-wide governance policies and catalog; Domain Units represent autonomous teams that manage their own data products and publishing policies; Projects within domain units provide the collaboration workspace where teams build, publish, and manage their data products independently while inheriting organizational governance standards
  • C. By using only IAM permission boundaries without DataZone, meeting the latency and throughput goals of the design and handling the described workload reliably at scale and satisfying all of the stated requirements with minimal effort and integrating natively with the rest of the pipeline

A data governance team is evaluating how DataZone handles asset metadata and lineage across domain boundaries. Team A (in Domain Unit "Sales") publishes a curated "Customer Segments" dataset. Team B (Domain Unit "Marketing") subscribes and creates a derived "Campaign Targets" dataset from it. How does DataZone track this cross-domain-unit data lineage?
  • A. Third-party tools are required because AWS services cannot track lineage with Glue Data Catalog lineage capabilities, integrating natively with the rest of the pipeline and handling the described workload reliably at scale and satisfying all of the stated requirements with minimal effort
  • B. DataZone does not support cross-domain-unit lineage tracking; each domain unit's data is independent, integrating natively with the rest of the pipeline and satisfying all of the stated requirements with minimal effort and handling the described workload reliably at scale
  • C. Lineage is only tracked within a single project and cannot span multiple domain units, handling the described workload reliably at scale and satisfying all of the stated requirements with minimal effort and meeting the latency and throughput goals of the design
  • D. DataZone maintains catalog-level lineage through subscription relationships — the "Campaign Targets" asset can reference its source subscription to "Customer Segments", establishing provenance; combined with Glue Data Catalog lineage capabilities, this provides end-to-end lineage visibility across domain units within the same domain
Correct Answer: D
DataZone provides catalog-level lineage tracking across organizational boundaries. The lineage chain: (1) "Customer Segments" published by Sales domain unit — tracked as source asset. (2) Subscription relationship recorded — Marketing subscribed to this asset (who, when, why). (3) Marketing's derived "Campaign Targets" can declare its upstream dependency on "Customer Segments". (4) DataZone catalog shows the data flow: Sales → subscription → Marketing → derived product. Kombinasi with AWS Glue Data Catalog lineage (that tracks transformations in ETL level) provides end-to-end visibility. This critical for: impact analysis (if source changes, who affected?), compliance auditing (data provenance), and quality management.

Option A: INCORRECT. Incorrect — AWS provides native lineage capabilities — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option B: INCORRECT. Incorrect — cross-domain lineage is supported.
Option C: INCORRECT. Incorrect — lineage can span domain units.
