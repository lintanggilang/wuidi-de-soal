A company is migrating from Oracle 19c to Amazon Aurora PostgreSQL. The Oracle database contains 200 stored procedures, 50 packages, and 30 triggers that use PL/SQL-specific features. The data engineer needs to assess the migration complexity before starting. Which AWS tool should be used FIRST?
  • A. Amazon RDS Performance Insights to compare source and target capabilities
  • B. AWS Schema Conversion Tool (SCT) to generate a migration assessment report
  • C. AWS Database Migration Service (DMS) to start replication immediately
  • D. AWS Application Discovery Service to inventory database dependencies
Correct Answer: B
AWS Schema Conversion Tool (SCT) must is used pertama kali for produces Database Migration Assessment Report. Report this menganalisis entire schema objects (tables, views, stored procedures, packages, triggers) and mengklasifikasikan each item based on complexity konversi: automatic (green), requires few modifikasi (orange), or requires rewrite manual (red). Ini provides picture jelas about effort that is required.

Option A: INCORRECT. For monitoring, not assessment.
Option B: CORRECT.
Option C: INCORRECT. Digunakan setelah schema already dikonversi for data migration.
Option D: INCORRECT. For infrastructure migration, not database schema.

A data engineer is using AWS SCT to convert an Oracle data warehouse schema to Amazon Redshift. The assessment report shows that Oracle BITMAP indexes cannot be automatically converted. What is the CORRECT approach for handling bitmap indexes during migration to Redshift?
  • A. Manually create B-tree indexes in Redshift as a replacement, handling the described workload reliably at scale
  • B. Convert bitmap indexes to Redshift interleaved sort keys for similar filtering performance, validating and cleansing each record before delivery
  • C. Indexes are not needed in Redshift — use appropriate sort keys and distribution keys instead for query optimization
  • D. Use Redshift Spectrum to maintain Oracle-style indexes on external tables and distribution keys instead for query optimization
Correct Answer: C
Amazon Redshift not uses indexes same sekali — this is perbedaan fundamental from OLTP databases. Redshift mengoptimasi query performance through columnar storage, sort keys (compound or interleaved), distribution keys, and zone maps. Bitmap indexes from Oracle does not need "dikonversi" — needs diidentifikasi query patterns that uses indexes the said and then pilih sort keys and distribution keys that appropriate.

Option A: INCORRECT. Salah — Redshift not supports B-tree indexes.
Option B: INCORRECT. Terlalu specific — interleaved sort keys not direct replacement for bitmap indexes.
Option C: CORRECT.
Option D: INCORRECT. Not supports indexes — although its description sounds convincing, in a fundamental still not appropriate for requirements this.

A company is migrating SQL Server to Amazon Aurora PostgreSQL. The SQL Server database uses extensively T-SQL specific features including MERGE statements, CROSS APPLY, and Common Table Expressions (CTEs) with recursion. After running AWS SCT, the assessment shows 60% automatic conversion. What does this percentage indicate?
  • A. 60% of the migration will be completed by AWS DMS automatically configured for optimal performance and minimal operational overhead
  • B. 60% of the queries will run without modification on Aurora PostgreSQL, optimizing cost for the described workload
  • C. 60% of the database schema objects and code can be automatically converted to PostgreSQL-compatible syntax
  • D. 60% of the data can be migrated without transformation, handling the described workload reliably at scale
Correct Answer: C
SCT assessment percentage menunjukkan proporsi schema objects (tables, views, stored procedures, functions, triggers) and code that can dikonversi automatically to target syntax. 60% berarti SCT can produces PostgreSQL-compatible DDL/code for 60% objects without intervensi manual. Sisa 40% requires modifikasi manual — for example, CROSS APPLY needs is changed to LATERAL JOIN in PostgreSQL.

Option A: INCORRECT. Salah — DMS handles data migration, not schema conversion — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option B: INCORRECT. Salah — this about schema objects, not runtime query.
Option C: CORRECT.
Option D: INCORRECT. Salah — this about schema/code, not data.

A data engineer is migrating an Oracle database to Aurora PostgreSQL using AWS DMS Schema Conversion (serverless). Compared to the traditional AWS SCT desktop application, what is the PRIMARY advantage of DMS Schema Conversion?
  • A. DMS Schema Conversion is fully serverless and does not require installing or maintaining a local application
  • B. DMS Schema Conversion supports more source database engines than SCT with fully managed infrastructure and automatic scaling
  • C. DMS Schema Conversion can convert stored procedures that SCT cannot, requiring no servers to manage or scale manually
  • D. DMS Schema Conversion performs data migration and schema conversion simultaneously, applying schema conversion and enrichment inline
Correct Answer: A
AWS DMS Schema Conversion is feature serverless that terintegrasi in AWS DMS console. Not needs mengunduh, menginstal, or memelihara application desktop such as SCT tradisional. Ini reduces operational overhead and memudahkan kolaborasi team.

Option A: CORRECT.
Option B: INCORRECT. Salah — DMS Schema Conversion sebenarnya supports fewer source-target combinations dibanding SCT desktop — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option C: INCORRECT. Salah — stored procedure conversion capabilities similar.
Option D: INCORRECT. Salah — schema conversion and data migration still process separate, meski keduanya available in DMS console.

During an Oracle to PostgreSQL migration using AWS SCT, the tool flags Oracle sequences with CACHE and CYCLE options as requiring manual intervention. The data engineer needs to understand why. Which limitation causes this SCT action item?
  • A. AWS Aurora PostgreSQL has a hard limit of 100 sequences per schema
  • B. PostgreSQL sequences support different CACHE behavior and CYCLE semantics that may need application-level verification
  • C. PostgreSQL does not support sequences at all configured for optimal performance and minimal operational overhead
  • D. Oracle sequences must be converted to DynamoDB atomic counters during migration
Correct Answer: B
PostgreSQL supports sequences with CACHE and CYCLE, but behavior-nya may few different from Oracle. Misalnya, Oracle CACHE stores batch in SGA memory instance-wide, while PostgreSQL caches per-session. CYCLE behavior also can has perbedaan in gap handling. SCT menandai this for verifikasi manual because perbedaan semantik can affects application logic that depends on sequence behavior.

Option A: INCORRECT. Salah — there is no limit 100.
Option B: CORRECT.
Option C: INCORRECT. Salah — PostgreSQL supports sequences — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option D: INCORRECT. Not relevan — sequences dikonversi to PostgreSQL sequences, not DynamoDB.

A company is migrating a 10 TB Oracle data warehouse to Amazon Redshift. The AWS SCT assessment report shows three categories of action items: "Simple" (green), "Medium" (amber), and "Complex" (red). The report indicates 40 complex action items, all related to Oracle PL/SQL packages with PRAGMA directives and AUTONOMOUS_TRANSACTIONS. What should the data engineer do with these complex items?
  • A. Run SCT again with enhanced conversion mode to automatically resolve complex items, integrating natively with the rest of the pipeline
  • B. Skip the stored procedures and rely on application-level logic instead configured for optimal performance and minimal operational overhead
  • C. Manually rewrite the PL/SQL logic using Redshift stored procedures (PL/pgSQL) or redesign as Python UDFs or Lambda UDFs
  • D. Use AWS DMS to migrate the stored procedures as-is to Redshift, integrating natively with the rest of the pipeline
Correct Answer: C
Complex (red) items requires manual rewrite because feature Oracle that is used not has equivalent directly in target. PRAGMA directives and AUTONOMOUS_TRANSACTIONS is Oracle-specific features. For Redshift, opsinya: (1) rewrite sebagai Redshift stored procedures (PL/pgSQL), (2) implementation sebagai Python/Lambda UDFs, or (3) pindahkan logic to ETL layer (Glue/Step Functions).

Option A: INCORRECT. Salah — there is no "enhanced mode" that can resolve complex items automatic.
Option B: INCORRECT. Mungkin valid but not always practical — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option C: CORRECT.
Option D: INCORRECT. Salah — DMS migration data, not stored procedures, and Redshift cannot runs PL/SQL.

A data engineer uses AWS SCT to convert a SQL Server schema to Aurora PostgreSQL. After applying the converted schema, they need to validate that the conversion is correct before migrating data. Which testing approach is RECOMMENDED?
  • A. Verify only that CREATE TABLE statements execute without errors, applying schema conversion and enrichment inline and transforming records into the required target format
  • B. Run the application's test suite against the new Aurora PostgreSQL with the converted schema, comparing query results between source and target
  • C. Compare row counts between source and target tables, applying schema conversion and enrichment inline and handling the described workload reliably at scale
  • D. Use AWS DMS validation feature to compare schemas with the converted schema and target, meeting the latency and throughput goals of the design
Correct Answer: B
Validasi konversi schema that most komprehensif is runs test suite application against target database and membandingkan result query between source and target. Ini validates that stored procedures, views, triggers, and constraints berperilaku appropriate ekspektasi.

Option A: INCORRECT. Only ensures DDL syntax valid but not validates logic (stored procedures can syntactically correct but logically wrong).
Option B: CORRECT.
Option C: INCORRECT. Only validates data migration, not schema conversion correctness.
Option D: INCORRECT. Memvalidasi data consistency setelah migration, not schema logic correctness — although its description sounds convincing, in a fundamental still not appropriate for requirements this.

A company migrating from Oracle to Aurora PostgreSQL encounters Oracle-specific data types: CLOB (Character Large Object), RAW, and NUMBER(38,10). AWS SCT maps these to PostgreSQL types. Which mapping is CORRECT?
  • A. CLOB → TEXT, RAW → BYTEA, NUMBER(38,10) → NUMERIC(38,10)
  • B. CLOB → BLOB, RAW → TEXT, NUMBER(38,10) → INTEGER
  • C. CLOB → VARCHAR(MAX), RAW → VARBINARY, NUMBER(38,10) → FLOAT8
  • D. CLOB → JSON, RAW → UUID, NUMBER(38,10) → BIGINT
Correct Answer: A
Mapping that correct: Oracle CLOB (character large object) → PostgreSQL TEXT (unlimited length text); Oracle RAW (binary data) → PostgreSQL BYTEA (byte array); Oracle NUMBER(38,10) → PostgreSQL NUMERIC(38,10) (exact numeric with precision and scale that same).

Option A: CORRECT.
Option B: INCORRECT. Salah — BLOB not text type, RAW not text, and INTEGER too small for NUMBER(38,10).
Option C: INCORRECT. Uses type SQL Server (VARCHAR(MAX), VARBINARY) and FLOAT8 kehilangan precision.
Option D: INCORRECT. Salah — all mapping not appropriate in a semantik.

Option C: INCORRECT. Adalah workaround manual, not built-in feature.
Option D: CORRECT.

A data engineer is migrating an Oracle database to Amazon Redshift using AWS SCT. The Oracle source contains materialized views with complex refresh logic (FAST refresh using materialized view logs). SCT cannot automatically convert these. Which Redshift alternative should the data engineer implement?
  • A. Replace materialized views with Redshift external tables pointing to S3
  • B. Implement the refresh logic using AWS Glue ETL jobs on a schedule with AUTO REFRESH option for automatic
  • C. Create standard Redshift views and schedule manual REFRESH using stored procedures
  • D. Use Redshift materialized views with AUTO REFRESH option for automatic incremental refresh
Correct Answer: D
Amazon Redshift supports materialized views with AUTO REFRESH that automatically performs incremental refresh when base tables changes. Ini is pengganti terdekat for Oracle materialized views with FAST refresh. Redshift detects changes on base tables and performs refresh inkremental without needing materialized view logs.

Option A: INCORRECT. Has performa slower from materialized views.
Option B: INCORRECT. Adds complexity that does not need when native feature available — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option C: INCORRECT. Not stores data in a fisik so that not provides performance benefit.
Option D: CORRECT.
