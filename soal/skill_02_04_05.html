Optimization techniques for query performance in data lakes and warehouses

1
A data engineering team stores 5 TB of sales transaction data in Amazon S3 as Parquet files. Analysts primarily query this data using Amazon Athena with filters on transaction_date and region. Current queries scan the entire dataset and take over 10 minutes. The team needs to reduce query time and cost. Which S3 partitioning strategy provides the MOST effective optimization?
  • A. Partition by s3://bucket/sales/transaction_id={id}/
  • B. Partition by s3://bucket/sales/region={region}/year={yyyy}/ with native S3 integration
  • C. Partition by s3://bucket/sales/year={yyyy}/month={MM}/day={dd}/region={region}/
  • D. Store all data in a single prefix with Parquet row group filtering
Jawaban Benar: C
Partitioning berdasarkan year/month/day/region adalah strategi optimal karena sesuai dengan pola query yang menggunakan filter transaction_date dan region. Hierarki date-first memungkinkan partition pruning yang efektif karena date range queries sangat umum.

Opsi A: SALAH. Menghasilkan terlalu banyak partisi kecil (high cardinality) yang justru menurunkan performa.
Opsi B: SALAH. Menempatkan region di level pertama, yang kurang optimal jika date queries lebih sering — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi C: BENAR.
Opsi D: SALAH. Tanpa partitioning akan selalu melakukan full scan.
2
A company uses Amazon Redshift to run analytical queries on a 2 TB fact table containing order data. Most queries filter by order_date and join with a dimension table on customer_id. The data engineer needs to configure sort keys for optimal performance. Which sort key configuration is MOST appropriate?
  • A. Interleaved sort key with (order_date, customer_id)
  • B. No sort key, rely on Redshift automatic optimization
  • C. Compound sort key with (customer_id) only
  • D. Compound sort key with (order_date, customer_id)
Jawaban Benar: D
Compound sort key (order_date, customer_id) adalah pilihan terbaik karena order_date sebagai kolom pertama akan sangat efektif untuk zone map filtering pada range queries yang paling sering digunakan. customer_id sebagai kolom kedua membantu merge joins dengan dimension table.

Opsi A: SALAH. Memberikan equal weight ke semua kolom, tapi memerlukan VACUUM REINDEX yang mahal dan kurang efisien ketika satu kolom (order_date) dominan di-filter.
Opsi B: SALAH. Tidak optimal untuk workload yang diketahui pola query-nya.
Opsi C: SALAH. Mengabaikan order_date yang merupakan filter utama.
Opsi D: BENAR.
3
A data engineer is optimizing a DynamoDB table that stores IoT sensor readings. The table has a partition key of device_id and sort key of timestamp. Analysts frequently need to query readings by sensor_type across all devices for a specific time range. Current queries require full table scans. Which indexing strategy resolves this access pattern?
  • A. Modify the base table's partition key to sensor_type
  • B. Add a Global Secondary Index (GSI) with timestamp as partition key and sensor_type as sort key
  • C. Create a Local Secondary Index (LSI) with sensor_type as the sort key and timestamp as sort key
  • D. Create a Global Secondary Index (GSI) with sensor_type as partition key and timestamp as sort key
Jawaban Benar: D
GSI dengan sensor_type sebagai partition key dan timestamp sebagai sort key memungkinkan query efisien berdasarkan sensor_type dengan time range filter tanpa scan seluruh tabel. GSI memberikan access pattern yang berbeda dari base table.

Opsi A: SALAH. Mengubah base table akan merusak access pattern existing.
Opsi B: SALAH. Menggunakan timestamp sebagai partition key yang akan menghasilkan hot partitions.
Opsi C: SALAH. Tidak bisa digunakan karena LSI harus memiliki partition key yang sama dengan base table (device_id), sehingga tetap perlu query per device — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi D: BENAR.
4
A data lake team is converting CSV files to Apache Parquet format for storage in S3. The dataset contains a mix of columns: 5 numeric columns frequently used for aggregations, 3 high-cardinality string columns, and 2 timestamp columns. They need to choose the optimal compression codec. Which codec selection strategy maximizes both compression ratio and query performance for this analytical workload?
  • A. Use LZO compression for all columns as it provides the fastest read performance
  • B. Use ZSTD compression which provides a balance of high compression ratio and fast decompression suitable for analytical queries
  • C. Use Snappy compression for all columns to maximize decompression speed
  • D. Use Gzip compression for all columns to maximize compression ratio and fast decompression suitable for analytical queries
Jawaban Benar: B
ZSTD (Zstandard) memberikan keseimbangan terbaik antara compression ratio yang tinggi (mendekati Gzip) dan kecepatan decompression yang cepat (mendekati Snappy). Untuk analytical workload dimana data dibaca berulang kali, ZSTD mengurangi storage cost sekaligus mempertahankan query performance.

Opsi A: SALAH. Sudah less common dan tidak optimal dibandingkan ZSTD.
Opsi B: BENAR.
Opsi C: SALAH. Tercepat untuk decompress tapi compression ratio lebih rendah, meningkatkan scan volume dan cost.
Opsi D: SALAH. Memiliki compression ratio tertinggi tapi decompression yang lambat, meningkatkan query latency — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
5
A data engineer notices that Amazon Athena queries against their Parquet-based data lake are slow despite using partitioning. Investigation reveals the data lake contains millions of small files (average 5 MB each) within each partition. What is the MOST effective approach to resolve this performance issue?
  • A. Add more partition levels to distribute files across more directories
  • B. Switch from Parquet to CSV format which handles small files better with native S3 integration and optimized data transfer
  • C. Compact small files into larger files targeting 128-512 MB per file using AWS Glue or an S3DistCp job
  • D. Increase the Athena DPU count to process more files in parallel
Jawaban Benar: C
Small file problem adalah masalah umum di data lakes. Setiap file memerlukan overhead untuk opening, reading metadata, dan closing. Menggabungkan file kecil menjadi file 128-512 MB mengurangi jumlah file operations secara drastis dan memungkinkan parallel processing yang lebih efisien.

Opsi A: SALAH. Akan memperburuk masalah dengan lebih banyak directory listings.
Opsi B: SALAH. Justru lebih buruk karena kehilangan columnar benefits — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi C: BENAR.
Opsi D: SALAH. Meningkatkan biaya tanpa menyelesaikan root cause — overhead per-file tetap ada.
6
A Redshift data warehouse has a 500 GB table that was loaded using COPY commands over several months. The DBA notices that queries are getting progressively slower, and the SVV_TABLE_INFO view shows the table has a high percentage of unsorted rows and deleted rows (marked as tombstones). Which maintenance operations should be performed to restore optimal performance?
  • A. Drop and recreate the table with a deep copy using CREATE TABLE AS SELECT
  • B. Run ANALYZE only, as statistics are the main issue
  • C. Resize the Redshift cluster to add more compute nodes
  • D. Run VACUUM FULL followed by ANALYZE on the table
Jawaban Benar: D
VACUUM FULL melakukan dua operasi penting: (1) menghapus deleted rows (reclaim space dari tombstones) dan (2) mengurutkan ulang rows berdasarkan sort key. ANALYZE kemudian memperbarui statistics yang digunakan query optimizer. Kedua operasi ini mengembalikan performa zone maps dan query planning.

Opsi A: SALAH. Bisa berhasil tapi lebih disruptive dan memerlukan downtime lebih lama.
Opsi B: SALAH. Tidak mengatasi unsorted rows dan tombstones.
Opsi C: SALAH. Meningkatkan biaya tanpa menyelesaikan root cause data organization.
Opsi D: BENAR.
7
A geospatial analytics team queries a data lake containing location-based events. Their queries frequently filter on both latitude/longitude ranges AND timestamp ranges simultaneously. Standard Hive-style partitioning on date alone leaves too much data to scan. Which data organization technique is MOST suitable for optimizing these multi-dimensional range queries?
  • A. Apply Z-ordering (space-filling curve) on latitude, longitude, and timestamp columns to co-locate related data
  • B. Use Parquet row group filtering with min/max statistics on lat/long columns
  • C. Create separate partitions for latitude ranges and longitude ranges in addition to date
  • D. Implement bucketing on a geohash column derived from latitude and longitude and timestamp columns to co-locate related data
Jawaban Benar: A
Z-ordering menggunakan space-filling curves untuk memetakan data multi-dimensi ke satu dimensi sambil mempertahankan locality. Ini memungkinkan data yang dekat dalam multiple dimensions (lat, long, timestamp) juga dekat secara fisik di storage, sehingga file pruning efektif untuk semua kombinasi filter.

Opsi A: BENAR.
Opsi B: SALAH. Membantu tapi tanpa Z-ordering, data mungkin tersebar acak sehingga min/max ranges overlap.
Opsi C: SALAH. Menyebabkan partition explosion karena kombinasi ranges yang banyak.
Opsi D: SALAH. Hanya membantu spatial queries tapi tidak mengoptimalkan temporal dimension secara bersamaan — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
8
A data engineer is configuring Parquet file writes for a data lake that will be queried by both Athena and Redshift Spectrum. The dataset has 200 columns but typical queries only access 5-10 columns at a time. The engineer needs to optimize row group size for this access pattern. Which row group configuration is MOST appropriate?
  • A. Set row group size to 1 GB to minimize the number of row groups per file
  • B. Set row group size to 128 MB (default) which provides optimal balance for columnar reads of wide tables
  • C. Set row group size to 8 MB to minimize memory usage during reads for columnar reads of wide tables
  • D. Set row group size to 32 KB to maximize predicate pushdown granularity
Jawaban Benar: B
Row group size 128 MB (default Parquet) memberikan keseimbangan optimal. Untuk wide tables (200 kolom) dimana hanya 5-10 kolom dibaca, row group yang cukup besar memastikan column chunks memiliki cukup data untuk sequential I/O yang efisien.

Opsi A: SALAH. Terlalu besar, memerlukan memory berlebihan dan membuat predicate pushdown kurang granular.
Opsi B: BENAR.
Opsi C: SALAH. Terlalu kecil — column chunks hanya ~40 KB per kolom, menghasilkan banyak random I/O — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi D: SALAH. Sangat kecil, setiap column chunk hanya ~160 bytes yang tidak efisien untuk I/O.
9
A data warehouse team uses Amazon Redshift and notices that certain queries that filter on a VARCHAR column containing product category names are performing full table scans instead of using zone maps for data skipping. The table uses a compound sort key on (product_category, transaction_date). What is the MOST likely cause and solution?
  • A. The table has too many unsorted rows after recent loads; run VACUUM SORT to restore zone map effectiveness
  • B. Compound sort keys don't support zone maps; switch to interleaved sort key configured for optimal performance and minimal
  • C. The query is using LIKE patterns which cannot leverage zone maps; use equality predicates instead
  • D. Zone maps don't work with VARCHAR columns; switch to integer encoding for categories
Jawaban Benar: A
Ketika data baru di-load ke Redshift (via COPY atau INSERT), rows baru ditambahkan sebagai unsorted region. Zone maps pada unsorted region memiliki min/max ranges yang sangat wide, membuat data skipping tidak efektif. VACUUM SORT mengurutkan ulang data sehingga zone maps memiliki ranges yang tight dan bisa melakukan effective pruning.

Opsi A: BENAR.
Opsi B: SALAH. Salah — compound sort keys bekerja sangat baik dengan zone maps, terutama untuk kolom pertama — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi C: SALAH. Salah — LIKE dengan prefix bisa leverage zone maps.
Opsi D: SALAH. Salah — zone maps bekerja dengan VARCHAR.
10
An analytics team uses Amazon Athena to query a data lake stored in ORC format on S3. They want to enable predicate pushdown to minimize data scanned. The table contains a high-cardinality column (user_id) that is frequently used in WHERE clauses. Queries currently scan 100% of data despite having user_id filters. Which technique enables effective predicate pushdown for this column?
  • A. Convert from ORC to Parquet format which has better predicate pushdown support for equality filters
  • B. Enable Bloom filters on the user_id column during ORC file creation to enable predicate pushdown for equality filters
  • C. Partition the data by user_id to leverage partition pruning instead of predicate pushdown
  • D. Increase the ORC stripe size to improve min/max index effectiveness
Jawaban Benar: B
Untuk high-cardinality columns, ORC min/max statistics (row index) tidak efektif karena setiap stripe likely memiliki wide range of user_ids. Bloom filters di ORC memberikan probabilistic test yang dapat menentukan apakah suatu stripe definitely doesn't contain a specific user_id, enabling effective data skipping untuk equality predicates.

Opsi A: SALAH. Salah — kedua format mendukung predicate pushdown, tapi ORC memiliki Bloom filter built-in — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi B: BENAR.
Opsi C: SALAH. Akan menghasilkan jutaan partisi yang sangat buruk untuk performance (partition explosion).
Opsi D: SALAH. Justru memperburuk masalah karena ranges menjadi lebih wide.
