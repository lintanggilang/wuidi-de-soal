A large enterprise is transitioning from a centralized data lake to a data mesh architecture. Currently, a central data engineering team of 5 people manages all data pipelines for 20 business domains, creating a significant bottleneck. Which principle of data mesh addresses this bottleneck, and how does it map to AWS services?
  • A. Federated computational governance — implement a governance council that reviews all pipeline changes before deployment
  • B. Domain ownership — each business domain (marketing, finance, logistics) owns and operates their own data pipelines and publishes data products, using AWS accounts per domain with their own Glue jobs, S3 buckets, and DataZone projects for publishing
  • C. Self-serve data platform — provide AWS Service Catalog templates so the central team can deploy pipelines faster
  • D. Data as a product — standardize all data into a single Parquet format across all domains with their own Glue jobs for publishing
Jawaban Benar: B
Domain ownership adalah prinsip data mesh yang langsung mengatasi bottleneck central team. Alih-alih 5 engineers melayani 20 domains, setiap domain memiliki engineers sendiri yang bertanggung jawab atas data mereka — dari ingestion hingga publishing data products. Pada AWS: setiap domain mendapat AWS account (atau set of accounts), mengelola Glue ETL, S3 storage, dan publishes melalui DataZone projects. Central team berubah peran menjadi platform team yang menyediakan tools/templates.

Opsi A: SALAH. Federated computational governance tentang automating governance policies, bukan distributing pipeline ownership.
Opsi B: BENAR.
Opsi C: SALAH. Self-serve platform membantu tapi jika masih central team yang deploy, bottleneck tetap ada.
Opsi D: SALAH. Data as product tentang treating datasets sebagai products (quality, documentation, SLAs), bukan format standardization — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
2
A company needs to securely share aggregated analytics data with a partner company for a joint marketing campaign. The partner should be able to query the shared data but must NOT be able to see individual customer records. Both companies use AWS. Which data sharing pattern ensures privacy while enabling collaboration?
  • A. Set up a VPN tunnel between VPCs and share a database endpoint with row-level security
  • B. Use AWS Clean Rooms to create a collaboration where both parties can run agreed-upon aggregate queries (COUNT, SUM, AVG) on each other's data without exposing individual records, with analysis rules restricting output to minimum aggregation thresholds
  • C. Create an S3 bucket with cross-account access and upload the raw customer data encrypted with the partner's KMS key
  • D. Export data to AWS Data Exchange as a free product that the partner subscribes to with analysis rules restricting output
Jawaban Benar: B
AWS Clean Rooms dirancang untuk privacy-preserving data collaboration. Key features: (1) Collaboration — both parties bring their data tanpa sharing raw records, (2) Analysis rules — restrict what queries can be run (only aggregations, minimum group sizes to prevent re-identification), (3) Output restrictions — results must meet minimum aggregation thresholds (e.g., COUNT must be ≥100 before showing result), preventing exposure of individuals, (4) No data movement — each party's data stays in their account.

Opsi A: SALAH. Database endpoint with RLS still exposes individual rows that pass the filter.
Opsi B: BENAR.
Opsi C: SALAH. Sharing raw data via S3 exposes individual records regardless of encryption.
Opsi D: SALAH. Data Exchange shares the actual dataset; once downloaded, partner has full access to all records — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
3
A governance framework requires that every data asset in the organization has an assigned Data Owner, Data Steward, and defined data classification level. Currently, metadata about ownership is scattered across wikis, Jira tickets, and tribal knowledge. Which AWS-native approach centralizes and enforces this governance metadata?
  • A. Use Amazon DataZone with custom metadata forms requiring Owner, Steward, and Classification fields before any asset can be published to the catalog — combined with Glue Data Catalog business glossary for standardized classification terms
  • B. Use AWS Config rules to check if resources have governance-related tags
  • C. Maintain a DynamoDB table with governance metadata and reference it in documentation for standardized classification terms
  • D. Create AWS resource tags (DataOwner, DataSteward, Classification) on all data resources and use Tag Policies in AWS Organizations to enforce required tags
Jawaban Benar: A
Amazon DataZone dengan custom metadata forms menyediakan governance enforcement yang terintegrasi dengan data discovery: (1) Metadata forms — template fields wajib diisi (Data Owner, Data Steward, Classification Level) sebelum asset bisa di-publish ke catalog. Ini enforces completeness. (2) Business glossary — standardisasi terminology (Confidential, Internal, Public) sehingga classification konsisten. (3) Catalog sebagai single source of truth — semua governance metadata terpusat dan discoverable. (4) Tied to access workflows — classification bisa drive approval policies.

Opsi A: BENAR.
Opsi B: SALAH. Config rules hanya detect missing tags, tidak enforce rich governance metadata.
Opsi C: SALAH. DynamoDB table terpisah dari data catalog, mudah menjadi stale — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi D: SALAH. Resource tags berguna tapi tidak menyediakan discovery experience atau tidak terhubung ke data access workflows.

A pharmaceutical company wants to share anonymized clinical trial data with 50 research institutions worldwide through a marketplace model. They want to monetize the data while maintaining control over who gets access. Which AWS service enables this external data sharing pattern?
  • A. Create 50 cross-account S3 replication rules, one for each institution's AWS account
  • B. Use Redshift data sharing with 50 consumer cluster configurations
  • C. AWS Data Exchange — publish the anonymized data as a product (free or paid), research institutions subscribe through the AWS Marketplace, and the publisher can review and approve subscriber eligibility before granting access
  • D. Amazon DataZone with external project membership for each research institution configured for optimal performance and minimal operational overhead
Jawaban Benar: C
AWS Data Exchange dirancang untuk third-party data sharing dan monetization: (1) Publisher creates data products — datasets, APIs, atau Lake Formation-based access, (2) Products listed di AWS Marketplace — discoverable oleh potential subscribers, (3) Pricing — free, subscription, atau per-use pricing models, (4) Subscriber eligibility — publisher bisa enable "subscription verification" yang requires approval sebelum access granted (important untuk controlled distribution ke research institutions), (5) Automatic fulfillment — once approved, subscribers get access tanpa manual setup per institution.

Opsi A: SALAH. 50 replication rules tidak scalable, tidak support monetization, dan requires knowing each institution's account.
Opsi B: SALAH. Redshift data sharing requires each consumer to have Redshift; research institutions may not.
Opsi C: BENAR.
Opsi D: SALAH. DataZone untuk internal/organizational governance, bukan external marketplace — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.

A company is building a data governance framework and needs to define data classification levels with corresponding handling requirements. They have four levels: Public, Internal, Confidential, and Restricted. Which classification-to-control mapping represents best practices for an AWS data platform?
  • A. Public: SSE-S3 | Internal: SSE-S3 | Confidential: SSE-S3 | Restricted: SSE-KMS — only encryption level changes between classifications
  • B. Classification levels only affect who can view data in the catalog; actual security controls are the same regardless of classification
  • C. All levels receive the same encryption and access controls to simplify management with CMK for non-privileged users
  • D. Public: no encryption needed, open access | Internal: SSE-S3, authenticated users | Confidential: SSE-KMS with CMK, role-based access, audit logging | Restricted: SSE-KMS with CMK + CloudHSM key store, MFA-required access, real-time monitoring, DLP scanning, data masking for non-privileged users
Jawaban Benar: D
Data classification framework yang efektif menerapkan controls proportional to sensitivity level. Progressive security controls: Public — minimal controls karena data bisa diakses siapa saja. Internal — basic encryption (SSE-S3 managed) dan authentication required. Confidential — stronger encryption (customer-managed CMK memberikan key rotation control dan access audit), role-based access (least privilege), dan audit logging wajib. Restricted — maximum controls: CMK dengan CloudHSM key store (FIPS 140-2 Level 3), MFA required untuk decrypt operations, real-time monitoring (GuardDuty, Macie), DLP scanning, dan dynamic data masking.

Opsi A: SALAH. Encryption alone tidak sufficient; access control, monitoring, dan other controls harus juga progressive.
Opsi B: SALAH. Classification tanpa corresponding controls tidak meaningful.
Opsi C: SALAH. Uniform controls wastes resources untuk low-sensitivity data atau under-protects high-sensitivity — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi D: BENAR.

A data mesh implementation requires "federated computational governance" — policies that are defined centrally but enforced automatically across all domain teams without requiring each team to manually implement them. Which AWS architecture implements federated computational governance?
  • A. Each domain team writes their own governance policies independently configured for optimal performance and minimal operational overhead
  • B. Central governance team deploys AWS Config conformance packs (encoding policies as rules), SCPs (preventive controls), and Lake Formation tag-based policies across all domain accounts through AWS Organizations — domain teams auto-inherit these guardrails without manual setup while retaining freedom in how they build within the guardrails
  • C. A central team reviews all domain pull requests to ensure governance compliance
  • D. A governance wiki that domain teams reference when building pipelines
Jawaban Benar: B
Federated computational governance berarti: policies defined centrally, enforced AUTOMATICALLY (computational — not manual review), dan applied across federation of domains. AWS implementation: (1) SCPs — preventive guardrails yang automatically prevent policy violations (region restrictions, service restrictions), (2) Config conformance packs — detective controls deployed to all domain accounts via Organizations, automatically evaluating compliance, (3) Lake Formation tag-based policies — centrally defined data access patterns inherited by all domains. Domain teams beroperasi freely WITHIN guardrails tanpa perlu manually implement governance.

Opsi A: SALAH. Independent policies bukan "federated" — leads to inconsistency — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi B: BENAR.
Opsi C: SALAH. Manual PR review is not computational and creates central bottleneck (opposite of data mesh goal).
Opsi D: SALAH. Wiki reference is manual, not computational.

A retail company wants to collaborate with their advertising partners to measure campaign effectiveness without revealing customer identities to each other. The retailer has purchase data and the ad partner has impression/click data. They need to match customers across datasets and compute aggregate conversion metrics. Which data sharing pattern and AWS service enables this privacy-preserving analysis?
  • A. AWS Clean Rooms with cryptographic computing — both parties configure their tables, define allowed analysis rules (only aggregate functions with minimum thresholds), and compute matches without either party seeing the other's raw data or individual-level join results
  • B. Use Redshift data sharing between the two companies' clusters with column masking
  • C. Both parties upload raw data to a shared S3 bucket and run Athena queries with cryptographic computing — both parties configure their tables
  • D. Exchange data through AWS Data Exchange and perform matching locally
Jawaban Benar: A
AWS Clean Rooms dengan cryptographic computing adalah solusi ideal untuk privacy-preserving matching: (1) Clean Rooms collaboration — kedua parties bring data tanpa sharing raw records, (2) Cryptographic computing (optional enhancement) — data tetap encrypted selama processing sehingga even AWS cannot see individual records, (3) Analysis rules — restrict output ke aggregate-only (conversion rate, total purchases) dengan minimum thresholds (e.g., results only shown if at least 100 matched customers), (4) No individual-level results — matching happens internally tapi only aggregate outputs returned.

Opsi A: BENAR.
Opsi B: SALAH. Redshift data sharing exposes queryable data; column masking helps tapi individual rows still visible.
Opsi C: SALAH. Shared bucket exposes raw data dari kedua parties — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi D: SALAH. Data Exchange membuat full dataset available ke partner, violating privacy.

A company's data governance team wants to measure their governance maturity. They currently have basic encryption and access controls but lack data cataloging, quality monitoring, and lineage tracking. Which assessment correctly identifies their governance maturity level and the next steps to advance?
  • A. They are at the highest maturity level since encryption and access controls are implemented
  • B. They don't need further governance investment since security controls are sufficient and assign data stewardship roles
  • C. They are at Level 1 (Initial/Ad-hoc) and should immediately implement all governance capabilities simultaneously
  • D. They are at Level 2 (Managed/Reactive) — basic security controls exist but governance is not proactive. To advance to Level 3 (Defined/Proactive): implement data cataloging (DataZone/Glue Catalog), define data quality rules (Glue Data Quality), establish data lineage (OpenLineage/DataZone), create governance policies, and assign data stewardship roles
Jawaban Benar: D
Data governance maturity models typically have 5 levels: Level 1 (Initial) — no formal governance. Level 2 (Managed) — basic controls exist (encryption, IAM) but reactive. Level 3 (Defined) — formal processes, cataloging, quality monitoring, lineage. Level 4 (Quantitatively Managed) — metrics-driven, automated governance. Level 5 (Optimizing) — continuous improvement, AI-driven governance. Perusahaan ini memiliki encryption dan access controls tapi lacks cataloging, quality, lineage — typical Level 2. Next steps ke Level 3: (1) DataZone untuk cataloging dan discovery, (2) Glue Data Quality untuk quality rules, (3) Lineage tracking, (4) Formal policies dan roles.

Opsi A: SALAH. Encryption/access alone bukan highest maturity.
Opsi B: SALAH. Security ≠ governance; governance encompasses quality, cataloging, lineage, stewardship — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi C: SALAH. Level 1 would mean NO controls; they have basic ones. Also "all simultaneously" is impractical.
Opsi D: BENAR.

In a data governance framework, three key roles are defined: Data Owner, Data Steward, and Data Custodian. A conflict arises when the marketing Data Owner wants to share customer data with an external partner, but the Data Steward identifies PII compliance concerns, and the Data Custodian notes that current encryption doesn't meet the partner's security requirements. Who has final authority and what is the resolution process?
  • A. The Data Steward has final authority since they represent compliance and governance
  • B. The Data Custodian blocks all sharing until their technical requirements are met, regardless of business need
  • C. The Data Owner has business decision authority but must address the Steward's compliance concerns (implement PII protection such as anonymization or consent) AND the Custodian's technical concerns (upgrade encryption) before proceeding. If concerns cannot be resolved, escalation goes to the Data Governance Council
  • D. The Data Owner has absolute authority and can override the Steward and Custodian's concerns configured for optimal performance and minimal operational overhead
Jawaban Benar: C
Dalam governance framework yang proper: Data Owner — accountable untuk business decisions tentang data (termasuk sharing), memiliki final business authority TAPI harus comply dengan governance policies. Data Steward — guardian of data quality dan compliance, provides requirements yang Owner must meet (PII handling, consent, regulatory compliance). Data Custodian — responsible untuk technical implementation (encryption, access controls, storage). Resolution: Owner decides to share tapi Steward dan Custodian requirements harus dipenuhi terlebih dahulu. Jika deadlock, Data Governance Council/Committee arbitrates.

Opsi A: SALAH. Steward advises dan sets requirements tapi doesn't make business decisions.
Opsi B: SALAH. Custodian implements solutions, doesn't have blocking authority over business decisions.
Opsi C: BENAR.
Opsi D: SALAH. Owner cannot override compliance requirements — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.

A company is deciding between a centralized governance model (single central team controls all governance) and a federated governance model (domains have autonomy with central policies). Their organization has 15 business domains, each with different data sensitivity levels and regulatory requirements (healthcare domain has HIPAA, finance has SOX, marketing has CCPA). Which model is MORE appropriate and why?
  • A. Federated model — central team defines baseline governance standards (encryption minimums, access control patterns, audit requirements) while each domain implements domain-specific policies addressing their regulatory needs (healthcare adds HIPAA controls, finance adds SOX controls). This balances consistency with domain-specific expertise
  • B. Centralized model — a single team can ensure consistency across all 15 domains with uniform policies
  • C. No formal governance model — let each domain decide independently what governance they need with domain-specific expertise
  • D. Centralized model with exceptions — apply HIPAA controls universally since they're the strictest, which automatically covers SOX and CCPA
Jawaban Benar: A
Federated governance adalah model yang tepat ketika: (1) Multiple domains dengan regulatory requirements berbeda — HIPAA, SOX, CCPA memiliki controls yang berbeda dan specific domain expertise diperlukan, (2) Scale — 15 domains terlalu banyak untuk satu central team mengelola semua detail, (3) Speed — domain teams bisa bergerak cepat tanpa bottleneck central approval untuk domain-specific decisions. Structure: Central team menetapkan BASELINE (minimum encryption standards, access patterns, audit requirements, tooling choices) dan domains ADD domain-specific controls di atas baseline.

Opsi A: BENAR.
Opsi B: SALAH. Uniform policies tidak address domain-specific regulations; central team unlikely memiliki HIPAA + SOX + CCPA expertise.
Opsi C: SALAH. No governance leads to inconsistency dan compliance failures — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi D: SALAH. HIPAA controls tidak automatically cover SOX (financial audit trails) atau CCPA (consumer rights); over-engineering non-healthcare domains menambah cost tanpa benefit.
