A data engineer needs to send email alerts to the on-call team when an AWS Glue ETL job fails. The alert should include the job name, error message, and timestamp. Which approach provides this with LEAST configuration effort?
  • A. Create a CloudWatch alarm on Glue job metrics that triggers SNS
  • B. Use a Lambda function that polls Glue job status every minute with state "FAILED"
  • C. Create an EventBridge rule matching Glue Job State Change events with state "FAILED", targeting an SNS topic that sends emails to the on-call team with input transformation to format the message
  • D. Add error notification code at the end of the Glue job script
Jawaban Benar: C
EventBridge captures Glue job state change events natively. Rule filters for FAILED state dan input transformation extracts jobName, message, timestamp into a readable email format. SNS topic delivers to email subscribers. All configuration, no code needed.

Opsi A: SALAH. Doesn't capture error details like job name and error message in the alert.
Opsi B: SALAH. Adds unnecessary cost and latency — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi C: BENAR.
Opsi D: SALAH. Doesn't execute if job crashes unexpectedly.

A data pipeline sends alerts via SNS when processing completes. The engineering team receives too many notifications (100+ per day for normal operations) causing alert fatigue. Only failures and SLA breaches should generate alerts. How should the notification strategy be improved?
  • A. Implement tiered alerting: use SNS filter policies to route only CRITICAL alerts (failures, SLA breaches) to the pager/email topic, and INFO alerts to a separate low-priority topic or CloudWatch logs only
  • B. Set up email rules to filter out non-critical alerts configured for optimal performance and minimal operational overhead
  • C. Reduce pipeline monitoring to check only once per day
  • D. Unsubscribe the team from all SNS notifications
Jawaban Benar: A
SNS filter policies allow subscribers to receive only messages matching certain criteria (e.g., severity=CRITICAL). Tiered approach: critical alerts → pager/email, informational → log archive or dashboard. This reduces noise while maintaining visibility.

Opsi A: BENAR.
Opsi B: SALAH. Still generates notifications, just hides them client-side — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi C: SALAH. Misses real-time failures requiring immediate action.
Opsi D: SALAH. Loses all visibility.

A data pipeline processes financial data with strict SLA: processing must complete by 6:00 AM daily. If not complete by 5:30 AM, an early warning alert should be sent. If not complete by 6:00 AM, a critical alert should be sent to the manager. Which implementation provides this two-tier alerting?
  • A. Use a CloudWatch alarm with two thresholds configured for optimal performance and minimal operational overhead
  • B. Have the pipeline send a "completion" event and alert if not received
  • C. Use two EventBridge scheduled rules: one at 5:30 AM checks if processing is complete (via Lambda checking status) and sends warning via SNS, another at 6:00 AM sends critical alert if still incomplete
  • D. Set the pipeline timeout to 6:00 AM and alert on timeout
Jawaban Benar: C
Two scheduled checks implement the escalating alert pattern: 5:30 AM Lambda checks pipeline status → if incomplete, publishes WARNING to SNS topic 1 (team email). 6:00 AM check → if still incomplete, publishes CRITICAL to SNS topic 2 (manager pager + team). This provides early warning for proactive intervention before SLA breach.

Opsi A: SALAH. Can't check "not completed by time X — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.".
Opsi B: SALAH. Complex to implement reliably.
Opsi C: BENAR.
Opsi D: SALAH. Only alerts after SLA already breached.

A data engineering team uses Amazon SQS as a buffer between pipeline stages. They need to be alerted when the queue depth exceeds 10,000 messages, indicating a processing backlog. Which monitoring and alerting configuration is correct?
  • A. Create a Lambda function polling the queue depth via GetQueueAttributes every minute
  • B. Configure SQS to send notifications when the queue is full
  • C. Use EventBridge to detect SQS queue depth changes with threshold > 10
  • D. Create a CloudWatch alarm on the ApproximateNumberOfMessagesVisible metric with threshold > 10,000, with the alarm action publishing to an SNS topic
Jawaban Benar: D
SQS natively publishes ApproximateNumberOfMessagesVisible metric to CloudWatch. CloudWatch alarm monitors this metric and triggers when threshold is breached. Alarm action sends to SNS topic for team notification. This is the standard AWS pattern for queue depth monitoring — no custom code needed.

Opsi A: SALAH. Reinvents CloudWatch's built-in capability.
Opsi B: SALAH. SQS doesn't have built-in "queue full" notifications.
Opsi C: SALAH. EventBridge doesn't monitor SQS queue depth natively — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi D: BENAR.
5
A Step Functions workflow has an on-failure SNS notification. When the workflow fails, the SNS notification is sent but only contains the execution ARN, not the actual error details. How can the notification include meaningful error information?
  • A. Configure SNS to automatically fetch details from Step Functions and sends the error to SNS directly
  • B. Increase the SNS message size limit to include full execution history
  • C. Add a Catch state in Step Functions that formats and sends the error to SNS directly
  • D. Use an EventBridge rule matching Step Functions execution status change to FAILED, with input transformation to extract the error and cause fields from the event detail, and target the SNS topic with the formatted message
Jawaban Benar: C
Adding a Catch block (global or per-state) that catches errors and transitions to a "NotifyFailure" state allows formatting the error details (Error, Cause fields) and publishing to SNS with full context. The Catch state receives the error information which can be included in the SNS message.

Opsi A: SALAH. SNS cannot fetch external data — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi B: SALAH. Message size not the issue; content is.
Opsi C: BENAR.
Opsi D: SALAH. Works too but Catch is more direct and captures error details within the workflow.

A company wants to integrate pipeline alerts with their Slack channel and PagerDuty for incident management. The alerts originate from an SNS topic. Which architecture enables multi-channel notification delivery?
  • A. Use AWS Chatbot for Slack integration and a separate SNS subscription for PagerDuty
  • B. Send all alerts to email and let team members forward to Slack/PagerDuty manually
  • C. Create separate EventBridge rules for each destination and a separate SNS subscription for PagerDuty
  • D. SNS topic with multiple subscriptions: Lambda function for Slack (calling Slack webhook API) and HTTPS endpoint subscription for PagerDuty's Events API
Jawaban Benar: A
AWS Chatbot is the native AWS service for Slack integration — it subscribes to SNS topics and formats alerts nicely in Slack channels. For PagerDuty, HTTPS endpoint subscription or Lambda subscriber calls PagerDuty's API. This is the AWS-recommended approach.

Opsi A: BENAR.
Opsi B: SALAH. Defeats automation purpose.
Opsi C: SALAH. Could work but adds complexity if SNS is already the alert source — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi D: SALAH. Works but AWS Chatbot is simpler.
7
A data pipeline publishes processing metrics to SNS after each run. Downstream consumers (dashboard, alerting, auditing) subscribe to this topic. One consumer (the auditing system) must receive EVERY message without loss, even during outages. Which SNS subscription type guarantees this?
  • A. Use an HTTP endpoint subscription with retry enabled
  • B. Subscribe an SQS queue to the SNS topic for the auditing system — SQS retains messages during consumer outages and provides at-least-once delivery guarantee
  • C. Use an email subscription for the auditing system and provides at-least-once delivery guarantee
  • D. Subscribe a Lambda function for the auditing system
Jawaban Benar: B
SQS subscription provides durability — messages persist in the queue (up to 14 days) even if the auditing consumer is down. When the consumer recovers, it processes queued messages. SNS → SQS is the standard pattern for guaranteed delivery to asynchronous consumers.

Opsi A: SALAH. If endpoint is down, SNS retries for limited time then gives up.
Opsi B: BENAR.
Opsi C: SALAH. Emails can be lost, no acknowledgment mechanism — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi D: SALAH. If Lambda fails/throttles, message could be lost without DLQ configuration.
8
A data engineer needs to send different types of alerts from a single SNS topic: "pipeline-alerts". Some subscribers only want failure alerts, others want all alerts including success notifications. How can subscribers selectively receive messages?
  • A. Create separate SNS topics for each alert type configured for optimal performance and minimal operational overhead
  • B. Use SNS message attributes (e.g., "alertType": "FAILURE") and configure subscription filter policies on each subscriber to match only their desired alertType values
  • C. Include filter instructions in the message body
  • D. Let subscribers discard unwanted messages after receiving them
Jawaban Benar: B
SNS subscription filter policies allow subscribers to receive only messages with matching attributes. Publisher sets MessageAttributes (alertType=FAILURE, SUCCESS, etc.). Subscriber A's filter: {"alertType": ["FAILURE"]}. Subscriber B's filter: {"alertType": ["FAILURE", "SUCCESS"]}. Messages not matching a subscriber's filter are not delivered to that subscriber.

Opsi A: SALAH. Increases publisher complexity — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi B: BENAR.
Opsi C: SALAH. SNS doesn't filter on body.
Opsi D: SALAH. Wastes resources.

A Kinesis Data Stream consumer (Lambda) is falling behind — the IteratorAge metric is increasing. The data engineer wants to be alerted when IteratorAge exceeds 5 minutes (300,000 ms), indicating the consumer is lagging. Which alerting configuration is CORRECT?
  • A. CloudWatch alarm on IncomingRecords metric exceeding a threshold
  • B. CloudWatch alarm on GetRecords.IteratorAgeMilliseconds metric (Maximum statistic) with threshold > 300000, alarm action targeting SNS topic
  • C. EventBridge rule matching Kinesis stream events with threshold > 300000
  • D. Lambda CloudWatch Logs metric filter for "IteratorAge" text
Jawaban Benar: B
GetRecords.IteratorAgeMilliseconds is the Kinesis metric showing how far behind the consumer is. Maximum statistic captures the worst-case lag. Alarm threshold 300,000 ms = 5 minutes. When breached, alarm publishes to SNS. This directly monitors consumer lag.

Opsi A: SALAH. Shows ingestion rate, not consumer lag.
Opsi B: BENAR.
Opsi C: SALAH. Kinesis doesn't emit EventBridge events for consumer lag — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi D: SALAH. Requires the Lambda to explicitly log iterator age.
10
A data pipeline processes sensitive financial data. Compliance requires that alert notifications (sent via SNS) must NOT contain actual data values — only metadata like job name, status, and timestamp. A developer accidentally publishes customer account numbers in SNS messages. How can this be prevented architecturally?
  • A. Enable SNS encryption at rest configured for optimal performance and minimal operational overhead
  • B. Add an IAM policy preventing certain data from being published
  • C. Use SNS message filtering to block messages containing numbers
  • D. Implement a Lambda function between the pipeline and SNS that sanitizes messages — removing or masking any PII/sensitive data before publishing to SNS, using a predefined allow-list of safe fields
Jawaban Benar: D
A sanitization Lambda acts as a gatekeeper between the pipeline and SNS. It validates that only allowed fields (job_name, status, timestamp) are present, strips or masks anything else. This enforces the compliance policy regardless of what the pipeline code sends. Allow-list approach is more secure than deny-list.

Opsi A: SALAH. Protects stored data, doesn't prevent sensitive data in message content — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi B: SALAH. Cannot inspect message content.
Opsi C: SALAH. Blocks entire messages, doesn't sanitize content.
Opsi D: BENAR.
