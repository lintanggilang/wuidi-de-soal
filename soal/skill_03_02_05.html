#EMR#EC2
A company runs nightly batch ETL jobs that process 2 TB of data consistently every night, taking 3 hours to complete. The workload runs 365 days per year with predictable resource requirements. The data engineering team is choosing between Amazon EMR on EC2 (provisioned) and Amazon EMR Serverless. Which option is MOST cost-effective for this specific workload pattern?
  • A. EMR on EC2 with Spot Instances for maximum cost savings, validating and cleansing each record before delivery
  • B. EMR on EC2 with Reserved Instances because sustained high-utilization workloads benefit from RI pricing discounts
  • C. EMR Serverless because it automatically scales resources to match the workload, reducing day-to-day operational effort
  • D. EMR Serverless because it eliminates idle cluster costs with Reserved Instances because sustained high-utilization workloads benefit
Jawaban Benar: B
Untuk workload yang predictable, consistent, dan berjalan setiap hari sepanjang tahun, Reserved Instances memberikan diskon hingga 72% dibanding On-Demand pricing. EMR on EC2 dengan RI ideal untuk sustained utilization pattern. EMR Serverless mengenakan premium untuk convenience dan lebih cost-effective untuk sporadic/unpredictable workloads.

Opsi A: SALAH. Berisiko interruption yang bisa menggagalkan 3-hour job.
Opsi B: BENAR.
Opsi C: SALAH. Berlaku tapi cost advantage tidak berlaku untuk steady predictable workload.
Opsi D: SALAH. Benar tapi per-compute-hour rate lebih mahal dari RI — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.

#Athena#Redshift
A startup has unpredictable analytics query patterns. Some days they run hundreds of queries against their data warehouse, while other days they run none. They need sub-second query response for small queries and can tolerate 30-second startup for larger queries. Which Amazon Redshift deployment option is MOST appropriate?
  • A. Amazon Redshift Provisioned with dc2.large nodes running 24/7 with fully managed infrastructure
  • B. Amazon Redshift Provisioned with pause/resume scheduled during business hours only
  • C. Amazon Redshift Serverless with appropriate RPU (Redshift Processing Unit) base capacity
  • D. Amazon Athena as a replacement for Redshift for unpredictable workloads
Jawaban Benar: C
Redshift Serverless secara otomatis scales compute resources berdasarkan workload demand. Pada hari tanpa query, biaya mendekati nol (hanya storage). Pada hari sibuk, resources scale up sesuai kebutuhan. RPU base capacity memungkinkan warm state untuk response cepat.

Opsi A: SALAH. Sangat wasteful untuk workload unpredictable — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi B: SALAH. Memerlukan prediksi kapan query akan dijalankan, tidak cocok untuk truly unpredictable patterns.
Opsi C: BENAR.
Opsi D: SALAH. Adalah solusi berbeda yang mungkin tidak memenuhi kebutuhan performa sub-second untuk complex queries.

#DynamoDB
A gaming company experiences massive traffic spikes during game launches (100x normal traffic) that last 2-3 hours, then traffic returns to normal levels. Their DynamoDB table stores player session data. During normal operations, the table handles 1,000 write requests/second. During launches, it needs to handle 100,000 writes/second. Which capacity mode should they choose?
  • A. Provisioned capacity at 100,000 WCU constantly to ensure readiness
  • B. On-demand capacity mode to handle spikes without pre-planning with scheduled scaling that increases
  • C. Provisioned capacity with scheduled scaling that increases before known game launches
  • D. Provisioned capacity with auto-scaling configured to scale up to 100,000 WCU
Jawaban Benar: C
Untuk spikes yang diketahui sebelumnya (game launches dijadwalkan), scheduled scaling pada provisioned capacity adalah pilihan paling cost-effective. Table di-scale up sebelum launch dan scale down setelah traffic kembali normal.

Opsi A: SALAH. Sangat wasteful untuk 1,000 WCU normal usage.
Opsi B: SALAH. Lebih mahal per request dan memiliki throttling pada initial spike jika previous peak belum mencapai level tersebut — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi C: BENAR.
Opsi D: SALAH. Memiliki lag time yang bisa menyebabkan throttling saat traffic naik 100x secara tiba-tiba (auto-scaling reacts, doesn't predict).

#Glue#EMR#EC2
A data engineering team is evaluating AWS Glue (serverless) versus Amazon EMR on EC2 (provisioned) for their ETL pipeline. The pipeline processes various datasets ranging from 100 MB to 500 GB, runs 3-4 times per day, and each job takes between 5 minutes and 2 hours depending on dataset size. The team has limited DevOps expertise. Which factor MOST strongly favors AWS Glue in this scenario?
  • A. AWS Glue eliminates the need to manage cluster lifecycle, patching, and capacity planning, which is critical for a team with limited DevOps expertise
  • B. AWS Glue supports more data formats than EMR, removing the need to provision or patch any infrastructure and applying schema conversion and enrichment inline
  • C. AWS Glue has faster processing speed than EMR for all dataset sizes with limited DevOps expertise, reducing day-to-day operational effort and minimizing end-to-end processing latency
  • D. AWS Glue provides better integration with the AWS Glue Data Catalog than EMR, transforming records into the required target format and reducing day-to-day operational effort
Jawaban Benar: A
Keuntungan utama serverless (Glue) adalah eliminasi operational overhead. Tim tidak perlu mengelola cluster lifecycle (start/stop/resize), OS patching, security updates, atau capacity planning. Untuk tim dengan limited DevOps, ini sangat signifikan.

Opsi A: BENAR.
Opsi B: SALAH. Salah karena EMR mendukung lebih banyak framework/format.
Opsi C: SALAH. Salah karena EMR bisa lebih cepat dengan konfigurasi optimal — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi D: SALAH. Salah karena EMR juga terintegrasi dengan Glue Data Catalog secara native.

#Lambda#Glue#EMR#EC2#Spark
A financial company has a data pipeline that must start processing within 2 seconds of data arrival with zero tolerance for cold start delays. The pipeline performs complex Spark transformations on streaming data. Which service deployment model addresses this latency requirement?
  • A. AWS Lambda triggered by the data arrival event
  • B. EMR Serverless with pre-initialized application, minimizing end-to-end processing latency
  • C. AWS Glue streaming ETL job with auto-scaling with real-time processing and low-latency
  • D. Amazon EMR on EC2 with a long-running Spark Structured Streaming application
Jawaban Benar: D
Amazon EMR on EC2 dengan long-running Spark Structured Streaming application selalu aktif dan ready to process data tanpa cold start. Application terus polling sumber data dan memproses dalam micro-batches (bisa serendah 100ms trigger interval). Zero cold start karena cluster selalu running.

Opsi A: SALAH. Memiliki cold start dan tidak mendukung complex Spark transformations.
Opsi B: SALAH. Memiliki cold start 1-2 menit bahkan dengan pre-initialized workers.
Opsi C: SALAH. Juga always-on tapi memiliki higher startup time jika job perlu di-restart — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi D: BENAR.

#EMR#Athena#Redshift#S3
A company is designing their data analytics architecture. They run ad-hoc queries ranging from simple SELECT statements (completing in seconds) to complex analytical queries joining multiple large tables (taking up to 30 minutes). Query volume varies from 5 queries/day to 200 queries/day. They want to optimize for cost while maintaining query performance. Which architecture BEST balances these requirements?
  • A. Amazon Redshift Serverless for complex queries with Athena for simple ad-hoc queries on S3 data
  • B. Amazon Athena for all queries since it's pay-per-query with Athena for simple ad-hoc queries on S3 data
  • C. Amazon EMR with Presto for all analytical queries, integrating natively with the rest of the pipeline
  • D. Amazon Redshift Provisioned ra3.xlplus cluster with 2 nodes running 24/7, avoiding charges for idle provisioned capacity
Jawaban Benar: A
Arsitektur hybrid memberikan optimasi terbaik: Redshift Serverless handles complex analytical queries dengan performa tinggi dan auto-scales berdasarkan demand (hemat saat volume rendah). Athena handles simple ad-hoc queries dengan biaya per-scan yang minimal. Ini memberikan cost-effectiveness karena kedua service hanya charge saat digunakan.

Opsi A: BENAR.
Opsi B: SALAH. Kurang optimal untuk complex multi-join queries yang berjalan 30 menit — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi C: SALAH. Memerlukan cluster management dan tidak cost-optimal untuk variable workloads.
Opsi D: SALAH. Wasteful pada hari dengan 5 queries.

#Glue#EMR#Athena#Redshift#S3#DynamoDB#EC2#Spark#Hive
A data engineer is migrating an on-premises Hadoop cluster to AWS. The cluster runs diverse workloads: Spark ETL, Hive queries, Presto interactive queries, and HBase for key-value access. The team wants maximum flexibility in framework versions and custom configurations. Which AWS service provides the MOST flexibility while maintaining the existing tool ecosystem?
  • A. AWS Glue for ETL, Athena for queries, and DynamoDB for key-value access
  • B. Amazon EMR on EC2 with all required frameworks installed on the cluster
  • C. Amazon Redshift for queries and S3 for storage, applying schema conversion and enrichment inline
  • D. EMR Serverless for Spark and Hive workloads with all required frameworks installed
Jawaban Benar: B
Amazon EMR on EC2 menyediakan fleksibilitas maksimum: mendukung semua framework Hadoop ecosystem (Spark, Hive, Presto, HBase), memungkinkan custom AMIs, bootstrap actions untuk konfigurasi spesifik, dan kontrol penuh atas versi framework. Ini paling mirip dengan on-premises Hadoop.

Opsi A: SALAH. Memecah ke multiple services yang memerlukan rewrite signifikan.
Opsi B: BENAR.
Opsi C: SALAH. Berbeda paradigma dan tidak mendukung HBase/Spark workloads.
Opsi D: SALAH. Hanya mendukung Spark dan Hive, bukan Presto atau HBase — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.

#Glue#EMR#Athena#Redshift#EC2#CloudTrail#KMS
A company's data pipeline processes customer data subject to strict compliance requirements. The security team mandates that all compute resources must run within a private VPC, must use customer-managed encryption keys, and must support detailed audit logging of all operations. How does this requirement impact the choice between provisioned and serverless services?
  • A. Provisioned services offer more granular network controls through security groups and NACLs, making them slightly more suitable for highly regulated environments
  • B. Only provisioned services (EMR on EC2, Redshift Provisioned) can meet these requirements because serverless services don't support VPC deployment
  • C. Serverless services are more secure because AWS manages the underlying infrastructure patching with fully managed infrastructure and automatic scaling
  • D. Both provisioned and serverless AWS data services support VPC, KMS encryption, and CloudTrail logging, so security is not a differentiator
Jawaban Benar: D
AWS serverless data services (Glue, Athena, Redshift Serverless, EMR Serverless) semuanya mendukung VPC deployment, KMS customer-managed keys, dan CloudTrail logging. Keamanan bukan lagi differentiator utama antara provisioned dan serverless.

Opsi A: SALAH. Partially true tapi granular network controls juga tersedia di serverless melalui VPC configurations dan security groups.
Opsi B: SALAH. Salah karena Glue mendukung VPC connections, EMR Serverless mendukung VPC, dll.
Opsi C: SALAH. Oversimplifies (patching bukan satu-satunya aspek security) — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi D: BENAR.

#Glue#EMR#EC2#Spark
A data engineering team runs an EMR Serverless Spark application that processes variable-size datasets (ranging from 10 GB to 2 TB). They notice that for small datasets (10-50 GB), the EMR Serverless job takes 4-5 minutes just to initialize before actual processing begins, while the processing itself only takes 2 minutes. For large datasets, the same initialization time is negligible compared to 45-minute processing. How should the team optimize for small dataset jobs?
  • A. Use EMR Serverless pre-initialized capacity (pre-warmed workers) to eliminate cold start for frequently run small jobs
  • B. Switch all small dataset processing to AWS Glue which has no initialization time
  • C. Batch small datasets together to amortize the initialization cost across more data for frequently run small jobs
  • D. Use a long-running EMR on EC2 cluster for small datasets and EMR Serverless for large datasets
Jawaban Benar: A
EMR Serverless pre-initialized capacity (pre-warmed workers) menjaga pool of initialized workers yang ready to execute, menghilangkan cold start time. Workers tetap warm dan bisa langsung mulai processing. Biaya pre-initialized workers lebih rendah dari running cluster tapi menghilangkan 4-5 menit cold start.

Opsi A: BENAR.
Opsi B: SALAH. Salah karena Glue juga memiliki startup time.
Opsi C: SALAH. Menambah latency untuk individual datasets — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi D: SALAH. Berfungsi tapi lebih kompleks secara operasional dengan dua systems berbeda.

#Redshift
A company is evaluating total cost of ownership (TCO) between Amazon Redshift Provisioned and Amazon Redshift Serverless. Their workload characteristics are: 8 hours of heavy querying during business hours (averaging 80% cluster utilization), 4 hours of moderate querying (40% utilization), and 12 hours of minimal activity (5% utilization). Which analysis correctly identifies when provisioned becomes more cost-effective?
  • A. Provisioned is always cheaper because you can use Reserved Instances with RI becomes more cost-effective when the effective average utilization exceeds approximately 30-40%
  • B. Provisioned with RI becomes more cost-effective when the effective average utilization exceeds approximately 30-40%, which this workload achieves with its weighted average of ~40%
  • C. Serverless is always cheaper because you only pay for actual compute used, reducing day-to-day operational effort and requiring no servers to manage or scale manually
  • D. The choice depends solely on the number of queries, not utilization patterns, reducing day-to-day operational effort and optimizing cost for the described workload
Jawaban Benar: B
TCO comparison antara provisioned (RI) dan serverless bergantung pada average utilization. Provisioned RI memberikan fixed cost regardless of usage, sehingga semakin tinggi utilization semakin cost-effective. Weighted average utilization: (8h × 80% + 4h × 40% + 12h × 5%) / 24h ≈ 37%. Dengan RI discounts (hingga 72% off on-demand), provisioned menjadi lebih murah di titik ini dibanding serverless yang charges per-RPU-hour consumed.

Opsi A: SALAH. Dan B terlalu absolut — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi B: BENAR.
Opsi C: SALAH.
Opsi D: SALAH. Salah karena utilization pattern (bukan hanya query count) menentukan cost.
