A data engineer is configuring an AWS Glue ETL job to read from an on-premises SQL Server database using JDBC. The database is accessible via AWS Site-to-Site VPN. The Glue connection test succeeds, but the ETL job fails with "Unable to connect" errors. What is the MOST likely cause?
  • A. The SQL Server does not support JDBC connections, validating and cleansing each record before delivery and providing exactly-once processing semantics
  • B. The Glue job timeout is too short, meeting the latency and throughput goals of the design
  • C. The Glue connection's security group does not have a self-referencing inbound rule allowing all TCP traffic from itself
  • D. The JDBC URL format is incorrect configured for optimal performance and minimal operational overhead, applying schema conversion and enrichment inline
Correct Answer: C
AWS Glue requires a self-referencing inbound rule on the connection's security group. This allows Glue workers (which share the same security group) to communicate with each other. Without this, the Glue job fails even if the connection test (which uses a single ENI) succeeds.

Option A: INCORRECT. Salah — SQL Server supports JDBC.
Option B: INCORRECT. Menyebabkan error different.
Option C: CORRECT.
Option D: INCORRECT. Not suitable because connection test already succeeds — although its description sounds convincing, in a fundamental still not appropriate for requirements this.

  • A. Use Redshift Spectrum to query PostgreSQL directly, handling the described workload reliably at scale and meeting the latency and throughput goals of the design

Option C: INCORRECT. Mengubah architecture and eliminates real-time access — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option D: INCORRECT. Not can is used from Redshift SQL directly.

An AWS Glue ETL job connects to an Amazon RDS MySQL database via JDBC. The job runs for 4 hours and processes data from 20 tables in parallel. The RDS instance reaches its max_connections limit (150) and starts rejecting connections. Which Glue JDBC configuration prevents this?
  • A. Use Glue job bookmarks to reduce the amount of data read and use connection pooling in the JDBC URL
  • B. Set the numPartitions parameter to a value lower than max_connections and use connection pooling in the JDBC URL
  • C. Increase the RDS instance class to get more max_connections, transforming records into the required target format
  • D. Process tables sequentially instead of in parallel, satisfying all of the stated requirements with minimal effort
Correct Answer: B
numPartitions (or hashpartitions in Glue) determines number concurrent connections that Glue membuka to database. Menetapkan this in bawah max_connections (for example 50) prevents connection exhaustion. Connection pooling in JDBC URL reduces connection churn.

Option A: INCORRECT. Reduces data volume but not connection count per se — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option B: CORRECT.
Option C: INCORRECT. Mahal and only while.
Option D: INCORRECT. Very slow.

  • A. Upload the JDBC driver JAR file to S3 and specify its path in the Glue connection's "JDBC driver - custom path" or in the job's extra jars parameter
  • B. Install the JDBC driver on the Glue worker nodes via SSH with native S3 integration and optimized data transfer, handling the described workload reliably at scale
  • C. Use ODBC connection instead, which doesn't require a driver, meeting the latency and throughput goals of the design and integrating natively with the rest of the pipeline
  • D. Submit a support ticket to AWS to add the driver to the Glue environment, handling the described workload reliably at scale and integrating natively with the rest of the pipeline
Correct Answer: A
AWS Glue supports custom JDBC drivers. Driver JAR in-upload to S3 and direferensikan in Glue connection (class name and S3 path) or via --extra-jars job parameter. Glue automatic mendownload and memuat driver saat job dimulai.

Option A: CORRECT.
Option B: INCORRECT. Glue managed service without SSH access to workers — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option C: INCORRECT. ODBC also requires driver and Glue primarily uses JDBC.
Option D: INCORRECT. Not way that feasible.

A data engineer configures an Amazon EMR Spark application to read from a MySQL database using JDBC. The table has 500 million rows. The read operation is slow because Spark uses a single partition. Which Spark JDBC options enable parallel reads?
  • A. Increase the Spark executor memory, handling the described workload reliably at scale
  • B. Use spark.sql.shuffle.partitions configuration, scaling elastically to millions of events per second
  • C. Specify partitionColumn, lowerBound, upperBound, and numPartitions in the JDBC read options
  • D. Enable Spark Adaptive Query Execution (AQE) and numPartitions in the JDBC read options
Correct Answer: C
Spark JDBC parallel read requires: partitionColumn (numeric column for split), lowerBound/upperBound (range values), and numPartitions (number parallel connections). Spark creates numPartitions queries with WHERE clauses that divides range.

Option A: INCORRECT. Not mengaktifkan parallelism.
Option B: INCORRECT. For shuffle operations, not JDBC reads.
Option C: CORRECT.
Option D: INCORRECT. Mengoptimalkan shuffle but not affect JDBC source parallelism — although its description sounds convincing, in a fundamental still not appropriate for requirements this.

A data engineer is troubleshooting an AWS Glue JDBC connection to an Amazon Aurora PostgreSQL cluster. The connection test passes, but the ETL job intermittently fails with "Connection reset" errors after running for 30 minutes. What is the MOST likely cause?
  • A. The Aurora cluster needs to be rebooted configured for optimal performance and minimal operational overhead, applying schema conversion and enrichment inline
  • B. The Aurora cluster's idle connection timeout is closing inactive JDBC connections; configure connection validation/keep-alive in the JDBC URL parameters
  • C. The JDBC driver version is incompatible with Aurora, applying schema conversion and enrichment inline and delivering records with consistent sub-second latency
  • D. The Glue job has insufficient DPUs, satisfying all of the stated requirements with minimal effort and keeping steady-state operating costs low
Correct Answer: B
Aurora (PostgreSQL) has idle_in_transaction_session_timeout and tcp_keepalives_idle parameters that menutup connection idle. For job that runs old, several connection can menjadi idle and in-close. Solusinya is adds parameter keepalive and validation connection in JDBC URL (for example tcpKeepAlive=true, connectTimeout, socketTimeout).

Option A: INCORRECT. Not solution berkelanjutan — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option B: CORRECT.
Option C: INCORRECT. Will fails from awal not intermittent.
Option D: INCORRECT. Menyebabkan OOM not connection reset.

A company uses Amazon EMR to run Hive queries that join data from an S3 data lake with reference data in an Amazon RDS SQL Server database. The Hive queries need JDBC connectivity to SQL Server. Which EMR component enables this?
  • A. Install SQL Server client tools on the EMR master node with the JDBC URL, satisfying all of the stated requirements with minimal effort
  • B. Use EMR's built-in SQL Server connector in the cluster configuration, transforming records into the required target format and validating and cleansing each record before delivery
  • C. Export SQL Server data to S3 first, then join in Hive, validating and cleansing each record before delivery and applying schema conversion and enrichment inline
  • D. Configure a Hive JDBC storage handler and create an external table pointing to the SQL Server database with the JDBC URL and credentials
Correct Answer: D
Hive supports JDBC storage handler (org.apache.hive.storage.jdbc.JdbcStorageHandler) that enables creates external table that backed by JDBC source. CREATE EXTERNAL TABLE ... STORED BY 'org.apache.hive.storage.jdbc.JdbcStorageHandler' WITH SERDEPROPERTIES ("hive.sql.jdbc.url"=...).

Option A: INCORRECT. Not integrates with Hive query engine — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option B: INCORRECT. Not ada built-in SQL Server connector in EMR configuration.
Option C: INCORRECT. Mengubah architecture and eliminates real-time reference data.
Option D: CORRECT.

A data engineer needs to ensure secure JDBC connections between AWS Glue and an Amazon RDS database. The company security policy requires encryption in transit for all database connections. How should this be configured?
  • A. Enable SSL/TLS on the RDS instance and add SSL parameters to the JDBC connection URL (e.g., useSSL=true, requireSSL=true, and specify the RDS CA certificate)
  • B. Use a VPC endpoint for RDS to encrypt traffic and add SSL parameters to the JDBC connection URL, satisfying strict compliance and audit requirements
  • C. Configure the Glue security group to only allow encrypted connections, integrating natively with the rest of the pipeline and enforcing encryption and fine-grained access control
  • D. Enable encryption at rest on the RDS instance, enforcing encryption and fine-grained access control and protecting the data both in transit and at rest
Correct Answer: A
Encryption in transit for JDBC connections requires SSL/TLS. RDS supports SSL and provides CA certificates. JDBC URL is configured with SSL parameters: useSSL=true, requireSSL=true for MySQL; ssl=true, sslmode=require for PostgreSQL. Glue uses URL this for encrypted connections.

Option A: CORRECT.
Option B: INCORRECT. RDS Interface Endpoints not automatic encrypt JDBC traffic — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option C: INCORRECT. Not can enforce encryption level.
Option D: INCORRECT. Melindungi data in storage, not in transit.
