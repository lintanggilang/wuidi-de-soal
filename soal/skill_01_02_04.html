Skill 1.2.4: Optimize Costs While Processing Data

Cost optimization strategies for ETL workloads using AWS Glue, EMR, Redshift, and serverless services

1
A company runs an AWS Glue ETL job daily that processes 100 GB of data. The job uses 50 G.1X workers and completes in 30 minutes. Analysis shows that workers are only 40% utilized during the run. Which change MOST reduces cost without impacting completion time?
  • A. Enable Glue Auto Scaling to dynamically adjust the number of workers based on actual utilization
  • B. Increase the number of workers to 100 to complete faster
  • C. Switch to G.2X worker type for more memory per worker configured for optimal performance and minimal operational overhead
  • D. Reduce the job timeout to force faster completion
Jawaban Benar: A
Glue Auto Scaling secara otomatis mengurangi jumlah workers ketika mereka under-utilized. Dengan 40% utilization, Auto Scaling akan menurunkan worker count, mengurangi DPU-hours yang dibayar. Job tetap selesai tepat waktu karena Glue menambah workers saat dibutuhkan. Opsi B (lebih banyak workers) menambah biaya. Opsi C (G.2X) lebih mahal per DPU-hour — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini. Opsi D (timeout) tidak mengontrol resource usage.
2
A data engineer uses Amazon Athena to process data stored in S3. The team queries 5 TB of CSV data daily for reporting. Athena charges per TB scanned. Which optimization reduces Athena costs by the MOST?
  • A. Convert CSV to Apache Parquet with Snappy compression and partition the data by commonly-filtered columns
  • B. Compress CSV files with gzip and partition the data by commonly-filtered columns
  • C. Use Athena workgroups with query result reuse enabled
  • D. Increase the Athena query timeout
Jawaban Benar: A
Parquet (columnar format) + compression + partitioning memberikan cost reduction terbesar. Parquet memungkinkan column pruning (hanya baca kolom yang diquery). Snappy compression mengurangi ukuran data 5-10x. Partitioning memungkinkan partition pruning (skip partisi yang tidak relevant). Kombinasi bisa mengurangi scan dari 5TB ke <100GB. Opsi B (gzip CSV) mengurangi ukuran tapi masih row-oriented (baca semua kolom) — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini. Opsi C (result reuse) hanya untuk repeated identical queries. Opsi D tidak mempengaruhi biaya.
3
A company runs daily ETL processing on Amazon EMR. The jobs take 3 hours. The cluster runs 24/7 but is only used during the 3-hour processing window. Which change provides the GREATEST cost savings?
  • A. Use transient EMR clusters that are created for the job and terminated after completion, with Spot Instances for task nodes
  • B. Right-size the cluster by reducing instance types with Spot Instances for task nodes for the job and terminated after completion
  • C. Purchase Reserved Instances for the EMR cluster
  • D. Enable EMR Managed Scaling on the existing cluster
Jawaban Benar: A
Transient clusters hanya berjalan selama job execution (3 jam) vs 24 jam — biaya berkurang 87.5% (dari 24h ke 3h). Spot Instances untuk task nodes menambah savings 60-90% pada compute. Total savings bisa 90%+. Opsi B (right-size) memberikan savings tapi cluster masih idle 21 jam — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini. Opsi C (Reserved) masih paying 24/7 meskipun lebih murah per jam. Opsi D (Managed Scaling) membantu saat running tapi tidak menghilangkan idle time.
4
A data engineer runs multiple small AWS Glue ETL jobs (each processing <1 GB) throughout the day. Each job allocates the default 10 DPUs. The jobs complete in 2-3 minutes but are billed for a minimum of 1 minute. What optimization reduces costs?
  • A. Reduce the NumberOfWorkers to 2 (minimum for Glue Spark ETL) since the data volume is small and doesn't need 10 DPUs
  • B. Combine all small jobs into a single large job that runs once daily
  • C. Switch to AWS Glue Python Shell jobs (charged at 1 DPU or 0.0625 DPU) for small data volumes
  • D. Run jobs more frequently with smaller datasets for small data volumes
Jawaban Benar: C
Glue Python Shell jobs menggunakan 1 DPU atau 0.0625 DPU (1/16 DPU) — jauh lebih murah dari Spark ETL (minimum 2 DPUs). Untuk data kecil (<1 GB) yang tidak membutuhkan distributed processing, Python Shell sangat cost-effective. Processing pandas-style cukup untuk volume kecil. Opsi A (2 workers) masih 2 DPU yang 32x lebih mahal dari 0.0625 DPU shell. Opsi B (combine) mengubah timeliness. Opsi D (more frequent) meningkatkan biaya — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
5
A company processes streaming data using Amazon Managed Service for Apache Flink (formerly Kinesis Data Analytics). The application runs 24/7 but traffic is 10x higher during business hours (8 AM to 6 PM) compared to overnight. KPU usage is over-provisioned at night. Which optimization reduces cost?
  • A. Enable Auto Scaling for the Flink application with min and max KPU limits to scale down during low-traffic periods
  • B. Stop the application at night and restart in the morning with min and max KPU limits to scale down during low-traffic periods
  • C. Use a smaller parallelism setting permanently
  • D. Buffer data in Kinesis during off-hours and process in batch the next morning
Jawaban Benar: A
Auto Scaling untuk Managed Flink (KDA) secara otomatis menyesuaikan KPU count berdasarkan traffic. Selama malam dengan 1/10 traffic, application scales down, reducing KPU costs. Selama business hours, scales up untuk handle load. Opsi B (stop/restart) kehilangan data atau meningkatkan Kinesis retention costs — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini. Opsi C (lower parallelism permanently) menyebabkan lag selama peak hours. Opsi D mengubah dari streaming ke batch yang mungkin melanggar business requirements.
6
A data engineer uses Amazon Redshift for ETL transformations. The cluster runs expensive CTAS (CREATE TABLE AS SELECT) queries that take 2 hours daily. The rest of the day the cluster is used only for light dashboard queries. Which Redshift feature reduces cost for this pattern?
  • A. Use Redshift Serverless which auto-scales compute to zero during idle periods and scales up for heavy ETL workloads
  • B. Pause the provisioned Redshift cluster overnight and scales up for heavy ETL workloads
  • C. Use Redshift concurrency scaling for the ETL workload
  • D. Resize the cluster to the minimum before ETL and resize back after
Jawaban Benar: A
Redshift Serverless secara otomatis mengalokasikan compute sesuai workload. Untuk heavy ETL (2 hours), compute scales up. Untuk light queries, compute minimal. Saat idle, charges berdasarkan RPU usage bukan provisioned capacity. Ini jauh lebih cost-effective untuk variable workloads. Opsi B (pause) hanya membantu overnight tapi cluster tetap provisioned saat idle selama day — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini. Opsi C (concurrency scaling) menambah capacity bukan reduce cost. Opsi D (resize) memakan waktu dan disrupts service.
7
A data pipeline writes intermediate results to S3 between processing stages. The intermediate data (500 GB daily) is only needed for 24 hours before the next run overwrites it. However, the data accumulates because no cleanup is configured. Which S3 feature prevents unnecessary storage cost accumulation?
  • A. Configure an S3 Lifecycle policy to expire objects after 1 day on the intermediate data prefix
  • B. Use S3 Intelligent-Tiering for the intermediate data
  • C. Move intermediate data to Glacier after 1 day
  • D. Enable S3 versioning to manage old data with native S3 integration and optimized data transfer
Jawaban Benar: A
S3 Lifecycle expiration policy otomatis menghapus objects setelah X hari. Dengan expiration 1 hari pada prefix intermediate data, objects dihapus setelah 24 jam, mencegah akumulasi storage costs. Opsi B (Intelligent-Tiering) mengurangi per-GB cost tapi data tetap terakumulasi. Opsi C (Glacier) memindahkan ke cheaper storage tapi masih menyimpan semua data. Opsi D (versioning) justru menyimpan lebih banyak copies — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
8
A data engineer runs an AWS Glue ETL job that reads 2 TB from S3, performs a simple filter (keeping 10% of records), and writes results back to S3. The job uses 100 G.1X workers and takes 45 minutes. Which optimization MOST reduces cost for this specific workload pattern?
  • A. Use S3 Select or Glue pushdown predicates to filter data at read time, dramatically reducing the data volume processed by Glue workers
  • B. Increase workers to 200 to finish faster (less DPU-hours)
  • C. Switch to G.2X workers for faster processing with native S3 integration and optimized data transfer
  • D. Run the job less frequently (weekly instead of daily)
Jawaban Benar: A
Jika job hanya mempertahankan 10% records, pushdown predicates atau S3 Select memfilter di sumber — Glue hanya memproses 200 GB bukan 2 TB. Ini mengurangi workers yang dibutuhkan secara dramatis (mungkin 10-20 workers cukup), mengurangi DPU-hours 80-90%. Opsi B (double workers) — DPU-hours tetap ~sama (half time × double workers). Opsi C (G.2X) lebih mahal per DPU-hour — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini. Opsi D mengubah business requirement.
9
A company processes data using both AWS Glue and Amazon EMR for different workloads. The monthly bill shows: Glue ETL $15,000 (various small jobs), EMR $25,000 (one large daily job on On-Demand). Which combination of changes provides the LARGEST total cost reduction?
  • A. Consolidate small Glue jobs where possible and enable Auto Scaling; switch EMR to Spot Instances for task nodes and Savings Plans for core nodes
  • B. Move all workloads to a single EMR cluster
  • C. Move all workloads to Glue
  • D. Switch everything to Lambda functions for task nodes and Savings Plans for core nodes
Jawaban Benar: A
Targeted optimizations per service: Consolidating small Glue jobs reduces startup overhead; Auto Scaling right-sizes workers. For EMR ($25K), Spot Instances on task nodes save 60-90%, Savings Plans on core nodes save ~40%. Combined savings could be 50%+ of total $40K bill. Opsi B (all EMR) — Glue small jobs lebih cocok sebagai serverless tanpa cluster management. Opsi C (all Glue) — large EMR job mungkin lebih cost-effective on EMR. Opsi D (Lambda) tidak bisa handle large-scale processing — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
10
A data pipeline uses AWS Glue to process data that is stored as many small files (100,000 files, average 1 MB each) in S3. The Glue job takes 2 hours due to excessive task scheduling overhead. The engineer wants to reduce both runtime and cost. Which optimization addresses the small files problem?
  • A. Enable Glue groupFiles option to combine small files into larger groups before processing, reducing the number of Spark tasks
  • B. Add more DPUs to process files faster configured for optimal performance and minimal operational overhead
  • C. Use Glue Python Shell job instead of Spark
  • D. Enable Glue job bookmarks
Jawaban Benar: A
groupFiles menggabungkan file-file kecil menjadi groups sebelum dibaca, mengurangi jumlah Spark tasks dari 100,000 ke beberapa ratus. Ini mengurangi scheduling overhead drastis, memperpendek runtime (mungkin dari 2 jam ke 20 menit), dan otomatis mengurangi DPU-hours yang dibayar. Opsi B (more DPUs) menambah parallelism tapi scheduling overhead tetap karena banyak tasks — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini. Opsi C (Python Shell) tidak bisa handle 100 GB secara efisien. Opsi D (bookmarks) untuk incremental processing bukan file grouping.
