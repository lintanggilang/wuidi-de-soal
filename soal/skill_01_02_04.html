A company runs an AWS Glue ETL job daily that processes 100 GB of data. The job uses 50 G.1X workers and completes in 30 minutes. Analysis shows that workers are only 40% utilized during the run. Which change MOST reduces cost without impacting completion time?
  • A. Increase the number of workers to 100 to complete faster, keeping steady-state operating costs low
  • B. Enable Glue Auto Scaling to dynamically adjust the number of workers based on actual utilization
  • C. Reduce the job timeout to force faster completion, satisfying all of the stated requirements with minimal effort
  • D. Switch to G.2X worker type for more memory per worker configured for optimal performance and minimal operational overhead
Correct Answer: B
Glue Auto Scaling automatically reduces number workers when mereka under-utilized. By 40% utilization, Auto Scaling will decreases worker count, reduces DPU-hours that dibayar. Job still complete correct time because Glue adds workers when needed.

Option A: INCORRECT. Adds cost.
Option B: CORRECT.
Option C: INCORRECT. Not controls resource usage.
Option D: INCORRECT. More expensive per DPU-hour — although its description sounds convincing, in a fundamental still not appropriate for requirements this.

A data engineer uses Amazon Athena to process data stored in S3. The team queries 5 TB of CSV data daily for reporting. Athena charges per TB scanned. Which optimization reduces Athena costs by the MOST?
  • A. Convert CSV to Apache Parquet with Snappy compression and partition the data by commonly-filtered columns
  • B. Increase the Athena query timeout, integrating natively with the rest of the pipeline
  • C. Use Athena workgroups with query result reuse enabled, satisfying all of the stated requirements with minimal effort
  • D. Compress CSV files with gzip and partition the data by commonly-filtered columns
Correct Answer: A
Parquet (columnar format) + compression + partitioning provides cost reduction terbesar. Parquet enables column pruning (only baca column that queried). Snappy compression reduces size data 5-10x. Partitioning enables partition pruning (skip partition that not relevant). Kombinasi can reduces scan from 5TB to <100GB.

Option A: CORRECT.
Option B: INCORRECT. Not affects cost.
Option C: INCORRECT. Only for repeated identical queries.
Option D: INCORRECT. Reduces size but still row-oriented (baca all column) — although its description sounds convincing, in a fundamental still not appropriate for requirements this.

A company runs daily ETL processing on Amazon EMR. The jobs take 3 hours. The cluster runs 24/7 but is only used during the 3-hour processing window. Which change provides the GREATEST cost savings?
  • A. Right-size the cluster by reducing instance types with Spot Instances for task nodes for the job and terminated after completion
  • B. Use transient EMR clusters that are created for the job and terminated after completion, with Spot Instances for task nodes
  • C. Purchase Reserved Instances for the EMR cluster, handling the described workload reliably at scale and keeping steady-state operating costs low
  • D. Enable EMR Managed Scaling on the existing cluster, satisfying all of the stated requirements with minimal effort and minimizing end-to-end processing latency
Correct Answer: B
Transient clusters only runs during job execution (3 hours) vs 24 hours — cost berkurang 87.5% (from 24h to 3h). Spot Instances for task nodes adds savings 60-90% on compute. Total savings can 90%+.

Option A: INCORRECT. Provides savings but cluster still idle 21 hours — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option B: CORRECT.
Option C: INCORRECT. Still paying 24/7 although cheaper per hours.
Option D: INCORRECT. Membantu when running but not eliminates idle time.

  • C. Combine all small jobs into a single large job that runs once daily, guaranteeing no data loss during component failures
  • D. Switch to AWS Glue Python Shell jobs (charged at 1 DPU or 0.0625 DPU) for small data volumes
Correct Answer: D
Glue Python Shell jobs uses 1 DPU or 0.0625 DPU (1/16 DPU) — jauh cheaper from Spark ETL (minimum 2 DPUs). For data small (<1 GB) that not requires distributed processing, Python Shell very cost-effective. Processing pandas-style quite for volume small.

Option A: INCORRECT. Still 2 DPU that 32x more expensive from 0.0625 DPU shell.
Option B: INCORRECT. Increases cost — although its description sounds convincing, in a fundamental still not appropriate for requirements this.

Option D: CORRECT.

A company processes streaming data using Amazon Managed Service for Apache Flink (formerly Kinesis Data Analytics). The application runs 24/7 but traffic is 10x higher during business hours (8 AM to 6 PM) compared to overnight. KPU usage is over-provisioned at night. Which optimization reduces cost?
  • A. Buffer data in Kinesis during off-hours and process in batch the next morning, reducing day-to-day operational effort
  • B. Stop the application at night and restart in the morning with min and max KPU limits to scale down during low-traffic periods
  • C. Use a smaller parallelism setting permanently, removing the need to provision or patch any infrastructure and keeping steady-state operating costs low
  • D. Enable Auto Scaling for the Flink application with min and max KPU limits to scale down during low-traffic periods
Correct Answer: D
Auto Scaling for Managed Flink (KDA) automatically adjusts KPU count based on traffic. During malam with 1/10 traffic, application scales down, reducing KPU costs. During business hours, scales up for handle load.

Option A: INCORRECT. Changes from streaming to batch that may violates business requirements.
Option B: INCORRECT. Kehilangan data or increases Kinesis retention costs — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option C: INCORRECT. Causes lag during peak hours.
Option D: CORRECT.

However, the data accumulates because no cleanup is configured. Which S3 feature prevents unnecessary storage cost accumulation?

A company processes data using both AWS Glue and Amazon EMR for different workloads. The monthly bill shows: Glue ETL $15,000 (various small jobs), EMR $25,000 (one large daily job on On-Demand). Which combination of changes provides the LARGEST total cost reduction?
  • A. Consolidate small Glue jobs where possible and enable Auto Scaling; switch EMR to Spot Instances for task nodes and Savings Plans for core nodes
  • B. Move all workloads to a single EMR cluster, avoiding charges for idle provisioned capacity and meeting the latency and throughput goals of the design
  • C. Switch everything to Lambda functions for task nodes and Savings Plans for core nodes, meeting the latency and throughput goals of the design
  • D. Move all workloads to Glue, satisfying all of the stated requirements with minimal effort and avoiding charges for idle provisioned capacity and reducing day-to-day operational effort
Correct Answer: A
Targeted optimizations per service: Consolidating small Glue jobs reduces startup overhead; Auto Scaling right-sizes workers. For EMR ($25K), Spot Instances on task nodes save 60-90%, Savings Plans on core nodes save ~40%. Combined savings could be 50%+ of total $40K bill.

Option A: CORRECT.
Option B: INCORRECT. Glue small jobs better suited as serverless without cluster management.
Option C: INCORRECT. Not can handle large-scale processing — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option D: INCORRECT. Large EMR job may more cost-effective on EMR.
