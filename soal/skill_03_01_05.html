A data engineering team manages a REST API deployed on Amazon API Gateway that serves analytics data to multiple internal consumer teams. They need to release a new version of the API with breaking schema changes while allowing existing consumers to continue using the current version during a 3-month migration window. Which API Gateway versioning strategy provides the LEAST operational overhead?
  • A. Use custom domain name with base path mappings to route /v1 and /v2 to different API stages
  • B. Create a completely separate API Gateway REST API for v2 with a new endpoint URL
  • C. Use API Gateway stage variables to route requests to different Lambda function versions based on the deployment stage (v1, v2)
  • D. Implement versioning through request headers and use a single Lambda function with conditional logic
Correct Answer: A
Custom domain names with base path mappings enables routing path-based (/v1, /v2) to API stages that different in bawah satu domain. Ini provides URL that bersih for consumers (api.company.com/v1/data, api.company.com/v2/data) and separates deployment in a full without overhead manages dua API separate.

Option A: CORRECT.
Option B: INCORRECT. Adds overhead manajemen dua API separate.
Option C: INCORRECT. Baik for configuration but stage variables not supports routing to versi API that correct-correct different in a struktural.
Option D: INCORRECT. Mencampur logika versi in satu function that difficult in-maintain.

They need to communicate this deprecation to all consumers proactively and track which consumers have migrated. Which combination of approaches is MOST effective?
  • A. Add a "Deprecation" and "Sunset" HTTP response header to the deprecated endpoint, enable API Gateway access logging to track consumer usage by API key

Correct Answer: A
Uses HTTP headers "Deprecation" (RFC 8594) and "Sunset" provides machine-readable notice that can dideteksi by consumer applications automatically. API Gateway access logging with API keys enables tracking granular about consumer mana that still uses endpoint deprecated. Ini combines komunikasi proaktif with monitoring.

Option A: CORRECT.
Option B: INCORRECT. Will directly memecah consumer that not siap — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option C: INCORRECT. Not provides tracking and easy terlewat.
Option D: INCORRECT. Not identifies consumer individual that not yet migration.

A data engineer needs to add a new optional field "processing_timestamp" to an existing API response without breaking any current consumers. The API is documented using OpenAPI specification and consumed by multiple teams. Which change is considered backward compatible?
  • A. Rename an existing field from "timestamp" to "processing_timestamp" to better describe its purpose, integrating natively with the rest of the pipeline
  • B. Add the new field as a required field in the response with a default value configured for optimal performance
  • C. Add the new optional field to the response body — consumers that don't need it can simply ignore it
  • D. Change the data type of the existing "timestamp" field from string to integer (Unix epoch), providing exactly-once processing semantics
Correct Answer: C
Adds field optional new to response body is backward-compatible change because consumer that already ada mengabaikan field that not mereka kenal (appropriate with Postel's Law / Robustness Principle).

Option A: INCORRECT. Adalah breaking change because consumer that reads field old not will menemukan data mereka.
Option B: INCORRECT. Can jadi problem if consumer performs strict schema validation — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option C: CORRECT.
Option D: INCORRECT. Adalah breaking change that will menyebabkan parsing errors on consumer that mengharapkan string.

Tiered usage plans enables diferensiasi service level between consumer groups. Critical consumers mendapat throttle/burst limits higher so that still can accesses API saat traffic spike. Method-level throttling melindungi endpoint that expensive in a komputasi.

Option A: INCORRECT. Not provides prioritas and can overload backend.
