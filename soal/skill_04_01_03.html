A data engineer stores Amazon RDS PostgreSQL credentials in AWS Secrets Manager with automatic rotation enabled every 30 days. After a rotation occurs, an AWS Glue ETL job fails to connect to the database with "authentication failed" errors, but recovers after being restarted. What is the MOST likely cause of this issue?
  • A. The Glue job caches the database credentials at startup and does not refresh them when rotation occurs during a long-running job
  • B. The rotation Lambda function failed to update the password in the RDS database configured for optimal performance and minimal operational overhead
  • C. Secrets Manager requires a manual approval step after rotation before the new credentials become active, handling the described workload reliably at scale
  • D. The Glue job's IAM role does not have permission to access the rotated secret version, validating and cleansing each record before delivery
Correct Answer: A
Glue jobs that long-running retrieves credentials saat startup and menyimpannya in memory. If rotasi occurs during job runs, job still uses credentials old that already not valid. Setelah restart, job retrieves credentials new and succeeds. Solusinya is implement credential refresh logic in job or uses connection that retrieves from Secrets Manager in a periodik.

Option A: CORRECT.
Option B: INCORRECT. Kurang possibility because job succeeds setelah restart — berarti credentials new valid — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option C: INCORRECT. Salah — Secrets Manager not requires manual approval, rotasi automatic directly active.
Option D: INCORRECT. Permission applies for all secret versions.

A company has multiple data pipelines (Glue jobs, Lambda functions, EMR applications) that all connect to a shared Amazon Aurora MySQL cluster. The security team mandates credential rotation every 7 days without any application downtime. Which Secrets Manager rotation strategy should the data engineer implement?
  • A. Multi-user alternating rotation strategy that alternates between two database users
  • B. Create a new database user on each rotation and delete the old one after 24 hours
  • C. Use IAM database authentication instead of Secrets Manager to eliminate password rotation entirely
  • D. Single-user rotation strategy where the existing user's password is directly updated
Correct Answer: A
Multi-user alternating rotation strategy uses dua database users that bergantian. Saat rotasi: user active (AWSCURRENT) still valid while user cadangan (AWSPREVIOUS) mendapat password new. Setelah complete, label ditukar. Ini ensures zero downtime because credentials old still valid until rotasi berikutnya.

Option A: CORRECT.
Option B: INCORRECT. Requires update permissions on each user new and very difficult in-maintain.
Option C: INCORRECT. Bagus but has connection limit (256 connections/seconds) that may not quite for multiple pipelines.
Option D: INCORRECT. Has window singkat where connections with password old will fails during rotation process — berisiko downtime.

A data engineer needs to store credentials for an on-premises Oracle database that is accessed by AWS Glue jobs. The credential includes hostname, port, username, password, and SID. The engineer evaluates AWS Secrets Manager versus AWS Systems Manager Parameter Store (SecureString). Which factor is the PRIMARY reason to choose Secrets Manager over Parameter Store for this use case?
  • A. Secrets Manager supports encryption with KMS keys while Parameter Store does not, satisfying strict compliance and audit requirements
  • B. Secrets Manager supports cross-region replication while Parameter Store is single-region only with Lambda integration
  • C. Secrets Manager can store larger values (up to 64 KB) compared to Parameter Store (4 KB limit)
  • D. Secrets Manager provides built-in automatic rotation with Lambda integration, which Parameter Store does not natively support
Correct Answer: D
Keunggulan main Secrets Manager dibanding Parameter Store is built-in automatic rotation capability with Lambda rotation functions. Secrets Manager provides rotation templates for berbagai databases and custom rotation Lambda functions for credential others. Parameter Store SecureString can stores credentials with encryption KMS but not has native rotation mechanism.

Option A: INCORRECT. Salah — Parameter Store SecureString also uses KMS encryption.
Option B: INCORRECT. Meskipun Secrets Manager supports cross-region replication, this not alasan PRIMARY for credential management use case.
Option C: INCORRECT. Salah — Parameter Store Advanced tier supports up to 8 KB, and 4 KB quite for credentials.
Option D: CORRECT.

The rotation Lambda function needs network access to both the Secrets Manager API and the Redshift cluster in a private VPC subnet. How should the engineer configure the rotation Lambda function's network access?
  • A. Deploy the Lambda function in the VPC with a NAT Gateway for Secrets Manager API access and direct VPC connectivity to Redshift, handling the described workload reliably at scale
  • B. Deploy the Lambda function in the VPC with a Secrets Manager VPC Interface Endpoint and ensure the security group allows outbound HTTPS to the endpoint and port 5439 to Redshift
  • C. Deploy the Lambda function outside the VPC with a Redshift public endpoint enabled configured for optimal performance and minimal operational overhead, handling the described workload reliably at scale
  • D. Deploy the Lambda function outside the VPC and use VPC peering to reach the Redshift cluster, satisfying all of the stated requirements with minimal effort and enforcing encryption and fine-grained access control
Correct Answer: B
Lambda rotation function must in-deploy in VPC that same with Redshift (for direct network access to port 5439). For accesses Secrets Manager API (that merupakan public service), is required VPC Interface Endpoint for Secrets Manager (secretsmanager.region.amazonaws.com). Ini enables Lambda accesses Secrets Manager API without internet access.

Option A: INCORRECT. Berfungsi but adds cost and requires internet gateway — less secure dibanding VPC endpoint.
Option B: CORRECT.
Option C: INCORRECT. Not can accesses Redshift in private subnet — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option D: INCORRECT. Not possible — Lambda in luar VPC not has VPC attachment for peering.

A data engineer implements credential rotation for a database used by multiple microservices. After rotation, some services get the new password (AWSCURRENT) while others still use the cached old password. The engineer wants to understand the secret versioning mechanism. During the rotation process, which version stages exist and what is their purpose?
  • A. AWSCURRENT (active credentials) and AWSBACKUP (rollback credentials) only and AWSPREVIOUS (last known good credentials)
  • B. AWSCURRENT (active credentials), AWSNEXT (scheduled future credentials), and AWSARCHIVED (historical credentials)
  • C. PRIMARY (active credentials), SECONDARY (backup credentials), and TERTIARY (historical credentials), applying schema conversion and enrichment inline
  • D. AWSCURRENT (active credentials), AWSPENDING (new credentials being tested), and AWSPREVIOUS (last known good credentials)
Correct Answer: D
Secrets Manager uses tiga version stages during rotation: (1) AWSCURRENT — credentials that active saat this, dikembalikan in a default saat GetSecretValue is called. (2) AWSPENDING — credentials new that sedang is created and ditest by rotation Lambda during rotation process. (3) AWSPREVIOUS — credentials sebelumnya that still valid, useful for services that still uses credentials old. Rotation Lambda melewati 4 steps: createSecret (buat AWSPENDING), setSecret (set in database), testSecret (validation AWSPENDING works), finishSecret (promosikan AWSPENDING menjadi AWSCURRENT). Opsi other uses label that not exist in Secrets Manager.

Option A: INCORRECT. Meskipun sounds convincing, still not correct for skenario this.
Option B: INCORRECT.
Option C: INCORRECT.
Option D: CORRECT.

A data team in Account A needs to access a database credential stored in AWS Secrets Manager in Account B. The Glue jobs in Account A must retrieve the secret at runtime. Which configuration enables this cross-account secret access?
  • A. Share the secret through AWS Resource Access Manager (RAM) to Account A configured for optimal performance and minimal operational overhead, satisfying all of the stated requirements with minimal effort and handling the described workload reliably at scale
  • B. In Account B: Add a resource-based policy on the secret allowing Account A's Glue role to perform secretsmanager:GetSecretValue. In Account A: Grant the Glue role permission to call secretsmanager:GetSecretValue on the Account B secret ARN.
  • C. Replicate the secret from Account B to Account A using Secrets Manager cross-region replication, meeting the latency and throughput goals of the design and handling the described workload reliably at scale and keeping steady-state operating costs low
  • D. Create an IAM user in Account B with access to the secret, and store those access keys in Account A's Secrets Manager, meeting the latency and throughput goals of the design and reducing day-to-day operational effort
Correct Answer: B
Cross-account secret access requires configuration in kedua akun: (1) Account B (resource owner): Resource-based policy on secret that allows Account A's role ARN for GetSecretValue. If secret encrypted with CMK, KMS key policy also must allow Account A. (2) Account A (requester): IAM policy on Glue role that allows secretsmanager:GetSecretValue on ARN secret in Account B.

Option A: INCORRECT. Not supports sharing Secrets Manager secrets — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option B: CORRECT.
Option C: INCORRECT. Not cross-account — this for DR between regions.
Option D: INCORRECT. Melanggar best practice and menimbulkan credential management recursion.

A data engineer needs to configure automatic rotation for Amazon Redshift cluster credentials stored in Secrets Manager. AWS provides native integration for Redshift rotation. Which statement about Secrets Manager's native Redshift rotation is CORRECT?
  • A. Native Redshift rotation changes the password in Secrets Manager but requires manual execution of ALTER USER on the Redshift cluster with fully managed infrastructure and automatic scaling
  • B. Native Redshift rotation is only available for Redshift Serverless, not provisioned Redshift clusters, integrating natively with the rest of the pipeline and minimizing end-to-end processing latency
  • C. Native Redshift rotation requires the engineer to write a custom Lambda function that uses the Redshift Data API to change the password
  • D. Native Redshift rotation uses a Secrets Manager-managed Lambda function that directly connects to Redshift to change the master user password without requiring custom code
Correct Answer: D
AWS Secrets Manager provides managed rotation for Amazon Redshift (baik provisioned maupun Serverless). Saat native rotation is configured, Secrets Manager creates and manages Lambda function that automatically: (1) Generates password new. (2) Connects to Redshift cluster. (3) Runs ALTER USER for changes password. (4) Updates secret value. Not needs custom code — quite configuration rotation schedule and network access (Lambda must can reach Redshift and Secrets Manager).

Option A: INCORRECT. Salah — rotation changes password in Redshift and Secrets Manager automatically — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option B: INCORRECT. Salah — available for keduanya.
Option C: INCORRECT. Salah — custom Lambda not is required for database that supported.
Option D: CORRECT.

A data engineer has a Lambda function that retrieves database credentials from Secrets Manager on every invocation. The function is invoked 10,000 times per minute. The engineer is concerned about Secrets Manager API throttling and cost. What is the MOST cost-effective approach to reduce API calls while maintaining security?
  • A. Cache the secret value in a DynamoDB table and read from DynamoDB instead, avoiding charges for idle provisioned capacity
  • B. Store the credentials in Lambda environment variables encrypted with KMS configured for optimal performance and minimal operational overhead
  • C. Use the AWS Secrets Manager caching library (client-side caching) with a configurable TTL in the Lambda function
  • D. Use Parameter Store instead of Secrets Manager as it has higher API rate limits
Correct Answer: C
AWS provides Secrets Manager Caching Library (available for Python, Java, .NET, Go) that performs client-side caching with configurable TTL. Library this stores secret value in memory Lambda execution environment and only calls Secrets Manager API saat cache expired. Ini in a drastis reduces API calls (from 10,000/minutes menjadi several calls per cache TTL period).

Option A: INCORRECT. Adds service dependency and risiko security — credentials stored in persistent store.
Option B: INCORRECT. Not supports automatic rotation — must redeploy Lambda each kali password changes — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option C: CORRECT.
Option D: INCORRECT. Has throughput limit that same and not solves problem caching.

A company's compliance policy requires that all database credentials must be rotated every 14 days. A data engineer configures Secrets Manager rotation for an RDS MySQL database. Two weeks after initial setup, the rotation fails. CloudWatch Logs from the rotation Lambda show "Access denied connecting to RDS instance." The rotation was working initially. What is the MOST likely cause?
  • A. The rotation Lambda function's security group was modified, removing access to the RDS instance on port 3306, meeting the latency and throughput goals of the design
  • B. The Secrets Manager VPC endpoint was deleted, preventing the Lambda function from communicating with Secrets Manager API, enforcing encryption and fine-grained access control
  • C. The master user credentials stored in a separate admin secret (used by the rotation function) have expired or been manually changed outside of Secrets Manager
  • D. The RDS instance was moved to a different subnet since initial configuration configured for optimal performance and minimal operational overhead, satisfying strict compliance and audit requirements
Correct Answer: C
For multi-user rotation strategy, rotation Lambda requires "master secret" — credentials admin/master user that is used for creates and changes password user other. If master credentials is changed manually (in luar Secrets Manager) or expired, rotation Lambda cannot login to database for performs changes password, produces "Access denied connecting to RDS." Error this specific menunjukkan problem database authentication, not network.

Option A: INCORRECT. Will produces "connection timeout," not "access denied.".
Option B: INCORRECT. Will produces error on Secrets Manager API calls, not RDS connection.
Option C: CORRECT.
Option D: INCORRECT. Also produces connectivity error, not auth error — although its description sounds convincing, in a fundamental still not appropriate for requirements this.

A data engineer manages an EMR cluster that runs multiple Spark jobs requiring credentials to connect to various data sources (RDS, Redshift, third-party API). The credentials are stored in AWS Secrets Manager. What is the RECOMMENDED way for Spark jobs on EMR to retrieve secrets from Secrets Manager?
  • A. Store all credentials in EMR cluster configuration properties at launch time and reference them as Spark configuration parameters, meeting the latency and throughput goals of the design
  • B. Use the AWS SDK (boto3) within the Spark job code to call Secrets Manager GetSecretValue at runtime, with the EMR EC2 instance profile role providing access
  • C. Use EMR's native Secrets Manager integration to automatically inject secrets as environment variables on all nodes with the EMR EC2 instance profile role providing access
  • D. Create a bootstrap action that writes all secrets to a file on the master node, then distribute the file to all workers via HDFS
Correct Answer: B
Best practice is uses AWS SDK (boto3 for Python) in in Spark job code for calls Secrets Manager GetSecretValue API saat runtime. EMR EC2 instances uses instance profile role that must has permission secretsmanager:GetSecretValue. Credentials is retrieved saat needed and not is stored in a persistent.

Option A: INCORRECT. Credentials menjadi visible in EMR configuration and not supports rotation setelah cluster launch.
Option B: CORRECT.
Option C: INCORRECT. Salah — EMR not has native integration for auto-inject Secrets Manager secrets sebagai environment variables — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option D: INCORRECT. Very not secure — credentials stored plaintext in filesystem that accessible by all users.
