Amazon EventBridge for event routing and scheduling in data pipelines

1
A data engineer needs to trigger a data processing pipeline every weekday at 2:00 AM UTC, but also needs to trigger the same pipeline on-demand when a specific S3 object is uploaded. The pipeline is implemented as a Step Functions state machine. Which EventBridge configuration supports BOTH trigger patterns with MINIMAL components?
  • A. Create two EventBridge rules on the default event bus — one schedule rule (cron expression for weekdays at 2 AM) and one event pattern rule matching S3 PutObject — both targeting the same Step Functions state machine
  • B. Use EventBridge Scheduler for the cron job and a separate S3 Event Notification directly triggering Step Functions
  • C. Create a single EventBridge rule with a complex pattern matching both schedule and S3 events
  • D. Use CloudWatch Events for the schedule and EventBridge for the S3 event pattern
Jawaban Benar: A
EventBridge mendukung dua jenis rules pada satu event bus: schedule rules (cron/rate expressions) dan event pattern rules. Kedua rules dapat mengarah ke target yang sama (Step Functions). Ini adalah pendekatan paling sederhana dengan satu service managing kedua triggers. Opsi B menggunakan dua service berbeda (EventBridge Scheduler + S3 notifications) yang menambah complexity. Opsi C salah — satu rule tidak bisa matching baik schedule maupun event pattern sekaligus. Opsi D (CloudWatch Events + EventBridge) redundant karena CloudWatch Events sekarang merupakan bagian dari EventBridge.
2
A company needs to schedule a one-time data migration job to run at a specific date and time (December 31, 2024 at 23:59 UTC). After execution, the schedule should be automatically cleaned up. They also need timezone-aware scheduling for recurring reports that run at 9 AM in each regional office's local time. Which AWS service handles BOTH requirements?
  • A. Amazon EventBridge Scheduler — supporting one-time schedules with auto-delete after completion and timezone-aware recurring schedules
  • B. EventBridge rules with rate expressions for recurring schedules and a Lambda function to create/delete one-time rules
  • C. AWS Systems Manager Maintenance Windows for one-time tasks and EventBridge rules for recurring schedules
  • D. Amazon MWAA (Airflow) DAGs with timezone-aware schedule intervals
Jawaban Benar: A
Amazon EventBridge Scheduler (bukan EventBridge rules) dirancang khusus untuk scheduling use cases. Fiturnya termasuk: one-time schedules (at expressions) dengan FlexibleTimeWindow, auto-delete setelah execution, timezone-aware cron expressions (IANA timezone support), dan built-in retry policies. Opsi B (EventBridge rules) tidak mendukung one-time schedule dengan auto-cleanup natively — memerlukan custom cleanup logic. Opsi C (Maintenance Windows) untuk patching/maintenance, bukan data pipeline scheduling. Opsi D (MWAA) berlebihan overhead untuk simple scheduling needs.
3
A data platform team needs to route AWS Glue job state change events (SUCCEEDED, FAILED, TIMEOUT) to different targets: successful completions trigger a downstream pipeline, failures send notifications to the ops team, and timeouts restart the job with increased resources. Which EventBridge configuration implements this routing logic?
  • A. Create three separate EventBridge rules with event patterns matching specific "detail.state" values (SUCCEEDED, FAILED, TIMEOUT) on the Glue Job State Change event, each with its own target
  • B. Create one rule matching all Glue job state changes and use input transformers to route to different targets
  • C. Use a single Lambda function as the target that reads the state and routes accordingly
  • D. Configure Glue job notifications directly to SNS, SQS, and Step Functions for each state
Jawaban Benar: A
EventBridge event patterns mendukung matching pada nested fields dalam event detail. Tiga rules terpisah, masing-masing matching pada "detail.state" yang spesifik, memungkinkan routing langsung ke target yang berbeda tanpa intermediate processing. Ini menggunakan EventBridge's native content-based routing. Opsi B salah — input transformers mengubah event format tetapi satu rule hanya bisa memiliki satu set targets, bukan routing conditional. Opsi C (Lambda router) bekerja tetapi menambah latency, cost, dan maintenance dibandingkan native EventBridge routing. Opsi D salah — Glue tidak mendukung direct notification configuration ke multiple services per state.
4
A multi-account organization has a centralized data lake account. Data engineering teams in 5 different AWS accounts need to send events when their ETL jobs complete, so the central account can trigger consolidation pipelines. Which EventBridge architecture enables this cross-account event routing?
  • A. Create a custom event bus in the central account with a resource-based policy allowing PutEvents from the 5 source accounts, and configure rules in source accounts to forward events to the central event bus
  • B. Use the default event bus in each account with cross-account rules that directly invoke targets in the central account
  • C. Set up AWS Organizations EventBridge integration to automatically share all events across member accounts
  • D. Deploy identical EventBridge rules in all accounts and use SNS cross-account subscriptions for event delivery
Jawaban Benar: A
Cross-account event routing di EventBridge dilakukan dengan: (1) membuat custom event bus di central account dengan resource-based policy yang mengizinkan PutEvents dari source accounts, (2) membuat rules di source accounts yang mengirim events ke central account's event bus sebagai target. Rules di central account kemudian memproses incoming events. Opsi B salah — default event bus tidak bisa menjadi target cross-account rule langsung. Opsi C salah — tidak ada auto-sharing di Organizations level untuk semua events. Opsi D (SNS) menambah component yang tidak perlu karena EventBridge sudah mendukung cross-account natively.
5
A data engineer needs to build a point-to-point integration that reads records from a DynamoDB Stream, filters them based on item attributes, enriches the payload with additional metadata, and delivers them to a Kinesis Data Stream. The solution should not require custom Lambda code for simple transformations. Which EventBridge feature provides this capability?
  • A. Amazon EventBridge Pipes — connecting DynamoDB Stream as source, with filtering and enrichment stages, to Kinesis Data Stream as target
  • B. EventBridge rules with input transformers to modify the event payload before delivery
  • C. EventBridge event bus with multiple rules for filtering and a Lambda enrichment function
  • D. EventBridge Scheduler with a recurring poll of DynamoDB Stream
Jawaban Benar: A
Amazon EventBridge Pipes dirancang untuk point-to-point integrations dengan pipeline stages: Source (DynamoDB Streams, SQS, Kinesis, etc.) → Filter (event pattern matching) → Enrichment (optional Lambda, Step Functions, API Gateway, or API Destination) → Target (Kinesis, Lambda, Step Functions, etc.). Ini menyediakan filtering tanpa Lambda code dan optional enrichment. Opsi B (input transformers) hanya mengubah format, bukan enrich dari external source. Opsi C memerlukan Lambda code untuk enrichment yang bertentangan dengan requirement. Opsi D (Scheduler) untuk time-based triggers, bukan stream processing.
6
A data pipeline uses EventBridge to trigger Lambda functions for processing. Occasionally, the target Lambda function is throttled or temporarily unavailable, causing event delivery to fail. The team needs to ensure no events are permanently lost and failed events can be investigated later. Which EventBridge mechanism handles this?
  • A. Configure a dead-letter queue (SQS) on the EventBridge rule and set retry policy with maximum age and retry attempts
  • B. Enable EventBridge event replay to automatically redeliver failed events
  • C. Configure Lambda's async invocation DLQ to capture events that EventBridge couldn't deliver
  • D. Use CloudWatch Logs to record all failed delivery attempts and manually reprocess them
Jawaban Benar: A
EventBridge rules mendukung dead-letter queue (SQS) configuration dimana events yang gagal dikirim setelah retry attempts dikirim ke DLQ untuk investigation. Retry policy mengonfigurasi: maximum event age (berapa lama EventBridge retry sebelum menyerah) dan maximum retry attempts. Ini memastikan tidak ada event yang hilang secara permanen. Opsi B (event replay) untuk memutar ulang archived events, bukan untuk handling delivery failures. Opsi C (Lambda async DLQ) hanya bekerja jika event berhasil sampai ke Lambda — jika EventBridge gagal deliver, Lambda DLQ tidak membantu. Opsi D (CloudWatch Logs) tidak menyimpan event payload untuk reprocessing.
7
A data engineering team deployed a change to their ETL pipeline that introduced a bug, causing incorrect data to be written for the past 3 hours. They need to reprocess all events that occurred during that time window from the original source events. The events were routed through EventBridge. Which feature enables reprocessing of historical events?
  • A. Use EventBridge archive and replay — replay archived events from the specific time window to a new rule that triggers the corrected pipeline
  • B. Query CloudTrail logs for the events that were published and manually re-invoke the pipeline for each
  • C. Enable EventBridge event bus logging and extract events from CloudWatch Logs for reprocessing
  • D. Configure the event source to resend all events from the past 3 hours
Jawaban Benar: A
EventBridge Archive menyimpan events yang match an archive rule, dan Replay memungkinkan re-delivery events dari archive untuk time window tertentu ke event bus. Events yang di-replay memiliki "replay-name" header sehingga rules dapat membedakan replay events dari live events. Ini built-in untuk exactly this use case — reprocessing historical events. Opsi B (CloudTrail) mencatat API calls, bukan event payloads. Opsi C (CloudWatch Logs) tidak menyimpan structured events untuk replay. Opsi D (resend from source) mungkin tidak feasible — source system mungkin tidak mendukung historical resending.
8
A company has a data pipeline where an S3 upload event needs to trigger different processing based on the file type: CSV files go to a Glue job, Parquet files go to an Athena query, and JSON files go to a Lambda function. All events come through the default EventBridge event bus. Which approach provides the MOST maintainable routing implementation?
  • A. Create three EventBridge rules with event patterns that match on the S3 object key suffix (.csv, .parquet, .json), each routing to its respective target
  • B. Create one rule that sends all S3 events to a Lambda router function that inspects the file extension and invokes the appropriate service
  • C. Configure three separate S3 event notifications with prefix/suffix filters, each pointing to the respective service
  • D. Use a Step Functions state machine with a Choice state that routes based on file extension
Jawaban Benar: A
EventBridge event patterns mendukung content-based routing dengan matching pada S3 event detail fields termasuk object key. Tiga rules terpisah memberikan clear separation of concerns, mudah di-maintain (add/remove rules independently), dan leverages EventBridge's native routing capability tanpa custom code. Opsi B (Lambda router) menambah latency, cost, dan maintenance burden. Opsi C (S3 event notifications) bisa bekerja tetapi memiliki limit per bucket dan kurang flexible dibanding EventBridge patterns. Opsi D (Step Functions) overhead untuk simple routing — Step Functions lebih cocok untuk complex orchestration.
9
A data engineer is designing an event-driven architecture where application events from multiple microservices need to be processed by the data platform. The team wants to isolate data platform events from application events, apply different retention policies, and allow only authorized services to publish to the data platform's event bus. Which EventBridge architecture meets these requirements?
  • A. Create a custom event bus for the data platform with a resource-based policy restricting PutEvents to authorized service roles, and configure archive with appropriate retention on the custom bus
  • B. Use the default event bus with IAM policies to restrict which services can publish specific event types
  • C. Create an SNS topic for inter-service communication and subscribe EventBridge as a target
  • D. Use EventBridge Pipes from each microservice directly to the data platform's processing targets
Jawaban Benar: A
Custom event bus menyediakan: (1) isolasi dari default bus events — hanya events yang explicitly dikirim ke custom bus yang ada di sana, (2) resource-based policy yang mengontrol siapa yang boleh PutEvents, (3) independent archive configuration dengan retention policy terpisah. Ini memenuhi semua tiga requirements: isolation, access control, dan retention. Opsi B (default bus + IAM) mencampur semua events di satu bus tanpa isolation yang bersih. Opsi C (SNS) menambah component dan tidak menyediakan archive/retention natively. Opsi D (Pipes) untuk point-to-point, bukan many-to-many event distribution.
10
A data platform runs daily ETL jobs triggered by EventBridge Scheduler. The team notices that some jobs occasionally fail to start at the scheduled time due to transient service issues. They need a scheduling solution that: retries if the target is temporarily unavailable, allows a flexible time window for execution, and provides visibility into schedule execution history. Which EventBridge Scheduler configuration addresses all requirements?
  • A. Configure EventBridge Scheduler with a retry policy (MaximumRetryAttempts and MaximumEventAgeInSeconds), FlexibleTimeWindow for execution jitter, and use CloudWatch metrics (InvocationAttemptCount, TargetErrorCount) for monitoring
  • B. Use EventBridge rules with cron expressions and configure dead-letter queues for failed invocations
  • C. Implement a Lambda function that polls for missed schedule executions and retriggers them
  • D. Use AWS Step Functions with a Wait state and built-in retry logic to manage scheduling
Jawaban Benar: A
EventBridge Scheduler memiliki built-in features untuk semua requirements: (1) Retry Policy dengan configurable MaximumRetryAttempts dan MaximumEventAgeInSeconds untuk automatic retries pada transient failures, (2) FlexibleTimeWindow yang mendistribusikan invocations dalam time window untuk mengurangi thundering herd dan accommodate jitter, (3) CloudWatch metrics (InvocationAttemptCount, TargetErrorCount, InvocationDroppedCount) memberikan visibility ke execution history. Opsi B (EventBridge rules) memiliki retry tapi tidak FlexibleTimeWindow. Opsi C (Lambda polling) custom dan unreliable. Opsi D (Step Functions Wait) bukan scheduling service.
