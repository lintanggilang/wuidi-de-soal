Preventing data from being copied to unauthorized AWS Regions for data residency compliance

1
A German bank processes customer data that must remain within the EU under GDPR data residency requirements. Their AWS Organization contains accounts across eu-west-1, eu-central-1, and us-east-1. Developers have been accidentally creating resources in us-east-1. Which preventive control MOST effectively ensures no data resources can be created outside EU regions across the entire organization?
  • A. Apply a Service Control Policy (SCP) at the organization root that denies all actions except for global services when aws:RequestedRegion is not in the approved EU region list
  • B. Use AWS Config rules to detect resources in non-EU regions and automatically terminate them, handling the described workload reliably at scale and integrating natively with the rest of the pipeline
  • C. Disable non-EU regions in the AWS Organizations account settings for all member accounts configured for optimal performance and minimal operational overhead, meeting the latency and throughput goals of the design
  • D. Create IAM policies in each account that deny all actions when aws:RequestedRegion is not an EU region, meeting the latency and throughput goals of the design
Correct Answer: A
SCPs (Service Control Policies) is preventive controls that applies for SEMUA principals in account (including root user). SCP that deny actions when aws:RequestedRegion not including EU regions prevents creation resource in region that not is allowed. SCP must excludes global services (IAM, Route 53, CloudFront, dll) that operates from us-east-1 but bersifat global.

Option A: CORRECT.
Option B: INCORRECT. Adalah detective control — resource already is created before is deleted, menyebabkan brief data exposure.
Option C: INCORRECT. Anda can opt-in regions (that non-default) but EU and US regions is default regions that cannot in-disable through account settings — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option D: INCORRECT. Requires management in each account and can in-override by admin that creates new policies.

A company has an S3 bucket in eu-central-1 containing regulated data. A developer attempts to configure S3 Cross-Region Replication (CRR) to a bucket in ap-southeast-1 for disaster recovery. The data governance team needs to ensure S3 replication can ONLY target buckets within approved EU regions. Which approach prevents unauthorized cross-region replication?
  • A. Configure AWS Config rule s3-bucket-replication-enabled with a parameter restricting allowed destination regions, integrating natively with the rest of the pipeline
  • B. Use an SCP that denies s3:PutReplicationConfiguration when the s3:DestinationRegion condition key is not in the approved EU region list
  • C. Use S3 Object Lock in Compliance mode to prevent any replication outside the current region with native S3 integration and optimized data transfer
  • D. Apply a bucket policy on the source bucket that denies s3:PutReplicationConfiguration unless the destination ARN contains an EU region
Correct Answer: D
Bucket policy with condition on destination ARN is approach most correct for mengontrol S3 replication destinations. Policy can uses condition StringLike on resource ARN or StringEquals on specific region identifier in ARN. Contoh: Deny s3:PutReplicationConfiguration except arn:aws:s3:::*eu-central-1* or *eu-west-1*. Ini prevents configuration replication to non-EU regions.

Option A: INCORRECT. Config rule s3-bucket-replication-enabled memeriksa whether replication enabled, not limits destination — this detective not preventive.
Option B: INCORRECT. Not ada condition key s3:DestinationRegion that valid for SCPs related S3 replication.
Option C: INCORRECT. S3 Object Lock prevents deletion/modification objek, not mengontrol kemana objek can direplikasi — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option D: CORRECT.
3
An organization uses Amazon RDS for PostgreSQL in eu-west-1 for their production database containing EU customer data. The DBA team needs to create cross-region read replicas for disaster recovery but ONLY within EU regions. They also need to prevent manual snapshots from being copied to non-EU regions. Which combination of controls achieves this? (Select the approach that covers both requirements)
  • A. SCP denying rds:CreateDBInstanceReadReplica and rds:CopyDBSnapshot when aws:RequestedRegion is not in EU regions
  • B. IAM policy denying rds:CreateDBInstanceReadReplica with condition on the DestinationRegion not being in EU, plus a separate SCP denying rds:CopyDBSnapshot to non-EU regions
  • C. AWS Config custom rule detecting non-EU read replicas combined with Systems Manager Automation to delete them
  • D. SCP with two statements: deny rds:CreateDBInstanceReadReplica when rds:DatabaseEngine condition is "postgres" and region is non-EU, plus deny rds:CopyDBClusterSnapshot to non-EU regions
Correct Answer: A
SCP that deny kedua actions (CreateDBInstanceReadReplica and CopyDBSnapshot) when aws:RequestedRegion not EU region is solution most simple and effective. For cross-region read replica, aws:RequestedRegion mengevaluasi region destination. For CopyDBSnapshot cross-region, request is sent to destination region so that aws:RequestedRegion also mencerminkan destination. Satu SCP mencakup kedua requirement.

Option A: CORRECT.
Option B: INCORRECT. Mencampur IAM and SCP adds complexity without benefit; also DestinationRegion not condition key standar for RDS.
Option C: INCORRECT. Detective control, not preventive — replika already is created before is deleted.
Option D: INCORRECT. Rds:DatabaseEngine condition key there is no; and CopyDBClusterSnapshot different from CopyDBSnapshot (cluster vs instance).

A company uses AWS Control Tower to manage their multi-account environment. They need to implement a guardrail that prevents any Amazon Redshift cluster snapshots from being copied to regions outside of their approved list (eu-central-1, eu-west-1, eu-west-2). Which Control Tower approach provides this preventive control?
  • A. Configure the Control Tower Region deny setting to block all services in non-approved regions, handling the described workload reliably at scale
  • B. Use Control Tower's detective guardrail to identify cross-region snapshots and send alerts configured for optimal performance and minimal operational overhead
  • C. Enable the built-in "Disallow cross-region data transfer" elective guardrail in Control Tower, handling the described workload reliably at scale
  • D. Create a custom Control Tower guardrail using an SCP that denies redshift:CopyClusterSnapshot when aws:RequestedRegion is not in the approved region list
Correct Answer: D
Control Tower supports custom SCPs sebagai preventive guardrails. For granular control on Redshift snapshot copying, custom SCP that deny redshift:CopyClusterSnapshot when region not approved list provides precisely scoped control. Ini preventive — request will ditolak before snapshot copy dimulai.

Option A: INCORRECT. Region deny setting memblokir SEMUA services in non-approved regions; this may too broad if ada legitimate services that needs runs in region other.
Option B: INCORRECT. Detective guardrail only detects and alert setelah violation occurs, snapshot already ter-copy — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option C: INCORRECT. Not ada built-in Control Tower guardrail with nama persis the said that specifically covers Redshift snapshot copying.
Option D: CORRECT.

A company uses AWS Backup to manage automated backups for their data infrastructure (RDS, DynamoDB, EFS) in eu-central-1. The compliance team discovers that AWS Backup has been configured to copy backups to us-east-1 as part of a cross-region backup strategy set up by a previous administrator. How should the data engineer prevent AWS Backup from creating copies in non-EU regions while maintaining the backup strategy for EU regions?
  • A. Use AWS Backup Vault Lock to prevent any modification to backup copies and their destinations, satisfying all of the stated requirements with minimal effort
  • B. Modify the backup plan AND apply an SCP denying backup:StartCopyJob with a condition that the destination vault ARN does not contain an EU region identifier
  • C. Apply an SCP that denies backup:CopyIntoRegion when the target region is not in the EU approved list with a condition that the destination vault ARN does not contain an EU region identifier
  • D. Modify the AWS Backup plan to remove the cross-region copy rule targeting us-east-1, and add copy rules only for eu-west-1, satisfying strict compliance and audit requirements
Correct Answer: B
Approach defense-in-depth is that most correct: (1) Modifikasi backup plan for deletes copy rule to us-east-1 and adds EU destination — this fixes configuration saat this, (2) Apply SCP sebagai preventive guardrail so that there is no administrator that can creates cross-region copy to non-EU in masa depan. Condition on destination vault ARN ensures backup copies only can dituju to vaults in EU regions.

Option A: INCORRECT. Vault Lock prevents deletion/modification recovery points, not mengontrol kemana backups can in-copy.
Option B: CORRECT.
Option C: INCORRECT. Backup:CopyIntoRegion not IAM action that valid — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option D: INCORRECT. Only fixes configuration current but not prevents future misconfiguration.

A multinational company has data in DynamoDB Global Tables that need to replicate between eu-west-1 and eu-central-1 for EU operations. However, a developer accidentally added us-west-2 as a replica region. The compliance team needs an immediate detective control to identify when DynamoDB tables are replicated to non-approved regions. Which AWS Config approach detects this violation?
  • A. Use the managed Config rule dynamodb-table-encrypted-kms to check if tables are encrypted in approved regions only, handling the described workload reliably at scale and satisfying strict compliance and audit requirements
  • B. Use the managed Config rule dynamodb-autoscaling-enabled and check its regional configuration, enforcing encryption and fine-grained access control and satisfying strict compliance and audit requirements and avoiding charges for idle provisioned capacity
  • C. Use CloudTrail to log CreateTable events and create a CloudWatch alarm for non-EU region activities with non-EU replicas as NON_COMPLIANT and marks tables with non-EU replicas as NON_COMPLIANT
  • D. Create a custom AWS Config rule using a Lambda function that evaluates DynamoDB table replica regions against an approved region list and marks tables with non-EU replicas as NON_COMPLIANT
Correct Answer: D
Custom AWS Config rule with Lambda function is solution most correct for memeriksa DynamoDB Global Tables replica regions. Lambda function can uses DynamoDB DescribeTable API for gets daftar replica regions, lalu membandingkan with approved region list. If ada replica in region that not is allowed, function mengembalikan NON_COMPLIANT. Config rule this runs periodic or saat configuration change is detected.

Option A: INCORRECT. Dynamodb-table-encrypted-kms memeriksa encryption, not replica regions.
Option B: INCORRECT. Dynamodb-autoscaling-enabled there is no hubungannya with regional replication.
Option C: INCORRECT. CloudTrail + CloudWatch can detects CreateTableReplica calls but not provides continuous compliance evaluation such as Config; also not memeriksa existing state — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option D: CORRECT.

A healthcare organization needs to ensure their S3 data cannot be replicated OR moved to regions outside of their country (Australia - ap-southeast-2). They want to use S3 Object Lock to add an additional layer of protection. A developer suggests using S3 Object Lock Compliance mode to prevent data movement. Is this correct, and what is the proper approach?
  • A. No, use S3 Glacier Vault Lock instead, which prevents cross-region movement of archived data with bucket policies restricting PutReplicationConfiguration, satisfying strict compliance and audit requirements and reducing day-to-day operational effort
  • B. Yes, S3 Object Lock Legal Hold prevents any operation including replication on the objects, satisfying strict compliance and audit requirements and protecting the data both in transit and at rest
  • C. No, S3 Object Lock protects against deletion/modification but does NOT prevent replication. Use SCPs to deny s3:ReplicateObject when the destination is not ap-southeast-2, combined with bucket policies restricting PutReplicationConfiguration
  • D. Yes, S3 Object Lock Compliance mode prevents cross-region replication and movement of objects, meeting the latency and throughput goals of the design and integrating natively with the rest of the pipeline
Correct Answer: C
S3 Object Lock (baik Compliance maupun Governance mode) melindungi objects from DELETION and OVERWRITE during retention period — BUKAN from replication or copying. Objects that locked still can direplikasi to region other if replication rule is configured. For prevents cross-region replication, is required: (1) SCP that deny s3:ReplicateObject in region that not is allowed, (2) Bucket policy that prevents PutReplicationConfiguration to non-approved destinations.

Option A: INCORRECT. Glacier Vault Lock also about deletion protection for archive, not cross-region movement prevention — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option B: INCORRECT. Salah — Legal Hold also only prevents deletion, not replication.
Option C: CORRECT.
Option D: INCORRECT. Salah — Object Lock not prevents replication.

A company operates in eu-central-1 and uses IAM condition keys to restrict actions to approved regions. However, they find that some AWS services (IAM, Organizations, Route 53, CloudFront) stop working because these are global services hosted in us-east-1. How should the SCP be structured to block non-EU regions while allowing global services to function?
  • A. Create two SCPs: one allowing all actions in EU regions, and another explicitly allowing global services in us-east-1, integrating natively with the rest of the pipeline and keeping steady-state operating costs low
  • B. Create the SCP with a Deny effect and add a NotAction list containing global service actions (iam:*, organizations:*, route53:*, cloudfront:*, etc.) so these services are excluded from the region restriction
  • C. Use StringNotEquals on aws:RequestedRegion with only the non-EU regions listed in the condition, rather than allowed regions, meeting the latency and throughput goals of the design and keeping steady-state operating costs low
  • D. Add a condition to the SCP that checks if the service is a global service before applying the region restriction with a Deny effect, enforcing encryption and fine-grained access control
Correct Answer: B
Pattern that correct for region-restriction SCP is uses NotAction (not Action) on statement Deny. NotAction contains daftar global service actions that must dikecualikan from restriction. Statement menjadi: "Deny everything NOT in this list UNLESS region is in approved list." Global services that needs in-exclude: iam:*, sts:*, organizations:*, route53:*, cloudfront:*, support:*, budgets:*, waf:*, dll.

Option A: INCORRECT. SCPs are deny-only effective (Allow in SCP only membuka ceiling, not grant); dua SCP separate not will produces efek that diinginkan because Deny still applies.
Option B: CORRECT.
Option C: INCORRECT. Approach this can works but not solves problem global services because mereka still in us-east-1.
Option D: INCORRECT. Not ada condition key that identifies whether service "global" or regional — although its description sounds convincing, in a fundamental still not appropriate for requirements this.

An organization needs to implement a comprehensive data residency solution that prevents data from leaving the EU across ALL data services (S3, RDS, Redshift, DynamoDB, EBS, EFS). They are concerned about both explicit copying (replication, snapshots) and implicit data movement (Lambda processing in other regions accessing EU data). Which layered approach provides the MOST comprehensive protection?
  • A. Apply a single SCP restricting aws:RequestedRegion to EU regions for all services with native S3 integration and optimized data transfer, satisfying all of the stated requirements with minimal effort
  • B. Enable AWS Artifact agreements for GDPR and rely on AWS's contractual guarantee that data stays in specified regions, handling the described workload reliably at scale and minimizing end-to-end processing latency
  • C. SCP restricting aws:RequestedRegion to EU + VPC endpoint policies denying cross-region API calls + S3 bucket policies restricting replication destinations + AWS Config rules for continuous compliance monitoring
  • D. Use AWS Control Tower Region deny guardrail combined with detective Config rules, satisfying all of the stated requirements with minimal effort and handling the described workload reliably at scale
Correct Answer: C
Defense-in-depth approach requires multiple layers: (1) SCP sebagai organizational-wide preventive guardrail for region restriction, (2) VPC endpoint policies adds network-level control — traffic to AWS services can is limited only to EU region endpoints, prevents Lambda or EC2 from calling APIs in non-EU regions, (3) S3 bucket policies sebagai resource-level control specific for replication, (4) AWS Config rules sebagai detective control for continuous compliance verification. Each layer handles attack vector different.

Option A: INCORRECT. Single SCP mencakup many but not handles network-level implicit access or resource-specific configurations — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option B: INCORRECT. Contractual agreement not technical control; not prevents misconfiguration by users.
Option C: CORRECT.
Option D: INCORRECT. Kurang granular dibanding opsi B because not mencakup VPC endpoint policies.

A data engineer discovers that an AWS Config rule has flagged an S3 bucket that has cross-region replication configured to an unauthorized region (us-west-2). The bucket contains 500 TB of data that has already been partially replicated. The Config rule needs to trigger automatic remediation to: (1) disable the replication rule, and (2) delete the objects that were already replicated to the unauthorized region. Which remediation approach is correct?
  • A. Configure EventBridge to detect the Config NON_COMPLIANT finding and trigger Step Functions that handles both remediation steps with error handling, satisfying all of the stated requirements with minimal effort
  • B. Configure AWS Config automatic remediation to disable the replication rule only, then use a separate scheduled Lambda to identify and delete already-replicated objects in the unauthorized region with appropriate approval workflow
  • C. Use Config manual remediation to prevent accidental deletion of 500 TB of potentially needed data with appropriate approval workflow, meeting the latency and throughput goals of the design and providing exactly-once processing semantics
  • D. Configure AWS Config automatic remediation using SSM Automation document that calls S3 DeleteBucketReplication API and then deletes objects in the destination bucket, meeting the latency and throughput goals of the design
Correct Answer: B
Remediation must is performed in a gradually and with risk management: (1) Immediate automated remediation: disable replication rule for STOP ongoing data transfer to unauthorized region — this urgent and low-risk. (2) Deleting 500 TB of already-replicated data requires careful handling — approval workflow is required because: data may still diakses, deletion 500 TB memakan time, needs confirm there is no dependencies. Automated deletion without approval for data skala large too berisiko.

Option A: INCORRECT. Can works but over-engineering for step 1 and still not should auto-delete without approval.
Option B: CORRECT.
Option C: INCORRECT. Manual remediation for step 1 (disabling replication) too slow because data terus ter-replicate during waits manual action — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option D: INCORRECT. Automatically deleting 500 TB without approval workflow too dangerous.
