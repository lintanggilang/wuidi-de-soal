A data engineer creates a Lambda function that needs to read from a Kinesis Data Stream, write processed records to DynamoDB, and send notifications to SNS. When configuring the Lambda execution role, which set of permissions follows the principle of least privilege?
  • A. Attach the AWS managed policy AmazonKinesisFullAccess, AmazonDynamoDBFullAccess, and AmazonSNSFullAccess
  • B. Create a custom policy allowing kinesis:GetRecords, kinesis:GetShardIterator, kinesis:DescribeStream, kinesis:ListShards on the specific stream ARN; dynamodb:PutItem, dynamodb:BatchWriteItem on the specific table ARN; and sns:Publish on the specific topic ARN
  • C. Attach the PowerUserAccess managed policy which covers all services except IAM
  • D. Create a custom policy with kinesis:*, dynamodb:*, and sns:* on resource "*"
Jawaban Benar: B
Least privilege berarti memberikan hanya permissions yang benar-benar diperlukan pada resource yang spesifik. Custom policy dengan: (1) Kinesis read permissions (GetRecords, GetShardIterator, DescribeStream, ListShards) — hanya actions untuk consume data. (2) DynamoDB write permissions (PutItem, BatchWriteItem) — hanya actions untuk menulis. (3) SNS publish permission — hanya action untuk mengirim notifikasi. Semua terbatas pada ARN spesifik. Opsi A (FullAccess policies) memberikan permissions berlebihan (termasuk Delete, Create). Opsi C (PowerUserAccess) memberikan hampir semua permissions. Opsi D (wildcard actions dan resources) terlalu broad.

A data engineer uses AWS CloudFormation to deploy a data pipeline stack that includes a Glue job, an S3 bucket, and a Lambda function. The CloudFormation stack creation fails with "AccessDenied" when trying to create the Glue job. The engineer's IAM user has full CloudFormation permissions. What is the MOST likely cause and solution?
  • A. The engineer's IAM user needs direct glue:CreateJob permission in addition to CloudFormation permissions
  • B. CloudFormation needs a service role with permissions to create the Glue job, S3 bucket, and Lambda function. The engineer should create and assign a CloudFormation service role with appropriate permissions.
  • C. The Glue job definition in the template has a syntax error causing CloudFormation to report it as an access issue
  • D. CloudFormation stacks can only be created from the AWS Management Console, not from the CLI
Jawaban Benar: B
CloudFormation service role is a best practice yang memisahkan "who can create stacks" dari "what resources stacks can create." Tanpa service role, CloudFormation menggunakan permissions dari calling user — jika user tidak memiliki glue:CreateJob, stack creation gagal. Solusinya: buat IAM role yang dipercaya oleh cloudformation.amazonaws.com dengan permissions untuk semua resources yang akan dibuat, lalu assign role tersebut ke stack. Opsi A bisa bekerja tapi bukan best practice — memberikan user permission langsung ke semua services kurang secure. Opsi C salah — syntax error menghasilkan error berbeda. Opsi D salah — CloudFormation bisa dipanggil dari CLI, SDK, dan Console.

A data engineer needs to allow a third-party SaaS application to write data to an S3 bucket in their AWS account. The SaaS provider gives their AWS Account ID and an External ID. Which IAM role configuration securely enables this access?
  • A. Create a role with trust policy allowing the SaaS provider's account as Principal, include an sts:ExternalId condition matching the provided External ID, and attach a policy allowing s3:PutObject on the target bucket
  • B. Create an IAM user with access keys and share the credentials with the SaaS provider
  • C. Create a role with trust policy allowing "*" as Principal and use the External ID in the permission policy's Condition block
  • D. Make the S3 bucket public and restrict access using bucket policy conditions based on the source IP of the SaaS provider
Jawaban Benar: A
Untuk third-party cross-account access, best practice adalah: (1) Trust policy dengan Principal: {"AWS": "arn:aws:iam::SAAS_ACCOUNT_ID:root"}. (2) Condition: {"StringEquals": {"sts:ExternalId": "provided-external-id"}}. External ID melindungi dari "confused deputy" attacks — tanpa External ID yang benar, bahkan jika seseorang mengetahui role ARN, mereka tidak bisa assume role. (3) Permission policy hanya memberikan s3:PutObject pada bucket spesifik. Opsi B (access keys) — long-term credentials tidak aman untuk third-party. Opsi C (Principal "*") memungkinkan siapa saja mencoba assume role. Opsi D (public bucket) sangat tidak aman.

A data engineer needs to configure an API Gateway REST API that triggers a Lambda function for a data ingestion endpoint. The API should accept requests only from authenticated IAM users and roles. Which authorization mechanism should be configured on the API Gateway method?
  • A. Set the authorization type to AWS_IAM on the API method. Callers must sign requests with SigV4 credentials of an IAM entity that has execute-api:Invoke permission on the API resource.
  • B. Create a Cognito User Pool and configure it as the authorizer for the API method
  • C. Create a Lambda authorizer that validates IAM access keys in the request headers
  • D. Set the authorization type to NONE and use a WAF rule to filter requests by IAM source
Jawaban Benar: A
AWS_IAM authorization pada API Gateway mengharuskan semua request di-sign menggunakan Signature Version 4 (SigV4) dengan credentials IAM entity (user atau role). API Gateway memverifikasi signature dan memeriksa apakah caller memiliki execute-api:Invoke permission pada API resource ARN. Ini adalah mekanisme native dan paling secure untuk IAM-based authentication. Opsi B (Cognito) dimaksudkan untuk end-user authentication, bukan IAM-based service-to-service. Opsi C (Lambda authorizer) menambahkan complexity yang tidak perlu jika IAM auth sudah cukup. Opsi D (NONE + WAF) tidak aman — WAF tidak bisa memvalidasi IAM identity.
5
A data engineer working from the AWS CLI needs to access resources in three different AWS accounts (Development, Staging, Production) for data pipeline management. Each account has a specific IAM role for the data engineering team. Which CLI configuration approach follows AWS best practices?
  • A. Create IAM users with access keys in each account and configure three named profiles with static credentials
  • B. Configure named profiles in ~/.aws/config with role_arn and source_profile settings, allowing the CLI to automatically assume roles in each account using temporary credentials
  • C. Use a single set of administrator credentials that has cross-account access to all three accounts
  • D. Store access keys for all accounts in environment variables and switch between them using shell scripts
Jawaban Benar: B
AWS CLI named profiles dengan role_arn dan source_profile adalah best practice untuk multi-account access. Konfigurasi: [profile dev] role_arn = arn:aws:iam::DEV_ACCOUNT:role/DataEngineerRole, source_profile = default. CLI secara otomatis memanggil sts:AssumeRole dan menggunakan temporary credentials (expire setelah 1 jam). Ini aman karena menggunakan temporary credentials, audit-friendly (AssumeRole events tercatat di CloudTrail), dan tidak menyimpan long-term credentials per account. Opsi A (static keys per account) menggunakan long-term credentials. Opsi C (single admin) melanggar least privilege. Opsi D (env variables) rawan error dan security risk.
6
A data engineer creates a Glue job that needs to write to an S3 bucket and also needs to start another Glue job as part of a pipeline. The engineer creates a role named "GlueETLRole" and attaches it to the Glue job. However, when the engineer tries to assign this role to the Glue job, they receive an error: "User is not authorized to perform iam:PassRole." What is required to resolve this?
  • A. The engineer's IAM user/role needs an iam:PassRole permission with the resource set to the GlueETLRole ARN and a condition restricting it to the glue.amazonaws.com service
  • B. The GlueETLRole needs an iam:PassRole permission in its own policy to allow itself to be passed
  • C. The engineer needs full IAM administrator access to assign any role to any service
  • D. The GlueETLRole trust policy must include the engineer's IAM user ARN as a trusted principal
Jawaban Benar: A
iam:PassRole adalah permission yang mengontrol siapa yang boleh meng-assign (pass) IAM role ke AWS service. Ini adalah security control yang mencegah privilege escalation — tanpa batasan ini, user bisa membuat service dengan admin role dan mendapat permissions lebih dari yang mereka miliki. Engineer memerlukan policy: {"Effect": "Allow", "Action": "iam:PassRole", "Resource": "arn:aws:iam::ACCOUNT:role/GlueETLRole", "Condition": {"StringEquals": {"iam:PassedToService": "glue.amazonaws.com"}}}. Opsi B salah — role tidak perlu permission untuk di-pass. Opsi C salah — full admin berlebihan. Opsi D salah — trust policy mengontrol siapa yang boleh assume role, bukan siapa yang boleh pass role.

A data engineer deploys an EMR cluster for a data processing pipeline. The cluster needs: (1) Access to S3 for input/output data, (2) Access to Glue Data Catalog as metastore, (3) Ability to publish CloudWatch metrics. Which IAM configuration correctly provides these permissions to the EMR cluster's EC2 instances?
  • A. Create an IAM role with the required permissions, create an instance profile containing that role, and specify the instance profile when launching the EMR cluster
  • B. Create an IAM user with the required permissions and pass the access keys to EMR through cluster configuration
  • C. Attach the permissions directly to the EMR service role (EMR_DefaultRole)
  • D. Create an IAM group with the required permissions and add the EMR cluster to the group
Jawaban Benar: A
EMR EC2 instances mendapatkan permissions melalui instance profile. Instance profile berisi IAM role yang mendefinisikan permissions untuk aplikasi yang berjalan di cluster (Spark, Hive, etc.). Role ini memerlukan: s3:GetObject/PutObject untuk data access, glue:GetDatabase/GetTable untuk Catalog access, dan cloudwatch:PutMetricData untuk metrics. Secara default, AWS membuat EMR_EC2_DefaultRole untuk ini, tetapi custom instance profile lebih baik untuk least privilege. Opsi B (IAM user + access keys) — kurang secure, credentials bisa bocor. Opsi C — EMR service role untuk cluster management, bukan untuk EC2 instances. Opsi D — IAM groups hanya untuk IAM users, bukan services.

A data engineer creates an AWS Glue job that needs to assume a cross-account role to read data from Account B's S3 bucket. The Glue job uses a service role (GlueServiceRole) in Account A. The engineer writes code in the Glue job to call sts:AssumeRole for the cross-account role. However, the AssumeRole call fails. The cross-account role's trust policy allows Account A. What permission is MOST likely missing?
  • A. The GlueServiceRole in Account A needs sts:AssumeRole permission with the cross-account role ARN as the resource
  • B. The cross-account role in Account B needs to trust the GlueServiceRole ARN specifically, not just Account A
  • C. Account A needs to be part of the same AWS Organization as Account B
  • D. The Glue job needs a VPC endpoint to reach the STS service endpoint
Jawaban Benar: A
Untuk berhasil memanggil sts:AssumeRole, calling principal (dalam hal ini GlueServiceRole) membutuhkan permission sts:AssumeRole pada target role ARN di IAM policy-nya. Ini sering terlewat — engineer menambahkan trust policy di Account B tapi lupa menambahkan permission di Account A. Diperlukan: {"Effect": "Allow", "Action": "sts:AssumeRole", "Resource": "arn:aws:iam::ACCOUNT_B:role/CrossAccountRole"} pada GlueServiceRole. Opsi B — jika trust policy sudah allows Account A root, semua principals di Account A yang memiliki sts:AssumeRole permission bisa assume. Opsi C — AWS Organizations tidak diperlukan untuk cross-account role assumption. Opsi D — STS memiliki regional endpoints yang accessible secara default.

A data engineer designs a serverless data pipeline where API Gateway receives data, triggers a Lambda function, which then writes to DynamoDB. The Lambda function also needs to invoke another Lambda function for data enrichment. Which trust policy should be on the Lambda execution role?
  • A. {"Version": "2012-10-17", "Statement": [{"Effect": "Allow", "Principal": {"Service": ["lambda.amazonaws.com", "apigateway.amazonaws.com"]}, "Action": "sts:AssumeRole"}]}
  • B. {"Version": "2012-10-17", "Statement": [{"Effect": "Allow", "Principal": {"Service": "lambda.amazonaws.com"}, "Action": "sts:AssumeRole"}]}
  • C. {"Version": "2012-10-17", "Statement": [{"Effect": "Allow", "Principal": {"Service": "dynamodb.amazonaws.com"}, "Action": "sts:AssumeRole"}]}
  • D. {"Version": "2012-10-17", "Statement": [{"Effect": "Allow", "Principal": {"AWS": "*"}, "Action": "sts:AssumeRole"}]}
Jawaban Benar: B
Lambda execution role hanya perlu trust policy untuk lambda.amazonaws.com. Trust policy menentukan SIAPA yang boleh assume role — dalam hal ini, Lambda service yang akan assume role saat menjalankan function. API Gateway tidak perlu ada di trust policy karena API Gateway memiliki role terpisah (API Gateway execution role) atau menggunakan Lambda proxy integration yang cukup dengan Lambda resource-based policy. DynamoDB dan Lambda invocation ditangani oleh permission policy, bukan trust policy. Opsi A salah — API Gateway tidak perlu assume Lambda's role. Opsi C salah — DynamoDB tidak assume role. Opsi D sangat tidak aman.

A data engineer uses AWS CloudFormation with a service role to deploy infrastructure. The CloudFormation template creates a Lambda function and assigns it an execution role. During stack creation, the error "User: arn:aws:iam::123456789012:role/CFNServiceRole is not authorized to perform: iam:PassRole on resource: arn:aws:iam::123456789012:role/LambdaExecRole" occurs. What should the engineer add to the CloudFormation service role?
  • A. Add iam:PassRole permission for the LambdaExecRole ARN with a condition that restricts iam:PassedToService to lambda.amazonaws.com
  • B. Add iam:CreateRole and iam:AttachRolePolicy permissions to allow CloudFormation to create the role
  • C. Add sts:AssumeRole permission for the LambdaExecRole ARN
  • D. Add administrator access to the CloudFormation service role to avoid permission issues
Jawaban Benar: A
CloudFormation service role memerlukan iam:PassRole permission ketika template meng-assign role ke service (misalnya assigning LambdaExecRole ke Lambda function). Permission yang diperlukan: {"Effect": "Allow", "Action": "iam:PassRole", "Resource": "arn:aws:iam::123456789012:role/LambdaExecRole", "Condition": {"StringEquals": {"iam:PassedToService": "lambda.amazonaws.com"}}}. Condition memastikan role hanya bisa di-pass ke Lambda service. Opsi B (CreateRole) — error bukan tentang membuat role, tapi meng-assign role ke Lambda. Opsi C (AssumeRole) — CloudFormation tidak perlu assume LambdaExecRole. Opsi D (admin access) melanggar least privilege dan merupakan security risk.
