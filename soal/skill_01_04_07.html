Amazon EFS mounts, /tmp ephemeral storage, S3 access patterns for Lambda-based data processing

1
A data engineer has a Lambda function that processes large ML model files (3GB) to generate predictions on incoming data. The model file must be loaded into memory for inference. The Lambda function's /tmp storage is insufficient for this use case. Which storage solution allows the Lambda function to access the 3GB model file with the LOWEST latency on subsequent invocations?
  • A. Store the model as a Lambda Layer to make it available in the function's runtime environment, minimizing end-to-end processing latency and handling the described workload reliably at scale and delivering records with consistent sub-second latency and integrating natively with the rest of the pipeline
  • B. Increase the Lambda ephemeral storage (/tmp) to 10GB and download the model from S3 on cold starts only, integrating natively with the rest of the pipeline and handling the described workload reliably at scale and streaming results downstream in near real time
  • C. Download the model from S3 to /tmp on every invocation and delete it after processing with local filesystem read speeds since EFS is already mounted, minimizing end-to-end processing latency and delivering records with consistent sub-second latency and handling the described workload reliably at scale
  • D. Mount an Amazon EFS file system to the Lambda function, store the model on EFS, and access it via the local mount point — subsequent invocations on warm containers access the model with local filesystem read speeds since EFS is already mounted
Jawaban Benar: D
EFS provides a persistent, shared filesystem that Lambda accesses via NFS mount. Unlike /tmp, EFS data persists across invocations and is shared across all concurrent executions. The model is stored once on EFS and accessed directly — no download step on cold starts. After initial cache warming, EFS provides consistent low-latency reads. EFS supports up to petabyte-scale storage, easily handling 3GB models.

Opsi A: SALAH. Lambda Layers have a 250MB unzipped limit, insufficient for a 3GB model.
Opsi B: SALAH. While /tmp can be configured up to 10GB, the model must still be downloaded from S3 on cold starts (significant latency).
Opsi C: SALAH. Downloading 3GB on every invocation adds 30+ seconds of latency, unacceptable for production — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi D: BENAR.

A Lambda function processes CSV files uploaded to S3. Each file is approximately 200MB. The function needs to download the file, parse it, apply transformations, and write the result back to S3. The engineer configured the Lambda function with 512MB /tmp storage (default), but the function fails with a "No space left on device" error. What is the MOST cost-effective solution?
  • A. Process the file in S3 directly without downloading using S3 Select, meeting the latency and throughput goals of the design and providing exactly-once processing semantics and satisfying all of the stated requirements with minimal effort and guaranteeing no data loss during component failures
  • B. Split the input file into 100 smaller files before triggering the Lambda function, satisfying all of the stated requirements with minimal effort and meeting the latency and throughput goals of the design and avoiding charges for idle provisioned capacity and providing exactly-once processing semantics
  • C. Increase the Lambda ephemeral storage (/tmp) from the default 512MB to a sufficient size (up to 10,240MB maximum) using the EphemeralStorage configuration — this allows the function to store the 200MB input plus the transformed output without requiring EFS or VPC configuration
  • D. Mount an EFS file system and use it as the working directory for file processing configured for optimal performance and minimal operational overhead, validating and cleansing each record before delivery and integrating natively with the rest of the pipeline and providing exactly-once processing semantics
Jawaban Benar: C
Lambda ephemeral storage (/tmp) can be configured from 512MB to 10,240MB (10GB). For a 200MB file, increasing /tmp to 1-2GB provides sufficient space for input and output without the overhead of EFS (which requires VPC, ENI, and has per-GB-month storage costs plus data transfer costs). /tmp is included in Lambda pricing with a small additional cost only above 512MB.

Opsi A: SALAH. S3 Select only supports limited query operations (SQL-like filtering), not complex transformations.
Opsi B: SALAH. Splitting files adds complexity and requires an orchestration layer before Lambda.
Opsi C: BENAR.
Opsi D: SALAH. EFS requires VPC configuration, adds cold start latency (ENI attachment), and costs more for simple temporary file storage — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
3
A data pipeline uses multiple Lambda functions that need to share intermediate results. Function A extracts data and produces a 500MB intermediate dataset. Function B (triggered after A completes) must read this intermediate data and apply additional transformations. The intermediate data is only needed for the pipeline run duration. Which storage approach BEST enables data sharing between these Lambda invocations?
  • A. Store the data in a DynamoDB table with 500MB record items and Function B reads it from the same mount point, meeting the latency and throughput goals of the design and handling the described workload reliably at scale and providing exactly-once processing semantics
  • B. Store intermediate data in Lambda's /tmp directory and rely on the next invocation using the same container, applying schema conversion and enrichment inline and validating and cleansing each record before delivery and handling the described workload reliably at scale
  • C. Pass the 500MB dataset as the payload in the Step Functions state machine between states, transforming records into the required target format and integrating natively with the rest of the pipeline and meeting the latency and throughput goals of the design
  • D. Mount a shared EFS file system on both Lambda functions. Function A writes intermediate data to EFS, and Function B reads it from the same mount point. EFS provides a shared persistent filesystem accessible by both functions with POSIX file semantics
Jawaban Benar: D
EFS provides a shared filesystem accessible by multiple Lambda functions simultaneously. Both functions mount the same EFS file system and can read/write to the same directories. This enables direct data sharing without object copies — Function B reads the same file Function A wrote. EFS supports concurrent access and provides file-level locking if needed.

Opsi A: SALAH. DynamoDB item size limit is 400KB, and it's not designed for large binary data storage — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi B: SALAH. /tmp is ephemeral and local to a specific container instance. Different Lambda functions (or even different invocations of the same function) use different containers with isolated /tmp directories.
Opsi C: SALAH. Step Functions payload limit is 256KB, far too small for 500MB.
Opsi D: BENAR.

A company deploys a Lambda function with an EFS mount for a data processing pipeline. After deployment, the Lambda function times out during cold starts, taking over 30 seconds before processing begins. The function previously completed in 5 seconds without EFS. What is the MOST likely cause of the cold start performance degradation?
  • A. EFS throughput mode is set to Provisioned and the function exceeds its allocated throughput, meeting the latency and throughput goals of the design and integrating natively with the rest of the pipeline and handling the described workload reliably at scale
  • B. The Lambda function is downloading the entire EFS file system content during cold start, integrating natively with the rest of the pipeline and satisfying all of the stated requirements with minimal effort and meeting the latency and throughput goals of the design
  • C. Lambda functions with EFS require VPC configuration, and the cold start includes creating an Elastic Network Interface (ENI) in the VPC. If the subnets don't have sufficient available IP addresses or the security groups are misconfigured, ENI creation takes significantly longer
  • D. EFS is replicating data across Availability Zones during Lambda initialization with EFS require VPC configuration, satisfying all of the stated requirements with minimal effort and handling the described workload reliably at scale and meeting the latency and throughput goals of the design
Jawaban Benar: C
EFS requires Lambda to be in a VPC (EFS access points are VPC-only resources). VPC-attached Lambda functions experience additional cold start latency due to ENI creation — historically 10-30+ seconds. While AWS has improved this with Hyperplane (reducing to 1-2 seconds in most cases), insufficient IP addresses in subnets or security group rule complexity can still cause delays. The fix includes ensuring subnets have ample IP space and using Provisioned Concurrency to eliminate cold starts.

Opsi A: SALAH. Throughput issues would cause I/O errors during file operations, not cold start delays.
Opsi B: SALAH. EFS uses lazy loading; only accessed files are read, not the entire filesystem.
Opsi C: BENAR.
Opsi D: SALAH. EFS replication is transparent to clients and doesn't affect mount time — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.

A data engineer needs to choose between /tmp ephemeral storage and EFS for a Lambda function that generates daily reports. The function downloads 2GB of data from S3, processes it, generates a 100MB PDF report, and uploads the report to S3. The function runs once daily and takes 3 minutes to execute. Which storage option is MOST cost-effective for this use case?
  • A. Mount EFS to store the downloaded data and generated report permanently, optimizing cost for the described workload and avoiding charges for idle provisioned capacity and meeting the latency and throughput goals of the design and handling the described workload reliably at scale and keeping steady-state operating costs low
  • B. Use Lambda ephemeral storage (/tmp) configured to 3GB — since the data is transient (downloaded from S3, processed, then uploaded back), there's no need for persistent storage. /tmp is automatically cleaned between invocations, and the cost is minimal (charged per GB-second only for storage above 512MB)
  • C. Stream the data directly from S3 without any local storage using S3 Select for persistent storage, keeping steady-state operating costs low and handling the described workload reliably at scale and meeting the latency and throughput goals of the design and integrating natively with the rest of the pipeline
  • D. Use both EFS for the download and /tmp for the report generation simultaneously, meeting the latency and throughput goals of the design and keeping steady-state operating costs low and avoiding charges for idle provisioned capacity and optimizing cost for the described workload and providing exactly-once processing semantics
Jawaban Benar: B
For transient workloads (download → process → upload), /tmp is ideal because data doesn't need to persist. Configuring /tmp to 3GB (within the 10GB limit) costs approximately $0.000000309 per GB-second above 512MB. For a 3-minute daily run using 2.5GB extra: ~$0.00014/day. EFS would cost $0.30/GB-month for storage PLUS data transfer costs, continuously. Since nothing needs to persist between daily runs, /tmp eliminates EFS's ongoing storage cost and VPC overhead.

Opsi A: SALAH. EFS costs are continuous (storage charged 24/7) even though data is needed only 3 minutes/day.
Opsi B: BENAR.
Opsi C: SALAH. S3 Select supports limited operations and cannot generate PDF reports — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi D: SALAH. Combining both adds unnecessary complexity and cost.

A machine learning pipeline runs 50 concurrent Lambda invocations that each need to read a shared 5GB reference dataset for data enrichment. Each function reads different portions of the dataset based on its partition key. The dataset is updated weekly. Which storage configuration provides the MOST efficient shared read access?
  • A. Mount EFS with an access point configured for read-only access. All 50 Lambda invocations share the same EFS mount and can concurrently read different portions of the dataset. Configure EFS with Elastic throughput mode to automatically scale read throughput based on demand
  • B. Have each of the 50 Lambda invocations independently download the 5GB dataset from S3 to their own /tmp storage, validating and cleansing each record before delivery and integrating natively with the rest of the pipeline and applying schema conversion and enrichment inline
  • C. Package the 5GB dataset as a Lambda Layer shared across all functions with an access point configured for read-only access and can concurrently read different portions of the dataset, transforming records into the required target format and handling the described workload reliably at scale
  • D. Store the dataset in DynamoDB and have each function query its relevant partition, meeting the latency and throughput goals of the design and transforming records into the required target format and handling the described workload reliably at scale and minimizing end-to-end processing latency
Jawaban Benar: A
EFS supports thousands of concurrent NFS connections from Lambda. All 50 invocations access the same filesystem simultaneously without duplicating data. Read-only access points enforce security. Elastic throughput mode automatically scales to match read demand from concurrent Lambdas without pre-provisioning. Weekly updates simply overwrite files on EFS. Total storage cost: ~$1.50/month (5GB × $0.30/GB).

Opsi A: BENAR.
Opsi B: SALAH. 50 concurrent downloads of 5GB each = 250GB of S3 transfer, costing significantly more and adding 30+ seconds of download time to each invocation.
Opsi C: SALAH. Lambda Layers have a 250MB limit, cannot hold 5GB — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi D: SALAH. DynamoDB is not optimized for large binary datasets; 5GB in DynamoDB would be extremely expensive and complex to partition.

A Lambda function with an EFS mount processes data files in a directory. During execution, the function encounters "Permission denied" errors when trying to write processed results to the EFS mount point at /mnt/data/output/. The EFS file system and access point are correctly configured. What is the MOST likely cause?
  • A. The security group attached to the Lambda function is blocking outbound NFS traffic on port 2049, integrating natively with the rest of the pipeline and meeting the latency and throughput goals of the design and satisfying all of the stated requirements with minimal effort
  • B. The EFS access point's POSIX user configuration (UID/GID) doesn't match the permissions on the /output directory, or the CreationInfo for the access point root directory was configured with restrictive permissions (e.g., 0755 instead of 0777) that prevent the Lambda function's mapped UID from writing
  • C. Lambda functions cannot write to EFS; they only support read operations, integrating natively with the rest of the pipeline and satisfying all of the stated requirements with minimal effort and meeting the latency and throughput goals of the design and keeping steady-state operating costs low
  • D. The EFS file system has reached its maximum storage capacity with restrictive permissions, integrating natively with the rest of the pipeline and handling the described workload reliably at scale and satisfying all of the stated requirements with minimal effort and optimizing cost for the described workload
Jawaban Benar: B
EFS access points map Lambda's execution identity to a POSIX user (UID/GID). If the access point specifies UID 1000 but the /output directory is owned by UID 0 (root) with permissions 0755, UID 1000 cannot write. Fix: either configure the access point's CreationInfo to create directories with appropriate permissions (e.g., 0777), or ensure the root directory path's ownership matches the access point's UID/GID.

Opsi A: SALAH. If security groups blocked NFS traffic, the function would fail to mount entirely (connection timeout), not produce a permission denied error.
Opsi B: BENAR.
Opsi C: SALAH. Lambda fully supports both read AND write operations on EFS mounts.
Opsi D: SALAH. EFS has no predefined storage capacity limit; it scales automatically to petabytes — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.

A data engineering team has a Lambda function that processes streaming data and needs to maintain a local cache of reference data (500MB) that is updated every hour. The function has high concurrency (100+ simultaneous executions). They want the cache to be immediately available on all Lambda instances without cold-start downloads. Which architecture provides cache consistency across all concurrent executions?
  • A. Use EFS as the shared cache. A separate scheduled Lambda function updates the reference data on EFS hourly. All 100+ concurrent execution instances read from the same EFS mount point, seeing the updated data immediately after the refresh Lambda completes its write
  • B. Store cache in each Lambda's /tmp and trigger a deployment to clear all containers when cache needs refreshing, delivering records with consistent sub-second latency and minimizing end-to-end processing latency and making the data queryable within seconds of arrival and providing exactly-once processing semantics
  • C. Implement a custom cache invalidation protocol using SNS to notify each Lambda instance to download fresh data, streaming results downstream in near real time and satisfying all of the stated requirements with minimal effort and meeting the latency and throughput goals of the design
  • D. Use Lambda environment variables to store the 500MB cache data configured for optimal performance and minimal operational overhead, meeting the latency and throughput goals of the design and making the data queryable within seconds of arrival and streaming results downstream in near real time
Jawaban Benar: A
EFS provides a single source of truth accessible by all concurrent Lambda instances. When the refresh Lambda updates files on EFS, all readers immediately see the new data (NFS strong consistency for close-to-open operations). No cache invalidation protocol needed — it's a shared filesystem. All 100+ instances read from the same mount point.

Opsi A: BENAR.
Opsi B: SALAH. /tmp is isolated per container; there's no mechanism to "clear all containers" without redeployment, and new containers would still need to populate their cache.
Opsi C: SALAH. SNS can trigger notification but each instance still needs to download 500MB independently, causing thundering herd and S3 bandwidth spikes.
Opsi D: SALAH. Lambda environment variables have a 4KB total limit, far below 500MB — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.

A Lambda function processes video files (1-5GB each) for a media analytics pipeline. The function needs to extract frames, analyze content, and store metadata. The processing requires random access to different parts of the video file. The current approach downloads the entire file to /tmp but fails for files over 10GB due to the ephemeral storage limit. Which approach handles files exceeding the /tmp limit?
  • A. Use S3 byte-range requests to read only the specific portions of the video file needed, eliminating the need for local storage entirely, satisfying all of the stated requirements with minimal effort and meeting the latency and throughput goals of the design and minimizing end-to-end processing latency
  • B. Request a service limit increase for Lambda /tmp storage beyond 10GB with sufficient throughput provisioned for the expected I/O pattern, satisfying all of the stated requirements with minimal effort and integrating natively with the rest of the pipeline and handling the described workload reliably at scale
  • C. Split the video into 512MB chunks in S3 and process each chunk in a separate Lambda invocation, meeting the latency and throughput goals of the design and satisfying all of the stated requirements with minimal effort and handling the described workload reliably at scale
  • D. Mount EFS with sufficient throughput provisioned for the expected I/O pattern. Stream the video file from S3 to EFS on first access, then perform random-access reads directly from the EFS mount. Jawaban Benar: D
EFS removes the /tmp size constraint entirely. A company is architecting a serverless data processing pipeline. The Lambda function needs to access a 50MB lookup table for data enrichment. The function runs with moderate concurrency (10-20 simultaneous executions) and the lookup table changes monthly. The team is evaluating storage options considering cost, performance, and complexity. Which storage option provides the BEST balance of these factors?
  • A. Download the lookup table from S3 to /tmp on every cold start and cached across warm invocations, removing the need to provision or patch any infrastructure and keeping steady-state operating costs low and validating and cleansing each record before delivery and reducing day-to-day operational effort and minimizing end-to-end processing latency
  • B. Mount EFS and store the lookup table on the shared filesystem, applying schema conversion and enrichment inline and requiring no servers to manage or scale manually and handling the described workload reliably at scale and removing the need to provision or patch any infrastructure and reducing day-to-day operational effort
  • C. Package the 50MB lookup table as a Lambda Layer. The layer is loaded into the Lambda execution environment on cold starts and cached across warm invocations. No VPC, no EFS configuration, no download step — the data is simply available as a file in /opt at function start
  • D. Store the lookup table in a DynamoDB table and query it for each enrichment lookup, validating and cleansing each record before delivery and keeping steady-state operating costs low and transforming records into the required target format and optimizing cost for the described workload and applying schema conversion and enrichment inline
Jawaban Benar: C
For a 50MB file that changes monthly, a Lambda Layer is optimal: it's deployed with the function (no download latency on cold start), cached in the execution environment (/opt), requires no VPC or EFS infrastructure, and costs nothing beyond standard Lambda pricing. Layers support up to 250MB unzipped, easily accommodating 50MB. Monthly updates only require publishing a new layer version.

Opsi A: SALAH. S3 download on cold start adds 2-5 seconds of latency and requires /tmp cleanup logic — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi B: SALAH. EFS adds VPC requirements, ENI cold start overhead, and ongoing storage/transfer costs — over-engineering for a 50MB static file.
Opsi C: BENAR.
Opsi D: SALAH. DynamoDB adds per-query latency and read capacity costs; loading the entire table for in-memory lookups is faster than individual queries.
