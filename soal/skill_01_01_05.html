A data engineer needs to schedule an AWS Glue ETL job to run every weekday at 6:00 AM UTC. The schedule must NOT trigger on weekends. Which scheduling approach is MOST appropriate?
  • A. Use Amazon MWAA (Airflow) with a DAG that runs daily and has a Python operator to skip weekends
  • B. Create a CloudWatch Events rule with rate(24 hours) and a Lambda to check the day
  • C. Create an Amazon EventBridge rule with a cron expression: cron(0 6 ? * MON-FRI *)
  • D. Use the AWS Glue built-in scheduler with a rate expression: rate(1 day)
Correct Answer: C
EventBridge (penerus CloudWatch Events) supports cron expressions that can determines days in weeks. cron(0 6 ? * MON-FRI *) runs on pukul 6:00 UTC only on days Senin up to Jumat. Ini solution most simple and native.

Option A: INCORRECT. Berlebihan for scheduling simple satu job.
Option B: INCORRECT. Adds complexity does not need with Lambda filter.
Option C: CORRECT.
Option D: INCORRECT. Not can excludes days certain.

A company has a complex data pipeline with 15 AWS Glue jobs that have dependencies between them. Job B and Job C depend on Job A completing successfully. Job D depends on both Job B and Job C completing. Which scheduling solution BEST manages these dependencies?
  • A. AWS Step Functions with Glue StartJobRun tasks
  • B. AWS Glue Workflows with triggers and job dependencies
  • C. Amazon MWAA (Apache Airflow) with a DAG defining task dependencies
  • D. EventBridge rules chained with Glue job state change events
Correct Answer: B
AWS Glue Workflows designed khusus for orchestrates multiple Glue jobs with dependensi. Workflows supports triggers conditional (on job success/failure) and fan-out/fan-in patterns. For pipeline that sepenuhnya uses Glue jobs, this is solution most terintegrasi.

Option A: INCORRECT. Can works but more generic and requires more configuration.
Option B: CORRECT.
Option C: INCORRECT. Adalah choice valid but adds overhead operasional (cluster management).
Option D: INCORRECT. Sulit for fan-in (waits multiple jobs complete).

Option B: INCORRECT. Not has DAG visualization and SLA monitoring bawaan.

Option D: CORRECT.

A company uses Amazon MWAA to orchestrate their data pipelines. They need to schedule a DAG that runs at 8:00 AM local time in the US/Eastern timezone, properly handling daylight saving time transitions. How should this be configured in the Airflow DAG?
  • A. Create two DAGs — one for EST and one for EDT — and enable/disable them manually during transitions
  • B. Use schedule_interval='0 8 * * *' with default UTC timezone and manually adjust for DST and specify start_date with timezone: pendulum
  • C. Use a Lambda function triggered by EventBridge to start the DAG at the correct local time
  • D. Set schedule_interval with a cron expression and specify start_date with timezone: pendulum.timezone('US/Eastern')

Apache Airflow supports timezone-aware scheduling uses library pendulum. By determines timezone in start_date, Airflow automatically handles transisi DST. DAG will always runs on 8:00 AM Eastern terlepas from whether EST or EDT applies.

Option A: INCORRECT. Very manual and error-prone.
Option B: INCORRECT. Menyebabkan DAG runs on hours that incorrect saat DST changes — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option C: INCORRECT. Adds complexity that does not need.

If all retries fail, the on-call engineer must be notified. Which combination of services provides this functionality?

Option C: CORRECT.
Option D: INCORRECT. Can retry but CloudWatch alarm must is configured separate and retry interval cannot dikustomisasi per Glue.

A company wants to schedule an AWS Glue crawler to run immediately after a Glue ETL job completes successfully. If the ETL job fails, the crawler should NOT run. Which is the MOST straightforward way to implement this?
  • A. Use Step Functions with a Choice state after the Glue job to decide whether to start the crawler
  • B. Add a post-processing step in the Glue job script to programmatically start the crawler via boto3
  • C. Use EventBridge rule matching Glue job state change to SUCCEEDED, targeting StartCrawler API
  • D. Create a Glue Workflow with a conditional trigger that starts the crawler on job SUCCEEDED state
Correct Answer: D
Glue Workflow with conditional trigger is way most native and straightforward for runs crawler setelah job sukses. Trigger "SUCCEEDED" only triggers crawler when job complete with sukses.

Option A: INCORRECT. Overkill for dua step simple.
Option B: INCORRECT. Mixing orchestration logic with ETL logic that not best practice.
Option C: INCORRECT. Bekerja but requires configuration in luar Glue.
Option D: CORRECT.

A data engineer uses Amazon EventBridge Scheduler to trigger multiple Lambda functions and Glue jobs at different intervals. The engineer needs to temporarily pause all scheduled tasks during a planned maintenance window without deleting any schedules. What is the MOST efficient approach?
  • A. Use a schedule group and disable the entire group during maintenance
  • B. Change each schedule's state to DISABLED individually and disable the entire
  • C. Set each schedule's end date to the maintenance start time
  • D. Delete all schedules before maintenance and recreate them after
Correct Answer: A
EventBridge Scheduler supports schedule groups. By menempatkan all related schedules in satu group, Anda can men-disable (or delete) entire group sekaligus. Ini most efficient for batch operations.

Option A: CORRECT.
Option B: INCORRECT. Not efficient for many schedules — although its description sounds convincing, in a fundamental still not appropriate for requirements this.
Option C: INCORRECT. Requires update each schedule and needs in-reset setelah maintenance.
Option D: INCORRECT. Berisiko kehilangan configuration.
