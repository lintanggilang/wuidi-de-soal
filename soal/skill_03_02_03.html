SQL querying patterns, views, and materialized views in Redshift and Athena

1
A data engineer has a complex reporting query in Amazon Redshift that joins 5 large tables and takes 45 seconds to execute. This query is run by 20 different analysts multiple times per day, but the underlying data only changes once daily during a nightly batch load. How should the engineer optimize this query for the analyst team?
  • A. Create a CTAS (CREATE TABLE AS SELECT) table and rebuild it with a scheduled job nightly
  • B. Create a standard view that encapsulates the join logic for reuse
  • C. Create a stored procedure that executes the query and caches results in a temporary table
  • D. Create a materialized view with AUTO REFRESH enabled
Jawaban Benar: D
Materialized views di Redshift menyimpan hasil query secara fisik, sehingga query berikutnya membaca dari pre-computed results (sub-second). AUTO REFRESH akan otomatis memperbarui materialized view ketika data underlying berubah (setelah nightly load). Ini ideal untuk query berat yang data-nya jarang berubah.

Opsi A: SALAH. Berfungsi tapi memerlukan scheduling terpisah dan tabel manual.
Opsi B: SALAH. Hanya menyimpan definisi query, tetap execute setiap kali dipanggil (45 detik).
Opsi C: SALAH. Memerlukan manual refresh dan temp table hilang setelah session.
Opsi D: BENAR.
2
A company stores raw event data in Amazon S3 partitioned by year/month/day. There are currently 3 years of data (over 1,000 partitions). Analysts frequently query data for the last 7 days using Amazon Athena but experience slow query planning phase. The Glue Data Catalog has all partitions registered. How can the data engineer reduce the query planning time in Athena?
  • A. Create an Athena view with a WHERE clause that limits to the last 7 days for partition metadata lookups in Glue Data Catalog
  • B. Reduce the number of partitions by repartitioning data to year/month granularity, handling the described workload reliably at scale
  • C. Use Athena partition projection to eliminate the need for partition metadata lookups in Glue Data Catalog
  • D. Increase the Athena DPU allocation for faster query planning, integrating natively with the rest of the pipeline
Jawaban Benar: C
Partition projection memungkinkan Athena menghitung partisi secara in-memory berdasarkan pola yang didefinisikan (misalnya date range), tanpa perlu melakukan GetPartitions call ke Glue Data Catalog. Ini secara drastis mengurangi query planning time untuk tabel dengan banyak partisi.

Opsi A: SALAH. Tetap memerlukan partition lookup — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi B: SALAH. Menghilangkan granularitas partitioning harian yang berguna untuk filter 7 hari terakhir.
Opsi C: BENAR.
Opsi D: SALAH. Tidak berlaku untuk Athena standar yang serverless (tidak ada DPU configuration untuk query planning).
3
A data engineer is building a data transformation layer in Amazon Athena. The engineer needs to create a cleaned and enriched version of raw data that can be queried by downstream users. The output should be stored as Parquet files in a specific S3 location, partitioned by date. Which Athena feature should the engineer use?
  • A. CREATE EXTERNAL TABLE pointing to the same S3 location with a Glue ETL job for transformation
  • B. INSERT INTO from a SELECT statement on the raw table with format
  • C. CREATE VIEW that applies transformation logic, applying schema conversion and enrichment inline
  • D. CREATE TABLE AS SELECT (CTAS) with format and partitioning specified
Jawaban Benar: D
CTAS di Athena memungkinkan pembuatan tabel baru dari hasil query SELECT. Anda bisa menentukan format output (Parquet), lokasi S3 tujuan, dan strategi partitioning. Data secara fisik ditulis ke S3 dalam format yang ditentukan. Ini ideal untuk membuat layer data yang ditransformasi.

Opsi A: SALAH. Menambah kompleksitas yang tidak perlu dengan Glue ETL job terpisah.
Opsi B: SALAH. Memerlukan tabel target yang sudah ada — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
Opsi C: SALAH. Hanya menyimpan definisi query tanpa materialisasi data.
Opsi D: BENAR.
4
A data engineer is creating a view in Amazon Redshift that references tables from an external schema (Redshift Spectrum tables pointing to S3). The source schema might evolve over time with new columns being added. The engineer wants the view to remain functional even when the underlying external table schema changes. Which type of view should be created?
  • A. Standard view with SELECT * to automatically pick up new columns
  • B. Late-binding view using WITH NO SCHEMA BINDING clause
  • C. Materialized view with AUTO REFRESH
  • D. Regular view with explicit column list
Jawaban Benar: B
Late-binding views (WITH NO SCHEMA BINDING) di Redshift tidak memverifikasi schema underlying table saat view dibuat. Schema divalidasi hanya saat query time. Ini sangat berguna untuk external/Spectrum tables yang schema-nya bisa berubah. Regular views memvalidasi schema saat CREATE dan akan error jika kolom berubah.

Opsi A: SALAH. Pada regular view tetap memiliki schema binding dan bisa break.
Opsi B: BENAR.
Opsi C: SALAH. Juga memiliki schema binding dan gagal saat refresh jika schema berubah.
Opsi D: SALAH. Akan break saat schema berubah.
5
A data analyst needs to calculate a running total of daily sales and the rank of each day's sales within its month, using Amazon Redshift. The query must show: date, daily_sales, running_total_for_month, and rank_within_month. Which SQL approach correctly achieves this?
  • A. Use a recursive CTE to iterate through dates and accumulate the running total with a separate query for rank, handling the described workload reliably at scale and enforcing encryption and fine-grained access control
  • B. Use SUM(daily_sales) OVER (PARTITION BY month ORDER BY date ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) for running total and RANK() OVER (PARTITION BY month ORDER BY daily_sales DESC) for rank
  • C. Use a self-join of the table on month with a GROUP BY to calculate cumulative sum and a subquery for rank, integrating natively with the rest of the pipeline
  • D. Use SUM(daily_sales) OVER (ORDER BY date) for running total and ROW_NUMBER() OVER (ORDER BY date) for rank with partition-level ordering and dedicated throughput, satisfying all of the stated requirements with minimal effort
Jawaban Benar: B
Window functions dengan PARTITION BY month membatasi kalkulasi dalam setiap bulan. SUM() OVER dengan ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW memberikan running total yang benar dalam bulan. RANK() OVER dengan ORDER BY daily_sales DESC memberikan ranking berdasarkan nilai sales dalam bulan.

Opsi A: SALAH. Sangat tidak efisien untuk masalah yang bisa diselesaikan dengan window functions.
Opsi B: BENAR.
Opsi C: SALAH. Tidak efisien dan lebih kompleks.
Opsi D: SALAH. Kehilangan PARTITION BY month sehingga running total lintas bulan dan rank tidak per-bulan — meskipun deskripsinya terdengar meyakinkan, secara fundamental tetap tidak sesuai untuk kebutuhan ini.
6
A data engineer needs to query semi-structured JSON data stored in an Amazon Redshift SUPER column. The JSON contains nested arrays of product reviews with fields like rating, text, and timestamp. The engineer needs to extract each review as a separate row with the parent product_id. Which Redshift SQL feature is required?
  • A. Use COPY command with JSON format option to reload the data into a normalized table
  • B. Cast the SUPER column to VARCHAR and use SPLIT_PART to parse the array
  • C. Use JSON_EXTRACT_PATH_TEXT function on the SUPER column
  • D. Use PartiQL syntax with unnesting from the SUPER column
Jawaban Benar: D
Redshift mendukung PartiQL syntax untuk querying SUPER type columns. PartiQL memungkinkan unnesting arrays menjadi baris individual menggunakan syntax FROM table t, t.reviews r dimana setiap element array menjadi row terpisah. Ini native dan efisien untuk semi-structured data.

Opsi A: SALAH. Memerlukan redesign tabel dan ETL pipeline.
Opsi B: SALAH. Sangat fragile dan tidak mendukung nested structures.
Opsi C: SALAH. Mengekstrak scalar value, tidak bisa unnest arrays menjadi multiple rows.
Opsi D: BENAR.
7
A data engineer is troubleshooting a slow-running query in Amazon Redshift that scans a 2 billion row fact table. The query filters on a date column but the explain plan shows a sequential scan instead of a range-restricted scan. Which Redshift system table should the engineer query to investigate the issue, and what is the MOST likely root cause?
  • A. Query STL_ALERT_EVENT_LOG; the query likely has implicit type casting on the filter column
  • B. Query STL_SCAN; the table likely has too many columns selected
  • C. Query SVV_TABLE_INFO; the table likely lacks a sort key on the date column
  • D. Query SVL_QUERY_SUMMARY; the table likely needs a VACUUM to restore sort order
Jawaban Benar: C
SVV_TABLE_INFO menampilkan metadata tabel termasuk sort key configuration. Jika tabel tidak memiliki sort key pada kolom date, Redshift tidak bisa melakukan zone map filtering (range-restricted scan) dan harus melakukan full sequential scan. Sort key memungkinkan Redshift melewati blocks yang tidak relevan berdasarkan min/max metadata.

Opsi A: SALAH. Berguna untuk alerts tapi bukan untuk diagnosa sort key.
Opsi B: SALAH. Menunjukkan detail scan tapi bukan root cause.
Opsi C: BENAR.
Opsi D: SALAH. Relevan jika sort key ada tapi data unsorted, namun SVL_QUERY_SUMMARY bukan tempat untuk memeriksa ini.

A data engineer needs to create a reusable query in Amazon Athena that calculates customer lifetime value (CLV) by joining orders, customers, and returns tables. The query should be accessible to business analysts who can add their own filters on top. However, the engineer does NOT want the results to be materialized as physical data in S3. Which Athena construct is appropriate?
  • A. Create a named query saved in Athena workgroup
  • B. Create a prepared statement with parameterized filters, absorbing sudden traffic spikes without throttling
  • C. Create a VIEW in Athena that encapsulates the CLV calculation logic
  • D. Create a CTAS table that stores pre-computed CLV values
Jawaban Benar: C
Athena views menyimpan definisi query tanpa mematerialisasi data. Analysts bisa SELECT dari view dengan tambahan WHERE clauses untuk filtering. Views memberikan abstraction layer yang reusable dan maintainable.

Opsi A: SALAH. Hanya bookmark, tidak bisa di-query dengan filter tambahan di atasnya.
Opsi B: SALAH. Untuk parameterized execution bukan untuk reusable query abstraction yang bisa difilter oleh analysts.
Opsi C: BENAR.
Opsi D: SALAH. Mematerialisasi data ke S3 yang bertentangan dengan requirement.
9
A data engineer needs to implement a hierarchical bill-of-materials (BOM) query in Amazon Redshift. Each product can contain sub-components, which in turn can contain their own sub-components, up to 10 levels deep. The engineer needs to traverse this hierarchy and calculate total component costs. Which SQL feature is required?
  • A. Recursive Common Table Expressions (CTEs) with UNION ALL
  • B. CONNECT BY PRIOR clause for hierarchical queries
  • C. Window functions with multiple PARTITION BY levels
  • D. Multiple self-joins of the BOM table (one for each level)
Jawaban Benar: A
Recursive CTEs (WITH RECURSIVE) memungkinkan traversal hierarki dengan kedalaman yang tidak diketahui atau variabel. CTE terdiri dari anchor member (root level) dan recursive member (UNION ALL) yang meng-join kembali ke CTE untuk level berikutnya. Redshift mendukung recursive CTEs.

Opsi A: BENAR.
Opsi B: SALAH. Adalah Oracle syntax, tidak didukung di Redshift.
Opsi C: SALAH. Untuk kalkulasi dalam partisi, bukan traversal hierarki.
Opsi D: SALAH. Memerlukan jumlah join yang diketahui sebelumnya dan sangat tidak efisien.
10
A data engineer is designing a data lakehouse architecture. Raw data lands in S3 and is cataloged in AWS Glue Data Catalog. The engineer needs to create a silver (cleaned) layer that is queryable from both Amazon Athena and Amazon Redshift Spectrum using the same table definition. The silver layer must be stored as Parquet with Snappy compression, partitioned by event_date. Which approach creates tables accessible from BOTH services with a single table definition?
  • A. Create the table in AWS Glue Data Catalog with appropriate Parquet SerDe and partition configuration
  • B. Create a Redshift materialized view over the external data and share it with Athena
  • C. Create an Athena CTAS table and then separately create a Redshift external table pointing to the same S3 location
  • D. Create an Apache Iceberg table in Athena which is automatically available in Redshift local tables
Jawaban Benar: A
AWS Glue Data Catalog berfungsi sebagai metastore terpusat yang bisa diakses oleh KEDUA Athena dan Redshift Spectrum. Tabel yang didefinisikan di Glue Data Catalog dengan Parquet SerDe dan partition information akan otomatis queryable dari Athena (native integration) dan Redshift Spectrum (via external schema yang mereferensikan Glue catalog). Satu definisi tabel, dua query engine.

Opsi A: BENAR.
Opsi B: SALAH. Tidak bisa diakses dari Athena.
Opsi C: SALAH. Membuat duplikat definisi.
Opsi D: SALAH. Memiliki integrasi terbatas lintas kedua services dalam mode ini.
