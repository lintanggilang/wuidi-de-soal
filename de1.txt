SELECT 
  product_id, 
  SUM(CASE WHEN quarter = 'Q1' THEN sales_amount ELSE 0 END) AS Q1, 
  SUM(CASE WHEN quarter = 'Q2' THEN sales_amount ELSE 0 END) AS Q2, 
  SUM(CASE WHEN quarter = 'Q3' THEN sales_amount ELSE 0 END) AS Q3, 
  SUM(CASE WHEN quarter = 'Q4' THEN sales_amount ELSE 0 END) AS Q4 
FROM 
  sales_data 
GROUP BY 
  product_id;

This SQL query correctly uses conditional aggregation with CASE statements to pivot the data. It sums the sales_amount based on the quarter values ('Q1', 'Q2', 'Q3', 'Q4') and assigns them to corresponding columns (Q1, Q2, Q3, Q4) for each product_id. Expiration actions delete objects rather than change their storage tier, so this would not preserve the audit exports for long-term retention. Deleting incomplete multipart uploads is useful cleanup, but it does not address the need to archive completed objects.

Overall explanation
Amazon S3 Lifecycle is the managed feature for applying time-based actions to objects in a bucket. A lifecycle rule can include a filter, such as a prefix or object tags, and can use Transition actions to move matching objects to lower-cost storage classes as they age. This fits workloads where access patterns are predictable, such as audit exports that are queried shortly after creation and then retained mostly for compliance or historical lookup.

Transition actions are different from expiration actions. A transition changes the storage class of an object, while an expiration deletes objects, old versions, or incomplete multipart uploads. Storage Lens is useful for organization-wide visibility and cost analysis, but it is observational rather than an automation mechanism for tiering. A scheduled Lambda function is a common anti-pattern for this use case because it requires custom code, monitoring, retries, and permission management when S3 already provides lifecycle automation. For more information, see Overview of S3 Lifecycle management and Elements of an S3 Lifecycle configuration.
